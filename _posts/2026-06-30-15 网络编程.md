## 网络编程基础

网络编程指的是：让运行在不同计算机上的程序，通过网络进行数据交换。

例如：

- 使用聊天软件发送消息；
- 浏览器访问网页；
- 客户端连接服务器；
- 游戏客户端和游戏服务器交互；
- 邮件客户端发送和接收邮件。

这些功能背后，本质上都是不同主机上的程序通过网络进行通信。

在 Java 中，网络编程相关的类主要位于 `java.net` 包中。通过这些类，Java 程序可以完成网络连接、数据发送、数据接收等操作。

### 什么是网络编程

计算机网络的作用是把分布在不同地理位置的计算机连接起来，使它们能够共享资源和交换数据。

但是，网络本身只提供了通信基础。真正要让两个程序之间传递数据，还需要编写网络程序。

例如：

```java
客户端程序  <------ 网络 ------>  服务器程序
```

客户端程序和服务器程序可能运行在同一台电脑上，也可能运行在不同城市、不同国家的电脑上。只要它们能够通过网络找到对方，并且遵守相同的通信规则，就可以进行数据交换。

### 网络编程需要解决的问题

想要让网络中的两个程序成功通信，需要解决三个核心问题：

1. 如何找到目标主机？
2. 如何找到目标主机上的具体程序？
3. 找到程序之后，双方按照什么规则传输数据？

这三个问题分别对应网络编程的三要素：

| 问题                     | 对应要素 | 作用                 |
| ------------------------ | -------- | -------------------- |
| 如何定位网络中的主机     | IP 地址  | 找到哪一台设备       |
| 如何定位主机中的应用程序 | 端口号   | 找到设备上的哪个程序 |
| 如何进行数据传输         | 通信协议 | 规定数据怎么传       |

因此，网络编程三要素是：

```java
IP 地址 + 端口号 + 通信协议
```

可以简单理解为：

- `IP 地址`：找到哪台电脑；
- `端口号`：找到这台电脑上的哪个程序；
- `通信协议`：规定双方怎么说话。

## 网络编程三要素

### IP 地址

IP 地址是网络中设备的唯一标识。它用于定位网络中的一台主机。

如果把网络看作现实中的城市，那么 IP 地址就类似于每个住户的门牌号。只有知道对方的地址，数据才能发送到正确的设备上。

例如：

```java
192.168.0.1
127.0.0.1
8.8.8.8
```

这些都是常见的 IPv4 地址形式。

#### IPv4 地址

IPv4 是目前仍然广泛使用的 IP 地址版本。

IPv4 使用 4 个字节表示一个地址。一个字节有 8 位，因此 IPv4 总共是 32 位。

二进制形式示例：

```java
11000000 10101000 00000000 00000001
```

为了方便阅读，通常会把每 8 位转换成一个十进制整数，并用点分隔：

```java
192.168.0.1
```

这种写法称为点分十进制表示法。

由于每个部分都是 8 位二进制数，所以每一段的取值范围是：

```java
0 ~ 255
```

因此，下面这些都不是合法的 IPv4 地址：

```java
-4.278.4.1
192.168.1.300
999.1.1.1
```

原因是它们的某些部分超出了 `0 ~ 255` 的范围。

#### IPv6 地址

随着互联网设备数量不断增加，IPv4 地址逐渐不够用，于是出现了 IPv6。

IPv6 使用 16 个字节表示一个地址，也就是 128 位。

IPv6 地址通常写成 8 组十六进制数，每组之间用冒号分隔。

例如：

```java
3ffe:3201:1401:1280:c8ff:fe4d:db39:1984
```

IPv6 能表示的地址数量远远大于 IPv4，可以满足更多设备接入互联网的需求。

#### 本机地址

本机地址指的是当前计算机自己。

常见写法有两个：

```java
127.0.0.1
localhost
```

它们通常都表示本机。

例如，一个服务器程序运行在自己电脑上，端口号是 `8080`，就可以通过下面地址访问：

```java
127.0.0.1:8080
```

或者：

```java
localhost:8080
```

这表示访问当前电脑上的 `8080` 端口对应的程序。

#### 私有地址

私有地址是专门用于局域网内部的地址，不能直接在公网互联网中使用。

常见私有地址范围之一是：

```java
192.168.0.0 ~ 192.168.255.255
```

家庭路由器、学校机房、公司内部网络中，经常可以看到类似地址：

```java
192.168.1.1
192.168.0.100
192.168.31.10
```

这些地址通常只在局域网内部有效。

------

#### 域名和 DNS

##### 域名

IP 地址是数字，不方便人类记忆。于是出现了域名。

域名是和 IP 地址对应的字符型地址。

例如：

```java
www.baidu.com
www.taobao.com
www.google.com
```

人们访问网站时，一般不会直接输入 IP 地址，而是输入域名。

域名的作用是让网络地址更容易记忆和传播。

##### DNS

DNS 的英文全称是 `Domain Name System`，中文称为域名系统。

它的作用是把域名解析成 IP 地址。

因为人容易记住域名，但计算机之间真正通信时，需要使用 IP 地址。因此，当用户访问：

```java
www.baidu.com
```

计算机会先通过 DNS 查询这个域名对应的 IP 地址，然后再根据 IP 地址访问目标服务器。

可以把 DNS 理解为网络世界中的“通讯录”。

例如：

```java
www.baidu.com  ----DNS解析---->  某个服务器 IP 地址
```

### 端口号

IP 地址只能定位到一台主机，但一台主机上可能运行很多网络程序。

例如，一台服务器上可能同时运行：

- Web 服务；
- 数据库服务；
- 邮件服务；
- 文件传输服务；
- 聊天服务。

如果只知道 IP 地址，只能找到这台电脑，无法知道数据应该交给哪个程序处理。

这时就需要端口号。

端口号用于标识一台主机上的具体应用程序。

可以这样理解：

```java
IP 地址：定位到哪一台电脑
端口号：定位到这台电脑上的哪一个程序
```

#### 端口号的取值范围

端口号使用 2 个字节表示。

2 个字节是 16 位，因此端口号的取值范围是：

```java
0 ~ 65535
```

端口号可以分为三类。

##### 公认端口

公认端口范围是：

```java
0 ~ 1023
```

这些端口通常被一些常见系统服务或标准服务占用。

例如：

| 端口号 | 常见服务           |
| ------ | ------------------ |
| 21     | FTP 文件传输       |
| 23     | Telnet 远程登录    |
| 25     | SMTP 邮件发送      |
| 53     | DNS 域名解析       |
| 80     | HTTP 网页访问      |
| 443    | HTTPS 加密网页访问 |

普通应用程序一般不建议随意使用这些端口。

##### 注册端口

注册端口范围是：

```java
1024 ~ 49151
```

这些端口通常分配给用户进程或常见应用程序。

例如：

| 端口号 | 常见服务           |
| ------ | ------------------ |
| 3306   | MySQL              |
| 5432   | PostgreSQL         |
| 6379   | Redis              |
| 8080   | Tomcat 或 Web 应用 |
| 1521   | Oracle             |

开发 Java Web 项目时，经常会见到 `8080` 端口。

##### 动态或私有端口

动态或私有端口范围是：

```java
49152 ~ 65535
```

这些端口通常由操作系统临时分配给客户端程序使用。

例如，浏览器访问服务器时，服务器可能使用 `80` 或 `443` 端口，而浏览器本地也需要一个临时端口来完成通信。这个临时端口通常就来自动态端口范围。

#### IP 地址和端口号的关系

IP 地址和端口号需要配合使用。

如果只知道 IP 地址，只能找到主机；如果只知道端口号，无法知道是哪台主机上的程序。

完整的网络定位方式通常是：

```java
IP地址:端口号
```

例如：

```java
127.0.0.1:8080
192.168.1.100:3306
www.example.com:80
```

可以类比为：

```java
IP 地址 = 小区地址 / 楼栋地址
端口号 = 房间号
```

只有同时知道地址和房间号，才能找到具体的人。
网络通信中，只有同时知道 IP 地址和端口号，才能找到目标主机上的具体程序。

### 通信协议

通信协议是网络通信双方共同遵守的规则。

两个人沟通时，必须使用双方都能理解的语言。计算机之间通信也一样，必须提前约定好数据格式、传输方式、传输顺序、错误处理方式等规则。

这些规则就叫通信协议。

通信协议规定的内容包括：

1. 数据如何封装；
2. 数据如何发送；
3. 数据如何接收；
4. 数据丢失怎么办；
5. 数据顺序错乱怎么办；
6. 连接如何建立；
7. 连接如何断开。

只有双方遵守同一种协议，才能正确交换数据。

#### OSI 参考模型

OSI 的英文全称是 `Open Systems Interconnection`，中文称为开放系统互联参考模型。

早期计算机网络发展过程中，不同厂商有自己的网络标准。不同厂商的设备和系统之间很难互联。

为了解决这个问题，国际标准化组织提出了 OSI 参考模型，希望提供一个通用的网络通信标准框架。

OSI 模型把复杂的网络通信过程划分为七层：

```java
应用层
表示层
会话层
传输层
网络层
数据链路层
物理层
```

从上到下，每一层负责不同的任务。

| 层级    | 名称       | 主要作用                     |
| ------- | ---------- | ---------------------------- |
| 第 7 层 | 应用层     | 面向用户应用，提供网络服务   |
| 第 6 层 | 表示层     | 数据格式转换、加密、压缩     |
| 第 5 层 | 会话层     | 建立、管理、维护会话         |
| 第 4 层 | 传输层     | 端到端传输，控制可靠性       |
| 第 3 层 | 网络层     | IP 寻址和路由选择            |
| 第 2 层 | 数据链路层 | 局域网内的数据帧传输         |
| 第 1 层 | 物理层     | 传输电信号、光信号或无线信号 |

##### 用发送微信消息理解 OSI 模型

假设你给朋友发送一条微信消息。在发送端，数据会从上往下逐层处理；在接收端，数据会从下往上逐层还原。

- **发送端：从上往下封装数据**
  - **应用层**：你在微信中输入消息，并点击发送。这一层直接面向用户应用，例如微信、浏览器、邮箱客户端等。
  - **表示层**：应用程序可能会对消息进行编码、加密、压缩等处理。例如，把文本转换成适合网络传输的数据格式。
  - **会话层**：负责建立和维护通信会话。例如，你的手机和服务器之间需要保持某种通信关系。
  - **传输层**：负责端到端的数据传输。如果数据较大，这一层可能会把数据拆分成多个数据段，并为它们编号，方便接收端重新组装。
  - **网络层**：负责给数据添加源 IP 地址和目标 IP 地址，并决定数据应该经过哪些路径到达目标主机。
  - **数据链路层**：负责在局域网范围内传输数据帧，通常会涉及 MAC 地址。
  - **物理层**：负责把数据转换成电信号、光信号或无线信号，数据最终会通过网线、光纤或 Wi-Fi 等介质发送出去。
- **接收端：从下往上解析数据**
  - **物理层**：接收到电信号、光信号或无线信号。
  - **数据链路层**：把底层信号还原成数据帧，并进行基本校验。
  - **网络层**：检查目标 IP 地址，确认数据是否发给当前主机。
  - **传输层**：将数据段按顺序重组，并处理可靠性问题。
  - **会话层**：维护通信会话状态。
  - **表示层**：对数据进行解密、解压或格式转换。
  - **应用层**：微信程序拿到最终消息，并显示在聊天窗口中。

#### OSI 模型的特点

OSI 模型的优点是分层清晰，适合学习和理解网络通信过程。

但是，OSI 模型比较复杂，商业落地较慢。实际互联网发展中，真正广泛使用的是更简单、更实用的 TCP/IP 模型。

#### TCP/IP 模型

TCP/IP 模型是互联网中实际广泛使用的网络通信模型。

它通常分为四层：

```java
应用层
传输层
网络层
网络接口层
```

## TCP/IP 四层模型

| 层级    | 名称       | 对应 OSI 层            | 主要作用                      |
| ------- | ---------- | ---------------------- | ----------------------------- |
| 第 4 层 | 应用层     | 应用层、表示层、会话层 | 面向具体应用程序              |
| 第 3 层 | 传输层     | 传输层                 | 端到端通信，常见协议 TCP、UDP |
| 第 2 层 | 网络层     | 网络层                 | IP 寻址和路由                 |
| 第 1 层 | 网络接口层 | 数据链路层、物理层     | 本地网络和物理传输            |

### 网络接口层

网络接口层负责把数据真正发送到网络介质中。

它对应 OSI 模型中的数据链路层和物理层。

常见技术包括：

```java
以太网
Wi-Fi
光纤通信
```

这一层关心的是：数据如何在当前局域网或物理网络中传输。

### 网络层

网络层的核心协议是 IP。

IP 的主要作用是：

1. 给数据包添加源 IP 地址和目标 IP 地址；
2. 根据目标 IP 地址进行路由选择；
3. 让数据可以跨越多个网络到达目标主机。

可以把 IP 理解为负责“找路”的协议。

### 传输层

传输层负责主机上两个程序之间的通信。

这一层最重要的协议是：

```java
TCP
UDP
```

#### TCP

TCP 的英文全称是 `Transmission Control Protocol`，中文称为传输控制协议。

它是一种面向连接、可靠的传输协议。

可以把 TCP 理解为“可靠快递”：

- 发送前需要建立连接；
- 会尽量保证数据不丢失；
- 会保证数据按顺序到达；
- 数据传输结束后需要释放连接。

常见应用：

```java
网页访问
文件传输
邮件发送
远程登录
```

#### UDP

UDP 的英文全称是 `User Datagram Protocol`，中文称为用户数据报协议。

它是一种无连接、不保证可靠性的传输协议。

可以把 UDP 理解为“快速邮筒”：

- 不需要先建立连接；
- 发送速度快；
- 不保证对方一定收到；
- 不保证数据顺序；
- 开销较小。

常见应用：

```java
视频直播
语音通话
网络游戏
广播通信
```

### 应用层

应用层面向具体应用程序。

常见应用层协议包括：

| 协议        | 作用         |
| ----------- | ------------ |
| HTTP        | 网页访问     |
| HTTPS       | 加密网页访问 |
| FTP         | 文件传输     |
| SMTP        | 邮件发送     |
| POP3 / IMAP | 邮件接收     |
| DNS         | 域名解析     |

Java 网络编程中，很多时候写的程序就是应用层程序。

例如：

- 使用 Socket 编写客户端和服务器；
- 使用 HTTP 访问网络资源；
- 编写聊天室程序；
- 编写文件传输程序。

## TCP/IP 协议族

TCP/IP 模型是一套分层结构，而 TCP/IP 协议族是具体实现这些层功能的一组协议。

可以这样理解：

```java
TCP/IP 模型：网络通信的分层设计图
TCP/IP 协议族：按照设计图真正工作的各种协议
```

每一层都有对应的协议。

### TCP/IP 协议族分层示例

| TCP/IP 层次 | 常见协议或技术       | 作用                 |
| ----------- | -------------------- | -------------------- |
| 应用层      | HTTP、FTP、DNS、SMTP | 面向具体应用         |
| 传输层      | TCP、UDP             | 控制端到端传输       |
| 网络层      | IP、ICMP             | 寻址、路由、错误控制 |
| 网络接口层  | 以太网、Wi-Fi        | 底层数据传输         |

### 常见协议说明

#### HTTP

HTTP 的英文全称是 `HyperText Transfer Protocol`，中文称为超文本传输协议。

它主要用于浏览器和服务器之间传输网页数据。

例如，在浏览器中访问网页时，通常使用 HTTP 或 HTTPS。

#### FTP

FTP 的英文全称是 `File Transfer Protocol`，中文称为文件传输协议。

它主要用于在网络中上传和下载文件。

#### DNS

DNS 的英文全称是 `Domain Name System`，中文称为域名系统。

它用于把域名解析成 IP 地址。

#### SMTP

SMTP 的英文全称是 `Simple Mail Transfer Protocol`，中文称为简单邮件传输协议。

它主要用于发送电子邮件。

#### IP

IP 的英文全称是 `Internet Protocol`，中文称为网际协议。

它负责网络层的寻址和路由，使数据包可以从源主机到达目标主机。

#### ICMP

ICMP 的英文全称是 `Internet Control Message Protocol`，中文称为互联网控制报文协议。

它主要用于网络错误报告和诊断。

常见的 `ping` 命令就和 ICMP 有关。

## 网络编程基础类

Java 为了保证跨平台能力，不允许程序直接调用底层操作系统的网络功能，而是通过 Java 类库提供统一的网络编程接口。

在 Java 中，网络编程相关的类主要位于：

```java
java.net
```

常见的网络编程基础类包括：

```java
InetAddress
URL
Socket
ServerSocket
DatagramSocket
DatagramPacket
```

其中，`InetAddress` 用于表示 IP 地址和主机名，`URL` 用于表示互联网资源地址。本节主要学习这两个基础类。

### InetAddress 类

`InetAddress` 是 `java.net` 包下的一个类，用于封装计算机的 IP 地址和主机名。

它表示的是网络中的一个主机地址，不包含端口号信息。

也就是说，`InetAddress` 只能表示：

```java
主机名 + IP 地址
```

不能表示：

```java
端口号
```

例如：

```java
baidu.com
39.156.70.37
localhost
127.0.0.1
```

这些都可以和 `InetAddress` 有关。

#### InetAddress 的作用

在网络编程中，很多类都需要使用 IP 地址或主机信息，例如：

```java
Socket
ServerSocket
URL
DatagramSocket
DatagramPacket
```

`InetAddress` 可以看作 Java 对 IP 地址的高层封装。程序员不需要直接处理底层二进制 IP 地址，而是可以通过 `InetAddress` 获取主机名、IP 地址等信息。

#### InetAddress 常用静态方法

##### getLocalHost()

`getLocalHost()` 用于获取本机的 `InetAddress` 对象。

```java
public static InetAddress getLocalHost() throws UnknownHostException
```

示例：

```java
InetAddress inetAddress = InetAddress.getLocalHost();
```

它返回的对象中封装了当前计算机的主机名和 IP 地址。

##### getByName(String host)

`getByName(String host)` 用于根据主机名或 IP 地址获取对应的 `InetAddress` 对象。

```java
public static InetAddress getByName(String host) throws UnknownHostException
```

参数 `host` 可以是域名，也可以是 IP 地址。

例如：

```java
InetAddress inetAddress = InetAddress.getByName("baidu.com");
```

如果传入的是域名，Java 会尝试通过 DNS 进行域名解析，找到该域名对应的 IP 地址。

##### getHostName()

`getHostName()` 用于获取主机名。

public String getHostName()

`getHostAddress()` 用于获取 IP 地址字符串。

public String getHostAddress()

public class NetTest01 {

### URL 类

#### 什么是 URL

URL 的英文全称是 `Uniform Resource Locator`，中文称为统一资源定位符。

URL 用于表示互联网中某个资源的地址。

例如：

```java
https://www.baidu.com
http://www.jd.com:8080/java/index.html?name=admin#tip
```

这些都是 URL。

URL 不仅能表示资源在哪里，还能表示使用什么协议访问这个资源。

#### URL 的基本格式

URL 的常见格式如下：

```java
协议://主机名:端口/路径?查询参数#锚点
```

例如：

```java
http://www.jd.com:8080/java/index.html?name=admin#tip
```

可以拆分为：

| 部分     | 示例               | 含义                 |
| -------- | ------------------ | -------------------- |
| 协议     | `http`             | 使用 HTTP 协议访问   |
| 主机名   | `www.jd.com`       | 要访问的服务器       |
| 端口     | `8080`             | 服务器上的应用端口   |
| 路径     | `/java/index.html` | 服务器中的资源路径   |
| 查询参数 | `name=admin`       | 向服务器提交的数据   |
| 锚点     | `tip`              | 页面中的某个定位位置 |

其中，协议和主机名通常是必需的；端口、路径、查询参数、锚点可以根据需要省略。

##### 默认端口

有些协议有默认端口。

例如：

| 协议  | 默认端口 |
| ----- | -------- |
| HTTP  | 80       |
| HTTPS | 443      |
| FTP   | 21       |

因此，下面两个地址在端口含义上通常是等价的：

```java
http://www.baidu.com
http://www.baidu.com:80
```

如果 URL 中没有显式写端口，就会使用协议默认端口。

#### Java 中的 URL 类

Java 使用 `java.net.URL` 类封装 URL 信息。

创建 URL 对象：

```java
URL url = new URL("http://www.jd.com:8080/java/index.html?name=admin#tip");
```

如果 URL 格式错误，会抛出 `MalformedURLException`。

```java
import java.net.MalformedURLException;
import java.net.URL;
```

#### URL 常用方法

| 方法               | 作用                      |
| ------------------ | ------------------------- |
| `getProtocol()`    | 获取协议                  |
| `getHost()`        | 获取主机名或域名          |
| `getDefaultPort()` | 获取协议默认端口          |
| `getPort()`        | 获取 URL 中显式指定的端口 |
| `getPath()`        | 获取资源路径              |
| `getFile()`        | 获取路径和查询参数        |
| `getQuery()`       | 获取查询参数              |
| `getRef()`         | 获取锚点                  |

#### 示例：解析 URL

```java
import java.net.MalformedURLException;
import java.net.URL;

public class NetTest02 {
    public static void main(String[] args) throws MalformedURLException {
        // 创建 URL 对象
        URL url = new URL("http://www.jd.com:8080/java/index.html?name=admin#tip");

        // 获取协议
        System.out.println("协议：" + url.getProtocol());

        // 获取域名或主机名
        System.out.println("域名：" + url.getHost());

        // 获取与 URL 协议关联的默认端口
        System.out.println("获取与URL关联的协议的默认端口：" + url.getDefaultPort());

        // 获取 URL 中显式指定的端口
        System.out.println("端口：" + url.getPort());

        // 获取资源路径
        System.out.println("getPath:" + url.getPath());

        // 获取路径和查询参数
        System.out.println("getFile:" + url.getFile());

        // 获取查询参数
        System.out.println("参数：" + url.getQuery());

        // 获取锚点
        System.out.println("锚点：" + url.getRef());
    }
}
```

输出结果：

```java
协议：http
域名：www.jd.com
获取与URL关联的协议的默认端口：80
端口：8080
getPath:/java/index.html
getFile:/java/index.html?name=admin
参数：name=admin
锚点：tip
```

#### URL 中路径、参数和锚点的区别

以这个 URL 为例：

```java
http://www.jd.com:8080/java/index.html?name=admin#tip
```

##### 路径

路径是服务器中的资源位置：

```java
/java/index.html
```

通过 `getPath()` 获取。

##### 查询参数

查询参数是发送给服务器的数据：

```java
name=admin
```

通过 `getQuery()` 获取。

查询参数通常采用下面格式：

```java
name=value&name=value&name=value
```

例如：

```java
userId=100&name=admin
```

表示向服务器提交了两个参数：

```java
userId = 100
name = admin
```

##### 锚点

锚点用于定位页面中的某个位置：

```java
tip
```

通过 `getRef()` 获取。

锚点通常只在浏览器端使用，不一定会发送给服务器处理。

##### 示例：解析带查询参数的 URL

```java
import java.net.MalformedURLException;
import java.net.URL;

public class NetTest02 {
    public static void main(String[] args) throws MalformedURLException {
        URL url = new URL(
                "http://127.0.0.1:8080/api/mis/user/searchByNameAndId?userId=100&name=admin"
        );

        System.out.println("协议：" + url.getProtocol());
        System.out.println("域名：" + url.getHost());
        System.out.println("获取与URL关联的协议的默认端口：" + url.getDefaultPort());
        System.out.println("端口：" + url.getPort());
        System.out.println("getPath:" + url.getPath());
        System.out.println("getFile:" + url.getFile());
        System.out.println("参数：" + url.getQuery());
        System.out.println("锚点：" + url.getRef());
    }
}
```

输出结果大致为：

```java
协议：http
域名：127.0.0.1
获取与URL关联的协议的默认端口：80
端口：8080
getPath:/api/mis/user/searchByNameAndId
getFile:/api/mis/user/searchByNameAndId?userId=100&name=admin
参数：userId=100&name=admin
锚点：null
```

这个 URL 中没有 `#锚点` 部分，因此 `getRef()` 返回 `null`。

#### GET 请求和查询参数

在 URL 中，路径和查询参数之间使用问号 `?` 分隔。

```java
http://ip:port/uri?name=value&name=value
```

例如：

```java
http://127.0.0.1:8080/api/mis/user/searchByNameAndId?userId=100&name=admin
```

其中：

```java
/api/mis/user/searchByNameAndId
```

是请求路径。

```java
userId=100&name=admin
```

是查询参数。

这种把参数拼接在 URL 后面的请求方式，通常属于 GET 请求。

GET 请求的特点是：

1. 参数直接出现在 URL 中；
2. 适合查询类请求；
3. 不适合传输敏感数据；
4. URL 长度通常受到浏览器或服务器限制。

#### 使用 URL 读取网络资源

`URL` 类不仅可以解析地址，还可以通过 `openStream()` 打开网络资源输入流。

方法如下：

```java
public final InputStream openStream() throws IOException
```

它会打开到此 URL 的连接，并返回一个输入流。通过这个输入流，可以读取服务器返回的数据。

##### 示例：读取网页内容

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.net.URL;

public class URLReadTest {
    public static void main(String[] args) {
        BufferedReader br = null;

        try {
            // 创建 URL 对象
            URL url = new URL("http://www.baidu.com/");

            // 打开网络输入流
            InputStream ips = url.openStream();

            // 将字节流转换为字符流，再包装为缓冲字符流
            br = new BufferedReader(new InputStreamReader(ips));

            String str;

            // 逐行读取服务器返回的内容
            while ((str = br.readLine()) != null) {
                System.out.println(str);
            }
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            // 关闭流资源
            if (br != null) {
                try {
                    br.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

这段代码可以把指定 URL 返回的内容读取到本地并输出。

从原理上看，这就是最简单的网络数据抓取过程：

1. 创建 URL；
2. 打开网络连接；
3. 获取输入流；
4. 读取服务器返回的数据；
5. 关闭流。

搜索引擎爬虫的第一步，也可以理解为从互联网上下载网页内容，然后再进行分析、建立索引。不过，真实爬虫还需要处理更多问题，例如编码、重定向、反爬限制、网络超时、页面解析、去重等。

##### openStream() 的注意事项

使用 `openStream()` 读取网络资源时，需要注意：

1. 访问网络可能失败，所以必须处理异常；
2. 网络读取可能比较慢，不能假设一定立即返回；
3. 使用完输入流后必须关闭；
4. 读取网页时要注意字符编码；
5. 真实项目中更常用 HTTP 客户端工具，而不是直接用 `openStream()` 处理复杂请求。

## TCP 和 UDP 协议

在网络编程中，应用程序之间真正传输数据时，通常会使用传输层协议。传输层中最重要的两个协议是：

1. `TCP`：传输控制协议，可靠传输；
2. `UDP`：用户数据报协议，快速传输。

Java 程序并不会直接操作 TCP 或 UDP 协议的底层细节，而是通过 `Socket` 套接字来使用这些协议完成通信。

### Socket 套接字概述

`Socket` 中文通常翻译为套接字。它是应用层和传输层之间的编程接口。

在网络分层模型中：

```java
应用程序位于应用层
TCP / UDP 位于传输层
```

应用程序如果想使用 TCP 或 UDP 发送数据，就需要通过 Socket 这个接口。

可以把 Socket 理解为应用程序和传输层之间的“服务窗口”。

应用程序只需要：

1. 把要发送的数据写入 Socket；
2. 从 Socket 中读取接收到的数据。

至于数据在底层如何分段、封装、路由、传输、校验、重传，这些复杂细节由操作系统和网络协议栈处理。

### Socket 的作用

Socket 的作用可以总结为：

```java
Socket = 应用程序使用网络协议进行通信的入口
```

通过 Socket，开发者可以分别编写：

1. 客户端程序；
2. 服务器端程序。

客户端和服务器通过网络连接后，就可以进行数据交换。

例如：

```java
客户端 Socket  <-------- 网络 -------->  服务器 Socket
```

Java 网络编程中，常见的 Socket 编程分为两类：

1. 基于 TCP 的 Socket 编程；
2. 基于 UDP 的 Socket 编程。

### TCP 协议

TCP 的英文全称是 `Transmission Control Protocol`，中文称为传输控制协议。

TCP 是一种：

```java
面向连接、可靠的、基于字节流的传输协议
```

#### TCP 的特点

##### 面向连接

使用 TCP 通信之前，客户端和服务器之间必须先建立连接。

这类似于打电话：

```java
先拨号建立通话
通话过程中双方交流
通话结束后挂断电话
```

TCP 建立连接时需要三次握手，断开连接时需要四次挥手。

##### 点对点通信

一条 TCP 连接只能连接两个端点：

```java
客户端 <------ TCP连接 ------> 服务器
```

因此，TCP 主要是一对一通信，不支持广播。

##### 可靠传输

TCP 会尽力保证数据可靠到达。

可靠性主要体现在：

1. 数据丢失后可以重传；
2. 数据乱序后可以重新排序；
3. 数据损坏后可以校验发现；
4. 接收方会对收到的数据进行确认；
5. 发送方可以根据确认情况判断是否需要重发。

因此，TCP 适合对数据准确性要求高的场景。

##### 面向字节流

TCP 传输的是字节流，而不是一条一条独立消息。

这意味着 TCP 只保证字节按顺序传输，但不保证保留应用层消息边界。

例如，发送方写了两次：

```java
write("hello");
write("world");
```

接收方可能一次读到：

```java
helloworld
```

也可能分多次读到：

```java
hel
lowor
ld
```

所以，使用 TCP 编程时，如果应用层需要区分一条条消息，就需要自己设计消息边界，例如使用换行符、固定长度、消息长度字段等方式。

##### 开销较大，速度相对较慢

TCP 为了保证可靠性，需要建立连接、确认应答、超时重传、流量控制、拥塞控制等机制。因此，TCP 的开销比 UDP 大，速度相对较慢。

#### TCP 的适用场景

TCP 适合对可靠性要求高的场景，例如：

1. 文件传输；
2. 邮件发送；
3. 网页访问；
4. 登录认证；
5. 数据库连接；
6. 支付、订单等重要业务数据传输。

这些场景中，数据不能随便丢失或乱序，因此更适合使用 TCP。

### UDP 协议

UDP 的英文全称是 `User Datagram Protocol`，中文称为用户数据报协议。

UDP 是一种：

```java
无连接、不可靠的、面向数据报的传输协议
```

#### UDP 的特点

##### 无连接

UDP 发送数据之前，不需要先建立连接。

这类似于发短信：

```java
写好内容
填好收件人
直接发送
```

发送方不关心接收方当前是否准备好，也不需要提前建立通信通道。

##### 面向数据报

UDP 每次发送的是一个完整的数据报。

一个 UDP 数据报中通常包含：

1. 数据内容；
2. 源地址信息；
3. 目标地址信息。

UDP 保留应用层消息边界。发送方发送一次数据报，接收方通常也按数据报为单位接收。

##### 不保证可靠性

UDP 不保证数据一定能到达。

也就是说：

1. 发送方发出数据后，不确认对方是否收到；
2. 数据丢失后，UDP 本身不会自动重传；
3. 数据乱序后，UDP 本身不会自动排序；
4. 接收方收到数据后，也不会自动给发送方确认。

因此，UDP 被称为不可靠协议。

这里的“不可靠”不是指不能用，而是指 UDP 协议本身不提供可靠性保障。如果应用程序需要可靠性，就需要自己在应用层设计确认、重传、排序等机制。

##### 支持一对一、一对多、多对一

UDP 可以用于：

1. 一对一通信；
2. 一对多通信；
3. 多对一通信；
4. 广播或组播场景。

这使得 UDP 在某些实时通信场景中更加灵活。

##### 开销小，速度快

UDP 不需要建立连接，也不需要维护复杂的可靠性机制，所以开销较小，速度较快。

#### UDP 数据报大小

UDP 数据报大小理论上受到 IP 包长度限制。一般可以简单理解为：UDP 单个数据报最大接近 64KB。

不过在实际网络中，不建议发送过大的 UDP 数据报。因为过大的数据报可能会被 IP 层分片，分片丢失会导致整个数据报不可用。

实际开发中，UDP 通常用于发送较小的数据包。

#### UDP 的适用场景

UDP 适合对实时性要求高、允许少量数据丢失的场景，例如：

1. 视频直播；
2. 视频会议；
3. 语音通话；
4. 网络游戏；
5. 广播通知；
6. 局域网发现服务。

这些场景中，速度和实时性通常比绝对可靠性更重要。

例如视频直播中，如果某一帧画面丢失，通常不会等待重传，而是直接播放后续画面。否则会造成明显卡顿。

### TCP 和 UDP 的区别

| 对比项       | TCP                            | UDP                    |
| ------------ | ------------------------------ | ---------------------- |
| 是否连接     | 面向连接                       | 无连接                 |
| 是否可靠     | 可靠传输                       | 不可靠传输             |
| 通信对象     | 一对一                         | 一对一、一对多、多对一 |
| 传输方式     | 面向字节流                     | 面向数据报             |
| 是否保证顺序 | 保证顺序                       | 不保证顺序             |
| 是否自动重传 | 支持重传                       | 不自动重传             |
| 速度         | 相对较慢                       | 相对较快               |
| 开销         | 较大                           | 较小                   |
| 适用场景     | 文件、邮件、网页、重要业务数据 | 直播、语音、游戏、广播 |

## 三次握手

三次握手是 TCP 建立连接的过程。

TCP 是面向连接的协议，通信前必须先确认双方都具备发送和接收数据的能力。这个确认过程就是三次握手。

### 三次握手中的关键标志

在理解三次握手之前，需要先理解两个常见标志。

#### SYN

`SYN` 是 `Synchronize Sequence Numbers` 的缩写，意思是同步序列号。

它表示发起连接请求。

可以理解为：

```java
我想和你建立连接
```

#### ACK

`ACK` 是 `Acknowledgment` 的缩写，意思是确认。

它表示确认收到了对方的数据或请求。

可以理解为：

```java
我收到了
```

### 三次握手的过程

假设客户端要和服务器建立 TCP 连接。

#### 第一次握手：客户端发送 SYN

客户端向服务器发送连接请求：

```java
客户端 -> 服务器：SYN
```

含义是：

```java
服务器，我想和你建立连接。
```

此时客户端进入等待服务器确认的状态。

#### 第二次握手：服务器返回 SYN + ACK

服务器收到客户端的连接请求后，向客户端返回：

```java
服务器 -> 客户端：SYN + ACK
```

含义是：

```java
我收到了你的请求，我也同意和你建立连接。
```

其中：

- `ACK` 表示确认收到了客户端的请求；
- `SYN` 表示服务器也向客户端发起连接确认。

#### 第三次握手：客户端返回 ACK

客户端收到服务器的响应后，再向服务器发送确认：

```java
客户端 -> 服务器：ACK
```

含义是：

```java
我也收到了你的确认，现在可以开始通信了。
```

服务器收到这个确认后，双方连接正式建立，可以开始传输数据。

#### 三次握手生活类比

三次握手类似于打电话前的确认过程：

```java
小明：喂，听得到吗？
小美：听得到，你听得到我吗？
小明：我也听得到，开始说吧。
```

三次确认完成后，双方都知道：

1. 自己能发送数据；
2. 自己能接收数据；
3. 对方能发送数据；
4. 对方能接收数据。

### 为什么 TCP 建立连接需要三次握手

三次握手的核心目的是：确认双方的发送能力和接收能力都正常。

#### 第一次握手后

服务器可以知道：

```java
客户端能发送数据
服务器能接收数据
```

但是客户端还不知道服务器是否能接收，也不知道服务器是否能发送。

#### 第二次握手后

客户端可以知道：

```java
客户端能发送数据
客户端能接收数据
服务器能发送数据
服务器能接收数据
```

但是服务器还不知道客户端是否能接收服务器的响应。

#### 第三次握手后

服务器可以知道：

```java
客户端能接收数据
```

至此，双方都确认了彼此的发送和接收能力，连接才能可靠建立。

#### 为什么不能只用两次握手

如果只用两次握手，可能出现“历史连接请求”导致的资源浪费问题。

假设：

1. 客户端发送了一个连接请求 `SYN`；
2. 这个请求由于网络问题，在路上滞留了很久；
3. 客户端等不到响应，于是重新发送了新的连接请求；
4. 新请求正常建立并完成通信；
5. 过了一会儿，旧的连接请求突然到达服务器。

如果只需要两次握手，服务器收到旧请求后，只要回复确认，就会认为连接已经建立。此时服务器会为这个连接分配资源，并等待客户端发送数据。

但是客户端并不知道这个旧连接的存在，也不会使用它。服务器就会白白浪费资源。

三次握手可以避免这个问题。因为旧请求到达服务器后，服务器虽然会回复，但客户端收到这个莫名其妙的响应后，不会再发送第三次确认。服务器收不到最终确认，就不会真正建立有效连接。

## 四次挥手

四次挥手是 TCP 断开连接的过程。

TCP 连接是全双工的，也就是说，双方都可以同时发送和接收数据。

因此，断开连接时，需要分别关闭两个方向的数据传输。

### FIN 标志

`FIN` 表示结束连接请求。

可以理解为：

```java
我这边的数据发送完了，我想关闭连接。
```

注意，发送 `FIN` 只表示当前这一方不再发送数据，但它仍然可以继续接收对方的数据。

### 四次挥手的过程

假设客户端主动断开连接。

#### 第一次挥手：客户端发送 FIN

客户端向服务器发送：

```java
客户端 -> 服务器：FIN
```

含义是：

```java
我的数据发完了，我想关闭从我到你的发送方向。
```

此时客户端不再向服务器发送数据，但仍然可以接收服务器的数据。

#### 第二次挥手：服务器返回 ACK

服务器收到客户端的 `FIN` 后，返回：

```java
服务器 -> 客户端：ACK
```

含义是：

```java
我知道你不再发送数据了。
```

但是服务器此时可能还有数据没有发送完，所以不能立刻关闭连接。

#### 第三次挥手：服务器发送 FIN

当服务器剩余数据也发送完之后，服务器再向客户端发送：

```java
服务器 -> 客户端：FIN
```

含义是：

```java
我这边的数据也发完了，我也准备关闭连接。
```

#### 第四次挥手：客户端返回 ACK

客户端收到服务器的 `FIN` 后，返回：

```java
客户端 -> 服务器：ACK
```

含义是：

```java
我收到了，你可以关闭了。
```

至此，TCP 连接关闭流程完成。

### 四次挥手生活类比

四次挥手类似于两个人打电话结束时的道别：

```java
小明：我说完了，我准备挂了。
小美：好的，我知道你说完了。
小美：我这边也说完了，我也准备挂了。
小明：好的，再见。
```

这说明双方都确认自己没有数据要发送，也确认对方已经知道连接要断开。

### 为什么断开连接需要四次挥手

原因是 TCP 是全双工通信。

全双工意味着：

```java
客户端可以向服务器发送数据
服务器也可以向客户端发送数据
```

这两个方向是相对独立的。

客户端发送 `FIN`，只能说明：

```java
客户端 -> 服务器 这个方向关闭
```

但不能说明：

```java
服务器 -> 客户端 这个方向也关闭
```

服务器收到客户端的 `FIN` 后，可能还有数据要继续发送给客户端。因此服务器需要先回复 `ACK`，表示“我知道你要关闭了”。等服务器自己的数据也发送完，再发送 `FIN`，表示“我也要关闭了”。

所以断开连接通常需要四次挥手。

### 2MSL 等待

在 TCP 四次挥手中，主动关闭连接的一方在发送最后一次 `ACK` 后，通常不会立刻释放连接，而是会等待一段时间，这个时间通常称为 `2MSL`。

#### 什么是 MSL

`MSL` 的英文全称是 `Maximum Segment Lifetime`，中文可以理解为最大报文段生存时间。

它表示一个 TCP 报文段在网络中能够存活的最长时间。

如果一个数据包在网络中停留太久，超过了 MSL，就会被丢弃。

#### 什么是 2MSL

`2MSL` 可以简单理解为：

```java
一个 TCP 报文在网络中来回一趟所允许的最大时间
```

主动关闭连接的一方等待 `2MSL`，主要是为了保证连接能够可靠关闭，并让网络中旧连接的数据包自然消失。

#### 为什么要等待 2MSL

##### 确保最后一个 ACK 能被对方收到

四次挥手最后一步是客户端向服务器发送 `ACK`。

如果这个 `ACK` 在网络中丢失，服务器会认为自己发送的 `FIN` 没有被确认，于是会重新发送 `FIN`。

如果客户端立刻关闭，不再等待，那么它就无法再次响应服务器重发的 `FIN`。

等待 `2MSL` 后，如果服务器重发 `FIN`，客户端还能再次发送 `ACK`，保证服务器可以正常关闭连接。

##### 让旧连接的数据包从网络中消失

网络中可能还残留着属于本次连接的旧数据包。

如果客户端立刻关闭连接，并且很快用相同的地址和端口建立新连接，旧数据包可能会被误认为是新连接的数据，造成混乱。

等待 `2MSL` 可以让旧连接中残留的数据包在网络中自然过期，避免影响下一次连接。

#### 2MSL 生活类比

可以把 2MSL 理解为挂电话后的短暂停留：

```java
小明：好的，再见。
```

说完以后，小明没有立刻离开，而是等了一会儿。

这样做有两个目的：

1. 如果小美没听到“再见”，又问一遍“小明你还在吗”，小明还能回答；
2. 等之前通话中延迟的声音彻底消失，不影响下一次通话。

## 基于 TCP 协议的编程

TCP 是一种面向连接、可靠的传输层协议。基于 TCP 的网络程序通常采用客户端和服务器端模型：

```java
客户端 Client  <------ TCP连接 ------>  服务器 Server
```

客户端主动连接服务器，服务器被动等待客户端连接。连接建立之后，客户端和服务器之间就可以通过输入流和输出流进行数据传输。

在 Java 中，基于 TCP 的编程主要使用两个类：

```java
Socket        // 客户端套接字
ServerSocket  // 服务器端套接字
```

### TCP 协议编程概述

在网络通信中，第一次主动发起通信的程序称为客户端，第一次等待连接的程序称为服务器端。

例如：

```java
客户端主动连接服务器
服务器等待客户端连接
```

一旦 TCP 连接建立成功，客户端和服务器之间就可以互相发送数据。此时二者之间只是角色上不同，本质上都是通过 Socket 进行通信。

TCP 通信的基本过程如下：

1. 服务器启动，绑定一个端口；
2. 服务器等待客户端连接；
3. 客户端根据服务器 IP 和端口发起连接；
4. 服务器接收连接，得到一个与客户端通信的 Socket；
5. 双方通过 Socket 获取输入流和输出流；
6. 通过 IO 流发送和接收数据；
7. 通信结束后关闭 Socket。

### Socket 和 ServerSocket 的关系

在 TCP 编程中，客户端和服务器端使用的类不同。

服务器端使用：

```java
ServerSocket
```

客户端使用：

```java
Socket
```

它们的关系可以理解为：

```java
ServerSocket：负责监听端口、等待客户端连接
Socket：负责和对方进行真正的数据通信
```

服务器端的 `ServerSocket` 并不直接用来读写客户端数据。它的主要作用是监听端口，并通过 `accept()` 方法接收客户端连接。

当客户端连接成功后，服务器端会得到一个新的 `Socket` 对象。这个 `Socket` 才是真正用于和客户端通信的对象。

### Socket 类

`Socket` 类用于实现客户端套接字，也表示两台机器之间通信的一个端点。

客户端通过 `Socket` 主动连接服务器。

#### Socket 构造方法

常用构造方法如下：

```java
public Socket(String host, int port) throws IOException
```

含义是：创建一个客户端套接字，并连接到指定主机的指定端口。

例如：

```java
Socket clientSocket = new Socket("127.0.0.1", 8888);
```

表示客户端连接本机 `8888` 端口上的服务器程序。

也可以使用 `InetAddress`：

```java
public Socket(InetAddress address, int port) throws IOException
```

#### Socket 常用方法

| 方法                | 作用                                |
| ------------------- | ----------------------------------- |
| `getInetAddress()`  | 获取远程主机的 IP 地址              |
| `getInputStream()`  | 获取输入流，用于接收对方发送的数据  |
| `getOutputStream()` | 获取输出流，用于向对方发送数据      |
| `shutdownInput()`   | 禁用输入流                          |
| `shutdownOutput()`  | 禁用输出流                          |
| `close()`           | 关闭 Socket，通常也会关闭相关 IO 流 |

#### Socket 中输入流和输出流的方向

对于当前程序来说：

```java
getInputStream()  = 读取对方发来的数据
getOutputStream() = 向对方发送数据
```

例如客户端中：

```java
clientSocket.getOutputStream()
```

表示客户端向服务器发送数据。

服务器端中：

```java
clientSocket.getInputStream()
```

表示服务器接收客户端发送过来的数据。

### ServerSocket 类

`ServerSocket` 类用于实现服务器端套接字。

服务器端程序需要先创建 `ServerSocket`，并绑定一个端口号。客户端连接时，就是连接这个端口。

#### ServerSocket 构造方法

常用构造方法如下：

```java
public ServerSocket(int port) throws IOException
```

例如：

```java
ServerSocket serverSocket = new ServerSocket(8888);
```

表示服务器启动后，占用当前计算机的 `8888` 端口，等待客户端连接。

#### ServerSocket 常用方法

| 方法               | 作用                                              |
| ------------------ | ------------------------------------------------- |
| `accept()`         | 监听并接收客户端连接，返回与客户端通信的 `Socket` |
| `getInetAddress()` | 获取服务器套接字绑定的本地地址                    |
| `close()`          | 关闭服务器套接字                                  |

其中，最重要的是 `accept()` 方法。

#### accept() 方法

`accept()` 用于等待客户端连接。

```java
Socket clientSocket = serverSocket.accept();
```

这个方法是阻塞方法。

所谓阻塞，就是程序执行到这里时，如果没有客户端连接，服务器线程会一直等待，不会继续向下执行。

只有当客户端连接到服务器后，`accept()` 才会返回一个 `Socket` 对象。服务器后续就通过这个 `Socket` 和客户端通信。

#### 端口占用问题

服务器端启动时，需要绑定一个端口。

例如：

```java
int port = 8888;
ServerSocket serverSocket = new ServerSocket(port);
```

如果当前电脑上已经有其他程序占用了 `8888` 端口，那么再次绑定该端口时会失败，常见异常是：

```java
java.net.BindException: Address already in use
```

含义是：地址已经被占用。

测试端口是否被占用的代码：

```java
import java.net.ServerSocket;

public class PortTest {
    public static void main(String[] args) {
        int port = 8888;

        try (ServerSocket serverSocket = new ServerSocket(port)) {
            // 如果能创建成功，说明当前端口可以绑定
        } catch (Exception e) {
            // 如果端口已被占用，通常会抛出 BindException
            e.printStackTrace();
        }
    }
}
```

> **注意**
>
> 同一台计算机上的同一个端口，同一时刻通常只能被一个服务端程序占用。

### TCP 单向通信

TCP 单向通信指的是：客户端向服务器发送消息，服务器只负责接收和打印消息，不给客户端回复。

这种通信模型适合理解 TCP 最基础的数据发送过程。

#### TCP 单向通信流程

服务器端步骤：

1. 创建 `ServerSocket`，绑定端口；
2. 调用 `accept()` 等待客户端连接；
3. 连接成功后，得到客户端对应的 `Socket`；
4. 通过 `Socket` 获取输入流；
5. 读取客户端发送的数据；
6. 关闭资源。

客户端步骤：

1. 创建 `Socket`，指定服务器 IP 和端口；
2. 通过 `Socket` 获取输出流；
3. 向服务器发送数据；
4. 刷新输出流；
5. 关闭资源。

##### 单向通信：服务器端代码

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.net.ServerSocket;
import java.net.Socket;
import java.text.SimpleDateFormat;
import java.util.Date;

public class Server {
    public static void main(String[] args) {
        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss SSS");

        int port = 8888;

        // 创建 ServerSocket，表示服务器启动并绑定 8888 端口
        try (ServerSocket serverSocket = new ServerSocket(port)) {
            System.out.println(sdf.format(new Date()) + "：服务器已启动，端口号：" + port);

            // 服务器持续接收客户端请求
            while (true) {
                // accept() 会阻塞等待客户端连接
                // 一旦有客户端连接成功，就返回一个 Socket
                try (Socket clientSocket = serverSocket.accept();

                     // 通过客户端 Socket 获取输入流，读取客户端发送的数据
                     BufferedReader br = new BufferedReader(
                             new InputStreamReader(clientSocket.getInputStream()))) {

                    String msg;

                    // readLine() 按行读取客户端发送的消息
                    // 如果客户端关闭连接，readLine() 可能返回 null
                    while ((msg = br.readLine()) != null) {
                        System.out.println(sdf.format(new Date())
                                + " 服务器接收到客户端的一条消息：" + msg);
                    }

                } catch (Exception e) {
                    e.printStackTrace();
                }
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这段代码中，服务器的核心是：

```java
Socket clientSocket = serverSocket.accept();
```

它表示服务器接收到了一个客户端连接。

然后通过：

```java
clientSocket.getInputStream()
```

获取输入流，读取客户端发来的消息。

##### 单向通信：客户端代码

```java
import java.io.BufferedWriter;
import java.io.OutputStreamWriter;
import java.net.Socket;
import java.util.Scanner;

public class Client {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // 127.0.0.1 表示本机地址，也可以写 localhost
        String ip = "127.0.0.1";
        int port = 8888;

        // 创建 Socket，主动连接服务器
        try (Socket clientSocket = new Socket(ip, port);

             // 获取输出流，用于向服务器发送消息
             BufferedWriter writer = new BufferedWriter(
                     new OutputStreamWriter(clientSocket.getOutputStream()))) {

            while (true) {
                System.out.print("请输入消息，这个消息即将发送给服务器：");

                // 从键盘接收用户输入
                String msg = scanner.next();

                // 将消息写入输出流
                writer.write(msg);

                // 写入换行符，配合服务器端 readLine() 读取
                writer.newLine();

                // 刷新缓冲区，确保消息真正发送出去
                writer.flush();
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

客户端的核心代码是：

```java
Socket clientSocket = new Socket("127.0.0.1", 8888);
```

这行代码会主动连接服务器。

如果服务器没有启动，或者服务器没有监听 `8888` 端口，客户端连接会失败。

#### 为什么要先启动服务器

TCP 通信中，客户端是主动连接的一方，服务器是等待连接的一方。

因此，必须先启动服务器，再启动客户端。

如果先启动客户端，客户端执行：

```java
new Socket("127.0.0.1", 8888);
```

时，会尝试连接本机 `8888` 端口。

如果此时服务器还没有启动，`8888` 端口上没有程序等待连接，客户端就会连接失败。

常见异常是：

```java
java.net.ConnectException: Connection refused
```

### TCP 双向通信

TCP 双向通信指的是：客户端可以向服务器发送消息，服务器也可以向客户端回复消息。

因为 TCP 是全双工协议，所以双方都可以同时具备输入流和输出流。

#### TCP 双向通信流程

服务器端

1. 创建 `ServerSocket`；
2. 调用 `accept()` 等待客户端连接；
3. 获取输入流，读取客户端消息；
4. 获取输出流，向客户端回复消息；
5. 循环处理消息。

客户端

1. 创建 `Socket` 连接服务器；
2. 获取输出流，向服务器发送消息；
3. 获取输入流，接收服务器回复；
4. 循环发送和接收消息。

##### 双向通信：服务器端代码

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.ServerSocket;
import java.net.Socket;
import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.Scanner;

public class Server {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss SSS");

        int port = 8888;

        System.out.println(sdf.format(new Date()) + "：服务器已启动，端口号：" + port);

        try (ServerSocket serverSocket = new ServerSocket(port);

             // 当前写法只接收一个客户端连接
             Socket clientSocket = serverSocket.accept();

             // 输入流：读取客户端发送的数据
             BufferedReader br = new BufferedReader(
                     new InputStreamReader(clientSocket.getInputStream()));

             // 输出流：向客户端发送数据
             BufferedWriter writer = new BufferedWriter(
                     new OutputStreamWriter(clientSocket.getOutputStream()))) {

            while (true) {
                // 服务器接收客户端消息
                String fromClientMsg = br.readLine();

                System.out.println(sdf.format(new Date())
                        + " 接收到客户端的消息：" + fromClientMsg);

                // 服务器向客户端回复消息
                System.out.print("请输入你要发给客户端的消息：");
                String sendClientMsg = scanner.next();

                writer.write(sendClientMsg);
                writer.newLine();
                writer.flush();
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这段代码中，服务器既有输入流，也有输出流：

```java
BufferedReader br = new BufferedReader(
        new InputStreamReader(clientSocket.getInputStream()));

BufferedWriter writer = new BufferedWriter(
        new OutputStreamWriter(clientSocket.getOutputStream()));
```

输入流用于接收客户端消息，输出流用于给客户端回复消息。

##### 双向通信：客户端代码

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.Socket;
import java.util.Scanner;

public class Client {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        String ip = "127.0.0.1";
        int port = 8888;

        try (Socket clientSocket = new Socket(ip, port);

             // 输出流：向服务器发送消息
             BufferedWriter writer = new BufferedWriter(
                     new OutputStreamWriter(clientSocket.getOutputStream()));

             // 输入流：接收服务器回复
             BufferedReader br = new BufferedReader(
                     new InputStreamReader(clientSocket.getInputStream()))) {

            while (true) {
                System.out.print("请输入发送给服务器的消息：");
                String sendMsgToServer = scanner.next();

                writer.write(sendMsgToServer);
                writer.newLine();
                writer.flush();

                // 接收服务器的回复
                String msgFromServer = br.readLine();

                System.out.println("客户端收到了来自服务器的消息：" + msgFromServer);
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

客户端发送消息后，会调用：

```java
String msgFromServer = br.readLine();
```

等待服务器回复。

这说明当前客户端和服务器的通信模式是：

```java
客户端发送一句
服务器回复一句
客户端再发送一句
服务器再回复一句
```

#### 双向通信中的阻塞问题

TCP 编程中，读取数据的方法通常会阻塞。

例如：

```java
br.readLine()
```

如果对方没有发送一行完整数据，当前线程会一直等待。

因此，如果客户端和服务器都同时等待对方发送数据，就可能出现“互相等待”的情况。

例如：

```java
客户端等待服务器回复
服务器也等待客户端继续发送
```

这时程序就会卡住。

所以，在设计 TCP 通信流程时，必须明确：

1. 谁先发送；
2. 谁先接收；
3. 什么时候结束一条消息；
4. 什么时候关闭连接。

### TCP 多客户端通信

前面的双向通信服务器端代码只能处理一个客户端。

原因是它把 `accept()` 写在了资源创建处，只接收了一次连接：

```java
Socket clientSocket = serverSocket.accept();
```

如果只有一个线程处理这个客户端，并且一直和这个客户端通信，那么后续客户端就无法被及时处理。

要让服务器同时处理多个客户端，常见方式是：

```java
主线程负责 accept() 接收客户端连接
每接收到一个客户端，就启动一个新线程处理该客户端
```

#### 多客户端服务器端代码

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.net.ServerSocket;
import java.net.Socket;
import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.Scanner;

public class Server {
    public static void main(String[] args) throws Exception {
        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss SSS");

        int port = 8888;

        System.out.println(sdf.format(new Date()) + "：服务器已启动，端口号：" + port);

        ServerSocket serverSocket = new ServerSocket(port);

        // 主线程持续接收不同客户端的请求
        while (true) {
            Socket clientSocket = serverSocket.accept();

            // 每接收到一个客户端，就启动一个线程单独处理
            new Thread(new ClientHandler(clientSocket)).start();
        }
    }
}

class ClientHandler implements Runnable {

    private Socket clientSocket;

    public ClientHandler(Socket clientSocket) {
        this.clientSocket = clientSocket;
    }

    @Override
    public void run() {
        Scanner scanner = new Scanner(System.in);
        SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss SSS");

        // 每个线程负责和一个客户端通信
        try (BufferedReader br = new BufferedReader(
                     new InputStreamReader(clientSocket.getInputStream()));

             BufferedWriter writer = new BufferedWriter(
                     new OutputStreamWriter(clientSocket.getOutputStream()))) {

            while (true) {
                // 接收客户端消息
                String fromClientMsg = br.readLine();

                System.out.println(sdf.format(new Date())
                        + " 接收到客户端的消息：" + fromClientMsg);

                // 给客户端回复消息
                System.out.print("请输入你要发给客户端的消息：");
                String sendClientMsg = scanner.next();

                writer.write(sendClientMsg);
                writer.newLine();
                writer.flush();
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这段代码的核心是：

```java
while (true) {
    Socket clientSocket = serverSocket.accept();
    new Thread(new ClientHandler(clientSocket)).start();
}
```

服务器主线程不负责和客户端长期聊天，只负责不断接收新的客户端连接。

每个客户端连接交给一个独立线程处理。

#### 多客户端通信的执行过程

假设有两个客户端 `Client1` 和 `Client2`。

执行过程如下：

1. 服务器启动，监听 `8888` 端口；
2. `Client1` 连接服务器；
3. 服务器 `accept()` 返回 `Client1` 对应的 `Socket`；
4. 服务器启动线程 `Thread-0` 处理 `Client1`；
5. 主线程继续回到 `accept()`，等待下一个客户端；
6. `Client2` 连接服务器；
7. 服务器 `accept()` 返回 `Client2` 对应的 `Socket`；
8. 服务器启动线程 `Thread-1` 处理 `Client2`；
9. 两个客户端分别由不同线程处理，互不影响。

#### 一个客户端一个线程的优缺点

这种写法简单直观，适合初学阶段理解多客户端通信。

优点：

1. 代码容易理解；
2. 一个客户端阻塞时，不影响服务器继续接收其他客户端；
3. 每个客户端有独立线程处理。

缺点：

1. 客户端数量很多时，会创建大量线程；
2. 线程太多会增加系统资源消耗；
3. 不适合高并发生产环境。

实际项目中，服务器通常会使用线程池、NIO 或 Netty 等方式处理大量连接。

#### shutdownInput() 和 shutdownOutput()

`Socket` 还提供了两个半关闭方法：

```java
shutdownInput()
shutdownOutput()
```

##### shutdownInput()

```java
socket.shutdownInput();
```

表示关闭当前 Socket 的输入方向。当前程序不再从这个 Socket 读取数据。

##### shutdownOutput()

```java
socket.shutdownOutput();
```

表示关闭当前 Socket 的输出方向。当前程序不再向这个 Socket 写出数据。

和 `close()` 不同，`shutdownInput()` 和 `shutdownOutput()` 只关闭一个方向，而不是整个 Socket。
