## 反射概述

反射是 Java 中非常重要的一种机制。它允许程序在运行期间动态获取类的信息，并且可以动态创建对象、访问属性、调用方法、操作构造方法。

正常情况下，写代码时一般是先知道类，再创建对象，再调用方法。

例如：

```java
Student student = new Student();
student.setName("jack");
```

这种方式是在编译阶段就明确知道要使用 `Student` 类。

而反射则是另一种方式：程序可以在运行期间根据类名字符串获取类的信息，然后再动态操作这个类。

例如：

```java
Class<?> clazz = Class.forName("com.jkweilai.Student");
```

这就是反射的入口。

### 反射的定义

Java 的反射机制是指：在程序运行期间，可以动态获取类的信息，并且可以动态操作类中的成员。

通过反射，程序可以做到：

1. 获取任意一个类的 `Class` 对象；
2. 获取类的成员变量；
3. 获取类的方法；
4. 获取类的构造方法；
5. 创建对象；
6. 调用对象的方法；
7. 访问或修改对象的属性；
8. 获取类的父类、接口、注解等信息。

也就是说，反射可以让程序在运行时“看清楚”一个类的内部结构，并且可以进一步操作它。

### 反射的理解

反射本质上是一个“反着来”的过程。

普通创建对象的过程是：

```java
类  ->  对象
```

例如：

```java
Student student = new Student();
```

程序员直接写出类名 `Student`，然后通过 `new` 创建对象。

反射的过程是：

```java
Class对象  ->  类的信息  ->  对象 / 属性 / 方法 / 构造方法
```

也就是说，反射不是一开始就直接写死某个类，而是先拿到这个类对应的 `Class` 对象，再通过 `Class` 对象获取类的各种结构信息。

### Class 对象是什么

在 Java 中，每一个被加载到 Java 虚拟机中的类，都会对应一个 `Class` 对象。

可以理解为：

```java
一个类的字节码信息，在 JVM 中对应一个 Class 对象
```

例如，`String.class` 表示的不是某一个字符串对象，而是 `String` 这个类型本身的信息。

```java
Class stringClass = String.class;
```

这个 `stringClass` 对象代表的是 `java.lang.String` 这个类。

通过它，可以获取 `String` 类的方法、属性、构造方法、父类、接口等信息。

### 反射中的核心类

反射相关的核心类主要有以下几个：

| 类            | 所在包              | 作用                 |
| ------------- | ------------------- | -------------------- |
| `Class`       | `java.lang`         | 表示一个类或一种类型 |
| `Field`       | `java.lang.reflect` | 表示类中的成员变量   |
| `Method`      | `java.lang.reflect` | 表示类中的成员方法   |
| `Constructor` | `java.lang.reflect` | 表示类中的构造方法   |

其中，`Class` 是反射的入口。

只有先获得某个类的 `Class` 对象，才能继续获取这个类的属性、方法和构造方法。

### 反射的优点

反射的优点主要是灵活。

#### 提高程序扩展性

通过反射，程序可以在运行期间根据配置文件、类名字符串等信息动态加载类，而不需要在代码中写死具体类名。

例如，框架中经常会出现这样的配置：

```java
com.jkweilai.service.UserService
```

程序可以读取这个类名，然后通过反射创建对象。

#### 降低耦合度

普通写法中，如果直接写：

```java
UserService service = new UserService();
```

代码就和 `UserService` 类绑定得很紧。

而反射可以根据字符串动态加载类，减少代码对具体类的直接依赖。

这也是很多框架底层会大量使用反射的原因。

#### 可以动态操作对象

反射可以在运行时获取对象的信息，并调用对象的方法。

即使在编译阶段不知道具体类是什么，也可以在运行阶段根据实际情况处理。

### 反射的缺点

反射虽然灵活，但也有明显缺点。

#### 性能较低

反射是在运行期间动态解析类信息、方法信息和属性信息，因此通常比直接调用方法性能低。

例如，直接调用：

```java
student.getName();
```

通常比通过反射调用：

```java
method.invoke(student);
```

效率更高。

所以反射一般不会用于普通业务逻辑中的大量高频调用，而更多用于框架底层、工具类、配置加载等场景。

#### 可读性较差

反射代码通常依赖字符串形式的类名、方法名、属性名。

例如：

```java
Class<?> clazz = Class.forName("com.jkweilai.Student");
```

如果类名写错，编译阶段不一定能发现，可能运行时才报错。

这会让代码逻辑不如普通调用直观。

#### 可能破坏封装

Java 中的 `private` 本来用于隐藏类的内部实现细节。

但反射可以通过设置访问权限，访问私有属性、私有方法、私有构造方法。

这既是反射的强大之处，也是它危险的地方。

如果滥用反射，就会破坏封装性，让程序更难维护。

## 获得 Class 对象

反射操作的第一步是获得 `Class` 对象。

获得 `Class` 对象常见有四种方式：

1. `Class.forName("全限定类名")`
2. `类型.class`
3. `对象.getClass()`
4. `类加载器.loadClass("全限定类名")`

### 方式一：Class.forName()

`Class.forName()` 是反射中非常常用的方式。

```java
Class<?> clazz = Class.forName("java.lang.String");
```

参数必须是类的全限定类名。

所谓全限定类名，就是包含完整包名的类名。

例如：

```java
java.lang.String
com.jkweilai.javase.reflect.clazz.Student
```

如果只写：

```java
String
```

通常是不可以的，因为 Java 无法确定这个类到底在哪个包中。

#### 示例：使用 Class.forName()

```java
public class ClassTest01 {
    public static void main(String[] args) throws ClassNotFoundException {
        // stringClass 代表的是 String 类型
        Class stringClass = Class.forName("java.lang.String");

        Class stringClass2 = Class.forName("java.lang.String");

        // 同一个类在 JVM 中只会加载一次
        System.out.println(stringClass == stringClass2); // true
    }
}
```

这段代码中，两次通过：

```java
Class.forName("java.lang.String")
```

获取 `String` 类的 `Class` 对象。

最终比较结果是：

```java
true
```

说明两次获取到的是同一个 `Class` 对象。

#### Class.forName() 的特点

`Class.forName()` 有两个重要特点：

1. 需要传入全限定类名；
2. 如果类不存在，会抛出 `ClassNotFoundException`；
3. 通常会触发类的加载和初始化。

例如：

```java
Class<?> clazz = Class.forName("java.lang.String1");
```

如果类名写错，就会抛出：

```java
java.lang.ClassNotFoundException
```

### 方式二：类型.class

如果在编译阶段已经明确知道某个类型，可以通过 `类型.class` 获取它的 `Class` 对象。

```java
Class<String> clazz = String.class;
```

这种方式简单、安全、性能高。

#### 示例：使用 类型.class

```java
public class ClassTest02 {
    public static void main(String[] args) throws Exception {
        // Java 中任何一种类型，包括基本类型和引用类型，都有 .class 属性
        Class stringClass1 = String.class;

        Class stringClass2 = Class.forName("java.lang.String");

        System.out.println(stringClass1 == stringClass2); // true

        // 基本数据类型的 Class 对象
        Class intClass = int.class;
        Class booleanType = boolean.class;
        Class doubleType = double.class;

        // 数组类型的 Class 对象
        Class<double[]> doubleArrayType = double[].class;
    }
}
```

这段代码说明：

1. `String.class` 和 `Class.forName("java.lang.String")` 得到的是同一个 `Class` 对象；
2. 基本数据类型也有对应的 `Class` 对象；
3. 数组类型也有对应的 `Class` 对象。

#### 类型.class 的特点

`类型.class` 的特点是：

1. 写法简单；
2. 不容易写错；
3. 不需要通过字符串查找类；
4. 编译阶段即可检查类型是否存在；
5. 性能较好。

但是，它的前提是：写代码时必须已经知道具体类型。

例如：

```java
String.class
int.class
double[].class
```

这些类型都是在写代码时明确写出来的。

### 方式三：对象.getClass()

如果已经有了某个对象，可以通过对象的 `getClass()` 方法获取该对象运行时所属类的 `Class` 对象。

```java
Student student = new Student("jack", 20);
Class clazz = student.getClass();
```

`getClass()` 方法来自 `Object` 类，因此 Java 中所有对象都可以调用。

#### 示例：使用对象.getClass()

```java
public class ClassTest03 {
    public static void main(String[] args) {
        Student s = new Student("jack", 20);

        // 获取 Student 对象对应的运行时类型
        Class studentType = s.getClass();

        String str = "abc";

        // 获取 String 对象对应的运行时类型
        Class stringType = str.getClass();

        Class stringType2 = String.class;

        System.out.println(stringType == stringType2); // true
    }
}

class Student {
    private String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

这里：

```java
str.getClass()
```

和：

```java
String.class
```

得到的是同一个 `Class` 对象。

#### 对象.getClass() 的特点

`对象.getClass()` 的特点是：可以在运行时动态获取某个对象的真实类型。

例如：

```java
Object obj = "abc";
Class clazz = obj.getClass();
```

虽然变量 `obj` 的编译类型是 `Object`，但它实际指向的是一个 `String` 对象。

因此：

```java
obj.getClass()
```

得到的是 `String` 类的 `Class` 对象。

这在处理多态对象时很有用。

### 方式四：类加载器.loadClass()

还可以通过类加载器获取 `Class` 对象。

```java
ClassLoader classLoader = ClassLoader.getSystemClassLoader();

Class<?> clazz = classLoader.loadClass("java.lang.String");
```

这种方式也需要传入全限定类名。

#### 示例：使用类加载器获取 Class 对象

```java
public class ClassTest04 {
    public static void main(String[] args) throws Exception {
        // 获取系统类加载器对象
        ClassLoader systemClassLoader = ClassLoader.getSystemClassLoader();

        // 通过类加载器加载类
        Class stringType = systemClassLoader.loadClass("java.lang.String");

        Class stringType2 = "abc".getClass();

        System.out.println(stringType == stringType2); // true
    }
}
```

这段代码中：

```java
systemClassLoader.loadClass("java.lang.String")
```

和：

```java
"abc".getClass()
```

得到的都是 `String` 类型对应的 `Class` 对象。

#### Class.forName() 和 ClassLoader.loadClass() 的区别

`Class.forName()` 和 `ClassLoader.loadClass()` 都可以根据全限定类名获取 `Class` 对象，但二者有一个重要区别：

```java
Class.forName() 通常会触发类初始化
ClassLoader.loadClass() 默认只加载类，不会主动执行静态代码块
```

示例：

```java
class MyClass {
    static {
        System.out.println("静态代码块执行了！");
    }
}
```

使用类加载器：

```java
ClassLoader systemClassLoader = ClassLoader.getSystemClassLoader();

Class myClassType = systemClassLoader.loadClass(
        "com.jkweilai.javase.reflect.clazz.MyClass"
);
```

这种方式会加载 `MyClass`，但默认不会执行静态代码块。

使用 `Class.forName()`：

```java
Class myClassType2 = Class.forName(
        "com.jkweilai.javase.reflect.clazz.MyClass"
);
```

这种方式会加载并初始化类，因此会执行静态代码块。

输出：

```java
静态代码块执行了！
```

> **结论**
>
> `Class.forName()` 更常用于反射场景；
> `ClassLoader.loadClass()` 更偏向类加载器层面的加载动作。
> 二者都能获得 `Class` 对象，但是否触发类初始化存在差异。

### Class 可以表示哪些结构

在 Java 中，`Class` 不只可以表示普通类，还可以表示任意 Java 类型。

例如：

```java
// 基本数据类型
Class<Integer> cls01 = int.class;

// 一维数组类型
Class<int[]> cls02 = int[].class;

// 二维数组类型
Class<int[][]> cls03 = int[][].class;

// void 类型
Class<Void> cls04 = void.class;

// 包装类
Class<Integer> cls05 = Integer.class;

// 自定义类
Class<Tiger> cls06 = Tiger.class;

// 接口
Class<AutoCloseable> cls07 = AutoCloseable.class;

// 注解
Class<Override> cls08 = Override.class;

// 枚举
Class<ElementType> cls09 = ElementType.class;
```

也就是说，`Class` 可以表示：

1. 普通类；
2. 接口；
3. 枚举；
4. 注解；
5. 基本数据类型；
6. 数组类型；
7. `void`；
8. 包装类；
9. 内部类等。

### 一个类只有一份 Class 对象

对于同一个类来说，在同一个类加载器加载的前提下，它在 JVM 中通常只有一份 `Class` 对象。

例如：

```java
Class c1 = String.class;
Class c2 = Class.forName("java.lang.String");
Class c3 = "abc".getClass();

System.out.println(c1 == c2); // true
System.out.println(c2 == c3); // true
```

虽然获取方式不同，但它们最终指向的都是 `String` 类在 JVM 中对应的那一份 `Class` 对象。

#### 为什么同一个类只有一份 Class 对象

Java 程序运行时，类的字节码文件会被类加载器加载到 JVM 中。

同一个类被加载后，它的结构信息会保存在方法区中，并对应一个 `Class` 对象。

这个 `Class` 对象就代表该类的运行时类型信息。

因此，对于同一个类而言：

```java
String.class
Class.forName("java.lang.String")
"abc".getClass()
```

得到的都是同一个 `Class` 对象。

> **注意**
>
> `ClassLoader.loadClass()` 默认只负责加载类，不一定触发类初始化。
>
> ```
> ClassLoader.getSystemClassLoader().loadClass("com.jkweilai.MyClass");
> ```
>
> 如果只是加载类，静态代码块可能不会执行。
>
> 而：
>
> ```
> Class.forName("com.jkweilai.MyClass");
> ```
>
> 通常会触发类初始化，从而执行静态代码块。

## 通过反射创建对象

前面已经学习了获取 `Class` 对象的几种方式。获得 `Class` 对象之后，就可以进一步使用反射机制创建对象。

普通创建对象的方式是：

```java
User user = new User();
```

这种写法属于硬编码。程序在编译阶段就已经明确写死了要创建 `User` 对象。

而反射创建对象的方式是：

```java
Class clazz = Class.forName("com.jkweilai.javase.reflect.instance.User");
Object obj = clazz.newInstance();
```

这种写法不是直接 `new User()`，而是先根据类名字符串获取 `Class` 对象，再通过 `Class` 对象动态创建对象。

### 普通 new 对象和反射创建对象的区别

普通方式：

```java
User user = new User();
```

特点：

1. 写法简单；
2. 性能较好；
3. 编译阶段就确定了创建哪个类的对象；
4. 类名写死在代码中，灵活性较差。

反射方式：

```java
Class clazz = Class.forName("com.jkweilai.javase.reflect.instance.User");
Object obj = clazz.newInstance();
```

特点：

1. 可以根据字符串动态决定创建哪个类的对象；
2. 灵活性更高；
3. 常用于框架、配置文件、工具类底层；
4. 性能比直接 `new` 低；
5. 代码可读性相对差一些；
6. `newInstance()` 对构造方法有要求。

### 使用 Class 的 newInstance() 创建对象

`Class` 类中提供了 `newInstance()` 方法，可以通过反射创建对象。

基本格式如下：

```java
Class clazz = Class.forName("类的全限定类名");
Object obj = clazz.newInstance();
```

其中：

```java
Class.forName("类的全限定类名")
```

用于获取目标类的 `Class` 对象。

```java
clazz.newInstance()
```

用于调用该类的无参数构造方法创建对象。

#### 示例：通过反射创建 User 对象

`User` 类：

```java
public class User {
    private String name;
    private int age;

    public User() {
    }

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "User{" +
                "name='" + name + '\'' +
                ", age=" + age +
                '}';
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

测试代码：

```java
public class InstanceTest01 {
    public static void main(String[] args) throws Exception {
        // 普通方式创建对象：类名写死在代码中
        User user = new User();
        System.out.println(user);

        // 反射方式创建对象
        // 第一步：根据全限定类名获取 Class 对象
        Class userType = Class.forName("com.jkweilai.javase.reflect.instance.User");

        // 第二步：通过 Class 对象创建实例
        // newInstance() 会调用 User 类的无参数构造方法
        Object obj = userType.newInstance();

        System.out.println(obj);
    }
}
```

执行过程：

1. `Class.forName()` 根据全限定类名加载 `User` 类；
2. 返回 `User` 类对应的 `Class` 对象；
3. `userType.newInstance()` 调用 `User` 类的无参构造方法；
4. 创建出一个 `User` 对象；
5. 由于返回值类型是 `Object`，所以用 `Object` 接收。

#### newInstance() 的本质

`clazz.newInstance()` 的本质是调用目标类的无参数构造方法创建对象。

例如：

```java
Object obj = clazz.newInstance();
```

等价于在底层尝试执行：

```java
new 目标类();
```

因此，如果目标类中有无参构造方法，就可以创建成功。

例如：

```java
public class User {
    public User() {
    }
}
```

这种类可以通过 `newInstance()` 创建对象。

#### newInstance() 的限制

`Class.newInstance()` 有明显限制。

##### 目标类必须有无参数构造方法

如果目标类没有无参构造方法，使用 `newInstance()` 创建对象会失败。

例如：

```java
public class Person {
    public Person(String name) {
        System.out.println("有参数构造器");
    }
}
```

这个 `Person` 类只有有参构造方法，没有无参构造方法。

测试代码：

```java
public class InstanceTest02 {
    public static void main(String[] args) throws Exception {
        // 获取 Person 类的 Class 对象
        Class personType = Class.forName("com.jkweilai.javase.reflect.instance.Person");

        // newInstance() 依赖无参数构造方法
        // 如果 Person 没有无参构造方法，这里会创建失败
        Object obj = personType.newInstance();

        System.out.println(obj);
    }
}
```

如果 `Person` 类没有无参构造方法，就无法通过 `Class.newInstance()` 正常创建对象。

##### 无参构造方法的访问权限必须足够

`newInstance()` 默认只能调用有访问权限的无参构造方法。

如果无参构造方法是私有的：

```java
public class User {
    private User() {
    }
}
```

直接使用：

```java
clazz.newInstance();
```

可能会因为访问权限不足而创建失败。

##### 高版本 JDK 中不推荐继续使用 Class.newInstance()

`Class.newInstance()` 在较高版本的 JDK 中已经不推荐使用。

更推荐的写法是通过 `Constructor` 创建对象：

```java
Object obj = clazz.getDeclaredConstructor().newInstance();
```

这种方式更加明确，也能更好地处理构造方法相关的异常。

不过在初学反射时，`Class.newInstance()` 仍然适合用来理解“通过 Class 对象创建对象”的基本思想。

#### newInstance() 可能出现的异常

使用 `newInstance()` 创建对象时，常见异常包括：

##### ClassNotFoundException

类名写错，或者类不存在时，会抛出该异常。

```java
Class clazz = Class.forName("com.jkweilai.User1");
```

如果 `com.jkweilai.User1` 不存在，就会抛出：

```java
ClassNotFoundException
```

##### InstantiationException

如果目标类无法被实例化，可能抛出该异常。

常见原因包括：

1. 类没有无参数构造方法；
2. 目标类型是接口；
3. 目标类型是抽象类；
4. 目标类型不能被直接实例化。

例如：

```java
Class clazz = Class.forName("java.util.List");
Object obj = clazz.newInstance();
```

`List` 是接口，不能直接创建对象。

##### IllegalAccessException

如果无参构造方法权限不足，可能抛出该异常。

例如目标类的无参构造方法是 `private`，外部无法直接访问，就可能创建失败。

### 通过配置文件动态创建对象

反射最经典的使用场景之一是：把类名写到配置文件中，程序运行时读取配置文件，然后根据类名创建对象。

这样做可以避免把具体类写死在 Java 代码中，提高程序的灵活性。

#### 硬编码创建对象的问题

普通写法：

```java
User user = new User();
```

这种方式的问题是：创建哪个类的对象已经写死在代码中。

如果将来不想创建 `User`，而想创建 `Date` 或其他类，就必须修改 Java 源代码，然后重新编译、重新运行。

例如从：

```java
User user = new User();
```

改成：

```java
Date date = new Date();
```

这就说明代码和具体类之间耦合度较高。

#### 配置文件 + 反射的思路

如果把类名写到配置文件中：

```properties
className=java.util.Date
```

Java 程序读取配置文件：

```java
String className = bundle.getString("className");
```

再根据类名动态创建对象：

```java
Class clazz = Class.forName(className);
Object obj = clazz.newInstance();
```

这样，如果以后想创建其他类的对象，只需要修改配置文件中的类名，不需要修改 Java 源代码。

#### 示例：读取配置文件并创建对象

```java
import java.util.ResourceBundle;

public class InstanceTest01 {
    public static void main(String[] args) throws Exception {
        // 读取类路径下的 bean.properties 配置文件
        // 注意：这里不写 .properties 后缀
        ResourceBundle bundle = ResourceBundle.getBundle(
                "com.jkweilai.javase.reflect.instance.bean"
        );

        // 根据 key 获取配置文件中的类名
        String className = bundle.getString("className");

        // 根据类名获取 Class 对象
        Class clazz = Class.forName(className);

        // 通过无参数构造方法创建对象
        Object obj = clazz.newInstance();

        System.out.println(obj);
    }
}
```

如果配置文件中是：

```properties
className=java.util.Date
```

那么程序运行时会创建 `java.util.Date` 对象。

如果改成：

```properties
className=com.jkweilai.javase.reflect.instance.User
```

那么程序运行时会创建 `User` 对象。

这说明：程序创建哪个对象，可以由配置文件决定，而不必修改 Java 源码。

#### 通过 FileInputStream 读取配置文件

除了 `ResourceBundle`，也可以使用 `Properties + FileInputStream` 读取配置文件。

示例：

```java
import java.io.FileInputStream;
import java.io.InputStream;
import java.util.Properties;

public class InstanceTest {
    public static void main(String[] args) {
        try {
            // 创建 Properties 集合，用来保存配置文件中的 key=value 数据
            Properties properties = new Properties();

            // 创建输入流，读取配置文件
            InputStream inputStream = new FileInputStream("classinfo.properties");

            // 加载配置文件中的数据
            properties.load(inputStream);

            // 获取配置文件中的类名
            String className = properties.getProperty("className");

            // 根据类名获取 Class 对象
            Class<?> clazz = Class.forName(className);

            // 通过反射创建对象
            Object obj = clazz.newInstance();

            System.out.println(obj);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

配置文件内容：

```properties
className=com.jkweilai.javase.reflect.instance.User
```

## 获取和操作类的结构

反射不仅可以创建对象，还可以获取一个类的完整结构信息，例如：

1. 类名；
2. 包名；
3. 父类；
4. 实现的接口；
5. 成员变量；
6. 成员方法；
7. 构造方法。

获取这些结构之后，还可以进一步操作它们：

1. 通过 `Field` 读写属性；
2. 通过 `Method` 调用方法；
3. 通过 `Constructor` 调用构造方法创建对象。

反射中常见的结构类如下：

| 类            | 含义                             |
| ------------- | -------------------------------- |
| `Class`       | 表示一个类或一种类型             |
| `Field`       | 表示属性，包括成员变量和静态变量 |
| `Method`      | 表示方法，包括成员方法和静态方法 |
| `Constructor` | 表示构造方法                     |
| `Modifier`    | 用于把修饰符数字转换成可读字符串 |
| `Parameter`   | 表示方法或构造方法中的参数       |

### 获取类的基本信息

获得 `Class` 对象后，可以通过 `Class` 类中的方法获取类的基本信息。

常用方法如下：

| 方法              | 作用                     |
| ----------------- | ------------------------ |
| `getName()`       | 获取完整类名，包含包名   |
| `getSimpleName()` | 获取简单类名，不包含包名 |
| `getPackage()`    | 获取类所在的包           |
| `getSuperclass()` | 获取父类的 `Class` 对象  |
| `getInterfaces()` | 获取当前类实现的接口数组 |
| `getModifiers()`  | 获取类的修饰符数字       |

### 示例：获取类名、包名、父类和接口

```java
public class ClassInfoTest {
    public static void main(String[] args) throws Exception {
        // 获取目标类的 Class 对象
        Class<?> clazz = Class.forName("java.lang.String");

        // 获取完整类名，包含包名
        System.out.println("完整类名：" + clazz.getName());

        // 获取简单类名，不包含包名
        System.out.println("简单类名：" + clazz.getSimpleName());

        // 获取包信息
        Package packageObj = clazz.getPackage();
        System.out.println("包名：" + packageObj.getName());

        // 获取父类
        Class<?> superClass = clazz.getSuperclass();
        System.out.println("父类：" + superClass.getName());

        // 获取实现的接口
        Class<?>[] interfaces = clazz.getInterfaces();
        for (Class<?> anInterface : interfaces) {
            System.out.println("接口：" + anInterface.getName());
        }
    }
}
```

需要注意：

```java
getName()
```

返回的是全限定类名，例如：

```java
java.lang.String
```

而：

```java
getSimpleName()
```

返回的是简单类名，例如：

```java
String
```

### 使用 Modifier 解析修饰符

反射中获取修饰符时，通常返回的是一个整数。

例如：

```java
int modifiers = clazz.getModifiers();
```

这个整数本身不直观，需要使用 `Modifier.toString()` 转换成字符串。

```java
String modifierText = Modifier.toString(modifiers);
```

完整示例：

```java
import java.lang.reflect.Modifier;

public class ModifierTest {
    public static void main(String[] args) {
        Class<?> clazz = String.class;

        // 获取类的修饰符数字
        int modifiers = clazz.getModifiers();

        // 把修饰符数字转换成字符串
        System.out.println(Modifier.toString(modifiers));
    }
}
```

修饰符数字可以理解为多个标记位的组合。

常见修饰符大致对应如下：

| 修饰符      | 数字 |
| ----------- | ---- |
| `public`    | `1`  |
| `private`   | `2`  |
| `protected` | `4`  |
| `static`    | `8`  |
| `final`     | `16` |

实际开发中不需要手动记这些数字，直接使用 `Modifier.toString()` 即可。

## 属性：Field

属性在反射中使用 `Field` 表示。

一个 `Field` 对象对应类中的一个属性，属性可以是：

1. 成员变量；
2. 静态变量；
3. 常量。

例如：

```java
public class Customer {
    public String publicField;
    protected String protectedField;
    String defaultField;
    private String privateField;

    public static final double MATH_PI = 3.14;
}
```

上面这个类中，每一个属性都可以对应一个 `Field` 对象。

### 获取属性

`Class` 中提供了获取属性的方法。

| 方法                            | 作用                                   |
| ------------------------------- | -------------------------------------- |
| `getFields()`                   | 获取当前类和父类中所有 `public` 属性   |
| `getDeclaredFields()`           | 获取当前类中声明的所有属性，不管权限   |
| `getField(String name)`         | 获取当前类或父类中的某个 `public` 属性 |
| `getDeclaredField(String name)` | 获取当前类中声明的某个属性，不管权限   |

#### getFields() 和 getDeclaredFields() 的区别

##### getFields()

```java
Field[] fields = clazz.getFields();
```

特点：

1. 只能获取 `public` 属性；
2. 可以获取当前类中的 `public` 属性，也可以获取父类中继承来的 `public` 属性；
3. 不能获取 `private`、默认权限、`protected` 属性。

##### getDeclaredFields()

```java
Field[] fields = clazz.getDeclaredFields();
```

特点：

1. 可以获取当前类中声明的所有属性；
2. 包括 `public`、`protected`、默认权限、`private`；
3. 不获取父类中声明的属性。

记忆方式：

```java
getFields()          = 当前类 + 父类 的 public 属性
getDeclaredFields()  = 当前类声明的所有属性
```

##### 示例：获取当前类的所有属性

```java
import java.lang.reflect.Field;
import java.lang.reflect.Modifier;

public class FieldTest01 {
    public static void main(String[] args) throws Exception {
        // 第一步：获取目标类的 Class 对象
        Class customerType = Class.forName(
                "com.jkweilai.javase.reflect.field.Customer"
        );

        // 第二步：获取当前类中声明的所有字段，不管权限
        Field[] fields = customerType.getDeclaredFields();

        System.out.println("字段的数量：" + fields.length);

        // 第三步：遍历每一个字段
        for (Field field : fields) {
            // 获取字段名
            System.out.println("字段名：" + field.getName());

            // 获取字段类型
            Class fieldType = field.getType();

            // 获取字段类型的完整名称
            System.out.println("字段的类型名：" + fieldType.getName());

            // 获取字段类型的简单名称
            System.out.println("字段的简单类型名：" + fieldType.getSimpleName());

            // 获取字段修饰符数字
            int modifiers = field.getModifiers();
            System.out.println("字段的修饰符数字：" + modifiers);

            // 将修饰符数字转换成字符串
            System.out.println("字段的修饰符：" + Modifier.toString(modifiers));
        }
    }
}
```

这个示例中的关键点是：

```java
Field[] fields = customerType.getDeclaredFields();
```

它可以获取当前类声明的所有属性，包括私有属性。

#### Field 常用方法

| 方法                            | 作用                            |
| ------------------------------- | ------------------------------- |
| `getName()`                     | 获取属性名                      |
| `getType()`                     | 获取属性类型，返回 `Class` 对象 |
| `getModifiers()`                | 获取属性修饰符数字              |
| `get(Object obj)`               | 获取指定对象中该属性的值        |
| `set(Object obj, Object value)` | 设置指定对象中该属性的值        |
| `setAccessible(true)`           | 取消访问检查，允许访问私有属性  |

##### 示例：拼接类中的属性结构

通过反射可以读取一个类的结构，并拼接出类似源码的字符串。

```java
import java.lang.reflect.Field;
import java.lang.reflect.Modifier;

public class FieldTest02 {
    public static void main(String[] args) throws Exception {
        StringBuilder sb = new StringBuilder();

        // 获取目标类
        Class clazz = Class.forName("java.lang.Math");

        // 拼接类修饰符
        sb.append(Modifier.toString(clazz.getModifiers()));
        sb.append(" class ");

        // 拼接完整类名
        sb.append(clazz.getName());

        // 拼接父类
        sb.append(" extends ");
        Class superClass = clazz.getSuperclass();
        sb.append(superClass.getName());

        // 拼接接口
        Class[] interfaces = clazz.getInterfaces();
        if (interfaces.length > 0) {
            sb.append(" implements ");
        }

        for (int i = 0; i < interfaces.length; i++) {
            Class in = interfaces[i];

            if (i == interfaces.length - 1) {
                sb.append(in.getName());
            } else {
                sb.append(in.getName());
                sb.append(",");
            }
        }

        sb.append("{\n");

        // 获取当前类声明的所有字段
        Field[] fields = clazz.getDeclaredFields();

        for (Field field : fields) {
            sb.append("\t");

            // 字段修饰符
            sb.append(Modifier.toString(field.getModifiers()));
            sb.append(" ");

            // 字段类型
            sb.append(field.getType().getSimpleName());
            sb.append(" ");

            // 字段名
            sb.append(field.getName());

            sb.append(";\n");
        }

        sb.append("}");

        System.out.println(sb);
    }
}
```

这种代码的意义是：通过反射可以在运行时分析一个类的结构，甚至可以生成类似类源码的描述信息。

### 操作属性

获取到 `Field` 对象之后，就可以使用它读写对象中的属性。

#### 操作属性的三要素

通过反射操作成员变量，需要明确三个信息：

```java
哪个对象
哪个属性
赋什么值 / 读取什么值
```

例如普通写法：

```java
p.setName("lucy");
String name = p.getName();
```

反射写法：

```java
Field nameField = personType.getDeclaredField("name");
nameField.setAccessible(true);
nameField.set(p, "lucy");
Object value = nameField.get(p);
```

#### 示例：操作私有属性 name

```java
import java.lang.reflect.Field;

public class FieldTest03 {
    public static void main(String[] args) throws Exception {
        // 创建 Person 对象
        Person p = new Person();

        // 第一步：获取 p 对象的运行时类型
        Class personType = p.getClass();

        // 第二步：获取当前类中声明的 name 字段
        Field nameField = personType.getDeclaredField("name");

        // 第三步：打破封装，允许访问 private 属性
        nameField.setAccessible(true);

        // 第四步：给 p 对象的 name 属性赋值
        // 三要素：哪个对象、哪个属性、赋什么值
        nameField.set(p, "lucy");

        // 第五步：读取 p 对象的 name 属性值
        Object retValue = nameField.get(p);

        System.out.println(retValue);
    }
}
```

`Person` 类：

```java
public class Person {
    private String name;
    private int age;

    public Person() {
    }

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

这段代码中，`name` 是私有属性。正常情况下外部不能直接访问：

```java
p.name = "lucy"; // 错误，private 属性不能直接访问
```

但是反射可以通过：

```java
nameField.setAccessible(true);
```

取消访问检查，从而操作私有属性。

#### 操作静态属性

成员变量属于对象，因此操作成员变量时需要传入对象：

```java
field.set(对象, 值);
field.get(对象);
```

静态变量属于类，不属于某个具体对象。因此操作静态变量时，第一个参数可以传入 `null`。

```java
field.set(null, 值);
field.get(null);
```

例如：

```java
Field field = clazz.getDeclaredField("MATH_PI");
field.setAccessible(true);

Object value = field.get(null);
System.out.println(value);
```

不过，如果字段是 `public static final` 常量，实际开发中不建议通过反射修改它。常量可能被编译器内联，强行修改容易产生难以理解的结果。

## 方法：Method

方法在反射中使用 `Method` 表示。

一个 `Method` 对象对应类中的一个方法。

方法可以是：

1. 成员方法；
2. 静态方法；
3. 公开方法；
4. 私有方法；
5. 有参方法；
6. 无参方法；
7. 有返回值方法；
8. 无返回值方法。

### 获取方法

`Class` 中提供了获取方法的方法。

| 方法                                                         | 作用                                   |
| ------------------------------------------------------------ | -------------------------------------- |
| `getMethods()`                                               | 获取当前类和父类中所有 `public` 方法   |
| `getDeclaredMethods()`                                       | 获取当前类中声明的所有方法，不管权限   |
| `getMethod(String name, Class<?>... parameterTypes)`         | 获取当前类或父类中的某个 `public` 方法 |
| `getDeclaredMethod(String name, Class<?>... parameterTypes)` | 获取当前类中声明的某个方法，不管权限   |

#### getMethods() 和 getDeclaredMethods() 的区别

##### getMethods()

```java
Method[] methods = clazz.getMethods();
```

特点：

1. 只能获取 `public` 方法；
2. 可以获取当前类中的 `public` 方法，也可以获取父类中继承来的 `public` 方法；
3. 会包含 `Object` 类中的公开方法，例如 `toString()`、`equals()`、`hashCode()` 等。

##### getDeclaredMethods()

```java
Method[] methods = clazz.getDeclaredMethods();
```

特点：

1. 可以获取当前类中声明的所有方法；
2. 包括 `public`、`protected`、默认权限、`private`；
3. 不获取父类中的方法。

记忆方式：

```java
getMethods()          = 当前类 + 父类 的 public 方法
getDeclaredMethods()  = 当前类声明的所有方法
```

##### 示例：获取方法信息

```java
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;
import java.lang.reflect.Parameter;

public class MethodTest01 {
    public static void main(String[] args) throws Exception {
        // 获取目标类
        Class clazz = Class.forName(
                "com.jkweilai.javase.reflect.method.UserService"
        );

        // 获取当前类声明的所有方法
        Method[] methods = clazz.getDeclaredMethods();

        System.out.println("方法的个数：" + methods.length);

        for (Method method : methods) {
            // 获取方法修饰符
            System.out.println(Modifier.toString(method.getModifiers()));

            // 获取方法返回值类型
            Class<?> returnType = method.getReturnType();
            System.out.println(returnType.getName());

            // 获取方法名
            System.out.println(method.getName());

            // 获取参数个数
            System.out.println("参数的个数：" + method.getParameterCount());

            // 获取参数类型
            Class[] parameterTypes = method.getParameterTypes();
            for (Class parameterType : parameterTypes) {
                System.out.println(parameterType.getName());
            }

            // 获取参数完整信息
            Parameter[] parameters = method.getParameters();
            for (Parameter parameter : parameters) {
                // 如果编译时没有加 -parameters，参数名通常是 arg0、arg1
                System.out.println("参数的名字：" + parameter.getName());
                System.out.println("参数的类型：" + parameter.getType().getName());
            }
        }
    }
}
```

这段代码可以获取方法的：

1. 修饰符；
2. 返回值类型；
3. 方法名；
4. 参数个数；
5. 参数类型；
6. 参数对象信息。

#### Method 常用方法

| 方法                                 | 作用                           |
| ------------------------------------ | ------------------------------ |
| `getModifiers()`                     | 获取方法修饰符数字             |
| `getReturnType()`                    | 获取返回值类型                 |
| `getName()`                          | 获取方法名                     |
| `getParameterTypes()`                | 获取形参类型数组               |
| `getParameterCount()`                | 获取参数个数                   |
| `getParameters()`                    | 获取参数对象数组               |
| `invoke(Object obj, Object... args)` | 调用方法                       |
| `setAccessible(true)`                | 取消访问检查，允许调用私有方法 |

##### 示例：拼接方法结构

```java
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;
import java.lang.reflect.Parameter;

public class MethodTest02 {
    public static void main(String[] args) throws Exception {
        StringBuilder sb = new StringBuilder();

        Class clazz = Class.forName("java.lang.String");

        // 拼接类头
        sb.append(Modifier.toString(clazz.getModifiers()));
        sb.append(" class ");
        sb.append(clazz.getName());
        sb.append(" extends ");
        sb.append(clazz.getSuperclass().getName());

        Class[] interfaces = clazz.getInterfaces();
        if (interfaces.length > 0) {
            sb.append(" implements ");
        }

        for (int i = 0; i < interfaces.length; i++) {
            if (i == interfaces.length - 1) {
                sb.append(interfaces[i].getName());
            } else {
                sb.append(interfaces[i].getName());
                sb.append(",");
            }
        }

        sb.append("{\n");

        // 拼接方法
        Method[] methods = clazz.getDeclaredMethods();

        for (Method method : methods) {
            sb.append("\t");

            // 修饰符
            sb.append(Modifier.toString(method.getModifiers()));
            sb.append(" ");

            // 返回值类型
            sb.append(method.getReturnType().getName());
            sb.append(" ");

            // 方法名
            sb.append(method.getName());
            sb.append("(");

            // 参数列表
            Parameter[] parameters = method.getParameters();

            for (int i = 0; i < parameters.length; i++) {
                Parameter parameter = parameters[i];

                sb.append(parameter.getType().getName());
                sb.append(" ");
                sb.append(parameter.getName());

                if (i != parameters.length - 1) {
                    sb.append(",");
                }
            }

            sb.append("){}\n");
        }

        sb.append("}");

        System.out.println(sb);
    }
}
```

这段代码可以生成类似下面的结构：

```java
public final class java.lang.String extends java.lang.Object implements ... {
    public boolean equals(java.lang.Object arg0){}
    public int length(){}
    ...
}
```

需要注意，参数名可能显示为：

```java
arg0
arg1
arg2
```

这是因为 Java 编译时默认不一定保留真实参数名。如果想保留真实参数名，需要在编译时加上 `-parameters` 参数。

### 操作方法

获取到 `Method` 对象之后，可以通过 `invoke()` 方法调用目标方法。

```java
Object result = method.invoke(对象, 实参列表);
```

#### 调用方法的四要素

通过反射调用方法，需要明确四个信息：

```java
调用哪个对象
调用哪个方法
传递什么参数
返回什么结果
```

例如普通调用：

```java
boolean success = userService.login("admin", "123456");
```

反射调用：

```java
Method loginMethod = userServiceType.getDeclaredMethod(
        "login", String.class, String.class
);

loginMethod.setAccessible(true);

Object result = loginMethod.invoke(userService, "admin", "123456");
```

#### 示例：调用私有成员方法

`UserService` 类：

```java
public class UserService {

    private boolean login(String username, String password) {
        if ("admin".equals(username) && "123456".equals(password)) {
            return true;
        }
        return false;
    }

    public void logout() {
        System.out.println("系统已经安全退出");
    }

    public boolean login(String username) {
        if ("jack".equals(username)) {
            return true;
        }
        return false;
    }
}
```

反射调用私有方法：

```java
import java.lang.reflect.Method;

public class MethodTest03 {
    public static void main(String[] args) throws Exception {
        // 创建业务对象
        UserService userService = new UserService();

        // 获取运行时类型
        Class<? extends UserService> userServiceType = userService.getClass();

        // 获取私有方法 login(String, String)
        // 方法存在重载时，必须通过参数类型精确定位
        Method loginMethod = userServiceType.getDeclaredMethod(
                "login", String.class, String.class
        );

        // 打破封装，允许调用 private 方法
        loginMethod.setAccessible(true);

        // 调用方法
        Object result = loginMethod.invoke(userService, "admin", "123456");

        System.out.println(result); // true
    }
}
```

这里调用的是私有方法：

```java
private boolean login(String username, String password)
```

由于它是 `private`，所以必须调用：

```java
loginMethod.setAccessible(true);
```

否则会因为访问权限不足而失败。

#### 示例：调用公开无参方法

```java
Method logoutMethod = userServiceType.getDeclaredMethod("logout");

Object retValue = logoutMethod.invoke(userService);

System.out.println(retValue); // null
```

`logout()` 方法没有返回值：

```java
public void logout()
```

因此通过反射调用后，`invoke()` 返回：

```java
null
```

> **注意**
>
> 如果被调用的方法返回值类型是 `void`，那么 `invoke()` 的返回值就是 `null`。

#### 调用静态方法

成员方法属于对象，所以调用成员方法时，`invoke()` 的第一个参数传入对象：

```java
method.invoke(obj, 参数);
```

静态方法属于类，不属于某个具体对象，因此调用静态方法时，第一个参数可以传入 `null`：

```java
method.invoke(null, 参数);
```

例如：

```java
Method method = clazz.getDeclaredMethod("staticMethod", String.class);
method.setAccessible(true);

Object result = method.invoke(null, "hello");
```

## 构造方法：Constructor

构造方法在反射中使用 `Constructor` 表示。

一个 `Constructor` 对象表示类中的一个构造方法。

通过 `Constructor`，可以：

1. 获取构造方法信息；
2. 调用无参构造方法创建对象；
3. 调用有参构造方法创建对象；
4. 调用私有构造方法创建对象。

### 获取构造方法

`Class` 中提供了获取构造方法的方法。

| 方法                                                 | 作用                               |
| ---------------------------------------------------- | ---------------------------------- |
| `getConstructors()`                                  | 获取当前类中所有 `public` 构造方法 |
| `getDeclaredConstructors()`                          | 获取当前类中所有构造方法，不管权限 |
| `getConstructor(Class<?>... parameterTypes)`         | 获取当前类中某个 `public` 构造方法 |
| `getDeclaredConstructor(Class<?>... parameterTypes)` | 获取当前类中某个构造方法，不管权限 |

#### getConstructors() 和 getDeclaredConstructors() 的区别

##### getConstructors()

```java
Constructor<?>[] constructors = clazz.getConstructors();
```

特点：

1. 只能获取 `public` 构造方法；
2. 只获取当前类的构造方法；
3. 不存在“继承父类构造方法”的说法。

##### getDeclaredConstructors()

```java
Constructor<?>[] constructors = clazz.getDeclaredConstructors();
```

特点：

1. 获取当前类中声明的所有构造方法；
2. 包括 `public`、`protected`、默认权限、`private`；
3. 不获取父类构造方法。

##### 示例：获取构造方法信息

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Modifier;
import java.lang.reflect.Parameter;

public class ConstructorTest {
    public static void main(String[] args) throws Exception {
        Class<?> userType = Class.forName(
                "com.jkweilai.javase.reflect.constructor.User"
        );

        // 获取当前类声明的所有构造方法
        Constructor<?>[] constructors = userType.getDeclaredConstructors();

        for (Constructor constructor : constructors) {
            // 构造方法修饰符
            System.out.print(Modifier.toString(constructor.getModifiers()) + " ");

            // 构造方法名
            System.out.print(constructor.getName());

            // 构造方法参数列表
            System.out.print("(");

            Parameter[] parameters = constructor.getParameters();

            for (int i = 0; i < parameters.length; i++) {
                Parameter parameter = parameters[i];

                System.out.print(parameter.getType().getName());
                System.out.print(" ");
                System.out.print(parameter.getName());

                if (i != parameters.length - 1) {
                    System.out.print(",");
                }
            }

            System.out.println("){}");
        }
    }
}
```

这段代码可以获取每个构造方法的：

1. 修饰符；
2. 构造方法名；
3. 参数类型；
4. 参数名称。

#### Constructor 常用方法

| 方法                              | 作用                               |
| --------------------------------- | ---------------------------------- |
| `getModifiers()`                  | 获取构造方法修饰符数字             |
| `getName()`                       | 获取构造方法名                     |
| `getParameterTypes()`             | 获取构造方法形参类型数组           |
| `getParameters()`                 | 获取参数对象数组                   |
| `newInstance(Object... initargs)` | 调用构造方法创建对象               |
| `setAccessible(true)`             | 取消访问检查，允许调用私有构造方法 |

### 操作构造方法

获取到 `Constructor` 对象之后，可以通过它创建对象。

```java
Object obj = constructor.newInstance(实参列表);
```

相比 `Class.newInstance()`，`Constructor.newInstance()` 更灵活。

`Class.newInstance()` 主要依赖无参构造方法，而 `Constructor.newInstance()` 可以调用指定参数列表的构造方法。

#### 示例：通过有参构造方法创建对象

`User` 类：

```java
public class User {
    private String name;
    private int age;
    private String email;
    private String addr;

    public User() {
    }

    public User(String name) {
        this.name = name;
    }

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public User(String name, int age, String email) {
        this.name = name;
        this.age = age;
        this.email = email;
    }

    public User(String name, int age, String email, String addr) {
        this.name = name;
        this.age = age;
        this.email = email;
        this.addr = addr;
    }

    @Override
    public String toString() {
        return "User{" +
                "name='" + name + '\'' +
                ", age=" + age +
                ", email='" + email + '\'' +
                ", addr='" + addr + '\'' +
                '}';
    }
}
```

反射调用有参构造方法：

```java
import java.lang.reflect.Constructor;

public class ConstructorTest02 {
    public static void main(String[] args) throws Exception {
        // 普通方式创建对象
        User user = new User("jack", 20, "jack@123.com", "天津南开");
        System.out.println(user);

        // 使用反射机制创建对象
        Class<?> userType = Class.forName(
                "com.jkweilai.javase.reflect.constructor.User"
        );

        // 获取指定参数列表的构造方法
        Constructor<?> constructor = userType.getDeclaredConstructor(
                String.class, int.class, String.class, String.class
        );

        // 调用构造方法创建对象
        Object obj = constructor.newInstance(
                "jack", 20, "jack@123.com", "天津南开"
        );

        System.out.println(obj);
    }
}
```

这段代码中，关键是：

```java
getDeclaredConstructor(String.class, int.class, String.class, String.class)
```

它表示获取参数列表为：

```java
String, int, String, String
```

的构造方法。

然后通过：

```java
constructor.newInstance("jack", 20, "jack@123.com", "天津南开");
```

调用该构造方法创建对象。

#### 示例：通过无参构造方法创建对象

```java
Constructor<?> constructor = userType.getDeclaredConstructor();

Object obj = constructor.newInstance();

System.out.println(obj);
```

这相当于调用：

```java
new User();
```

如果目标类没有无参构造方法，获取无参构造方法时就会失败。

#### 调用私有构造方法

如果构造方法是私有的，需要先调用：

```java
constructor.setAccessible(true);
```

然后再调用：

```java
constructor.newInstance(参数);
```

示例：

```java
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);

constructor.setAccessible(true);

Object obj = constructor.newInstance("jack");
```

这说明反射可以突破构造方法的访问权限限制。

## setAccessible(true)

`setAccessible(true)` 是反射中非常重要的方法。

它的作用是取消 Java 语言访问检查，使反射可以访问非公开成员。

例如：

```java
field.setAccessible(true);
method.setAccessible(true);
constructor.setAccessible(true);
```

可以用于：

1. 访问私有属性；
2. 调用私有方法；
3. 调用私有构造方法。

### setAccessible(true) 的意义

正常情况下，`private` 成员只能在本类内部访问。

例如：

```java
private String name;
```

外部代码不能直接访问：

```java
p.name = "lucy"; // 编译失败
```

但是反射可以这样操作：

```java
Field nameField = clazz.getDeclaredField("name");
nameField.setAccessible(true);
nameField.set(p, "lucy");
```

这说明反射可以突破封装。

### JDK 17 中能否操作 JDK 内部私有成员

对于自己编写的普通类，通常可以通过：

```java
setAccessible(true)
```

访问私有属性、私有方法和私有构造方法。

但是在 JDK 9 之后，Java 引入了模块化系统；到 JDK 17 时，对 JDK 内部类的强封装更加严格。

因此，在 JDK 17 中，如果要反射访问 JDK 自身某些模块内部的私有成员，可能会失败，并抛出类似异常：

```java
java.lang.reflect.InaccessibleObjectException
```

原因是：即使调用了 `setAccessible(true)`，模块系统也可能不允许外部模块访问 JDK 内部未开放的包。

如果确实需要访问，通常需要在启动参数中显式开放模块，例如：

```java
--add-opens java.base/java.lang=ALL-UNNAMED
```

不过，实际开发中不建议随意反射操作 JDK 内部私有成员。这样做会破坏封装，也可能导致程序在不同 JDK 版本中表现不一致。

> **结论**
>
> `setAccessible(true)` 对普通自定义类通常有效；
> 对 JDK 17 中被模块系统强封装的 JDK 内部类，不一定有效。

## 反射中获取泛型参数

Java 泛型主要用于编译期类型检查。程序编译之后，很多泛型信息会发生类型擦除。

例如：

```java
List<String> list = new ArrayList<>();
```

在运行时，`List<String>` 中的 `String` 泛型信息大部分会被擦除，底层主要把它当作 `List` 处理。

但是，Java 并不是完全丢弃所有泛型信息。JDK 1.5 引入泛型之后，字节码中会通过 `Signature` 属性保留一部分泛型签名信息。因此，在某些声明位置上，反射仍然可以读取到泛型参数。

常见可以读取泛型信息的位置包括：

1. 父类上的泛型；
2. 接口上的泛型；
3. 属性上的泛型；
4. 方法形参上的泛型；
5. 方法返回值上的泛型；
6. 构造方法形参上的泛型。

### 反射获取泛型的核心类型

反射获取泛型信息时，常用两个接口：

```java
java.lang.reflect.Type
java.lang.reflect.ParameterizedType
```

#### Type 接口

`Type` 是 Java 中所有类型信息的顶层接口之一。

它可以表示：

1. 普通类型；
2. 参数化类型；
3. 类型变量；
4. 泛型数组；
5. 通配符类型。

在反射中，很多获取泛型的方法返回值都是 `Type`。

例如：

```java
Type genericSuperclass = clazz.getGenericSuperclass();
Type genericType = field.getGenericType();
Type genericReturnType = method.getGenericReturnType();
```

#### ParameterizedType 接口

`ParameterizedType` 表示参数化类型，也就是带泛型参数的类型。

例如：

```java
Animal<String, Integer>
Map<String, Integer>
List<String>
```

这些都属于参数化类型。

当通过反射获取到的 `Type` 对象确实是带泛型参数的类型时，就可以判断它是否是 `ParameterizedType`：

```java
if (type instanceof ParameterizedType pt) {
    Type[] actualTypeArguments = pt.getActualTypeArguments();
}
```

其中：

```java
getActualTypeArguments()
```

用于获取实际泛型参数数组。

例如：

```java
Map<String, Integer>
```

获取到的泛型参数就是：

```java
java.lang.String
java.lang.Integer
```

#### 获取泛型信息的基本套路

获取泛型信息的代码通常都有固定结构：

```java
Type type = 获取某个位置上的泛型类型;

if (type instanceof ParameterizedType pt) {
    Type[] actualTypeArguments = pt.getActualTypeArguments();

    for (Type actualTypeArgument : actualTypeArguments) {
        System.out.println(actualTypeArgument.getTypeName());
    }
}
```

这段代码可以理解为三步：

1. 先通过反射获取某个位置上的泛型声明；
2. 判断这个类型是否是参数化类型；
3. 如果是参数化类型，就获取实际泛型参数。

### 获取父类中的泛型

如果一个类继承父类时指定了泛型参数，可以通过反射获取父类上的泛型信息。

例如：

```java
class Animal<X, Y> {
}

class Cat extends Animal<String, Integer> {
}
```

`Cat` 继承 `Animal` 时，明确指定了：

```java
String
Integer
```

因此，可以通过反射从 `Cat` 类上获取它父类的泛型参数。

#### getGenericSuperclass()

获取父类泛型信息使用：

```java
Type genericSuperclass = clazz.getGenericSuperclass();
```

它返回的是当前类父类的泛型类型信息。

如果父类没有泛型参数，返回的可能只是普通 `Class` 类型；如果父类有泛型参数，返回的通常是 `ParameterizedType`。

#### 示例：获取父类泛型

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

public class GenericTest01 {
    public static void main(String[] args) {
        // 获取 Cat 类的 Class 对象
        Class catType = Cat.class;

        // 获取 Cat 类父类上的泛型信息
        Type genericSuperclass = catType.getGenericSuperclass();

        // 判断父类是否是带泛型参数的参数化类型
        if (genericSuperclass instanceof ParameterizedType pt) {
            // 获取父类上的所有实际泛型参数
            Type[] actualTypeArguments = pt.getActualTypeArguments();

            // 遍历输出泛型参数
            for (Type actualTypeArgument : actualTypeArguments) {
                System.out.println(actualTypeArgument.getTypeName());
            }
        }
    }
}

class Animal<X, Y> {
}

class Cat extends Animal<String, Integer> {
}
```

输出结果：

```java
java.lang.String
java.lang.Integer
```

这说明反射成功获取到了：

```java
Animal<String, Integer>
```

中的两个泛型参数。

### 获取接口中的泛型

如果一个类实现接口时指定了泛型参数，也可以通过反射获取接口上的泛型信息。

例如：

```java
interface Flyable<E, F> {
}

interface Movable<X, Y> {
}

class Bird implements Flyable<String, Integer>, Movable<Integer, String> {
}
```

`Bird` 实现了两个接口，并且分别指定了泛型参数：

```java
Flyable<String, Integer>
Movable<Integer, String>
```

由于一个类可以实现多个接口，所以获取接口泛型时返回的是数组。

#### getGenericInterfaces()

获取接口泛型信息使用：

```java
Type[] genericInterfaces = clazz.getGenericInterfaces();
```

它返回当前类实现的所有接口的泛型类型信息。

#### 示例：获取接口泛型

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

public class GenericTest02 {
    public static void main(String[] args) {
        // 获取 Bird 类的 Class 对象
        Class birdType = Bird.class;

        // 获取 Bird 实现的所有接口上的泛型信息
        Type[] genericInterfaces = birdType.getGenericInterfaces();

        // 遍历所有接口
        for (Type genericInterface : genericInterfaces) {
            // 判断接口是否是参数化类型
            if (genericInterface instanceof ParameterizedType pt) {
                // 获取接口中的实际泛型参数
                Type[] actualTypeArguments = pt.getActualTypeArguments();

                for (Type actualTypeArgument : actualTypeArguments) {
                    System.out.println(actualTypeArgument.getTypeName());
                }
            }
        }
    }
}

interface Flyable<E, F> {
}

interface Movable<X, Y> {
}

class Bird implements Flyable<String, Integer>, Movable<Integer, String> {
}
```

输出结果：

```java
java.lang.String
java.lang.Integer
java.lang.Integer
java.lang.String
```

前两行来自：

```java
Flyable<String, Integer>
```

后两行来自：

```java
Movable<Integer, String>
```

### 获取属性中的泛型

如果类中的属性声明使用了泛型，也可以通过反射获取。

例如：

```java
class MyClass {
    Map<Integer, String> map = new HashMap<>();
}
```

这里 `map` 属性的声明类型是：

```java
Map<Integer, String>
```

反射可以读取到这个属性声明中的泛型参数。

#### getGenericType()

获取属性泛型信息使用：

```java
Type genericType = field.getGenericType();
```

它返回字段声明上的泛型类型信息。

普通获取字段类型的方法是：

```java
field.getType()
```

但是 `getType()` 只能获取原始类型，例如：

```java
java.util.Map
```

如果想获取 `Map<Integer, String>` 中的 `Integer` 和 `String`，需要使用：

```java
field.getGenericType()
```

#### 示例：获取属性泛型

```java
import java.lang.reflect.Field;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.HashMap;
import java.util.Map;

public class GenericTest03 {
    public static void main(String[] args) throws Exception {
        // 获取 MyClass 的 Class 对象
        Class clazz = MyClass.class;

        // 获取 map 属性
        Field field = clazz.getDeclaredField("map");

        // 获取 map 属性声明上的泛型信息
        Type genericType = field.getGenericType();

        // 判断该属性类型是否是参数化类型
        if (genericType instanceof ParameterizedType pt) {
            // 获取实际泛型参数
            Type[] actualTypeArguments = pt.getActualTypeArguments();

            for (Type actualTypeArgument : actualTypeArguments) {
                System.out.println(actualTypeArgument.getTypeName());
            }
        }
    }
}

class MyClass {
    Map<Integer, String> map = new HashMap<>();
}
```

输出结果：

```java
java.lang.Integer
java.lang.String
```

### 获取方法形参中的泛型

如果方法的形参使用了泛型，也可以通过反射获取。

例如：

```java
public static void doSome(List<String> list, Map<String, Integer> map) {
}
```

这个方法有两个形参：

```java
List<String>
Map<String, Integer>
```

反射可以获取这些形参声明中的泛型参数。

#### getGenericParameterTypes()

获取方法形参泛型信息使用：

```java
Type[] genericParameterTypes = method.getGenericParameterTypes();
```

它返回方法所有形参的泛型类型信息。

普通获取形参类型的方法是：

```java
method.getParameterTypes()
```

但是它只能获取原始类型，例如：

```java
List.class
Map.class
```

如果想获取 `List<String>` 中的 `String`，或者 `Map<String, Integer>` 中的 `String` 和 `Integer`，需要使用：

```java
method.getGenericParameterTypes()
```

#### 示例：获取方法形参泛型

```java
import java.lang.reflect.Method;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.List;
import java.util.Map;

public class GenericTest04 {
    public static void main(String[] args) throws Exception {
        // 获取当前类的 Class 对象
        Class clazz = GenericTest04.class;

        // 获取 doSome(List, Map) 方法
        // 注意：反射获取方法时，参数类型写的是原始类型 List.class、Map.class
        Method doSomeMethod = clazz.getDeclaredMethod(
                "doSome", List.class, Map.class
        );

        // 获取方法形参上的泛型信息
        Type[] genericParameterTypes = doSomeMethod.getGenericParameterTypes();

        // 遍历每一个形参
        for (Type genericParameterType : genericParameterTypes) {
            // 判断形参是否为参数化类型
            if (genericParameterType instanceof ParameterizedType pt) {
                // 获取该形参上的实际泛型参数
                Type[] actualTypeArguments = pt.getActualTypeArguments();

                for (Type actualTypeArgument : actualTypeArguments) {
                    System.out.println(actualTypeArgument.getTypeName());
                }
            }
        }
    }

    public static void doSome(List<String> list, Map<String, Integer> map) {
    }
}
```

输出结果：

```java
java.lang.String
java.lang.String
java.lang.Integer
```

其中：

```java
java.lang.String
```

来自：

```java
List<String>
```

后面的：

```java
java.lang.String
java.lang.Integer
```

来自：

```java
Map<String, Integer>
```

### 获取方法返回值中的泛型

如果方法返回值使用了泛型，也可以通过反射获取。

例如：

```java
public static Map<String, Integer> getMap() {
    return null;
}
```

这个方法的返回值类型是：

```java
Map<String, Integer>
```

反射可以读取返回值上的泛型参数。

#### getGenericReturnType()

获取方法返回值泛型信息使用：

```java
Type genericReturnType = method.getGenericReturnType();
```

普通获取返回值类型使用：

```java
method.getReturnType()
```

但是 `getReturnType()` 只能获取原始返回类型，例如：

```java
Map.class
```

如果想获取 `Map<String, Integer>` 中的泛型参数，需要使用：

#### 示例：获取方法返回值泛型

这说明反射成功获取到了：


中的泛型参数。

### 获取构造方法形参中的泛型

构造方法的形参如果使用了泛型，也可以通过反射获取。

例如：

```java
public Tiger(Map<String, Integer> map) {
}
```

这个构造方法的形参类型是：

```java
Map<String, Integer>
```

反射可以获取构造方法形参上的泛型参数。

#### Constructor 的 getGenericParameterTypes()

获取构造方法形参泛型使用：

```java
Type[] parameterTypes = constructor.getGenericParameterTypes();
```

它和 `Method` 的 `getGenericParameterTypes()` 类似，只不过一个用于普通方法，一个用于构造方法。

#### 示例：获取构造方法形参泛型

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.Map;

public class ConstructorGenericTest {
    public static void main(String[] args) {
        try {
            // 获取 Tiger 类的 Class 对象
            Class<Tiger> clazz = Tiger.class;

            // 获取参数为 Map 的公开构造方法
            // 注意：这里使用的是擦除后的原始类型 Map.class
            Constructor<Tiger> constructor = clazz.getConstructor(Map.class);

            // 获取构造方法形参上的泛型信息
            Type[] parameterTypes = constructor.getGenericParameterTypes();

            for (Type parameterType : parameterTypes) {
                if (parameterType instanceof ParameterizedType pt) {
                    Type[] actualTypeArguments = pt.getActualTypeArguments();

                    for (Type argument : actualTypeArguments) {
                        System.out.println(argument.getTypeName());
                    }
                }
            }
        } catch (NoSuchMethodException e) {
            e.printStackTrace();
        }
    }
}

class Tiger {
    public Tiger(Map<String, Integer> map) {
    }
}
```

输出结果：

```java
java.lang.String
java.lang.Integer
```

## 类的加载过程分析

Java 程序运行时，源代码不会直接被 JVM 执行。Java 源文件首先会被编译成 `.class` 字节码文件，然后 JVM 再把字节码文件加载到内存中，最终才能使用这个类。

一个类从 `.class` 文件进入 JVM，并变成可以被程序使用的运行时结构，主要经历三个阶段：

```java
装载 -> 链接 -> 初始化
```

其中，链接阶段又可以继续细分为：

```java
验证 -> 准备 -> 解析
```

所以完整过程可以表示为：

```java
装载 -> 验证 -> 准备 -> 解析 -> 初始化
```

### 类加载过程总览

类加载过程可以理解为：JVM 把磁盘上的 `.class` 文件变成内存中可使用的 `Class` 对象和运行时数据结构的过程。

整体流程如下：

```java
.class 字节码文件
        ↓
装载 Loading
        ↓
链接 Linking
    ├── 验证 Verification
    ├── 准备 Preparation
    └── 解析 Resolution
        ↓
初始化 Initialization
        ↓
类可以正式使用
```

需要注意，类加载不是简单地把文件读进内存，而是包含校验、分配空间、符号解析、执行静态初始化逻辑等多个步骤。

### 装载

装载，也叫 `Loading`。

装载阶段主要完成三件事：

1. 通过类的全限定名获取该类的二进制字节流；
2. 把字节码中的静态存储结构转换成方法区中的运行时数据结构；
3. 在内存中生成一个代表该类的 `java.lang.Class` 对象。

简单理解：

```java
装载 = 把 .class 文件读入 JVM，并创建对应的 Class 对象
```

例如，程序第一次使用某个类时：

```java
Class<?> clazz = Class.forName("com.jkweilai.User");
```

JVM 会尝试找到 `com.jkweilai.User` 对应的 `.class` 文件，然后把它加载进内存。

#### 装载阶段的结果

装载完成后，JVM 中会出现该类对应的 `Class` 对象。

也就是说：

```java
一个被加载的类 -> 对应一个 Class 对象
```

例如：

```java
Class<?> clazz = String.class;
```

这里的 `clazz` 就是 `String` 类在 JVM 中对应的 `Class` 对象。

这个 `Class` 对象可以作为反射的入口，用来获取类名、属性、方法、构造方法、父类、接口等信息。

### 链接

链接，也叫 `Linking`。

链接阶段的作用是：把已经装载进 JVM 的类数据进行校验、准备和解析，使它具备可以运行的基础条件。

链接阶段分为三个小阶段：

```java
验证 -> 准备 -> 解析
```

#### 验证

验证，也叫 `Verification`。

验证阶段的作用是：确保加载进来的 `.class` 文件符合 JVM 规范，不会危害 JVM 安全。

例如，JVM 会检查：

1. 文件格式是否合法；
2. 是否以合法的魔数开头；
3. 字节码指令是否合法；
4. 类的继承关系是否合法；
5. 是否存在破坏虚拟机安全的行为。

##### 魔数 0xCAFEBABE

每一个合法的 Java `.class` 文件开头都有一个固定的魔数：

```java
0xCAFEBABE
```

这个魔数用于标识当前文件是一个 Java class 文件。

如果一个文件不是以这个魔数开头，JVM 就不会把它当成合法的 class 文件加载。

可以使用一些工具查看 `.class` 文件的十六进制内容，例如：

```java
Hex Viewer
```

也可以使用字节码查看工具查看 class 文件结构，例如：

```java
jclasslib
javap
```

#### 准备

准备，也叫 `Preparation`。

准备阶段的作用是：为类变量，也就是静态变量，分配内存空间，并设置默认初始值。

注意：准备阶段主要处理的是静态变量，不是成员变量。

例如：

```java
public class User {
    public static int value = 11;
}
```

在准备阶段，`value` 会先被赋默认值：

```java
value = 0;
```

而不是直接赋值为 `11`。

真正赋值为 `11` 是在后面的初始化阶段完成的。

##### 准备阶段的默认值

不同类型的静态变量在准备阶段会被赋予不同默认值。

| 类型                           | 默认值   |
| ------------------------------ | -------- |
| `byte`、`short`、`int`、`long` | `0`      |
| `float`、`double`              | `0.0`    |
| `char`                         | `\u0000` |
| `boolean`                      | `false`  |
| 引用类型                       | `null`   |

例如：

```java
public class Test {
    public static int a = 10;
    public static String name = "jack";
}
```

准备阶段：

```java
a = 0
name = null
```

初始化阶段：

```java
a = 10
name = "jack"
```

##### final 静态常量的特殊情况

对于一些 `static final` 修饰的编译期常量，准备阶段可能就会直接赋值。

例如：

```java
public static final int VALUE = 11;
```

这种情况中，`VALUE` 是编译期常量，准备阶段就可能直接赋值为：

```java
VALUE = 11;
```

而不是先赋值为 `0`。

但是，并不是所有 `static final` 都一定在准备阶段完成真实赋值。如果右边不是编译期常量，而是运行时才能确定的值，则仍然需要等初始化阶段执行。

例如：

```java
public static final int VALUE = new Random().nextInt();
```

这种值不能在编译期确定，因此不能简单认为准备阶段就会赋真实值。

#### 解析

解析，也叫 `Resolution`。

解析阶段的作用是：把常量池中的符号引用转换为直接引用。

简单来说：

```java
符号引用 -> 直接引用
```

##### 符号引用

符号引用可以理解为一种“名字形式的引用”。

例如：

```java
我要调用 java.lang.Math 类中的 abs() 方法
```

这里的 `java.lang.Math`、`abs` 都是通过符号描述目标。

符号引用并不直接指向内存地址，只是用名称描述要访问的类、方法或字段。

##### 直接引用

直接引用可以理解为可以直接定位目标的引用。

例如：

```java
直接定位到 Math.abs() 方法在内存中的位置
```

解析之后，JVM 后续调用方法或访问字段时，就不需要每次都通过名字查找，而是可以通过直接引用定位目标。

##### 解析阶段的意义

解析阶段可以提高后续执行效率。

如果每次调用方法时都通过字符串形式的类名、方法名去查找，会非常低效。解析后，JVM 可以直接根据引用找到目标结构。

可以借助字节码工具观察符号引用，例如：

```java
jclasslib
javap -v
```

但是，工具通常只能帮助我们看到常量池中的符号引用，不一定能直接看到 JVM 内部把符号引用替换为直接引用的完整过程。

### 初始化

初始化，也叫 `Initialization`。

初始化阶段是真正执行类中静态初始化逻辑的阶段。

这一阶段，JVM 会执行编译器自动生成的：

```java
<clinit>()
```

方法。

#### 什么是 () 方法

`<clinit>()` 是类初始化方法，全称可以理解为 class initialization method。

它不是程序员手动编写的方法，而是编译器自动生成的。

它由两部分内容按源码出现顺序合并而成：

1. 静态变量的显式赋值语句；
2. 静态代码块中的语句。

例如：

```java
public class User {
    public static int value = 10;

    static {
        System.out.println("静态代码块执行");
        value = 20;
    }
}
```

编译器会把静态变量显式赋值和静态代码块合并到 `<clinit>()` 中，执行顺序与源码中的书写顺序有关。

#### 初始化阶段示例

```java
public class Test {
    public static int a = 10;

    static {
        a = 20;
    }
}
```

执行过程大致如下：

准备阶段：

```java
a = 0
```

初始化阶段执行 `<clinit>()`：

```java
a = 10
a = 20
```

最终结果：

```java
a = 20
```

#### 什么时候不会生成 ()

如果一个类中没有静态变量显式赋值，也没有静态代码块，那么编译器可能不会生成 `<clinit>()` 方法。

例如：

```java
public class Empty {
    private int age;
}
```

这个类没有任何静态初始化逻辑，因此不需要 `<clinit>()`。

## 类加载器

类加载器，也就是 `ClassLoader`，负责把 `.class` 字节码文件加载到 JVM 内存中。

简单理解：

```java
ClassLoader = 负责加载 class 文件的对象
```

当程序第一次需要使用某个类时，JVM 会通过类加载器找到对应的 `.class` 文件，并把它加载进内存。

### 类加载器的作用

类加载器主要负责：

1. 根据类的全限定名查找 `.class` 文件；
2. 读取 `.class` 文件的字节码；
3. 把字节码加载进 JVM；
4. 创建该类对应的 `Class` 对象；
5. 维护类加载器之间的父子委派关系。

例如，程序中第一次使用：

```java
com.jkweilai.User
```

JVM 会通过类加载器去查找并加载：

```java
com/jkweilai/User.class
```

### 类加载器的分类

在 JDK 8 中，常见类加载器主要有：

```java
启动类加载器 Bootstrap ClassLoader
扩展类加载器 Extension ClassLoader
系统类加载器 System ClassLoader
用户自定义类加载器 User ClassLoader
```

它们之间存在父加载器关系，而不是 Java 类继承关系。

#### 启动类加载器

启动类加载器，也叫引导类加载器，英文是 `Bootstrap ClassLoader`。

特点：

1. 由 C/C++ 实现，嵌入在 JVM 内部；
2. 不是 Java 对象；
3. 不继承 `java.lang.ClassLoader`；
4. 没有父加载器；
5. Java 代码中通常无法直接获取它，打印时常显示为 `null`；
6. 负责加载 Java 核心类库。

在 JDK 8 中，它主要加载类似下面路径中的核心类库：

```java
JAVA_HOME/jre/lib/rt.jar
```

`rt.jar` 中包含很多 Java 运行时核心类，其中 `rt` 可以理解为 runtime。

例如：

```java
java.lang.String
java.lang.Object
java.lang.System
```

这些核心类通常由启动类加载器加载。

#### 扩展类加载器

扩展类加载器，英文是 `Extension ClassLoader`。

在 JDK 8 中，它对应的实现类通常是：

```java
sun.misc.Launcher$ExtClassLoader
```

特点：

1. 由 Java 语言实现；
2. 继承自 `ClassLoader`；
3. 父加载器是启动类加载器；
4. 负责加载扩展目录中的类库。

在 JDK 8 中，扩展类加载器通常从下面路径加载类库：

```java
JAVA_HOME/jre/lib/ext
```

或者系统属性：

```java
java.ext.dirs
```

指定的目录中加载类库。

#### 系统类加载器

系统类加载器，也叫应用类加载器，英文是 `System ClassLoader` 或 `Application ClassLoader`。

在 JDK 8 中，它对应的实现类通常是：

```java
sun.misc.Launcher$AppClassLoader
```

特点：

1. 由 Java 语言实现；
2. 继承自 `ClassLoader`；
3. 父加载器是扩展类加载器；
4. 负责加载 classpath 下的类；
5. 通常用于加载程序员自己写的类。

可以通过下面方法获取系统类加载器：

```java
ClassLoader systemClassLoader = ClassLoader.getSystemClassLoader();
```

一般项目中自己写的类，例如：

```java
com.jkweilai.User
com.jkweilai.Student
```

通常都是由系统类加载器加载的。

#### 用户自定义类加载器

用户自定义类加载器是开发者自己编写的类加载器。

通常需要继承：

```java
java.lang.ClassLoader
```

自定义类加载器可以实现一些特殊需求，例如：

1. 从指定目录加载 class 文件；
2. 从网络加载 class 文件；
3. 从加密文件中读取并解密字节码；
4. 实现插件化架构；
5. 实现应用隔离；
6. 热部署或动态扩展功能。

例如，一些插件系统可以在程序运行时加载新的 jar 包，从而实现不重启程序也能扩展功能。

### JDK 9 之后的变化

需要注意，JDK 9 引入模块化系统后，类加载器结构发生了一些变化。

在 JDK 8 中常说：

```java
Bootstrap ClassLoader
Extension ClassLoader
Application ClassLoader
```

而在 JDK 9 之后，扩展类加载器被平台类加载器替代：

```java
Bootstrap ClassLoader
Platform ClassLoader
Application ClassLoader
```

JDK 17 中，通常看到的是：

```java
Bootstrap ClassLoader
Platform ClassLoader
App ClassLoader
```

不过学习类加载器原理时，仍然经常以 JDK 8 的三层结构作为入门模型。

### 获取类加载器

可以通过系统类加载器继续向上获取父加载器。

示例代码：

```java
public class ClassLoaderTest {
    public static void main(String[] args) {
        // 获取系统类加载器
        ClassLoader systemClassLoader = ClassLoader.getSystemClassLoader();
        System.out.println(systemClassLoader);

        // 获取系统类加载器的父加载器
        ClassLoader parent = systemClassLoader.getParent();
        System.out.println(parent);

        // 继续获取父加载器
        ClassLoader root = parent.getParent();
        System.out.println(root);
    }
}
```

在 JDK 8 中，可能输出类似：

```java
sun.misc.Launcher$AppClassLoader@18b4aac2
sun.misc.Launcher$ExtClassLoader@14ae5a5
null
```

其中：

```java
null
```

并不是表示没有启动类加载器，而是因为启动类加载器不是普通 Java 对象，Java 代码无法直接拿到它。

#### 父加载器不是继承关系

类加载器中的“父加载器”不是 Java 继承意义上的父类。

例如：

```java
systemClassLoader.getParent()
```

获取的是系统类加载器内部记录的父加载器对象。

它是一种组合或委托关系，不是：

```java
class AppClassLoader extends ExtClassLoader
```

所以不要把父加载器理解成继承关系。

正确理解：

```java
父加载器 = 当前类加载器委托加载时优先交给的上级加载器
```

### Class.forName() 和 ClassLoader.loadClass() 的区别

`Class.forName()` 和 `ClassLoader.loadClass()` 都可以根据类名加载类并返回 `Class` 对象，但它们有一个重要区别：

```java
Class.forName() 通常会触发类初始化
ClassLoader.loadClass() 默认不会触发类初始化
```

#### Class.forName()

`Class.forName()` 是 `Class` 类的静态方法。

常见写法：

```java
Class<?> clazz = Class.forName("com.jkweilai.MyClass");
```

它通常会完成：

```java
装载 + 链接 + 初始化
```

如果类中有静态代码块，通常会执行静态代码块。

例如：

```java
class MyClass {
    static {
        System.out.println("静态代码块执行了！");
    }
}
```

调用：

```java
Class.forName("com.jkweilai.MyClass");
```

会触发输出：

```java
静态代码块执行了！
```

#### ClassLoader.loadClass()

`ClassLoader.loadClass()` 是类加载器对象的实例方法。

常见写法：

```java
ClassLoader classLoader = ClassLoader.getSystemClassLoader();

Class<?> clazz = classLoader.loadClass("com.jkweilai.MyClass");
```

它默认主要完成：

```java
装载 + 链接
```

通常不会主动执行初始化阶段，所以不会立刻执行静态代码块。

只有当类第一次被主动使用时，才会触发初始化。

#### 示例对比

```java
class MyClass {
    static {
        System.out.println("静态代码块执行了！");
    }
}
```

使用 `loadClass()`：

```java
ClassLoader systemClassLoader = ClassLoader.getSystemClassLoader();

Class<?> clazz = systemClassLoader.loadClass("com.jkweilai.MyClass");
```

通常不会输出：

```java
静态代码块执行了！
```

使用 `Class.forName()`：

```java
Class<?> clazz = Class.forName("com.jkweilai.MyClass");
```

会输出：

```java
静态代码块执行了！
```

## 双亲委派模型

双亲委派模型是 Java 类加载器的重要机制。

它的核心思想是：当一个类加载器收到类加载请求时，不会自己先加载，而是先把请求委托给父加载器。

委托过程会一直向上，直到最顶层的启动类加载器。

如果父加载器能够加载，就由父加载器完成加载；如果父加载器无法加载，才会把任务交回子加载器尝试加载。

### 双亲委派的过程

假设系统类加载器收到一个类加载请求。

过程如下：

```java
系统类加载器收到加载请求
        ↓
先委托给扩展类加载器
        ↓
扩展类加载器再委托给启动类加载器
        ↓
启动类加载器尝试加载
        ↓
如果启动类加载器能加载，直接返回
        ↓
如果不能加载，交回扩展类加载器
        ↓
扩展类加载器尝试加载
        ↓
如果还不能加载，交回系统类加载器
        ↓
系统类加载器最后尝试加载
```

可以总结为：

```java
先向上委托，再向下加载
```

### 双亲委派的好处

双亲委派机制主要有两个好处：

1. 避免类的重复加载；
2. 保护 Java 核心类库安全。

#### 避免类重复加载

如果没有双亲委派机制，同一个类可能被多个类加载器重复加载，导致 JVM 中出现多个“看起来名字一样，但实际不是同一个类型”的类。

双亲委派可以让父加载器优先加载公共类，从而减少重复加载问题。

#### 保护核心 API

双亲委派可以防止用户随意篡改 Java 核心类。

例如，用户自己写了一个类：

```java
package java.lang;

public class String {
}
```

如果没有双亲委派机制，系统类加载器可能会加载这个伪造的 `java.lang.String`，从而破坏 Java 核心 API。

有了双亲委派后，加载 `java.lang.String` 时，请求会先向上委托到启动类加载器。启动类加载器会优先加载 JDK 自带的 `java.lang.String`，用户自己写的 `java.lang.String` 就不会替代核心类。

这保证了 Java 核心类库的安全性和稳定性。

### 类什么时候会初始化

类被加载不代表一定会初始化。

初始化通常发生在类被主动使用时。

常见主动使用场景包括：

1. 创建类的实例；
2. 访问类的静态变量；
3. 调用类的静态方法；
4. 使用反射 `Class.forName()` 加载类；
5. 初始化子类时，父类会先初始化；
6. JVM 启动时包含 `main()` 方法的主类会初始化。

例如：

```java
new User();
```

会触发 `User` 类初始化。

```java
User.staticValue
```

访问静态变量也会触发初始化。

```java
User.staticMethod();
```

调用静态方法也会触发初始化。

### 类加载和类初始化不是一回事

需要区分：

```java
加载类
初始化类
```

加载类是把 class 文件加载进 JVM。

初始化类是执行 `<clinit>()`，也就是执行静态变量显式赋值和静态代码块。

例如：

```java
ClassLoader.getSystemClassLoader().loadClass("com.jkweilai.MyClass");
```

通常只是加载类，不会初始化类。

而：

```java
Class.forName("com.jkweilai.MyClass");
```

通常会加载并初始化类。
