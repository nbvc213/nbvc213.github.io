## 数据库基础

数据库是软件开发中用于**长期保存、组织和管理数据**的核心技术。应用程序产生的数据如果需要在程序关闭后继续保存，并能够被高效地查询、修改和共享，通常就需要借助数据库系统完成。

### 什么是数据库

**数据库（Database，DB）**是按照一定的数据结构和规则组织、存储、管理的数据集合。可以将数据库理解为一个“电子化的数据仓库”：其中的数据并不是随意堆放，而是按照特定的数据模型和结构进行组织，以便后续高效地查询、增加、修改和删除。

数据库通常具有以下特点：

- **长期存储**：数据可以持久保存在磁盘等存储设备中，不会随着程序结束而消失。
- **有组织地存储**：数据按照一定结构和规则保存，而不是简单堆积。
- **统一管理**：可以通过数据库管理系统统一完成数据的查询、增加、修改、删除、权限控制和备份等操作。
- **可共享**：多个程序或用户可以在权限允许的情况下访问同一份数据。
- **能够管理大量数据**：根据数据库类型、服务器配置和系统架构，可以管理百万级、千万级甚至更大规模的数据。

数据库存在的重要原因之一，就是现实世界中需要长期保存的数据非常多。例如用户信息、商品信息、订单记录、消费记录、出行记录、聊天消息等，都需要可靠地保存和管理。

从更广泛的角度看，**数据并不局限于文字和数字**。图片、音频、视频等同样属于数据，只是在数据库系统中可能采用不同的存储方式。

> **结论：** 数据库的核心并不是“把数据保存下来”，而是**按照一定结构和规则保存数据，使数据能够被长期、高效、可靠地管理和使用**。

### 数据库的类型

数据库可以按照采用的数据模型和组织方式进行分类。学习 Java 数据库开发时，最常接触的是**关系型数据库**和**非关系型数据库（NoSQL）**。

#### 关系型数据库

**关系型数据库（Relational Database）**是基于**关系模型**组织数据的数据库。实际使用时，数据通常以**二维表**的形式保存，不同表之间还可以通过特定字段建立联系。

例如，一个学生信息表可以保存学生数据：

| id   | name | age  |
| ---- | ---- | ---- |
| 1    | 张三 | 20   |
| 2    | 李四 | 21   |

课程信息可以存放在另一张表中，再通过其他字段或关联表描述“学生选修课程”的关系。

关系型数据库中的关系通常包括：

- **一对一**：一个对象对应另一个对象。例如一个用户对应一份用户详细资料。
- **一对多**：一个对象可以对应多个对象。例如一个班级中包含多个学生。
- **多对多**：多个对象可以分别对应多个对象。例如一个学生可以选择多门课程，一门课程也可以被多个学生选择。

> **易错点：** “一对一、一对多、多对多”描述的是**数据之间的关联关系**，并不是“关系模型”本身的完整定义。关系型数据库的核心仍然是使用关系模型，以二维表等形式组织数据。

关系型数据库主要涉及三个方面：

1. **数据结构**：描述数据以什么形式组织。关系型数据库主要使用二维表保存数据。
2. **数据操作**：规定如何查询和修改数据，通常通过 SQL 完成。
3. **完整性约束**：限制数据必须满足一定规则，例如某个字段不能为空、编号不能重复，以及不同表之间的关联必须有效等。

常见的关系型数据库管理系统包括 `MySQL`、`Oracle Database`、`Microsoft SQL Server`、`PostgreSQL`、`SQLite`、`IBM Db2` 等。

#### 非关系型数据库

**NoSQL** 泛指不以传统关系模型作为主要数据组织方式的一类数据库。NoSQL 常被解释为 **Not Only SQL**，强调数据库的数据存储方式并不局限于传统关系型数据库。

随着互联网应用规模扩大，一些系统需要面对：

- 海量数据；
- 高并发读写；
- 数据结构变化频繁；
- 分布式存储；
- 大规模横向扩展。

在这类场景下，传统关系型数据库并不一定始终是最合适的方案，因此出现了多种不同类型的 NoSQL 数据库。

NoSQL 并不是某一种具体数据库，也不存在一种统一的数据模型。常见的 NoSQL 数据模型包括键值、文档、列族、图等。

与关系型数据库相比，很多 NoSQL 数据库更加注重：

- **横向扩展能力**：可以通过增加服务器节点扩展系统容量和处理能力。
- **灵活的数据结构**：部分 NoSQL 数据库不要求所有数据具有完全相同的固定结构。
- **高并发和大数据量处理能力**：某些类型的 NoSQL 数据库针对特定读写场景进行了优化。

> **注意：** 不能简单理解为“NoSQL 没有数据关系”或者“NoSQL 不支持 ACID”。不同 NoSQL 数据库的设计目标不同，一些 NoSQL 数据库同样能够提供事务和一定程度的 ACID 保证。关系型数据库和 NoSQL 数据库只是采用了不同的数据组织方式和设计取舍。

### 数据库管理系统

#### 什么是 DBMS

**数据库管理系统（Database Management System，DBMS）\**是专门负责\**创建、管理和操作数据库的软件系统**。

数据库本身负责保存数据，而 DBMS 则负责提供操作这些数据的能力。常见功能包括：

- 创建和删除数据库；
- 创建、修改和删除数据库中的表等对象；
- 查询、增加、修改和删除数据；
- 管理用户和访问权限；
- 控制事务；
- 提供数据安全、备份和恢复等功能。

因此，严格来说：

- **DB（Database）**：数据库，即实际组织和保存的数据集合。
- **DBMS（Database Management System）**：管理数据库的软件。
- `MySQL`、`Oracle Database`、`PostgreSQL` 等属于 **DBMS**，而不是某一个具体数据库。

例如，在 MySQL 中可以创建一个名为 `shop` 的数据库：

```text
MySQL
└── shop
    ├── user
    ├── product
    └── orders
```

其中：

- `MySQL` 是数据库管理系统；
- `shop` 是数据库；
- `user`、`product`、`orders` 是数据库中的表。

> **易错点：** 日常交流中经常会把 MySQL 简称为“数据库”，这种说法便于沟通，但从概念上说，**MySQL 是数据库管理系统 DBMS**。

## SQL

### 什么是 SQL

**SQL（Structured Query Language，结构化查询语言）**是专门用于操作关系型数据库的语言。

通过 SQL，可以向数据库管理系统表达诸如以下需求：

- 创建一张表；
- 向表中添加数据；
- 查询满足条件的数据；
- 修改已有数据；
- 删除数据；
- 管理数据库用户和权限。

例如，要查询 `student` 表中的所有数据，可以编写：

```sql
SELECT * FROM student;
```

执行时，并不需要告诉数据库“先读取哪个磁盘位置，再检查哪一条记录”。只需要说明**想得到什么结果**，具体如何读取和查找数据主要由 DBMS 自己决定。

因此，SQL 属于典型的**声明式语言**，也常被称为非过程化语言。

> **结论：** 使用 SQL 时，重点通常是描述“我要什么数据”或“我要进行什么操作”，而不是详细规定数据库内部必须按照什么步骤完成。

SQL 是一套通用的语言标准，并不是只为 MySQL 设计的。MySQL、Oracle、PostgreSQL、SQL Server 等关系型数据库都支持 SQL。

不过，各数据库产品在遵循 SQL 标准的基础上也增加了自己的扩展，因此不同 DBMS 的 SQL 语法并非完全一致。

### SQL 的常见分类

SQL 通常按照用途划分为以下几类。

| 分类 | 全称                                       | 主要作用             | 常见语句                     |
| ---- | ------------------------------------------ | -------------------- | ---------------------------- |
| DQL  | Data Query Language，数据查询语言          | 查询数据             | `SELECT`                     |
| DDL  | Data Definition Language，数据定义语言     | 定义数据库结构       | `CREATE`、`ALTER`、`DROP`    |
| DML  | Data Manipulation Language，数据操纵语言   | 增加、修改、删除数据 | `INSERT`、`UPDATE`、`DELETE` |
| DCL  | Data Control Language，数据控制语言        | 管理访问权限         | `GRANT`、`REVOKE`            |
| TCL  | Transaction Control Language，事务控制语言 | 控制事务             | `COMMIT`、`ROLLBACK`         |

#### DQL：数据查询语言

**DQL**主要负责从数据库中查询数据，不直接改变数据库中已有的数据。

核心语句是：

```sql
SELECT
```

查询时经常还会配合：

```sql
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

例如：

```sql
SELECT name, age
FROM student
WHERE age >= 18
ORDER BY age;
```

这条 SQL 表示：从 `student` 表中查询年龄不小于 18 岁的学生姓名和年龄，并按照年龄排序。

#### DDL：数据定义语言

**DDL**用于定义和管理数据库中的结构，例如数据库、表等数据库对象。

常见语句包括：

```sql
CREATE
ALTER
DROP
```

例如：

```sql
CREATE TABLE student (
    id INT,
    name VARCHAR(20)
);
```

这类语句关注的是**数据应该按照什么结构保存**，而不是某一条具体的数据内容。

#### DML：数据操纵语言

**DML**主要负责对表中的具体数据进行增加、修改和删除。

常见语句包括：

```sql
INSERT
UPDATE
DELETE
```

例如：

```sql
INSERT INTO student (id, name)
VALUES (1, '张三');
```

这条 SQL 会向 `student` 表中插入一条数据。

#### DCL：数据控制语言

**DCL**主要负责控制数据库用户对数据库对象的访问权限。

常见语句包括：

```sql
GRANT
REVOKE
```

其中：

- `GRANT`：授予权限；
- `REVOKE`：撤销权限。

例如，数据库管理员可以允许某个用户查询指定表，但不允许该用户删除表中的数据。

#### TCL：事务控制语言

**TCL**用于控制数据库事务。

常见语句包括：

```sql
COMMIT
ROLLBACK
```

其中：

- `COMMIT`：提交事务，使当前事务中的修改正式生效；
- `ROLLBACK`：回滚事务，撤销当前事务中尚未提交的修改。

事务的具体工作机制会在后续数据库事务相关知识中进一步学习。

> **补充：** 有些资料会使用 `TPL`（Transaction Processing Language）表示事务处理语言，或者单独列出游标控制相关语句。但在 Java 和数据库基础学习中，更常见的分类是 **DQL、DDL、DML、DCL、TCL**，因此优先掌握这五类即可。

### DB、DBMS 与 SQL 的关系

数据库开发中最容易混淆的三个概念是 **DB、DBMS 和 SQL**：

```text
应用程序 / 用户
       │
       │ 编写 SQL
       ▼
      DBMS
       │
       │ 执行 SQL，对数据进行管理
       ▼
       DB
```

三者的职责可以概括为：

| 概念 | 含义                                       | 作用                             |
| ---- | ------------------------------------------ | -------------------------------- |
| DB   | Database，数据库                           | 保存和组织数据                   |
| DBMS | Database Management System，数据库管理系统 | 管理和操作数据库                 |
| SQL  | Structured Query Language，结构化查询语言  | 向关系型 DBMS 表达数据库操作要求 |

例如，Java 程序需要查询用户信息时，可以向 MySQL 发送一条 SQL：

```sql
SELECT * FROM user;
```

这里：

1. **Java 程序**发出 SQL；
2. **MySQL（DBMS）**负责解析并执行 SQL；
3. DBMS 从对应的 **数据库（DB）**中读取数据；
4. 查询结果再返回给 Java 程序。

> **结论：** **DB 用来存数据，DBMS 用来管理 DB，SQL 是操作关系型 DBMS 的主要语言。**

## MySQL 概述

**MySQL** 是一种常用的**关系型数据库管理系统（RDBMS）**，主要负责数据库的创建、存储和管理，并通过 SQL 完成数据的查询、增加、修改、删除等操作。

MySQL 最初由瑞典 MySQL AB 公司开发，后来 MySQL AB 被 Sun 公司收购，Sun 公司又被 Oracle 公司收购，因此 MySQL 目前属于 Oracle 旗下产品。

MySQL 具有以下特点：

- **提供免费版本**：MySQL Community Edition（社区版）可以免费使用，同时也存在面向企业的商业版本。
- **能够管理大量数据**：可以用于存储和管理规模较大的业务数据，实际能够承载的数据量还会受到硬件配置、表结构、索引设计和系统架构等因素影响。
- **使用 SQL**：MySQL 使用 SQL 作为主要的数据库操作语言，同时也在 SQL 标准基础上提供了一些自己的扩展。
- **支持多种操作系统**：可以运行在 Windows、Linux 等不同平台上。
- **支持多种编程语言**：Java、C、C++、Python、PHP 等语言都可以通过相应的驱动程序连接 MySQL。
- **应用广泛**：经常用于 Web 应用、企业后台系统等需要持久化存储数据的场景。

> **易错点：** 严格来说，MySQL 是 **DBMS（数据库管理系统）**，不是某一个具体的数据库 DB。平时所说的“安装 MySQL”，实际上是在安装用于管理数据库的软件系统。

## MySQL 的安装

Windows 下安装 MySQL 常见的方式有两种：

| 安装方式   | 特点                                          |
| ---------- | --------------------------------------------- |
| MSI 安装包 | 通过图形化安装程序完成配置，操作相对简单      |
| ZIP 压缩包 | 解压后手动配置，更有利于理解 MySQL 的安装过程 |

下面主要介绍 **ZIP 压缩包的手动安装方式**。

### 下载并解压 MySQL

从 MySQL 官网下载适用于 Windows 的 MySQL Community Server ZIP 压缩包，然后将其解压到指定目录。

例如：

```text
C:\mysql
```

解压后的目录中会包含 `bin`、`lib`、`share` 等目录，其中 `bin` 目录保存了 MySQL 的主要可执行程序。

常见程序包括：

- `mysqld`：MySQL **服务器程序**，负责真正管理数据库。
- `mysql`：MySQL **命令行客户端程序**，用于连接 MySQL Server 并执行 SQL。

### 配置 Path 环境变量

将 MySQL 的 `bin` 目录加入系统环境变量 `Path`：

```text
C:\mysql\bin
```

配置后，可以直接在命令行中执行：

```text
mysql
mysqld
```

否则通常需要写出完整路径才能执行这些程序。

> **注意：** 修改 `Path` 时应当在原有内容基础上**新增 MySQL 的路径**，不要覆盖已有的环境变量内容。

### 初始化数据目录

ZIP 方式安装 MySQL 时，需要手动初始化 MySQL 的**数据目录（Data Directory）**。

使用管理员权限打开命令提示符，进入 MySQL 的 `bin` 目录：

```text
cd C:\mysql\bin
```

执行：

```text
mysqld --initialize --console
```

初始化过程中，MySQL 会完成以下工作：

1. 创建所需的数据目录和系统文件。
2. 初始化 MySQL 内部使用的系统数据。
3. 创建初始的 `root` 管理员账户。
4. 在控制台生成 `root` 用户的**临时密码**。

生成的临时密码需要妥善保存，第一次登录 MySQL 时会用到。

> **易错点：** `data` 目录不能简单理解为“一个数据库”。它是整个 MySQL Server 的**数据目录**，其中可以保存多个数据库以及 MySQL 自身运行所需的数据。

### 安装 MySQL Windows 服务

为了让 Windows 统一管理 MySQL Server，可以将 MySQL 注册为 Windows 服务。

进入 `bin` 目录后，以管理员权限执行：

```text
mysqld --install
```

如果没有指定其他服务名称，通常会注册一个名为：

```text
MySQL
```

的 Windows 服务。

安装完成后，可以通过 Windows 的“服务”管理界面查看 MySQL 服务。

也可以自定义服务名称，例如：

```text
mysqld --install MySQL84
```

此时服务名称就是 `MySQL84`。

> **易错点：** `mysqld --initialize` 和 `mysqld --install` 的作用不同。前者用于**初始化数据目录**，后者用于**注册 Windows 服务**，不能互相替代。

### MySQL 的卸载

如果使用 ZIP 方式手动安装 MySQL，卸载时通常按照以下顺序进行。

1. 停止 MySQL 服务：

```text
net stop MySQL
```

1. 删除 MySQL Windows 服务：

```text
mysqld --remove
```

也可以使用：

```text
sc delete MySQL
```

1. 删除 MySQL 的安装目录。

例如：

```text
C:\mysql
```

1. 如果之前配置了系统 `Path`，将其中的 MySQL `bin` 路径删除。

> **注意：** 如果 MySQL 的数据目录位于安装目录中，直接删除整个安装目录会同时删除其中保存的数据库数据。需要保留数据时，应先进行备份。

## MySQL 的使用

### 启动和停止 MySQL 服务

MySQL 安装为 Windows 服务后，可以使用命令控制其运行状态。

启动 MySQL 服务：

```text
net start MySQL
```

停止 MySQL 服务：

```text
net stop MySQL
```

其中的 `MySQL` 是**Windows 服务名称**。

如果安装时使用了其他名称，例如：

```text
mysqld --install MySQL84
```

那么启动时应使用：

```text
net start MySQL84
```

停止时使用：

```text
net stop MySQL84
```

也可以在 Windows 的“服务”管理界面中手动启动或停止 MySQL 服务。

### 登录 MySQL

MySQL Server 启动后，可以使用 `mysql` 命令行客户端进行连接。

使用 `root` 用户登录：

```text
mysql -u root -p
```

其中：

- `mysql`：启动 MySQL 命令行客户端。
- `-u`：指定登录使用的用户名。
- `root`：MySQL 默认创建的管理员账户。
- `-p`：表示登录时需要输入密码。

执行命令后，输入初始化 MySQL 时生成的临时密码。

登录成功后，会进入：

```text
mysql>
```

此时就可以输入 SQL 操作数据库。

整个过程可以理解为：

```text
mysql 客户端
     │
     │ 用户名、密码、SQL
     ▼
mysqld 服务器
     │
     ▼
数据库中的数据
```

因此：

```text
mysql -u root -p
```

并不是启动 MySQL Server，而是**启动客户端并连接已经运行的 MySQL Server**。

### 修改 root 密码

第一次使用临时密码登录后，需要修改 `root` 用户的密码。

基础学习时推荐使用：

```sql
ALTER USER 'root'@'localhost'
IDENTIFIED BY 'NewPassword123!';
```

其中：

- `root`：用户名。
- `localhost`：表示该账户从本机连接。
- `IDENTIFIED BY`：用于设置账户密码。

在 MySQL 8 中，也可以显式指定认证插件。例如 MySQL 8.4 默认使用 `caching_sha2_password`：

```sql
ALTER USER 'root'@'localhost'
IDENTIFIED WITH caching_sha2_password
BY 'NewPassword123!';
```

旧资料中可能还会出现：

```sql
ALTER USER 'root'@'localhost'
IDENTIFIED WITH mysql_native_password
BY 'NewPassword123!';
```

`mysql_native_password` 属于较旧的认证方式，在 MySQL 8.4 中已经默认禁用，因此新版本中不应再把它作为默认写法。

> **结论：** 基础学习阶段修改密码时，优先使用 `IDENTIFIED BY` 即可；只有确实需要指定认证方式时，再显式设置认证插件。

### 安装与使用流程总结

使用 ZIP 包安装并使用 MySQL，可以按照下面的流程理解：

```text
下载并解压 MySQL
        ↓
配置 bin 目录到 Path
        ↓
初始化数据目录
mysqld --initialize --console
        ↓
保存 root 临时密码
        ↓
注册 Windows 服务
mysqld --install
        ↓
启动 MySQL Server
net start MySQL
        ↓
使用 mysql 客户端登录
mysql -u root -p
        ↓
修改 root 密码
        ↓
开始执行 SQL
```

其中需要重点区分：

| 程序     | 作用                                         |
| -------- | -------------------------------------------- |
| `mysqld` | MySQL Server 服务端程序，负责管理数据库      |
| `mysql`  | MySQL 命令行客户端，负责连接服务器并发送 SQL |

> **结论：** `mysqld` 负责“提供数据库服务”，`mysql` 负责“连接数据库服务”。先要保证 MySQL Server 正常运行，客户端才能成功连接。

## 登录 MySQL

MySQL Server 启动后，可以通过 `mysql` 命令行客户端连接服务器。根据客户端和服务器是否位于同一台计算机，可以分为**本地登录**和**远程登录**。

### 本地登录

使用 `root` 用户登录本机 MySQL：

```text
mysql -u root -p
```

执行后输入 `root` 用户的密码，认证成功即可进入 MySQL 命令行。

这条命令可以拆分理解：

| 内容      | 含义                                                     |
| --------- | -------------------------------------------------------- |
| `mysql`   | 启动 MySQL 命令行客户端，对应 `bin` 目录中的 `mysql.exe` |
| `-u root` | 指定登录用户为 `root`，`-u` 是 `--user` 的简写           |
| `-p`      | 要求输入密码，`-p` 是 `--password` 的简写                |

如果已经将 MySQL 的 `bin` 目录配置到系统 `Path` 中，就可以在任意命令行目录直接执行 `mysql`；否则需要进入 `bin` 目录，或者使用 `mysql.exe` 的完整路径。

密码也可以直接写在 `-p` 后面，例如：

```text
mysql -u root -p123456
```

其中 `-p` 与密码之间**不能添加空格**。不过这种方式会将密码直接暴露在命令中，因此不推荐使用。更安全的方式是只写 `-p`，然后根据提示输入密码。

> **注意：** 日常登录推荐使用 `mysql -u root -p`，不要把密码直接写在命令行中。

### 远程登录

如果 MySQL Server 安装在另一台计算机上，需要通过 `-h` 指定服务器地址：

```text
mysql -h 192.168.1.100 -u dev_user -p
```

其中：

- `-h` 是 `--host` 的简写，用于指定 MySQL Server 所在的主机；
- `192.168.1.100` 是服务器的 IP 地址；
- `dev_user` 是用于登录远程 MySQL 的账户。

如果服务器没有使用默认的 `3306` 端口，还可以通过大写的 `-P` 指定端口：

```text
mysql -h 192.168.1.100 -P 3307 -u dev_user -p
```

`127.0.0.1` 是本机 IPv4 回环地址，`localhost` 也通常表示当前计算机。因此连接本机 MySQL 时经常可以看到：

```text
mysql -h 127.0.0.1 -u root -p
```

或者：

```text
mysql -h localhost -u root -p
```

二者在“连接本机”这一点上作用相近，但 MySQL 对不同主机写法可能采用不同的连接方式，因此不能简单认为它们在所有情况下完全等价。

MySQL 初始化后默认创建的是：

```text
'root'@'localhost'
```

这表示该 `root` 账户主要用于**本机管理**，默认不应直接开放给其他计算机远程使用。

不推荐通过直接修改 `mysql.user` 表，把：

```text
'root'@'localhost'
```

修改成允许任意主机连接的账户。更合理的做法是根据实际需要创建专门的远程用户，并只授予所需权限。

例如，只允许 IP 为 `192.168.1.20` 的计算机使用 `dev_user`：

```sql
CREATE USER 'dev_user'@'192.168.1.20'
IDENTIFIED BY 'Password123!';
```

授予该用户操作 `test` 数据库的权限：

```sql
GRANT ALL PRIVILEGES ON test.* TO 'dev_user'@'192.168.1.20';
```

此后可以在 `192.168.1.20` 上执行：

```text
mysql -h 192.168.1.100 -u dev_user -p
```

连接位于 `192.168.1.100` 的 MySQL Server。

通过 `CREATE USER`、`GRANT` 等账户管理语句修改权限后会直接生效，一般不需要再执行：

```sql
FLUSH PRIVILEGES;
```

`FLUSH PRIVILEGES` 主要与直接修改 MySQL 授权表等特殊情况有关，而直接修改授权表本身也不是推荐的账户管理方式。

> **注意：** 能否远程连接不仅取决于 MySQL 用户，还与 MySQL Server 的监听地址、服务器防火墙和网络是否连通有关。实际开发中通常创建专门的业务或开发账户，而不是为了方便直接开放 `root` 远程登录。

## MySQL 命令行常用命令

登录 MySQL 后，可以通过一些基本命令查看和管理数据库。

**1. 查看当前 MySQL Server 中的数据库**

```sql
SHOW DATABASES;
```

**2. 创建数据库**

创建一个名为 `test` 的数据库：

```sql
CREATE DATABASE test;
```

**3. 切换到指定数据库**

```sql
USE test;
```

执行后，后续对表的操作默认针对 `test` 数据库。

**4. 查看当前正在使用的数据库**

```sql
SELECT DATABASE();
```

如果尚未通过 `USE` 选择数据库，结果通常为 `NULL`。

**5. 查看当前数据库中的表**

```sql
SHOW TABLES;
```

`SHOW TABLES` 查询的是**当前已经选择的数据库**，因此通常需要先执行：

```sql
USE test;
```

**6. 删除数据库**

```sql
DROP DATABASE test;
```

执行后，`test` 数据库及其中的表和数据都会被删除。

> **注意：** `DROP DATABASE` 属于破坏性操作。数据库被删除后，其中的数据也会随之删除，执行前应确认数据库名称。

**7. 查看 MySQL Server 版本**

登录 MySQL 后执行：

```sql
SELECT VERSION();
```

如果还没有登录 MySQL，也可以在操作系统命令行执行：

```text
mysql --version
```

二者的使用位置不同：

```text
Windows 命令行
    │
    ├── mysql --version
    │
    └── mysql -u root -p
              ↓
            mysql>
              │
              └── SELECT VERSION();
```

**8. 退出 MySQL**

可以使用：

```text
exit
```

或者：

```text
quit
```

也可以使用：

```text
\q
```

> **易错点：** `Ctrl + C` 主要用于中断或取消当前正在输入、执行的语句，并不是标准的退出 MySQL 命令。退出客户端应使用 `exit`、`quit` 或 `\q`。

## 数据库表

**表（Table）是关系型数据库中存储和组织数据的基本结构。** 一张表由行和列组成，可以直观地表示同一类对象的数据。

例如，可以使用一张学生表保存学生信息：

| name |  age | gender |
| ---- | ---: | ------ |
| 张三 |   20 | 男     |
| 李四 |   22 | 女     |

其中：

- **行（Row）**：也称为**记录（Record）**，一行表示一条完整的数据。例如“张三、20、男”就是一条学生记录。
- **列（Column）**：也称为**字段（Field）**，表示数据的某一种属性。例如 `name`、`age`、`gender` 都是字段。

可以将表理解为：

```text
student 表

             字段（列）
       ┌────────┬─────┬────────┐
       │ name   │ age │ gender │
┌─────▶├────────┼─────┼────────┤
│      │ 张三    │ 20  │ 男     │
│记录  ├────────┼─────┼────────┤
│（行）│ 李四    │ 22  │ 女     │
└─────▶└────────┴─────┴────────┘
```

每个字段在创建时通常需要确定以下信息：

| 属性       | 作用                                 | 示例                     |
| ---------- | ------------------------------------ | ------------------------ |
| 字段名     | 标识该字段保存什么数据               | `name`、`age`            |
| 数据类型   | 规定字段能够保存什么类型的数据       | `VARCHAR`、`INT`、`DATE` |
| 长度或精度 | 某些数据类型可以进一步限制长度或精度 | `VARCHAR(20)`            |
| 约束       | 对字段中的数据增加规则               | 非空、唯一、主键等       |

例如：

```sql
CREATE TABLE student (
    id INT NOT NULL,
    name VARCHAR(20),
    age INT,
    PRIMARY KEY (id)
);
```

其中：

- `id` 保存学生编号，数据类型为 `INT`；
- `NOT NULL` 表示 `id` 不能为空；
- `name` 使用 `VARCHAR(20)` 保存字符串；
- `PRIMARY KEY` 表示 `id` 是该表的主键。

字段名通常采用简洁统一的命名方式。在项目中经常使用**全小写字母，多个单词之间使用下划线连接**，例如：

```text
student_name
hire_date
department_id
```

这属于常见的数据库命名规范，具体项目还应遵循项目自身约定。

> **结论：** 数据库负责管理数据，关系型数据库中的数据主要组织在表中；**表由行和列组成，一行是一条记录，一列是一个字段**。

### 熟悉测试数据

后续 SQL 查询主要围绕 `emp`、`dept`、`salgrade` 三张表展开，因此需要先熟悉每张表及字段的含义。

| 表名       | 保存的数据   |
| ---------- | ------------ |
| `emp`      | 员工信息     |
| `dept`     | 部门信息     |
| `salgrade` | 工资等级信息 |

#### 查看表结构

可以通过 `DESC` 或 `DESCRIBE` 查看一张表的结构：

```sql
DESC emp;
```

或者：

```sql
DESCRIBE emp;
```

这里查询的不是表中的具体数据，而是**表的结构信息**。

常见结果字段包括：

| 字段      | 含义                   |
| --------- | ---------------------- |
| `Field`   | 字段名                 |
| `Type`    | 字段的数据类型         |
| `Null`    | 是否允许保存 `NULL`    |
| `Key`     | 字段的索引或键相关信息 |
| `Default` | 字段的默认值           |
| `Extra`   | 字段的其他附加信息     |

其中 `Key` 常见值包括：

- `PRI`：该字段属于主键；
- `UNI`：该字段具有唯一索引；
- `MUL`：该字段具有非唯一索引，一个值可以重复出现。

> **易错点：** `DESC` 结果中的 `Key` 不能简单理解为“这个字段是不是主键或外键”。例如外键列不一定会直接以“外键”字样显示。当前阶段重点先认识 `PRI` 表示主键即可。

#### `emp` 员工表

`emp` 保存员工信息：

| 字段       | 含义                                     |
| ---------- | ---------------------------------------- |
| `empno`    | 员工编号，整数类型，不能为空，并且是主键 |
| `ename`    | 员工姓名                                 |
| `job`      | 工作岗位                                 |
| `mgr`      | 直属上级的员工编号                       |
| `hiredate` | 入职日期                                 |
| `sal`      | 工资                                     |
| `comm`     | 奖金或补助                               |
| `deptno`   | 员工所在部门的编号                       |

例如：

```text
7369  SMITH  CLERK  7902  1980-12-17  800  NULL  20
```

表示：

- 员工编号为 `7369`；
- 姓名为 `SMITH`；
- 岗位为 `CLERK`；
- 上级员工编号为 `7902`；
- 入职日期为 `1980-12-17`；
- 工资为 `800`；
- 没有奖金或补助；
- 所属部门编号为 `20`。

其中 `mgr` 保存的同样是员工编号。例如员工 `SMITH` 的 `mgr` 为 `7902`，可以在 `emp` 表中找到员工编号为 `7902` 的员工 `FORD`。这说明 `SMITH` 的直属上级是 `FORD`。

#### `dept` 部门表

`dept` 保存部门信息：

| 字段     | 含义           |
| -------- | -------------- |
| `deptno` | 部门编号，主键 |
| `dname`  | 部门名称       |
| `loc`    | 部门所在地     |

例如：

```text
20  RESEARCH  DALLAS
```

表示编号为 `20` 的部门名称为 `RESEARCH`，所在地为 `DALLAS`。

`emp` 表中的 `deptno` 与 `dept` 表中的 `deptno` 在业务含义上相互对应。

例如：

```text
emp
SMITH → deptno = 20

              ↓

dept
20 → RESEARCH → DALLAS
```

因此可以通过部门编号找到员工所属部门的信息，这也是后续学习**多表查询**时的重要基础。

> **注意：** 当前测试脚本只是让 `emp.deptno` 和 `dept.deptno` 在业务含义上建立联系，并没有显式声明 `FOREIGN KEY` 外键约束。字段之间“有业务关系”和“数据库中已经创建外键约束”是两个不同概念。

#### `salgrade` 工资等级表

`salgrade` 保存工资等级及对应的工资区间：

| 字段    | 含义             |
| ------- | ---------------- |
| `grade` | 工资等级         |
| `losal` | 该等级的最低工资 |
| `hisal` | 该等级的最高工资 |

例如：

```text
GRADE = 3
LOSAL = 1401
HISAL = 2000
```

表示工资位于 `1401 ~ 2000` 范围内时，对应工资等级 `3`。

因此，如果某个员工的工资为：

```text
1600
```

根据 `salgrade` 表可以判断：

```text
1401 <= 1600 <= 2000
```

该员工属于工资等级 `3`。

后续学习 SQL 查询时，需要逐渐熟悉三张表之间的数据关系：

```text
EMP
员工信息
│
├── deptno ───────→ DEPT
│                   部门信息
│
└── sal ──────────→ SALGRADE
                    根据工资区间确定工资等级
```

可以分别查看三张表中的数据：

```sql
SELECT * FROM emp;
```

```sql
SELECT * FROM dept;
```

```sql
SELECT * FROM salgrade;
```

> **结论：** 后续查询练习中，应能够快速判断字段所属的表及其含义。例如看到 `ename` 应想到员工姓名，看到 `deptno` 应想到部门编号，看到 `sal` 应想到员工工资，看到 `losal`、`hisal` 应想到工资等级的上下限。

## 简单查询

查询是 SQL 中最核心的操作之一，属于 **DQL（数据查询语言）**。查询主要通过 `SELECT` 语句完成，它负责从数据库表中检索需要的数据，并将查询结果返回。

完整的 `SELECT` 查询可以包含 `SELECT`、`FROM`、`WHERE`、`GROUP BY`、`ORDER BY` 等多个子句。当前阶段先学习最基础的字段查询和条件查询。

### 查询字段

查询指定字段的基本格式为：

```sql
SELECT 字段名
FROM 表名;
```

例如，查询所有员工的编号：

```sql
SELECT empno
FROM emp;
```

查询所有员工的姓名：

```sql
SELECT ename
FROM emp;
```

其中：

- `SELECT` 表示需要查询什么内容；
- `FROM` 表示数据来自哪张表；
- `empno`、`ename` 是字段名；
- `emp` 是表名。

如果不知道一张表有哪些字段，可以通过：

```sql
DESC emp;
```

查看表结构。

在 `mysql` 命令行客户端中，一条 SQL 通常以分号 `;` 表示结束。没有输入分号时，客户端会认为语句还没有输入完成，继续等待后续内容。

例如：

```text
mysql> SELECT ename
    ->
```

补上：

```text
;
```

后才会提交执行。

如果一条 SQL 尚未执行，并且发现已经写错，可以在 `mysql` 客户端中输入：

```text
\c
```

取消当前正在输入的语句。

> **注意：** SQL 关键字通常不区分大小写，因此 `SELECT`、`select` 都可以使用。为了提高可读性，笔记和项目中通常将 SQL 关键字写成大写。数据库名、表名是否区分大小写还可能受到操作系统和 MySQL 配置影响，因此不能简单理解为“SQL 中所有内容都不区分大小写”。

---

### 查询多个字段

查询多个字段时，在字段之间使用逗号 `,` 分隔：

```sql
SELECT 字段1, 字段2, 字段3
FROM 表名;
```

例如，查询员工编号和员工姓名：

```sql
SELECT empno, ename
FROM emp;
```

`SELECT` 后字段的书写顺序决定**查询结果中各列的显示顺序**。

例如：

```sql
SELECT ename, empno
FROM emp;
```

和：

```sql
SELECT empno, ename
FROM emp;
```

查询的是相同的两个字段，但结果中的列顺序不同。

---

### 查询所有字段

如果需要查询表中的所有字段，可以将所有字段逐一列出：

```sql
SELECT empno, ename, job, mgr, hiredate, sal, comm, deptno
FROM emp;
```

也可以使用 `*` 表示所有字段：

```sql
SELECT *
FROM emp;
```

例如，查看所有部门信息：

```sql
SELECT *
FROM dept;
```

`SELECT *` 写法简单，非常适合在学习、调试或者临时查看数据时使用，但正式项目代码中通常更推荐明确写出需要的字段。

主要原因包括：

- **可读性更好**：可以直接看出程序到底需要哪些数据；
- **避免查询无用数据**：如果表中字段很多，只查询实际需要的字段可以减少不必要的数据读取和传输；
- **降低表结构变化的影响**：表增加新字段以后，明确指定字段的 SQL 返回结构更加稳定；
- **有利于数据库优化**：某些情况下，只查询特定字段可以更充分地利用索引。

因此，开发中更推荐：

```sql
SELECT empno, ename, sal
FROM emp;
```

而不是无条件使用：

```sql
SELECT *
FROM emp;
```

> **结论：** `SELECT *` 适合快速查看数据；正式业务查询应尽量明确写出实际需要的字段。

---

### 查询字段参与运算

`SELECT` 后不仅可以写字段本身，还可以编写表达式。数值字段可以参与加、减、乘、除等数学运算。

例如，查询员工姓名和月薪：

```sql
SELECT ename, sal
FROM emp;
```

如果 `sal` 保存的是月薪，可以计算年薪：

```sql
SELECT ename, sal * 12
FROM emp;
```

还可以先给月薪增加 `1000`，再计算新的年薪：

```sql
SELECT ename, (sal + 1000) * 12
FROM emp;
```

这里的计算只发生在**查询结果中**，并不会修改表中原来保存的 `sal` 数据。

例如：

```sql
SELECT sal + 1000
FROM emp;
```

只是将计算结果展示出来，数据库中的工资并没有真正增加 `1000`。

> **注意：** 查询表达式和修改数据是两件不同的事情。`SELECT` 中进行计算不会改变原始数据。

---

### 字段别名

当查询结果中包含表达式时，默认列名可能不够直观。

例如：

```sql
SELECT ename, sal * 12
FROM emp;
```

结果中的第二列可能显示为：

```text
sal * 12
```

可以通过**别名（Alias）**为查询结果中的列重新命名。

基本格式为：

```sql
SELECT 字段或表达式 AS 别名
FROM 表名;
```

例如：

```sql
SELECT ename, sal * 12 AS annual_salary
FROM emp;
```

结果中的第二列就会显示为：

```text
annual_salary
```

`AS` 可以省略：

```sql
SELECT ename, sal * 12 annual_salary
FROM emp;
```

两种写法效果相同。

为了让含义更加清楚，初学阶段建议保留 `AS`：

```sql
SELECT ename AS employee_name,
       sal AS monthly_salary
FROM emp;
```

别名只会改变**查询结果中显示的列名**，不会修改数据库表中的真实字段名。

#### 别名包含特殊字符或空格

如果别名中包含空格，可以使用反引号：

```sql
SELECT ename,
       sal * 12 AS `annual salary`
FROM emp;
```

中文别名也可以使用：

```sql
SELECT ename AS 姓名,
       sal AS 月薪,
       sal * 12 AS 年薪
FROM emp;
```

如果希望统一处理包含空格或特殊字符的别名，也可以使用反引号：

```sql
SELECT ename AS `员工姓名`,
       sal * 12 AS `员工年薪`
FROM emp;
```

> **注意：** SQL 中普通字符串值推荐统一使用**单引号**，例如 `'FORD'`。字段名、表名、别名等属于标识符，不要把字符串引号和标识符的写法混为一谈。

---

## 条件查询

实际开发中很少每次都查询整张表的数据，更多情况下只需要查询**满足某些条件的数据**。

条件查询通过 `WHERE` 子句完成：

```sql
SELECT 字段
FROM 表名
WHERE 条件;
```

例如，只查询工资为 `3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal = 3000;
```

常见条件运算符如下：

| 运算符                | 含义                   |
| --------------------- | ---------------------- |
| `=`                   | 等于                   |
| `<>`、`!=`            | 不等于                 |
| `>`                   | 大于                   |
| `>=`                  | 大于等于               |
| `<`                   | 小于                   |
| `<=`                  | 小于等于               |
| `BETWEEN ... AND ...` | 判断是否位于指定区间   |
| `IS NULL`             | 判断是否为 `NULL`      |
| `IS NOT NULL`         | 判断是否不为 `NULL`    |
| `AND`                 | 多个条件同时成立       |
| `OR`                  | 多个条件至少一个成立   |
| `IN`                  | 是否属于指定的一组值   |
| `NOT IN`              | 是否不属于指定的一组值 |
| `LIKE`                | 模糊匹配               |

对于当前阶段的简单查询，可以把 SQL 的逻辑处理顺序理解为：

```text
FROM
  ↓
WHERE
  ↓
SELECT
```

例如：

```sql
SELECT ename
FROM emp
WHERE sal > 2000;
```

可以理解为：

1. 先确定从 `emp` 表获取数据；
2. 使用 `sal > 2000` 过滤记录；
3. 从过滤后的记录中取出 `ename` 并返回。

后续加入分组、排序等子句后，完整的逻辑执行顺序还会继续扩展。

---

### 等于和不等于

#### 等于 `=`

`=` 用于判断两个值是否相等，可以比较数字、字符串、日期等数据。

例如，查询工资为 `3000` 的员工：

```sql
SELECT empno, ename, sal
FROM emp
WHERE sal = 3000;
```

查询姓名为 `FORD` 的员工：

```sql
SELECT job, sal
FROM emp
WHERE ename = 'FORD';
```

字符串值通常使用**单引号**：

```sql
'FORD'
'MANAGER'
'CLERK'
```

是否能够使用：

```sql
WHERE ename = 'ford'
```

匹配数据库中的：

```text
FORD
```

取决于字段采用的**排序规则（Collation）**。

很多 MySQL 默认使用的排序规则是不区分大小写的，因此可能认为：

```text
FORD
ford
Ford
```

相等。但如果使用区分大小写的排序规则，比较结果就会不同。

> **易错点：** 不能简单记忆成“MySQL 中表里的字符串不区分大小写”。**字符串比较是否区分大小写由字符集和排序规则等因素决定。**

#### 不等于 `<>`、`!=`

MySQL 支持两种常见的不等于写法：

```text
<>
!=
```

例如，查询工资不是 `3000` 的员工：

```sql
SELECT empno, ename, sal
FROM emp
WHERE sal <> 3000;
```

也可以写成：

```sql
SELECT empno, ename, sal
FROM emp
WHERE sal != 3000;
```

`<>` 是标准 SQL 中常见的不等于写法，`!=` 与 Java 中的不等号写法相同，也被 MySQL 支持。

查询岗位不是 `MANAGER` 的员工：

```sql
SELECT ename, job
FROM emp
WHERE job <> 'MANAGER';
```

---

### 大小比较

条件查询可以直接进行大小比较。

查询工资大于 `3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal > 3000;
```

查询工资大于等于 `3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal >= 3000;
```

查询工资小于 `3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal < 3000;
```

查询工资小于等于 `3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal <= 3000;
```

---

### AND

`AND` 表示多个条件需要**同时成立**。

例如，查询工资大于等于 `3000` 并且小于等于 `5000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal >= 3000
  AND sal <= 5000;
```

只有同时满足：

```text
sal >= 3000
```

和：

```text
sal <= 5000
```

的记录才会被保留下来。

MySQL 也支持：

```text
&&
```

表示逻辑与，但这是 MySQL 的扩展写法。为了让 SQL 更清晰、更通用，**推荐始终使用 `AND`**。

---

### OR

`OR` 表示多个条件中**至少一个成立即可**。

例如，查询岗位为 `MANAGER` 或 `SALESMAN` 的员工：

```sql
SELECT ename, job
FROM emp
WHERE job = 'MANAGER'
   OR job = 'SALESMAN';
```

这里不能写成：

```sql
WHERE job = 'MANAGER'
  AND job = 'SALESMAN'
```

因为一条员工记录中的 `job` 不可能既等于 `MANAGER`，又同时等于 `SALESMAN`。

因此，自然语言中的“和”不一定对应 SQL 中的 `AND`。

例如：

> 查询 20 和 30 部门的员工。

实际含义是：

```text
部门编号 = 20
或者
部门编号 = 30
```

所以应该使用：

```sql
SELECT *
FROM emp
WHERE deptno = 20
   OR deptno = 30;
```

> **结论：** 判断应该使用 `AND` 还是 `OR`，不能只看自然语言中有没有“和”“或者”，而应判断**一条记录需要同时满足多个条件，还是满足其中一个条件即可**。

MySQL 默认情况下也支持 `||` 表示 `OR`，但其含义可能受到 SQL 模式影响，因此实际开发中推荐明确使用：

```sql
OR
```

---

### AND 与 OR 的优先级

当 `AND` 和 `OR` 同时出现时，**`AND` 的优先级高于 `OR`**。

例如，希望查询：

> 工资小于 `1500`，并且部门编号为 `20` 或 `30` 的员工。

如果写成：

```sql
SELECT ename, sal, deptno
FROM emp
WHERE sal < 1500
  AND deptno = 20
   OR deptno = 30;
```

实际判断关系更接近：

```text
(sal < 1500 AND deptno = 20)
OR
deptno = 30
```

结果会把部门编号为 `30` 的员工全部包含进来，即使某些员工工资并不小于 `1500`。

正确写法应该明确使用括号：

```sql
SELECT ename, sal, deptno
FROM emp
WHERE sal < 1500
  AND (deptno = 20 OR deptno = 30);
```

此时：

```text
sal < 1500
```

是所有结果都必须满足的条件，然后再要求部门编号满足 `20` 或 `30`。

> **结论：** 遇到多个 `AND`、`OR` 混合使用时，不要依赖记忆复杂的运算符优先级。**通过小括号明确表达条件之间的组合关系，通常是最清晰、最安全的写法。**

---

### BETWEEN ... AND ...

`BETWEEN ... AND ...` 用于判断一个值是否位于指定区间。

基本格式：

```sql
字段 BETWEEN 最小值 AND 最大值
```

例如，查询工资位于 `1600 ~ 3000` 的员工：

```sql
SELECT ename, sal
FROM emp
WHERE sal BETWEEN 1600 AND 3000;
```

它等价于：

```sql
SELECT ename, sal
FROM emp
WHERE sal >= 1600
  AND sal <= 3000;
```

因此，`BETWEEN ... AND ...` **包含左右两个边界值**。

```text
1600 <= sal <= 3000
```

书写时通常应按照：

```text
小值 → 大值
```

的顺序。

例如：

```sql
sal BETWEEN 1600 AND 3000
```

如果写成：

```sql
sal BETWEEN 3000 AND 1600
```

相当于同时要求：

```text
sal >= 3000
并且
sal <= 1600
```

普通情况下自然无法匹配记录。

`BETWEEN ... AND ...` 也可以用于日期。

例如，查询在 `1982-01-23` 到 `1987-04-19` 之间入职的员工：

```sql
SELECT ename, hiredate
FROM emp
WHERE hiredate BETWEEN '1982-01-23' AND '1987-04-19';
```

日期字面值需要使用单引号括起来。

> **结论：** `BETWEEN a AND b` 可以记忆为 **`>= a AND <= b`**，左右边界都包含在查询范围内。

---

### NULL 判断

数据库中的 `NULL` 表示**缺失、未知或者没有提供值**。

`NULL` 不是数字 `0`，也不是空字符串：

```text
NULL
0
''
```

三者含义不同。

由于 `NULL` 表示未知值，因此不能使用普通的：

```text
= NULL
```

或者：

```text
<> NULL
```

判断。

#### IS NULL

查询没有津贴的员工：

```sql
SELECT ename, sal, comm
FROM emp
WHERE comm IS NULL;
```

不能写成：

```sql
WHERE comm = NULL;
```

因为：

```text
comm = NULL
```

得到的不是普通的 `TRUE` 或 `FALSE`，而是**未知（UNKNOWN）**。

#### IS NOT NULL

查询存在津贴的员工：

```sql
SELECT ename, sal, comm
FROM emp
WHERE comm IS NOT NULL;
```

不能写成：

```sql
WHERE comm <> NULL;
```

> **结论：**
>
> 判断为空：
>
> ```sql
> IS NULL
> ```
>
> 判断不为空：
>
> ```sql
> IS NOT NULL
> ```
>
> **不要使用 `= NULL` 或 `!= NULL`。**

---

### IN 和 NOT IN

#### IN

当同一个字段需要与多个确定值进行比较时，可以使用 `IN`。

例如：

```sql
WHERE job IN ('MANAGER', 'SALESMAN', 'CLERK')
```

可以理解为：

```sql
WHERE job = 'MANAGER'
   OR job = 'SALESMAN'
   OR job = 'CLERK'
```

因此，查询岗位为 `MANAGER` 或 `SALESMAN` 的员工，可以写成：

```sql
SELECT ename, sal, job
FROM emp
WHERE job IN ('MANAGER', 'SALESMAN');
```

相比：

```sql
SELECT ename, sal, job
FROM emp
WHERE job = 'MANAGER'
   OR job = 'SALESMAN';
```

`IN` 在同一字段匹配多个值时通常更加简洁。

对于数字同样可以使用：

```sql
SELECT ename, sal
FROM emp
WHERE sal IN (1500, 1600, 3000);
```

表示：

```text
sal = 1500
或者
sal = 1600
或者
sal = 3000
```

> **易错点：** `IN` 表示“属于这些离散值中的某一个”，**不表示区间**。

例如：

```sql
sal IN (1500, 5000)
```

只匹配：

```text
1500
5000
```

不会匹配 `2000`、`3000`、`4000`。

如果需要查询 `1500 ~ 5000` 的区间，应使用：

```sql
sal BETWEEN 1500 AND 5000
```

或者：

```sql
sal >= 1500 AND sal <= 5000
```

#### NOT IN

`NOT IN` 表示某个值**不属于指定集合**。

例如：

```sql
WHERE job NOT IN ('MANAGER', 'SALESMAN')
```

对于普通非 `NULL` 值，可以理解为：

```sql
WHERE job <> 'MANAGER'
  AND job <> 'SALESMAN'
```

例如：

```sql
SELECT ename, job
FROM emp
WHERE job NOT IN ('MANAGER', 'SALESMAN');
```

---

### IN、NOT IN 与 NULL

`NULL` 与 `IN`、`NOT IN` 一起使用时非常容易出错。理解这个问题的关键，是先知道 SQL 的条件判断存在三种结果：

```text
TRUE
FALSE
UNKNOWN
```

其中，`WHERE` 最终只保留判断结果为 **TRUE** 的记录，结果为 `FALSE` 或 `UNKNOWN` 的记录都会被过滤掉。

#### IN 与 NULL

从逻辑语义上，可以将：

```sql
comm IN (NULL, 300)
```

理解为：

```sql
comm = NULL OR comm = 300
```

因此：

```sql
SELECT *
FROM emp
WHERE comm IN (NULL, 300);
```

可以按照下面的逻辑理解：

```sql
SELECT *
FROM emp
WHERE comm = NULL
   OR comm = 300;
```

但 SQL 中不能使用：

```sql
comm = NULL
```

判断空值。任何值与 `NULL` 使用普通比较运算符进行比较，结果通常都是 `UNKNOWN`。

例如，当：

```text
comm = 300
```

时：

```text
comm = NULL OR comm = 300

UNKNOWN OR TRUE

→ TRUE
```

因此这条记录能够被查询出来。

如果 `comm` 本身就是 `NULL`：

```text
NULL = NULL OR NULL = 300

UNKNOWN OR UNKNOWN

→ UNKNOWN
```

同样不会被查询出来。

所以：

```sql
WHERE comm IN (NULL, 300)
```

**并不能查询出 `comm` 为 `NULL` 的记录**。

如果真正需要查询：津贴为空或者津贴等于 `300`

应该明确使用：

```sql
SELECT *
FROM emp
WHERE comm IS NULL
   OR comm = 300;
```

> **易错点：** 不能记忆成“`IN` 会自动忽略 `NULL`”。准确地说，是 `IN` 中涉及 `NULL` 的普通等值比较会产生 `UNKNOWN`，而 `WHERE` 不会保留结果为 `UNKNOWN` 的记录。

#### NOT IN 与 NULL

从逻辑语义上，可以将：

```sql
comm NOT IN (NULL, 300)
```

理解为：

```sql
comm <> NULL AND comm <> 300
```

因此：

```sql
SELECT *
FROM emp
WHERE comm NOT IN (NULL, 300);
```

可以按照下面的逻辑理解：

```sql
SELECT *
FROM emp
WHERE comm <> NULL
  AND comm <> 300;
```

假设：

```text
comm = 500
```

那么：

```text
500 <> NULL AND 500 <> 300

UNKNOWN AND TRUE

→ UNKNOWN
```

由于 `WHERE` 只保留 `TRUE`，这条记录仍然不会被查询出来。

即使 `500` 明明既不是 `NULL`，也不是 `300`，最终也无法通过这个条件。

这就是 `NOT IN` 中包含 `NULL` 时特别容易出现问题的原因。

如果需要查询：

> 津贴不为空，并且津贴不是 `300`

应该写成：

```sql
SELECT *
FROM emp
WHERE comm IS NOT NULL
  AND comm NOT IN (300);
```

> **结论：**
>
> 对于普通值，可以从逻辑上理解为：
>
> ```text
> IN     → 多个 = 使用 OR 连接
> NOT IN → 多个 <> 使用 AND 连接
> ```
>
> 但一旦集合中出现 `NULL`，普通比较会产生 `UNKNOWN`，因此必须结合 SQL 的三值逻辑分析，不能按照 Java 中只有 `true` 和 `false` 的二值逻辑理解。

---

### IN 与 OR 的选择

同一个字段需要匹配多个值时：

```sql
WHERE deptno = 10
   OR deptno = 20
   OR deptno = 30
```

通常可以改写为：

```sql
WHERE deptno IN (10, 20, 30)
```

两者表达的业务含义基本相同，但 `IN` 通常更加紧凑、清楚。

不能简单记忆：

```text
OR = O(n)
IN = O(log n)
```

也不能认为“没有索引时 `IN` 一定比 `OR` 快”。SQL 的实际执行效率会受到很多因素影响，例如：

- 是否存在索引；
- 数据量；
- 候选值数量；
- 数据分布；
- MySQL 优化器生成的执行计划；
- MySQL 版本和服务器配置。

MySQL 优化器还可能将逻辑上等价的 `IN` 和多个 `OR` 条件采用相近的方式处理，因此不能只根据语法形式直接判断执行效率。

> **结论：** **同一字段匹配多个离散值时，优先使用 `IN`，主要因为写法更加简洁、可读性更好。性能是否存在明显差异不能一概而论，需要结合实际执行计划和数据进行判断。**

### LIKE 模糊查询

当查询条件不能通过一个确定值直接描述，而是需要按照字符串的某种模式进行匹配时，可以使用 `LIKE`。

基本格式：

```sql
SELECT 字段
FROM 表名
WHERE 字段 LIKE '匹配模式';
```

`LIKE` 中最常用的两个通配符是：

| 通配符 | 含义                              |
| ------ | --------------------------------- |
| `%`    | 匹配任意数量的字符，包括 0 个字符 |
| `_`    | 匹配任意 1 个字符                 |

#### `%` 匹配任意多个字符

查询姓名以 `S` 开头的员工：

```sql
SELECT ename
FROM emp
WHERE ename LIKE 'S%';
```

其中：

```text
S%
```

表示：

```text
以 S 开头
后面可以有任意数量字符
```

查询姓名以 `T` 结尾的员工：

```sql
SELECT ename
FROM emp
WHERE ename LIKE '%T';
```

查询姓名中包含 `O` 的员工：

```sql
SELECT ename
FROM emp
WHERE ename LIKE '%O%';
```

可以直观理解为：

```text
'S%'   → S 开头
'%T'   → T 结尾
'%O%'  → 任意位置包含 O
```

#### `_` 匹配任意一个字符

查询姓名中**第二个字符为 `A`** 的员工：

```sql
SELECT ename
FROM emp
WHERE ename LIKE '_A%';
```

模式：

```text
_A%
```

可以拆解为：

```text
_  → 第一个字符任意
A  → 第二个字符必须是 A
%  → 后面字符数量任意
```

例如：

```text
WARD
MARTIN
```

都满足第二个字符为 `A`。

`%` 和 `_` 的区别是：

```text
%  → 0 个、1 个或多个字符
_  → 必须恰好 1 个字符
```

---

### 查询通配符本身

如果数据中本身包含 `%` 或 `_`，但又希望把它们当作普通字符查询，就需要进行**转义**。

例如创建测试数据：

```sql
DROP TABLE IF EXISTS student;

CREATE TABLE student (
    id INT,
    name VARCHAR(255)
);

INSERT INTO student VALUES (1, 'susan');
INSERT INTO student VALUES (2, 'lucy');
INSERT INTO student VALUES (3, 'jack_son');
```

如果直接执行：

```sql
SELECT *
FROM student
WHERE name LIKE '%_%';
```

这里的 `_` 会被解释为：

```text
任意一个字符
```

因此它并不是在查询“名字中包含下划线”的学生。

MySQL 默认可以使用反斜杠对 `_` 进行转义：

```sql
SELECT *
FROM student
WHERE name LIKE '%\_%';
```

这里：

```text
\_
```

表示普通的下划线字符 `_`。

为了让转义规则更加明确，也可以通过 `ESCAPE` 自己指定转义字符。

例如使用 `!` 作为转义字符：

```sql
SELECT *
FROM student
WHERE name LIKE '%!_%' ESCAPE '!';
```

其中：

```text
!_
```

表示普通字符 `_`，而不是通配符。

同理，如果需要匹配普通的 `%`，也可以进行转义。

> **结论：**
>
> ```text
> %  → 任意数量字符
> _  → 任意一个字符
> ```
>
> 如果需要查询真正的 `%` 或 `_` 字符，应将通配符进行转义。

## 排序操作

查询结果默认并不保证按照某个固定顺序返回。如果需要按照某个字段的大小、字母顺序或日期先后排列，应使用 `ORDER BY` 子句。

基本语法：

```sql
SELECT 字段
FROM 表
ORDER BY 排序字段 ASC|DESC;
```

其中：

- `ASC`：升序（Ascending），从小到大排列。
- `DESC`：降序（Descending），从大到小排列。
- 如果省略排序方式，**默认按照升序 `ASC` 排列**。

### 单字段排序

查询员工编号、姓名和薪资，并按照薪资从低到高排列：

```sql
SELECT empno, ename, sal
FROM emp
ORDER BY sal ASC;
```

由于默认就是升序，因此也可以省略 `ASC`：

```sql
SELECT empno, ename, sal
FROM emp
ORDER BY sal;
```

按照薪资从高到低排列：

```sql
SELECT empno, ename, sal
FROM emp
ORDER BY sal DESC;
```

字符串字段同样可以排序。例如按照员工姓名升序排列：

```sql
SELECT empno, ename
FROM emp
ORDER BY ename;
```

### 多字段排序

`ORDER BY` 可以同时指定多个排序字段，字段之间使用逗号分隔：

```sql
ORDER BY 字段1 排序方式, 字段2 排序方式;
```

例如，先按照薪资升序排列；如果多个员工的薪资相同，再按照姓名升序排列：

```sql
SELECT empno, ename, sal
FROM emp
ORDER BY sal ASC, ename ASC;
```

多个排序字段具有**先后优先级**：

1. 先根据第一个字段排序。
2. 只有第一个字段的值相同时，才使用第二个字段继续排序。
3. 如果第二个字段仍然相同，再继续比较后面的排序字段。

因此：

```sql
ORDER BY sal ASC, ename ASC
```

并不是同时独立排序，而是以 `sal` 为主要排序依据，以 `ename` 为次要排序依据。

### WHERE 与 ORDER BY

需要同时进行条件过滤和排序时，`WHERE` 写在 `ORDER BY` 前面。

例如，查询岗位为 `MANAGER` 的员工，并按照薪资升序排列：

```sql
SELECT ename, sal
FROM emp
WHERE job = 'MANAGER'
ORDER BY sal ASC;
```

对于当前阶段的简单查询，可以将其逻辑处理顺序理解为：

```text
FROM
  ↓
WHERE
  ↓
SELECT
  ↓
ORDER BY
```

也就是：

1. `FROM` 确定从哪张表获取数据。
2. `WHERE` 过滤不符合条件的记录。
3. `SELECT` 确定最终返回哪些列。
4. `ORDER BY` 对查询结果进行排序。

> **结论：** `WHERE` 负责“筛选哪些数据”，`ORDER BY` 负责“这些数据按照什么顺序显示”。

## DISTINCT 去重

查询某个字段时，结果中可能存在重复数据。

例如，查询所有员工的岗位：

```sql
SELECT job
FROM emp;
```

由于多个员工可能具有相同岗位，因此查询结果中的 `job` 会重复。

如果只希望看到不同的岗位，可以使用 `DISTINCT`：

```sql
SELECT DISTINCT job
FROM emp;
```

`DISTINCT` 的作用是**对查询结果进行去重**，不会删除或修改表中原有的数据。

### DISTINCT 的位置

`DISTINCT` 应写在 `SELECT` 后、所有查询字段之前：

```sql
SELECT DISTINCT job
FROM emp;
```

不能写成：

```sql
SELECT ename, DISTINCT job
FROM emp;
```

因为 `DISTINCT` 不是只修饰它后面的某一个字段，而是作用于当前查询结果。

### 多字段联合去重

当 `DISTINCT` 后存在多个字段时，会根据这些字段组成的**完整组合**进行去重。

例如：

```sql
SELECT DISTINCT deptno, job
FROM emp;
```

此时判断重复的依据是：

```text
deptno + job
```

只有两条记录的 `deptno` 和 `job` **全部相同**，才会被认为是重复记录。

例如：

```text
deptno    job
-------   --------
10        MANAGER
10        CLERK
20        MANAGER
20        CLERK
```

虽然 `deptno` 和 `job` 各自都存在重复值，但四种组合都不同，因此四条结果都会保留。

> **结论：** `DISTINCT` 放在所有查询字段之前；存在多个字段时，按照**多个字段的组合结果联合去重**。

## 数据处理函数

SQL 查询不仅可以直接读取字段，还可以通过各种函数对字段中的数据进行处理，然后返回处理后的结果。

例如：

```sql
SELECT UPPER(ename)
FROM emp;
```

会先读取员工姓名，再通过 `UPPER()` 转换为大写形式。

这类针对每一行数据分别进行处理的函数通常称为**单行函数**：一行数据输入，产生一行对应的处理结果。

例如：

```text
SMITH  → UPPER() → SMITH
Allen  → UPPER() → ALLEN
```

后续还会学习 `COUNT()` 等聚合函数，这类函数可以对多行数据进行统计，处理方式与单行函数不同。

### SELECT 中的常量与表达式

`SELECT` 后并不只能写字段，也可以直接写常量：

```sql
SELECT 100;
```

结果只有一行：

```text
100
```

字符串常量需要使用单引号：

```sql
SELECT 'abc';
```

如果写成：

```sql
SELECT abc;
```

`abc` 会被当作字段名或其他标识符解析，而不是字符串。

如果常量后面带有表：

```sql
SELECT 100
FROM emp;
```

那么常量会随着表中的每一条记录产生一次结果。假设 `emp` 中存在 14 条记录，就会得到 14 行 `100`。

> **结论：** `SELECT` 后可以放字段、常量、表达式和函数，不一定必须直接查询某个字段。

### 字符串处理函数

#### UPPER() 和 LOWER()

`UPPER()` 用于将字符串中的字母转换为大写：

```sql
SELECT UPPER(ename) AS ename
FROM emp;
```

MySQL 还提供了作用相同的 `UCASE()`：

```sql
SELECT UCASE(ename) AS ename
FROM emp;
```

`LOWER()` 用于将字母转换为小写：

```sql
SELECT LOWER(ename) AS ename
FROM emp;
```

也可以使用作用相同的 `LCASE()`：

```sql
SELECT LCASE(ename) AS ename
FROM emp;
```

其中：

```text
UPPER() / UCASE() → 转换为大写
LOWER() / LCASE() → 转换为小写
```

例如，如果不确定数据库中的员工姓名采用大写、小写还是大小写混合形式，可以先统一转换后再比较：

```sql
SELECT ename, job, sal
FROM emp
WHERE UPPER(ename) = 'SMITH';
```

这段 SQL 会先将 `ename` 转换成大写，再与 `'SMITH'` 比较。

#### SUBSTR() 截取字符串

`SUBSTR()` 用于截取字符串。

常见格式有两种：

```sql
SUBSTR(字符串, 起始位置, 截取长度)
```

或者：

```sql
SUBSTR(字符串, 起始位置)
```

如果省略第三个参数，就会从指定位置一直截取到字符串末尾。

例如：

```sql
SELECT SUBSTR('ABCDEFG', 2, 3);
```

结果为：

```text
BCD
```

MySQL 字符串位置**从 1 开始，而不是从 0 开始**：

```text
A B C D E F G
1 2 3 4 5 6 7
```

因此：

```sql
SUBSTR('ABCDEFG', 2, 3)
```

表示从第 2 个字符开始，连续截取 3 个字符。

负数可以表示从字符串右侧开始定位。例如：

```sql
SELECT SUBSTR('ABCDEFG', -1);
```

从右侧第 1 个字符开始，因此得到：

```text
G
```

例如，查询姓名中第二个字符为 `A` 的员工：

```sql
SELECT ename
FROM emp
WHERE SUBSTR(ename, 2, 1) = 'A';
```

#### LENGTH() 与 CHAR_LENGTH()

`LENGTH()` 返回字符串所占用的**字节数**：

```sql
SELECT LENGTH('abc');
```

结果为：

```text
3
```

`CHAR_LENGTH()` 返回字符串包含的**字符数量**：

```sql
SELECT CHAR_LENGTH('abc');
```

结果同样为：

```text
3
```

当字符串包含中文等多字节字符时，两者可能不同。

例如，在常见的 `utf8mb4` 字符集中：

```sql
SELECT LENGTH('你好'),
       CHAR_LENGTH('你好');
```

可以理解为：

```text
LENGTH()      → 统计存储所占字节
CHAR_LENGTH() → 统计有多少个字符
```

因此，不能固定记忆为“一个汉字占 2 个长度”。一个字符占多少字节与所使用的字符集有关。

> **易错点：** `LENGTH()` 统计**字节数**，`CHAR_LENGTH()` 统计**字符数**。处理中文字符串长度时，通常更应关注 `CHAR_LENGTH()`。

#### CONCAT() 字符串拼接

`CONCAT()` 用于将多个字符串连接起来：

```sql
CONCAT(字符串1, 字符串2, ...)
```

例如：

```sql
SELECT CONCAT('Hello', ' ', 'MySQL');
```

结果为：

```text
Hello MySQL
```

也可以拼接字段：

```sql
SELECT CONCAT(ename, '-', job)
FROM emp;
```

MySQL 中不要使用 `+` 进行字符串拼接。

例如：

```sql
SELECT 10 + '20';
```

MySQL 会尝试按照**数值加法**处理，而不是得到字符串：

```text
1020
```

因此字符串拼接应明确使用：

```sql
CONCAT()
```

`||` 在 MySQL 默认模式下也不应作为字符串拼接的标准写法，其含义还可能受到 SQL 模式配置影响。为了避免歧义，应统一使用 `CONCAT()`。

> **结论：** Java 中常使用 `+` 拼接字符串，而 MySQL 中字符串拼接应优先使用 `CONCAT()`。

#### TRIM() 去除字符串两端内容

`TRIM()` 最常见的作用是去除字符串两端的空格：

```sql
SELECT TRIM('    abc    ');
```

结果为：

```text
abc
```

例如：

```sql
SELECT CONCAT(TRIM('    abc    '), 'def');
```

结果为：

```text
abcdef
```

`TRIM()` 还可以删除两端指定的字符。

删除前面的 `0`：

```sql
SELECT TRIM(LEADING '0' FROM '000111000');
```

结果：

```text
111000
```

删除后面的 `0`：

```sql
SELECT TRIM(TRAILING '0' FROM '000111000');
```

结果：

```text
000111
```

同时删除两端的 `0`：

```sql
SELECT TRIM(BOTH '0' FROM '000111000');
```

结果：

```text
111
```

其中：

| 写法       | 作用                 |
| ---------- | -------------------- |
| `LEADING`  | 去除前端指定字符     |
| `TRAILING` | 去除后端指定字符     |
| `BOTH`     | 去除前后两端指定字符 |

### 数字处理函数

#### RAND()

`RAND()` 用于生成一个范围在 **0（包含）到 1（不包含）之间**的伪随机小数：

```sql
SELECT RAND();
```

例如可能得到：

```text
0.482731...
```

也可以传入一个整数种子：

```sql
SELECT RAND(10);
```

指定相同种子可以产生可重复的伪随机序列，常用于需要重复得到一致测试结果的场景。

> **注意：** `RAND()` 属于普通伪随机函数，不适合直接用于密码、令牌等安全敏感场景。

#### ROUND() 四舍五入

`ROUND(x)` 对数值进行取整：

```sql
SELECT ROUND(3.6);
```

结果：

```text
4
```

`ROUND(x, y)` 表示保留 `y` 位小数：

```sql
SELECT ROUND(3.14159, 2);
```

结果：

```text
3.14
```

如果 `y` 为负数，则表示对小数点左侧进行舍入。

例如：

```sql
SELECT ROUND(126, -1);
```

表示保留到十位。

#### TRUNCATE() 截断

`TRUNCATE(x, y)` 用于保留指定的小数位，并直接舍去后面的部分：

```sql
SELECT TRUNCATE(3.149, 2);
```

结果：

```text
3.14
```

它与 `ROUND()` 的区别在于：

```text
ROUND()    → 按规则进行舍入
TRUNCATE() → 直接截掉多余部分
```

#### CEIL() 与 FLOOR()

`CEIL()` 返回**大于或等于指定数值的最小整数**：

```sql
SELECT CEIL(3.2);
```

结果：

```text
4
```

`FLOOR()` 返回**小于或等于指定数值的最大整数**：

```sql
SELECT FLOOR(3.8);
```

结果：

```text
3
```

可以直观理解为：

```text
CEIL()  → 向上取整
FLOOR() → 向下取整
```

### NULL 处理函数

在 SQL 中，`NULL` 表示未知或缺失值。

一个非常重要的规则是：

> **普通数学运算中只要有 `NULL` 参与，结果通常仍然是 `NULL`。**

例如：

```sql
SELECT 100 + NULL;
```

结果为：

```text
NULL
```

这会影响实际查询。

假设员工年收入计算方式为：

```text
(月薪 + 津贴) × 12
```

直接查询：

```sql
SELECT ename,
       (sal + comm) * 12 AS annual_salary
FROM emp;
```

如果某个员工：

```text
sal = 800
comm = NULL
```

那么：

```text
800 + NULL
    ↓
NULL

NULL * 12
    ↓
NULL
```

最终年收入也会变成 `NULL`。

#### IFNULL()

`IFNULL(x, y)` 用于处理空值：

```text
如果 x 不为 NULL → 返回 x
如果 x 为 NULL   → 返回 y
```

例如：

```sql
IFNULL(comm, 0)
```

表示：

> 如果 `comm` 有值就使用原来的值；如果 `comm` 为 `NULL`，就把它当作 `0` 使用。

因此年收入可以写成：

```sql
SELECT ename,
       (sal + IFNULL(comm, 0)) * 12 AS annual_salary
FROM emp;
```

如果：

```text
sal = 800
comm = NULL
```

处理过程变为：

```text
IFNULL(NULL, 0)
        ↓
        0

(800 + 0) * 12
        ↓
       9600
```

> **结论：** 当可能为 `NULL` 的字段参与表达式计算时，应考虑是否需要通过 `IFNULL()` 等方式进行空值处理。

### 日期和时间函数

MySQL 提供了大量处理日期和时间的函数，可以获取当前时间、提取日期组成部分、计算日期间隔以及完成日期与字符串之间的转换。

#### 获取当前日期和时间

获取当前日期和时间：

```sql
SELECT NOW();
```

例如：

```text
2026-08-17 14:30:25
```

也可以使用：

```sql
SELECT SYSDATE();
```

`NOW()` 与 `SYSDATE()` 的主要区别是：

- `NOW()` 返回**当前 SQL 语句开始执行时**的时间，在同一条语句执行过程中通常保持一致。
- `SYSDATE()` 返回函数实际执行到该位置时的时间，因此在耗时较长的语句中可能发生变化。

基础开发中通常更加常用：

```sql
NOW()
```

#### 获取当前日期

常见写法包括：

```sql
SELECT CURDATE();
```

```sql
SELECT CURRENT_DATE();
```

```sql
SELECT CURRENT_DATE;
```

结果只包含：

```text
年-月-日
```

例如：

```text
2026-08-17
```

#### 获取当前时间

常见写法包括：

```sql
SELECT CURTIME();
```

```sql
SELECT CURRENT_TIME();
```

```sql
SELECT CURRENT_TIME;
```

结果只包含：

```text
时:分:秒
```

#### 提取年月日时分秒

可以从一个日期时间中分别提取不同组成部分：

```sql
SELECT YEAR(NOW());
SELECT MONTH(NOW());
SELECT DAY(NOW());
SELECT HOUR(NOW());
SELECT MINUTE(NOW());
SELECT SECOND(NOW());
```

例如：

```sql
SELECT YEAR('2026-08-17 14:30:25');
```

结果：

```text
2026
```

也可以一次提取日期部分：

```sql
SELECT DATE('2026-08-17 14:30:25');
```

结果：

```text
2026-08-17
```

提取时间部分：

```sql
SELECT TIME('2026-08-17 14:30:25');
```

结果：

```text
14:30:25
```

#### DATE_ADD() 日期增加

`DATE_ADD()` 用于在指定日期或时间基础上增加一定时间。

基本语法：

```sql
DATE_ADD(日期, INTERVAL 数量 单位)
```

例如，在 `2023-01-03` 基础上增加 3 天：

```sql
SELECT DATE_ADD('2023-01-03', INTERVAL 3 DAY);
```

结果：

```text
2023-01-06
```

增加 3 个月：

```sql
SELECT DATE_ADD('2023-01-03', INTERVAL 3 MONTH);
```

结果：

```text
2023-04-03
```

常见单位包括：

| 单位          | 含义 |
| ------------- | ---- |
| `YEAR`        | 年   |
| `QUARTER`     | 季度 |
| `MONTH`       | 月   |
| `WEEK`        | 周   |
| `DAY`         | 日   |
| `HOUR`        | 时   |
| `MINUTE`      | 分   |
| `SECOND`      | 秒   |
| `MICROSECOND` | 微秒 |

时间数量也可以为负数：

```sql
SELECT DATE_ADD(
    '2022-10-01 10:10:10',
    INTERVAL -1 MICROSECOND
);
```

增加负数实际上就是减去对应时间，因此也可以使用 `DATE_SUB()`：

```sql
SELECT DATE_SUB(
    '2022-10-01 10:10:10',
    INTERVAL 1 MICROSECOND
);
```

二者表达的含义相同。

MySQL 还支持复合时间单位，例如：

```text
YEAR_MONTH
DAY_HOUR
DAY_MINUTE
DAY_SECOND
HOUR_MINUTE
HOUR_SECOND
MINUTE_SECOND
```

例如，在某个日期基础上增加 3 天 2 小时：

```sql
SELECT DATE_ADD(
    '2023-01-01 10:00:00',
    INTERVAL '3 2' DAY_HOUR
);
```

其中：

```text
'3 2' DAY_HOUR
```

表示：

```text
3 天 2 小时
```

> **补充：** `DATE_ADD()` 的复合时间单位很多，基础阶段不需要全部记忆。重点掌握 `YEAR`、`MONTH`、`DAY`、`HOUR`、`MINUTE`、`SECOND` 即可，需要其他单位时再查阅即可。

#### DATE_FORMAT() 日期格式化

`DATE_FORMAT()` 用于按照指定格式，将日期时间转换成字符串：

```sql
DATE_FORMAT(日期, '格式')
```

常见格式符：

| 格式符 | 含义          |
| ------ | ------------- |
| `%Y`   | 四位年份      |
| `%y`   | 两位年份      |
| `%m`   | 两位月份      |
| `%d`   | 两位日期      |
| `%H`   | 24 小时制小时 |
| `%i`   | 分钟          |
| `%s`   | 秒            |

例如：

```sql
SELECT DATE_FORMAT(
    NOW(),
    '%Y-%m-%d %H:%i:%s'
);
```

可能得到：

```text
2026-08-17 14:30:25
```

需要特别注意：

```text
%m → 月
%i → 分
```

不能将分钟错误写成 `%m`。

#### STR_TO_DATE() 字符串转换为日期

`STR_TO_DATE()` 与 `DATE_FORMAT()` 的作用方向相反：

```text
DATE_FORMAT()
日期 → 字符串

STR_TO_DATE()
字符串 → 日期
```

基本语法：

```sql
STR_TO_DATE('日期字符串', '日期格式')
```

例如，有一张学生表：

```sql
CREATE TABLE t_student (
    name VARCHAR(255),
    birth DATE
);
```

现在需要插入生日：

```text
10/01/1985
```

由于这个字符串不是最常用的标准日期格式，可以先进行转换：

```sql
INSERT INTO t_student(name, birth)
VALUES (
    'zhangsan',
    STR_TO_DATE('10/01/1985', '%m/%d/%Y')
);
```

其中：

```text
'10/01/1985'
'%m/%d/%Y'
```

两者格式一一对应：

```text
10   / 01 / 1985
%m   / %d / %Y
```

如果字符串本身使用 MySQL 能直接识别的标准日期格式，例如：

```text
1985-10-01
```

通常可以直接写：

```sql
INSERT INTO t_student(name, birth)
VALUES ('zhangsan', '1985-10-01');
```

> **结论：**
>
> ```text
> DATE_FORMAT() → 日期转字符串
> STR_TO_DATE() → 字符串转日期
> ```

#### DAYOFWEEK()、DAYOFMONTH()、DAYOFYEAR()

`DAYOFWEEK()` 返回指定日期是一周中的第几天：

```sql
SELECT DAYOFWEEK('2026-08-17');
```

其编号规则为：

```text
周日 → 1
周一 → 2
...
周六 → 7
```

`DAYOFMONTH()` 返回该日期是当前月的第几天：

```sql
SELECT DAYOFMONTH('2026-08-17');
```

结果：

```text
17
```

`DAYOFYEAR()` 返回该日期是一年中的第几天：

```sql
SELECT DAYOFYEAR('2026-08-17');
```

一年通常为 `1 ~ 365`，闰年最多为 `366`。

#### LAST_DAY()

`LAST_DAY()` 用于获取指定日期所在月份的最后一天：

```sql
SELECT LAST_DAY('2026-02-10');
```

结果：

```text
2026-02-28
```

因此不需要自己判断某个月究竟有 28、29、30 还是 31 天。

#### DATEDIFF()

`DATEDIFF()` 用于计算两个日期相差的**天数**：

```sql
DATEDIFF(日期1, 日期2)
```

计算方向为：

```text
日期1 - 日期2
```

例如：

```sql
SELECT DATEDIFF('2026-08-20', '2026-08-17');
```

结果：

```text
3
```

`DATEDIFF()` 主要比较日期部分，时间中的时、分、秒不会参与天数差计算。

#### TIMEDIFF()

`TIMEDIFF()` 用于计算两个时间或日期时间之间的时间差：

```sql
TIMEDIFF(时间1, 时间2)
```

例如：

```sql
SELECT TIMEDIFF(
    '2026-08-17 20:30:30',
    '2026-08-17 10:10:00'
);
```

结果表示：

```text
10:20:30
```

也就是相差 10 小时 20 分钟 30 秒。

### IF() 条件函数

`IF()` 可以根据一个条件返回不同结果：

```sql
IF(条件, 条件成立时的结果, 条件不成立时的结果)
```

例如：

```sql
SELECT IF(500 < 1000, 'YES', 'NO');
```

由于条件成立，因此结果为：

```text
YES
```

查询员工工资，如果工资高于 `3000` 返回 `1`，否则返回 `0`：

```sql
SELECT ename,
       sal,
       IF(sal > 3000, 1, 0) AS high_salary
FROM emp;
```

如果希望查询时将 `SMITH` 的工资提高 10%，其他员工保持原工资：

```sql
SELECT ename,
       IF(ename = 'SMITH', sal * 1.1, sal) AS sal
FROM emp;
```

`IF()` 还可以嵌套，但当条件较多时，可读性会逐渐下降。

例如：

- `MANAGER` 工资增加 10%；
- `SALESMAN` 工资增加 20%；
- 其他岗位保持不变。

可以使用：

```sql
SELECT ename,
       job,
       IF(
           job = 'MANAGER',
           sal * 1.1,
           IF(job = 'SALESMAN', sal * 1.2, sal)
       ) AS sal
FROM emp;
```

对于多个分支，更适合使用 `CASE`：

```sql
SELECT ename,
       job,
       CASE
           WHEN job = 'MANAGER' THEN sal * 1.1
           WHEN job = 'SALESMAN' THEN sal * 1.2
           ELSE sal
       END AS sal
FROM emp;
```

> **结论：** 简单的“二选一”判断可以使用 `IF()`；分支较多时，`CASE` 通常更加清晰。

### CAST() 类型转换

`CAST()` 用于将一个值显式转换成指定的数据类型。

基本语法：

```sql
CAST(值 AS 数据类型)
```

例如，将字符串转换为日期：

```sql
SELECT CAST('2020-10-11' AS DATE);
```

常见目标类型包括：

| 类型       | 含义       |
| ---------- | ---------- |
| `DATE`     | 日期       |
| `TIME`     | 时间       |
| `DATETIME` | 日期和时间 |
| `SIGNED`   | 有符号整数 |
| `CHAR`     | 字符串     |
| `DECIMAL`  | 精确小数   |

例如：

```sql
SELECT CAST('123' AS SIGNED);
```

将字符串 `'123'` 转换为整数：

```text
123
```

需要注意，`DECIMAL` 属于**精确数值类型**，不能简单理解为普通浮点数。

> **结论：** 当数据库不能自动完成合适的类型转换，或者希望明确指定转换结果时，可以使用 `CAST()`。

### MD5() 哈希函数

`MD5()` 可以对输入内容计算 MD5 摘要：

```sql
SELECT MD5('abc12345');
```

执行后会得到一个由十六进制字符组成的固定长度结果。

需要注意，MD5 **不是“加密后还能解密”的加密算法，而是哈希算法（Hash）**。它的基本特点是：

```text
原始数据
   ↓
 MD5()
   ↓
固定长度哈希值
```

哈希计算本身不存在正常意义上的“解密”过程。

但是 MD5 已经不适合作为现代安全场景中的密码保护算法，因为其抗碰撞能力较弱，而且对常见密码可以通过字典、暴力尝试等方式快速猜测原文。

因此，`MD5()` 可以作为数据库字符串处理函数了解其作用，但**不应把简单的 MD5 值直接作为现代系统的用户密码存储方案**。

> **易错点：** `MD5()` 是**哈希函数**，不是可逆的“加密函数”；“无法直接逆运算”也不等于“适合安全保存密码”。

## 分组函数

**分组函数（Aggregate Function，也称聚合函数）**用于对一组数据进行统计计算，其特点是**多行数据输入，得到一个统计结果**。

分组函数的基本执行原则是：**先确定分组，再对每一组数据执行分组函数。** 如果没有使用 `GROUP BY` 进行分组，那么经过 `WHERE` 过滤后的全部数据会被看作一组。

MySQL 中最常用的五个分组函数包括：

| 函数      | 作用     |
| --------- | -------- |
| `MAX()`   | 求最大值 |
| `MIN()`   | 求最小值 |
| `AVG()`   | 求平均值 |
| `SUM()`   | 求和     |
| `COUNT()` | 统计数量 |

例如，假设 `emp` 表存在 14 条员工记录，没有使用 `GROUP BY`：

```sql
SELECT MAX(sal)
FROM emp;
```

此时 14 条员工记录整体作为一组，`MAX()` 从这一组数据中计算最高工资，最终只返回一个结果。

---

### MAX()、MIN()、AVG()、SUM()

#### MAX()

`MAX()` 用于获取一组数据中的最大值。

查询所有员工的最高工资：

```sql
SELECT MAX(sal)
FROM emp;
```

#### MIN()

`MIN()` 用于获取一组数据中的最小值。

查询所有员工的最低工资：

```sql
SELECT MIN(sal)
FROM emp;
```

#### AVG()

`AVG()` 用于计算一组数值的平均值。

查询所有员工的平均工资：

```sql
SELECT AVG(sal)
FROM emp;
```

#### SUM()

`SUM()` 用于计算一组数值的总和。

查询所有员工的工资总和：

```sql
SELECT SUM(sal)
FROM emp;
```

查询所有员工的津贴总和：

```sql
SELECT SUM(comm)
FROM emp;
```

---

### 分组函数与 NULL

`MAX()`、`MIN()`、`AVG()`、`SUM()` 以及 `COUNT(字段)` 在计算时都会**忽略 `NULL` 值**。

例如，`emp` 表中共有 14 名员工，但只有 4 名员工的 `comm` 不为 `NULL`：

```sql
SELECT SUM(comm)
FROM emp;
```

`SUM()` 只会对实际存在的津贴进行求和，不会把 `NULL` 当成 `0` 参与计算。

同样：

```sql
SELECT AVG(comm)
FROM emp;
```

计算的是：

```text
所有非 NULL 的 comm 之和
÷
非 NULL 的 comm 数量
```

而不是：

```text
所有 comm 之和
÷
员工总人数
```

例如：

```text
comm

300
500
NULL
NULL
```

`AVG(comm)` 的计算方式是：

```text
(300 + 500) / 2
```

而不是：

```text
(300 + 500 + 0 + 0) / 4
```

> **易错点：** “分组函数忽略 `NULL`”主要是指**对字段值进行统计时，不把 `NULL` 作为有效值参与计算**。`COUNT(*)` 比较特殊，它统计的是记录行数，因此不会因为某个字段为 `NULL` 而少计一行。

---

### COUNT()

`COUNT()` 用于统计数量，但根据参数不同，统计含义也不同。

#### COUNT(字段)

```sql
SELECT COUNT(ename)
FROM emp;
```

`COUNT(ename)` 统计的是 `ename` 字段中**不为 `NULL` 的值有多少个**。

如果 `ename` 的 14 条数据全部不为 `NULL`，结果就是：

```text
14
```

如果统计 `comm`：

```sql
SELECT COUNT(comm)
FROM emp;
```

假设只有 4 个员工的 `comm` 不为 `NULL`，结果就是：

```text
4
```

因此：

```text
COUNT(字段)
```

统计的不是表的总行数，而是**该字段非 NULL 值的数量**。

#### COUNT(*)

```sql
SELECT COUNT(*)
FROM emp;
```

`COUNT(*)` 统计的是查询结果中**总共有多少行记录**。

即使某一行中的某些字段为 `NULL`，这一行仍然会被统计。

例如：

```text
emp 表共有 14 行
```

那么：

```sql
SELECT COUNT(*)
FROM emp;
```

结果就是：

```text
14
```

#### COUNT(1)

也可以写成：

```sql
SELECT COUNT(1)
FROM emp;
```

在这里，常量 `1` 对每一行都不是 `NULL`，因此最终同样会统计全部记录。

所以从统计结果来看：

```sql
COUNT(*)
COUNT(1)
```

都可以用于统计记录总行数。

基础学习和实际开发中，统计记录数时通常直接使用：

```sql
COUNT(*)
```

即可。

> **结论：**
>
> ```text
> COUNT(*)    → 统计记录总行数
> COUNT(字段) → 统计该字段非 NULL 值的数量
> ```

---

### COUNT() 与 DISTINCT

`COUNT()` 可以配合 `DISTINCT` 统计某个字段中**不同值的数量**。

例如，查询公司中存在多少种不同的岗位：

```sql
SELECT COUNT(DISTINCT job)
FROM emp;
```

假设员工岗位包括：

```text
CLERK
SALESMAN
MANAGER
ANALYST
PRESIDENT
```

即使多名员工都属于 `MANAGER`，重复的岗位只计算一次，因此结果为：

```text
5
```

可以将：

```sql
COUNT(DISTINCT job)
```

理解为：

1. 先对 `job` 的非 `NULL` 值去重；
2. 再统计去重后的数量。

---

### 分组函数组合使用

多个分组函数可以在同一条 `SELECT` 语句中一起使用。

例如，一次性统计员工数量、最高工资、最低工资、平均工资和工资总和：

```sql
SELECT COUNT(*),
       MAX(sal),
       MIN(sal),
       AVG(sal),
       SUM(sal)
FROM emp;
```

由于这里没有使用 `GROUP BY`，因此经过条件过滤后的整张表作为一个整体进行统计，最终返回一行结果。

例如：

```text
COUNT(*)  MAX(sal)  MIN(sal)  AVG(sal)  SUM(sal)
--------  --------  --------  --------  --------
14        5000      800       ...       ...
```

这正体现了分组函数的特点：

```text
多行数据
   ↓
分组函数
   ↓
一个统计结果
```

---

### 分组函数不能直接用于 WHERE

分组函数不能直接写在 `WHERE` 条件中。

例如，希望查询工资高于平均工资的员工，下面的写法是错误的：

```sql
SELECT ename, job, sal
FROM emp
WHERE sal > AVG(sal);
```

原因与 SQL 的逻辑执行顺序有关。

当前阶段可以将相关执行顺序理解为：

```text
FROM
  ↓
WHERE
  ↓
GROUP BY
  ↓
分组函数计算
  ↓
SELECT
```

也就是说：

1. `FROM` 先确定数据来源。
2. `WHERE` 对原始记录进行过滤。
3. 过滤完成以后才进行分组。
4. 分组确定以后，才能计算 `AVG()`、`MAX()`、`SUM()` 等分组函数。
5. 最后执行 `SELECT` 得到查询结果。

当执行：

```sql
WHERE sal > AVG(sal)
```

时，SQL 还处于 `WHERE` 过滤阶段，此时分组尚未形成，`AVG(sal)` 也就还没有得到平均工资，因此不能直接用于 `WHERE` 判断。

即使没有显式编写：

```sql
GROUP BY
```

也不能认为平均值已经提前计算完成。所谓“没有 `GROUP BY` 时，所有数据自成一组”，这一步同样发生在 **`WHERE` 过滤之后**。

可以直观理解为：

```text
emp 原始数据
     ↓
WHERE 先过滤
     ↓
剩余数据形成分组
     ↓
AVG(sal)
MAX(sal)
SUM(sal)
...
```

> **易错点：** `WHERE` 负责**分组之前的行过滤**，而分组函数必须等分组确定后才能计算，因此分组函数不能直接作为 `WHERE` 条件。
