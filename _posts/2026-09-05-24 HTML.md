## Web 前端简介

**Web 前端**主要负责浏览器中页面内容的展示与用户交互。现代 Web 前端通常以 **HTML、CSS 和 JavaScript** 为基础，通过浏览器解析和执行这些内容，最终形成用户看到并能够操作的网页。

### C/S 架构与 B/S 架构

从客户端与服务器的交互方式来看，软件系统常见的架构形式包括 **C/S 架构**和 **B/S 架构**。

#### C/S 架构

**C/S（Client/Server，客户端/服务器）架构**需要用户在本地安装专门的客户端程序，由客户端与服务器进行通信。

例如，桌面版即时通信软件、部分大型游戏以及一些企业内部客户端软件，都可以采用 C/S 架构。

C/S 架构通常具有以下特点：

- 客户端可以承担较多的界面展示和业务处理工作，因此能够充分利用本地计算机资源。
- 可以根据业务需要实现较复杂的界面和交互效果。
- 用户需要安装客户端，部署和更新时通常需要考虑客户端版本管理。
- 客户端往往与特定操作系统或运行环境存在一定关联。

> 注意：不能简单认为“C/S 的大部分数据都存储在客户端”。数据究竟保存在客户端还是服务器，取决于具体系统的设计，与是否采用 C/S 架构没有固定比例关系。

#### B/S 架构

**B/S（Browser/Server，浏览器/服务器）架构**以浏览器作为主要客户端。用户通常不需要安装专门的业务客户端，只需通过浏览器访问服务器提供的 Web 应用。

例如，网上银行、后台管理系统、电子商务网站等都大量采用 B/S 架构。

B/S 架构通常具有以下特点：

- 用户可以直接通过浏览器访问系统，使用门槛较低。
- 系统的大部分更新部署在服务器端完成，客户端通常无需单独升级业务程序。
- 跨平台能力较强，只要存在兼容的浏览器即可访问。
- 页面和交互需要受到浏览器环境及 Web 标准的约束。

早期 Web 技术能力有限，因此 B/S 应用的界面和交互通常弱于专用客户端。随着 HTML5、CSS3、现代 JavaScript 和浏览器能力的发展，**现代 B/S 应用同样可以实现复杂的页面、动画和交互效果**，因此不能再简单认为 B/S 页面一定比 C/S 页面简陋。

Web 前端开发主要面向 B/S 架构。只要应用需要在浏览器中展示数据、接收用户操作并与服务器交互，就会涉及 Web 前端技术。

### Web 前端的核心技术

一个网站通常由多个网页组成，而网页最基础的三项技术是 **HTML、CSS 和 JavaScript**。

| 技术       | 主要职责   | 作用                                             |
| ---------- | ---------- | ------------------------------------------------ |
| HTML       | 结构与内容 | 定义页面中有哪些元素，以及这些元素之间的结构关系 |
| CSS        | 表现与样式 | 控制元素的颜色、大小、位置、布局等视觉效果       |
| JavaScript | 行为与交互 | 控制页面逻辑，使页面能够响应用户操作并动态变化   |

#### HTML

**HTML（HyperText Markup Language，超文本标记语言）**负责描述网页的结构和内容，可以理解为网页的“骨架”。

例如，一个网页需要包含标题、正文和按钮，可以使用 HTML 进行组织：

```html
<h1>用户信息</h1>
<p>欢迎登录系统</p>
<button>退出登录</button>
```

HTML 主要解决“页面中有什么”以及“这些内容之间是什么结构关系”，并不负责具体的视觉样式。

#### CSS

**CSS（Cascading Style Sheets，层叠样式表）**负责控制网页的表现形式，可以理解为网页的“外观”。

例如，可以使用 CSS 修改标题颜色以及按钮大小：

```css
h1 {
    color: blue;
}

button {
    width: 120px;
    height: 40px;
}
```

因此，HTML 决定“页面中有什么”，CSS 则进一步决定“这些内容看起来是什么样”。

#### JavaScript

**JavaScript**负责网页中的逻辑和交互行为，使页面能够根据用户操作或程序状态发生变化。

例如，可以让按钮在被点击时执行相应操作：

```javascript
button.onclick = function () {
    alert("按钮被点击");
};
```

因此，可以将三者的职责概括为：**HTML 负责结构，CSS 负责样式，JavaScript 负责行为。**

例如，可以把开发网页类比为建造房屋：HTML 负责建立房屋的主体结构，CSS 负责装修和布置，而 JavaScript 则使灯光、门锁等设备能够根据人的操作产生相应行为。

> 结论：HTML、CSS 和 JavaScript 并不是相互替代的技术，而是分别负责网页的结构、表现和行为，并共同构成 Web 前端开发的基础。

### 浏览器与浏览器引擎

浏览器是用户访问 Web 应用的主要客户端程序。对于前端开发而言，浏览器不仅负责显示页面，还需要解析 HTML、处理 CSS、执行 JavaScript，并完成页面绘制和用户交互。

在基础阶段，需要重点区分 **渲染引擎**和 **JavaScript 引擎**：

- **渲染引擎（Rendering Engine）**主要负责解析 HTML、CSS，并完成页面布局和绘制。
- **JavaScript 引擎（JavaScript Engine）**主要负责解析和执行 JavaScript 代码。

日常讨论中有时会使用“浏览器内核”这一说法，但这个概念并没有非常严格统一的边界。学习时应尽量明确具体指的是渲染引擎还是 JavaScript 引擎。

常见浏览器及其主要引擎如下：

| 浏览器          | 渲染引擎 | JavaScript 引擎 |
| --------------- | -------- | --------------- |
| Google Chrome   | Blink    | V8              |
| Microsoft Edge  | Blink    | V8              |
| Opera           | Blink    | V8              |
| Mozilla Firefox | Gecko    | SpiderMonkey    |
| Safari          | WebKit   | JavaScriptCore  |

其中，Blink、Gecko 和 WebKit 只需作为了解内容掌握：

- **Blink**：Chromium 使用的渲染引擎，Chrome、现代 Edge、Opera 等浏览器通常使用 Blink。
- **Gecko**：Mozilla 开发的 Web 引擎，主要应用于 Firefox。
- **WebKit**：开源 Web 引擎，Safari 使用 WebKit 处理 Web 内容。

> 注意：渲染引擎与 JavaScript 引擎承担的职责不同。例如 Blink 负责页面布局和渲染，而 V8 负责执行 JavaScript，不能将二者理解为同一个组件。

### Web 运行的基础技术

理解 Web 应用的基本运行过程，需要认识 **TCP/IP、HTTP 和 HTML** 所承担的不同职责。三者处于不同层次，共同参与浏览器与服务器之间的数据通信和页面展示。

#### TCP/IP

**TCP/IP**不是某一个单独的协议，而是一组互联网通信协议的统称，是互联网通信的重要基础。

在 Web 访问过程中，可以重点理解其中两方面的作用：

- **IP**负责网络地址标识以及数据包在不同网络之间的转发。
- **TCP**可以在通信双方之间提供可靠、有序的数据传输能力。

其中，**路由（Routing）**是网络设备根据目标 IP 地址和路由信息，为数据包选择后续转发路径的过程。

例如，可以将路由过程类比为快递运输：包裹上记录着目的地址，每到一个物流节点，该节点都会判断下一步应该将包裹发送到哪里，最终使包裹逐步到达目的地。

> 注意：TCP/IP 负责的是网络通信，而不是“建立电脑和服务器之间的物理连接”。真正的物理连接可能来自网线、光纤、Wi-Fi 等通信介质。

#### HTTP

**HTTP（HyperText Transfer Protocol，超文本传输协议）**是 Web 中浏览器与服务器之间常用的应用层通信协议。

HTTP 规定了客户端和服务器以什么形式发送**请求（Request）**和返回**响应（Response）**。

例如，浏览器访问某个网页时，会向服务器发送 HTTP 请求：

`浏览器 → HTTP 请求 → Web 服务器`

服务器处理请求后，再通过 HTTP 响应返回 HTML、JSON、图片等数据：

`浏览器 ← HTTP 响应 ← Web 服务器`

因此，HTTP 主要解决的是：**浏览器与服务器之间按照什么规则交换 Web 数据。**

#### HTML

**HTML**用于描述网页的结构和内容，是浏览器生成页面内容的重要基础。

服务器可以通过 HTTP 将 HTML 文档返回给浏览器。浏览器读取 HTML 后，根据其中的标签和结构组织页面内容，同时还可以继续加载 HTML 中引用的 CSS、JavaScript、图片等资源。

#### 浏览器访问网页的基本过程

在基础阶段，可以将一次 Web 页面访问简化为以下过程：

1. 用户在浏览器中访问一个 Web 地址。
2. 浏览器通过网络向目标服务器发送 HTTP 请求。
3. 请求数据通过 TCP/IP 网络进行传输并到达服务器。
4. 服务器接收并处理请求，通过 HTTP 响应返回 HTML 等资源。
5. 浏览器接收到 HTML 后进行解析，并继续加载页面所需的 CSS、JavaScript、图片等资源。
6. 渲染引擎根据 HTML 和 CSS 完成页面布局和绘制。
7. JavaScript 引擎执行 JavaScript，使页面具备动态逻辑和交互能力。
8. 最终形成用户可以看到并操作的网页。

整个过程可以简化为：

`浏览器发起请求 → 网络传输 → 服务器处理 → 返回页面资源 → 浏览器解析并渲染 → 用户看到并操作网页`

由此可以看出，Web 前端主要工作在浏览器一侧：**HTML 负责组织页面内容，CSS 负责控制页面样式，JavaScript 负责实现页面逻辑和交互。**

## HTML 概述

**HTML（HyperText Markup Language，超文本标记语言）**是用于描述网页结构和内容的标记语言。浏览器通过解析 HTML 中的各种标签，识别网页中的标题、段落、图片、超链接等内容，并按照相应结构进行展示。

### HTML 简介

HTML 提供了大量具有不同语义和作用的**标签（Tag）**。网页中需要描述什么内容，就选择相应的 HTML 标签，例如标题使用标题标签，段落使用段落标签，图片使用图片标签，超链接使用超链接标签。

HTML **不是编程语言，而是一种标记语言**。它主要负责描述网页中“有什么内容”以及“这些内容之间是什么结构关系”，本身并不用于完成传统编程语言中的算法计算和复杂程序控制。

例如：

```html
<h1>个人中心</h1>
<p>欢迎访问个人中心。</p>
<a href="profile.html">查看个人资料</a>
```

其中，`<h1>` 描述标题，`<p>` 描述段落，`<a>` 描述超链接。浏览器根据这些标签的含义组织并展示网页内容。

HTML 中的“超文本（HyperText）”表示网页内容不仅限于普通文本，还可以包含图片、音视频等其他资源，并能够通过**超链接（Hyperlink）**建立不同网页或资源之间的联系。用户点击超链接后，可以从当前页面跳转到另一个页面或资源，这也是 Web 页面能够相互连接的重要基础。

> 结论：HTML 的核心作用是**使用标签描述网页的结构和内容**；“超文本”则体现了网页能够包含多种形式的内容，并通过超链接相互关联。

### HTML 的标准化与发展（了解）

HTML 的发展过程中主要涉及 **IETF、W3C 和 WHATWG** 等组织。

- **IETF（Internet Engineering Task Force，互联网工程任务组）**参与了 HTML 早期的规范化工作，HTML 2.0 就以 RFC 的形式发布。此后 IETF 的主要工作更多集中在 HTTP、TCP/IP 等互联网协议领域。
- **W3C（World Wide Web Consortium，万维网联盟）**由万维网发明者 Tim Berners-Lee 于 1994 年创建，曾长期负责 HTML、CSS 等 Web 标准的制定，HTML 4、XHTML 以及 W3C 版 HTML5 都与其密切相关。
- **WHATWG（Web Hypertext Application Technology Working Group）**于 2004 年由 Apple、Mozilla、Opera 等浏览器厂商相关人员发起，主张继续发展兼容现有 Web 的 HTML，并推动了现代 HTML5 的形成。

早期 W3C 曾尝试将 Web 标记语言的发展重点转向更加严格的 XHTML 体系，而浏览器厂商更倾向于在兼容已有网页的基础上继续发展 HTML，因此推动了 WHATWG 的成立。

后来 W3C 与 WHATWG 在 HTML 标准上的工作逐渐重新统一。现代 HTML 不再主要依靠 HTML 5.1、HTML 5.2 等固定大版本持续演进，而是由 WHATWG 持续维护 **HTML Living Standard（HTML 现行标准）**。

HTML 的主要发展过程简要了解如下：

| 阶段                 | 时间        | 主要说明                    |
| -------------------- | ----------- | --------------------------- |
| HTML 早期草案        | 1990 年代初 | HTML 最初形成并逐步发展     |
| HTML 2.0             | 1995 年     | 以 RFC 1866 发布            |
| HTML 3.2             | 1997 年     | 成为 W3C 推荐标准           |
| HTML 4.0             | 1997 年     | HTML 功能进一步完善         |
| HTML 4.01            | 1999 年     | HTML 4 的修订版本           |
| XHTML 1.0            | 2000 年     | 使用 XML 规则重新规范 HTML  |
| XHTML 1.1            | 2001 年     | 进一步强化 XHTML 的严格语法 |
| HTML5                | 2014 年     | W3C 发布 HTML5 推荐标准     |
| HTML Living Standard | 现代        | WHATWG 持续更新 HTML 标准   |

这部分内容只需建立基本认识，**无需记忆所有版本的具体发布日期**。学习现代前端开发时，重点应放在当前 HTML 语法以及现代浏览器实际支持的标准上。

#### XHTML 与 HTML

**XHTML（Extensible HyperText Markup Language，可扩展超文本标记语言）**可以理解为按照 XML 规则重新规范后的 HTML，其语法要求比传统 HTML 更严格。

例如，XHTML 通常要求标签正确嵌套、标签必须闭合、属性值必须使用引号等，而 HTML 对部分语法具有较强的容错能力。

现代 HTML 可以写成 `<input type="text">`，而传统 XHTML 风格通常要求写成 `<input type="text" />`。

XHTML 曾经被视为 Web 标记语言的发展方向，但后来 HTML5 重新成为主流。**目前开发普通网页时主要使用现代 HTML，而不是 XHTML。**

> 补充：现代 HTML 虽然具有较强的语法容错能力，但开发时仍应保持标签正确嵌套、结构清晰等良好编码习惯。不能因为浏览器能够容错，就故意编写不规范的 HTML。

## HTML 开发环境

HTML 文件本质上是文本文件，因此并不依赖某一种特定开发工具。理论上使用记事本等普通文本编辑器即可编写 HTML，但实际开发通常使用 VS Code、WebStorm 等具有代码提示、格式化和项目管理功能的开发工具。

### HTML 文件的创建与运行

HTML 文件通常使用 `.html` 扩展名，也可以使用 `.htm`，现代开发中一般使用 `.html`，例如 `index.html`、`login.html`、`user.html`。

HTML 文件属于普通文本文件，因此可以使用记事本等文本编辑器创建和修改。不过为了提高开发效率，实际开发通常使用专业代码编辑器或 IDE。

一个最基本的 HTML 文件可以写成：

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>第一个网页</title>
</head>
<body>
    <h1>Hello HTML</h1>
</body>
</html>
```

HTML 最终由**浏览器解析和渲染**，因此编写完成后可以直接使用 Chrome、Edge 等浏览器打开 `.html` 文件查看页面效果。

直接双击 `index.html` 时，浏览器通常会使用类似 `file:///.../index.html` 的本地文件地址打开页面；在实际 Web 开发过程中，也可以通过本地 Web 服务器访问页面，例如 `http://127.0.0.1:5500/index.html`。

两种方式都可以显示 HTML，但通过本地服务器访问页面更加接近实际 Web 应用使用 HTTP 访问资源的运行方式。

### 常用 HTML 开发工具

常见的 Web 前端开发工具包括 VS Code、WebStorm 和 HBuilderX 等。

| 工具      | 类型         | 主要特点                                         |
| --------- | ------------ | ------------------------------------------------ |
| VS Code   | 代码编辑器   | 免费、轻量、插件生态丰富，前端开发中使用广泛     |
| WebStorm  | 专业 IDE     | JetBrains 开发，代码分析、重构和工程化功能较强   |
| HBuilderX | IDE / 编辑器 | DCloud 开发，对 uni-app 等国内跨平台技术支持较好 |

**VS Code（Visual Studio Code）**由 Microsoft 开发，本身属于代码编辑器，但通过插件可以获得代码提示、格式化、调试、Git 等大量开发能力，适合从 HTML 基础学习一直使用到后续完整的前端项目开发。

**WebStorm**是 JetBrains 提供的专业 JavaScript/Web IDE，对 HTML、CSS、JavaScript、Vue、React 等前端技术具有较完整的代码分析与重构能力。IntelliJ IDEA 与 WebStorm 的 Web 开发能力存在较多重叠，对于已经使用 IntelliJ IDEA 的开发者，也可以直接在 IDEA 中进行前端开发。

**HBuilderX**由 DCloud 开发，对 uni-app 等跨平台开发场景支持较好，在国内移动端和跨平台项目中较为常见。

### 使用 VS Code 开发 HTML

#### 基本开发步骤

使用 VS Code 创建 HTML 页面时，可以按照以下流程进行：

1. 在任意位置创建用于保存代码的目录，例如 `html-study`。
2. 打开 VS Code。
3. 选择 `File → Open Folder...`，打开创建好的代码目录。
4. 在目录中新建 HTML 文件，例如 `index.html`。
5. 编写 HTML 代码并保存。
6. 使用浏览器直接打开文件，或者使用 Live Server 启动本地 Web 服务器后访问页面。

在 HTML 文件中输入 `!` 后使用 Emmet 补全，可以快速生成 HTML5 的基本页面结构：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>

</body>
</html>
```

这是 VS Code 提供的 **Emmet** 功能，不需要为了这一功能额外安装插件。

> 注意：`Ctrl + B` 的作用是**显示或隐藏侧边栏**，并不是“编辑窗口最大化”；删除当前行通常使用 `Ctrl + Shift + K`。

#### 使用 Live Server 运行 HTML

最简单的方式是直接使用浏览器打开 `.html` 文件，但学习 Web 开发时可以安装 **Live Server** 插件。

安装后，可以在 HTML 文件编辑窗口中选择 `Open with Live Server`。Live Server 会在当前计算机中启动一个简单的本地 HTTP 服务器，并通过浏览器访问当前页面，例如 `http://127.0.0.1:5500/index.html`。

Live Server **不会把 HTML 文件上传到互联网**，而是在本机启动 Web 服务器。与直接双击 HTML 文件相比，这种方式更加接近实际 Web 应用通过 HTTP 访问页面的运行环境。

Live Server 还可以监听文件变化。HTML、CSS 等文件保存后，浏览器通常能够自动刷新，从而减少手动刷新页面的操作。

### VS Code 配置

VS Code 的大部分设置既可以通过图形界面修改，也可以直接编辑 `settings.json`。

按 `Ctrl + ,` 可以打开设置页面，再通过设置页面右上角的相关按钮打开 `settings.json`。直接修改图形界面中的设置和修改 `settings.json`，本质上都是在修改 VS Code 的配置。

例如，可以使用以下配置：

```json
{
    "workbench.iconTheme": "vscode-icons",
    "editor.fontSize": 20,

    // 保存时自动格式化
    "editor.formatOnSave": true,

    // 保存时自动修复
    "editor.codeActionsOnSave": {
        "source.fixAll.eslint": "explicit"
    },

    // 默认格式化工具选择 Prettier
    "editor.defaultFormatter": "esbenp.prettier-vscode",

    // 文件自动保存
    "files.autoSave": "afterDelay",
    "files.autoSaveDelay": 1000,

    // 括号对着色
    "editor.bracketPairColorization.enabled": true,

    // 括号缩进参考线
    "editor.guides.bracketPairs": true
}
```

各项配置的作用如下。

#### `workbench.iconTheme`

```json
"workbench.iconTheme": "vscode-icons"
```

用于设置 VS Code 的**文件图标主题**。

配置为 `vscode-icons` 后，不同类型的文件通常会显示不同图标，例如 HTML、CSS、JavaScript、Java、JSON 文件会具有不同的视觉标识，从而更容易在项目目录中区分文件类型。

这一配置需要安装对应的 `vscode-icons` 插件。如果使用 Material Icon Theme，则应选择对应的图标主题，而不是继续设置为 `vscode-icons`。

#### `editor.fontSize`

```json
"editor.fontSize": 20
```

用于设置代码编辑区的**字体大小**，这里设置为 `20` 像素。

字体大小完全属于个人使用习惯，不影响代码本身。也可以在 VS Code 设置界面中搜索 `Font Size` 进行修改。

#### `editor.formatOnSave`

```json
"editor.formatOnSave": true
```

表示**保存文件时自动执行代码格式化**。

例如，在 HTML 中手动写出缩进比较混乱的代码，保存后 VS Code 会调用当前配置的格式化工具重新整理缩进、换行和空格，使代码格式更加统一。

这一配置只表示“保存时执行格式化”，至于具体使用哪个格式化工具，则由 `editor.defaultFormatter` 等配置决定。

#### `editor.codeActionsOnSave`

```json
"editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
}
```

用于控制**保存文件时自动执行哪些代码修复操作**。

其中，`source.fixAll.eslint` 表示让 ESLint 对能够自动修复的问题执行修复，例如某些项目中的代码风格问题、无用语法问题等。

`"explicit"` 表示只有在明确触发保存操作时才执行相应修复，而不是在所有可能触发保存的场景下都无条件执行。

这一配置需要项目本身已经正确使用 ESLint，并安装相应 ESLint 插件才能发挥实际作用。

> 注意：ESLint 是否能够修复某个问题，取决于项目配置的 ESLint 规则。不是所有报错都能够自动修复。

#### `editor.defaultFormatter`

```json
"editor.defaultFormatter": "esbenp.prettier-vscode"
```

用于指定 VS Code 默认使用 **Prettier** 作为代码格式化工具。

`esbenp.prettier-vscode` 是 Prettier 插件的扩展 ID。当执行“格式化文档”或者配合 `editor.formatOnSave` 保存文件时，VS Code 会优先使用 Prettier 对代码进行格式化。

Prettier 主要处理缩进、空格、换行、引号等**代码格式问题**，通常不负责判断业务逻辑是否正确。

#### `files.autoSave`

```json
"files.autoSave": "afterDelay"
```

用于开启**延迟自动保存**。

`afterDelay` 表示文件发生修改后，等待一段时间自动保存，不再需要每次手动按 `Ctrl + S`。

VS Code 还支持其他自动保存方式，但学习阶段理解 `afterDelay` 即可。

#### `files.autoSaveDelay`

```json
"files.autoSaveDelay": 1000
```

用于设置自动保存的等待时间，单位为**毫秒**。

`1000` 表示文件修改后约 `1000 ms`，即 `1 s` 后自动保存。

因此，`files.autoSave` 和 `files.autoSaveDelay` 通常配合使用：前者决定是否采用延迟自动保存，后者决定延迟多久。

#### `editor.bracketPairColorization.enabled`

```json
"editor.bracketPairColorization.enabled": true
```

用于启用**括号对着色**。

当代码中存在多层 `()`、`[]`、`{}` 时，VS Code 会使用不同颜色帮助区分对应的开始括号和结束括号。随着 JavaScript、Java 等代码嵌套层级增加，这一功能有助于快速判断括号的对应关系。

#### `editor.guides.bracketPairs`

```json
"editor.guides.bracketPairs": true
```

用于显示与括号层级相关的**引导线**。

当代码存在多层代码块时，引导线可以帮助观察某段代码属于哪一层括号范围，对于判断嵌套结构比较有帮助。

### 配置之间的配合关系

上述配置并不是完全独立的，其中有几组具有明显的配合关系。

保存文件时，可能同时发生以下操作：

1. `files.autoSave` 决定文件是否自动保存。
2. `files.autoSaveDelay` 决定自动保存前等待多长时间。
3. `editor.formatOnSave` 决定保存时是否执行代码格式化。
4. `editor.defaultFormatter` 决定格式化时默认使用哪个工具。
5. `editor.codeActionsOnSave` 决定保存时是否执行 ESLint 等代码修复操作。

因此，可以将整个过程简化理解为：

```
修改代码 → 触发保存 → Prettier 格式化 → ESLint 执行可用的自动修复 → 文件保存完成
```

其中，Prettier 与 ESLint 的职责并不完全相同：**Prettier 重点解决代码“长什么样”，ESLint 重点检查代码“是否符合规则、是否存在部分潜在问题”**。

> 补充：`settings.json` 属于开发工具配置，而不是 HTML 语法知识。当前阶段不要求记忆每一个配置项，但应理解这些配置分别解决什么问题。后续进行 JavaScript、Vue 等项目开发时，这些工具配置会逐渐成为日常开发环境的一部分。

## 第一个 HTML 程序

学习 HTML 时，可以将 **MDN Web Docs** 作为重要的文档和学习资料来源。MDN 是面向 Web 开发者的开放文档平台，主要提供 HTML、CSS、JavaScript、Web API、HTTP 等 Web 技术的教程、指南、语法参考和浏览器兼容性信息。其内容关注标准化的 Web 技术，并由 MDN 团队和开源社区持续维护。

> 注意：MDN 是非常重要且可信的 Web 技术文档，但它**不是 Web 标准的制定机构**，因此不宜称为“官方标准”。HTML 等标准本身主要由 WHATWG 等标准组织维护，MDN 的作用是对这些 Web 标准和浏览器实现进行文档化说明。

---

### HTML 文档的基本结构

创建 `index.html` 文件，可以编写一个最基本的 HTML 页面：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>我的第一个 HTML 页面</title>
</head>
<body>
    <p>body 元素中的内容会显示在网页中。</p>
</body>
</html>
```

一个完整 HTML 文档的基本组成可以概括如下：

| 结构              | 作用                                                    |
| ----------------- | ------------------------------------------------------- |
| `<!DOCTYPE html>` | 声明当前文档使用现代 HTML，使浏览器按照标准模式解析页面 |
| `<html>`          | HTML 文档的根元素，其他 HTML 元素通常都包含在其中       |
| `<head>`          | 保存页面的元数据、标题、样式引用等信息                  |
| `<body>`          | 保存网页中主要展示给用户的内容                          |

其中，`<html lang="zh-CN">` 中的 `lang` 用于声明当前页面的主要语言。页面内容为中文时，应使用 `zh-CN` 等合适的语言标识，而不是机械使用脚手架中常见的 `en`。

#### `<!DOCTYPE html>`

`<!DOCTYPE html>` 称为**文档类型声明（Document Type Declaration）**，通常放在 HTML 文件的第一行：

```html
<!DOCTYPE html>
```

早期 HTML 和 XHTML 中的文档类型声明比较复杂，需要关联特定的文档类型定义。现代 HTML 将其简化为 `<!DOCTYPE html>`。它的主要作用是告诉浏览器按照现代 HTML 的**标准模式（Standards Mode）**解析页面，避免浏览器进入为了兼容早期网页而保留的怪异模式。

> 注意：将 `<!DOCTYPE html>` 简单记作“HTML5 标记”便于入门，但并不完全准确。现代 HTML 已采用持续演进的 Living Standard，不再以传统的大版本号作为主要标准形式。

#### `<html>` 标签

`<html>` 是整个 HTML 文档的**根元素**，页面中的 `<head>` 和 `<body>` 等内容都位于其中：

```html
<html lang="zh-CN">
    <head>
        ...
    </head>
    <body>
        ...
    </body>
</html>
```

通常一个 HTML 文档只有一个 `<html>` 根元素。

---

### `<head>` 标签

`<head>` 用于定义 HTML 文档的**头部信息**，位于 `<html>` 内部、`<body>` 之前。其中主要保存页面自身的元数据和所引用的外部资源，这些内容大多数不会像正文一样直接显示在网页中。

常见的 `<head>` 子元素包括 `<title>`、`<meta>`、`<link>`、`<style>`、`<script>` 等。例如：

```html
<head>
    <meta charset="UTF-8">
    <title>用户中心</title>
    <link rel="stylesheet" href="style.css">
</head>
```

其中，`<meta>` 提供页面元数据，`<title>` 设置页面标题，`<link>` 可以引用外部 CSS 文件。`<head>` 中还可以包含 `<base>`、`<noscript>` 等其他元数据相关元素。

#### `<title>` 标签

`<title>` 用于定义当前 HTML 文档的**页面标题**，必须放在 `<head>` 中：

```html
<head>
    <meta charset="UTF-8">
    <title>个人网上银行</title>
</head>
```

`<title>` 中的文本通常会显示在浏览器的标签页或窗口标题位置，同时也能够向搜索引擎和用户说明当前页面的主要内容。

例如，相比 `<title>首页</title>`，`<title>商品详情 - 网上商城</title>` 能够更加清楚地描述当前页面。

一个准确、具有描述性的标题有助于用户识别页面，同时对 **SEO（Search Engine Optimization，搜索引擎优化）**也具有重要意义。SEO 是通过优化网站内容、结构和其他因素，提高网站在搜索引擎自然搜索结果中的可见性的过程。

> 注意：`<title>` 描述的是**整个网页的标题**，而 `<h1>` 等标题标签描述的是**网页正文中的标题**，二者作用不同。

#### `<meta>` 标签

`<meta>` 用于提供 HTML 文档的**元数据（Metadata）**，即描述页面自身的信息。它通常位于 `<head>` 中，其内容一般不会直接显示在网页正文中，而是提供给浏览器、搜索引擎等程序使用。

常见用途包括声明字符编码、提供页面描述以及提供其他页面级配置信息。

##### 声明字符编码

可以使用 `charset` 属性声明 HTML 文档采用的字符编码：

```html
<meta charset="UTF-8">
```

`UTF-8` 能够表示中文、英文以及世界上绝大多数常用字符，因此现代网页通常使用 UTF-8。

如果文件实际保存的字符编码与浏览器解析时采用的字符编码不一致，就可能出现中文乱码等问题。

因此，HTML 页面通常都会在 `<head>` 中声明：

```html
<head>
    <meta charset="UTF-8">
</head>
```

##### 页面关键字

以前可以通过 `keywords` 提供与当前网页相关的关键词：

```html
<meta name="keywords" content="Java,HTML,Web前端">
```

这种方式曾经被部分搜索引擎用于理解网页内容，但后来由于大量网站通过堆砌关键词操纵搜索排名，其实际作用逐渐降低。

对于 Google Search 而言，`keywords` 元标签目前会被直接忽略，对网页索引和搜索排名没有影响。

因此，**现代 Web 开发通常无需专门编写 `keywords` 元标签**。学习该写法主要是为了能够理解旧项目中的 HTML 代码。

##### 页面描述

可以使用 `description` 描述当前网页的主要内容：

```html
<meta name="description" content="提供 Java、HTML、CSS 等编程技术学习内容">
```

`description` 通常使用一段简短、准确的文字概括当前页面。搜索引擎可能使用它作为搜索结果中显示的页面摘要，但也可能根据用户搜索内容直接从网页正文中生成更合适的摘要。

因此，`description` 的主要价值在于**帮助搜索引擎和用户理解页面内容，并可能改善搜索结果摘要的展示效果**，而不能简单理解为“填写后就能提升搜索排名”。

> 结论：当前阶段 `<meta>` 最需要掌握的是 `<meta charset="UTF-8">`。`description` 需要知道其基本作用，而 `keywords` 主要作为旧式 SEO 写法了解即可。

---

### `<body>` 标签

`<body>` 用于定义 HTML 文档的**主体内容**。网页中大多数需要直接展示给用户的内容，例如文本、标题、图片、按钮、表格、表单等，通常都写在 `<body>` 中。

例如：

```html
<body>
    <h1>用户中心</h1>
    <p>欢迎登录系统。</p>
    <button>退出登录</button>
</body>
```

可以将 `<head>` 和 `<body>` 简单区分为：

- `<head>` 主要描述**页面自身的信息和资源**。
- `<body>` 主要描述**页面中展示给用户的内容**。

#### `background` 和 `bgcolor` 属性（了解）

早期 HTML 可以直接通过 `<body>` 的 `background` 属性设置背景图片：

```html
<body background="img/bg.jpg">
    ...
</body>
```

也可以通过 `bgcolor` 设置背景颜色：

```html
<body bgcolor="yellow">
    ...
</body>
```

这两种写法在现代 HTML 中都已经**废弃（Deprecated）**，不应继续用于新项目。现代 Web 开发遵循“HTML 负责结构、CSS 负责样式”的原则，因此应使用 CSS 设置背景。

设置背景图片应使用：

```css
body {
    background-image: url("img/bg.jpg");
}
```

设置背景颜色应使用：

```css
body {
    background-color: yellow;
}
```

> 易错点：浏览器目前可能仍然能够识别 `background` 和 `bgcolor`，但“浏览器还能运行”并不代表这种写法仍然推荐使用。阅读旧项目时需要认识这些属性，新代码应使用 CSS。

### HTML 注释

HTML 注释用于在源代码中添加说明信息，其基本语法为：

```html
<!-- 注释内容 -->
```

例如：

```html
<body>
    <!-- 用户信息区域 -->
    <h1>用户中心</h1>

    <!-- 页面欢迎信息 -->
    <p>欢迎登录系统。</p>
</body>
```

注释内容存在于 HTML 源代码中，但浏览器在正常渲染页面时**不会将注释作为网页内容显示给用户**。

注释主要用于说明代码作用、标记页面结构、暂时屏蔽部分 HTML 内容等。例如：

```html
<!-- <p>这段内容暂时不显示。</p> -->
```

此时 `<p>` 位于注释内部，因此不会被浏览器作为正常 HTML 元素渲染。

> 注意：HTML 注释虽然不会直接显示在页面中，但通常仍然可以通过浏览器的“查看网页源代码”或开发者工具看到。因此，**不能在 HTML 注释中保存密码、密钥、账号等敏感信息**。

## HTML 基础标签

HTML 提供了大量用于描述网页内容结构和语义的标签。基础阶段需要重点掌握标题、段落、文本语义与格式、图片等常用标签，并理解一个基本原则：**HTML 标签首先用于描述内容的结构和含义，具体的字体、颜色、对齐方式等视觉效果通常交给 CSS 控制。**

> 补充：HTML 标签名本身不区分大小写，但现代 Web 开发统一推荐使用小写形式，例如使用 `<body>`、`<p>`，而不是 `<BODY>`、`<P>`。

### 标题标签

HTML 使用 `<h1>`～`<h6>` 表示六个级别的标题，其中 `<h1>` 表示最高级别标题，`<h6>` 表示最低级别标题。

```html
<body>
    <h1>一级标题</h1>
    <h2>二级标题</h2>
    <h3>三级标题</h3>
    <h4>四级标题</h4>
    <h5>五级标题</h5>
    <h6>六级标题</h6>
</body>
```

浏览器默认通常会将 `<h1>` 显示得最大，将 `<h6>` 显示得最小，但**标题标签的核心作用是表示内容的层级，而不是控制字体大小**。字体大小等视觉效果可以通过 CSS 任意修改，因此不能因为想让文字变大就随意使用 `<h1>`。

例如，一篇文章可以按照以下结构组织：

```html
<h1>Java 学习笔记</h1>

<h2>Java 基础语法</h2>
<h3>变量</h3>
<h3>运算符</h3>

<h2>面向对象</h2>
<h3>类与对象</h3>
<h3>继承</h3>
```

这种写法能够清楚表达文档结构：`<h1>` 是整篇内容的主标题，`<h2>` 是一级章节，`<h3>` 是章节下的子标题。

一般应按照内容层级依次使用标题，尽量不要无理由跳级。例如 `<h2>` 后直接使用 `<h5>`，会使文档结构难以理解。一个页面通常也建议使用一个能够概括页面主要内容的 `<h1>`。

#### `align` 属性（了解）

早期 HTML 可以使用 `align` 设置标题的水平对齐方式：

```html
<h1 align="center">用户中心</h1>
```

常见值包括 `left`、`right`、`center` 和 `justify`，分别表示左对齐、右对齐、居中和两端对齐。

但是，`align` 属于旧式 HTML 表现属性，现代开发不应继续使用。页面对齐属于**样式**，应通过 CSS 的 `text-align` 控制，例如：

```html
<h1 style="text-align: center;">用户中心</h1>
```

> 注意：`align` 并不是所谓“所有块级元素通用的属性”。一些旧式 HTML 元素曾分别支持该属性，但现代 HTML 已逐渐废弃这类直接控制样式的属性。

---

### 段落标签

`<p>`（Paragraph）用于表示一个**段落**。每一段具有独立含义的文本通常应该放在一个 `<p>` 元素中。

```html
<body>
    <p>HTML 用于描述网页的结构和内容。</p>
    <p>CSS 用于控制网页的表现样式。</p>
</body>
```

浏览器默认会将不同 `<p>` 元素按照块状形式排列，并在段落之间保留一定间距，因此视觉上通常表现为“一个段落占据一块区域”。但这种显示效果属于浏览器的默认样式，`<p>` 的本质仍然是**表示一个语义上的段落**。

不要为了增加页面间距而创建空的 `<p>`，例如 `<p></p>`。页面间距属于样式问题，应通过 CSS 处理。

早期 HTML 中 `<p>` 同样支持 `align`：

```html
<p align="center">居中的段落</p>
```

该属性现在已经过时，现代开发应使用 CSS，例如 `<p style="text-align: center;">居中的段落</p>`。

### 文本语义与格式标签

HTML 中存在多种用于描述文本含义的标签。有些标签在浏览器中的默认显示效果相似，但**语义并不相同**，使用时不能只根据“看起来是什么样”进行选择。

#### `<b>` 与 `<strong>`

`<b>` 通常会被浏览器显示为**粗体**，用于吸引读者注意某段文字，但不表示这段内容具有更高的重要性。

例如：

```html
<p>本章涉及三个关键词：<b>HTML</b>、<b>CSS</b> 和 <b>JavaScript</b>。</p>
```

`<strong>` 表示内容具有**较强的重要性、严肃性或紧迫性**，浏览器默认通常也会以粗体显示：

```html
<p><strong>警告：删除操作无法撤销。</strong></p>
```

因此，二者虽然默认都可能显示为粗体，但含义不同：

| 标签       | 主要含义                   | 浏览器默认效果 |
| ---------- | -------------------------- | -------------- |
| `<b>`      | 吸引注意，但不增加重要程度 | 通常为粗体     |
| `<strong>` | 表示重要、严重或紧迫的内容 | 通常为粗体     |

如果只是单纯为了让文字变粗，没有任何语义上的需要，更适合使用 CSS 的 `font-weight` 控制。

#### `<em>` 与 `<i>`

`<em>`（Emphasis）表示对文字进行**语气上的强调**，浏览器默认通常显示为斜体。

```html
<p>提交订单之前，<em>一定要</em>确认收货地址。</p>
```

改变 `<em>` 的位置可能会改变一句话想强调的重点。例如“我<em>没有</em>删除文件”强调的是“没有”，“<em>我</em>没有删除文件”强调的是执行者。

`<i>` 表示由于某种原因需要与普通正文区分的文字，例如专业术语、外来语、物种学名、人物内心想法等，浏览器默认也通常显示为斜体：

```html
<p><i>HTML</i> 是 HyperText Markup Language 的缩写。</p>
```

二者的区别可以概括为：

| 标签   | 主要含义                     | 浏览器默认效果 |
| ------ | ---------------------------- | -------------- |
| `<em>` | 对内容进行语气上的强调       | 通常为斜体     |
| `<i>`  | 表示与普通正文有所区别的文本 | 通常为斜体     |

因此，`<em>` 并不是简单的“斜体标签”，`<i>` 也不只是“没有语义的斜体标签”。二者在现代 HTML 中都有各自的语义。

#### `<del>` 与 `<ins>`

`<del>`（Deleted）表示**已经从文档中删除的内容**，浏览器默认通常会添加删除线：

```html
<p>原价：<del>299 元</del>，现价：199 元。</p>
```

`<ins>`（Inserted）表示**后来新增或插入的内容**，浏览器默认通常会添加下划线：

```html
<p>活动时间：<ins>本周六上午 10 点</ins></p>
```

二者经常配合表示文档修改：

```html
<p>
    原价：<del>299 元</del>
    现价：<ins>199 元</ins>
</p>
```

`<del>` 和 `<ins>` 还可以使用 `datetime` 记录内容发生修改的时间，使用 `cite` 指向能够说明修改原因的资源：

```html
<p>
    原价：
    <del datetime="2026-09-01" cite="change-log.html">299 元</del>
    现价：
    <ins datetime="2026-09-01" cite="change-log.html">199 元</ins>
</p>
```

这些属性属于进一步用法，基础阶段知道 `<del>` 表示删除内容、`<ins>` 表示新增内容即可。

#### `<small>`

`<small>` 用于表示**附属说明、版权信息、免责声明、法律条款等次要内容**。浏览器默认通常将其中的文字显示得比周围文字稍小。

例如：

```html
<footer>
    <small>© 2026 示例公司。保留所有权利。</small>
</footer>
```

或者：

```html
<p>
    商品价格为 199 元。
    <small>实际价格以结算页面显示为准。</small>
</p>
```

> 注意：`<small>` 不是通用的“缩小字体标签”。如果只是为了让某段文字视觉上变小，应使用 CSS 的 `font-size`；当内容本身属于附属说明、小字条款等语义时，才适合使用 `<small>`。

#### `<u>`

`<u>` 在浏览器中默认通常表现为下划线，但现代 HTML 中它并不是单纯的“下划线标签”，而是用于表示某些**非文本性质的注释或标记**，例如标记拼写错误等。

```html
<p>这个单词存在拼写错误：<u>Jvaa</u></p>
```

如果目的只是让普通文字显示下划线，应使用 CSS 的 `text-decoration`，而不是依赖 `<u>`。

同时，由于网页中的超链接默认也经常带有下划线，应避免滥用 `<u>` 导致普通文字看起来像可以点击的链接。

#### `<sup>` 与 `<sub>`

`<sup>`（Superscript）用于表示**上标文本**，`<sub>`（Subscript）用于表示**下标文本**。

例如，数学中的平方可以写为：

```html
<p>(a - b)<sup>2</sup> = a<sup>2</sup> - 2ab + b<sup>2</sup></p>
```

化学式中的下标可以写为：

```html
<p>水的化学式是 H<sub>2</sub>O。</p>
```

因此，`<sup>` 常用于指数、序号等需要上标表示的内容，`<sub>` 常用于化学式、数学变量下标等内容。

#### `<abbr>`

`<abbr>`（Abbreviation）用于表示**缩写或缩略语**。

例如：

```html
<p><abbr title="HyperText Markup Language">HTML</abbr> 是一种标记语言。</p>
```

其中，`title` 可以提供缩写的完整含义。桌面浏览器通常可以在鼠标悬停时显示该说明，但不应该只依赖悬停提示帮助用户理解缩写。

对于重要或者不常见的缩写，更推荐在第一次出现时直接在正文中给出完整名称，例如：

```html
<p>
    超文本标记语言（<abbr title="HyperText Markup Language">HTML</abbr>）
    用于描述网页结构。
</p>
```

这样即使设备不支持鼠标悬停，用户也能直接理解缩写的含义。

#### `<pre>`

`<pre>`（Preformatted Text）用于表示**预格式化文本**。其中的空格、缩进和换行通常会按照 HTML 源代码中的形式保留下来。

普通 HTML 文本中的连续空格和换行通常会被浏览器折叠，例如源码中输入多个空格，在页面中往往仍只表现为一个空格。而 `<pre>` 可以保留这些格式。

例如：

```html
<pre>
姓名：张三
年龄：20
专业：软件工程
</pre>
```

如果直接展示程序代码，也可以利用 `<pre>` 保留代码的缩进：

```html
<pre>
for (int i = 0; i &lt; 3; i++) {
    System.out.println(i);
}
</pre>
```

其中使用 `&lt;` 表示字符 `<`，因为 `<` 在 HTML 中具有标签语法含义。

浏览器默认通常会使用等宽字体显示 `<pre>` 中的内容，但这属于默认样式。`<pre>` 真正的核心作用是**保留预先排好的文本格式和空白字符**。

#### `<br>` 与 `<hr>`

`<br>`（Line Break）用于在文本中插入一次**换行**。它属于没有结束标签和内部内容的空元素。

例如：

```html
<p>
    安徽省合肥市<br>
    蜀山区某某路<br>
    邮编：230000
</p>
```

`<br>` 适合用于地址、诗歌等本身就需要明确换行的位置，不应该为了增加普通段落之间的距离而连续写大量 `<br>`。

`<hr>` 表示内容之间的**主题性分隔（Thematic Break）**，浏览器默认通常将其显示为一条水平线：

```html
<p>第一部分：HTML 基础</p>

<hr>

<p>第二部分：CSS 基础</p>
```

因此，`<hr>` 的语义重点是“内容主题发生分隔”，水平线只是浏览器提供的默认视觉效果。

### 图片标签

`<img>`（Image）用于在 HTML 页面中**嵌入图片**。

例如：

```html
<img src="img/cat.jpg" alt="一只橘猫" title="小猫">
```

`<img>` 属于**空元素（Void Element）**，自身不能包含内容，因此不需要写对应的 `</img>` 结束标签。

常用属性如下：

| 属性     | 作用               |
| -------- | ------------------ |
| `src`    | 指定图片资源的位置 |
| `alt`    | 提供图片的替代文本 |
| `title`  | 提供图片的补充说明 |
| `width`  | 指定图片宽度       |
| `height` | 指定图片高度       |

#### `src`

`src`（Source）用于指定图片资源的位置，是 `<img>` 最核心的属性之一。

例如：

```html
<img src="img/avatar.jpg" alt="用户头像">
```

图片路径既可以使用相对路径，也可以使用完整的网络地址。基础学习阶段通常主要使用项目中的相对路径，例如 `img/avatar.jpg` 表示在当前页面相应位置下查找图片资源。

如果 `src` 指定的文件不存在、路径错误或者图片无法正常获取，浏览器就无法正常显示图片。

#### `alt`

`alt`（Alternative Text）用于提供图片的**替代文本**：

```html
<img src="img/book.jpg" alt="一本放在桌面上的 Java 编程书籍">
```

当图片无法正常显示时，浏览器可能显示 `alt` 中的文字；更重要的是，屏幕阅读器等辅助技术可以利用替代文本向无法直接看到图片的用户说明图片内容。

因此，`alt` 不应简单理解成“图片加载失败时的提示语”。

例如下面这种写法信息价值很低：

```html
<img src="img/book.jpg" alt="图片加载失败">
```

更合适的写法是描述图片本身：

```html
<img src="img/book.jpg" alt="Java 编程书籍封面">
```

如果图片完全属于装饰性内容、不承担实际信息，通常可以使用空的 `alt`：

```html
<img src="img/decorative-line.png" alt="">
```

> 结论：`alt` 应说明**图片表达了什么信息**，而不是只说明“图片加载失败了”。

#### `title`

`title` 可以为图片提供补充性的说明信息：

```html
<img src="img/cat.jpg" alt="一只趴在窗边的猫" title="橘猫">
```

桌面浏览器通常会在鼠标悬停时显示 `title` 内容，但这种交互在触摸设备等环境中并不可靠，因此**不能使用 `title` 代替 `alt`**。图片的重要信息应该直接出现在正文或 `alt` 中。

#### `width` 与 `height`

`width` 和 `height` 分别用于指定图片的宽度和高度。

HTML 属性中的写法是**不带单位的整数**：

```html
<img
    src="img/cat.jpg"
    alt="一只橘猫"
    width="300"
    height="200"
>
```

这里的 `300` 和 `200` 表示 CSS 像素。HTML 属性中不应写成 `width="300px"`，也不应使用 `width="50%"` 这类 CSS 写法。需要使用 `px`、百分比等复杂尺寸控制时，应交给 CSS。

早期入门材料经常建议“只设置 `width` 或 `height` 中的一个，这样图片才能等比例缩放”。这种说法并不适合作为现代开发规则。

**现代 HTML 通常推荐同时提供图片本身正确的 `width` 和 `height`**，这样浏览器在图片尚未下载完成时，就能够提前计算图片的宽高比例并为图片预留空间，从而减少页面内容突然跳动。需要真正控制图片显示大小时，再使用 CSS。

如果人为设置的宽高比例与原图片比例不同，就可能导致图片被拉伸或压缩。例如，一张原本比例为 `2:1` 的图片，如果强制设置为宽 `200`、高 `200`，最终就可能被显示成正方形并发生变形。

> 易错点：HTML 的 `width`、`height` 属性与 CSS 中的 `width`、`height` 属性不要混淆。HTML 中通常写 `width="300"`；CSS 中则可以写 `width: 300px;`、`width: 50%;` 等带单位或百分比的形式。

### `<a>` 超链接标签

`<a>`（Anchor）用于创建**超链接**，可以将文字、图片等内容链接到其他网页、文件、当前页面中的指定位置，或者其他 URL 能够表示的资源。

最基本的写法为：

```html
<a href="https://www.example.com">访问网站</a>
```

其中，`<a>` 与 `</a>` 之间的内容是用户可以点击的区域，`href` 指定链接目标。

浏览器通常会为超链接提供默认样式，例如文字带下划线、鼠标悬停时指针变成手形，但这些都只是浏览器的默认 CSS 样式，可以通过 CSS 修改。

#### `href` 属性

`href` 是 `<a>` 最核心的属性，用于指定**超链接指向的 URL**。`href` 通常解释为 **Hypertext Reference（超文本引用）**，而不是 `hot reference`。

例如：

```html
<a href="https://www.example.com">访问示例网站</a>
```

当 `href` 指向 `http://` 或 `https://` 地址并发生普通页面导航时，浏览器通常会通过 HTTP `GET` 方法获取目标资源，因此在基础阶段可以理解为“点击普通网页超链接通常会产生 GET 请求”。HTTP 中的 `GET` 用于获取目标资源的当前表示。

但不能简单记成“**点击 `<a>` 一定会向服务器发送 GET 请求**”，因为 `href` 可以指向多种不同目标。例如 `href="#content"` 只是在当前文档中跳转，`href="mailto:test@example.com"` 可以调用邮件程序，这些情况并不等同于向 Web 服务器发送普通 GET 请求。`href` 也不仅限于 HTTP URL。

> 结论：`href` 的本质是**指定超链接的目标地址**。当目标是普通 HTTP/HTTPS Web 资源时，点击链接通常会触发页面导航并通过 GET 获取资源。

#### URL

**URL（Uniform Resource Locator，统一资源定位符）**用于定位网络中的资源，例如 `https://www.example.com:8443/products/list.html?page=2#detail`。

一个完整 URL 可以包含以下部分：

`协议（scheme）://主机（host）:端口（port）/路径（path）?查询参数（query）#片段（fragment）`

以上述 URL 为例：

| 部分     | 内容                  | 作用                                         |
| -------- | --------------------- | -------------------------------------------- |
| 协议     | `https`               | 指定访问资源所使用的协议                     |
| 主机     | `www.example.com`     | 指定目标服务器，可以是域名，也可以是 IP 地址 |
| 端口     | `8443`                | 指定目标主机上的网络服务端口                 |
| 路径     | `/products/list.html` | 标识服务器中的目标资源                       |
| 查询参数 | `?page=2`             | 向目标资源附带额外参数                       |
| 片段     | `#detail`             | 定位资源内部的某个位置                       |

其中，查询参数和片段等部分都可以省略。URL 中的主机通常使用域名，也可以直接使用 IP 地址，因此不能将 URL 固定理解为“协议 + IP 地址 + 端口 + 资源路径”。

例如：

`http://192.168.1.10:8080/user/index.html`

其中，`http` 表示使用 HTTP，`192.168.1.10` 是目标主机的 IP 地址，`8080` 是端口号，`/user/index.html` 是资源路径。

对于 HTTP 和 HTTPS，如果使用默认端口，URL 中通常可以省略端口号，例如 HTTP 默认通常使用 `80`，HTTPS 默认通常使用 `443`。

> 注意：HTTP 并不是“W3C 制定的一种数据格式”。HTTP 是 Web 中客户端与服务器进行通信的**应用层协议**，现代 HTTP 核心规范由 IETF 通过 RFC 进行标准化。

#### 域名与 DNS

相比 IP 地址，域名更容易记忆，例如 `www.example.com`。

浏览器访问使用域名的 URL 时，需要通过 **DNS（Domain Name System，域名系统）**查询该域名对应的 IP 地址，然后才能找到目标服务器并建立后续网络通信。

因此，可以将过程简化理解为：

`www.example.com → DNS 查询 → 获得服务器 IP 地址 → 与服务器通信`

DNS 主要负责的是**域名与 IP 地址之间的解析**，不会把 `http://www.example.com` 整体转换成类似 `http://某个IP:80/index.html` 的完整 URL。协议、端口、路径等仍然来自原来的 URL。

同一个域名还可能对应多个 IP 地址，而且对应关系可能发生变化。因此，通过 `ping www.example.com` 看到的某个 IP 地址不能理解为“这个网站永久唯一的服务器 IP”。

> 易错点：即使通过 `ping` 得到了某个网站的 IP 地址，也不能保证直接在浏览器中输入该 IP 就能够得到与域名完全相同的页面。现代网站可能使用虚拟主机、HTTPS、CDN 等机制，需要依赖域名才能正确确定具体站点。

#### `target` 属性

`target` 用于指定链接打开后的**浏览上下文（Browsing Context）**。

常用值如下：

| 值         | 作用                                                        |
| ---------- | ----------------------------------------------------------- |
| `_self`    | 在当前页面中打开，默认值                                    |
| `_blank`   | 在新的浏览上下文中打开，通常表现为新标签页                  |
| `_parent`  | 在当前页面的父级浏览上下文中打开                            |
| `_top`     | 在最顶层浏览上下文中打开                                    |
| 自定义名称 | 在具有对应 `name` 的浏览上下文中打开，例如指定的 `<iframe>` |

例如：

```html
<a href="https://www.example.com" target="_blank">新标签页打开</a>

<a href="https://www.example.com" target="_self">当前页面打开</a>
```

`_parent` 和 `_top` 主要在 `<iframe>` 等存在嵌套浏览上下文的场景中使用。

例如，一个 `<iframe>` 定义为：

```html
<iframe src="welcome.html" name="contentFrame" title="内容区域"></iframe>
```

可以使用：

```html
<a href="user.html" target="contentFrame">用户信息</a>
```

点击链接后，`user.html` 会加载到名为 `contentFrame` 的 `<iframe>` 中，而不是让整个页面发生跳转。

#### 页面内锚点

超链接还可以跳转到当前页面的指定位置，这种方式称为**文档片段（Document Fragment）**。

现代 HTML 应通过元素的 `id` 属性定义目标位置：

```html
<a href="#java">跳转到 Java 章节</a>

<h2 id="java">Java 基础</h2>
```

点击链接后，浏览器会查找 `id="java"` 的元素，并滚动到该位置。URL 此时通常会变成类似 `page.html#java` 的形式。

早期 HTML 中也可以写：

```html
<a name="java"></a>
```

然后通过 `href="#java"` 跳转。你上传的锚点示例使用的正是这种方式。

但 `<a>` 的 `name` 属性已经属于**废弃写法**，现代 HTML 应统一使用 `id`。

> 结论：现代页面内跳转使用 `href="#目标id"` 配合元素的 `id="目标id"`。

#### 图片超链接

`<a>` 中不仅可以放文字，也可以包含图片，因此可以将图片制作成可点击的超链接。附件中的示例也是通过 `<a>` 包裹 `<img>` 实现图片链接。

例如：

```html
<a href="https://www.example.com">
    <img src="img/logo.png" alt="访问示例网站">
</a>
```

此时用户点击图片就会激活外层 `<a>` 的超链接。

对于作为链接使用的图片，`alt` 应尽量描述**链接的作用或目标**，而不是简单写成“图片加载失败”。

### `<iframe>` 内联框架

`<iframe>`（Inline Frame，内联框架）用于在当前 HTML 页面中**嵌入另一个独立的 HTML 页面**。可以将其理解为当前页面内部存在一个独立的浏览区域。

例如：

```html
<iframe
    src="map.html"
    width="600"
    height="400"
    title="地图"
></iframe>
```

常见属性如下：

| 属性      | 作用                                               |
| --------- | -------------------------------------------------- |
| `src`     | 指定需要嵌入的页面 URL                             |
| `width`   | 指定 iframe 的宽度                                 |
| `height`  | 指定 iframe 的高度                                 |
| `name`    | 为 iframe 命名，可以作为 `<a target="...">` 的目标 |
| `title`   | 描述 iframe 中的内容，便于辅助技术识别             |
| `sandbox` | 对 iframe 中的页面施加额外安全限制                 |

其中，HTML 中的 `width` 和 `height` 属性表示 CSS 像素，例如 `width="600"`、`height="400"`。如果需要百分比、自适应布局等复杂尺寸控制，通常应通过 CSS 实现。

`title` 应简要说明 iframe 中嵌入的内容，例如 `title="地图"`、`title="视频播放器"`，有助于屏幕阅读器等辅助技术理解页面结构。

`<iframe>` 常用于嵌入地图、视频等第三方内容，在页面中集成其他独立页面或系统，以及配合 `sandbox` 对部分嵌入内容进行隔离。

#### `name` 与 `target`

`<iframe>` 可以通过 `name` 属性获得一个名称，然后将 `<a>` 的 `target` 指向该名称，使链接对应的页面加载到指定 iframe 中。

例如：

```html
<a href="user.html" target="contentFrame">用户信息</a>

<iframe
    src="welcome.html"
    name="contentFrame"
    title="内容区域"
></iframe>
```

初始情况下，iframe 中显示 `welcome.html`。点击“用户信息”后，整个主页面不会跳转，而是由名为 `contentFrame` 的 iframe 加载 `user.html`。

#### `_parent` 与 `_top`

`target="_parent"` 和 `target="_top"` 主要用于**页面存在 iframe 嵌套时**。要理解二者，需要先明确三个层级：

```text
顶层页面
└── iframe A
    └── iframe B
```

假设当前超链接位于最里面的 `iframe B` 中：

- `_self`：在当前的 `iframe B` 中打开目标页面。
- `_parent`：跳出当前的 `iframe B`，在它的**直接父级 iframe A** 中打开目标页面。
- `_top`：跳出所有 iframe，在最外层的**顶级页面**中打开目标页面。

例如，最外层页面 `index.html` 中嵌入 `parent.html`：

```html
<!-- index.html -->
<h1>网站首页</h1>

<iframe
    src="parent.html"
    title="父级框架"
></iframe>
```

`parent.html` 中又嵌入 `child.html`：

```html
<!-- parent.html -->
<h2>父级页面</h2>

<iframe
    src="child.html"
    title="子级框架"
></iframe>
```

此时形成：

`index.html → parent.html → child.html`

在最内层的 `child.html` 中分别定义链接：

```html
<!-- child.html -->

<a href="page1.html" target="_self">在当前 iframe 中打开</a>

<a href="page2.html" target="_parent">在父级 iframe 中打开</a>

<a href="page3.html" target="_top">在最外层页面中打开</a>
```

点击不同链接时：

1. 点击 `_self`，`page1.html` 只替换当前的 `child.html`，外层结构保持不变。
2. 点击 `_parent`，`page2.html` 会替换 `parent.html` 所在的浏览区域，因此 `child.html` 所在的这一层也随之消失。
3. 点击 `_top`，`page3.html` 会直接替换最外层的 `index.html`，整个当前页面都跳转到 `page3.html`。

因此，可以将三者简化理解为：

`_self` → 当前层

`_parent` → 向外跳一层

`_top` → 一直跳到最外层

> 注意：如果当前页面本身没有位于 iframe 中，`_parent` 找不到更高的父级浏览上下文，效果通常与 `_self` 相同；如果当前页面已经是最顶层页面，`_top` 的效果也与 `_self` 基本相同。因此，`_parent` 和 `_top` 的区别主要在**多层 iframe 嵌套**时才能明显体现。

> 注意：并不是任意网站都允许被 `<iframe>` 嵌入。目标网站可以通过相应的安全策略禁止其他页面嵌入，因此可能出现 URL 本身能够正常访问，但放入 `<iframe>` 后无法显示的情况。

### `<br>` 与 `<hr>` 的补充

`<br>` 和 `<hr>` 前面已经介绍过，这里重点补充其语法和旧式表现属性。

`<br>` 是**空元素（Void Element）**，用于产生换行，没有结束标签，因此写成 `<br>` 即可，不应该写成 `<br></br>`。

例如：

```html
<p>
    第一行<br>
    第二行<br>
    第三行
</p>
```

也可以看到一些 XHTML 风格或格式化工具生成的 `<br />`，浏览器同样能够正确解析，但现代 HTML 通常直接写 `<br>` 即可。

`<hr>` 表示内容之间发生**主题性分隔**，浏览器默认通常将其显示为一条水平线。你上传的示例还使用了 `size`、`width`、`align` 和 `color` 设置其显示效果。

例如旧式写法：

```html
<hr size="3" width="90%" align="center" color="red">
```

这些属性主要用于直接控制显示效果，在现代 HTML 中已经不推荐继续使用。`<hr>` 的外观应该通过 CSS 设置，例如：

```html
<hr class="section-line">
```

```css
.section-line {
    width: 90%;
    border: none;
    border-top: 3px solid red;
}
```

现代 HTML 中 `<hr>` 的重点也不是“画水平线”，而是表示**两部分内容之间的主题发生变化**，水平线只是浏览器提供的默认表现。

### `<span>` 与 `<div>`

`<span>` 和 `<div>` 都属于**通用容器元素**，本身不会表达特定的业务语义，通常用于包裹一部分内容，方便后续通过 CSS 设置样式或通过 JavaScript 操作。

二者最直观的区别在于浏览器提供的默认显示方式：`<span>` 默认按照行内方式显示，而 `<div>` 默认按照块级方式显示。

#### `<span>`

`<span>` 是一个通用的**行内容器**，适合包裹一句话或一段内容中的局部区域。

例如：

```html
<p>用户名：<span class="error">用户名已存在</span></p>
```

单独增加 `<span>` 后，如果没有设置任何 CSS，通常不会产生明显的视觉变化。它的主要价值在于为局部内容提供一个可以被 CSS 或 JavaScript 精确选中的容器。

例如：

```css
.error {
    color: red;
}
```

于是只需要修改 `<span>` 包裹的局部文字，而不会影响整个 `<p>`。

附件中的例子也是在输入框之后使用 `<span>` 显示“用户名已存在”的局部提示信息。

#### `<div>`

`<div>`（Division）是一个通用的**块级容器**，常用于组织页面中的一组内容，也是 CSS 布局中非常常见的基础元素。

例如：

```html
<div class="user-card">
    <h2>用户信息</h2>
    <p>姓名：张三</p>
    <p>年龄：20</p>
</div>
```

`<div>` 可以相互嵌套，用于构造页面的结构层次。附件中的示例就通过多个 `<div>` 相互嵌套形成多层盒子。

> 注意：`<div>` 不能严格理解为“图层标签”。它的本质是**没有特定语义的通用容器**，只是经常配合 CSS 用于页面布局。

`<span>` 与 `<div>` 可以简单对比如下：

| 标签     | 默认显示方式 | 常见用途                         |
| -------- | ------------ | -------------------------------- |
| `<span>` | 行内         | 包裹局部文字或局部内容           |
| `<div>`  | 块级         | 组织一组内容、构建页面结构和布局 |

需要注意，所谓“行内”和“块级”描述的是元素的**默认 CSS 显示方式**。CSS 可以改变元素的 `display`，因此不能认为 `<span>` 永远不能独占一行，或者 `<div>` 永远必须独占一行。

### 列表标签

HTML 提供了**无序列表**和**有序列表**，列表中的每一个列表项使用 `<li>` 表示。

#### 无序列表

`<ul>`（Unordered List）用于表示**顺序没有实际意义**的一组内容。

例如：

```html
<ul>
    <li>Java</li>
    <li>HTML</li>
    <li>CSS</li>
</ul>
```

浏览器默认通常会在每个列表项前显示项目符号。

列表还可以进行嵌套，嵌套列表应该放在对应的 `<li>` 内部：

```html
<ul>
    <li>
        中国
        <ul>
            <li>北京</li>
            <li>上海</li>
            <li>合肥</li>
        </ul>
    </li>
    <li>美国</li>
</ul>
```

附件中的示例也展示了多层 `<ul>` 嵌套结构。

早期 HTML 可以使用 `<ul type="disc">`、`<ul type="circle">`、`<ul type="square">` 等方式改变项目符号，但 `<ul>` 的 `type` 属性已经废弃，现代开发应使用 CSS 的 `list-style-type`。

例如：

```css
ul {
    list-style-type: square;
}
```

如果需要取消项目符号，也应使用：

```css
ul {
    list-style-type: none;
}
```

因此，`type="none"` 不应作为现代 `<ul>` 的标准写法记忆。

#### 有序列表

`<ol>`（Ordered List）用于表示**顺序具有实际意义**的一组内容，例如操作步骤、排行榜等。

```html
<ol>
    <li>创建 HTML 文件</li>
    <li>编写 HTML 代码</li>
    <li>保存文件</li>
    <li>使用浏览器打开</li>
</ol>
```

`<ol>` 的 `type` 属性可以指定编号类型：

| `type` | 编号形式          |
| ------ | ----------------- |
| `1`    | `1、2、3……`，默认 |
| `A`    | `A、B、C……`       |
| `a`    | `a、b、c……`       |
| `I`    | `I、II、III……`    |
| `i`    | `i、ii、iii……`    |

例如：

```html
<ol type="A">
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ol>
```

与 `<ul>` 不同，`<ol>` 的 `type` 属性目前仍然可以使用。不过如果编号样式只是纯视觉需求，一般仍建议通过 CSS 的 `list-style-type` 控制；如果编号形式本身具有文档意义，则可以使用 `type`。

> 结论：判断使用 `<ul>` 还是 `<ol>` 的关键不是项目符号长什么样，而是**交换列表项顺序后，内容含义是否发生变化**。顺序无意义使用 `<ul>`，顺序有意义使用 `<ol>`。

### `<base>` 标签

`<base>` 用于指定当前 HTML 文档中**相对 URL 解析时所使用的基准 URL**。

`<base>` 必须放在 `<head>` 中，一个文档中只能定义一个 `<base>` 元素。

例如：

```html
<head>
    <base href="https://www.example.com/resources/">
</head>

<body>
    <img src="images/logo.png" alt="网站 Logo">
    <a href="user.html">用户中心</a>
</body>
```

此时浏览器会将相对地址解析为：

`images/logo.png` → `https://www.example.com/resources/images/logo.png`

`user.html` → `https://www.example.com/resources/user.html`

因此，`<base>` 会影响页面中大量使用相对 URL 的元素，例如 `<a href>`、`<img src>`、`<link href>` 等。

如果页面**没有**定义 `<base>`，相对 URL 默认基于**当前 HTML 文档自身的 URL**进行解析，并不是统一“从应用根目录开始查找”。

例如当前页面为：

`http://localhost:5500/user/index.html`

其中：

- `img/avatar.png` 通常解析为 `http://localhost:5500/user/img/avatar.png`；
- `/img/avatar.png` 以 `/` 开头，表示从当前站点的根路径开始解析，通常为 `http://localhost:5500/img/avatar.png`。

> 易错点：`<base>` 会改变整个页面相对 URL 的解析基础，因此使用后可能同时影响图片、链接、CSS 等多个资源路径。在实际项目中如果不了解其影响范围，容易造成大量路径异常。

### `<progress>` 进度条标签

`<progress>` 用于表示一个**任务的完成进度**，例如文件上传进度、文件下载进度或某项任务的处理进度。

基本形式为：

```html
<progress value="50" max="100"></progress>
```

其中：

| 属性    | 作用               |
| ------- | ------------------ |
| `value` | 当前已经完成的进度 |
| `max`   | 总进度，即最大值   |

`max` 必须是大于 `0` 的有效数字，如果省略，默认值为 `1`；`value` 必须位于 `0` 到 `max` 之间。

`value` **并不是必填属性**，是否提供 `value` 决定了进度条属于确定型还是不确定型。

#### 确定型进度条

当任务的完成程度已经明确时，同时设置 `value` 和 `max`：

```html
<progress value="60" max="100"></progress>
```

表示任务已经完成 `60%`。

#### 不确定型进度条

如果只知道任务正在执行，但不知道已经完成多少，可以省略 `value`：

```html
<progress max="100"></progress>
```

此时进度条处于**不确定状态（Indeterminate）**，浏览器通常会显示持续运动的进度效果。附件中的代码同时演示了确定型和不确定型两种形式。

> 注意：`<progress>` 表示的是**任务完成进度**。如果只是表示某个静态数值处于一个范围中的位置，例如磁盘使用率、考试成绩等，并不一定适合使用 `<progress>`。

---

### HTML、CSS 与 JavaScript 的职责分离

学习这些基础标签时，可以看到早期 HTML 中存在大量直接控制样式的属性，例如 `align`、`color`、`bgcolor`、`size` 等，甚至还有使用 `<font>` 设置字体颜色的旧式写法。附件中的进度条示例也保留了 `<font color="red">` 这样的代码。

现代 Web 开发更加重视**结构、样式和行为分离**：

- **HTML** 负责页面的结构和语义，例如页面中有哪些标题、段落、图片、列表和链接。
- **CSS** 负责页面的表现和布局，例如颜色、大小、间距、位置以及动画效果。
- **JavaScript** 负责页面的行为和交互，并可以通过 DOM 动态读取、创建、修改或删除页面元素，也可以动态修改元素的样式和状态。

例如，不推荐：

```html
<p align="center">
    <font color="red">操作失败</font>
</p>
```

更推荐使用 HTML 表达结构：

```html
<p class="error-message">操作失败</p>
```

再通过 CSS 设置样式：

```css
.error-message {
    color: red;
    text-align: center;
}
```

这样修改页面样式时通常只需要调整 CSS，而不必在大量 HTML 标签中逐个修改表现属性，使页面结构更加清晰，也更便于维护。

> 结论：现代 Web 开发应遵循 **HTML 负责结构与语义、CSS 负责样式与布局、JavaScript 负责行为与交互** 的基本职责划分。这里不宜将 JavaScript 简单描述为“对结果或样式进行 CRUD”；CRUD 更常用于描述数据的创建、读取、更新和删除，而 JavaScript 在前端承担的职责更加广泛。

### 音频与视频标签

HTML 提供了 `<audio>` 和 `<video>` 两个原生多媒体标签，分别用于在网页中嵌入**音频**和**视频**。浏览器可以直接提供播放、暂停、音量、进度等基本媒体控制能力，不需要依赖早期的 Flash 等外部插件。

#### `<audio>` 音频标签

`<audio>` 用于在网页中嵌入音频资源，例如 MP3、OGG 等格式的音频文件。

最基本的写法为：

```html
<audio src="music.mp3" controls>
    您的浏览器不支持音频播放。
</audio>
```

其中，`<audio>` 与 `</audio>` 之间的文本属于**后备内容**。当浏览器无法支持 `<audio>` 元素时，可以向用户显示相应提示。

常用属性如下：

| 属性       | 作用                                       |
| ---------- | ------------------------------------------ |
| `src`      | 指定音频文件的 URL                         |
| `controls` | 显示浏览器提供的播放、暂停、音量等控制界面 |
| `autoplay` | 音频资源可播放后尝试自动播放               |
| `loop`     | 播放结束后自动重新播放                     |
| `muted`    | 初始状态设置为静音                         |
| `preload`  | 提示浏览器页面加载时应如何预加载音频       |

`controls`、`autoplay`、`loop` 和 `muted` 都属于**布尔属性**。只要属性存在就表示启用，因此通常直接写成 `controls`、`loop`，无需写成 `controls="true"`。

例如：

```html
<audio src="music.mp3" controls loop></audio>
```

##### `preload` 属性

`preload` 用于向浏览器提供音频资源预加载策略的建议，常见值如下：

| 值         | 作用                             |
| ---------- | -------------------------------- |
| `none`     | 页面加载时尽量不预加载音频       |
| `metadata` | 只预加载时长、媒体信息等元数据   |
| `auto`     | 浏览器可以根据情况预加载整个音频 |

例如：

```html
<audio src="music.mp3" controls preload="metadata"></audio>
```

`preload` 只是一种**提示（hint）**，浏览器可以根据网络环境、用户设置等实际情况决定是否采用该策略。如果同时使用 `autoplay`，浏览器通常需要加载足够的媒体数据才能播放，因此 `preload` 的实际意义会降低。

##### 使用 `<source>` 提供多个音频源

除了直接通过 `src` 指定一个音频文件，还可以在 `<audio>` 中使用多个 `<source>`，为浏览器提供不同格式的媒体资源：

```html
<audio controls>
    <source src="music.mp3" type="audio/mpeg">
    <source src="music.ogg" type="audio/ogg">
    您的浏览器不支持音频播放。
</audio>
```

浏览器会按照 `<source>` 的书写顺序依次判断资源是否能够使用，并选择合适的音频源。

其中，`src` 指定资源地址，`type` 声明资源的 MIME 类型。提供 `type` 后，浏览器可以提前判断自己是否支持这种媒体类型，而无需先下载文件再进行判断。

因此，音频资源通常可以采用两种写法：**简单场景直接使用 `<audio src="...">`，需要提供多个候选资源时使用多个 `<source>`。**

---

#### `<video>` 视频标签

`<video>` 用于在网页中嵌入视频资源，例如 MP4、WebM 等格式的视频文件。

例如：

```html
<video src="video.mp4" controls width="600">
    您的浏览器不支持视频播放。
</video>
```

`<video>` 与 `<audio>` 的很多属性相同，包括 `src`、`controls`、`autoplay`、`loop`、`muted` 和 `preload`，同时还具有与视频画面相关的 `poster`、`width`、`height` 等属性。

| 属性       | 作用                             |
| ---------- | -------------------------------- |
| `src`      | 指定视频资源的 URL               |
| `controls` | 显示视频播放控制界面             |
| `autoplay` | 视频资源可播放后尝试自动播放     |
| `loop`     | 播放结束后循环播放               |
| `muted`    | 初始状态静音                     |
| `poster`   | 指定视频开始播放前显示的封面图片 |
| `width`    | 指定视频显示区域的宽度           |
| `height`   | 指定视频显示区域的高度           |
| `preload`  | 提示浏览器采用何种预加载策略     |

例如：

```html
<video
    src="video.mp4"
    controls
    width="600"
    poster="cover.jpg"
></video>
```

`poster="cover.jpg"` 表示在视频尚未开始播放时显示 `cover.jpg` 作为封面。

HTML 中 `width`、`height` 属性填写的是**不带单位的数值**，例如 `width="600"`，不要写成 `width="600px"`。如果需要百分比、自适应布局等复杂尺寸控制，应通过 CSS 设置。

##### 使用 `<source>` 提供多个视频源

与 `<audio>` 相同，`<video>` 也可以通过多个 `<source>` 提供不同格式的视频：

```html
<video controls width="600" poster="cover.jpg">
    <source src="video.mp4" type="video/mp4">
    <source src="video.webm" type="video/webm">
    您的浏览器不支持视频播放。
</video>
```

浏览器会按照顺序选择自身能够播放的资源。

##### 自动播放限制

虽然 `<audio>` 和 `<video>` 都提供 `autoplay` 属性，但**是否真正能够自动播放由浏览器的自动播放策略决定**。

现代浏览器通常会限制带声音的媒体自动播放，以避免网页打开后突然播放声音。因此，视频自动播放经常需要同时设置 `autoplay` 和 `muted`：

```html
<video src="video.mp4" autoplay muted loop></video>
```

这表示视频尝试自动播放、初始静音，并在播放结束后循环。

> 注意：即使设置了 `autoplay`，也不能保证所有浏览器和所有场景下一定自动播放。是否允许播放还可能受到用户交互、浏览器设置和设备策略等因素影响。

> 结论：`<audio>` 和 `<video>` 分别负责嵌入音频和视频；简单场景可以直接使用 `src`，需要兼容多个候选媒体资源时可以使用 `<source>`。媒体播放行为由 HTML 属性与浏览器自身策略共同决定。

## HTML 实体字符

HTML 中的某些字符具有特殊语法含义，或者难以直接通过键盘输入。此时可以使用**字符引用（Character Reference）**来表示这些字符，学习中也经常称为 **HTML 实体字符（HTML Entities）**。

例如，希望网页直接显示 `<h1>` 这几个字符时，不能简单把它当作普通文字书写，否则浏览器可能把它识别成 HTML 标签。可以写成：

```html
&lt;h1&gt;
```

浏览器最终显示：

`<h1>`

你上传的示例中同样使用 `&lt;`、`&gt;` 表示标签字符，并演示了 `&copy;`、`&reg;`、`&yen;`、`&nbsp;`、`&times;` 和 `&rarr;` 等字符引用。

### 实体字符的基本格式

常见的命名字符引用通常采用：

`&实体名称;`

即以 `&` 开头，以 `;` 结束，例如 `&lt;`、`&copy;`、`&nbsp;`。

HTML 还支持使用字符对应的 Unicode 码点进行**数字字符引用**，例如 `&#60;` 同样可以表示 `<`。基础阶段重点掌握常见的命名形式即可。

### HTML 中具有特殊意义的字符

以下字符在 HTML 语法中具有特殊意义，因此在特定场景下需要使用字符引用：

| 字符 | 字符引用 | 说明   |
| ---- | -------- | ------ |
| `<`  | `&lt;`   | 小于号 |
| `>`  | `&gt;`   | 大于号 |
| `&`  | `&amp;`  | 和号   |
| `"`  | `&quot;` | 双引号 |
| `'`  | `&apos;` | 单引号 |

其中，**`<` 和 `&` 是最需要注意的两个字符**。`<` 可能被浏览器识别为标签开始，`&` 可能被识别为字符引用开始，因此在需要将它们作为普通文字显示时通常应进行转义。

例如，要在网页中展示 Java 条件：

```html
<p>判断条件：age &lt; 18</p>
```

浏览器显示为 `判断条件：age < 18`。

`>` 通常没有 `<` 那么容易产生语法冲突，并不是所有情况下都必须写成 `&gt;`；双引号和单引号是否需要转义，也与它们是否处于属性值等特定上下文有关。因此，不宜简单记成“表格中的五个字符在 HTML 中任何地方都必须转义”。

例如：

```html
<p>10 > 5</p>
```

这种正文写法本身通常没有问题。

但如果属性值使用双引号包围，而属性值本身又需要包含双引号，就可以使用 `&quot;`。

### 常用符号

一些不方便直接输入的符号也可以使用 HTML 字符引用：

| 字符 | 字符引用   | 说明                       |
| ---- | ---------- | -------------------------- |
| ©    | `&copy;`   | 版权符号                   |
| ®    | `&reg;`    | 注册商标                   |
| ™    | `&trade;`  | 商标符号                   |
| €    | `&euro;`   | 欧元符号                   |
| £    | `&pound;`  | 英镑符号                   |
| ¥    | `&yen;`    | 日元或人民币使用的货币符号 |
| §    | `&sect;`   | 章节符号                   |
| ¶    | `&para;`   | 段落符号                   |
| •    | `&bull;`   | 项目符号                   |
| …    | `&hellip;` | 省略号                     |
| —    | `&mdash;`  | 长破折号                   |
| –    | `&ndash;`  | 短破折号                   |

例如：

```html
<footer>&copy; 2026 示例公司</footer>
```

浏览器显示为 `© 2026 示例公司`。

### 空白字符

HTML 在普通文本中会对连续的**可折叠空白字符**进行合并。也就是说，在 HTML 源代码中连续输入多个普通空格，浏览器通常仍然只显示为一个空格。

例如：

```html
<p>Java          HTML          CSS</p>
```

页面中并不会按照源代码中的大量空格显示。

如果确实需要插入特殊空白，可以使用相应的字符引用：

| 字符引用 | 含义                             |
| -------- | -------------------------------- |
| `&nbsp;` | 不换行空格（Non-Breaking Space） |
| `&ensp;` | En Space                         |
| `&emsp;` | Em Space                         |

其中，`&nbsp;` 最常见。它除了能够产生空格之外，还具有**不允许浏览器在该位置自动换行**的特点。

例如：

```html
<p>100&nbsp;km</p>
```

`100` 和 `km` 之间使用不换行空格后，浏览器会尽量避免在二者之间换行。

`&ensp;` 和 `&emsp;` 是具有特定排版宽度的空格，不能简单理解成严格意义上的“半角空格”和“全角空格”。

> 注意：不要为了页面缩进、元素间距而连续使用大量 `&nbsp;`、`&emsp;`。现代 Web 页面中的间距和布局应主要通过 CSS 的 `margin`、`padding`、布局系统等方式控制。HTML 实体字符用于表达**字符本身**，不应替代 CSS 布局。

---

### 数学符号

常见数学符号可以写成：

| 字符 | 字符引用   | 说明     |
| ---- | ---------- | -------- |
| ×    | `&times;`  | 乘号     |
| ÷    | `&divide;` | 除号     |
| ±    | `&plusmn;` | 加减号   |
| ≠    | `&ne;`     | 不等于   |
| ≤    | `&le;`     | 小于等于 |
| ≥    | `&ge;`     | 大于等于 |
| ∞    | `&infin;`  | 无穷大   |

例如：

```html
<p>10 &times; 20 = 200</p>
<p>x &ge; 0</p>
```

页面显示为 `10 × 20 = 200` 和 `x ≥ 0`。

### 箭头符号

常见箭头字符引用如下：

| 字符 | 字符引用 |
| ---- | -------- |
| ←    | `&larr;` |
| →    | `&rarr;` |
| ↑    | `&uarr;` |
| ↓    | `&darr;` |
| ↔    | `&harr;` |

例如：

```html
<p>首页 &rarr; 用户中心 &rarr; 订单详情</p>
```

最终显示为 `首页 → 用户中心 → 订单详情`。

> 结论：HTML 实体字符最重要的作用有两个：一是**安全地表示在 HTML 语法中具有特殊意义的字符**，例如使用 `&lt;` 显示 `<`；二是表示一些不方便直接输入的特殊字符。对于能够直接使用 UTF-8 正常书写的普通字符，没有必要为了使用实体而全部转换成实体形式。

## HTML 表格

HTML 表格用于表示具有**行、列关系的二维结构化数据**，例如学生信息、商品清单、销售报表等。一个基本表格主要由 `<table>`、`<tr>`、`<th>` 和 `<td>` 等元素组成。

> 注意：HTML 表格用于表示**表格型数据**，不应该像早期网页开发那样使用 `<table>` 进行整个页面的布局。页面布局应交给 CSS。

### 表格的基本结构

HTML 中创建表格主要涉及以下元素：

| 标签      | 英文含义          | 作用               |
| --------- | ----------------- | ------------------ |
| `<table>` | Table             | 定义整个表格       |
| `<tr>`    | Table Row         | 定义表格中的一行   |
| `<td>`    | Table Data Cell   | 定义普通数据单元格 |
| `<th>`    | Table Header Cell | 定义表头单元格     |

例如，一个三行三列的表格可以写成：

```html
<table>
    <tr>
        <td>姓名</td>
        <td>年龄</td>
        <td>城市</td>
    </tr>
    <tr>
        <td>张三</td>
        <td>20</td>
        <td>合肥</td>
    </tr>
    <tr>
        <td>李四</td>
        <td>22</td>
        <td>南京</td>
    </tr>
</table>
```

表格的结构可以理解为：

`<table>` → 整个表格  
`<tr>` → 表格中的一行  
`<td>` / `<th>` → 一行中的单元格

也就是说，**单元格通常放在 `<tr>` 中，而 `<tr>` 再放在 `<table>` 或表格的行分组元素中。**

#### `<th>` 表头单元格

如果某个单元格表示一行或一列的**标题**，应该使用 `<th>`，而不是普通的 `<td>`。

例如：

```html
<table>
    <tr>
        <th>姓名</th>
        <th>年龄</th>
        <th>城市</th>
    </tr>
    <tr>
        <td>张三</td>
        <td>20</td>
        <td>合肥</td>
    </tr>
</table>
```

浏览器默认通常会将 `<th>` 中的内容显示为**粗体并居中**，但这只是默认样式。`<th>` 真正重要的作用是表达“这个单元格是表头”，使表格结构更加清晰，也有利于辅助技术理解表格中标题与数据之间的关系。

对于较规范的表格，还可以使用 `scope` 说明表头对应的是行还是列：

```html
<table>
    <tr>
        <th scope="col">姓名</th>
        <th scope="col">年龄</th>
    </tr>
    <tr>
        <td>张三</td>
        <td>20</td>
    </tr>
</table>
```

`scope="col"` 表示该 `<th>` 是**列标题**，而 `scope="row"` 可以表示**行标题**。对于结构简单的入门表格，可以先重点掌握 `<th>` 与 `<td>` 的区别。

上传的表格示例中也是先通过 `<th>` 定义“序号、姓名、性别、城市、操作”等表头，再通过 `<td>` 保存具体数据。

---

### `<caption>` 表格标题

`<caption>` 用于为整个 `<table>` 提供一个**标题或简短说明**。

例如：

```html
<table>
    <caption>学生信息表</caption>
    <tr>
        <th>姓名</th>
        <th>年龄</th>
    </tr>
    <tr>
        <td>张三</td>
        <td>20</td>
    </tr>
</table>
```

浏览器默认通常会将 `<caption>` 显示在表格顶部，并居中显示。具体显示位置和样式仍然可以通过 CSS 修改。

`<caption>` 描述的是**整个表格的内容或用途**，而 `<th>` 描述的是具体行或列的标题，两者作用不同。

例如：

```html
<table>
    <caption>2026 年第一季度销售情况</caption>
    <tr>
        <th>月份</th>
        <th>销售额</th>
    </tr>
    ...
</table>
```

其中，“2026 年第一季度销售情况”描述整个表格，“月份”和“销售额”则分别描述各列的数据含义。

---

### 单元格合并

HTML 通过 `colspan` 和 `rowspan` 实现单元格跨越多列或多行：

- `colspan`：一个单元格**横跨多列**。
- `rowspan`：一个单元格**纵跨多行**。

二者的值表示当前单元格总共占据多少列或多少行。

#### `colspan` 列合并

例如，让“学生信息”横跨两列：

```html
<table>
    <tr>
        <th colspan="2">学生信息</th>
    </tr>
    <tr>
        <th>姓名</th>
        <th>年龄</th>
    </tr>
    <tr>
        <td>张三</td>
        <td>20</td>
    </tr>
</table>
```

`colspan="2"` 表示当前 `<th>` 占据原本两个单元格的位置。

因此，第一行只需要写一个 `<th>`，不能再额外补写第二个单元格，否则这一行最终占据的列数就会超过正常表格结构。

#### `rowspan` 行合并

例如：

```html
<table>
    <tr>
        <th>姓名</th>
        <td>张三</td>
        <td rowspan="2">学生基本信息</td>
    </tr>
    <tr>
        <th>年龄</th>
        <td>20</td>
    </tr>
</table>
```

`rowspan="2"` 表示“学生基本信息”这一单元格同时占据当前行和下一行的位置。

因此，第二行只需要写两个单元格，**不需要再为第三列创建新的 `<td>`**，因为这一位置已经被上一行的 `rowspan="2"` 占用。

上传的示例同时使用了 `rowspan="3"` 和 `colspan="2"`，并将被合并位置原本对应的单元格删除，这正是单元格合并时需要注意的结构变化。

> 易错点：`rowspan` 和 `colspan` 并不是“把多个已经存在的单元格合成一个”，而是**让当前这个单元格占据原本属于多个单元格的位置**。因此，被占据的位置不应该再重复编写 `<td>` 或 `<th>`。

---

### 表格的结构化分组

当表格内容比较完整或数据较多时，可以使用 `<thead>`、`<tbody>` 和 `<tfoot>` 将表格划分为**表头、主体和表尾**三个逻辑区域：

```html
<table>
    <thead>
        ...
    </thead>

    <tbody>
        ...
    </tbody>

    <tfoot>
        ...
    </tfoot>
</table>
```

这些元素本身主要负责**描述表格的结构和语义**，并不会自动给表格增加明显的视觉效果，但可以使 HTML 结构更加清晰，也便于通过 CSS 分别设置表头、主体和表尾的样式。

#### `<thead>`

`<thead>` 表示表格的**表头区域**，通常包含描述各列含义的 `<th>`：

```html
<thead>
    <tr>
        <th>商品</th>
        <th>价格</th>
    </tr>
</thead>
```

一个 `<table>` 最多只能有一个 `<thead>`。现代 HTML 的表格结构中，`<thead>` 应位于 `<tbody>` 和 `<tfoot>` 之前。

#### `<tbody>`

`<tbody>` 表示表格的**主体数据区域**：

```html
<tbody>
    <tr>
        <td>键盘</td>
        <td>299 元</td>
    </tr>
    <tr>
        <td>鼠标</td>
        <td>199 元</td>
    </tr>
</tbody>
```

一个表格可以拥有**多个 `<tbody>`**，因此还可以进一步将主体数据划分为多个逻辑分组。

对于简单表格，即使源代码中没有显式书写 `<tbody>`，浏览器解析 HTML 表格结构时也可能在 DOM 中生成相应的 `<tbody>`。实际开发中，如果表格本身具有明确的表头、主体和汇总区域，建议主动写出这些结构。

#### `<tfoot>`

`<tfoot>` 表示表格的**表尾或汇总区域**，通常用于显示总计、平均值等汇总信息：

```html
<tfoot>
    <tr>
        <th>总计</th>
        <td>498 元</td>
    </tr>
</tfoot>
```

一个 `<table>` 最多只能有一个 `<tfoot>`。

> 注意：早期 HTML 规范曾要求 `<tfoot>` 写在 `<tbody>` 之前，这也是一些旧教程仍然采用这种顺序的原因。**现代 HTML 已经改为 `<tfoot>` 位于 `<tbody>` 之后**，因此现在推荐按照 `<thead> → <tbody> → <tfoot>` 的自然阅读顺序书写。

上传的示例中将 `<thead>`、`<tfoot>`、`<tbody>` 分别定义，并通过 `id` 进行区分，体现了表格可以按照功能划分成不同区域。 但按照现代 HTML 的结构规则，更推荐调整为 `<thead>`、`<tbody>`、`<tfoot>` 的顺序。

#### 完整示例

```html
<table>
    <caption>2026 年销售报表</caption>

    <thead>
        <tr>
            <th scope="col">月份</th>
            <th scope="col">销售额</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>1 月</td>
            <td>10,000 元</td>
        </tr>
        <tr>
            <td>2 月</td>
            <td>15,000 元</td>
        </tr>
    </tbody>

    <tfoot>
        <tr>
            <th scope="row">总计</th>
            <td>25,000 元</td>
        </tr>
    </tfoot>
</table>
```

整个结构可以概括为：

`<table>` → 整个表格  
`<caption>` → 表格标题  
`<thead>` → 表头区域  
`<tbody>` → 主体数据区域  
`<tfoot>` → 表尾、汇总区域  
`<tr>` → 行  
`<th>` / `<td>` → 单元格

---

### 表格的旧式样式属性（了解）

早期 HTML 经常直接在 `<table>`、`<tr>`、`<td>` 等元素上使用属性控制表格样式，例如：

```html
<table
    border="1"
    width="600"
    align="center"
    cellpadding="10"
    cellspacing="0"
>
    ...
</table>
```

上传的示例同样使用了 `border`、`width`、`align`、`cellpadding` 和 `cellspacing` 等属性。

这些属性的传统含义如下：

| 属性          | 传统作用                       | 现代替代方式                  |
| ------------- | ------------------------------ | ----------------------------- |
| `border`      | 设置表格边框                   | CSS `border`                  |
| `cellpadding` | 设置单元格内容与边框之间的间距 | CSS `padding`                 |
| `cellspacing` | 设置相邻单元格之间的间距       | CSS `border-spacing`          |
| `width`       | 设置表格宽度                   | CSS `width`                   |
| `align`       | 设置表格或单元格的对齐方式     | CSS `margin`、`text-align` 等 |

这些表现属性现在已经被废弃或不推荐继续使用，新代码应该通过 CSS 设置表格外观。

例如，早期可能写成：

```html
<table border="1" cellspacing="0" cellpadding="10" width="600">
    ...
</table>
```

现代开发更推荐：

```html
<table class="student-table">
    ...
</table>
```

```css
.student-table {
    width: 600px;
    border-collapse: collapse;
}

.student-table th,
.student-table td {
    border: 1px solid #000;
    padding: 10px;
}
```

其中，`border-collapse: collapse;` 会将相邻单元格的边框合并成一条边框，这才是现代 CSS 中解决表格“双线边框”问题的常见方式。

因此，不能简单记成“`cellspacing="0"` 会把双线边框变成单线边框”。它只是旧式地将单元格之间的间距设置为 `0`；现代开发应使用 CSS 的 `border-collapse` 明确控制边框合并方式。

如果需要让单元格内容居中，也不再使用：

```html
<td align="center">张三</td>
```

而应通过 CSS：

```css
.student-table th,
.student-table td {
    text-align: center;
}
```

> 结论：HTML 表格重点学习的是**数据结构和语义**，即 `<table>`、`<tr>`、`<th>`、`<td>`、`<caption>`、`rowspan`、`colspan`、`<thead>`、`<tbody>`、`<tfoot>`；边框、宽度、间距、颜色、对齐等视觉效果应交给 CSS。

## HTML 表单

**HTML 表单（Form）**用于收集用户输入的数据，并在用户提交表单时按照指定方式将数据发送到目标地址。登录、注册、搜索、资料填写、文件上传等功能都大量使用表单。

一个完整的表单通常可以从三个部分理解：

- **表单容器**：通过 `<form>` 定义表单整体，并决定数据提交到哪里、采用什么请求方式。
- **表单控件**：用于收集具体数据，例如文本框、密码框、单选框、复选框、下拉列表等。
- **表单按钮**：用于提交、重置表单，或者配合 JavaScript 执行其他操作。

---

### `<form>` 表单标签

`<form>` 用于定义一个 HTML 表单，所有需要随该表单一起提交的控件通常放在 `<form>` 内部。

```html
<form action="/user/login" method="post">
    <input type="text" name="username">
    <input type="password" name="password">
    <button type="submit">登录</button>
</form>
```

浏览器默认通常会将 `<form>` 按块状方式显示，但其核心作用并不是页面布局，而是**建立表单控件与表单提交行为之间的关系**。

#### `<form>` 的常用属性

| 属性      | 作用                                                     |
| --------- | -------------------------------------------------------- |
| `action`  | 指定表单提交的目标 URL                                   |
| `method`  | 指定提交表单使用的 HTTP 请求方法，主要为 `get` 或 `post` |
| `enctype` | 指定表单数据提交时采用的编码方式                         |
| `name`    | 为表单指定名称                                           |
| `id`      | 为表单元素指定唯一标识                                   |

##### `action`

`action` 用于指定**表单数据提交到哪个地址**。

例如：

```html
<form action="/user/save">
    ...
</form>
```

提交表单时，浏览器会向 `/user/save` 发起请求。

##### `method`

`method` 用于指定表单采用的 HTTP 请求方式，HTML 表单中最常用的是 `get` 和 `post`。如果省略 `method`，默认采用 `get`。

```html
<form action="/user/query" method="get">
    ...
</form>
```

```html
<form action="/user/save" method="post">
    ...
</form>
```

两者最直观的区别是：

- **GET**：表单数据通常被编码到 URL 的查询字符串中，因此可以直接出现在浏览器地址栏。
- **POST**：表单数据通常放在 HTTP 请求体中，不会因为普通表单提交而直接显示在地址栏中。

例如，表单中存在：

```html
<input type="text" name="username" value="zhangsan">
<input type="text" name="age" value="20">
```

使用 GET 提交后，URL 可能类似：

`/user/query?username=zhangsan&age=20`

使用 POST 提交时，这些数据通常位于请求体中。

> 易错点：不能记成“GET 数据在请求头中”。GET 表单的数据通常位于 **URL 的查询字符串（Query String）**中；POST 表单数据通常位于请求体中。

GET 与 POST 也不能简单理解为“GET 不安全、POST 安全”。POST 只是不会直接把普通表单数据显示在 URL 中，真正的网络传输安全需要依赖 HTTPS 等机制。

##### `enctype`

`enctype` 用于指定**表单数据在提交时采用的编码方式**，主要与 `method="post"` 配合使用。

常见值如下：

| `enctype`                           | 主要用途                                     |
| ----------------------------------- | -------------------------------------------- |
| `application/x-www-form-urlencoded` | 普通表单提交的默认编码方式                   |
| `multipart/form-data`               | 包含文件上传的表单                           |
| `text/plain`                        | 以较简单的纯文本形式编码，实际业务中很少使用 |

如果没有指定，默认使用：

`application/x-www-form-urlencoded`

这种方式会将普通表单字段编码成类似：

`username=zhangsan&age=20`

附件中的示例也明确展示了默认的 `application/x-www-form-urlencoded`，以及文件上传时使用的 `multipart/form-data`。

如果表单需要上传文件，应使用：

```html
<form
    action="/user/upload"
    method="post"
    enctype="multipart/form-data"
>
    <input type="file" name="photo">
    <button type="submit">上传</button>
</form>
```

> 注意：`name=value&name=value...` 是 URL 查询字符串以及 `application/x-www-form-urlencoded` 编码下常见的表现形式。使用 `multipart/form-data` 上传文件时，请求体采用的是另一种多部分编码结构，因此不能认为所有表单提交的数据格式永远都是 `name=value&...`。

---

### 表单数据如何提交

表单控件要参与正常的表单提交，**通常必须具有 `name` 属性**。

例如：

```html
<form action="/user/save" method="get">
    <input type="text" name="username" value="zhangsan">
    <input type="text" name="age" value="20">
    <button type="submit">提交</button>
</form>
```

提交后的数据可以形成：

`username=zhangsan&age=20`

其中：

- `name="username"` 决定参数名 `username`。
- 用户填写的内容或控件当前值决定参数值。
- 最终形成类似 `username=zhangsan` 的键值关系。

如果写成：

```html
<input type="text" value="zhangsan">
```

由于没有 `name`，该控件的值通常不会作为正常表单字段提交。

因此，可以将表单数据理解为：

`表单控件 → name + 当前值 → 表单编码 → HTTP 请求`

附件中的完整表单示例也通过 `username`、`pwd`、`gender`、`hobby`、`grade` 等 `name` 组织提交参数。

> 注意：`id` 和 `name` 的作用不同。`id` 是元素在当前文档中的标识，可供 `<label>`、CSS、JavaScript 等使用；`name` 则直接关系到表单提交时的**参数名称**。

到目前为止，浏览器访问服务器资源可以简单归纳为三种常见操作：

1. 在地址栏中输入 HTTP/HTTPS URL 并访问，通常产生 GET 请求。
2. 点击普通 HTTP/HTTPS 超链接，通常产生 GET 请求。
3. 提交表单，根据 `<form method>` 可以产生 GET 或 POST 请求。

---

### `<input>` 表单控件

`<input>` 是 HTML 表单中最常见的元素之一，其具体作用主要由 `type` 属性决定。

例如：

`type="text"` 表示文本框，`type="password"` 表示密码框，`type="radio"` 表示单选按钮。

常用属性包括 `type`、`name`、`value`、`id`、`checked`、`readonly`、`disabled` 等。

#### `type="text"`

`type="text"` 表示**单行文本输入框**：

```html
<input
    type="text"
    name="username"
    maxlength="20"
>
```

用户在输入框中填写的文字就是控件当前的 `value`。

也可以提前设置初始值：

```html
<input
    type="text"
    name="username"
    value="zhangsan"
>
```

`maxlength` 用于限制用户最多能够输入多少个字符：

```html
<input type="text" name="username" maxlength="10">
```

#### `type="password"`

`type="password"` 表示**密码输入框**：

```html
<input type="password" name="password">
```

用户输入的字符通常不会直接以明文显示，而会由浏览器使用圆点等形式遮挡。

但这只是**界面上的隐藏效果**，并不意味着密码已经被加密。真正的数据传输安全仍需要 HTTPS 等机制保证。

#### `type="radio"`

`type="radio"` 表示**单选按钮**。

需要互斥选择的一组单选按钮必须使用相同的 `name`：

```html
<input type="radio" name="gender" value="male"> 男
<input type="radio" name="gender" value="female"> 女
```

如果选择“男”，提交的数据通常为：

`gender=male`

因此，单选按钮的 `value` 一般需要开发者明确指定，否则服务器很难通过提交值判断用户选择了哪个选项。

使用 `checked` 可以设置默认选中：

```html
<input type="radio" name="gender" value="male" checked> 男
<input type="radio" name="gender" value="female"> 女
```

`checked` 属于布尔属性，只要属性存在就表示选中，不需要写成 `checked="true"`。

#### `type="checkbox"`

`type="checkbox"` 表示**复选框**，允许用户同时选择多个选项。

例如：

```html
<input type="checkbox" name="hobby" value="swim"> 游泳
<input type="checkbox" name="hobby" value="music"> 音乐
<input type="checkbox" name="hobby" value="reading"> 阅读
```

如果用户同时选择“游泳”和“音乐”，采用普通表单编码时可能得到：

`hobby=swim&hobby=music`

同一类复选框通常使用相同的 `name`，这样服务器可以将多个值理解为同一个字段的多个选项。

不过与单选按钮不同，**复选框是否能够同时选中并不是由 `name` 决定的**。checkbox 本身就可以独立选中；使用相同 `name` 主要是为了将多个相关选项作为同一组数据提交。

同样可以使用 `checked` 设置默认选中项。

#### `type="file"`

`type="file"` 用于让用户选择需要上传的文件：

```html
<input type="file" name="photo">
```

需要进行正常文件上传时，表单通常应设置：

```html
<form
    action="/upload"
    method="post"
    enctype="multipart/form-data"
>
    <input type="file" name="photo">
    <button type="submit">上传</button>
</form>
```

使用 `multiple` 可以允许用户一次选择多个文件：

```html
<input type="file" name="photos" multiple>
```

`multiple` 同样是布尔属性。

#### `type="hidden"`

`type="hidden"` 表示**隐藏表单域**。它不会作为普通控件显示在页面上，但其 `name` 和 `value` 可以随表单一起提交。

```html
<input type="hidden" name="userId" value="10001">
```

例如，页面中不需要让用户手动修改某条记录的 ID，但提交修改表单时服务器又必须知道是哪条记录，就可以使用隐藏域携带该值。

附件中的示例就是通过隐藏域提交 `code=123`。

> 注意：`hidden` 只是**界面上不可见**，绝不是安全机制。用户仍然可以通过浏览器开发者工具查看和修改隐藏域，因此不能把密码、可信权限值等敏感数据仅依赖隐藏域保护。

---

### `<select>` 下拉列表

`<select>` 用于创建选择列表，每一个候选项通过 `<option>` 定义：

```html
<select name="fruit">
    <option value="apple">苹果</option>
    <option value="banana">香蕉</option>
    <option value="orange">橙子</option>
</select>
```

如果用户选择“香蕉”，提交的数据通常为：

`fruit=banana`

其中，用户看到的是 `<option>` 标签中的文字，而服务器收到的通常是 `value`。

使用 `selected` 可以设置默认选中项：

```html
<option value="banana" selected>香蕉</option>
```

`size` 可以指定选择控件同时显示多少个选项：

```html
<select name="city" size="3">
    ...
</select>
```

使用 `multiple` 可以允许选择多个选项：

```html
<select name="city" multiple>
    <option value="hefei">合肥</option>
    <option value="nanjing">南京</option>
    <option value="shanghai">上海</option>
</select>
```

桌面环境下，用户通常可以配合 `Ctrl`、`Shift` 等方式进行多选，具体操作可能因系统和浏览器而不同。

附件中的示例同时使用了 `multiple`、`size` 和 `selected`。

---

### `<textarea>` 多行文本域

`<textarea>` 用于输入**多行文本**，适合个人简介、评论、反馈等内容。

```html
<textarea
    name="intro"
    cols="50"
    rows="10"
></textarea>
```

其中，`cols` 表示文本区域的可见宽度参考，`rows` 表示默认可见行数。

现代页面通常会使用 CSS 更精确地控制文本域尺寸。

`<textarea>` 与普通 `<input>` 有一个重要区别：其 HTML 初始值不是通过 `value` 属性设置，而是写在开始标签与结束标签之间。

例如：

```html
<textarea name="intro">默认内容</textarea>
```

其中“默认内容”会成为文本域的初始内容。

因此，如果希望文本域初始为空，就不要随意在标签内部添加文字或无意义空白。

附件中的代码也特别强调了这一点。

---

### 表单按钮

HTML 表单中常见的按钮包括提交按钮、重置按钮和普通按钮。

#### `type="submit"`

`type="submit"` 表示**提交表单**：

```html
<input type="submit" value="提交">
```

也可以使用：

```html
<button type="submit">提交</button>
```

用户点击后，浏览器会按照 `<form>` 的 `action`、`method`、`enctype` 等配置提交表单。

#### `type="reset"`

`type="reset"` 用于将当前表单控件恢复为页面初始状态：

```html
<input type="reset" value="重置">
```

或者：

```html
<button type="reset">重置</button>
```

需要注意，重置并不等价于“全部清空”，而是恢复到 HTML 中定义的**初始值或初始选中状态**。

#### `type="button"`

`type="button"` 表示普通按钮：

```html
<input type="button" value="获取验证码">
```

或者：

```html
<button type="button">获取验证码</button>
```

普通按钮自身不会提交表单，通常需要 JavaScript 为它绑定具体行为。

#### `<button>`

现代开发中经常使用 `<button>` 创建按钮，因为它可以包含文字以及其他 HTML 内容，样式控制也更加灵活。

常见写法为：

```html
<button type="submit">提交</button>
<button type="reset">重置</button>
<button type="button">普通按钮</button>
```

如果 `<button>` 位于表单中且没有显式设置 `type`，默认通常相当于：

```html
<button type="submit">提交</button>
```

附件中的表单代码也演示了 `<button>`、`input type="submit"` 与普通 `input type="button"` 的差异。

> 易错点：在表单中如果一个按钮只是用于执行 JavaScript，而不是提交表单，应明确写成 `type="button"`，否则省略 `type` 后可能意外触发表单提交。

#### `type="image"`（了解）

`<input type="image">` 可以使用图片作为提交按钮：

```html
<input
    type="image"
    src="submit.png"
    alt="提交"
>
```

点击后同样可以提交表单。现代开发通常更倾向于使用 `<button>` 配合 CSS 实现按钮样式，因此这种方式已经较少作为普通按钮使用。

### `readonly` 与 `disabled`

`readonly` 和 `disabled` 都可能使用户无法直接修改控件，但二者的行为存在重要区别。

| 属性       | 用户能否修改 | 是否参与正常表单提交 |
| ---------- | ------------ | -------------------- |
| `readonly` | 否           | **会**               |
| `disabled` | 否           | **不会**             |

例如：

```html
<input
    type="text"
    name="username"
    value="zhangsan"
    readonly
>
```

虽然用户无法修改，但提交表单时仍然会提交：

`username=zhangsan`

而：

```html
<input
    type="text"
    name="username"
    value="zhangsan"
    disabled
>
```

该控件不会作为正常表单字段提交。

附件中的示例正好演示了 `readonly` 会提交而 `disabled` 不提交的区别。

另外，`readonly` 并不是所有表单控件都支持，它主要适用于文本类输入控件和 `<textarea>`；`disabled` 则可以用于更多表单控件。

> 结论：如果只是希望用户不能修改，但服务器仍需要接收该字段，可以考虑 `readonly`；如果希望控件完全处于禁用状态并且不参与提交，则使用 `disabled`。

### `<label>` 标签

`<label>` 用于为表单控件提供**文字标签**，并建立文字与具体表单控件之间的关联。

例如，与其只写：

```html
用户名：
<input type="text" name="username">
```

更推荐：

```html
<label for="username">用户名：</label>
<input
    type="text"
    id="username"
    name="username"
>
```

这样“用户名”文字与输入框就建立了明确关联。

`<label>` 的主要价值包括：

- 让用户更加清楚控件的用途。
- 点击标签文字时可以激活或聚焦对应控件。
- 扩大单选框、复选框等小型控件的可点击区域。
- 改善屏幕阅读器等辅助技术对表单的理解。

HTML 提供两种常见关联方式。

#### 隐式关联

直接使用 `<label>` 包裹控件：

```html
<label>
    用户名：
    <input type="text" name="username">
</label>
```

#### 显式关联

通过 `<label for>` 与控件的 `id` 建立关联：

```html
<label for="user-password">密码：</label>

<input
    type="password"
    id="user-password"
    name="password"
>
```

其中：

`for="user-password"` ↔ `id="user-password"`

两者值必须对应。

附件中同时展示了隐式关联和 `for + id` 显式关联两种方式。

对于单选框和复选框，`<label>` 尤其有价值：

```html
<label>
    <input type="checkbox" name="agree">
    我已阅读并同意用户协议
</label>
```

此时用户既可以点击小复选框，也可以直接点击“我已阅读并同意用户协议”这段文字完成选择。

还可以利用 `<label for>` 激活文件选择控件，例如：

```html
<label for="avatar">选择头像</label>
<input type="file" id="avatar" name="avatar">
```

后续配合 CSS 可以进一步定制界面样式。

### `placeholder` 属性

`placeholder` 用于在输入控件**当前值为空时显示提示文字**，帮助用户理解应该输入什么内容。

例如：

```html
<input
    type="text"
    name="username"
    placeholder="请输入用户名"
>
```

或者：

```html
<textarea
    name="feedback"
    placeholder="请输入您的意见或建议"
></textarea>
```

当用户开始输入实际内容后，placeholder 通常会自动消失；用户再次将输入内容清空后，提示文字重新显示。

`placeholder` 适合提供简短的输入提示，例如格式要求：

```html
<input
    type="text"
    name="phone"
    placeholder="请输入 11 位手机号码"
>
```

> 注意：`placeholder` **不能代替 `<label>`**。placeholder 在用户输入内容后会消失，而且辅助技术对它的处理方式与真正的标签不同。因此，一个规范表单通常仍应使用 `<label>` 说明字段名称，再使用 `placeholder` 提供额外的格式提示。

### 表单提交的整体流程

一个普通表单从用户填写到服务器接收数据，可以概括为：

1. 用户在 `<input>`、`<select>`、`<textarea>` 等控件中填写或选择内容。
2. 浏览器根据控件的 `name` 和当前值确定需要提交的数据。
3. 用户点击提交按钮。
4. 浏览器读取 `<form>` 的 `action`、`method` 和 `enctype`。
5. 浏览器按照指定编码方式组织表单数据。
6. 浏览器向 `action` 指定的 URL 发送 HTTP 请求。
7. 服务器接收请求，并根据参数名称读取用户提交的数据。

例如：

```html
<form action="/login" method="post">
    <label for="username">用户名：</label>
    <input
        type="text"
        id="username"
        name="username"
    >

    <label for="password">密码：</label>
    <input
        type="password"
        id="password"
        name="password"
    >

    <button type="submit">登录</button>
</form>
```

假设用户填写用户名 `zhangsan`、密码 `123456`，可以将核心关系理解为：

`username → zhangsan`  
`password → 123456`

浏览器将这些表单字段按照 `<form>` 的配置编码并发送给 `/login`，服务器随后便可以通过字段名称 `username` 和 `password` 获取用户提交的数据。

> 结论：理解 HTML 表单的关键不是记住所有标签，而是掌握一条主线：**`<form>` 决定“往哪里、怎么提交”，表单控件负责“收集什么数据”，`name` 决定“参数叫什么”，控件当前值决定“参数值是什么”，提交按钮最终触发表单提交。**
