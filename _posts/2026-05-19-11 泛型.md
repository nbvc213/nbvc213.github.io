## 泛型

泛型（Generics）是 JDK 1.5 引入的重要特性，本质是**参数化类型**。它允许在定义类、接口或方法时，把具体的数据类型先作为“参数”保留下来，等到使用时再传入实际类型。

泛型最常见的使用场景是集合。使用泛型后，集合可以明确限制元素类型，编译器能够在编译阶段检查类型是否正确，从而减少强制类型转换，并降低运行时出现 `ClassCastException` 的风险。

```java
ArrayList<String> list = new ArrayList<>();
```

这行代码表示创建一个只能存储 `String` 类型元素的集合。此时，集合中添加元素和获取元素都会受到 `String` 类型约束。

> 结论：泛型的核心作用是把类型检查从运行阶段提前到编译阶段，让代码更加安全、清晰、简洁。

### 泛型的引入

在没有泛型之前，如果希望一个容器可以保存任意类型的数据，通常会使用 `Object` 类型。因为 `Object` 是所有类的父类，所以任意引用类型对象都可以向上转型为 `Object` 存入集合。

例如，可以用 `Object[]` 模拟一个简单集合：

```java
public class MyArrayList {
    private Object[] elementData;
    private int size;

    public MyArrayList() {
        this.elementData = new Object[10];
    }

    public void add(Object element) {
        if (size == elementData.length) {
            throw new RuntimeException("集合已满");
        }
        elementData[size++] = element;
    }

    public Object get(int index) {
        if (index < 0 || index >= size) {
            throw new IndexOutOfBoundsException("数组下标越界");
        }
        return elementData[index];
    }

    public int size() {
        return size;
    }
}
```

这种写法可以存储任意对象：

```java
MyArrayList list = new MyArrayList();

list.add("jack");
list.add("lucy");
list.add("tom");
list.add(100);
```

表面上看，使用 `Object` 提高了集合的灵活性；但问题在于，元素取出时只能得到 `Object` 类型。如果需要使用字符串特有的方法，就必须进行向下转型：

```java
for (int i = 0; i < list.size(); i++) {
    String name = (String) list.get(i);
    System.out.println(name.charAt(0));
}
```

如果集合中混入了非 `String` 类型的元素，例如 `Integer`，程序在编译阶段不会报错，但运行到强制类型转换时会抛出 `ClassCastException`。

```text
java.lang.ClassCastException
```

这种问题的本质在于：**编译器只知道集合中存的是 Object，不知道开发者期望取出的具体类型**。因此，错误只能在运行时暴露。

> 易错点：使用 `Object` 可以存储任意类型，但取出数据时需要强制类型转换。只要集合中混入了不符合预期的类型，就可能在运行时发生 `ClassCastException`。

#### 使用泛型改造集合

泛型可以把集合中的元素类型作为参数传入，使集合在使用时明确保存哪一种类型的数据。

```java
public class MyArrayList<E> {
    private Object[] elementData;
    private int size;

    public MyArrayList() {
        this.elementData = new Object[10];
    }

    public void add(E element) {
        if (size == elementData.length) {
            throw new RuntimeException("集合已满");
        }
        elementData[size++] = element;
    }

    public E get(int index) {
        if (index < 0 || index >= size) {
            throw new IndexOutOfBoundsException("数组下标越界");
        }
        return (E) elementData[index];
    }

    public int size() {
        return size;
    }
}
```

其中，`<E>` 表示类型参数。`E` 不是固定类型，而是一个临时的类型变量。真正使用集合时，才为 `E` 指定具体类型。

```java
MyArrayList<String> list = new MyArrayList<>();

list.add("jack");
list.add("lucy");
list.add("tom");

// list.add(100); // 编译错误

for (int i = 0; i < list.size(); i++) {
    String name = list.get(i);
    System.out.println(name.charAt(0));
}
```

当 `MyArrayList<String>` 创建完成后，`E` 就可以理解为被指定成了 `String`。此时：

1. `add(E element)` 相当于只能添加 `String`；
2. `get(int index)` 相当于返回 `String`；
3. 添加非 `String` 类型数据会在编译阶段报错；
4. 取出元素时不需要手动强制类型转换。

> 结论：泛型通过牺牲“任意类型都能存”的灵活性，换来了编译阶段的类型检查、代码简化和更高的安全性。

### 泛型的好处

泛型主要有两个好处：**提高类型安全性** 和 **减少强制类型转换**。

#### 提高类型安全性

使用泛型后，集合能保存什么类型，在创建集合时就已经确定。

```java
MyArrayList<String> names = new MyArrayList<>();

names.add("jack");
names.add("lucy");

// names.add(123); // 编译错误
```

如果试图向 `MyArrayList<String>` 中添加 `Integer`，编译器会直接报错。这样可以把原本可能在运行时才出现的类型转换异常提前到编译阶段发现。

#### 减少强制类型转换

未使用泛型时，取出元素需要手动强转：

```java
String name = (String) list.get(0);
```

使用泛型后，编译器已经知道集合中元素的类型，取出时可以直接赋值：

```java
String name = names.get(0);
```

代码更简洁，可读性也更强。

> 注意：在正确使用泛型、没有混用原始类型和不安全强转的前提下，泛型可以有效避免集合取值时常见的 `ClassCastException`。

### 类型参数与类型实参

泛型中常见两个概念：**类型参数** 和 **类型实参**。

| 概念     | 示例                | 含义                                   |
| -------- | ------------------- | -------------------------------------- |
| 类型参数 | `E`、`T`            | 定义泛型类、接口或方法时声明的类型变量 |
| 类型实参 | `String`、`Integer` | 使用泛型时传入的具体类型               |

例如：

```java
public class Box<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}
```

这里的 `T` 是类型参数。使用时可以指定具体类型：

```java
Box<String> box = new Box<>();
box.setValue("hello");

String value = box.getValue();
System.out.println(value);
```

此时，`String` 是类型实参，可以理解为把 `T` 指定成了 `String`。

常见类型参数命名如下：

| 类型参数 | 常见含义                     |
| -------- | ---------------------------- |
| `E`      | Element，元素，常用于集合    |
| `T`      | Type，类型，常用于普通泛型类 |
| `K`      | Key，键                      |
| `V`      | Value，值                    |
| `N`      | Number，数字                 |

这些命名不是语法强制要求，但属于常见规范，有助于提高代码可读性。

### 钻石表达式

在 JDK 1.7 之后，创建泛型对象时可以使用钻石表达式 `<>`，让编译器根据左侧声明自动推断右侧类型。

完整写法：

```java
MyArrayList<String> list = new MyArrayList<String>();
```

简化写法：

```java
MyArrayList<String> list = new MyArrayList<>();
```

两种写法含义相同。由于左侧已经声明了 `String`，右侧的 `<>` 可以由编译器自动推断为 `String`。

> 结论：钻石表达式只是简化泛型对象创建语法，不改变泛型本身的含义。

### 泛型不能直接使用基本数据类型

泛型的类型实参必须是引用数据类型，不能直接使用基本数据类型。

错误写法：

```java
MyArrayList<int> list = new MyArrayList<>(); // 编译错误
```

如果需要保存整数，应使用基本数据类型对应的包装类：

```java
MyArrayList<Integer> list = new MyArrayList<>();

list.add(100);
list.add(200);

Integer value = list.get(0);
System.out.println(value);
```

这里的 `100` 是 `int` 类型字面量，但可以添加到 `MyArrayList<Integer>` 中，是因为 Java 会进行自动装箱，把 `int` 自动转换成 `Integer`。

> 易错点：泛型中不能写 `int`、`double`、`char` 等基本数据类型，应使用 `Integer`、`Double`、`Character` 等包装类。

### 泛型的工作原理

泛型主要在**编译阶段**发挥作用。它并不是让 JVM 在运行时真正保存一份完整的泛型类型信息，而是通过编译检查和泛型擦除机制实现类型安全。

#### 编译阶段：类型检查

编译器会根据泛型声明检查添加和获取的数据类型是否正确。

```java
MyArrayList<String> list = new MyArrayList<>();

list.add("hello");
// list.add(100); // 编译错误
```

由于 `list` 被声明为 `MyArrayList<String>`，编译器会要求 `add()` 方法只能接收 `String` 类型参数。如果传入 `Integer`，会在编译阶段直接报错。

这正是泛型最重要的价值：**把类型错误提前暴露**。

#### 编译后：泛型擦除

为了兼容 JDK 1.5 之前没有泛型的旧代码，Java 编译器会在编译后进行**泛型擦除**。所谓泛型擦除，就是在生成字节码时去掉泛型类型信息，将类型参数替换为原始类型，通常是 `Object`。

例如，源码中定义的是：

```java
public class MyArrayList<E> {
    public void add(E element) {
        // ...
    }

    public E get(int index) {
        // ...
    }
}
```

编译后可以近似理解为：

```java
public class MyArrayList {
    public void add(Object element) {
        // ...
    }

    public Object get(int index) {
        // ...
    }
}
```

也就是说，泛型并不是在运行时让集合真正变成“只能存 `String` 的集合”。集合底层仍然可以理解为基于 `Object` 存储，只是在编译阶段已经进行了类型限制。

#### 运行阶段：自动插入类型转换

虽然泛型擦除后，`get()` 方法底层返回值可以理解为 `Object`，但开发者写代码时并不需要手动强制转换：

```java
String name = list.get(0);
```

这是因为编译器会根据泛型声明自动插入类型转换。上面的代码编译后可以近似理解为：

```java
String name = (String) list.get(0);
```

只不过这个转换动作由编译器自动完成，开发者不需要手动编写。

> 结论：泛型是一种编译阶段的类型安全机制。它通过编译时类型检查保证类型使用正确，再通过泛型擦除兼容旧版本字节码，并由编译器自动插入必要的类型转换。

### 原始类型的风险

定义了泛型的类，如果使用时不写类型实参，就称为使用**原始类型**（Raw Type）。

```java
MyArrayList list = new MyArrayList();
```

这种写法会绕过泛型检查，使集合重新退回到类似 `Object` 容器的状态：

```java
MyArrayList list = new MyArrayList();

list.add("jack");
list.add(100);

String name = (String) list.get(1); // 运行时可能抛出 ClassCastException
```

原始类型通常是为了兼容旧代码而保留的写法。实际开发中，应尽量避免使用。

正确写法：

```java
MyArrayList<String> list = new MyArrayList<>();
```

> 注意：只要使用原始类型或进行不安全的强制类型转换，泛型带来的类型安全就可能被破坏。

### 泛型的使用

泛型可以定义在**类、接口和方法**上，用于把数据类型作为参数传入，从而提高代码的复用性和类型安全性。泛型的核心思想是：定义代码时不写死具体类型，使用代码时再明确具体类型。

泛型常见使用位置如下：

| 使用位置   | 作用                                                   |
| ---------- | ------------------------------------------------------ |
| 泛型类     | 让整个类中的实例变量、实例方法使用同一个类型参数       |
| 泛型方法   | 让单个方法拥有独立的类型参数                           |
| 泛型接口   | 让接口方法中的参数或返回值类型由实现类或对象创建时决定 |
| 泛型通配符 | 在无法确定具体泛型类型时，扩大方法参数的接收范围       |

#### 在类上定义泛型

在类名后使用 `<类型参数>`，可以定义泛型类。

```java
[修饰符] class 类名<泛型1, 泛型2, ...> {
}
```

例如：

```java
public class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}
```

这里的 `T` 是定义在类上的类型参数。它可以用于实例变量、构造方法、实例方法的参数和返回值。

使用泛型类时，需要在创建对象或声明引用时明确类型：

```java
public class BoxDemo {
    public static void main(String[] args) {
        Box<String> box = new Box<>("hello");

        String value = box.getValue();
        System.out.println(value);
    }
}
```

当 `Box<String>` 确定后，`T` 就可以理解为 `String`。因此：

```java
box.setValue("java");  // 正确
// box.setValue(100);  // 编译错误
```

> 结论：类上定义的泛型，由使用这个类时传入的具体类型决定。确定类型后，类中的相关实例成员都会受到该类型约束。

##### 类上泛型的作用范围

定义在类上的泛型，可以在**实例变量**和**实例方法**中使用。

```java
public class UserInfo<N, A> {
    private N name;
    private A age;

    public UserInfo(N name, A age) {
        this.name = name;
        this.age = age;
    }

    public N getName() {
        return name;
    }

    public A getAge() {
        return age;
    }
}
```

使用时：

```java
public class UserInfoDemo {
    public static void main(String[] args) {
        UserInfo<String, Integer> user = new UserInfo<>("jack", 20);

        String name = user.getName();
        Integer age = user.getAge();

        System.out.println(name);
        System.out.println(age);
    }
}
```

这段代码中，`N` 被指定为 `String`，`A` 被指定为 `Integer`。因此，`getName()` 返回 `String`，`getAge()` 返回 `Integer`。

但是，类上定义的泛型不能直接用于静态变量、静态方法和静态代码块。

```java
public class Box<T> {
    private T value;

    // static T data;           // 编译错误
    // public static void show(T value) {} // 编译错误
}
```

原因在于：类上的泛型需要在创建对象时才能确定具体类型，而静态成员属于类本身，加载类时就存在，不依赖某个具体对象。

> 易错点：类上定义的泛型属于对象级别，静态成员属于类级别。静态成员不能直接使用类上定义的泛型。

#### 在方法上定义泛型

如果希望某个方法自己拥有独立的类型参数，可以在方法上定义泛型。泛型方法的类型参数写在**返回值类型之前**。

```java
[修饰符] <泛型1, 泛型2, ...> 返回值类型 方法名(形参列表) {
}
```

例如：

```java
public class MethodGenericDemo {
    public <T> T echo(T value) {
        return value;
    }

    public static <E> E getSame(E value) {
        return value;
    }
}
```

调用时，编译器通常可以根据传入的实参自动推断类型。

```java
public class Test {
    public static void main(String[] args) {
        MethodGenericDemo demo = new MethodGenericDemo();

        String text = demo.echo("hello");
        Integer number = demo.echo(100);

        String name = MethodGenericDemo.getSame("jack");
        Integer age = MethodGenericDemo.getSame(18);

        System.out.println(text);
        System.out.println(number);
        System.out.println(name);
        System.out.println(age);
    }
}
```

这段代码中：

- 调用 `demo.echo("hello")` 时，`T` 被推断为 `String`；
- 调用 `demo.echo(100)` 时，`T` 被推断为 `Integer`；
- 调用静态方法 `getSame("jack")` 时，`E` 被推断为 `String`。

泛型方法中的类型参数不一定必须出现在形参列表中，也可以只出现在返回值类型中。

```java
public class MethodGenericDemo {
    public static <T> T getDefaultValue() {
        return null;
    }
}
```

调用时：

```java
public class Test {
    public static void main(String[] args) {
        String name = MethodGenericDemo.getDefaultValue();
        Integer age = MethodGenericDemo.getDefaultValue();

        System.out.println(name);
        System.out.println(age);
    }
}
```

这段代码中：

- `String name = MethodGenericDemo.getDefaultValue();` 中，`T` 被推断为 `String`；
- `Integer age = MethodGenericDemo.getDefaultValue();` 中，`T` 被推断为 `Integer`。

此时，编译器不是根据实参推断泛型类型，而是根据**返回值接收位置的目标类型**进行推断。

如果泛型类型参数既没有出现在形参列表中，也没有出现在返回值类型中，通常没有实际意义。

```java
public class MethodGenericDemo {
    public <T> void show() {
        System.out.println("hello");
    }
}
```

调用时：

```java
MethodGenericDemo demo = new MethodGenericDemo();
demo.show();
```

上面的代码语法上是合法的，但 `T` 没有参与参数传递，也没有影响返回值类型，因此这个泛型类型参数没有发挥实际作用。实际开发中应避免这种多余的泛型定义。

> 注意：泛型方法既可以定义在实例方法上，也可以定义在静态方法上。静态方法如果需要使用泛型，必须自己在方法上定义类型参数，不能直接使用类上定义的泛型。

#### 类泛型与方法泛型的区别

类上定义的泛型和方法上定义的泛型，作用范围不同。

| 对比项             | 类上定义泛型             | 方法上定义泛型         |
| ------------------ | ------------------------ | ---------------------- |
| 定义位置           | 类名后面                 | 方法返回值类型前面     |
| 作用范围           | 整个类的实例成员         | 当前方法内部           |
| 类型确定时机       | 创建对象或声明引用时确定 | 调用方法时根据实参推断 |
| 是否可用于静态方法 | 不能直接使用             | 可以                   |

例如：

```java
public class DataBox<T> {
    private T data;

    public T getData() {
        return data;
    }

    public void setData(T data) {
        this.data = data;
    }

    public static <E> E getValue(E value) {
        return value;
    }
}
```

这里的 `T` 是类上的泛型，只能用于实例成员；`E` 是静态方法自己定义的泛型，只在 `getValue()` 方法内部有效。

> 结论：如果整个类都围绕某一种类型工作，适合在类上定义泛型；如果只有某个方法需要临时适配不同类型，适合在方法上定义泛型。

#### 在接口上定义泛型

泛型也可以定义在接口上。定义格式如下：

```java
[修饰符] interface 接口名<泛型1, 泛型2, ...> {
}
```

例如：

```java
public interface Flyable<T> {
    void fly(T obj);
}
```

接口上定义泛型后，实现类有两种处理方式：一种是在实现接口时明确具体类型，另一种是继续保留泛型。

##### 实现泛型接口：明确具体类型

如果定义实现类时已经能够确定接口的泛型类型，可以直接在 `implements` 后指定具体类型。

```java
interface Flyable<T> {
    void fly(T obj);
}

class Bird implements Flyable<String> {
    @Override
    public void fly(String obj) {
        System.out.println(obj + "在飞翔");
    }
}
```

使用时：

```java
public class FlyDemo {
    public static void main(String[] args) {
        Bird bird = new Bird();

        bird.fly("小鸟");
        // bird.fly(100); // 编译错误
    }
}
```

由于 `Bird implements Flyable<String>` 已经明确了 `T` 是 `String`，所以 `fly()` 方法的参数类型固定为 `String`。

这种方式适合实现类本身只服务于某一种具体类型的场景。

##### 实现泛型接口：继续保留泛型

如果定义实现类时还不能确定具体类型，可以让实现类继续定义泛型，并把该泛型传递给接口。

```java
interface Flyable<T> {
    void fly(T obj);
}

class Animal<T> implements Flyable<T> {
    @Override
    public void fly(T obj) {
        System.out.println(obj + "在飞翔");
    }
}
```

使用时再明确具体类型：

```java
public class FlyDemo {
    public static void main(String[] args) {
        Animal<String> animal = new Animal<>();
        animal.fly("小猫");

        Animal<Integer> numberAnimal = new Animal<>();
        numberAnimal.fly(100);
    }
}
```

这类写法适合实现类本身仍然需要保持通用性，由创建对象时再决定具体类型。

> 结论：实现泛型接口时，如果实现类能确定类型，就直接写死具体类型；如果实现类也需要保持灵活，就继续在实现类上定义泛型。

### 泛型通配符

泛型通配符使用 `?` 表示一种未知的引用类型，常用于方法参数中，用来接收不同泛型实参的对象。

通配符主要有三种形式：

| 通配符形式         | 含义                               |
| ------------------ | ---------------------------------- |
| `<?>`              | 无限定通配符，可以接收任意引用类型 |
| `<? extends 类型>` | 上限通配符，只能接收该类型及其子类 |
| `<? super 类型>`   | 下限通配符，只能接收该类型及其父类 |

通配符解决的是“方法参数无法确定具体泛型类型”的问题。

#### 为什么需要通配符

泛型具有严格的类型约束。即使 `Integer` 是 `Number` 的子类，`ArrayList<Integer>` 也不是 `ArrayList<Number>` 的子类。

```java
ArrayList<Number> list = new ArrayList<Integer>(); // 编译错误
```

这意味着，如果一个方法参数写成 `ArrayList<Number>`，它只能接收 `ArrayList<Number>`，不能接收 `ArrayList<Integer>` 或 `ArrayList<Double>`。

```java
public static void print(ArrayList<Number> list) {
}
```

下面的调用无法通过编译：

```java
ArrayList<Integer> nums = new ArrayList<>();
print(nums); // 编译错误
```

如果希望方法能够接收 `Number` 及其子类作为泛型实参的集合，就需要使用上限通配符：

```java
public static void print(ArrayList<? extends Number> list) {
}
```

#### 无限定通配符

`<?>` 表示未知类型，可以接收任意引用类型的泛型对象。

```java
public static void print(ArrayList<?> list) {
    for (int i = 0; i < list.size(); i++) {
        Object value = list.get(i);
        System.out.println(value);
    }
}
```

调用示例：

```java
print(new ArrayList<String>());
print(new ArrayList<Integer>());
print(new ArrayList<Object>());
```

在 `ArrayList<?>` 中，`?` 的实际类型由传入的实参决定。它可能是 `String`，也可能是 `Integer`，也可能是其他引用类型。

> 注意：`ArrayList<?>` 不等同于 `ArrayList<Object>`。`ArrayList<Object>` 表示集合中可以存放任意对象；`ArrayList<?>` 表示可以接收任意泛型类型的集合，但接收后并不知道集合元素的具体类型。

由于 `ArrayList<?>` 中的元素类型未知，读取元素时通常只能按 `Object` 处理。

```java
public static void print(ArrayList<?> list) {
    Object value = list.get(0);
}
```

#### 上限通配符

`<? extends 类型>` 表示未知类型必须是指定类型或其子类。

```java
public static void printNumbers(ArrayList<? extends Number> list) {
    for (int i = 0; i < list.size(); i++) {
        Number value = list.get(i);
        System.out.println(value);
    }
}
```

可以传入：

```java
printNumbers(new ArrayList<Number>());
printNumbers(new ArrayList<Integer>());
printNumbers(new ArrayList<Double>());
```

不能传入：

```java
// printNumbers(new ArrayList<String>()); // 编译错误
// printNumbers(new ArrayList<Object>()); // 编译错误
```

因为 `String` 不是 `Number` 的子类，`Object` 是 `Number` 的父类，也不符合 `? extends Number` 的要求。

上限通配符适合“主要读取数据”的场景。因为无论实际类型是 `Integer`、`Double` 还是 `Number`，取出的元素都至少可以当作 `Number` 使用。

```java
Number value = list.get(0);
```

> 结论：`<? extends Number>` 限制的是泛型实参的最高父类型。实际传入的类型只能是 `Number` 或 `Number` 的子类。

#### 下限通配符

`<? super 类型>` 表示未知类型必须是指定类型或其父类。

例如：

```java
class Animal {
    public void eat() {
        System.out.println("动物在进食");
    }
}

class Bird extends Animal {
    @Override
    public void eat() {
        System.out.println("鸟儿在吃虫子");
    }
}
```

定义一个接收 `Bird` 或其父类泛型集合的方法：

```java
public static void addBird(ArrayList<? super Bird> list) {
    list.add(new Bird());
}
```

可以传入：

```java
addBird(new ArrayList<Bird>());
addBird(new ArrayList<Animal>());
addBird(new ArrayList<Object>());
```

不能传入：

```java
// addBird(new ArrayList<String>()); // 编译错误
```

因为 `String` 不是 `Bird` 的父类。

下限通配符适合“向集合中添加指定类型对象”的场景。对于 `ArrayList<? super Bird>`，无论实际集合是 `ArrayList<Bird>`、`ArrayList<Animal>` 还是 `ArrayList<Object>`，都一定可以安全地放入 `Bird` 对象。

但是，从这类集合中取出元素时，编译器不能确定实际元素一定是 `Bird`，因此通常只能按 `Object` 接收；如果需要当作更具体的类型使用，则需要结合实际情况进行强制类型转换。

```java
public static void read(ArrayList<? super Bird> list) {
    Object value = list.get(0);
}
```

> 结论：`<? super Bird>` 限制的是泛型实参的最低子类型。实际传入的类型只能是 `Bird` 或 `Bird` 的父类。

#### 通配符使用总结

三种通配符的适用场景可以概括如下：

| 写法                          | 可接收的泛型实参  | 读取特点             | 添加特点                           |
| ----------------------------- | ----------------- | -------------------- | ---------------------------------- |
| `ArrayList<?>`                | 任意引用类型      | 只能按 `Object` 读取 | 不能安全添加具体对象               |
| `ArrayList<? extends Number>` | `Number` 或其子类 | 可以按 `Number` 读取 | 不能安全添加具体 `Number` 子类对象 |
| `ArrayList<? super Bird>`     | `Bird` 或其父类   | 通常按 `Object` 读取 | 可以安全添加 `Bird` 或其子类对象   |

> 结论：上限通配符 `extends` 更适合读取数据，下限通配符 `super` 更适合写入数据。简单记忆为：读数据用 `extends`，写数据用 `super`。

## 自然排序 Comparable

自然排序（Natural Ordering）是指对象所属的类自己定义比较规则，然后由排序工具按照这个规则完成排序。在 Java 中，自然排序通过 `java.lang.Comparable<T>` 接口实现。

如果一个自定义类的对象需要被 `Arrays.sort()` 等工具直接排序，那么这个类通常需要实现 `Comparable<T>` 接口，并重写 `compareTo(T o)` 方法，在该方法中写清楚对象之间的比较规则。

> 结论：`Comparable` 把“对象应该如何比较大小”这件事定义在类的内部，因此也常被称为**内部比较器**。

### 对象为什么不能直接比较大小

基本数据类型中，除 `boolean` 以外，数值类型和字符类型可以使用比较运算符进行大小比较。

```java
int a = 10;
int b = 20;

System.out.println(a > b);
```

但是对象属于引用数据类型，变量中保存的是对象的引用。两个对象之间通常不能直接使用 `>`、`<` 这类比较运算符来判断大小。

```java
Person p1 = new Person("张三", 20);
Person p2 = new Person("李四", 18);

// System.out.println(p1 > p2); // 编译错误
```

对象的“大小”本身没有统一标准。对于学生对象，可以按年龄比较，也可以按姓名比较，还可以按成绩比较。因此，比较对象之前必须先明确比较规则。

例如，按照年龄升序比较：

```java
public int compareTo(Person other) {
    return this.age - other.age;
}
```

这里的含义是：

| 返回值 | 含义                 |
| ------ | -------------------- |
| 正数   | 当前对象大于参数对象 |
| 负数   | 当前对象小于参数对象 |
| `0`    | 两个对象相等         |

> 注意：对象排序的关键不是对象“天然有大小”，而是开发者为对象定义了一个明确的比较规则。

### Comparable 接口

`Comparable<T>` 是 Java 提供的自然排序接口，位于 `java.lang` 包中。该接口中最核心的方法是 `compareTo()`。

```java
public interface Comparable<T> {
    int compareTo(T o);
}
```

其中，`T` 表示要和当前对象进行比较的对象类型。

例如，`Person implements Comparable<Person>` 表示 `Person` 对象可以和另一个 `Person` 对象进行比较。

```java
public class Person implements Comparable<Person> {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public int compareTo(Person other) {
        return this.age - other.age;
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
}
```

这段代码表示：`Person` 对象按照年龄进行自然排序，并且默认规则是年龄升序。

### compareTo() 方法的返回值规则

`compareTo()` 方法通过 `int` 返回值表示两个对象的大小关系。

假设调用形式如下：

```java
this.compareTo(other)
```

返回值规则如下：

| 返回值 | 含义                   |
| ------ | ---------------------- |
| `> 0`  | `this` 大于 `other`    |
| `< 0`  | `this` 小于 `other`    |
| `== 0` | `this` 与 `other` 相等 |

例如：

```java
@Override
public int compareTo(Person other) {
    return this.age - other.age;
}
```

如果 `this.age` 大于 `other.age`，返回正数；如果 `this.age` 小于 `other.age`，返回负数；如果二者相等，返回 `0`。

#### 升序规则

升序表示“小的排前面，大的排后面”。

```java
@Override
public int compareTo(Person other) {
    return this.age - other.age;
}
```

可以简记为：

```text
this 在前，通常表示升序
```

#### 降序规则

降序表示“大的排前面，小的排后面”。

```java
@Override
public int compareTo(Person other) {
    return other.age - this.age;
}
```

可以简记为：

```text
this 在后，通常表示降序
```

> 易错点：`compareTo()` 的返回值不要求必须是 `1`、`-1`、`0`，只要能区分正数、负数和零即可。

### 对象数组的自然排序

如果对象所属的类实现了 `Comparable` 接口，就可以使用 `Arrays.sort()` 对对象数组进行排序。

```java
import java.util.Arrays;

public class ComparableDemo {
    public static void main(String[] args) {
        Person[] persons = {
                new Person("张三", 21),
                new Person("李四", 18),
                new Person("王五", 20),
                new Person("赵六", 17)
        };

        Arrays.sort(persons);

        for (Person person : persons) {
            System.out.println(person);
        }
    }
}
```

如果 `Person` 的 `compareTo()` 按年龄升序实现，则输出结果会按年龄从小到大排列。

```text
Person{name='赵六', age=17}
Person{name='李四', age=18}
Person{name='王五', age=20}
Person{name='张三', age=21}
```

`Arrays.sort(persons)` 在排序过程中会不断比较数组中的相邻或相关元素，底层会调用元素对象的 `compareTo()` 方法。开发者不需要手动调用 `compareTo()` 完成排序，只需要在类中提供正确的比较规则。

> 补充：从使用角度看，`compareTo()` 是由排序工具在合适时机自动调用的方法，也可以理解为一种回调方法。开发者负责写规则，排序工具负责调用规则。

#### 如果对象没有实现 Comparable

基本类型数组可以直接排序：

```java
int[] nums = {10, 3, 8, 1};
Arrays.sort(nums);
System.out.println(Arrays.toString(nums));
```

字符串数组也可以直接排序：

```java
String[] names = {"abc", "abf", "abd", "abe"};
Arrays.sort(names);
System.out.println(Arrays.toString(names));
```

这是因为 `String` 已经实现了 `Comparable` 接口，Java 已经为字符串定义好了默认排序规则。

但是，如果自定义对象没有实现 `Comparable` 接口，直接调用 `Arrays.sort()` 会出现运行时异常。

```java
Person[] persons = {
        new Person("张三", 21),
        new Person("李四", 18)
};

Arrays.sort(persons); // 如果 Person 没有实现 Comparable，运行时会出错
```

常见异常是：

```text
java.lang.ClassCastException
```

原因是排序工具需要把数组元素当作 `Comparable` 来比较。如果元素对象没有实现该接口，就无法调用 `compareTo()` 完成排序。

> 结论：自定义对象数组想要直接使用 `Arrays.sort()` 进行自然排序，对象所属的类必须实现 `Comparable` 接口。

#### 使用冒泡排序理解 compareTo()

为了理解 `compareTo()` 在排序中的作用，可以先从冒泡排序的思想入手。冒泡排序的核心是：不断比较相邻两个元素，如果顺序不符合要求，就交换位置。

对于对象数组，不能直接写：

```java
if (arr[j] > arr[j + 1]) {
}
```

而应通过 `compareTo()` 判断：

```java
if (arr[j].compareTo(arr[j + 1]) > 0) {
    Person temp = arr[j];
    arr[j] = arr[j + 1];
    arr[j + 1] = temp;
}
```

如果 `arr[j].compareTo(arr[j + 1]) > 0`，说明前一个对象大于后一个对象。在升序排序中，大的对象应该放后面，因此需要交换位置。

```java
public class ArrayUtil {
    public static void sort(Person[] arr) {
        for (int i = 0; i < arr.length - 1; i++) {
            for (int j = 0; j < arr.length - i - 1; j++) {
                if (arr[j].compareTo(arr[j + 1]) > 0) {
                    Person temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                }
            }
        }
    }
}
```

这段代码说明，排序算法本身只关心 `compareTo()` 的返回结果，不关心对象内部到底按哪个属性比较。对象的比较规则由类自己决定。

#### 使用 Comparable 优化通用排序

如果只为 `Person[]` 编写排序方法，那么只能排序 `Person` 数组。若以后还要排序 `Book[]`、`Student[]`、`Product[]`，就需要不断编写新的排序方法，代码会大量重复。

更合理的做法是：让需要排序的类都实现 `Comparable` 接口，然后排序工具只依赖 `Comparable` 进行比较。

```java
public class ArrayUtil {
    public static void sort(Object[] arr) {
        for (int i = 0; i < arr.length - 1; i++) {
            for (int j = 0; j < arr.length - i - 1; j++) {
                Comparable current = (Comparable) arr[j];

                if (current.compareTo(arr[j + 1]) > 0) {
                    Object temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                }
            }
        }
    }
}
```

这种写法的思路是：

1. `Object[]` 可以接收任意引用类型数组；
2. 排序时把数组元素强制转换为 `Comparable`；
3. 通过 `compareTo()` 调用对象内部定义的比较规则；
4. 如果数组元素没有实现 `Comparable`，转换时会抛出 `ClassCastException`。

Java 提供的 `Arrays.sort(Object[] arr)` 就采用了类似思想：它可以接收对象数组，但数组中的元素必须具备可比较能力。

> 结论：`Comparable` 的作用是把不同类型对象的排序能力统一抽象出来。排序工具不需要知道对象具体是什么类，只需要知道对象能否通过 `compareTo()` 比较大小。

### Arrays.sort() 与自然排序

`Arrays` 是 Java 提供的数组工具类。对于对象数组，`Arrays.sort(Object[] arr)` 可以按照元素的自然顺序进行排序。

```java
Arrays.sort(arr);
```

这里的“自然顺序”指的是元素所属类在 `compareTo()` 方法中定义的默认排序规则。

例如：

```java
public class Person implements Comparable<Person> {
    private String name;
    private int age;

    @Override
    public int compareTo(Person other) {
        return this.age - other.age;
    }
}
```

此时，`Person` 的自然排序规则就是按年龄升序排序。

如果改成：

```java
@Override
public int compareTo(Person other) {
    return other.name.compareTo(this.name);
}
```

此时，`Person` 的自然排序规则就变成按姓名降序排序。

> 结论：自然排序不是固定规则，而是类自己通过 `compareTo()` 定义出来的默认规则。

### 自然排序的局限

自然排序有一个明显局限：**一个类通常只能定义一种默认排序规则**。

例如，`Person` 类中只能有一个 `compareTo()` 方法。如果在 `compareTo()` 中按年龄升序排序，那么 `Arrays.sort(persons)` 默认就会按年龄升序；如果改成按姓名降序排序，默认规则又会变成姓名降序。

但是在实际开发中，同一种对象可能有多种排序需求：

- 按年龄升序；
- 按年龄降序；
- 按姓名升序；
- 按姓名降序；
- 先按年龄排序，年龄相同再按姓名排序。

这些需求无法同时都写进一个 `compareTo()` 方法中。

> 注意：`Comparable` 适合定义对象最常用、最自然的默认排序规则。如果需要临时指定多种排序规则，通常需要使用外部比较器 `Comparator`。

### 常见类的自然排序

Java 中很多类已经实现了 `Comparable` 接口，因此可以直接使用 `Arrays.sort()` 排序。

例如，`Integer` 默认按数值升序排序：

```java
import java.util.Arrays;

public class IntegerSortDemo {
    public static void main(String[] args) {
        Integer[] nums = {3, 1, 5, 4, 2};

        Arrays.sort(nums);

        System.out.println(Arrays.toString(nums));
    }
}
```

运行结果：

```text
[1, 2, 3, 4, 5]
```

`String` 默认按字典顺序排序：

```java
import java.util.Arrays;

public class StringSortDemo {
    public static void main(String[] args) {
        String[] names = {"abc", "abf", "abm", "abe", "abd"};

        Arrays.sort(names);

        System.out.println(Arrays.toString(names));
    }
}
```

运行结果：

```text
[abc, abd, abe, abf, abm]
```

## 定制排序 Comparator

定制排序是指把对象的比较规则定义在对象所属类的外部。Java 中通过 `java.util.Comparator<T>` 接口实现定制排序，也称为**外部比较器**。

与 `Comparable` 不同，`Comparator` 不要求被排序的类自己实现比较接口，而是由额外的比较器对象提供比较规则。因此，同一个类可以根据不同需求使用不同的排序规则，例如按年龄升序、按年龄降序、按姓名升序、按成绩降序等。

> 结论：`Comparable` 适合固定的默认排序规则；`Comparator` 适合灵活、多变、临时指定的排序规则。

### Comparator 接口

`Comparator<T>` 是 Java 提供的比较器接口，位于 `java.util` 包下。它的核心方法是 `compare(T o1, T o2)`。

```java
public interface Comparator<T> {
    int compare(T o1, T o2);
}
```

`compare()` 方法用于比较两个对象的大小，返回值规则如下：

| 返回值 | 含义              |
| ------ | ----------------- |
| `> 0`  | `o1` 大于 `o2`    |
| `< 0`  | `o1` 小于 `o2`    |
| `== 0` | `o1` 与 `o2` 相等 |

例如，按照年龄升序比较：

```java
@Override
public int compare(User u1, User u2) {
    return u1.getAge() - u2.getAge();
}
```

按照年龄降序比较：

```java
@Override
public int compare(User u1, User u2) {
    return u2.getAge() - u1.getAge();
}
```

可以简记为：

```text
第一个对象在前，一般表示升序；
第一个对象在后，一般表示降序。
```

> 易错点：`Comparator` 中的方法名是 `compare()`，不是 `compareTo()`。`compareTo()` 是 `Comparable` 接口中的方法。

### 使用独立比较器类

如果某种排序规则会被多次使用，可以单独定义一个比较器类，实现 `Comparator<T>` 接口。

例如，定义一个用户类：

```java
public class User {
    private String name;
    private int age;

    public User(int age, String name) {
        this.age = age;
        this.name = name;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    @Override
    public String toString() {
        return "User{name='" + name + "', age=" + age + "}";
    }
}
```

定义一个按照年龄降序排序的比较器：

```java
import java.util.Comparator;

public class UserAgeDescComparator implements Comparator<User> {
    @Override
    public int compare(User u1, User u2) {
        return u2.getAge() - u1.getAge();
    }
}
```

使用比较器排序：

```java
import java.util.Arrays;

public class ComparatorDemo {
    public static void main(String[] args) {
        User[] users = {
                new User(20, "jack"),
                new User(18, "lucy"),
                new User(22, "tom"),
                new User(19, "rose")
        };

        Arrays.sort(users, new UserAgeDescComparator());

        for (User user : users) {
            System.out.println(user);
        }
    }
}
```

运行结果示例：

```text
User{name='tom', age=22}
User{name='jack', age=20}
User{name='rose', age=19}
User{name='lucy', age=18}
```

这种写法的优点是比较规则可以复用，适合较重要、较稳定的排序规则。

### 使用匿名内部类定义比较器

如果某个排序规则只在当前代码中临时使用，可以使用匿名内部类直接创建 `Comparator` 对象。

```java
import java.util.Arrays;
import java.util.Comparator;

public class ComparatorAnonymousDemo {
    public static void main(String[] args) {
        User[] users = {
                new User(20, "jack"),
                new User(18, "lucy"),
                new User(22, "tom"),
                new User(19, "rose")
        };

        Arrays.sort(users, new Comparator<User>() {
            @Override
            public int compare(User u1, User u2) {
                return u1.getName().compareTo(u2.getName());
            }
        });

        for (User user : users) {
            System.out.println(user);
        }
    }
}
```

这段代码按照用户名升序排序。匿名内部类的写法本质上完成了两件事：

1. 定义了一个没有名字的类，这个类实现了 `Comparator<User>` 接口；
2. 创建了这个匿名比较器类的对象，并把它传给 `Arrays.sort()`。

> 注意：匿名内部类适合临时排序规则。如果比较规则需要在多个地方复用，应优先单独定义比较器类。

### Arrays.sort() 实现定制排序

`Arrays` 工具类提供了支持定制排序的方法：

```java
public static <T> void sort(T[] a, Comparator<? super T> c)
```

该方法接收两个参数：

| 参数                      | 含义               |
| ------------------------- | ------------------ |
| `T[] a`                   | 要排序的数组       |
| `Comparator<? super T> c` | 排序时使用的比较器 |

例如，按照年龄升序排序：

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u1.getAge() - u2.getAge();
    }
});
```

按照年龄降序排序：

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u2.getAge() - u1.getAge();
    }
});
```

调用该方法时，排序规则不再由 `User` 类自己决定，而是由传入的 `Comparator` 对象决定。

> 结论：`Arrays.sort(arr)` 使用对象的自然排序规则；`Arrays.sort(arr, comparator)` 使用外部传入的定制排序规则。

### 多种排序规则

`Comparator` 的优势在于可以为同一个类定义多种排序规则。

例如，对同一个 `User[]` 数组，可以按年龄排序，也可以按姓名排序。

#### 按年龄升序

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u1.getAge() - u2.getAge();
    }
});
```

#### 按年龄降序

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u2.getAge() - u1.getAge();
    }
});
```

#### 按姓名升序

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u1.getName().compareTo(u2.getName());
    }
});
```

#### 按姓名降序

```java
Arrays.sort(users, new Comparator<User>() {
    @Override
    public int compare(User u1, User u2) {
        return u2.getName().compareTo(u1.getName());
    }
});
```

由于 `String` 已经实现了 `Comparable` 接口，因此字符串之间可以直接调用 `compareTo()` 完成字典顺序比较。

#### 按小数属性排序

如果比较的是 `double`、`float` 等小数类型，不建议直接相减后强转为 `int`。更推荐使用包装类提供的比较方法。

例如，定义学生类：

```java
public class Student {
    private String name;
    private int age;
    private double score;

    public Student(String name, int age, double score) {
        this.name = name;
        this.age = age;
        this.score = score;
    }

    public double getScore() {
        return score;
    }

    @Override
    public String toString() {
        return "Student{name='" + name + "', age=" + age + ", score=" + score + "}";
    }
}
```

按照成绩升序排序：

```java
Arrays.sort(students, new Comparator<Student>() {
    @Override
    public int compare(Student s1, Student s2) {
        return Double.compare(s1.getScore(), s2.getScore());
    }
});
```

按照成绩降序排序：

```java
Arrays.sort(students, new Comparator<Student>() {
    @Override
    public int compare(Student s1, Student s2) {
        return Double.compare(s2.getScore(), s1.getScore());
    }
});
```

> 注意：比较 `double` 类型时，优先使用 `Double.compare()`。它比简单相减更准确，也能避免精度和类型转换带来的问题。

### 自定义排序工具方法

为了理解 `Comparator` 的底层思想，可以用冒泡排序模拟一个支持外部比较器的排序方法。

普通写法中，如果方法参数使用 `Object[]` 和原始类型 `Comparator`，类型安全较弱：

```java
public static void sort(Object[] arr, Comparator comparator) {
    for (int i = 0; i < arr.length - 1; i++) {
        for (int j = 0; j < arr.length - i - 1; j++) {
            if (comparator.compare(arr[j], arr[j + 1]) > 0) {
                Object temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}
```

更合理的写法是给方法定义泛型：

```java
import java.util.Comparator;

public class ArrayUtil {
    public static <E> void sort(E[] arr, Comparator<? super E> comparator) {
        for (int i = 0; i < arr.length - 1; i++) {
            for (int j = 0; j < arr.length - i - 1; j++) {
                if (comparator.compare(arr[j], arr[j + 1]) > 0) {
                    E temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;
                }
            }
        }
    }
}
```

这段代码中：

1. `<E>` 表示数组元素类型；
2. `E[] arr` 表示要排序的是某种确定类型的数组；
3. `Comparator<? super E>` 表示比较器可以比较 `E` 类型对象，也可以比较 `E` 的父类对象；
4. `comparator.compare(arr[j], arr[j + 1]) > 0` 表示前一个元素大于后一个元素，需要交换位置。

> 结论：定制排序的本质是“排序算法不负责决定谁大谁小，只负责调用比较器；比较器负责定义谁大谁小”。

### Comparator 与 Comparable 的区别

`Comparable` 和 `Comparator` 都可以用于对象排序，但适用场景不同。

| 对比项               | `Comparable`                   | `Comparator`                   |
| -------------------- | ------------------------------ | ------------------------------ |
| 所在包               | `java.lang`                    | `java.util`                    |
| 核心方法             | `compareTo(T o)`               | `compare(T o1, T o2)`          |
| 比较规则位置         | 定义在对象所属类内部           | 定义在对象所属类外部           |
| 常见称呼             | 内部比较器、自然排序           | 外部比较器、定制排序           |
| 排序规则数量         | 一个类通常只能定义一种默认规则 | 可以定义多种规则               |
| 是否需要修改被排序类 | 需要实现 `Comparable`          | 不需要修改被排序类             |
| 常用方法             | `Arrays.sort(arr)`             | `Arrays.sort(arr, comparator)` |

选择规则如下：

```text
比较规则固定，优先使用 Comparable；
比较规则灵活多变，优先使用 Comparator。
```

例如：

- `Person` 默认就应该按身份证号排序，可以使用 `Comparable`；
- `Person` 有时按年龄排，有时按姓名排，有时按工资排，更适合使用 `Comparator`。

### 定制排序的优点

定制排序的主要优点如下：

1. **排序规则灵活**：同一个类可以根据需求使用多种比较规则。
2. **不侵入原类**：无需修改被排序类的源码，尤其适合排序 Java 已有类或第三方类。
3. **可临时指定规则**：可以在调用 `Arrays.sort()` 时直接传入比较器。
4. **类型更安全**：使用 `Arrays.sort(T[] arr, Comparator<? super T> comparator)` 时，编译器可以检查比较器类型是否匹配。

> 注意：使用 `Comparator` 的排序称为**定制排序**，不是自然排序。自然排序对应的是 `Comparable` 和 `Arrays.sort(arr)`。
