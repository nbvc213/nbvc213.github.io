## 注解

注解（Annotation）是 Java 从 JDK 1.5 开始引入的一种元数据机制。它可以理解为写在代码中的**特殊标记**，用于向编译器、JVM、框架或其他程序提供额外信息。

注解本身不会直接改变程序逻辑，也不会主动执行功能。它真正发挥作用，依赖于编译器、框架或反射程序对注解进行读取和解析。

### 什么是注解

注解是一种用于描述代码的元数据。它可以标记在类、方法、属性、构造方法、参数等程序结构上，用来补充说明这些结构的含义或用途。

例如：

```java
@Override
public String toString() {
    return "User{}";
}
```

`@Override` 就是一个注解。它表示当前方法应该重写父类或接口中的方法。编译器读取到这个注解后，会检查该方法是否真的完成了重写。如果方法名、参数列表或返回值不符合重写规则，编译器就会报错。

注解的定义使用 `@interface`：

```java
public @interface MyAnnotation {
}
```

这说明注解本身也是一种 Java 类型，属于**引用数据类型**。注解编译之后同样会生成 `.class` 文件，只是它不是普通类，而是一种特殊的注解类型。

### 注解和注释的区别

注释和注解都可以看作代码中的标记，但二者的作用对象和运行机制完全不同。

| 对比项           | 注释           | 注解                                             |
| ---------------- | -------------- | ------------------------------------------------ |
| 英文             | Comment        | Annotation                                       |
| 作用对象         | 程序员         | 编译器、JVM、框架或其他程序                      |
| 是否参与编译处理 | 编译时被忽略   | 可被编译器或程序读取                             |
| 是否影响程序行为 | 不影响程序行为 | 可能影响编译检查、框架处理或运行时逻辑           |
| 是否能被反射读取 | 不能           | 运行时保留的注解可以被反射读取                   |
| 典型用途         | 解释代码含义   | 标记过时、抑制警告、配置框架行为、辅助运行时处理 |

注释只用于说明代码，方便程序员阅读。例如：

```java
// 用户名称
private String name;
```

这类内容在编译时会被忽略，不会进入普通字节码逻辑，也不会被程序读取。

注解则是写给程序看的。例如：

```java
@Deprecated
public void oldMethod() {
}
```

`@Deprecated` 表示该方法已经过时。编译器或开发工具读取到这个注解后，会在其他代码调用该方法时给出过时警告。

> **易错点**
>
> 注释是给人看的说明文字；注解是给程序读取的元数据。注解不是“高级注释”，它可以参与编译检查、框架配置或运行时处理。

### 注解为什么需要解析器

注解本身只是一个标记，不会自动产生功能。真正起作用的是读取并处理注解的程序，这类程序通常可以称为**注解解析器**。

例如，`@Override` 本身不会检查方法重写，真正执行检查的是编译器；`@Deprecated` 本身不会发出警告，真正发出提示的是编译器或开发工具；框架中的 `@Service`、`@Controller`、`@Test` 等注解，也必须由框架读取并处理后才有实际效果。

一个典型的注解处理流程如下：

1. 在类、方法或属性上添加注解。
2. 编译器、JVM、框架或反射程序读取注解。
3. 注解解析器根据注解信息执行对应逻辑。

例如，一个简单的运行时注解处理过程可以理解为：

```java
Class<?> clazz = UserService.class;

if (clazz.isAnnotationPresent(MyAnnotation.class)) {
    // 读取到指定注解后，执行对应处理逻辑
}
```

这类写法说明，注解要想在运行时发挥作用，通常需要配合反射读取。

> **结论**
>
> 注解本身只负责“标记”，真正起作用的是“读取并解释注解的程序”。没有解析器，注解通常不会产生实际效果。

### 注解的重要性

在 JavaSE 中，注解常用于基础辅助功能，例如编译检查、标记过时、抑制警告和生成文档。

常见内置注解包括：

```java
@Override
```

用于检查方法是否正确重写。

```java
@Deprecated
```

用于标记类、方法或构造方法已经过时，不推荐继续使用。

```java
@SuppressWarnings
```

用于抑制编译器产生的某些警告。

这些注解的使用相对简单，主要作用是辅助编译器或开发工具进行检查和提示。

在 JavaEE 和主流框架中，注解的作用更加重要。大量框架使用注解替代传统 XML 配置，从而减少重复配置，提高开发效率。

例如：

```java
@Service
public class UserService {
}
```

框架扫描到 `@Service` 后，可以把 `UserService` 识别为业务组件，并交给容器管理。再如：

```java
@Test
public void testLogin() {
}
```

测试框架扫描到 `@Test` 后，可以自动执行该测试方法。

这些功能的底层通常离不开反射。框架会扫描类路径，获取类、方法或属性上的注解，再根据注解信息创建对象、调用方法或完成依赖注入等操作。

因此，注解在现代 Java 开发中非常重要。很多框架的核心机制都可以概括为：

```java
框架 = 反射 + 注解 + 设计模式
```

这句话并不是严格定义，而是对框架底层常见实现思想的概括：反射负责动态获取和操作类结构，注解负责提供元数据信息，设计模式负责组织整体架构和扩展方式。

## Java 内置注解

Java 内置注解是 JDK 已经提供好的常用注解，主要用于辅助编译检查、标记过时 API、抑制警告以及约束函数式接口。它们本身不负责执行业务逻辑，而是由编译器、开发工具或相关程序读取后产生对应效果。

常见内置注解包括 `@Deprecated`、`@Override`、`@SuppressWarnings` 和 `@FunctionalInterface`。

> **注意**
>
> 这几个注解的主要作用大多体现在编译检查和开发提示阶段，但它们的保留策略并不完全相同。例如 `@Override` 和 `@SuppressWarnings` 只保留在源码阶段，而 `@Deprecated` 和 `@FunctionalInterface` 可以保留到运行时。

### @Deprecated

`@Deprecated` 用于标记已经过时、不推荐继续使用的程序元素。它可以修饰类、方法、构造方法、属性、参数、局部变量、包、模块等。

被 `@Deprecated` 标记的元素仍然可以使用，但编译器或开发工具会给出警告，提示开发者该 API 已经过时，应优先使用替代方案。

例如：

```java
@Deprecated
public class OldUserService {

    @Deprecated
    public String serviceName;

    @Deprecated
    public OldUserService() {
    }

    @Deprecated
    public void saveUser() {
        System.out.println("old save user");
    }
}
```

当其他代码继续使用这个类、构造方法、属性或方法时，开发工具通常会用删除线或警告信息提示该元素已经过时。

```java
OldUserService service = new OldUserService();
service.serviceName = "userService";
service.saveUser();
```

`@Deprecated` 的作用不是禁止使用，而是提醒开发者：该元素已经不推荐使用，未来可能被替代，甚至可能被删除。

#### since 和 forRemoval

从较新版本的 JDK 开始，`@Deprecated` 中提供了两个属性：

```java
String since() default "";
boolean forRemoval() default false;
```

`since` 用于说明该元素从哪个版本开始被标记为过时；`forRemoval` 用于说明该元素未来是否可能被移除。

例如：

```java
@Deprecated(since = "2.0", forRemoval = true)
public void oldMethod() {
}
```

这表示 `oldMethod()` 从 `2.0` 版本开始过时，并且未来可能被移除。

> **补充**
>
> 注解中的 `since()` 和 `forRemoval()` 虽然后面带有小括号，但它们表示的是注解的属性。`default` 后面的值表示属性的默认值。

### @Override

`@Override` 用于标记一个方法是重写父类或接口中的方法。它只能修饰方法。

例如：

```java
class Animal {
    public void eat() {
        System.out.println("animal eat");
    }
}

class Dog extends Animal {
    @Override
    public void eat() {
        System.out.println("dog eat");
    }
}
```

`@Override` 的核心作用是让编译器检查当前方法是否真的构成重写。如果方法并没有正确重写父类或接口中的方法，编译器会直接报错。

例如：

```java
class Animal {
    public void eat() {
        System.out.println("animal eat");
    }
}

class Dog extends Animal {
    @Override
    public void eet() {
        System.out.println("dog eat");
    }
}
```

这段代码中，`eet()` 方法名写错了，并没有重写父类的 `eat()` 方法。由于添加了 `@Override`，编译器会发现问题并报错。

如果不写 `@Override`，这个错误可能不会在第一时间暴露，程序会把 `eet()` 当作子类新增的方法处理，导致运行结果不符合预期。

> **结论**
>
> 重写方法时建议始终添加 `@Override`。它可以让编译器帮助检查重写是否正确，避免因为方法名、参数列表等细节写错而产生隐蔽错误。

### @SuppressWarnings

`@SuppressWarnings` 用于抑制编译器警告。它可以修饰类、方法、构造方法、属性、局部变量等。

当代码中存在某些编译警告，但开发者确认这些警告可以接受时，可以使用 `@SuppressWarnings` 进行抑制。

例如：

```java
@SuppressWarnings("unused")
int count = 10;
```

这表示抑制“变量未使用”的警告。

再如：

```java
@SuppressWarnings("rawtypes")
List list = new ArrayList();
```

这表示抑制使用原始类型 `List` 时产生的泛型警告。

常见警告类型如下：

| 写法          | 作用                                                       |
| ------------- | ---------------------------------------------------------- |
| `unchecked`   | 抑制未检查类型转换相关警告                                 |
| `unused`      | 抑制变量、方法等未使用的警告                               |
| `resource`    | 抑制资源未关闭相关警告                                     |
| `deprecation` | 抑制使用过时 API 的警告                                    |
| `fallthrough` | 抑制 `switch` 分支缺少 `break` 的警告                      |
| `serial`      | 抑制实现 `Serializable` 但未声明 `serialVersionUID` 的警告 |
| `rawtypes`    | 抑制使用原始泛型类型的警告                                 |
| `all`         | 抑制所有类型警告                                           |

`@SuppressWarnings` 的属性名是 `value`，当注解中只有 `value` 一个属性需要赋值时，可以省略 `value =`。

下面几种写法含义相近：

```java
@SuppressWarnings(value = "all")
@SuppressWarnings("all")
@SuppressWarnings(value = {"all"})
@SuppressWarnings({"all"})
```

如果要抑制多种警告，可以写成数组形式：

```java
@SuppressWarnings({"unused", "rawtypes"})
public void test() {
    List list = new ArrayList();
    int number = 10;
}
```

> **易错点**
>
> `@SuppressWarnings` 不应该被滥用。实际开发中，如果警告可以通过改进代码解决，应优先修改代码；只有在确认警告无实际风险，或当前阶段无法避免时，才考虑抑制警告。

### @FunctionalInterface

`@FunctionalInterface` 是 JDK 1.8 引入的注解，用于标记函数式接口。

函数式接口的要求是：**接口中有且只能有一个抽象方法**。

例如：

```java
@FunctionalInterface
public interface Task {
    void execute();
}
```

这个接口中只有一个抽象方法 `execute()`，因此它是一个函数式接口。

函数式接口中可以定义默认方法和静态方法，因为它们不是抽象方法，不会破坏“只有一个抽象方法”的要求。

```java
@FunctionalInterface
public interface Task {

    void execute();

    default void printInfo() {
        System.out.println("task info");
    }

    static void help() {
        System.out.println("task help");
    }
}
```

如果在函数式接口中再添加一个抽象方法，就会编译失败：

```java
@FunctionalInterface
public interface Task {

    void execute();

    void stop();
}
```

这段代码中，`execute()` 和 `stop()` 都是抽象方法，不符合函数式接口的要求，因此编译器会报错。

> **结论**
>
> `@FunctionalInterface` 的作用是让编译器检查接口是否符合函数式接口规范。它不是创建函数式接口的必要条件，但添加后可以提高代码的准确性和可读性。

### 内置注解对比

| 注解                   | 主要作用                         | 常用位置                   | 主要处理者                 |
| ---------------------- | -------------------------------- | -------------------------- | -------------------------- |
| `@Deprecated`          | 标记过时元素，提示不推荐继续使用 | 类、方法、构造方法、属性等 | 编译器、开发工具、文档工具 |
| `@Override`            | 检查方法是否正确重写             | 方法                       | 编译器                     |
| `@SuppressWarnings`    | 抑制编译器警告                   | 类、方法、变量等           | 编译器                     |
| `@FunctionalInterface` | 检查接口是否符合函数式接口规范   | 接口                       | 编译器                     |

## 自定义注解

自定义注解用于定义符合业务或框架需要的元数据标记。它本身不直接执行逻辑，通常需要配合编译器、注解处理器或反射程序读取后，才能产生实际效果。

### 注解的定义

Java 中定义不同类型时使用的关键字不同：定义类使用 `class`，定义接口使用 `interface`，定义枚举使用 `enum`，定义注解使用 `@interface`。

自定义注解的基本语法如下：

```java
[修饰符] @interface 注解名称 {
    // 注解属性
}
```

例如：

```java
public @interface Log {
}
```

这段代码定义了一个名为 `Log` 的注解。注解也是一种 Java 类型，编译后会生成对应的 `.class` 文件。

定义好的注解可以使用在程序结构上：

```java
@Log
public class UserService {

    @Log
    private String serviceName;

    @Log
    public UserService() {
    }

    @Log
    public void saveUser() {
        System.out.println("save user");
    }
}
```

如果一个注解没有使用 `@Target` 限制可用位置，那么它默认可以出现在常见的声明位置上，例如类、属性、构造方法、方法、参数等位置。

> **补充**
>
> `@Target` 是元注解，用于限制注解能写在哪里。没有学习元注解之前，只需要先理解：默认情况下，自定义注解不主动限制使用位置。

### 注解属性的定义

注解中可以定义属性。注解属性也常被称为注解元素。

注解属性的语法比较特殊，它不是普通成员变量，而是以“无参数方法”的形式声明：

```java
public @interface UserInfo {
    int id();
    String name();
    double[] scores();
}
```

其中：

```java
int id();
```

表示定义了一个名为 `id` 的属性，属性类型是 `int`。

```java
String name();
```

表示定义了一个名为 `name` 的属性，属性类型是 `String`。

```java
double[] scores();
```

表示定义了一个名为 `scores` 的属性，属性类型是 `double[]`。

> **易错点**
>
> 注解属性虽然写法像无参数方法，但使用时应理解为注解中的配置项。方法名表示属性名，返回值类型表示属性类型。

#### 注解属性允许的类型

注解属性的类型不是任意类型。常见允许类型包括：

| 类型           | 示例                                     |
| -------------- | ---------------------------------------- |
| 基本数据类型   | `int`、`double`、`boolean`               |
| `String`       | `String name()`                          |
| `Class`        | `Class<?> type()`                        |
| 枚举类型       | `Season season()`                        |
| 注解类型       | `OtherAnnotation value()`                |
| 以上类型的数组 | `String[] names()`、`Class<?>[] types()` |

例如：

```java
public enum Season {
    SPRING, SUMMER, AUTUMN, WINTER
}
public @interface Config {
    String name();
    int age();
    boolean enabled();
    Season season();
    Class<?> type();
    String[] tags();
}
```

不允许把普通对象类型作为注解属性类型，例如：

```java
public class Student {
}
```

下面这种写法是错误的：

```java
public @interface Config {
    Student student(); // 编译错误
    Object object();   // 编译错误
}
```

原因是注解的属性值需要能以稳定、明确的形式写入注解元数据中，普通对象不符合注解属性的类型要求。

#### 注解属性的赋值

如果注解中定义了属性，并且没有提供默认值，那么使用注解时必须给这些属性赋值。

例如：

```java
public @interface UserInfo {
    int id();
    String name();
    String[] tags();
}
```

使用时需要写成 `属性名 = 属性值` 的形式：

```java
@UserInfo(id = 1001, name = "jack", tags = {"admin", "test"})
public class User {
}
```

多个属性之间使用逗号分隔：

```java
@UserInfo(id = 1002, name = "lucy", tags = {"user", "normal"})
public void save() {
}
```

数组类型的属性使用 `{}` 赋值：

```java
tags = {"admin", "test"}
```

如果数组属性只有一个元素，可以省略大括号：

```java
@UserInfo(id = 1003, name = "tom", tags = "single")
public class Account {
}
```

这等价于：

```java
@UserInfo(id = 1003, name = "tom", tags = {"single"})
public class Account {
}
```

> **易错点**
>
> 如果注解属性没有默认值，使用注解时必须显式赋值；否则编译无法通过。

#### 注解属性的默认值

注解属性可以使用 `default` 指定默认值。

例如：

```java
public @interface UserInfo {
    int id() default -1;
    String name() default "unknown";
    String[] tags() default {};
}
```

有默认值后，使用注解时可以不写这些属性：

```java
@UserInfo
public class User {
}
```

也可以只覆盖其中一部分属性：

```java
@UserInfo(id = 1001)
public class AdminUser {
}
```

这表示 `id` 使用显式传入的 `1001`，而 `name` 和 `tags` 继续使用默认值。

如果一个注解中有些属性有默认值，有些属性没有默认值，那么没有默认值的属性仍然必须赋值。

```java
public @interface Table {
    String name();
    String comment() default "";
}
```

使用时：

```java
@Table(name = "tb_user")
public class User {
}
```

这里 `name` 没有默认值，所以必须赋值；`comment` 有默认值，可以省略。

#### value 属性的简写

`value` 是注解中一个特殊的属性名。

如果注解中只有一个属性，并且这个属性名正好叫 `value`，那么使用注解时可以省略 `value =`，直接写属性值。

例如：

```java
public @interface Alias {
    String value();
}
```

完整写法：

```java
@Alias(value = "userService")
public class UserService {
}
```

简写形式：

```java
@Alias("userService")
public class UserService {
}
```

这两种写法完全等价。

如果 `value` 是数组类型，也可以使用类似规则：

```java
public @interface Roles {
    String[] value();
}
```

完整写法：

```java
@Roles(value = {"admin", "user"})
public class AccountService {
}
```

简写形式：

```java
@Roles({"admin", "user"})
public class AccountService {
}
```

如果数组中只有一个元素，还可以继续省略大括号：

```java
@Roles("admin")
public class AdminService {
}
```

这等价于：

```java
@Roles({"admin"})
public class AdminService {
}
```

> **结论**
>
> 只有当注解属性名为 `value` 时，使用注解才可以省略 `value =`。如果属性名不是 `value`，不能省略属性名。

#### value 属性简写的限制

`value` 属性的简写有明确限制。

如果注解中只有一个属性，但属性名不是 `value`，不能省略属性名：

```java
public @interface Alias {
    String name();
}
```

使用时必须写：

```java
@Alias(name = "userService")
public class UserService {
}
```

不能写成：

```java
@Alias("userService") // 编译错误
public class UserService {
}
```

如果注解中除了 `value` 之外还有其他没有默认值的属性，也不能只写一个值了事。

```java
public @interface Mapping {
    String value();
    String method();
}
```

使用时必须把没有默认值的属性都写出来：

```java
@Mapping(value = "/user", method = "GET")
public void queryUser() {
}
```

如果其他属性有默认值，则仍然可以只简写 `value`：

```java
public @interface Mapping {
    String value();
    String method() default "GET";
}
@Mapping("/user")
public void queryUser() {
}
```

### 自定义注解的使用流程

自定义注解的一般使用流程如下：

1. 使用 `@interface` 定义注解。
2. 在注解中按需定义属性。
3. 使用注解时为没有默认值的属性赋值。
4. 通过编译器、注解处理器或反射程序读取注解。
5. 根据注解信息执行对应处理逻辑。

例如：

```java
public @interface Route {
    String value();
    String method() default "GET";
}
public class UserController {

    @Route(value = "/user/list", method = "GET")
    public void listUsers() {
        System.out.println("query user list");
    }
}
```

这类写法本身只是把路径和请求方式作为元数据标记在方法上。只有当框架或程序读取 `@Route` 并解析其中的属性后，才会真正根据这些信息完成请求映射等处理。

## Java 的元注解

元注解是**修饰注解的注解**。普通注解用于标记类、方法、属性等程序结构，而元注解用于规定一个注解本身的使用规则，例如：注解保留到哪个阶段、能写在哪些位置、是否进入 JavaDoc 文档、是否能被子类继承等。

Java 中常见元注解包括 `@Retention`、`@Target`、`@Documented`、`@Inherited` 和 `@Repeatable`。

### @Retention

`@Retention` 用于指定注解的**保留阶段**。也就是说，它决定一个注解会被保留到源码阶段、字节码阶段，还是运行时阶段。

`@Retention` 的取值由 `RetentionPolicy` 枚举表示，常见取值如下：

| 取值                      | 含义                                                 |
| ------------------------- | ---------------------------------------------------- |
| `RetentionPolicy.SOURCE`  | 注解只保留在源代码中，编译后不会进入 `.class` 文件   |
| `RetentionPolicy.CLASS`   | 注解会进入 `.class` 文件，但运行时不能通过反射获取   |
| `RetentionPolicy.RUNTIME` | 注解会进入 `.class` 文件，并且运行时可以通过反射获取 |

如果一个注解没有显式使用 `@Retention` 指定保留策略，默认保留策略是 `RetentionPolicy.CLASS`。

例如：

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface Config {
    String value();
}
```

这表示 `@Config` 注解会保留到运行时，因此可以通过反射读取。

```java
@Config("userService")
public class UserService {
}
```

运行时读取注解：

```java
public class Test {
    public static void main(String[] args) {
        Class<UserService> clazz = UserService.class;

        if (clazz.isAnnotationPresent(Config.class)) {
            Config config = clazz.getAnnotation(Config.class);
            System.out.println(config.value());
        }
    }
}
```

如果 `@Config` 的保留策略是 `SOURCE` 或 `CLASS`，上述运行时反射代码就无法正常读取该注解。

> **结论**
>
> 如果自定义注解需要在运行时通过反射读取，必须使用 `@Retention(RetentionPolicy.RUNTIME)`。

### @Target

`@Target` 用于指定注解可以使用的位置。它的取值由 `ElementType` 枚举表示。

常见取值如下：

| 取值                          | 可修饰位置                                           |
| ----------------------------- | ---------------------------------------------------- |
| `ElementType.TYPE`            | 类、接口、枚举、注解                                 |
| `ElementType.FIELD`           | 属性、枚举常量                                       |
| `ElementType.METHOD`          | 方法                                                 |
| `ElementType.PARAMETER`       | 方法参数                                             |
| `ElementType.CONSTRUCTOR`     | 构造方法                                             |
| `ElementType.LOCAL_VARIABLE`  | 局部变量                                             |
| `ElementType.ANNOTATION_TYPE` | 注解                                                 |
| `ElementType.PACKAGE`         | 包                                                   |
| `ElementType.TYPE_PARAMETER`  | 类型参数，例如泛型类、泛型接口、泛型方法中的类型变量 |
| `ElementType.TYPE_USE`        | 任意类型使用处                                       |

例如，定义一个只能写在类和方法上的注解：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Log {
    String value() default "";
}
```

使用时：

```java
@Log("service class")
public class OrderService {

    @Log("create order")
    public void createOrder() {
        System.out.println("create order");
    }
}
```

如果把 `@Log` 写在属性上，就会编译失败：

```java
public class OrderService {

    @Log("field") // 编译错误：@Log 不允许写在属性上
    private String name;
}
```

`@Target` 的作用是限制注解的使用范围，使注解语义更清晰，也能让编译器提前检查错误用法。

> **结论**
>
> `@Target` 解决的是“注解能写在哪里”的问题。定义自定义注解时，通常应根据注解语义明确限制它的使用位置。

### @Documented

`@Documented` 用于指定一个注解是否会出现在 JavaDoc 生成的 API 文档中。

默认情况下，注解不一定会被 JavaDoc 工具展示。如果一个注解使用了 `@Documented` 标记，那么当被它修饰的类、方法等生成 API 文档时，这个注解信息也会进入文档。

例如：

```java
import java.lang.annotation.Documented;
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

@Documented
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface ApiInfo {
    String value();
}
```

使用该注解：

```java
@ApiInfo("用户业务类")
public class UserService {

    @ApiInfo("保存用户")
    public void saveUser() {
        System.out.println("save user");
    }
}
```

使用 JavaDoc 工具生成文档时，`@ApiInfo` 的信息可以出现在对应的 API 文档中。

`@Documented` 本身不会影响程序运行，也不会改变注解的反射读取能力。它只影响 API 文档生成结果。

> **注意**
>
> `@Documented` 只控制注解是否进入 JavaDoc 文档，不控制注解是否保留到运行时。运行时能否通过反射读取注解，取决于 `@Retention`。

### @Inherited

`@Inherited` 用于表示某个注解是否可以被子类继承。

如果一个注解被 `@Inherited` 标记，并且这个注解标注在父类上，那么子类在没有显式声明该注解的情况下，也可以通过反射获取到这个注解。

例如：

```java
import java.lang.annotation.Inherited;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Inherited
@Retention(RetentionPolicy.RUNTIME)
public @interface Role {
    String value();
}
```

父类使用注解：

```java
@Role("base")
public class BaseService {
}
```

子类继承父类：

```java
public class UserService extends BaseService {
}
```

通过反射读取子类注解：

```java
public class Test {
    public static void main(String[] args) {
        Class<UserService> clazz = UserService.class;

        Role role = clazz.getAnnotation(Role.class);
        System.out.println(role.value());
    }
}
```

虽然 `UserService` 本身没有直接写 `@Role`，但由于 `@Role` 被 `@Inherited` 标记，并且父类 `BaseService` 使用了 `@Role`，因此子类可以通过反射读取到继承而来的注解。

`@Inherited` 有几个重要边界：

1. 它只对**类继承**有效。
2. 它不作用于接口实现。
3. 它不作用于方法、属性、构造方法等成员。
4. 它通常需要配合 `@Retention(RetentionPolicy.RUNTIME)`，否则运行时反射无法读取。

例如，父接口上标注了某个被 `@Inherited` 修饰的注解，实现类并不会因此自动继承该注解。

> **易错点**
>
> `@Inherited` 的“继承”只适用于类上的注解继承，不表示方法、属性或接口上的注解也会被继承。

### @Repeatable

`@Repeatable` 是 JDK 1.8 引入的元注解，用于支持**重复注解**。它允许同一个注解在同一个位置上使用多次。

在 JDK 1.8 之前，如果需要给同一个元素配置多个同类注解，通常需要使用数组属性。JDK 1.8 之后，可以通过 `@Repeatable` 让多个相同注解直接重复书写。

定义可重复注解时，需要同时定义两个注解：

1. 被重复使用的注解；
2. 用于容纳多个重复注解的容器注解。

例如：

```java
import java.lang.annotation.Repeatable;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Repeatable(Routes.class)
@Retention(RetentionPolicy.RUNTIME)
public @interface Route {
    String value();
}
```

容器注解：

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface Routes {
    Route[] value();
}
```

使用重复注解：

```java
@Route("/user/list")
@Route("/user/detail")
public class UserController {
}
```

这表示 `UserController` 同时配置了两个 `@Route` 注解。

读取时可以使用：

```java
public class Test {
    public static void main(String[] args) {
        Route[] routes = UserController.class.getAnnotationsByType(Route.class);

        for (Route route : routes) {
            System.out.println(route.value());
        }
    }
}
```

输出结果：

```java
/user/list
/user/detail
```

`@Repeatable` 的意义是让同类配置可以直接重复书写，代码可读性更强。

> **注意**
>
> 可重复注解必须指定容器注解，容器注解中必须有一个返回重复注解数组的 `value()` 属性。

### 元注解之间的关系

不同元注解解决的问题不同。

| 元注解        | 解决的问题                           |
| ------------- | ------------------------------------ |
| `@Retention`  | 注解保留到哪个阶段                   |
| `@Target`     | 注解可以写在哪些位置                 |
| `@Documented` | 注解是否进入 JavaDoc 文档            |
| `@Inherited`  | 类上的注解是否能被子类继承           |
| `@Repeatable` | 同一个注解是否可以在同一位置重复使用 |

这些元注解可以组合使用。例如：

```java
import java.lang.annotation.Documented;
import java.lang.annotation.ElementType;
import java.lang.annotation.Inherited;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Documented
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Component {
    String value() default "";
}
```

这表示 `@Component`：

1. 可以写在类、接口、枚举、注解上；
2. 会保留到运行时；
3. 可以进入 JavaDoc 文档；
4. 标注在父类上时，可以被子类继承。

## 反射中注解的使用

注解本身只是代码中的元数据标记。若要在程序运行期间读取注解，并根据注解内容执行逻辑，就需要配合反射使用。

通过反射读取注解有两个基本前提：注解必须使用 `@Retention(RetentionPolicy.RUNTIME)` 保留到运行时；注解必须通过 `@Target` 允许写在对应位置上，例如类、属性或方法。否则，即使代码中写了注解，运行时反射也可能无法读取。

### 反射读取注解的前提

如果希望运行时通过反射读取类、属性或方法上的注解，定义注解时必须设置运行时保留策略：

```java
@Retention(RetentionPolicy.RUNTIME)
```

如果注解只保留到源码阶段或字节码阶段，运行时反射无法获取。例如：

```java
@Retention(RetentionPolicy.SOURCE)
```

表示注解只存在于源代码中，编译后不会进入 `.class` 文件。

```java
@Retention(RetentionPolicy.CLASS)
```

表示注解会进入 `.class` 文件，但运行时不能通过普通反射获取。

只有：

```java
@Retention(RetentionPolicy.RUNTIME)
```

表示注解会保留到运行时，可以被反射读取。

同时，注解还需要通过 `@Target` 指定可使用位置。例如：

```java
@Target(ElementType.TYPE)
```

表示该注解可以写在类、接口、枚举或注解上。

```java
@Target(ElementType.FIELD)
```

表示该注解可以写在属性上。

```java
@Target(ElementType.METHOD)
```

表示该注解可以写在方法上。

### 反射读取注解的常用方法

类、属性、方法、构造方法等反射对象都可以读取注解。常用方法如下：

| 方法                                              | 作用                                 |
| ------------------------------------------------- | ------------------------------------ |
| `getAnnotations()`                                | 获取当前元素上所有可读取的公开注解   |
| `getDeclaredAnnotations()`                        | 获取当前元素上直接声明的所有注解     |
| `isAnnotationPresent(Class<A> annotationClass)`   | 判断当前元素上是否存在指定注解       |
| `getAnnotation(Class<A> annotationClass)`         | 获取当前元素上的指定注解对象         |
| `getDeclaredAnnotation(Class<A> annotationClass)` | 获取当前元素上直接声明的指定注解对象 |

如果只是想判断某个注解是否存在，使用 `isAnnotationPresent()`；如果想读取注解中的属性值，使用 `getAnnotation()` 获取注解对象后，再调用注解属性方法。

例如：

```java
if (clazz.isAnnotationPresent(Table.class)) {
    Table table = clazz.getAnnotation(Table.class);
    System.out.println(table.value());
}
```

这段代码中，`table.value()` 并不是调用普通方法，而是在读取注解中的 `value` 属性值。

#### 获取类上的注解

读取类上的注解时，需要先获取类对应的 `Class` 对象，再通过 `Class` 对象获取注解。

例如，定义一个用于标记数据库表名的注解：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Table {
    int id() default 0;
    String value();
}
```

定义一个使用注解的类：

```java
@Table(id = 1001, value = "tb_user")
public class User {
}
```

通过反射读取类上的注解：

```java
public class AnnotationReadTest {
    public static void main(String[] args) {
        Class<User> clazz = User.class;

        if (clazz.isAnnotationPresent(Table.class)) {
            Table table = clazz.getAnnotation(Table.class);

            System.out.println("id = " + table.id());
            System.out.println("value = " + table.value());
        }
    }
}
```

执行结果：

```java
id = 1001
value = tb_user
```

这类写法的核心流程是：

1. 通过 `User.class` 获取 `Class` 对象。
2. 使用 `isAnnotationPresent(Table.class)` 判断类上是否存在 `@Table`。
3. 使用 `getAnnotation(Table.class)` 获取注解对象。
4. 通过 `table.id()` 和 `table.value()` 读取注解属性值。

如果需要获取类上的全部注解，可以使用：

```java
Annotation[] annotations = clazz.getAnnotations();

for (Annotation annotation : annotations) {
    System.out.println(annotation);
}
```

不过，直接获取所有注解通常只能整体查看注解信息；如果要读取某个注解中的具体属性值，更常用的做法是获取指定注解对象。

#### 获取属性上的注解

读取属性上的注解时，需要先通过 `Class` 获取对应的 `Field` 对象，再通过 `Field` 读取注解。

例如，定义一个用于描述字段信息的注解：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Column {
    String value();
    boolean required() default false;
}
```

定义一个使用字段注解的类：

```java
public class User {

    @Column(value = "user_name", required = true)
    private String username;

    @Column("age")
    private int age;
}
```

通过反射读取属性上的注解：

```java
import java.lang.reflect.Field;

public class AnnotationReadTest {
    public static void main(String[] args) throws NoSuchFieldException {
        Class<User> clazz = User.class;

        Field field = clazz.getDeclaredField("username");

        if (field.isAnnotationPresent(Column.class)) {
            Column column = field.getAnnotation(Column.class);

            System.out.println("value = " + column.value());
            System.out.println("required = " + column.required());
        }
    }
}
```

执行结果：

```java
value = user_name
required = true
```

这里需要注意，`getDeclaredField("username")` 可以获取当前类中声明的指定属性，即使该属性是 `private`。读取属性上的注解不需要调用 `setAccessible(true)`，因为这里只是读取属性的注解信息，不是读写属性值。

> **易错点**
>
> `setAccessible(true)` 用于突破访问权限读写私有属性或调用私有方法；如果只是读取私有属性上的注解，通常不需要设置访问权限。

如果要读取属性上的全部注解，可以使用：

```java
Annotation[] annotations = field.getAnnotations();

for (Annotation annotation : annotations) {
    System.out.println(annotation);
}
```

但实际开发中更常见的是读取指定注解，并解析其中属性值。

#### 获取方法上的注解

读取方法上的注解时，需要先通过 `Class` 获取对应的 `Method` 对象，再通过 `Method` 读取注解。

例如，定义一个用于标记方法路径的注解：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Route {
    String value();
    String method() default "GET";
}
```

定义一个使用方法注解的类：

```java
public class UserController {

    @Route(value = "/user/list", method = "GET")
    public void listUsers(String keyword) {
        System.out.println("list users: " + keyword);
    }
}
```

通过反射读取方法上的注解：

```java
import java.lang.reflect.Method;

public class AnnotationReadTest {
    public static void main(String[] args) throws NoSuchMethodException {
        Class<UserController> clazz = UserController.class;

        Method method = clazz.getDeclaredMethod("listUsers", String.class);

        if (method.isAnnotationPresent(Route.class)) {
            Route route = method.getAnnotation(Route.class);

            System.out.println("value = " + route.value());
            System.out.println("method = " + route.method());
        }
    }
}
```

执行结果：

```java
value = /user/list
method = GET
```

获取方法时，如果方法有参数，必须写清楚参数类型：

```java
clazz.getDeclaredMethod("listUsers", String.class);
```

如果方法没有参数，则写成：

```java
clazz.getDeclaredMethod("listUsers");
```

这与前面反射获取方法的规则一致。方法重载时，方法名相同，参数列表不同，反射必须依靠参数类型定位具体方法。

> **易错点**
>
> 通过反射获取方法注解时，必须先正确获取目标 `Method` 对象。若方法存在参数或重载，`getDeclaredMethod()` 的参数类型必须写准确。

#### 获取注解属性值

注解对象获取后，可以通过调用注解属性方法读取属性值。

例如：

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Module {
    String name();
    String[] authors();
}
```

使用注解：

```java
@Module(name = "用户模块", authors = {"jack", "lucy"})
public class UserModule {
}
```

读取属性值：

```java
import java.util.Arrays;

public class AnnotationReadTest {
    public static void main(String[] args) {
        Class<UserModule> clazz = UserModule.class;

        Module module = clazz.getAnnotation(Module.class);

        System.out.println(module.name());
        System.out.println(Arrays.toString(module.authors()));
    }
}
```

执行结果：

```java
用户模块
[jack, lucy]
```

数组类型属性读取后得到的是数组。如果需要直接打印数组内容，通常使用 `Arrays.toString()`，否则直接输出数组对象会得到类似地址形式的结果。

### getAnnotations 和 getDeclaredAnnotations 的区别

`getAnnotations()` 和 `getDeclaredAnnotations()` 都可以获取注解数组，但含义不同。

| 方法                       | 含义                                                         |
| -------------------------- | ------------------------------------------------------------ |
| `getAnnotations()`         | 获取当前元素上可读取的注解，类上可能包含通过 `@Inherited` 继承来的注解 |
| `getDeclaredAnnotations()` | 只获取当前元素上直接声明的注解                               |

例如，父类上有一个可以继承的注解：

```java
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Role {
    String value();
}
```

父类使用注解：

```java
@Role("base")
public class BaseService {
}
```

子类没有显式使用注解：

```java
public class UserService extends BaseService {
}
```

读取子类注解：

```java
System.out.println(UserService.class.getAnnotations().length);
System.out.println(UserService.class.getDeclaredAnnotations().length);
```

`getAnnotations()` 可以读取继承来的 `@Role`，而 `getDeclaredAnnotations()` 只读取 `UserService` 自己声明的注解。

> **注意**
>
> `@Inherited` 只对类上的注解继承有效，不适用于属性、方法和接口实现。

### 反射解析注解的基本流程

反射解析注解的基本流程可以总结为：

1. 定义注解，并设置 `@Retention(RetentionPolicy.RUNTIME)`。
2. 使用 `@Target` 指定注解可出现的位置。
3. 在类、属性或方法上使用注解。
4. 通过反射获取对应结构对象，例如 `Class`、`Field`、`Method`。
5. 使用 `isAnnotationPresent()` 判断是否存在指定注解。
6. 使用 `getAnnotation()` 获取注解对象。
7. 调用注解属性方法读取配置值。
8. 根据注解配置执行后续逻辑。

核心代码模式如下：

```java
if (element.isAnnotationPresent(MyAnnotation.class)) {
    MyAnnotation annotation = element.getAnnotation(MyAnnotation.class);

    // 读取注解属性
    String value = annotation.value();

    // 根据注解属性执行后续逻辑
}
```

其中，`element` 可以是 `Class`、`Field`、`Method`、`Constructor` 等反射对象。
