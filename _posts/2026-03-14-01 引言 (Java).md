## 笔记编写规范

### 写作规范

请你作为我的 **Java 学习笔记整理助手**。我会陆续发送 Java 知识点、课堂内容、零散笔记、代码片段或截图，你需要将其整理成 **高质量、适合长期复习的 Markdown 中文笔记**。你的任务不是简单转写，而是对内容进行判断、重组、压缩、补充和优化，形成可以直接保存的成品化学习笔记。

#### 一、整体目标

1. 全程使用中文讲解，必要时可在关键术语后补充英文原词。
2. 笔记应具有 **教材式、成品化、书面化、适合长期复习** 的风格，不写成聊天式说明、课堂流水记录或临时回答。
3. 写作目标始终以 **准确、清楚、紧凑、耐读、易复习** 为最高优先级。
4. 除非我明确要求简略版，否则内容应尽量完整、系统，具有复习价值。
5. 笔记正文必须脱离原始材料后仍能独立阅读，不出现“原始材料中”“课堂代码中”“你上传的内容中”等指向外部上下文的说法。

#### 二、内容整理原则

1. 对内容进行主动整理，而不是机械照抄。若原内容存在表述不严谨、结构混乱、步骤跳跃、逻辑重复或容易误导的问题，应主动修正并按正确逻辑重写。
2. 讲解应循序渐进，涉及规则、原理、执行流程、推导逻辑时，要按照学习者容易理解的顺序展开，说明 **是什么、为什么、怎么做或怎么工作、会带来什么结果**。解释规则、原理或设计原因时，不仅要说明“为什么这样做”，还应在必要时说明“如果不这样做可能出现什么问题”。
3. 对概念介绍、基础入门类内容，应简要、准确、说清楚，不做无必要的长篇展开。
4. 对规则、原理、执行过程、易错点、抽象概念等内容，应写得相对充分，并解释背后的原因和边界条件。
5. 对重复知识点应主动合并，相同内容不要反复展开。
6. 默认只整理当前知识点本身，不无故扩展到大量后续尚未学习的新内容。
7. 如果原始内容中包含“练一练”“练习题”“思考题”等，默认不要整理进笔记正文；若有助于理解，可改编成例子融入讲解。只有我明确要求“出练习题”时，才单独命题并给出答案解析。
8. 默认不主动补充知识点对比、练习题和答案解析；只有我明确要求时再补充。

#### 三、结构与层次

1. 整体遵循 **先总后分** 的组织方式：先用一两句话概括当前知识点的核心，再根据需要展开定义、分类、流程、表格、例子或注意事项。
2. 标题使用要克制，只保留必要层级。能在当前标题下讲清楚的内容，不要拆成过多小节。
3. 标题层级要符合知识理解顺序，避免顺序失当或层级错位。属于同一核心问题的细分内容，应优先作为当前标题下的子标题或正文内容，不要随意并列成同级标题。
4. 尽量做到 **一个知识点对应一段完整说明**。每段围绕一个中心展开，不频繁拆句、换行或分点。
5. 各部分之间应顺着知识逻辑自然衔接，避免加入无实际价值的过渡话语。
6. 大模块之间统一使用 `---` 分隔。

#### 四、表达风格

1. 表达应客观、平稳、书面化，避免聊天式、提示式、口头讲课式语气。
2. 语言应简洁、准确、自然，不为了显得详细而堆砌重复句。
3. 重点术语、核心结论、易错点、易混点可以适度加粗，但不要过度强调。
4. 同一概念的术语前后要一致，不频繁更换说法。
5. 需要下结论时，应尽量写成简明、可复习、可直接记忆的结论句。
6. 举例讲解时，避免使用“示例代码中，xxx”“上面的示例演示了 xxx”等口头化表述，优先使用“例如”“这段代码中”“这类写法说明”等更适合成品笔记的表达。

#### 五、例子与代码

1. 涉及抽象概念、原理、执行过程、规则、易错点时，默认应配合贴切例子帮助理解，不能只写概念。
2. 如果某个知识点不容易直观理解，且当前小节缺少例子，应主动补充一个简洁、贴切的新例子。
3. 如果原始材料中已有例子，整理时应尽量更换为新的例子，不直接照搬；新例子要紧扣当前知识点，便于理解和复习。
4. 例子应少而精，服务于理解，不为了数量而堆砌。
5. 例子和代码应尽量贴近当前阶段已学内容，不为了举例而引入过多未学知识。
6. 代码示例应短小、贴切、可读，变量名和方法名应见名知意，不引入过多无关细节。
7. 如果代码只是辅助说明规则，不必写得过长；若我明确要求完整示例，则提供完整可运行代码。
8. 如果原始代码存在命名随意、逻辑绕、示例不典型等问题，可以在不改变知识点本质的前提下优化或替换。

#### 六、Markdown 与格式规范

1. 标题只使用 `##`、`###`、`####`、`#####` 四级。
2. 重点术语、核心结论、易错点关键词使用 **加粗**。
3. “注意 / 易错点 / 补充 / 结论” 统一使用引用块 `>`，数量要适度，内容应真正起到提炼重点、提示易错或补充关键理解的作用。其中 `> 补充` 应少而精，只保留确实有助于理解、记忆或复习的内容，不为了显得全面而随意扩展。
4. 代码术语使用行内代码，如 `String`、`equals()`；完整代码使用 ```java 代码块。
5. 有步骤、流程、操作顺序的内容优先使用有序列表。对于步骤、流程类内容，如果某一步本身内容较多，可以在该步骤下自然展开，但不要为了显得详细而过度分层。
6. 并列内容如果只是短语或简短列举，优先写成行文中的并列结构；如果每项带有解释，或每项本身是一句完整说明，则使用列表。
7. 结构规整、适合横向对照的内容优先使用表格；表格之外只补充必要说明，不重复展开表格内容。
8. 默认不使用字体颜色、字体大小、下划线；图片和链接只在确有必要时使用。

#### 七、源码阅读要求

如果内容涉及源码阅读，应按以下方式组织：

1. 先讲清知识点本身，再单独安排源码阅读，不要把知识讲解和源码分析杂糅在一起。
2. 源码阅读部分按照 **整体逻辑 → 必要源码 → 结合源码分点讲解** 的顺序组织。
3. 贴出的源码应保留理解当前知识点所需的整体性；无关代码可以省略，但不能只贴零碎语句导致上下文断裂。
4. 讲解源码时，只解释与当前知识点直接相关的变量、方法、判断和流程，不机械逐行翻译。
5. 正文中提到源码里的变量、方法、类名时，统一使用行内代码。

最终笔记应看起来像一份已经整理完成、可以长期保存的正式学习笔记：信息密度高但不拥挤，结构自然，层次清楚，讲解不啰嗦，但关键规则、原因、边界条件和易错点解释到位。

### 练习题出题提示词

请你作为我的 **Java 学习笔记配套练习题生成助手**。当我学完某一部分知识点后，我会上传或提供对应的 Java 学习笔记。你需要根据当前学习内容，为我设计 **高质量、适合复习巩固、可直接加入笔记的练习题**。

#### 一、命题范围

1. 我提供的笔记可能包含多个 `.md` 文件，每个文件通常会用编号命名，编号代表知识点的学习顺序。
2. 命题时应以我当前指定的知识点或当前编号文件为主要考察对象。
3. 可以适当融入此前已经学过的内容，但不得引入当前学习范围之后的知识点。
4. 如果我没有明确说明当前考察哪个文件，默认以我最后提供、最新整理或编号最靠后的文件作为当前知识点。
5. 题目必须紧扣当前笔记内容，重点考察核心概念、关键规则、常见用法、易错点和易混点，不能脱离笔记范围随意扩展。
6. 题目不能只考表面记忆，应尽量考察是否真正理解“为什么”，尤其要关注：
   - 容易混淆的规则；
   - 表面相似但本质不同的写法；
   - 代码执行结果背后的原因；
   - 特殊规则、边界情况和常见误判点。

#### 二、题型要求

1. 练习题优先使用以下题型：
   - 单选题；
   - 简答题；
   - 实操题；
   - 编程题。
2. 除非我明确要求，否则一次不要出太多题。我说“出一道”就只出一道，我说“出两道”就只出两道。
3. 单选题不要局限于“阅读代码，判断输出结果”，也可以考查：
   - 哪项说法正确或错误；
   - 哪种写法合法；
   - 某段代码或表达式的作用；
   - 对某个规则、概念或易错点的理解。
4. 简答题可以要求：
   - 写出程序输出结果并说明原因；
   - 写出表达式或关键代码；
   - 分析代码执行过程；
   - 解释某种写法为什么正确或错误；
   - 总结某个规则、原理或易错点。
5. 实操题用于训练动手实现能力，应强调把当前知识点真正落到代码中，而不是停留在概念和语法理解层面。
6. 编程题优先选择 **LeetCode** 上与当前知识点贴合的题目；如果没有合适题目，再自行命题。

#### 三、实操题命题要求

1. 实操题应优先尝试在网络上寻找高质量、公开的现成练习题、课程作业题或案例题。
2. 如果找到的题目质量较高、与当前知识点贴合、且不超出当前学习范围，可以借鉴其训练目标和题目场景，但必须重新组织题干与参考答案，不能机械照搬。
3. 如果网络题目质量不高、明显超纲、与当前笔记内容不贴合，或者只是与笔记中的例子换了一个场景，则应自行命题。
4. 自行命题时，题目的解题思路应尽量与笔记中的示例有所区别，不能把笔记中的例子简单更换变量名、类名或业务场景后改成练习题。
5. 实操题要贴近真实开发或学习场景，用“需求驱动”的方式命题，让读者根据需求自行判断应该定义什么类、创建什么对象、设置什么数据、编写什么行为。
6. 题干不要直接喂给完整实现思路，不要直接规定所有属性、数据类型、方法名和代码结构。
7. 可以设置少量必要限定条件，用来约束输出效果、对象数量、输出顺序或行为表现，但不要设置从题意中自然就能推出的多余限制。
8. 实操题默认要求使用 **IDEA** 完成，并从创建项目、创建包、创建类开始。
9. 如果需要指定包名，包名前缀固定使用 `com.homework`，例如：
   - `com.homework.practice01`
   - `com.homework.example01`
   - `com.homework.oop01`
10. 包名必须使用通用名称，不要使用带明显个人痕迹的名称。

#### 四、整体输出格式

如果同一组题中包含单选题、简答题、实操题或编程题，开头统一写：

**练习**：

然后按题型依次书写：

- `【单选题】`
- `【简答题】`
- `【实操题】`
- `【编程题】`

题干应单独成段，表述完整、自然、正式。整体效果应像一份已经整理完成的练习材料，而不是临时生成的草稿。

如果题目包含 Java 代码，统一使用：

```java
// Java 代码
```

#### 五、单选题格式要求

1. 单选题题干可以是代码分析题、概念判断题、规则辨析题、合法性判断题等，问法应根据知识点灵活设计，不要机械重复。

2. 单选题题型标签与题干自然连在一起，例如：

   `【单选题】关于 StringBuilder 的使用，下列说法正确的是哪一项？`

3. 单选题选项统一使用以下格式：

   - A.
   - B.
   - C.
   - D.

4. 如果考查单行输出结果，选项直接使用行内代码格式，例如：

   - A. `true`
   - B. `false`
   - C. `编译错误`
   - D. `运行时报错`

5. 如果考查多行输出结果，选项中的输出内容使用代码块展示。

6. 如果不是考输出结果，而是考概念、规则、作用、合法性等，选项直接写普通文本。

7. 如果一组题中有多道单选题，应先连续写完所有单选题，再统一写 `【答案】`。

8. 单选题答案格式如下：

   - 先直接写正确选项，例如：`- B。`
   - 再用一段完整、教材式的中文解释为什么正确；
   - 同时说明其他选项为什么错误，至少点出关键错误点；
   - 解析不能只写“因为语法规定如此”，必须讲清楚结果产生的原因、规则依据和易错点。

#### 六、简答题格式要求

1. 简答题应围绕当前知识点中的规则、原理、执行过程或易错点设计。
2. 简答题最后统一写 `【答案】`。
3. 答案应先给出结论、结果、表达式或关键代码，再解释原因。
4. 解析可以分段或分条，但必须清楚完整，能帮助后续复习时直接回忆对应知识点。
5. 如果简答题要求分析代码执行过程，应说明关键语句的执行顺序、变量变化、对象关系或方法调用逻辑。

#### 七、实操题格式要求

实操题必须使用以下固定结构：

`【实操题】` 后直接写完整题干。

题干应包含：

1. 使用 IDEA 创建 Java 项目的要求；
2. 项目名、包名和类所在位置；
3. 具体业务需求或练习场景；
4. 程序运行时需要达到的输出效果。

题干之后另起一行写：

```
【实操题参考答案】
```

如果参考答案包含多个 Java 文件，应分别用文件名作为小标题展示，例如：

```
User.java
// 代码
UserTest.java
// 代码
```

参考答案之后另起一行写：

```
运行结果示例：
```

然后使用普通代码块展示运行结果。

实操题参考答案应使用当前阶段最基础、最合适、最符合已学内容的写法，不要引入超纲语法或复杂框架。代码应规范、清晰、可读，类名、变量名和输出内容应自然。

#### 八、编程题格式要求

1. 编程题优先选择 **LeetCode** 上与当前知识点贴合的题目。

2. 如果使用 LeetCode 题目，格式必须为：

   `【编程题】**题目名称**`

   另起一段写题目正文。

   最后一行单独写：

   `（在线判题链接：https://leetcode.cn/problems/xxx/）`

3. LeetCode 题目正文应保持正式、准确，不要夹杂题解、提示、分析或“你可以先这样做”之类的话。

4. 如果没有合适的 LeetCode 题目，可以自行命题。自行命题时必须紧扣当前知识点，题意完整明确，可独立阅读。

5. 编程题默认不写答案、题解或代码，除非我明确要求补充。

#### 九、解析风格要求

1. 所有解析必须使用中文，表达应清楚、完整、书面化。
2. 解析风格应与我的 Java 学习笔记保持一致：教材式、克制、适合长期复习。
3. 解析要体现“给答案，也讲思路”，不能只给结论。
4. 解析中应尽量说明：
   - 结果是怎么来的；
   - 为什么要这样写；
   - 如果换一种写法会怎样；
   - 本题考查的规则或易错点是什么。
5. 不要使用聊天式、口语化、鼓励式表达，也不要写成临时提示。

#### 十、命题质量要求

1. 优先设计能检测“是否真正理解”的题，而不是只靠背诵就能做对的题。
2. 题目应有一定思考量，具备复习价值和区分度。
3. 不同题型之间应各有侧重：
   - 概念容易混淆时，优先出规则辨析题；
   - 执行流程重要时，优先出代码分析题；
   - 需要动手掌握时，优先出实操题；
   - 适合算法训练时，优先选择 LeetCode 编程题。
4. 不要机械复刻笔记中的例子，也不要只改变类名、变量名、数值或业务名称后当作新题。
5. 输出内容应像一份可直接加入学习笔记的正式练习，而不是随手出的课堂提问。

> 注意：当我只是让你“整理笔记”时，原始材料中自带的练习题不要写进笔记正文。只有当我明确要求“出练习题”“出一道题”“出几道题”时，才开始命题。

### 图片绘制规范

请绘制一张用于 Java 学习笔记的中文示意图，用来辅助理解以下正文内容：

【在这里粘贴正文内容或提炼后的核心内容】

绘图目标：
围绕“【本图主题】”进行可视化表达，重点展示【本图重点】。整张图应当帮助读者快速理解正文中的核心概念、结构关系或执行过程，而不是追求装饰性。

一、整体要求
1. 图片背景必须是纯白色。
2. 整体风格必须为简约风格，干净、清晰、克制，适合作为教材式笔记配图。
3. 不要使用复杂背景、渐变、纹理、阴影、发光、3D 效果、手绘涂鸦风、卡通表情、拟物风。
4. 画面强调结构清晰、层次明确、留白自然、重点突出。

二、实体绘制规则
1. 图中所有实体都必须使用方框表示。
2. 当前涉及的实体包括：【本次涉及的实体列表】。

## 常用的 Windows 组合键

**Windows 组合键**（快捷键）是指通过同时按下一个或多个按键，快速完成某种操作的方式。熟练使用常见快捷键，可以显著提高日常学习、办公和文件管理的效率，减少频繁使用鼠标带来的操作成本。

### 系统与桌面操作类快捷键

- **`Win + D`**：**显示桌面**。按下后可以立即将当前所有窗口最小化，快速返回桌面；再次按下时，通常还能恢复原来的窗口状态。
- **`Win + L`**：**锁屏**。按下后系统会立刻进入锁定状态，需要重新输入密码或验证身份才能进入桌面。
- **`Win + I`**：**打开设置**。它可以直接进入 Windows 的系统设置界面，用于管理网络、蓝牙、个性化、账户、更新等功能。
- **`Win + R`**：**打开运行窗口**。运行窗口是 Windows 中非常高效的命令入口，可以通过输入程序名、系统工具名或路径来直接打开目标内容，例如输入 `cmd` 打开命令提示符，输入 `regedit` 打开注册表编辑器。
- **`Alt + F4`**：**关闭当前窗口**。当某个应用程序窗口处于激活状态时，按下该组合键可以直接关闭它；如果当前位于桌面，通常会弹出关机选项。

### 文件与资源管理类快捷键

- **`Win + E`**：**打开文件资源管理器**。它是文件管理中最常用的快捷键之一，可以快速进入磁盘、文件夹和文件的浏览界面，适合高频率进行查找、整理、复制和移动文件的场景。
- **`F2`**：**重命名选中的文件或文件夹**。在资源管理器中选中某个对象后按下 `F2`，可以立即进入重命名状态。相比右键菜单操作，这种方式更直接、更高效。
- **`Delete`**：**删除选中的文件或内容**。在文件管理中，按下后一般会将文件移入回收站，而不是立即彻底删除，因此通常仍有恢复的机会。这是日常最常用的删除方式。
- **`Shift + Delete`**：**永久删除选中的文件或内容**。这种删除方式通常会跳过回收站，直接执行更彻底的删除，因此风险更高。只有在确认文件不再需要时，才建议使用该快捷键。

### 编辑操作类快捷键

- **`Ctrl + C`**：**复制**当前选中的内容。
- **`Ctrl + V`**：**粘贴**剪贴板中的内容。
- **`Ctrl + X`**：**剪切**当前选中的内容。与复制不同，剪切的目的是“移动”内容，而不是“保留原处再复制一份”。因此它通常用于将文件、文字或对象从一个位置转移到另一个位置。
- **`Ctrl + A`**：**全选**当前区域中的所有内容。
- **`Ctrl + Z`**：**撤销**上一步操作。这个快捷键的意义在于快速纠正错误，例如误删文字、误移动文件、误修改内容等。它是日常编辑操作中极其重要的“补救”手段。
- **`Ctrl + Y`**：**恢复**刚刚被撤销的操作。它通常与 `Ctrl + Z` 成对出现：`Ctrl + Z` 是回退，`Ctrl + Y` 是前进。
- **`Ctrl + S`**：**保存**当前文件。
- **`Home`**：将**光标快速移动到当前行的行首**。当一行内容较长时，如果仅靠鼠标或方向键逐步移动，效率会很低，而 `Home` 可以让光标一步回到本行最前面，适合快速修改行首内容或准备在行首插入文本。
- **`End`**：将**光标快速移动到当前行的行尾**。它与 `Home` 相对应，主要用于快速跳转到本行最后，适合在一行代码、文本或命令的末尾继续补充内容。
- **`Shift + Home`**：从**当前光标位置开始，向左选中直到当前行行首**。它适合在不使用鼠标的情况下，快速选中当前光标前面的整段行内内容。
- **`Shift + End`**：从**当前光标位置开始，向右选中直到当前行行尾**。它与 `Shift + Home` 相对应，适合快速选中当前光标后面的整段行内内容。
- **`Ctrl + Home`**：将**光标快速移动到整篇文本的开头**。这里的“开头”不是当前行，而是当前文档、代码文件或文本区域的最开始位置。对于内容较长的文件，这个快捷键非常实用，因为它省去了大量滚动和手动定位操作。
- **`Ctrl + End`**：将**光标快速移动到整篇文本的末尾**。它与 `Ctrl + Home` 相对应，用于快速跳转到文档最后，适合在文章末尾追加内容、检查结尾部分或快速定位到最新编辑位置。
- **鼠标双击**：通常用于**快速选中一个单词**。这种方式在阅读文章、修改变量名、复制某个术语时非常方便，因为系统会自动以“单词”为单位进行选中，而不需要用户自己拖动精确范围。

### 窗口切换与任务管理类快捷键

- **`Alt + Tab`**：**切换应用程序窗口**。按住 `Alt` 再连续按 `Tab`，可以在当前打开的程序之间切换。它更适合快速跳转到另一个正在使用的窗口，是多任务场景下最常见的快捷键之一。
- **`Win + Tab`**：**打开任务视图**。与 `Alt + Tab` 不同，它不仅能显示所有打开的窗口，还能管理虚拟桌面，因此更偏向“全局查看和整理任务”，而不只是简单切换窗口。
- **`Win + 左方向键 / 右方向键`**：**窗口分屏贴靠**。该快捷键可以让当前窗口快速贴靠到屏幕左侧或右侧，方便与另一个窗口并排显示。它非常适合一边查资料、一边写文档的学习和办公场景。

## DOS 命令入门

### 什么是 DOS 命令

**DOS** 是 **Disk Operating System** 的缩写，中文通常译为 **磁盘操作系统**。早期个人计算机广泛使用 DOS 作为操作系统，后来随着 Windows 图形界面系统的发展，DOS 逐渐退出主流桌面操作系统舞台。

不过，在今天的学习和开发环境中，人们仍然经常把 Windows 中的命令行窗口习惯性地称为 **“DOS 窗口”**，把在其中输入的命令称为 **“DOS 命令”**。这种叫法在日常交流中非常常见，但从严格意义上说，现代 Windows 中使用的并不是真正的 DOS 系统，而是 **命令提示符**（Command Prompt）或其他命令行工具。

对于普通用户来说，很多操作可以通过鼠标和图形界面完成；但对于程序员，尤其是 **Java 软件工程师**，掌握基本命令行操作是必要的。

### 如何打开 DOS 命令窗口

在 Windows 中，最常见的打开方式是通过 **运行窗口** 启动命令提示符。具体操作为：先按下 **`Win + R`** 打开运行窗口，然后在输入框中输入 **`cmd`**，最后按下 **回车键**，即可打开 DOS 命令窗口。这里大家平时所说的“DOS 命令窗口”，实际上通常指的是 Windows 的 **命令提示符**（Command Prompt）。

打开命令窗口后，通常会看到类似下面这样的内容：

```
C:\Users\Administrator>
```

这表示命令行当前正处于某个具体位置，后面输入的命令就会以这个位置为基础执行。

> **补充**：`cmd` 是 Windows 中 **命令提示符程序** 的启动命令，因此在运行窗口中输入 `cmd`，本质上就是在启动命令提示符。

### 如何在 DOS 命令窗口中复制和粘贴

在 Windows 10 及之后的系统中，DOS 命令窗口已经支持比较方便的复制和粘贴操作。最常见的做法是：先用鼠标左键选中窗口中的目标内容，然后点击鼠标右键，此时选中的内容通常就会被复制到剪贴板中；如果要粘贴，只需要在目标位置再次点击鼠标右键即可。

> **注意**：这里所说的复制和粘贴，是指 **在 DOS 命令窗口内部** 进行的操作。

### 当前所在目录

在 DOS 命令窗口中，**当前所在目录** 指的是命令行此刻所处的位置，也可以叫做 **当前路径**。当窗口中显示类似 `C:\Users\Administrator>` 这样的提示信息时，`C:\Users\Administrator` 对应的路径就是当前所在目录。如果你此时执行文件相关命令，而命令中又没有特别写明其他路径，那么系统通常就会默认你要操作的是当前目录中的文件和文件夹。

## 常用的 DOS 命令

掌握常用的 DOS 命令，是后续进行 Java 开发环境配置、文件管理、程序编译与运行的基础。很多看起来“图形界面也能完成”的操作，在命令行中往往只需要一条命令即可完成，而且更快、更直接、更适合程序员的工作方式。下面整理的是最常见、最实用的一组基础命令。

### `dir`

`dir` 命令用于**列出当前目录下所有的文件和子目录**。当你进入某个目录后，如果想先看看这个位置下面到底有哪些内容，最常用的就是 `dir`。执行后，命令窗口会显示当前路径下的文件夹、文件、修改时间等信息。它的核心作用是“查看当前目录的内容”，因此在进行删除、进入目录、拷贝文件等操作之前，通常都会先执行一次 `dir`，确认当前位置和目录内容是否正确。

> **注意**：`dir` 默认查看的是**当前目录**中的内容，而不是整个磁盘中的所有内容。

### `cls`

`cls` 命令用于**清屏**，也就是清除当前命令窗口中已经显示出来的内容。它不会删除文件，也不会撤销之前执行过的命令，只是把屏幕显示区域清空，让界面重新变得整洁。这个命令在连续执行了很多命令、屏幕内容过多、不方便继续观察输出结果时非常有用。

> **注意**：`cls` 只是清除显示内容，并不会清除命令历史记录。如果想再次查看之前输入过的命令，仍然可以尝试使用方向键查找历史命令。

### `exit`

`exit` 命令用于**退出 DOS 命令窗口**。执行后，当前命令提示符窗口会直接关闭。它适合在命令行操作完成之后，用于结束当前会话。

### 切换盘符

在 DOS 命令窗口中，如果要从一个盘切换到另一个盘，可以**直接输入盘符加冒号**。例如当前在 `C:` 盘下，如果要切换到 `D:` 盘，只需要输入 `D:` 并回车即可。这种切换方式非常直接，不需要使用 `cd` 命令。

> **易错点**：很多初学者会写成 `cd D:`，这是不规范的。盘符切换应直接写 `D:`。

### `del`

`del` 命令用于**删除一个或多个文件**。它针对的是**文件**，而不是目录。如果要删除某个具体文件，可以直接写文件名；如果要批量删除一类文件，可以结合通配符使用，例如 `*.java` 表示删除当前目录下所有扩展名为 `.java` 的文件。

```
del A.txt
del *.java
```

> **注意**：`del` 默认删除的是**当前目录**中的文件，如果命令中没有写完整路径，就会以当前路径为准。

> **易错点**：`del` 不能直接用来删除目录；删除目录通常使用 `rd`。

### `ipconfig`

`ipconfig` 命令用于**查看本机的 IP 地址信息**。在网络通信中，IP 地址可以理解为计算机在网络中的地址标识，因此如果要进行网络调试、排查连接问题，通常会先查看本机 IP 配置。执行 `ipconfig` 可以看到比较基础的网络信息；如果执行 `ipconfig /all`，则可以看到更详细的内容，例如网卡信息、物理地址、DHCP 状态等。

### `ping`

`ping` 命令用于**测试当前计算机与目标主机之间是否能够正常通信**。目标可以是一个 IP 地址，也可以是一个合法域名。执行后，系统会向目标发送测试数据包，并根据返回结果显示是否连通、耗时是多少、是否存在丢包等信息。如果能够正常收到回复，通常说明网络连接是通的。

```
ping 192.168.1.100
ping www.baidu.com
ping www.baidu.com -t
```

`ping` 后面加上 `-t` 参数，表示**持续不断地发送测试数据包**，适合用来观察网络是否稳定。如果想终止当前正在执行的 `ping -t` 命令，可以按 **`Ctrl + C`**。

### `mkdir` 或 `md`

`mkdir` 命令用于**新建目录**，`md` 是它的简写形式，两者作用完全相同。这个命令的核心作用是在当前目录下创建一个新的文件夹，或者按照给定路径创建新的目录结构。在命令行中组织项目目录、练习文件夹、分类资料时，经常会用到它。

```
mkdir test
md demo
```

> **注意**：如果目录名中包含空格，实际使用时通常需要结合引号处理。

### `cd`

`cd` 是 **change directory** 的缩写，用于**切换目录**。它是命令行中最核心、最常用的命令之一，因为很多命令都依赖“当前目录”来执行。使用 `cd` 时，可以进入某个子目录，也可以返回上一级目录，还可以回到根目录。

```
cd 目录名
cd ..
cd /
```

其中，`cd ..` 表示**回到上一级目录**，`cd /` 表示**回到当前盘符的根目录**。`cd` 后面跟的路径既可以是**绝对路径**，也可以是**相对路径**。所谓绝对路径，就是从盘符开始写出的完整路径，例如 `E:\test`；所谓相对路径，就是相对于当前目录而言的路径，不从盘符开始写。绝对路径的优点是定位明确，不依赖当前位置；相对路径的优点是书写简洁，但前提是你必须清楚自己当前在哪个目录下。实际使用中，如果目录名字较长，还可以在输入一部分目录名后按 **`Tab` 键**，让系统自动补全目录名称，这样可以提高效率并减少输入错误。

```
cd E:\test
cd demo
```

### `rd`

`rd` 命令用于**删除目录**。如果目录是空的，可以直接删除；如果目录中还有内容，则需要加参数强制删除。对于不为空的目录，常见写法是 `rd /s /q 目录名`，其中 `/s` 表示连同目录中的内容一起删除，`/q` 表示安静模式，不再逐个确认。

```
rd test
rd /s /q test
```

> **注意**：`rd /s /q` 会删除整个目录及其内部所有内容，操作风险较高，必须谨慎使用。

### `ren`

`ren` 命令用于**重命名文件或目录**。它的作用与图形界面中的“重命名”一致，只不过是在命令行中完成。使用时，一般需要写出旧名称和新名称。

```
ren old.txt new.txt
```

### `copy`

`copy` 命令用于**复制文件**。它可以将一个文件复制到另一个位置，也可以复制后重新命名。这个命令在做文件备份、整理配置文件、保留代码副本时很常用。

```
copy A.txt B.txt
copy A.txt D:\backup\
```

> **注意**：`copy` 主要用于复制**文件**，不是目录。

### `shutdown`

`shutdown` 命令用于**执行关机操作**。通过它可以指定延迟多少秒后自动关机，因此常用于定时关机、脚本控制关机等场景。例如下面的命令表示在 **3600 秒** 之后关机，也就是 **1 小时后关机**。

```
shutdown -s -t 3600
```

其中，`-s` 表示关机，`-t` 表示设置延迟时间，单位是秒。

> **补充**：如果设置了延迟关机后又想取消，常见做法是使用 `shutdown -a` 终止本次关机计划。

## 批处理文件

**批处理文件** 是一种可以**按顺序批量执行多条 DOS 命令**的文件。它的常见扩展名是 **`.bat`**，因此也常被称为 **BAT 文件**。本质上，它并不是一种复杂的程序语言文件，而是把原本需要在命令窗口中一条一条手动输入的命令，提前写入到一个文本文件中，然后由系统一次性顺序执行。

也就是说，如果某些命令你经常要重复执行，例如切换盘符、进入某个目录、删除若干文件、复制文件、创建目录等，那么就没有必要每次都手工输入。此时可以把这些命令统一写进一个 **`.bat`** 文件中，之后只需要**双击这个文件**，系统就会自动按顺序执行里面的所有命令。这就是批处理文件最大的意义：**把重复性的命令操作自动化**。

从使用角度看，批处理文件的作用可以理解为：把“多步命令行操作”封装成“一次执行”。这样做的好处有两个：一是可以提高效率，避免重复输入；二是可以减少人为输入错误，尤其是在路径较长、命令较多的情况下，这种优势会更明显。

> **注意**：批处理文件本质上仍然是一个**文本文件**，只是它的扩展名不是 `.txt`，而是 `.bat`。正因为批处理文件本质上是文本，所以可以使用**文本编辑器**打开和编写，例如记事本等。

批处理文件中的命令通常是**自上而下、按顺序依次执行**的。也就是说，写在前面的命令会先执行，写在后面的命令会后执行。因此，在编写批处理文件时，命令的排列顺序非常重要，不能随意打乱。

例如，下面这组命令：

```
d:
cd test/xyz
del a.txt
del b.txt
```

它的执行逻辑不是“同时执行”，而是按照下面的顺序一步一步进行：

1. 先执行 `d:`，把当前盘符切换到 **D 盘**；
2. 再执行 `cd test/xyz`，进入 `D:` 盘下的 `test/xyz` 目录；
3. 然后执行 `del a.txt`，删除当前目录中的 `a.txt`；
4. 最后执行 `del b.txt`，删除当前目录中的 `b.txt`。

之所以必须按这个顺序写，是因为后面的删除命令依赖前面的路径切换结果。如果不先切换到正确的位置，那么 `del a.txt` 和 `del b.txt` 删除的就未必是目标目录中的文件，甚至可能找不到文件。

批处理文件可以使用普通的文本编辑器来编写。编写时，本质上就是把要执行的 DOS 命令一行一行写进去，然后将文件保存为 **`.bat`** 扩展名。保存之后，直接**双击 `my.bat` 文件**，系统就会自动打开命令环境，并依次执行其中的命令。
