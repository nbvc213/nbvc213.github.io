## 笔记编写规范

### 格式规范

1. 标题只用 #、##、###、#### 四级。
2. 重点术语、核心结论、易错点关键词统一用 **粗体**。
3. “注意 / 易错点 / 补充 / 结论”统一用引用块 > 书写。
4. 代码术语用行内代码，完整代码用 ```java 代码块。
5. 有步骤的内容用有序列表，并列内容用无序列表。
6. 对比类内容优先用表格。
7. 大模块之间用分隔线 ---。
8. 字体颜色、字体大小、下划线默认不用。
9. 图片和链接只在确有必要时使用。
10. 整体风格以清晰、统一、便于长期复习为最高原则。

### 写作规范

请你作为我的 Java 学习笔记整理助手。我会陆续给你发送 Java 知识点、课堂内容、零散笔记、代码或截图，你需要将其整理成高质量的 Markdown 中文笔记。

请遵守以下要求：
1. 全程使用中文讲解，必要时在术语后标注英文。
2. 使用 Markdown 语法，结构清晰，层次分明，整体风格像教材或出版书籍，便于长期复习。
3. 重点内容要突出显示，重点术语、核心结论、易错点、易混点要加粗或单独归纳。
4. 讲解必须清楚、完整，不跳步骤。凡是涉及过程、原理、执行流程、推导逻辑的地方，都要一步一步说明。
5. 不仅要讲“是什么”，还要讲“为什么这样设计”“为什么这样写”“如果不这样会怎样”。
6. 如果我提供的原始内容存在表述不严谨、步骤跳跃、结构混乱等问题，请主动优化，而不是机械照抄。
7. 输出内容应尽量整理成可直接保存、适合长期复习的成品笔记，而不是聊天式回答。
8. 除非我特别要求简略版，否则请尽量写得完整、系统。

默认情况下，你只需要整理理论内容，不必主动补充以下内容：
- 知识点对比
- Java 代码示例
- 练习题及答案解析

只有当我明确提出要求时，你再补充这些内容：
- 若我要求“加入对比分析”，再补充相关知识点对比；
- 若我要求“加入代码示例”，再补充完整可运行的 Java 示例及详细讲解；
- 若我要求“加入练习题”，再补充练习题、参考答案与解析。

### 补充规范

请按以下要求整理或修改我提供的学习笔记：

1. 对于“概念介绍类”内容，只做简要、准确的说明即可，不要无必要地展开过多，不要把本来几句话能讲清楚的内容写成长篇解释。
2. 对于并列内容，如果各项只是词语、短语或简短列举，优先直接写成行文中的并列表达，例如“xxx、xxx、xxx”；如果每一项后面还有进一步解释，或者每一项本身就是一句相对完整的话，则应使用分点或列表呈现，以保证结构清晰、层次自然。
3. 对于包含关系、定义区别、基本原理这类内容，尽量用一两段自然行文讲清楚，不要拆成很多零散的小标题、小分点、小短句，避免笔记显得松散、啰嗦。
4. 对于“安装步骤”“操作流程”“使用步骤”这类内容，优先写成有序列表；每一步尽量写成一段完整的话，只有当某一步内容确实较多时，才在该步骤下继续细分。
5. 整体表达要简洁、紧凑、清晰，适合长期复习，不要写成聊天式说明，也不要为了“看起来详细”而把内容切得过碎。
6. 保持结构克制：只保留我要求的章节，不要擅自新增过多小节；如果某部分没必要单独成节，就直接并入当前章节。
7. 修改时优先优化“结构是否紧凑、表达是否简练、层次是否自然”，而不是单纯把内容越写越多。
8. 如果某一部分只是基础入门说明，请优先做到“说清楚”，而不是“铺得很开”。
9. 如果我提供的某次内容中存在重复的知识点，请主动合并，相同内容不要重复展开；整理时尽量做到一个知识点写成一段，不要无必要地频繁换行、拆句或拆步骤。只有当某部分内容确实较长，或涉及较长公式、代码块等必须单独展示的内容时，才单独成行；若步骤本身较短，也应尽量紧凑书写，避免把本可连贯表达的内容切得过碎。

请在整理笔记时，默认遵循以下隐性风格要求：

1. 整体风格应偏向**教材式、成品化、可长期复习**，表达平稳、客观，不写成聊天式说明，也不要写成课堂实录式流水笔记。
2. 写作时应遵循**先总后分**的组织方式，先用一两句话概括当前知识点的核心，再根据需要自然展开分类、表格或补充内容，但整体结构要收得紧，不要为了显得详细而增加过多层级。
3. **标题要克制使用**。不要把每一个细小知识点都拆成独立小节；能在当前标题下自然讲清的内容，就直接并入正文，不额外新增过多小标题。
4. 整理时尽量做到**一个知识点对应一段完整说明**。每一段应围绕一个中心展开，信息可以适当集中，但不要把一句话拆成很多零碎短句，也不要把本可一段讲清的内容切成多段。
5. 对于**并列内容**，如果各项只是词语、短语或简短列举，优先直接写成行文中的并列表达，例如“xxx、xxx、xxx”；如果每一项后面还有进一步解释，或者每一项本身就是一句相对完整的话，则应使用分点或列表呈现，以保证结构清晰、层次自然。
6. 对于**结构规整、适合对照的信息**，优先使用表格呈现，例如“数据类型、占用字节数、取值范围、默认值”这类内容；表格之外只补充必要说明，不重复把表格内容再展开一遍。
7. **补充内容要少而精**。只有确实对理解、记忆或复习有帮助的延伸内容，才放入 `> 补充`；不要为了显得全面而随意增加拓展说明。
8. 表达风格应保持**书面化、稳定、克制**，多使用“用于表示……”“可以分为……”“现阶段重点掌握……”这类教材式表达，避免使用过强的口语化表述。
9. 写作时应优先考虑**复习效率**，保留当前阶段最该掌握的内容；对暂时不重要、后续还会系统展开的内容，可以简要点到为止，不必提前铺陈过多。
10. 各部分之间要注意**衔接自然**。前后内容应顺着知识逻辑展开，不要频繁加入“接下来我们来看……”“下面继续讲……”这类过渡性废话。
11. `> 注意`、`> 易错点`、`> 补充`、`> 结论` 可以保留，但数量应适度，作用应是**提炼重点、提示易错、压缩结论**，而不是把正文重复再说一遍。
12. 整体应追求：**信息密度高、结构克制、表达简洁、层次自然、成品感强**。最终效果应更像一本整理好的学习笔记，而不是一份边讲边记的草稿。

## 常用的 Windows 组合键

**Windows 组合键**（快捷键）是指通过同时按下一个或多个按键，快速完成某种操作的方式。熟练使用常见快捷键，可以显著提高日常学习、办公和文件管理的效率，减少频繁使用鼠标带来的操作成本。

### 系统与桌面操作类快捷键

- **`Win + D`**：**显示桌面**。按下后可以立即将当前所有窗口最小化，快速返回桌面；再次按下时，通常还能恢复原来的窗口状态。
- **`Win + L`**：**锁屏**。按下后系统会立刻进入锁定状态，需要重新输入密码或验证身份才能进入桌面。
- **`Win + I`**：**打开设置**。它可以直接进入 Windows 的系统设置界面，用于管理网络、蓝牙、个性化、账户、更新等功能。
- **`Win + R`**：**打开运行窗口**。运行窗口是 Windows 中非常高效的命令入口，可以通过输入程序名、系统工具名或路径来直接打开目标内容，例如输入 `cmd` 打开命令提示符，输入 `regedit` 打开注册表编辑器。
- **`Alt + F4`**：**关闭当前窗口**。当某个应用程序窗口处于激活状态时，按下该组合键可以直接关闭它；如果当前位于桌面，通常会弹出关机选项。

### 文件与资源管理类快捷键

- **`Win + E`**：**打开文件资源管理器**。它是文件管理中最常用的快捷键之一，可以快速进入磁盘、文件夹和文件的浏览界面，适合高频率进行查找、整理、复制和移动文件的场景。
- **`F2`**：**重命名选中的文件或文件夹**。在资源管理器中选中某个对象后按下 `F2`，可以立即进入重命名状态。相比右键菜单操作，这种方式更直接、更高效。
- **`Delete`**：**删除选中的文件或内容**。在文件管理中，按下后一般会将文件移入回收站，而不是立即彻底删除，因此通常仍有恢复的机会。这是日常最常用的删除方式。
- **`Shift + Delete`**：**永久删除选中的文件或内容**。这种删除方式通常会跳过回收站，直接执行更彻底的删除，因此风险更高。只有在确认文件不再需要时，才建议使用该快捷键。

### 编辑操作类快捷键

- **`Ctrl + C`**：**复制**当前选中的内容。
- **`Ctrl + V`**：**粘贴**剪贴板中的内容。
- **`Ctrl + X`**：**剪切**当前选中的内容。与复制不同，剪切的目的是“移动”内容，而不是“保留原处再复制一份”。因此它通常用于将文件、文字或对象从一个位置转移到另一个位置。
- **`Ctrl + A`**：**全选**当前区域中的所有内容。
- **`Ctrl + Z`**：**撤销**上一步操作。这个快捷键的意义在于快速纠正错误，例如误删文字、误移动文件、误修改内容等。它是日常编辑操作中极其重要的“补救”手段。
- **`Ctrl + Y`**：**恢复**刚刚被撤销的操作。它通常与 `Ctrl + Z` 成对出现：`Ctrl + Z` 是回退，`Ctrl + Y` 是前进。
- **`Ctrl + S`**：**保存**当前文件。
- **`Home`**：将**光标快速移动到当前行的行首**。当一行内容较长时，如果仅靠鼠标或方向键逐步移动，效率会很低，而 `Home` 可以让光标一步回到本行最前面，适合快速修改行首内容或准备在行首插入文本。
- **`End`**：将**光标快速移动到当前行的行尾**。它与 `Home` 相对应，主要用于快速跳转到本行最后，适合在一行代码、文本或命令的末尾继续补充内容。
- **`Shift + Home`**：从**当前光标位置开始，向左选中直到当前行行首**。它适合在不使用鼠标的情况下，快速选中当前光标前面的整段行内内容。
- **`Shift + End`**：从**当前光标位置开始，向右选中直到当前行行尾**。它与 `Shift + Home` 相对应，适合快速选中当前光标后面的整段行内内容。
- **`Ctrl + Home`**：将**光标快速移动到整篇文本的开头**。这里的“开头”不是当前行，而是当前文档、代码文件或文本区域的最开始位置。对于内容较长的文件，这个快捷键非常实用，因为它省去了大量滚动和手动定位操作。
- **`Ctrl + End`**：将**光标快速移动到整篇文本的末尾**。它与 `Ctrl + Home` 相对应，用于快速跳转到文档最后，适合在文章末尾追加内容、检查结尾部分或快速定位到最新编辑位置。
- **鼠标双击**：通常用于**快速选中一个单词**。这种方式在阅读文章、修改变量名、复制某个术语时非常方便，因为系统会自动以“单词”为单位进行选中，而不需要用户自己拖动精确范围。

### 窗口切换与任务管理类快捷键

- **`Alt + Tab`**：**切换应用程序窗口**。按住 `Alt` 再连续按 `Tab`，可以在当前打开的程序之间切换。它更适合快速跳转到另一个正在使用的窗口，是多任务场景下最常见的快捷键之一。
- **`Win + Tab`**：**打开任务视图**。与 `Alt + Tab` 不同，它不仅能显示所有打开的窗口，还能管理虚拟桌面，因此更偏向“全局查看和整理任务”，而不只是简单切换窗口。
- **`Win + 左方向键 / 右方向键`**：**窗口分屏贴靠**。该快捷键可以让当前窗口快速贴靠到屏幕左侧或右侧，方便与另一个窗口并排显示。它非常适合一边查资料、一边写文档的学习和办公场景。

## DOS 命令入门

### 什么是 DOS 命令

**DOS** 是 **Disk Operating System** 的缩写，中文通常译为 **磁盘操作系统**。早期个人计算机广泛使用 DOS 作为操作系统，后来随着 Windows 图形界面系统的发展，DOS 逐渐退出主流桌面操作系统舞台。

不过，在今天的学习和开发环境中，人们仍然经常把 Windows 中的命令行窗口习惯性地称为 **“DOS 窗口”**，把在其中输入的命令称为 **“DOS 命令”**。这种叫法在日常交流中非常常见，但从严格意义上说，现代 Windows 中使用的并不是真正的 DOS 系统，而是 **命令提示符**（Command Prompt）或其他命令行工具。

对于普通用户来说，很多操作可以通过鼠标和图形界面完成；但对于程序员，尤其是 **Java 软件工程师**，掌握基本命令行操作是必要的。

### 如何打开 DOS 命令窗口

在 Windows 中，最常见的打开方式是通过 **运行窗口** 启动命令提示符。具体操作为：先按下 **`Win + R`** 打开运行窗口，然后在输入框中输入 **`cmd`**，最后按下 **回车键**，即可打开 DOS 命令窗口。这里大家平时所说的“DOS 命令窗口”，实际上通常指的是 Windows 的 **命令提示符**（Command Prompt）。

打开命令窗口后，通常会看到类似下面这样的内容：

```
C:\Users\Administrator>
```

这表示命令行当前正处于某个具体位置，后面输入的命令就会以这个位置为基础执行。

> **补充**：`cmd` 是 Windows 中 **命令提示符程序** 的启动命令，因此在运行窗口中输入 `cmd`，本质上就是在启动命令提示符。

### 如何在 DOS 命令窗口中复制和粘贴

在 Windows 10 及之后的系统中，DOS 命令窗口已经支持比较方便的复制和粘贴操作。最常见的做法是：先用鼠标左键选中窗口中的目标内容，然后点击鼠标右键，此时选中的内容通常就会被复制到剪贴板中；如果要粘贴，只需要在目标位置再次点击鼠标右键即可。

> **注意**：这里所说的复制和粘贴，是指 **在 DOS 命令窗口内部** 进行的操作。

### 当前所在目录

在 DOS 命令窗口中，**当前所在目录** 指的是命令行此刻所处的位置，也可以叫做 **当前路径**。当窗口中显示类似 `C:\Users\Administrator>` 这样的提示信息时，`C:\Users\Administrator` 对应的路径就是当前所在目录。如果你此时执行文件相关命令，而命令中又没有特别写明其他路径，那么系统通常就会默认你要操作的是当前目录中的文件和文件夹。

## 常用的 DOS 命令

掌握常用的 DOS 命令，是后续进行 Java 开发环境配置、文件管理、程序编译与运行的基础。很多看起来“图形界面也能完成”的操作，在命令行中往往只需要一条命令即可完成，而且更快、更直接、更适合程序员的工作方式。下面整理的是最常见、最实用的一组基础命令。

### `dir`

`dir` 命令用于**列出当前目录下所有的文件和子目录**。当你进入某个目录后，如果想先看看这个位置下面到底有哪些内容，最常用的就是 `dir`。执行后，命令窗口会显示当前路径下的文件夹、文件、修改时间等信息。它的核心作用是“查看当前目录的内容”，因此在进行删除、进入目录、拷贝文件等操作之前，通常都会先执行一次 `dir`，确认当前位置和目录内容是否正确。

> **注意**：`dir` 默认查看的是**当前目录**中的内容，而不是整个磁盘中的所有内容。

### `cls`

`cls` 命令用于**清屏**，也就是清除当前命令窗口中已经显示出来的内容。它不会删除文件，也不会撤销之前执行过的命令，只是把屏幕显示区域清空，让界面重新变得整洁。这个命令在连续执行了很多命令、屏幕内容过多、不方便继续观察输出结果时非常有用。

> **注意**：`cls` 只是清除显示内容，并不会清除命令历史记录。如果想再次查看之前输入过的命令，仍然可以尝试使用方向键查找历史命令。

### `exit`

`exit` 命令用于**退出 DOS 命令窗口**。执行后，当前命令提示符窗口会直接关闭。它适合在命令行操作完成之后，用于结束当前会话。

### 切换盘符

在 DOS 命令窗口中，如果要从一个盘切换到另一个盘，可以**直接输入盘符加冒号**。例如当前在 `C:` 盘下，如果要切换到 `D:` 盘，只需要输入 `D:` 并回车即可。这种切换方式非常直接，不需要使用 `cd` 命令。

> **易错点**：很多初学者会写成 `cd D:`，这是不规范的。盘符切换应直接写 `D:`。

### `del`

`del` 命令用于**删除一个或多个文件**。它针对的是**文件**，而不是目录。如果要删除某个具体文件，可以直接写文件名；如果要批量删除一类文件，可以结合通配符使用，例如 `*.java` 表示删除当前目录下所有扩展名为 `.java` 的文件。

```
del A.txt
del *.java
```

> **注意**：`del` 默认删除的是**当前目录**中的文件，如果命令中没有写完整路径，就会以当前路径为准。

> **易错点**：`del` 不能直接用来删除目录；删除目录通常使用 `rd`。

### `ipconfig`

`ipconfig` 命令用于**查看本机的 IP 地址信息**。在网络通信中，IP 地址可以理解为计算机在网络中的地址标识，因此如果要进行网络调试、排查连接问题，通常会先查看本机 IP 配置。执行 `ipconfig` 可以看到比较基础的网络信息；如果执行 `ipconfig /all`，则可以看到更详细的内容，例如网卡信息、物理地址、DHCP 状态等。

### `ping`

`ping` 命令用于**测试当前计算机与目标主机之间是否能够正常通信**。目标可以是一个 IP 地址，也可以是一个合法域名。执行后，系统会向目标发送测试数据包，并根据返回结果显示是否连通、耗时是多少、是否存在丢包等信息。如果能够正常收到回复，通常说明网络连接是通的。

```
ping 192.168.1.100
ping www.baidu.com
ping www.baidu.com -t
```

`ping` 后面加上 `-t` 参数，表示**持续不断地发送测试数据包**，适合用来观察网络是否稳定。如果想终止当前正在执行的 `ping -t` 命令，可以按 **`Ctrl + C`**。

### `mkdir` 或 `md`

`mkdir` 命令用于**新建目录**，`md` 是它的简写形式，两者作用完全相同。这个命令的核心作用是在当前目录下创建一个新的文件夹，或者按照给定路径创建新的目录结构。在命令行中组织项目目录、练习文件夹、分类资料时，经常会用到它。

```
mkdir test
md demo
```

> **注意**：如果目录名中包含空格，实际使用时通常需要结合引号处理。

### `cd`

`cd` 是 **change directory** 的缩写，用于**切换目录**。它是命令行中最核心、最常用的命令之一，因为很多命令都依赖“当前目录”来执行。使用 `cd` 时，可以进入某个子目录，也可以返回上一级目录，还可以回到根目录。

```
cd 目录名
cd ..
cd /
```

其中，`cd ..` 表示**回到上一级目录**，`cd /` 表示**回到当前盘符的根目录**。`cd` 后面跟的路径既可以是**绝对路径**，也可以是**相对路径**。所谓绝对路径，就是从盘符开始写出的完整路径，例如 `E:\test`；所谓相对路径，就是相对于当前目录而言的路径，不从盘符开始写。绝对路径的优点是定位明确，不依赖当前位置；相对路径的优点是书写简洁，但前提是你必须清楚自己当前在哪个目录下。实际使用中，如果目录名字较长，还可以在输入一部分目录名后按 **`Tab` 键**，让系统自动补全目录名称，这样可以提高效率并减少输入错误。

```
cd E:\test
cd demo
```

### `rd`

`rd` 命令用于**删除目录**。如果目录是空的，可以直接删除；如果目录中还有内容，则需要加参数强制删除。对于不为空的目录，常见写法是 `rd /s /q 目录名`，其中 `/s` 表示连同目录中的内容一起删除，`/q` 表示安静模式，不再逐个确认。

```
rd test
rd /s /q test
```

> **注意**：`rd /s /q` 会删除整个目录及其内部所有内容，操作风险较高，必须谨慎使用。

### `ren`

`ren` 命令用于**重命名文件或目录**。它的作用与图形界面中的“重命名”一致，只不过是在命令行中完成。使用时，一般需要写出旧名称和新名称。

```
ren old.txt new.txt
```

### `copy`

`copy` 命令用于**复制文件**。它可以将一个文件复制到另一个位置，也可以复制后重新命名。这个命令在做文件备份、整理配置文件、保留代码副本时很常用。

```
copy A.txt B.txt
copy A.txt D:\backup\
```

> **注意**：`copy` 主要用于复制**文件**，不是目录。

### `shutdown`

`shutdown` 命令用于**执行关机操作**。通过它可以指定延迟多少秒后自动关机，因此常用于定时关机、脚本控制关机等场景。例如下面的命令表示在 **3600 秒** 之后关机，也就是 **1 小时后关机**。

```
shutdown -s -t 3600
```

其中，`-s` 表示关机，`-t` 表示设置延迟时间，单位是秒。

> **补充**：如果设置了延迟关机后又想取消，常见做法是使用 `shutdown -a` 终止本次关机计划。

## 批处理文件

**批处理文件** 是一种可以**按顺序批量执行多条 DOS 命令**的文件。它的常见扩展名是 **`.bat`**，因此也常被称为 **BAT 文件**。本质上，它并不是一种复杂的程序语言文件，而是把原本需要在命令窗口中一条一条手动输入的命令，提前写入到一个文本文件中，然后由系统一次性顺序执行。

也就是说，如果某些命令你经常要重复执行，例如切换盘符、进入某个目录、删除若干文件、复制文件、创建目录等，那么就没有必要每次都手工输入。此时可以把这些命令统一写进一个 **`.bat`** 文件中，之后只需要**双击这个文件**，系统就会自动按顺序执行里面的所有命令。这就是批处理文件最大的意义：**把重复性的命令操作自动化**。

从使用角度看，批处理文件的作用可以理解为：把“多步命令行操作”封装成“一次执行”。这样做的好处有两个：一是可以提高效率，避免重复输入；二是可以减少人为输入错误，尤其是在路径较长、命令较多的情况下，这种优势会更明显。

> **注意**：批处理文件本质上仍然是一个**文本文件**，只是它的扩展名不是 `.txt`，而是 `.bat`。正因为批处理文件本质上是文本，所以可以使用**文本编辑器**打开和编写，例如记事本等。

批处理文件中的命令通常是**自上而下、按顺序依次执行**的。也就是说，写在前面的命令会先执行，写在后面的命令会后执行。因此，在编写批处理文件时，命令的排列顺序非常重要，不能随意打乱。

例如，下面这组命令：

```
d:
cd test/xyz
del a.txt
del b.txt
```

它的执行逻辑不是“同时执行”，而是按照下面的顺序一步一步进行：

1. 先执行 `d:`，把当前盘符切换到 **D 盘**；
2. 再执行 `cd test/xyz`，进入 `D:` 盘下的 `test/xyz` 目录；
3. 然后执行 `del a.txt`，删除当前目录中的 `a.txt`；
4. 最后执行 `del b.txt`，删除当前目录中的 `b.txt`。

之所以必须按这个顺序写，是因为后面的删除命令依赖前面的路径切换结果。如果不先切换到正确的位置，那么 `del a.txt` 和 `del b.txt` 删除的就未必是目标目录中的文件，甚至可能找不到文件。

批处理文件可以使用普通的文本编辑器来编写。编写时，本质上就是把要执行的 DOS 命令一行一行写进去，然后将文件保存为 **`.bat`** 扩展名。保存之后，直接**双击 `my.bat` 文件**，系统就会自动打开命令环境，并依次执行其中的命令。
