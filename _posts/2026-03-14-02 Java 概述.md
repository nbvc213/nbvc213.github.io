## 计算机概述

计算机是一种能够**接收、存储、处理和输出数据**的现代电子设备。从整体上看，计算机系统由两大部分组成：

- **硬件（Hardware）**
- **软件（Software）**

硬件负责提供实际的物理基础，软件负责告诉计算机“该做什么、怎么做”。二者必须相互配合，计算机才能正常工作。

### 硬件

**硬件** 是计算机系统中看得见、摸得着的物理部件。常见的硬件主要包括以下几类：

- **中央处理器（CPU）**：负责执行指令和处理数据，是计算机的核心部件，可以理解为计算机的“大脑”。
- **内存**：用于临时存放正在运行的程序和数据，断电后其中的数据通常会丢失。
- **硬盘**：用于长期保存操作系统、程序和各种数据，属于永久性存储设备。
- **显示器**：负责将计算机处理后的文字、图像等内容显示出来。
- **键盘和鼠标**：属于输入设备，用于向计算机输入指令和数据。
- **主板**：用于连接各个硬件部件，使它们能够协同工作。
- **电源**：为整台计算机提供电能。

此外，计算机中还可能包含 **显卡、网卡、声卡、散热器、光驱** 等硬件组件，它们共同配合，保证计算机能够完成不同类型的任务。

> **补充**：学习编程时，最需要优先理解的硬件通常是 **CPU、内存、硬盘**，因为它们与程序运行关系最密切。

### 软件

**软件** 是安装在计算机中的程序和系统，它本身看不见、摸不着，但可以控制硬件完成各种任务。通常可以分为两大类：

- **系统软件** 主要负责管理硬件资源，并为其他软件提供运行环境。常见的系统软件包括：
  - **操作系统**：如 Windows、macOS、Linux、Android、iOS 等
  - **驱动程序**：用于让操作系统识别并控制硬件设备
  - **系统工具**：用于维护、管理和优化计算机系统
- **应用软件** 主要用于满足用户的具体需求，帮助用户完成某种实际工作。常见的应用软件包括：
  - **办公软件**：如 Word、Excel、PowerPoint
  - **图形图像软件**：如 Photoshop
  - **浏览器**：如 Chrome、Edge、Safari、Firefox

> **注意**：**操作系统属于系统软件**，而不是应用软件，这是一个很基础但容易混淆的知识点。

### 计算机语言

**计算机程序** 是一组按照一定顺序组织起来的**指令和规则**，其作用是指导计算机完成某项特定任务。简单来说，程序就是“告诉计算机应该做什么、按什么步骤做”的一套指令。

例如，在餐厅点餐的场景中，服务员把顾客点的菜品输入系统后，系统会自动计算总价、记录订单并显示结果。这个能够完成“接收输入—处理数据—输出结果”的系统，本质上就是一个计算机程序。

**计算机语言** 是人和计算机之间进行交流的一种方式，也可以理解为**编写计算机程序所使用的语言**。因为计算机本身不能直接理解人类自然语言，所以人们需要借助特定的语言，把想要计算机完成的任务描述出来。

常见的计算机语言大致可以分为两类：

- **低级语言**：更接近计算机底层，如 **机器语言**、**汇编语言**
- **高级语言**：更接近人类的表达方式，如 **C、Java、Python**

计算机语言的发展，大致经历了从**低级语言**到**高级语言**的过程，整体趋势可以概括为：**越来越容易理解，越来越适合人编写程序**。

#### 机器语言

**机器语言** 是最早的计算机语言，由大量 **0 和 1** 组成。计算机可以直接识别和执行机器语言，但对于人来说非常难读、难写、也很难维护。

#### 汇编语言

为了降低编写机器语言的难度，人们发明了 **汇编语言**。汇编语言用一些更容易记忆的**助记符**来代替原始的二进制指令，因此比机器语言更容易阅读和书写。

常见助记符例如：

- `MOV`：数据传送
- `ADD`：加法
- `SUB`：减法
- `MUL`：乘法
- `DIV`：除法

> **注意**：汇编语言虽然比机器语言更容易理解，但它本质上仍然属于比较底层的语言。

#### 高级语言

后来出现了 **高级语言**。高级语言的语法更接近人类的思维方式，程序员不再需要过多关注底层硬件细节，而可以更专注于“要解决什么问题”。这大大提高了开发效率，也推动了软件技术的发展。

常见的高级语言有：**Fortran**、**COBOL**、**BASIC**、**ALGOL**、**C**、**Java**、**Python**。

> **结论**：高级语言的出现，大幅降低了编程门槛，使程序开发更加高效。

#### 面向对象编程语言

在高级语言继续发展的过程中，出现了**面向对象编程语言**。这类语言强调通过“对象”来组织程序，把数据和操作封装在一起，使大型程序更容易开发、维护和扩展。

常见的面向对象编程语言有：**C++**、**Java**、**Python**

由于后续要学习 Java，因此这里可以先有一个初步认识：**Java 就是一门高级的、面向对象的编程语言。**

## Java 语言概述

**Java** 是一门广泛使用的**面向对象编程语言**（Object-Oriented Programming Language，OOP），由 **Sun Microsystems** 公司于 **1995 年**正式推出。后来，Sun 公司于 **2010 年**被 **Oracle（甲骨文）** 收购，此后 Oracle 成为了 Java 的主要维护者之一。

### Java 之父

通常把 **詹姆斯·高斯林（James Gosling）** 称为 **Java 之父**。他是 Java 语言的核心设计者之一，在 Sun 公司工作期间，参与并推动了 Java 的设计与发展。

Java 最初的设计目标之一，是希望程序能够在不同平台上运行，而不需要针对每个平台分别重写代码。围绕这个目标，Java 引入了许多重要思想，例如：

- **虚拟机机制**
- **垃圾回收机制**
- **面向对象编程思想**

这些设计使 Java 在诞生之后迅速获得了广泛关注，并逐渐发展成为一门影响力极大的编程语言。

### Java 名字的来历与 Logo

Java 这个名字有一段比较有名的背景。Java 在开发早期并不叫 Java，而是叫 **Oak**。后来由于该名称已经被其他公司使用，Sun 公司需要重新命名，最终选择了 **Java** 这个名字。

“Java” 一般被认为与 **咖啡文化** 有关，因此 Java 的经典 Logo 也是一杯**冒着热气的咖啡**。这也是为什么很多 Java 相关图标、周边形象都会和咖啡联系在一起。

### Java 语言发展史

Java 的发展历史较长，初学阶段不需要记住所有版本，只需要对几个重要节点有基本认识。

#### 早期发展

- **1995 年**：Java 语言正式诞生。
- **1996 年**：发布 **Java 1.0**，标志着 Java 开始正式进入开发者视野。
- **1998 年**：发布 **Java 2（Java SE）**，这是 Java 发展中的一个重要阶段。

#### 重要版本

- **Java SE 5.0（2004 年）**：引入了很多至今仍然非常重要的特性，例如：**泛型**、**枚举**、**注解**、**自动装箱 / 拆箱**。
- **Java SE 8（2014 年）**：这是 Java 历史上非常重要的版本之一，引入了：**Lambda 表达式**、**Stream API**、**新的日期时间 API**。
- **Java SE 11（2018 年）**：这是一个 **LTS 版本**（Long-Term Support，长期支持版本），在企业开发中影响很大。
- **Java SE 17（2021 年）**：同样是一个 **LTS 版本**，也是很多项目常用的长期支持版本。
- **Java SE 21（2023 年）**：也是一个 **LTS 版本**，属于较新的长期支持版本。

> **注意**：初学 Java 时，不必试图记住每个版本都新增了什么。更重要的是先知道：**Java 8、Java 11、Java 17、Java 21** 都是非常有代表性的版本，其中 **11、17、21** 都是 **LTS 版本**。

> **补充**：**LTS** 表示长期支持，一般更适合企业长期使用，因为维护周期更长、稳定性更高。

### Java 的三大分支

Java 在传统分类中通常分为三大分支：

- **Java SE（Java Standard Edition）**：即 **Java 标准版**，是 Java 的核心基础。它包含 Java 语言的基本语法、核心类库、JVM 以及常用开发工具。初学 Java 时，首先接触的通常就是 Java SE。它主要用于开发**桌面程序、控制台程序以及基础服务端程序**。
- **Java EE（Java Enterprise Edition）**：即 **Java 企业版**，是在 Java SE 基础上面向企业级开发扩展出来的一套体系，主要用于开发**大型企业应用系统**，例如电商系统、ERP 系统、CRM 系统等。
- **Java ME（Java Micro Edition）**：即 **Java 微型版**，主要面向**嵌入式设备和资源受限设备**，例如早期手机、机顶盒、路由器、一些便携式设备等。

这三大分支的关系可以简单理解为：**Java SE 是基础，Java EE 和 Java ME 都是在 Java SE 的基础上进行扩展或裁剪后形成的不同方向**。其中，Java EE 更强调企业级开发能力，而 Java ME 更强调轻量化和资源受限环境下的运行能力。

### Java 语言特性

Java 之所以能够长期流行，和它本身的一些重要语言特性有很大关系。下面对这些特性作简要整理。

#### 简单易学

Java 的语法风格与 C / C++ 有一定渊源，因此在表达能力较强的同时，也尽量避免了一些过于复杂、容易出错的设计。对于初学者来说，Java 的整体学习曲线相对平稳，更适合作为系统学习面向对象编程的入门语言之一。

> **补充**：这里所说的“简单”，是相对于一些更底层、更复杂的语言而言，并不意味着 Java 没有学习难度。

#### 面向对象

Java 是一门典型的**面向对象编程语言**，支持 **封装、继承、多态** 等核心特性。Java 程序通常围绕“类”和“对象”来组织代码，因此它非常适合构建结构清晰、易于维护的大型程序。

#### 跨平台性

Java 最著名的特点之一就是 **跨平台**，常见表述为：**一次编译，到处运行**。其核心原因在于：Java 源代码不会直接编译成某个操作系统专用的机器码，而是先编译成 **字节码**，再由对应平台上的 **JVM（Java 虚拟机）** 来执行。不同操作系统上安装各自适配的 JVM 后，Java 程序就可以在这些平台上运行。

也就是说，真正屏蔽操作系统差异的关键，并不是“Java 代码本身会自动适配所有平台”，而是 **JVM 屏蔽了底层平台差异**。

> **结论**：Java 的跨平台能力，本质上依赖于 **字节码 + JVM** 的运行机制。

#### 安全性

Java 在设计时就比较重视安全性。它提供了多种机制来降低程序出错或被恶意利用的风险，例如类型检查、异常处理、权限控制等。因此，相较于一些更底层的语言，Java 在很多场景下更安全、更稳定。

#### 高性能

Java 通常被认为具有较好的性能。虽然它不像某些底层语言那样直接生成本地机器码执行，但借助 JVM 的优化机制，Java 在很多实际应用场景中仍然可以表现出较高的执行效率。

> **注意**：这里的“高性能”是相对而言的，不能简单理解为 Java 在所有场景下都比其他语言更快。

#### 多线程支持

Java 对**多线程（Multithreading）** 提供了较完善的支持，这使得程序可以更好地利用多核处理器，提高并发处理能力。对于服务器程序、网络程序以及大型系统开发来说，这一特性非常重要。

#### 垃圾回收机制

Java 提供了 **垃圾回收机制（Garbage Collection，GC）**，也就是**自动内存管理机制**。在一些需要手动管理内存的语言中，程序员需要自己负责申请和释放内存，如果处理不当，就容易出现**内存泄漏**、**悬挂指针** 等问题。Java 则把大量内存回收工作交给了 JVM 自动完成，从而减轻了程序员的负担，也提高了开发安全性。

> **结论**：**垃圾回收机制** 是 Java 非常重要的特性之一，它让程序员能够把更多精力放在业务逻辑上，而不是频繁处理底层内存释放问题。

### Java 的加载与执行

理解 Java 的加载与执行过程，最好的方式不是孤立地去背“编译”“运行”“JVM”“类加载器”等概念，而是沿着一条完整主线来理解：**一个 `Test.java` 文件，从编写完成到最终运行，到底经历了什么？**

一个 Java 程序从写出来到真正运行起来，通常会经过两个大阶段：**编译阶段**、**运行阶段**。也就是说，`Test.java` 并不是写完之后就能直接运行。它必须先被编译成 JVM 能识别的 **字节码文件**，然后再交给 JVM 去加载和执行。

#### 编译阶段

当我们编写完 `Test.java` 之后，首先要做的不是运行它，而是先使用 `javac` 命令对它进行编译。

```cmd
javac Test.java
```

这里的 `javac` 可以理解为 **Java 编译器**。它的作用是把 Java 源文件 `Test.java` 编译成对应的字节码文件 `Test.class`。

这个过程可以理解为：

1. 程序员编写的是 **Java 源代码**
2. `javac` 读取源代码
3. 将源代码翻译为 **字节码（bytecode）**
4. 最终生成一个 `.class` 文件

如果源文件名是 `Test.java`，并且其中定义的是 `Test` 类，那么编译后通常会生成 `Test.class`。

> **注意**：`javac` 的作用是**编译**，不是运行。
>
> - **`.java` 文件** 是程序员编写的源代码文件
> - **`.class` 文件** 是编译之后生成的字节码文件

> **注意**：很多初学者容易误以为：**编译后的 `.class` 文件就是机器码，可以直接被操作系统执行。**这是错误的。`.class` 文件中保存的不是操作系统能直接执行的机器指令，而是 **Java 字节码**。这种字节码并不是给操作系统直接看的，而是给 **JVM（Java Virtual Machine，Java 虚拟机）** 看的。

#### 运行阶段

当 `Test.class` 已经生成后，就可以使用 `java` 命令来运行程序。

```cmd
java Test
```

这里要注意，运行时写的是 **`Test`**，而不是 `Test.class`。因为 `java` 命令要的是 **类名**，不是文件名全称。这里的 `java` 命令可以理解为：**启动 JVM 来运行某个类**。

程序大致会按照下面的顺序运行：

1. **启动 JVM**：执行 `java Test` 后，首先启动的是 **Java 虚拟机**。
2. **JVM 启动类加载器（ClassLoader）**：JVM 启动之后，并不会凭空知道 `Test` 在哪里，它需要借助 **类加载器** 去寻找对应的字节码文件。
3. **类加载器查找 `Test.class`**：类加载器会根据类名 `Test`，去对应的位置查找 `Test.class` 文件。
4. **将 `Test.class` 加载到 JVM 中**：找到字节码文件后，类加载器会把它加载到 JVM 的内存中。
5. **JVM 解释字节码**：JVM 会把 `Test.class` 中的字节码逐步解释成当前操作系统和硬件平台能够识别的机器指令。
6. **操作系统执行机器码**：最终由操作系统去执行这些机器指令，再通过底层硬件完成实际操作。

这条主线可以概括为：**`java Test` → 启动 JVM → 启动类加载器 → 加载 `Test.class` → JVM 解释字节码 → 操作系统执行机器码**。

> **补充**：Java 之所以能够实现**跨平台**，核心原因并不是源代码本身可以直接适应所有操作系统，而是因为 Java 源代码会先被编译成统一格式的**字节码文件**，再由不同操作系统上各自安装的 **JVM（Java 虚拟机）** 去解释执行。也就是说，真正负责屏蔽平台差异的是 **JVM**，而不是 `.java` 或 `.class` 文件本身。因此常说 Java 具有“**一次编译，到处运行**”的特性。

> **补充**：Java 既有**编译过程**，也有**解释执行过程**。前者体现在：`Test.java` 需要先通过 `javac` 编译成 `Test.class`；后者体现在：`Test.class` 并不是机器码，而是需要由 JVM 再进一步解释并执行。因此，更准确地说，Java 是一种**编译与解释并存的混合型语言**，而不能简单地只归为编译型语言或解释型语言中的某一类。

> **补充**：Java 程序的**编译阶段**和**运行阶段**不一定必须在同一台机器、同一个操作系统上完成。例如，可以先在 Windows 上将 `Test.java` 编译为 `Test.class`，再把 `Test.class` 拷贝到 Linux 或 macOS 上运行。只要目标平台上安装了与该系统适配的 JVM，程序通常就可以正常执行。这也是 Java 跨平台特性的一种具体体现。

### JDK、JRE、JVM

**JDK（Java Development Kit）** 是 **Java 开发工具包**，面向开发人员使用，包含 Java 开发和运行所需的工具与类库。

**JRE（Java Runtime Environment）** 是 **Java 运行时环境**，面向程序运行，包含 Java 程序运行所需的环境和基础类库。

**JVM（Java Virtual Machine）** 是 **Java 虚拟机**，它负责把 Java 字节码解释或编译为当前平台可以执行的机器指令。

三者的关系可以直接理解为：**JDK 包含 JRE，JRE 包含 JVM**。也就是说，**JDK** 最大，既能开发也能运行；**JRE** 主要用于运行；**JVM** 则是最核心的执行环境，专门负责执行字节码。

### JDK 下载和安装（Windows）

1. **下载 JDK 安装包。** 到 Oracle 官网下载对应版本的 JDK 安装文件即可，本节以 **JDK 21** 为例，下载时注意选择 Windows 对应的版本和位数。

2. **运行安装程序。** 双击下载好的安装文件，启动安装向导后，按照提示依次点击 `Next` 继续安装即可。

4. **等待安装完成。** 在安装确认界面点击安装按钮后，等待安装程序自动完成即可，中间一般不需要额外操作。

5. **检查 `PATH` 环境变量。** 为了让系统在任意目录下都能识别 `java` 和 `javac` 命令，需要确保 JDK 的 `bin` 目录已经加入 `PATH`，例如 `C:\Program Files\Java\jdk-21\bin`。有些较新的 JDK 安装程序会自动完成这一步，但学习时仍然要理解它的作用。

6. **验证安装是否成功。** 打开命令行窗口，输入下面两个命令进行检查：

   ```cmd
   java -version
   javac -version
   ```

   如果能够正确输出版本信息，说明 JDK 已经安装成功，并且命令行可以正常找到 `java` 和 `javac`。

> ##### 环境变量
>
> 当我们在 Windows 命令行中输入一个命令时，系统并不是“天然认识”这个命令，而是要先去找这个命令对应的可执行文件。比如输入 `java` 时，Windows 实际上是在查找 `java.exe`；如果找到了，就执行它；如果找不到，就会提示该命令无法识别。
>
> Windows 查找命令时，一个非常重要的依据就是 **`PATH` 环境变量**。`PATH` 本质上是一组目录列表，系统会按照这些目录依次查找命令对应的可执行文件。正因为 `java.exe` 和 `javac.exe` 位于 JDK 的 `bin` 目录下，所以为了保证 `java` 和 `javac` 命令可用，需要把类似 `D:\Programs\Java\jdk-21\bin` 这样的路径配置到 `PATH` 中。
>
> Windows 中的环境变量又分为 **用户变量** 和 **系统变量**。前者只对当前用户生效，后者对整台计算机上的所有用户生效。实际配置 Java 时，二者都可以使用，只是生效范围不同而已。

### JDK 目录说明

安装完成 JDK 后，可以看到其中包含多个目录和文件。学习阶段不需要一开始把所有内容都记住，但要先对整体结构有一个基本认识，其中尤其要重点关注 **`bin`**、**`lib`** 和 **`src.zip`**。

| 名称                   | 作用                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **`bin` 目录**         | 存放 JDK 的可执行文件，如 `java`、`javac`、`javadoc` 等。以后在命令行中使用 Java 相关命令，本质上就是在调用这里面的程序。 |

| `legal` 目录           | 存放相关法律文件和许可证信息。                               |

### 编写第一个 Java 程序

编写第一个 Java 程序时，首先要在任意位置新建一个文件，文件名为 `HelloWorld.java`。这里最重要的是：**文件扩展名必须是 `.java`**，因为这表示它是一个 Java 源文件。如果扩展名写错，Java 编译器就无法按 Java 源代码来处理它。

然后使用任意文本编辑器打开该文件，输入下面的代码：

```java
public class HelloWorld {
    public static void main(String[] args){
        System.out.println("Hello World!");
    }
}
```

这段程序需要特别注意的地方：

1. 文件名必须是 `HelloWorld.java`。
2. 代码中的类名是 `HelloWorld`，它要与文件名保持一致。
3. `main` 方法是程序的入口，Java 程序运行时会先从这里开始执行。
4. `System.out.println("Hello World!");` 的作用是向控制台输出一行内容。

代码写完并保存后，还不能直接运行，需要先编译，再运行。

1. 先使用 `javac HelloWorld.java` 对源文件进行编译。
2. 编译成功后会生成 `HelloWorld.class` 字节码文件。
3. 再使用 `java HelloWorld` 启动 JVM 运行该程序。

#### 解释 `HelloWorld`

1. `public class HelloWorld {`：这一行定义了一个名为 `HelloWorld` 的类。`class` 表示“定义一个类”，`HelloWorld` 是类名，前面的 `public` 表示这个类是公开的，可以被外部访问。如果这里定义的是一个 **`public` 类**，那么源文件名通常也必须与类名保持一致，也就是说文件名应写成 `HelloWorld.java`。
2. `public static void main(String[] args) {`：这一行定义了程序的主方法，也就是程序的**入口方法**。当我们使用 `java HelloWorld` 运行程序时，JVM 会先找到 `HelloWorld` 这个类，再去找其中的 `main` 方法，并从这里开始执行代码。
3. `System.out.println("Hello, World!");`：这一行表示向控制台输出一行字符串内容，也就是输出 `Hello, World!`。这是程序真正完成的功能。
4. 最后两个 `}`：花括号表示代码块的结束。前一个 `}` 表示 `main` 方法结束，后一个 `}` 表示 `HelloWorld` 类结束。

#### `public class` 与 `class` 的区别

在 Java 中，`class` 和 `public class` 都可以用来定义类，但二者在 **数量限制**、**文件命名要求** 和 **使用规则** 上有所不同。

1. **一个 `.java` 源文件中可以定义多个类。**也就是说，一个 Java 文件里不一定只能写一个类，写多个类在语法上是允许的。
2. **一个类编译后通常会生成一个对应的 `.class` 文件。**如果一个源文件中写了多个类，那么编译后通常会生成多个字节码文件。
3. **`public class` 不是必须的。**一个源文件中可以一个 `public class` 都没有，只写普通的 `class`。
4. **如果一个源文件中定义了 `public class`，那么这个 `public class` 的类名必须和源文件名保持一致。**例如，若源文件名是 `Demo.java`，那么其中如果有 `public class`，这个类名就必须是 `Demo`。
5. **一个源文件中最多只能有一个 `public class`。**普通的 `class` 可以有多个，但 `public class` 如果出现，就只能有一个。
6. **任何一个类中都可以编写 `main` 方法。**也就是说，不是只有 `public class` 才能写程序入口，普通类也可以写 `main` 方法。
7. **想执行哪个类的 `main` 方法，就运行哪个类。**例如执行 `java Student`，就是从 `Student` 类的 `main` 方法开始执行；执行 `java Demo`，就是从 `Demo` 类的 `main` 方法开始执行。
8. **对于一个完整的软件系统来说，主入口通常只有一个。**虽然语法上可以在多个类中都写 `main` 方法，但实际项目中一般只保留一个主要入口。

假设源文件名为：`Book.java`

```java
class Reader {
    public static void main(String[] args) {
        System.out.println("Reader...");
    }
}

class Writer {
    public static void main(String[] args) {
        System.out.println("Writer...");
    }
}

public class Book {
    public static void main(String[] args) {
        System.out.println("Book...");
    }
}
```

编译这个文件后，通常会生成 3 个字节码文件：

- `Reader.class`
- `Writer.class`
- `Book.class`

这说明：**一个源文件中写了几个类，编译后通常就会生成几个对应的 `.class` 文件。**

### 环境变量 `CLASSPATH`

`CLASSPATH` 是一个和 Java 类加载有关的环境变量。前面接触过的 `PATH` 也是环境变量，但二者作用不同：`PATH` 是 **Windows 用来查找可执行命令** 的，而 `CLASSPATH` 是 **Java 用来查找类（`.class` 文件）** 的。更准确地说，`CLASSPATH` 是给 JVM 中的 **类加载器（ClassLoader）** 指路的。

当我们执行 `java Test` 时，JVM 会启动，并由类加载器去查找 `Test.class`。类加载器并不是随便到处找，而是按照 `CLASSPATH` 指定的路径去查找。也就是说，`CLASSPATH` 决定了：**类加载器应该去哪些位置寻找要加载的类**。

**`CLASSPATH` 的查找规则**：

1. 如果 **没有显式配置** `CLASSPATH`，那么类加载器默认会从**当前路径**下查找类。
2. 如果 **显式配置了** `CLASSPATH`，那么类加载器就会按照你配置的路径去查找，而**不会再自动从当前路径查找**。

这也是很多初学者容易困惑的地方：明明 `Test.class` 就在当前目录下，但程序仍然提示找不到类。其原因往往不是类不存在，而是你已经配置了 `CLASSPATH`，而且配置内容里**没有包含当前路径**。

> **补充**：在 Windows 中，如果希望类加载器既去 `C:\Users` 目录下查找类，又去当前路径下查找类，可以这样配置：`classpath=C:\Users;.`。这里最后的 `.` 表示**当前路径**。分号 `;` 是 Windows 下多个路径之间的分隔符。
>
> 也就是说，这个配置的含义是：先去 `C:\Users` 下找，再去当前目录下找。

> **易错点**：很多人以为配置了 `CLASSPATH` 之后，系统还会自动去当前目录查找。这个理解是错误的。**一旦显式配置了 `CLASSPATH`，当前路径就不再默认包含在内，除非你自己写上 `.`。**
