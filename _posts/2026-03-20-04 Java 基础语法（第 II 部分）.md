## 控制语句

控制语句用于**控制程序的执行流程**，决定哪些代码执行、哪些代码跳过、哪些代码需要重复执行。程序默认是自上而下顺序执行的，而控制语句的作用，就是在“顺序执行”的基础上，根据条件或规则改变执行路径。

Java 中常见的控制语句分为三类：**分支语句、循环语句、跳转语句**。其中，分支语句用于“做选择”，循环语句用于“做重复”，跳转语句用于“改变当前执行位置”或“提前结束当前结构”。

| 类别         | 作用                     | 常见语句                      |
| ------------ | ------------------------ | ----------------------------- |
| **分支语句** | 根据条件选择不同执行路径 | `if`、`switch`                |
| **循环语句** | 重复执行某段代码         | `for`、`while`、`do...while`  |
| **跳转语句** | 改变当前执行顺序         | `break`、`continue`、`return` |

### 分支语句

分支语句用于根据条件成立与否，决定程序接下来走哪一条路径。Java 中常见的分支语句有两种：`if` 和 `switch`。其中，`if` 适合处理**范围判断、条件组合、布尔表达式判断**这类问题；`switch` 更适合处理**多个固定值的匹配判断**。本节先掌握 `if` 语句。

#### if 语句

`if` 语句也叫**条件控制语句**，它的核心作用是：**先判断条件，再决定是否执行某个分支中的代码**。学习 `if` 时，最重要的不是去记四种写法，而是理解它始终围绕同一个问题展开：**条件是否成立**。

在 Java 中，`if` 后面的小括号内必须是一个**布尔表达式**，也就是结果只能是 `true` 或 `false` 的表达式。条件成立时，执行对应分支；条件不成立时，就跳过该分支，继续往后执行。

##### if 的四种基本写法

`if` 语句常见有四种形式，它们的区别主要在于：**分支数量不同，是否有兜底分支不同**。

###### 1. 单分支 if

单分支 `if` 表示：**条件成立就执行，不成立就什么都不做**。它适合处理“只有在满足某个条件时才需要额外做一件事”的场景。

```java
if (布尔表达式) {
    // 条件为 true 时执行
}
```

这种写法只有一个判断条件，因此它可能执行，也可能完全不执行。比如判断“是否成年”“是否及格”“输入是否有效”等，都可以先用单分支 `if` 做基础处理。

###### 2. 双分支 if...else

`if...else` 表示：**条件成立执行一条路径，条件不成立执行另一条路径**。它适合处理“二选一”的问题。

```java
if (布尔表达式) {
    // 条件为 true 时执行
} else {
    // 条件为 false 时执行
}
```

这种写法的特点是：只要程序进入这条 `if...else` 结构，**一定会有一个分支执行**。因为当 `if` 条件不成立时，程序会自动进入 `else` 分支。

###### 3. 多分支 if...else if...

当判断条件不止两个，而且不同条件对应不同处理方式时，可以使用 `if...else if...` 结构。程序会从上到下依次判断，一旦某个条件成立，就执行该分支，然后结束整个 `if` 结构。

```java
if (布尔表达式1) {
    // 条件1成立时执行
} else if (布尔表达式2) {
    // 条件1不成立且条件2成立时执行
} else if (布尔表达式3) {
    // 前两个条件都不成立且条件3成立时执行
}
```

这种写法适合处理“多种情况分类判断”的问题，例如成绩等级、正负零判断等。需要注意的是，它虽然有多个分支，但**不保证一定有分支执行**；如果所有条件都不成立，整个结构就会直接结束。

###### 4. 多分支 if...else if...else

这是在上一种基础上增加一个最终的 `else` 兜底分支。它表示：前面的条件都不成立时，执行最后这个默认分支。

```java
if (布尔表达式1) {
    // 条件1成立时执行
} else if (布尔表达式2) {
    // 条件2成立时执行
} else if (布尔表达式3) {
    // 条件3成立时执行
} else {
    // 以上条件都不成立时执行
}
```

这种写法既适合做多情况分类，也适合处理“前面都不满足时的默认处理”。它和 `if...else` 一样，**可以保证至少有一个分支执行**。

下面用“根据温度给出提示”来对应说明 `if` 的四种基本写法。四种写法的差别，不在于语法长短，而在于**是否需要兜底分支、是否需要处理多种情况**。

```java
int temperature = 28;

// 1. 单分支 if：条件满足才执行，不满足就直接跳过
if (temperature >= 35) {
    System.out.println("天气炎热，注意防暑");
}

// 2. 双分支 if...else：两种情况二选一
if (temperature >= 26) {
    System.out.println("今天天气偏热");
} else {
    System.out.println("今天天气较凉爽");
}

// 3. 多分支 if...else if...：多个条件依次判断，但不一定有分支执行
if (temperature > 35) {
    System.out.println("高温天气");
} else if (temperature < 0) {
    System.out.println("严寒天气");
}

// 4. 多分支 if...else if...else：多个条件依次判断，并且一定会有一个分支执行
if (temperature >= 35) {
    System.out.println("高温天气");
} else if (temperature >= 26) {
    System.out.println("炎热天气");
} else if (temperature >= 16) {
    System.out.println("温和天气");
} else {
    System.out.println("较冷天气");
}
```

> 注意：`if...else if...else` 的判断顺序是**从上往下依次进行**的，因此条件的排列顺序非常重要。前面已经匹配成功的情况下，后面的分支不会再判断。

> **如果某个分支中只有一条 Java 语句，从语法上说，大括号可以省略**。例如：
>
> ```java
> if (条件)
>     语句;
> ```
>
> 但在实际开发和学习中，一般**不建议省略大括号**。因为一旦省略，代码的视觉层次会变弱，稍不注意就容易让人误判哪些语句属于分支内部，哪些语句已经脱离分支。尤其在以后维护代码、增加新语句时，这种写法更容易埋下错误。
>
> `if` 后面如果省略大括号，那么**只有紧跟着的第一条语句**属于该分支，后面的语句默认不再受这个 `if` 控制。

##### if 语句的执行特点

对于同一个 `if` 结构来说，程序在执行时会按照顺序依次判断条件，但**最终最多只会进入一个分支**。也就是说，`if` 结构不是“多个条件都满足就执行多个分支”，而是“一旦匹配成功，就结束整组分支判断”。

这也是为什么在多分支判断中，常常要把条件写成**由特殊到一般**、或**由高到低**的顺序。例如成绩分级时，先判断 `>= 90`，再判断 `>= 80`，再判断 `>= 70`，就不需要再额外写 `< 90`、`< 80` 这些上界条件，因为只要能进入后面的分支，就已经说明前面的条件不成立了。

`else` 的作用是提供一个**兜底分支**。当所有前置条件都不成立时，程序仍然有一条明确的执行路径。正因为有了 `else`，`if...else` 和 `if...else if...else` 这两种写法才可以保证“至少有一个分支执行”。

如果没有 `else`，就意味着程序允许“所有条件都不满足，然后什么都不做”。这种情况并不一定错误，但必须是你有意为之；如果逻辑上本来希望程序一定给出一个处理结果，那么通常就应该加上 `else`。

##### if 语句中的嵌套

在 `if` 语句内部，还可以继续写 `if`，这叫做 **if 嵌套**。它适合处理“先判断大条件，再在某个分支内部继续细分”的场景。

下面以“判断一个年份中的某个月有多少天”为例：先判断月份是否合法，再在 `2` 月这个特殊分支中继续判断是否为闰年。

```java
int year = 2024;
int month = 2;

if (month >= 1 && month <= 12) {
    if (month == 2) {
        if ((year % 4 == 0 && year % 100 != 0) || year % 400 == 0) {
            System.out.println(year + "年" + month + "月有29天");
        } else {
            System.out.println(year + "年" + month + "月有28天");
        }
    } else if (month == 4 || month == 6 || month == 9 || month == 11) {
        System.out.println(year + "年" + month + "月有30天");
    } else {
        System.out.println(year + "年" + month + "月有31天");
    }
} else {
    System.out.println("月份输入不合法");
}
```

这个例子中，最外层 `if` 先保证月份合法；进入合法分支后，再根据月份分类；当月份等于 `2` 时，又继续嵌套一层 `if` 判断闰年。这样写的好处是层次清楚：**先判断大范围，再判断特殊情况**。

需要注意的是，嵌套 `if` 并不特殊，它仍然只是普通 Java 代码中的一种结构组合。只要逻辑清楚、层次明确，就可以使用；但如果嵌套层数太多，代码的可读性会明显下降，这时通常要考虑是否可以通过拆分逻辑、提取方法等方式让结构更清晰。

#### switch 语句

`switch` 语句也叫**选择语句**，用于对**同一个表达式的多个可能取值**进行分支判断。与 `if` 更擅长处理“范围、关系、复合条件”不同，`switch` 更适合处理“**某个值等于哪一个固定选项**”这一类问题，因此它常用于菜单选择、状态码判断、字符命令判断、枚举值分发等场景。

##### 基本语法

`switch` 的经典写法如下：

```java
switch (表达式) {
    case 常量值1:
        语句块1;
        break;
    case 常量值2:
        语句块2;
        break;
    case 常量值3:
        语句块3;
        break;
    default:
        默认语句块;
}
```

执行时，程序会先计算 `switch` 后面表达式的值，再依次与各个 `case` 后面的常量值进行匹配；如果匹配成功，就从对应位置开始执行；如果都不匹配，则进入 `default` 分支。这里需要特别注意，`switch` 判断的不是“是否大于、是否小于、是否同时满足多个条件”，而是“**是否等于某个固定值**”。

`switch` 适合做**精确值匹配**，不适合做复杂条件判断。比如“用户输入 `A`、`B`、`C` 分别执行不同操作”“状态码为 `0`、`1`、`2` 时输出不同信息”“命令是 `start`、`stop`、`pause` 时分别处理”，这类问题都很适合用 `switch`。但如果题目要求判断“分数是否大于 60”“年龄是否在 18 到 35 之间”“是否同时满足两个条件”，这种带有范围或逻辑组合的判断，通常还是 `if` 更自然。

下面的例子根据用户输入的命令字符，输出对应操作。这个场景中，判断对象始终是同一个变量，而且每个分支都是固定值匹配，因此用 `switch` 很合适。

```java
char command = 'P';

switch (command) {
    case 'S':
        System.out.println("执行保存操作");
        break;
    case 'P':
        System.out.println("执行打印操作");
        break;
    case 'Q':
        System.out.println("退出程序");
        break;
    default:
        System.out.println("无法识别的命令");
}
```

这个例子体现了 `switch` 的典型特点：判断对象只有一个，就是 `command`；每个分支匹配的都是明确的常量值；如果没有任何分支匹配，则进入 `default`。

##### break 与 case 穿透

在经典 `switch` 语法中，`break` 的作用是**结束当前 `switch` 结构**。如果某个 `case` 匹配成功后没有写 `break`，程序就会继续向下执行后续分支中的代码，这种现象叫做 **case 穿透**。初学阶段大多数情况下并不希望发生穿透，因此通常应在每个分支末尾显式写上 `break`。

例如：

```java
int level = 2;

switch (level) {
    case 1:
        System.out.println("普通会员");
    case 2:
        System.out.println("高级会员");
    case 3:
        System.out.println("超级会员");
    default:
        System.out.println("处理结束");
}
```

这里 `level` 的值是 `2`，程序会从 `case 2` 开始执行，但由于后面没有 `break`，所以还会继续执行 `case 3` 和 `default`。因此，经典 `switch` 中的 `break` 不是可有可无的装饰，而是决定分支是否会继续向下贯穿的重要控制点。

> **易错点**：`switch` 一旦匹配到某个 `case`，如果没有 `break`，程序不会重新判断后面的 `case` 是否匹配，而是直接顺序向下执行。

##### case 合并

当多个取值对应同一种处理逻辑时，可以把多个 `case` 合并书写，这样代码会更紧凑，也更符合“相同情况统一处理”的思路。比如根据月份判断季度时，`3`、`4`、`5` 都属于春季，就可以合并到同一组分支中。

```java
int month = 4;

switch (month) {
    case 3:
    case 4:
    case 5:
        System.out.println("当前属于春季");
        break;
    case 6:
    case 7:
    case 8:
        System.out.println("当前属于夏季");
        break;
    case 9:
    case 10:
    case 11:
        System.out.println("当前属于秋季");
        break;
    case 12:
    case 1:
    case 2:
        System.out.println("当前属于冬季");
        break;
    default:
        System.out.println("月份输入不合法");
}
```

这里多个 `case` 连续出现，但它们后面共用同一段语句块，这就是 `case` 合并。它并不是穿透导致的偶然现象，而是有意利用“多个取值对应同一处理”的一种常见写法。

##### switch 中继续嵌套 if

虽然 `switch` 适合做精确值匹配，但在某个分支内部，仍然可以继续写 `if`，用来处理该分支下更细的条件判断。也就是说，`switch` 和 `if` 并不是互相排斥的，很多实际问题反而需要它们配合使用。

例如，先根据操作类型分支，再在“转账”分支里判断余额是否足够：

```java
String action = "transfer";
double balance = 800;
double amount = 1000;

switch (action) {
    case "query":
        System.out.println("当前余额：" + balance);
        break;
    case "transfer":
        if (balance >= amount) {
            System.out.println("转账成功");
        } else {
            System.out.println("余额不足");
        }
        break;
    case "exit":
        System.out.println("系统退出");
        break;
    default:
        System.out.println("不支持的操作类型");
}
```

这个例子说明：`switch` 先负责选择“大方向”，`if` 再负责处理分支内部的细节条件。两者各有分工，组合使用很常见。

##### switch 的使用注意点

`switch` 使用时需要重点掌握以下规则。

首先，`switch` 更适合做**单一表达式的多值判断**，不适合直接处理范围判断。例如“分数在 90 到 100 之间”这种问题，本质上是区间判断，不是固定值匹配，因此直接用 `switch(score)` 并不自然。即使有些题目可以通过预处理把范围转换成整数档位再进入 `switch`，本质上也还是先做了额外变换。

其次，`case` 后面必须写**常量值**，不能直接写普通变量。因为 `switch` 在匹配时，需要把表达式结果与一组固定候选值进行比较，所以这些值必须在编译阶段就是确定的。

再次，`default` 分支虽然不是必须写的，但通常建议保留。这样即使输入值不在预期范围内，程序也能有一个明确的兜底处理，而不是静默跳过。

最后，`default` 可以写在 `switch` 块中的任意位置，但从可读性来看，通常仍然建议放在最后。

> **注意**：初学阶段可以把 `switch` 后面支持的常见类型先记为：`byte`、`short`、`char`、`int`、`String` 和 `enum`。这些已经足够覆盖大多数基础题目。

> **易错点**：`case` 后面要求的是“固定可匹配的常量值”，不是任意表达式，更不是普通变量名。

##### switch 与 if 的区别

`if` 和 `switch` 都属于分支语句，但两者擅长解决的问题并不一样。为了避免机械套用，可以从下面几个角度理解：

| 比较角度 | `if`                         | `switch`               |
| -------- | ---------------------------- | ---------------------- |
| 判断依据 | 条件是否成立                 | 值是否等于某个固定选项 |
| 适合场景 | 范围判断、关系判断、复合条件 | 单个变量的多值精确匹配 |
| 灵活性   | 更强                         | 相对更集中、更规整     |
| 可读性   | 条件复杂时更自然             | 固定值较多时更清晰     |

因此，并不是 `switch` 一定比 `if` 高级，也不是 `if` 能写的都应该改成 `switch`。真正的原则是：**看题目本质是在做条件判断，还是在做固定值分发**。

##### 较新写法

在较新的 Java 版本中，`switch` 还提供了更简洁的**箭头写法**。箭头写法的一个重要特点是：分支更紧凑，而且不会出现传统写法中那种“忘写 `break` 导致穿透”的问题。

```java
int code = 2;

switch (code) {
    case 1 -> System.out.println("订单待支付");
    case 2 -> System.out.println("订单待发货");
    case 3 -> System.out.println("订单已完成");
    default -> System.out.println("未知状态");
}
```

如果多个取值对应同一处理，也可以直接合并：

```java
int day = 6;

switch (day) {
    case 1, 2, 3, 4, 5 -> System.out.println("工作日");
    case 6, 7 -> System.out.println("休息日");
    default -> System.out.println("输入不合法");
}
```

当某个分支中有多条语句时，可以配合代码块使用：

```java
String role = "admin";

switch (role) {
    case "admin" -> {
        System.out.println("欢迎管理员登录");
        System.out.println("正在加载后台管理界面");
    }
    case "user" -> System.out.println("欢迎普通用户登录");
    default -> System.out.println("角色信息无效");
}
```

> **注意**：在 Java 12 中，`switch` 的箭头写法以预览特性的形式引入；从 Java 14 开始，这种写法成为正式特性。

### 循环语句

当某一段代码需要被**重复执行**时，就应该考虑使用循环语句。循环的作用不是单纯“少写几行代码”，而是把“重复执行的规律”表达出来：**重复做什么、重复多少次、什么时候结束**，这三件事是循环结构的核心。

Java 中常见的循环语句有三种：`for`、`while`、`do...while`。它们都能完成重复执行的任务，只是适合的场景不同。其中，`for` 最适合“**循环次数或循环规律较明确**”的情况，因此通常是初学阶段最先掌握、也最常用的一种。

| 循环语句     | 适用特点                   |
| ------------ | -------------------------- |
| `for`        | 循环次数或变化规律较明确   |
| `while`      | 先判断条件，再决定是否继续 |
| `do...while` | 先执行一次，再判断是否继续 |

#### for 循环

`for` 循环是最典型的计数型循环。它特别适合处理“从几开始，到几结束，每次怎么变化”这类问题，例如输出一段连续数字、求某个范围内的和、按固定步长遍历数据等。

它的基本语法如下：

```java
for (初始化表达式; 布尔表达式; 更新表达式) {
    // 循环体
}
```

这三个位置分别负责：**准备循环变量、控制循环是否继续、更新循环变量**。其中，真正被反复执行的是大括号中的**循环体**。

**for 循环的执行过程**：理解 `for` 循环时，重点不是死记语法，而是弄清它的执行顺序。一个标准的 `for` 循环，会按照下面的顺序运行：

1. 先执行**初始化表达式**，并且整个循环过程中只执行一次。
2. 再判断**布尔表达式**是否为 `true`。
3. 如果结果为 `true`，执行一次**循环体**。
4. 循环体执行结束后，执行一次**更新表达式**。
5. 再回到布尔表达式继续判断，决定是否进入下一轮。
6. 当布尔表达式结果为 `false` 时，循环结束。

例如：

```java
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}
```

这个循环的含义是：先让 `i` 从 `1` 开始；只要 `i <= 5`，就执行循环体；每执行完一轮，就让 `i` 自增 `1`。因此最终输出的是 `1` 到 `5`。

> **注意**：`for` 循环不是“一次性把所有内容都执行完”，而是**按轮次反复执行**。每一轮都会重新判断条件。

##### for 循环四个部分的作用

`for` 循环虽然写在一行里，但实际上可以拆成四个角色来理解。

**初始化表达式**用于准备循环开始时需要的变量，最常见的是定义计数变量。它只在循环开始前执行一次，因此通常用来完成“起点设置”。

**布尔表达式**决定循环是否继续。只要条件为 `true`，循环就会继续；一旦为 `false`，循环立即结束。它相当于整个循环的“门槛”。

**循环体**是每一轮真正要重复执行的代码。循环的价值，最终都体现在这里：到底要重复打印、重复累加，还是重复判断，都是在循环体中完成的。

**更新表达式**用于修改变量状态，使循环能够逐步逼近结束条件。它的存在非常重要，因为如果变量一直不变，布尔表达式就可能永远为 `true`，从而形成死循环。

`for` 循环中的初始化表达式、布尔表达式、更新表达式，从语法上说都**可以省略**，但这并不意味着可以随意乱省。尤其是布尔表达式一旦省略，默认相当于始终为 `true`，这通常会导致循环无法自动结束。

例如：

```java
for (;;) {
    System.out.println("循环执行中");
}
```

这是一种最典型的**无限循环**写法。它本身语法没有问题，但如果循环体中没有其他终止手段，程序就会一直运行下去。因此，初学阶段应先把标准写法掌握扎实，再去理解这些省略形式。

##### 循环变量的作用域

如果循环变量是在 `for` 的初始化部分中声明的，那么这个变量只在当前 `for` 循环内部有效，循环结束后就不能再访问了。例如：

```java
for (int i = 0; i < 3; i++) {
    System.out.println(i);
}
```

这里的 `i` 只属于这一个循环。循环结束后，`i` 的作用域也随之结束。这种写法的好处是变量使用范围更小、更集中，不容易被外部代码误用。

如果变量是在循环外部先声明，再放进 `for` 中使用，那么循环结束后它仍然可以继续访问。两种写法都合法，但从代码整洁和变量管理的角度看，**若变量只服务于当前循环，通常应尽量把它定义在 `for` 内部**。

##### for 循环的嵌套

在一个 `for` 循环的循环体中，再写另一个 `for` 循环，这就叫 **for 循环嵌套**。嵌套循环适合处理“外层控制大轮次，内层控制小轮次”的问题，例如打印矩形、打印乘法表、处理二维数据等。

理解嵌套循环时，一个很重要的原则是：**不要把内层 `for` 想得太特殊，它本质上仍然只是外层循环体中的一段普通代码**。也就是说，外层每执行一轮，内层就会完整执行一遍。

例如，下面的代码用于输出一个 `4 × 3` 的星号矩形：

```java
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 4; j++) {
        System.out.print("*");
    }
    System.out.println();
}
```

这里外层循环控制“输出几行”，内层循环控制“每行输出几个星号”。因此可以把嵌套循环理解为：**外层管行，内层管列**。很多图形打印题，本质上都是这种思路。

> **注意**：嵌套循环并不难，难的是没有分清每一层循环各自负责什么。写之前先想清楚“外层控制什么，内层控制什么”，代码就会顺很多。

##### 累加器思想

累加器思想，是指在循环开始前先准备一个变量，用来在循环过程中不断保存“当前累计结果”。这个结果可以是**和**、**积**、**个数**、**最大值**、**最小值**等。也就是说，累加器并不只用于“加法”，它本质上是一个**在循环中持续更新中间结果的变量**。

例如，求 `1 ~ 100` 的奇数和时，不可能等循环结束后再一次性得到答案，而是要在每一轮遇到符合条件的数时，把它加到已有结果中。因此需要先准备一个变量，例如 `sum`，初始值设为 `0`，然后在循环中不断执行“加入当前值”的操作。

```java
int sum = 0;
for (int i = 1; i <= 100; i += 2) {
    sum += i;
}
```

这里的 `sum` 就是累加器。它的特点是：**循环开始前先有初始值，循环过程中不断更新，循环结束后得到最终结果**。

累加器思想通常包含三个步骤：

1. 在循环外定义一个变量，作为结果保存器。
2. 根据问题性质，为它设置合适的初始值。
3. 在循环体中不断更新这个变量，直到循环结束。

之所以强调“初始值合适”，是因为不同题目的累计方式不同。求和时，初始值通常设为 `0`；求连乘时，初始值通常设为 `1`；统计个数时，初始值也通常设为 `0`。如果初始值设置错误，后面的结果即使更新过程正确，也会整体出错。

##### 标记变量思想

标记变量思想，是指在循环开始前先准备一个**布尔变量**，用它表示某种状态是否成立；然后在循环过程中根据条件变化去修改这个状态，最后在循环结束后，根据这个标记变量的值给出结论。

这种思想特别适合处理“是否满足”“是否出现过”“是否全部成立”“是否存在某种情况”这类问题。也就是说，它关注的不是累计结果，而是**状态判断**。

例如，判断一个整数是否为质数时，可以先假设它是质数，用一个变量记录这个状态：

```java
boolean isPrime = true;
```

然后在循环中尝试寻找它的因子。一旦发现存在某个数可以把它整除，就说明它不是质数，此时把 `isPrime` 改为 `false`，并结束循环。最后根据 `isPrime` 的值判断输出结果。

```java
boolean isPrime = true;
for (int i = 2; i <= num / 2; i++) {
    if (num % i == 0) {
        isPrime = false;
        break;
    }
}
```

这里的 `isPrime` 就是标记变量。它的作用不是保存数值结果，而是保存“当前判断状态”。

标记变量思想一般包含以下步骤：

1. 在循环外定义一个布尔变量，表示某种状态。
2. 根据题目要求，先给它一个合理的初始值。
3. 在循环中检查条件，一旦发现状态被破坏或状态发生变化，就修改标记变量。
4. 循环结束后，根据标记变量的最终值得出结论。

这种写法的关键在于：**先假设一种状态成立，再在遍历过程中不断验证它是否会被推翻**。在质数判断中，就是先假设“它是质数”，然后用循环去寻找反例；只要找到一个反例，这个假设就被推翻。

标记变量思想常常会和 `break` 配合使用，因为一旦结论已经明确，就没有必要继续循环。例如，在判断质数时，只要发现一个因子，就已经能够确定“它不是质数”，继续往后检查不会改变结论，因此可以直接终止循环。这样不仅逻辑更清楚，也能减少不必要的判断。

> **易错点**：标记变量的初始值不能随便写，它必须和“默认假设”保持一致。比如判断质数时，若初始值就写成 `false`，后面的逻辑就会完全错位。

#### while 循环

`while` 循环也是一种**先判断、后执行**的循环结构。它会先检查条件是否成立，只有条件为 `true` 时，才会进入循环体执行；如果一开始条件就是 `false`，那么循环体一次也不会执行。因此，`while` 循环的执行次数通常是 **0 次到多次**。

它的基本语法如下：

```java
while (布尔表达式) {
    // 循环体
}
```

这里的**布尔表达式**决定循环是否继续，循环体中写的是需要重复执行的代码。与 `for` 相比，`while` 没有把“初始化表达式”和“更新表达式”集中写在一行里，而是把它们拆到了循环外部或循环体内部，因此结构上更灵活，但也更容易因为少写更新语句而造成死循环。

**`while` 循环的执行顺序**比较直接，可以概括为下面几步：

1. 先准备循环开始前需要的变量。
2. 判断 `while` 后面的布尔表达式是否为 `true`。
3. 如果为 `true`，执行一次循环体。
4. 循环体执行结束后，再次回到条件判断处。
5. 当条件变为 `false` 时，循环结束。

例如，输出 `1 ~ 10`：

```java
int i = 1;
while (i <= 10) {
    System.out.println(i);
    i++;
}
```

这个循环中，`i = 1` 是循环开始前的准备工作；`i <= 10` 是继续执行的条件；`i++` 则负责更新变量，使 `i` 最终大于 `10`，从而让循环结束。

##### while 与 for 的关系

`while` 和 `for` 在本质上都是循环结构，都可以完成“重复执行某段代码”的任务。很多 `for` 能写的内容，`while` 也能写；很多 `while` 能写的内容，`for` 也能写。它们的主要区别，不在于“能力大小”，而在于**代码组织方式不同**。

**`for` 更适合“开始值、结束条件、更新规律都比较明确”的情况**，因为它把这三部分集中写在一行，结构非常紧凑。**`while` 则更适合“循环是否继续，主要取决于某个条件是否还成立”的情况**，因为它把重点放在条件本身上，形式更自然。

例如，输出 `1 ~ 10` 这种题目，`for` 和 `while` 都能完成：

```java
for (int i = 1; i <= 10; i++) {
    System.out.println(i);
}

int i = 1;
while (i <= 10) {
    System.out.println(i);
    i++;
}
```

两段代码的效果相同，但表达方式不同。前者更像“从 1 数到 10”，后者更像“只要还没超过 10，就继续执行”。

下面给出一个更贴近 `while` 使用特点的例子：不断对一个正整数做整除处理，直到它变成 `0` 为止。

```java
int num = 12345;

while (num > 0) {
    System.out.println(num % 10);
    num /= 10;
}
```

这个例子中，程序并没有事先写死“循环 5 次”，而是通过 `num > 0` 这个条件来决定是否继续。每执行一轮，就去掉一位数字，因此最终一定会结束。这正体现了 `while` 的典型特点：**不强调固定次数，而强调条件驱动**。

#### do...while 循环

`do...while` 循环也是一种条件控制循环，但它与 `while` 的最大区别在于：**先执行循环体，再判断条件是否成立**。因此，只要程序进入 `do...while` 结构，循环体就**至少会执行一次**。这也是它与 `while` 最本质的区别：`while` 是“先判断后执行”，执行次数是 **0 ~ N 次**；`do...while` 是“先执行后判断”，执行次数是 **1 ~ N 次**。

它的基本语法如下：

```java
do {
    // 循环体
} while (布尔表达式);
```

这里需要特别注意，`while (布尔表达式)` 后面有一个分号 `;`，这是 `do...while` 语法的一部分，不能漏写。

**`do...while` 的执行顺序**可以概括为下面几步：

1. 先执行一次 `do` 大括号中的循环体。
2. 执行结束后，判断 `while` 后面的布尔表达式。
3. 如果结果为 `true`，继续下一轮，再次执行循环体。
4. 如果结果为 `false`，循环结束。

例如：

```java
int i = 1;
do {
    System.out.println(i);
    i++;
} while (i <= 5);
```

这段代码会输出 `1 ~ 5`。它的执行逻辑不是“先看 `i <= 5` 再决定是否打印”，而是先打印一次，再决定是否继续。因此，理解 `do...while` 时一定要抓住“**第一次执行不受条件限制**”这一点。

> 注意：`do...while` 的条件判断发生在循环体之后，因此即使条件一开始就是 `false`，循环体仍然会先执行一次。

##### do...while 与 while 的区别

`do...while` 和 `while` 的结构很像，本质上也都是循环语句，但两者的适用场景略有不同。

| 比较角度 | `while`              | `do...while`     |
| -------- | -------------------- | ---------------- |
| 判断时机 | 先判断，后执行       | 先执行，后判断   |
| 执行次数 | `0 ~ N` 次           | `1 ~ N` 次       |
| 适合场景 | 可能一次都不需要执行 | 至少要先执行一次 |

例如，当程序要求“先让用户输入一次，再决定要不要继续输入”时，`do...while` 往往比 `while` 更自然；而当程序要求“只有满足条件时才允许执行”时，`while` 往往更合适。

下面这个例子用于不断读取非负整数，并在用户输入 `-1` 时结束：

```java
java.util.Scanner scanner = new java.util.Scanner(System.in);

int sum = 0;
int num;

do {
    System.out.print("请输入一个非负整数，输入 -1 结束：");
    num = scanner.nextInt();
    if (num != -1) {
        sum += num;
    }
} while (num != -1);

System.out.println("总和是：" + sum);
```

这个例子中，程序必须先接收一次输入，之后才能判断是否继续，因此用 `do...while` 会比 `while` 更贴合题意。

### 跳转语句

跳转语句用于**改变程序当前的正常执行顺序**。前面学习的分支语句和循环语句，解决的是“走哪条路”和“重复多少次”；而跳转语句解决的是“**当前这一步要不要提前结束**”“**是否直接进入下一轮**”“**是否直接离开方法**”这类问题。

Java 中常见的跳转语句有三个：`break`、`continue`、`return`。它们虽然都能“打断当前执行过程”，但作用范围并不相同。

| 跳转语句   | 作用                                   |
| ---------- | -------------------------------------- |
| `break`    | 终止当前循环，或结束 `switch` 语句     |
| `continue` | 结束当前这一次循环，直接进入下一次循环 |
| `return`   | 结束当前方法                           |

#### break

`break` 是最常见的跳转语句之一。它可以单独构成一条完整的 Java 语句，写法非常简单：

```java
break;
```

它的核心作用是：**立即结束当前所在的循环或 `switch` 语句**，后续本应继续执行的那部分内容将不再执行，程序会直接跳转到该结构之后的位置继续向下运行。

`break` 适合用于“**已经找到结果，没有必要继续循环**”的场景。例如：查找某个目标值，一旦找到就可以停止；判断一个数是否满足某个条件，一旦结论明确就不必继续；在输入处理中，一旦读到结束标记就立即退出循环。

当 `break` 出现在循环中时，它表示“**循环到这里就可以结束了**”。也就是说，不再继续后面的轮次，而是直接跳出整个循环。

例如，下面的代码在循环变量等于 `4` 时结束循环：

```java
for (int i = 0; i < 10; i++) {
    if (i == 4) {
        break;
    }
    System.out.println("i = " + i);
}
System.out.println("循环结束");
```

这段代码最终输出的是 `0、1、2、3`，当 `i == 4` 时，`break` 执行，整个 `for` 循环立即结束，因此 `4` 以及后面的值都不会再输出。循环结束后，程序继续执行后面的 `System.out.println("循环结束");`。

##### break 在 switch 中的作用

`break` 还常常出现在 `switch` 语句中，用来阻止 **case 穿透**。当某个 `case` 匹配成功并执行完对应语句后，如果没有写 `break`，程序就可能继续向下执行其他分支；而写了 `break` 之后，就会立即结束整个 `switch` 结构。

因此，在 `switch` 中，`break` 的含义不是“结束循环”，而是“**结束当前 `switch`**”。

##### break 在嵌套循环中的默认作用范围

如果一个循环内部又嵌套了另一个循环，那么 `break` 默认结束的是哪一层循环，是一个非常重要的问题。结论是：**`break` 默认只终止离它最近的那一层循环。**

例如：

```java
for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 6; col++) {
        if (col == 4) {
            break;
        }
        System.out.println("col = " + col);
    }
}
System.out.println("程序结束");
```

这里有两层循环，`break` 写在内层循环中，因此它默认只会终止内层的 `for (int col = 1; ...)`，不会终止外层循环。也就是说，每当内层循环执行到 `col == 4` 时，就结束当前这一轮内层循环，然后外层循环继续进入下一轮。

这说明，`break` 并不会“自动帮你结束所有循环”，它只对**当前所在的最近那层循环**生效。

##### 使用标签终止指定循环

在某些嵌套循环场景中，默认只结束最近一层循环还不够，我们可能希望**直接结束外层循环**。这时可以借助**标签（label）**来实现定向跳出。

标签的写法是：在某个循环前面加上一个名字和冒号，例如：

```java
outer:
for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 6; col++) {
        if (col == 4) {
            break outer;
        }
        System.out.println("col = " + col);
    }
}
System.out.println("程序结束");
```

这里的 `outer:` 就是给外层循环起的标签名。当执行到 `break outer;` 时，程序不是结束最近的内层循环，而是直接结束被标记为 `outer` 的那一层循环。也就是说，整个外层循环连同它内部的所有后续执行都会被终止。

这种写法的本质是：**`break` 不再只根据“最近原则”决定终止对象，而是明确指定要跳出哪一层循环。**

> **补充**：标签并不是 `for` 独有的语法，它本质上是给某个语句块起名字，再配合跳转语句使用。但在基础阶段，它最常见的用法就是“给外层循环加标签，然后配合 `break` 定向结束”。

#### continue

`continue` 也是一种跳转语句，它和 `break` 一样常出现在循环中，但两者的作用并不相同。`break` 是**结束整个当前循环**，而 `continue` 是**结束当前这一轮循环，直接进入下一轮**。因此，学习 `continue` 时，最关键的就是把它和 `break` 区分开：一个是“整轮循环到此为止”，一个是“这一次先跳过，后面还继续”。

`continue` 的基本写法如下：

```java
continue;
```

它只能出现在**循环语句**中，不能像 `break` 那样用于结束 `switch`。它的含义是：当前这一轮循环后面的代码不再执行，程序直接回到循环结构的下一轮流程中。

下面这段代码用于输出 `0 ~ 9`，但跳过 `4`：

```java
for (int i = 0; i < 10; i++) {
    if (i == 4) {
        continue;
    }
    System.out.println("i = " + i);
}
System.out.println("循环结束");
```

这段代码中，当 `i == 4` 时，执行 `continue`，于是本轮循环中 `continue` 后面的 `System.out.println("i = " + i);` 不会执行，程序会直接进入下一轮。因此最终会输出 `0、1、2、3、5、6、7、8、9`，唯独不会输出 `4`。

##### continue 与 break 的区别

`continue` 和 `break` 很容易混淆，因为它们都会让当前循环中的部分代码不再执行。但它们的作用层级不同。

- `break`：结束**整个当前循环**
- `continue`：结束**当前这一次循环**

例如，下面两段代码看起来很像，但结果完全不同。

使用 `break`：

```java
for (int i = 0; i < 8; i++) {
    if (i == 3) {
        break;
    }
    System.out.print(i);
}
```

输出结果是：

```
012
```

因为当 `i == 3` 时，整个循环直接结束，后面 `4、5、6、7` 都不会再进入循环。

使用 `continue`：

```java
for (int i = 0; i < 8; i++) {
    if (i == 3) {
        continue;
    }
    System.out.print(i);
}
```

输出结果是：

```
0124567
```

因为当 `i == 3` 时，只是当前这一轮不输出 `3`，但循环并没有结束，后面的 `4、5、6、7` 仍然会继续执行。

##### continue 的典型使用场景

`continue` 适合用于“**某些情况不需要处理，直接跳过即可**”的场景。例如：

- 遍历数字时跳过某些特殊值；
- 统计时只处理满足条件的数据；
- 读取输入时忽略不合法或不需要的数据；
- 输出图形时跳过某些位置。

例如，统计 `1 ~ 100` 中不是 `3` 的倍数的数字个数：

```java
int count = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) {
        continue;
    }
    count++;
}
System.out.println(count);
```

这里的思路非常清楚：凡是 `3` 的倍数就直接跳过，剩下的再统计。与其把真正要执行的代码包进一个很大的 `if` 里，不如先用 `continue` 把“不需要处理的情况”过滤掉，这样主逻辑反而更清晰。

##### 带标签的 continue

和 `break` 一样，`continue` 也可以配合标签使用。在嵌套循环中，普通 `continue` 默认只作用于**离它最近的当前循环**；如果希望直接进入某个外层循环的下一轮，也可以通过标签指定。

例如：

```java
outer:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 4; j++) {
        if (j == 3) {
            continue outer;
        }
        System.out.println("i = " + i + ", j = " + j);
    }
}
```

这里当 `j == 3` 时，执行的是 `continue outer;`，含义不是继续当前内层循环，而是**直接进入外层循环 `outer` 的下一轮**。因此，当前这一轮外层循环中后面的内层执行也全部被跳过了。

> **练习**：
>

> - B。循环变量 `i` 从 `1` 到 `6`。当 `i` 是偶数时，条件 `i % 2 == 0` 成立，执行 `continue`，因此这一轮后面的 `System.out.print(i);` 不会执行；当 `i` 是奇数时，不会进入 `continue`，所以会正常输出。因此最终输出的是 `1、3、5`，即：`135`。

#### return

`return` 也是一种跳转语句，但它和 `break`、`continue` 不在同一个层级上。前两者作用于**循环**或 `switch` 这类局部结构，而 `return` 作用于**方法**。它的核心含义是：**立即结束当前方法的执行**。

因此，学习 `return` 最直接的方式，就是把它和 `break` 放在一起比较：`break` 结束的是循环或 `switch`，结束后方法中的后续代码还有机会继续执行；而 `return` 一旦执行，当前方法会立刻结束，方法后面的代码全部不再执行。

如果它出现在 `main` 方法中，那么效果通常就表现为：当前程序的主流程直接结束，因为 `main` 本身就是程序的入口方法。

例如：

```java
public class ReturnTest1 {
    public static void main(String[] args) {
        System.out.println("开始执行");

        if (true) {
            return;
        }

        System.out.println("这句不会输出");
    }
}
```

程序只会输出“开始执行”，因为执行到 `return` 后，`main` 方法已经结束，后面的语句不会再运行。

##### return 常见的使用场景

`return` 常用于以下几类情况：

一类是**当前方法已经完成任务，没有必要继续往下执行**。例如某个结果已经找到、某个条件已经满足，这时可以直接返回。

另一类是**输入不合法，方法无法继续正常处理**。这种情况下，先做校验，再用 `return` 提前结束方法，是一种非常常见的写法。

例如：

```java
public class ReturnTest2 {
    public static void main(String[] args) {
        int score = 135;

        if (score < 0 || score > 100) {
            System.out.println("输入成绩不合法");
            return;
        }

        System.out.println("成绩输入合法，继续处理后续逻辑");
    }
}
```

这里如果输入不合法，就直接结束方法，避免程序继续处理错误数据。这种写法可以让后续代码建立在“输入已经合法”的前提上，逻辑会更清楚。

> **补充**：这种“先校验，不合法就直接 `return`”的写法，在实际开发中非常常见，因为它能减少不必要的嵌套，让主流程更清晰。

## 方法

方法是 Java 中非常重要的基础结构。前面学习的分支、循环、跳转语句，解决的是“代码怎么执行”；而方法解决的是“**这段代码是否应该单独封装出来，作为一个可以反复使用的功能**”。因此，方法的核心价值不在于语法本身，而在于它让程序从“零散语句堆在一起”逐步变成“按功能组织”的结构化代码。

### 方法的作用

方法（`method`）本质上就是一段**可以完成某个特定功能、并且能够被重复调用的代码片段**。在 C 语言中，类似的概念通常叫**函数**；在 Java 中，方法必须定义在类中，是类的一部分。

学习方法时，最先要理解的不是“怎么写语法”，而是“**为什么要有方法**”。最直接的原因就是：很多程序中的逻辑会重复出现，如果每次都重新写一遍，不仅代码冗余，而且一旦逻辑要修改，就必须到多处同步修改，维护成本很高。方法的出现，就是为了解决这种**重复代码无法复用**的问题。

例如，判断一个整数是否为质数，本质上是一种独立功能。如果程序中要判断多个数字，而每次都把完整判断逻辑重写一遍，那么代码会显得重复且臃肿。更合理的方式，是把“判断质数”这件事单独封装成一个方法，以后只需要反复调用即可。

除此之外，方法还有几个非常重要的意义。第一，它能让代码按功能拆分，避免一个方法里堆满过多细节，从而提升可读性。第二，它能把复杂问题分解成若干个小步骤，让程序结构更清晰。第三，它能隐藏具体实现细节，对外只暴露“方法名、参数、返回值”这些接口信息，调用者只关心“怎么用”，不一定需要关心“里面怎么实现”。

因此，方法不仅是“少写重复代码”的工具，更是一种**组织程序结构**的重要方式。

### 方法的定义

定义方法时，需要明确这个方法的几个关键信息：它叫什么名字、接收什么数据、完成后是否返回结果、方法体中具体做什么。其基本语法格式如下：

```java
[修饰符列表] 返回值类型 方法名(形式参数列表){
    方法体;
}
```

这是一种固定结构，虽然现在看起来组成部分较多，但本质上就是在回答几个问题：

1. **谁可以调用这个方法**
2. **这个方法最后返回什么类型的数据**
3. **这个方法叫什么**
4. **调用它时需要给它什么数据**
5. **它内部到底做什么事**

#### 修饰符列表

修饰符列表用于说明方法的访问和使用方式。现阶段可以先把它理解为“方法前面那一部分固定写法”。在当前学习阶段，通常统一写成：`public static`。

这里先不展开更深入的含义，后面学习面向对象时会进一步介绍。当前只需要知道：在本阶段的大多数示例中，方法前面通常都会写 `public static`。

#### 返回值类型

返回值类型表示：**这个方法执行结束后，会把什么类型的结果交给调用者**。

如果方法执行完之后确实会返回一个结果，那么这个类型必须明确写出来，例如 `int`、`double`、`boolean`、`String` 等。只要是 Java 中合法的数据类型，都可以作为返回值类型。

如果方法执行结束后**不返回任何数据**，返回值类型也不能空着，而是必须写：`void`。`void` 的意思是“没有返回值”。

例如：

```java
public static int sum(int a, int b)
```

表示这个方法最终会返回一个 `int` 类型的结果。

```java
public static void printLine()
```

表示这个方法只负责执行某个操作，但不向调用者返回数据。

#### 方法名

方法名就是这个功能的名字。它必须是合法标识符，但更重要的是要**见名知意**。因为方法的作用通常对应一种行为，所以方法名一般使用动词或动词短语，例如 `sum`、`printInfo`、`isPrime`、`getMax` 等。

一个好的方法名，应当让人一眼就能大致知道这个方法是干什么的，而不需要先去看方法体内部代码。

#### 形式参数列表

形式参数列表简称**形参**，位于方法名后面的小括号中，用来接收调用者传进来的数据。

例如：

```java
public static int sum(int a, int b)
```

这里的 `int a, int b` 就是形参，表示这个方法需要接收两个 `int` 类型的数据。

形参的个数可以是 `0` 个、`1` 个，也可以是多个；多个参数之间用逗号隔开。每一个形参都可以理解为该方法内部的局部变量，它们只在当前方法中有效。

如果方法不需要接收任何数据，那么小括号也不能省略，只是里面为空：

```java
public static void hello()
```

#### 方法体

方法体就是一对大括号中的内容，真正的处理逻辑都写在这里。也就是说，方法的功能最终是靠方法体中的 Java 语句实现的。

### 方法的调用

方法定义好以后，并不会自动执行；只有在程序中**调用**它时，它才会真正运行。方法调用可以理解为“**请求这个方法开始工作**”。

如果一个方法带有 `static`，那么在当前阶段通常使用下面这种方式调用：

```java
类名.方法名(实际参数列表);
```

例如：

```java
Math.abs(-10);
```

这里 `Math` 是类名，`abs` 是方法名，`-10` 是实际传进去的数据。

如果**调用者和被调用者在同一个类中**，那么前面的“类名.”通常可以省略，直接写方法名即可。例如在同一个类的 `main` 方法里调用另一个静态方法时，常常直接写：

```java
sum(10, 20);
```

而不是必须写成：

```java
当前类名.sum(10, 20);
```

#### 实参与形参

调用方法时，小括号里真正传进去的数据，叫做**实际参数**，简称**实参**；方法定义时，用来接收这些数据的变量，叫做**形式参数**，简称**形参**。

例如：

```java
sum(10, 20);
```

这里的 `10` 和 `20` 是实参。

如果方法定义是：

```java
public static int sum(int a, int b)
```

这里的 `a` 和 `b` 是形参。

学习这部分时，要重点记住一点：**实参和形参必须一一对应**。所谓对应，主要包括两层意思：

1. **个数对应**
2. **类型对应**

如果方法需要两个参数，你只传一个，就不行；如果方法要求 `int`，你传进来一个明显不能匹配的类型，也不行。

### 方法的返回值与接收

如果一个方法有返回值，那么调用这个方法时，可以用变量去接收它返回的结果。例如：

```java
double result = sum(10, 20.5);
```

这里 `sum(10, 20.5)` 执行后会返回一个结果，这个结果被变量 `result` 接收。

当然，方法即使有返回值，也不一定非要接收。例如：

```java
sum(10, 20.5);
```

这种写法也是合法的，只是返回结果被直接丢弃了，没有保存起来。

而对于 `void` 方法，由于本身没有返回值，所以自然也不能用变量去接收。

#### return 语句

`return` 是方法部分的一个核心知识点。它和前面学习过的跳转语句有联系，但在方法中，它承担了更重要的作用：**结束方法，并在需要时返回结果**。

`return` 有两种基本写法：

```java
return;
return 值;
```

##### `return;`

`return;` 表示**直接结束当前方法**，但不返回任何数据。它通常只能出现在返回值类型为 `void` 的方法中。

例如：

```java
public static void printInfo() {
    System.out.println("开始执行");
    return;
}
```

这里 `return;` 的作用是：方法到这里立即结束。

对于 `void` 方法来说，`return;` 可以写，也可以不写。如果方法走到最后自然结束，同样是合法的。

##### `return 值;`

如果方法有返回值，那么就必须使用 `return 值;` 的形式，把一个与返回值类型匹配的数据交给调用者。

例如：

```java
public static int sum(int a, int b) {
    return a + b;
}
```

这里方法声明说自己返回 `int`，那么最终就必须通过 `return` 返回一个 `int` 类型的结果。

#### 返回值类型与 return 必须一致

方法定义时的返回值类型，相当于方法对外做出的“承诺”。既然承诺说返回某种类型，方法真正执行时就必须做到。否则就属于**言行不一致**，编译器会直接报错。

例如，方法声明返回 `int`，却什么都不返回，或者只写了 `return;`，都是错误的。相反，如果方法声明是 `void`，却写了 `return 1;`，同样错误。

因此，学习方法时必须牢牢记住：**方法声明的返回值类型，必须和实际 `return` 回去的数据类型一致。**

#### return 的执行特点

`return` 不只是“返回结果”，它还有一个非常重要的特征：**只要执行到 `return`，方法立即结束**。因此，在同一个作用域中，如果某条语句已经确定一定会执行 `return`，那么它后面的语句就不可能再执行到，这种代码会被编译器判定为**无法访问的语句**。

例如：

```java
public static int m() {
    return 100;
    // 下面不能再写可执行语句
}
```

这不是风格问题，而是语义上根本不可能执行到。

不过，如果 `return` 只出现在某个条件分支里，而方法后面仍然存在其他可达路径，那么后面的代码仍然可能合法。这一点要结合具体结构来判断。

#### 返回值方法中的“缺少返回语句”

对于**返回值类型不是 `void`** 的方法，Java 要求该方法在执行结束时**必须能够返回一个对应类型的值**。如果编译器发现：这个方法在某些执行路径下可能走到末尾，却没有返回值，就会报出 **“缺少返回语句”** 的错误。

这个知识点的关键，不是看方法里“有没有写过 `return`”，而是看：**方法的所有可能执行路径，是否都一定能返回结果**。

先看下面这种写法：

```java
public static int m(){
    boolean flag = true;
    if(flag){
        return 100;
    }
}
```

这段代码虽然在 `if` 分支中写了 `return 100;`，但编译器仍然会报错：**缺少返回语句**。

原因在于：从语法分析的角度看，`flag` 是一个普通变量。虽然这里它当前被赋值为 `true`，但编译器不会仅凭这种写法，就把整个方法认定为“一定只会走 `if` 分支”。它看到的是：如果 `if(flag)` 成立，就返回 `100`；但如果不成立，方法就会直接走到结尾，而结尾并没有返回值。因此，这个方法存在“某些路径没有返回值”的可能，于是报错。

也就是说，**只在部分分支中写 `return`，并不能保证整个方法合法**。

下面这种写法同样会报错：

```java
public static int m(){
    if(true){
        return 100;
    }
}
```

虽然从运行角度看，`if(true)` 似乎一定成立，但在 Java 的这套编译规则下，**没有 `else` 的 `if` 语句仍然不足以让方法形成完整的返回路径**，因此依然会报 **“缺少返回语句”**。

而下面这种写法是正确的：

```java
public static int m(){
    boolean flag = true;
    if(flag){
        return 100;
    }else{
        return 200;
    }
}
```

因为无论条件成立还是不成立，方法最终都会返回一个 `int` 值，所以所有执行路径都被覆盖了，不会再出现“缺少返回语句”的问题。

> **注意**：Java 规定：**如果一个方法声明了返回值类型，那么只要这个方法体“有可能正常执行到结尾”，就会产生编译错误**，因为这意味着存在“没有返回值就结束方法”的路径。
>
> 而对于 **没有 `else` 的 `if` 语句**，Java 在可达性/正常完成规则上采取的是一种比较保守的处理方式：它认为这种 `if-then` 语句本身是**可以正常完成**的。也就是说，哪怕你写的是 `if(true){ return 100; }`，编译器也不会把它当成“整个方法一定已经返回了”，所以方法后面如果没有别的 `return`，仍然会报 **“缺少返回语句”**。

### 方法设计时的一个重要思路

初学方法时，很容易把方法只理解成“把一堆代码包起来”。但更重要的是：**设计方法时，要先想清楚“输入是什么，输出是什么”**。

例如，设计“判断质数”的方法时，就应先问自己：

1. 这个方法要处理什么数据？是某个整数，所以应有一个 `int` 类型参数。
2. 这个方法处理完以后，最合适的结果是什么？是“是”或“不是”，所以返回 `boolean` 最自然。

于是就能得到类似下面这样的设计：

```java
public static boolean isPrime(int num)
```

这样的方法设计比“直接在方法里打印结果”更灵活，因为调用者既可以打印，也可以继续把返回值用于其他判断逻辑。

### 方法执行时的内存变化

方法在 **定义** 和 **调用** 两种状态下，内存表现是不同的。理解这一点，是后续学习 **参数传递**、**局部变量作用范围**、**方法调用顺序** 和 **栈内存分析** 的基础。

#### 方法定义与调用时的内存分配

方法**只定义、不调用**时，不会为它分配运行时的活动空间。此时，方法对应的字节码指令只是作为类的一部分被保存下来。在 Java 8 的 HotSpot 虚拟机中，这类与类相关的信息通常放在 **元空间（Metaspace）** 中。

当方法被**真正调用**时，JVM 才会在 **虚拟机栈（JVM Stack）** 中为这次调用分配一块独立的运行空间。这个过程叫作 **压栈**，分配出来的这块空间叫作 **栈帧（Stack Frame）**。

方法执行结束后，对应的栈帧会从栈中移除，这个过程叫作 **弹栈**。弹栈之后，该方法运行期间使用的那块栈内存也随之释放。

| 状态               | 内存表现           | 说明                                       |
| ------------------ | ------------------ | ------------------------------------------ |
| 方法已定义但未调用 | 不分配运行活动空间 | 只有方法的字节码信息被保存                 |
| 方法开始调用       | 压栈               | 在虚拟机栈中创建该方法的栈帧               |
| 方法执行过程中     | 占用当前栈帧       | 局部变量、运算中间结果等都在当前栈帧中处理 |
| 方法执行结束       | 弹栈               | 当前方法对应的栈帧被释放                   |

> 栈帧中通常包含以下内容：
>
> - **局部变量表**：保存方法中的局部变量，以及形参的值。
> - **操作数栈**：保存计算过程中临时入栈、出栈的数据，用于支持表达式求值和字节码指令执行。
> - 其他与方法调用相关的信息。

#### 方法调用时栈是如何变化的

方法调用时，栈中的变化遵循一个很重要的规律：**后调用的方法先入栈，也先执行结束；先调用的方法在栈底，最后结束。**

假设调用关系是：`main` 方法中调用方法 A，方法 A 中又调用方法 B，那么执行过程可以按下面的顺序理解：

1. 程序启动后，首先进入 `main` 方法，`main` 方法对应的栈帧入栈。
2. `main` 执行到调用方法 A 时，A 的栈帧入栈。
3. A 执行到调用方法 B 时，B 的栈帧入栈。
4. B 执行结束后，B 的栈帧先弹出。
5. A 继续从调用 B 之后的位置往下执行，执行结束后，A 的栈帧弹出。
6. `main` 再继续向下执行，最后 `main` 的栈帧弹出。

也就是说，方法调用形成的是一种 **先进后出（LIFO）** 的结构，这正是“栈”这种数据结构的特点。

#### 参数传递时为什么不会互相影响

这是方法内存变化中非常经典的一点。

当一个方法调用另一个方法，并把变量传进去时，**传递过去的并不是原变量本身，而是变量中保存的值的副本**。这个副本会作为形参，存放到被调用方法自己的栈帧中的局部变量表里。

这就意味着：

- 调用者的方法有自己的局部变量；
- 被调用者的方法也有自己的局部变量；
- 它们处在**不同的栈帧**中；
- 即使变量名一样，本质上也不是同一个变量。

如果 `main` 方法中有一个整型变量，值为 `10`，调用另一个方法时把这个值传进去，那么被调用方法接收到的是 `10` 的一份复制值。之后即使被调用方法把自己的形参加一、减一，也只是修改了自己栈帧中的局部变量，不会影响 `main` 方法中原来的那个变量。

### 方法重载

**方法重载（Overload）** 是指：在**同一个类**中，允许出现**方法名相同**、但**参数列表不同**的多个方法。它属于**编译阶段**就能确定调用目标的机制，因此也常被归入**静态多态**的一种表现形式。

方法重载的核心意义，不在于“多写几个同名方法”，而在于：当一组方法的**功能本质相似**时，可以用**同一个方法名**统一表达，只通过参数差异区分不同情况。这样既符合人的理解习惯，也有利于后续维护。

当多个方法的**功能相似**，只是处理的数据类型、参数个数或输入形式不同，这时通常就适合使用方法重载。

例如，一个“求和”功能，可能既要支持整数相加，也要支持长整数相加，还要支持小数相加。虽然参与运算的数据类型不同，但它们表达的业务含义都是“求和”，这时就没有必要分别起很多不同的方法名，而是可以统一使用同一个名字，通过参数列表加以区分。

这种设计更符合自然语言习惯，也更符合 API 设计的一致性原则。

#### 什么情况下构成方法重载

判断多个方法是否构成重载，只看三个核心条件：

1. **在同一个类中**
2. **方法名相同**
3. **参数列表不同**

其中，所谓“参数列表不同”，主要包括以下三种情况：

- **参数个数不同**
- **参数类型不同**
- **参数顺序不同**

例如，下面这组方法就都构成重载：

```java
public class OverloadDemo {
    public static void show() {
    }

    public static void show(int a) {
    }

    public static void show(double a) {
    }

    public static void show(int a, int b) {
    }

    public static void show(double a, int b) {
    }
}
```

上面这些方法之所以构成重载，是因为它们虽然都叫 `show`，但参数列表彼此不同：

- `show()`：参数个数不同
- `show(int a)` 和 `show(double a)`：参数类型不同
- `show(int a, int b)` 和 `show(double a, int b)`：参数类型不同

可以概括为：只要方法名相同，并且参数列表有区别，这些方法之间就可能构成重载。

| 比较项             | 是否影响重载判断 |
| ------------------ | ---------------- |
| 方法名是否相同     | 影响             |
| 参数个数是否不同   | 影响             |
| 参数类型是否不同   | 影响             |
| 参数顺序是否不同   | 影响             |
| 返回值类型是否不同 | **不影响**       |
| 参数名是否不同     | **不影响**       |

#### 为什么返回值类型不能决定方法重载

很多初学者容易误以为：两个方法如果名字一样、参数也一样，只要返回值不同，就可以算重载。这个理解是错误的。

原因在于：**方法调用时，编译器主要根据“方法名”和“实参列表”来确定要调用哪一个方法**。如果两个方法的方法名相同、参数列表也完全相同，那么编译器在看到调用语句时，根本无法仅靠返回值来判断应该调用哪一个。

例如，一个方法调用写成 `m(10)`，编译器此时首先要确定“调用哪个 `m` 方法”。如果两个 `m` 的参数列表完全一样，只是返回值一个是 `int`、一个是 `double`，那么在调用点这里就已经产生歧义了。

所以，**返回值类型不同不能构成方法重载**。

#### 为什么参数名不同也不算重载

参数名只是方法内部用来接收数据的一个局部变量名，它不参与方法签名的区分。也就是说：

- `method(int a, int b)`
- `method(int x, int y)`

这两个方法在编译器看来，本质上仍然是同一个参数列表：都是两个 `int` 参数，因此它们不是重载，而是**重复定义**，会直接导致编译报错。

这也说明，判断重载时，应该关注的是**参数的类型、个数、顺序**，而不是参数名写成什么。

#### 方法重载在编译阶段是如何确定的

方法重载属于**编译阶段**的机制。编译器在看到方法调用时，会根据：

- 方法名
- 实参个数
- 实参类型
- 实参顺序

来匹配最合适的方法版本。

也就是说，**重载方法究竟调用哪一个，是在编译时就已经确定下来的**，而不是程序运行后才临时决定。

这也是为什么方法重载常被称为**静态多态**：看起来是“同一个方法名有多种表现形式”，但实际调用目标是在编译期静态决定的。

> **补充**：这里的“静态”指的是**调用目标在编译阶段可确定**，并不是说方法本身必须用 `static` 修饰。两者不是一个概念。

### 方法递归

**方法递归**是指：一个方法在执行过程中**再次调用它自己**。它本质上仍然是普通的方法调用，只不过调用目标恰好还是当前方法，因此在理解递归时，不能把它看成一种完全新的机制，而要把它放回到前面已经学过的 **方法调用** 和 **栈帧变化** 中去理解。

从代码形式上看，递归最直接的特征就是：**方法自己调用自己**。例如，一个方法在处理某个问题时，先把问题缩小，再交给自己继续处理，直到满足某个停止条件为止，这就是递归的基本思想。

例如，下面这个方法会不断打印数字，并把问题规模逐步缩小：

```java
public class RecursionDemo1 {
    public static void main(String[] args) {
        printNum(3);
    }

    public static void printNum(int n) {
        System.out.println(n);
        if (n == 1) {
            return;
        }
        printNum(n - 1);
    }
}
```

这段代码的执行过程是：先打印 `3`，再调用 `printNum(2)`；`printNum(2)` 再调用 `printNum(1)`；当 `n == 1` 时满足结束条件，递归停止。输出结果为：

```java
3
2
1
```

这个例子说明，递归并不是“神秘地一下完成很多事”，而是通过**一层一层调用自己**，不断把问题变小，直到可以直接结束。

递归之所以存在，是因为有些问题天然具有“**大问题可以拆成若干个同类小问题**”的结构。此时，方法不需要一次把所有过程都写平，而是可以让自己不断处理规模更小的同类问题。

例如，“计算 1 到 n 的和”这个问题，就可以拆成：

- `1 到 n 的和`
- 等于 `n + 1 到 n-1 的和`

这样就很适合用递归表达：

```java
public class RecursionDemo2 {
    public static void main(String[] args) {
        System.out.println(sum(4));
    }

    public static int sum(int n) {
        if (n == 1) {
            return 1;
        }
        return n + sum(n - 1);
    }
}
```

当调用 `sum(4)` 时，实际会逐步展开为：

1. `sum(4)` 等于 `4 + sum(3)`
2. `sum(3)` 等于 `3 + sum(2)`
3. `sum(2)` 等于 `2 + sum(1)`
4. `sum(1)` 等于 `1`

最后再逐层返回，得到结果 `10`。

不过，虽然递归写起来有时更自然，但它的底层仍然依赖方法一层一层地调用，因此它一定会伴随**栈帧不断入栈**的过程。

#### 递归的两个基本组成部分

一个完整、合法的递归，通常必须同时具备两部分：

- **递归体**：也就是方法在某种情况下继续调用自己。
- **结束条件**：也就是在满足某个条件时，不再继续递归，而是直接返回。

例如，在下面这个方法中：

```java
public static int sum(int n) {
    if (n == 1) {
        return 1;
    }
    return n + sum(n - 1);
}
```

其中：

- `if (n == 1) { return 1; }` 是**结束条件**
- `return n + sum(n - 1);` 是**递归体**

也就是说，这个方法并不是一上来就无限调用自己，而是先判断：如果已经到最小问题了，就直接返回；否则才继续递归。

如果只有递归调用，而没有结束条件，那么方法就会无限地一层一层调用自己，最终导致栈内存被耗尽。

例如：

```java
public class RecursionDemo3 {
    public static void main(String[] args) {
        test();
    }

    public static void test() {
        System.out.println("开始执行 test...");
        test();
    }
}
```

这个方法中只有 `test();`，却没有任何停止条件，因此它会一直调用自己，最终抛出 **`StackOverflowError`**。

如果只有结束条件，但递归体设计不合理，问题规模没有真正缩小，那么递归也可能无法正确结束，或者递归层数异常深，最终仍然出错。

例如，下面这个写法虽然看起来“有结束条件”，但实际上仍然有问题：

```java
public class RecursionDemo4 {
    public static void main(String[] args) {
        countDown(3);
    }

    public static void countDown(int n) {
        if (n == 0) {
            return;
        }
        System.out.println(n);
        countDown(n); // 错误：n 没有变小
    }
}
```

这里虽然写了 `if (n == 0)` 作为结束条件，但递归调用时传入的仍然是 `n`，而不是更小的值，因此 `n` 永远不会变成 `0`，结束条件也就永远无法触发。这个例子说明：**递归不仅要有结束条件，还必须让问题规模不断缩小。**

> 注意：递归真正能结束，不仅取决于“写没写结束条件”，还取决于**每次递归是否都在朝结束条件靠近**。

#### 递归为什么容易导致栈内存溢出，以及结束条件的作用

递归之所以容易出现 **栈内存溢出（`StackOverflowError`）**，根本原因在于：**每调用一次方法，JVM 都会为这次调用创建一个新的栈帧**；而递归调用又是方法不断调用自己，所以会导致栈帧持续入栈。由于栈内存大小是有限的，如果递归一直不结束，或者递归层数过深，就可能在到达结束位置之前把栈空间耗尽，从而抛出 `java.lang.StackOverflowError`。

因此，递归在使用时**必须有结束条件**。结束条件的作用，是在递归进行到某一层时停止继续调用自己，让方法开始逐层返回；如果没有结束条件，递归就会无限进行下去，栈帧不断累积，最终几乎一定会发生栈内存溢出。

例如，下面是一个**有结束条件**的递归：

```java
public static void printLevel(int level) {
    if (level == 0) {
        return;
    }
    System.out.println("第 " + level + " 层");
    printLevel(level - 1);
}
```

而下面则是一个**没有结束条件**的递归：

```java
public static void printLevel(int level) {
    System.out.println("第 " + level + " 层");
    printLevel(level - 1);
}
```

前者在 `level == 0` 时会停止，后者则会一直调用下去。这个对比可以直接看出：结束条件的本质就是给递归设置一个明确的停止点。

不过，需要特别注意的是：**有结束条件，并不等于一定不会发生栈溢出**。因为即使结束条件本身是正确的，如果递归层数太深，而 JVM 分配的栈空间又不足，那么程序仍然可能在真正到达结束条件之前就已经溢出。

例如，下面这个递归逻辑本身没有问题：

```java
public static int sum(int n) {
    if (n == 1) {
        return 1;
    }
    return n + sum(n - 1);
}
```

如果传入的是 `sum(5)`，通常没有问题；但如果传入的是一个极大的数字，例如递归层数特别深，那么即使它理论上最终可以结束，也仍然可能因为中途压栈过多而抛出栈内存溢出错误。也就是说，**“逻辑上能结束”** 和 **“运行时一定安全结束”** 不是完全一样的概念。

所以，判断一个递归是否安全，不能只看“有没有结束条件”，还要同时看两件事：第一，**递归过程是否真的在不断逼近结束条件**；第二，**在到达结束条件之前，栈空间是否足够**。这也是为什么在很多情况下，如果循环和递归都能完成同一个功能，通常更建议优先使用循环，因为循环往往不会像递归那样持续增加新的栈帧，内存开销更小，也更不容易出现栈溢出问题。

#### 递归和循环如何选择

如果一个问题既可以用递归完成，也可以用循环完成，通常应**优先考虑循环**。

原因不是因为递归“不能用”，而是因为循环通常更节省栈内存。循环反复执行时，通常仍然停留在当前方法的同一个栈帧中；而递归每深入一层，就要新建一层栈帧，因此内存开销更大，也更容易引发栈溢出问题。

例如，“计算 1 到 100 的和”这个问题，既可以写成递归，也可以写成循环。

递归写法如下：

```java
public class RecursionDemo5 {
    public static int sum(int n) {
        if (n == 1) {
            return 1;
        }
        return n + sum(n - 1);
    }
}
```

循环写法如下：

```java
public class LoopDemo {
    public static int sum(int n) {
        int result = 0;
        for (int i = 1; i <= n; i++) {
            result += i;
        }
        return result;
    }
}
```

这两种写法都能完成相同功能，但如果只是做这种线性求和，循环通常更直接，也更节省内存。因为循环始终在当前方法内部反复执行，而递归会不断产生新的方法调用。

当然，这并不意味着递归没有价值。有些问题本身就是层级结构、树形结构或分治结构，用递归表达会更自然、更清晰。例如，后面学习到文件夹遍历、树结构处理、二叉树相关问题时，递归往往就比循环更容易表达问题本身的层次关系。

但在当前阶段，应先形成一个基本判断：**能用简单循环解决的场景，通常没有必要优先写成递归。**

#### 实际开发中遇到递归栈溢出怎么办

如果在实际开发中因为递归出现了栈内存溢出，不应只盯着“扩大内存”这一种做法，而应按逻辑顺序排查。

1. **先检查递归结束条件是否正确**。确认递归是否真的存在停止条件，以及每次递归是否都在向结束条件靠近。
2. **再检查递归层数是否过深**。即使逻辑正确，也可能因为层数太多而导致栈不够用。
3. **如果业务确实需要，且递归逻辑正确，可以考虑适当调整 JVM 栈大小**。
4. **如果问题本身不适合递归，或者数据规模过大，应改用循环或其他非递归方案**。

这里需要特别注意：**扩大栈内存不是优先级最高的根本解决方案**。如果递归本身逻辑有问题，那么无论把栈调多大，最终都可能仍然溢出；只有在确认递归逻辑正确、只是调用层数较深的情况下，调整栈大小才有实际意义。

## package 和 import

`package` 和 `import` 都与 **类的组织和使用** 有关。前者解决的是“**类放在哪里、如何管理**”的问题，后者解决的是“**我在当前类中如何使用别的类**”的问题。它们本身不改变类的功能，但会直接影响代码的结构、可读性和后续维护方式。

### package

**包（package）** 本质上是一种类的组织机制。随着项目中的类越来越多，如果所有类都放在同一个位置，不仅难以管理，也容易出现**类名冲突**。因此，Java 引入包机制，把功能相关的类分门别类地组织起来。

可以把包理解成现实中的“文件夹分类”：

- 与用户相关的类放在一个包中；
- 与订单相关的类放在另一个包中；
- 与工具相关的类再放在其他包中。

这样做的好处主要有两点：**便于代码管理**、**避免类名冲突**。

例如，两个不同模块中都可能有 `UserService` 这个类名。如果没有包，它们就会重名；有了包之后，就可以分别写成：

- `com.example.user.UserService`
- `com.example.admin.UserService`

虽然简类名都叫 `UserService`，但全限定类名不同，因此不会冲突。

#### 怎么定义包

定义包的语法非常简单，直接在 Java 源文件第一行编写：

```java
package 包名;
```

例如：

```java
package com.example.shop.order;
```

这表示当前类属于 `com.example.shop.order` 这个包。

这里要特别注意：**package 语句只能写在 Java 源文件的第一行，并且通常只能写一条。** 之所以要求放在最前面，是因为编译器在处理这个类时，首先就要知道它属于哪个包；如果包信息写在后面，就不利于编译器先确定该类的逻辑位置。

例如，下面这种写法是正确的：

```java
package com.example.demo;

public class Test {
}
```

> **易错点**：**package 语句必须放在源文件第一行。** 在它前面不能先写 `import`，也不能先写 `class` 定义。

#### 包名命名规范

包名在语法上虽然可以有多种写法，但在实际开发中通常遵循统一规范：**全部小写**，并且一般采用“**公司域名倒序 + 项目名 + 模块名 + 功能名**”的形式。

例如：

- `com.example.mall.user.service`
- `com.company.crm.order.dao`

之所以使用“公司域名倒序”，主要是为了尽量保证**全局唯一性**。因为现实中公司域名本身就具有较高的唯一性，把它倒过来作为包名前缀，更不容易与别人重名。

例如，公司域名是 `example.com`，倒过来就写成 `com.example`。再往后继续补充项目、模块和功能信息，就形成了更完整的包结构。

> **注意**：包名要求使用 **小写字母**，这样风格统一，也能减少因大小写混用带来的混乱。

#### 简类名与全限定类名

有了包机制之后，一个类就有了两种常见写法：

- **简类名**：只写类名本身，例如 `OrderService`
- **全限定类名**：包名 + 类名，例如 `com.example.shop.order.OrderService`

其中，全限定类名能唯一定位到某个类；简类名只是日常书写时的简化形式。

例如，下面这个类：

```java
package com.example.study;

public class Student {
}
```

它的：

- 简类名是 `Student`
- 全限定类名是 `com.example.study.Student`

之所以要区分这两个概念，是因为在不同场景下，Java 对类名的要求不同。比如：

- **在同一个包中使用另一个类时，通常可以直接写简类名**；
- **在不同包中，若不使用 `import`，就必须写全限定类名**。

下面看一个简单例子。假设有两个类都在 `com.example.calc` 包下。

```java
package com.example.calc;

public class MathTool {
    public static void add() {
        System.out.println("执行加法逻辑");
    }
}
```

```java
package com.example.calc;

public class Test {
    public static void main(String[] args) {
        MathTool.add();
    }
}
```

这里 `Test` 中直接写 `MathTool.add();` 就可以，不需要再写成 `com.example.calc.MathTool.add();`，原因是这两个类在**同一个包下**，编译器能够直接识别这个简类名。

这说明：**同一个包中的类，彼此使用时可以直接写简类名。**

如果两个类不在同一个包下，情况就不同了。

```java
package com.example.util;

public class CountTool {
    public static void show() {
        System.out.println("显示统计结果");
    }
}
```

```java
package com.example.app;

public class Test {
    public static void main(String[] args) {
        com.example.util.CountTool.show();
    }
}
```

这里 `Test` 和 `CountTool` 不在同一个包中，因此如果不写 `import`，就必须使用**全限定类名** `com.example.util.CountTool`。

#### 带包时的编译与运行

一旦类声明了包，就不能再像无包类那样随便编译、运行了，因为编译器和 JVM 都需要按照**包结构**来定位类。

编译时常见写法是：

```cmd
javac -d 编译输出目录 Java源文件路径
```

例如：

```cmd
javac -d . Test.java
```

这里 `-d .` 表示：把编译后的 `.class` 文件按照包结构输出到当前目录下。

假设 `Test.java` 中写的是：

```java
package com.example.demo;

public class Test {
    public static void main(String[] args) {
        System.out.println("hello");
    }
}
```

编译后，当前目录下会生成类似这样的目录结构：

```
com
└─ example
   └─ demo
      └─ Test.class
```

运行时，则必须使用**全限定类名**：

```cmd
java com.example.demo.Test
```

不能再只写：

```cmd
java Test
```

原因是：带包之后，JVM 会按照全限定类名去对应的包路径中查找 `.class` 文件，而不是只在当前目录下简单查找一个叫 `Test.class` 的类。

### import

如果说 `package` 解决的是“类如何分类管理”，那么 **`import`** 解决的就是“当前类如何方便地使用其他包中的类”。

当 A 类和 B 类**不在同一个包下**时，如果 A 想使用 B，又不想每次都写 B 的全限定类名，就可以通过 `import` 把 B 引入进来。引入之后，在当前源文件中就可以直接写 B 的**简类名**。

例如，下面这个类定义在工具包中：

```java
package com.example.tool;

public class Printer {
    public static void print() {
        System.out.println("打印一行内容");
    }
}
```

如果另一个类在别的包下：

```java
package com.example.app;

import com.example.tool.Printer;

public class Test {
    public static void main(String[] args) {
        Printer.print();
    }
}
```

这里因为写了：

```java
import com.example.tool.Printer;
```

所以在 `Test` 中就可以直接写 `Printer.print();`，而不必写成：

```java
com.example.tool.Printer.print();
```

这说明：**import 的作用不是“把类复制过来”，而是让当前源文件在书写时可以直接使用该类的简类名。**

#### import 的位置要求

`import` 语句的位置也有严格要求：它只能出现在 **package 语句之下，class 定义之前**。

正确顺序应当是：

1. `package`
2. `import`
3. `class`

例如：

```java
package com.example.test;

import java.util.Scanner;

public class Demo {
}
```

如果把 `import` 写到类定义后面，就是错误的。因为编译器在读到类体之前，就要先知道外部类的引入情况。

#### 什么情况下需要 import

是否需要 `import`，可以按下面的思路判断：

- **同一个包下的类**：通常不需要 `import`
- **不同包下的类**：通常需要 `import`
- **`java.lang` 包下的类**：**不需要手动 `import`**

例如，`String`、`System`、`Math` 都属于 `java.lang` 包，因此平时直接使用即可：

```java
public class Demo {
    public static void main(String[] args) {
        String name = "Tom";
        System.out.println(name);
    }
}
```

这里没有写：

```java
import java.lang.String;
import java.lang.System;
```

程序仍然完全正常，因为 **`java.lang` 是 Java 自动默认导入的核心包**。

#### import 多个类的例子

`import` 语句可以写多条。例如：

```java
package com.example.app;

import java.util.Scanner;
import java.util.ArrayList;

public class Demo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        ArrayList list = new ArrayList();
    }
}
```

这里同时导入了 `Scanner` 和 `ArrayList` 两个类，所以在代码中都可以直接使用简类名。

#### 模糊导入（通配符导入）

如果某个包中的类使用得比较多，也可以使用通配符 `*` 做**模糊导入**：

```java
import java.util.*;
```

这样写表示：当前源文件中如果要使用 `java.util` 包下的类，可以直接写简类名。

例如：

```java
package com.example.app;

import java.util.*;

public class Demo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        HashMap map = new HashMap();
        ArrayList list = new ArrayList();
    }
}
```

这里 `Scanner`、`HashMap`、`ArrayList` 都来自 `java.util` 包，所以都能直接使用。

不过要注意，`*` 只能用于**类名这一层的批量导入**，不能写成“包名任意匹配”的形式。也就是说，下面这种写法是错误的：

```java
import *;
```

或者：

```java
import java.*;
```

这类写法都不合法。

> **补充**：`import java.util.*;` 表示导入 `java.util` 包下的所有类名使用权限，并不表示把它的子包也一起导入。比如 `java.util` 和 `java.util.regex` 是不同层级，前者的通配导入不会自动包含后者。

#### 静态导入

除了普通导入，Java 还支持 **静态导入**，语法形式为：

```java
import static 类的全限定名.静态成员;
```

或者：

```java
import static 类的全限定名.*;
```

静态导入的作用是：让某个类中的**静态成员**在当前类中可以直接使用，而不必再写“类名.”。

例如，不使用静态导入时：

```java
public class Demo {
    public static void main(String[] args) {
        System.out.println("hello");
    }
}
```

这里必须写 `System.out.println(...)`。

如果写成静态导入：

```java
package com.example.app;

import static java.lang.System.out;

public class Demo {
    public static void main(String[] args) {
        out.println("hello");
    }
}
```

此时就可以直接写 `out.println("hello");`，因为 `out` 是 `System` 类中的静态成员，已经被静态导入了。

### package 和 import 的关系

`package` 与 `import` 经常一起出现，但它们解决的问题不同：

| 关键字    | 作用                                 | 本质问题     |
| --------- | ------------------------------------ | ------------ |
| `package` | 声明当前类属于哪个包                 | 类放在哪里   |
| `import`  | 引入其他包中的类，便于直接使用简类名 | 类怎么拿来用 |

可以这样理解：

- `package` 是在给“自己”定位；
- `import` 是在把“别人”引进来方便使用。

>
> 【单选题】已知有如下两个类：
>
> ```java
> package com.demo.service;
> 
> public class UserService {
>     public static void show() {
>         System.out.println("UserService...");
>     }
> }
> ```
>
> ```java
> package com.demo.app;
> 
> public class Test {
>     public static void main(String[] args) {
>         com.demo.service.UserService.show();
>     }
> }
> ```
>
> 下列关于第二个类的说法，**正确的是**哪一项？
>
> - A. `Test` 类一定编译错误，因为没有写 `import`
> - B. `Test` 类可以正常编译，因为使用了 `UserService` 的全限定类名
> - C. `Test` 类只有在和 `UserService` 位于同一个包下时才能调用 `show()`
> - D. `Test` 类必须把 `com.demo.service.UserService.show();` 改成 `UserService.show();` 才合法
>
> 【答案】
>
> - C。`package` 语句的作用是声明当前类所属的包，因此编译器在处理源文件时，首先就要知道这个类属于哪个包，所以它**必须写在 Java 源文件第一行**。A 错在 `package` 不能放在 `import` 后面；B 错在一个源文件中通常只能声明一个所属包，因此不能写多条 `package` 语句；D 错在包名虽然语法上不一定强制全小写，但开发规范要求**全部小写**，并且通常遵循“域名倒序 + 项目名 + 模块名 + 功能名”的命名方式。
> - D。`import` 的书写位置有明确要求：它必须位于 **`package` 语句之下、`class` 定义之前**。A 错在 `java.lang` 包下的类会被 Java 自动导入，例如 `String`、`System`、`Math`，平时不需要手动 `import`；B 错在 `import` 可以写多条；C 错在同一个包下的类通常可以直接使用简类名，不必再专门写 `import`。因此只有 D 正确。
> - C。代码中虽然只手动导入了 `Scanner`，但 `String` 和 `System` 都属于 **`java.lang` 包**，这个包中的类会被 Java 自动导入，所以不需要显式写出 `import java.lang.String;` 或 `import java.lang.System;`。因此整段代码可以正常通过编译。A 和 B 都错在不了解 `java.lang` 的默认导入机制；D 错在 `Scanner` 本来就是一个普通类，完全可以通过 `import java.util.Scanner;` 引入使用。
> - B。`Test` 类虽然没有写 `import com.demo.service.UserService;`，但它在调用时直接写了 **全限定类名** `com.demo.service.UserService.show();`，因此编译器能够准确找到这个类，所以代码是合法的。A 错在把“未写 `import`”误认为“必然报错”，实际上**不用 `import` 也可以，只要写全限定类名**；C 错在不同包下的类也可以访问，只是通常需要 `import` 或直接写全限定类名；D 错在 `UserService.show();` 只有在已经 `import` 该类，或者和当前类在同一个包下时才可以直接这样写。
