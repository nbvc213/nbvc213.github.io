## File 类

`File` 是 `java.io` 包下用于表示**文件路径或目录路径**的类。实例化一个 `File` 对象，并不等于真的创建了文件或目录，它只是把某个路径封装成 Java 对象，方便后续对该路径对应的文件或目录进行判断、创建、删除、重命名、遍历等操作。

> 结论：`File` 操作的是文件或目录本身，以及文件或目录的属性；如果要读写文件内容，需要使用 IO 流技术。

### File 类的基本作用

`File` 可以表示两类路径：

1. **文件路径**：例如 `note.txt`、`D:/data/user.txt`。
2. **目录路径**：例如 `src`、`D:/workspace/project`。

例如：

```java
File file = new File("data.txt");
File dir = new File("logs");
```

这两行代码只是创建了两个 `File` 对象，并不会自动在磁盘上创建 `data.txt` 文件或 `logs` 文件夹。是否真实存在，需要通过 `exists()` 判断；如果不存在，需要调用 `createNewFile()`、`mkdir()` 或 `mkdirs()` 创建。

### File 的构造方法

`File` 常用构造方法如下：

| 构造方法                            | 说明                                   |
| ----------------------------------- | -------------------------------------- |
| `File(String pathname)`             | 根据路径字符串创建 `File` 对象         |
| `File(String parent, String child)` | 根据父路径和子路径创建 `File` 对象     |
| `File(File parent, String child)`   | 根据父路径对象和子路径创建 `File` 对象 |

#### 使用路径字符串创建 File

```java
import java.io.File;

public class FileConstructorDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println(file.getPath());
        System.out.println(file.getAbsolutePath());
    }
}
```

`"logs/app.log"` 是一个相对路径，表示从当前程序工作目录开始查找 `logs/app.log`。

#### 使用父路径和子路径创建 File

```java
File file = new File("logs", "app.log");

System.out.println(file.getPath());
```

这种写法可以把父目录和子路径分开写，适合在代码中拼接路径。

> 注意：`File` 的构造方法只是封装路径，不会检查路径是否真实存在，也不会自动创建文件或目录。

### 相对路径与绝对路径

路径可以分为**相对路径**和**绝对路径**。

| 路径类型 | 说明                                   | 示例               |
| -------- | -------------------------------------- | ------------------ |
| 相对路径 | 相对于当前工作目录的路径               | `data/user.txt`    |
| 绝对路径 | 从磁盘根目录或系统根目录开始的完整路径 | `D:/data/user.txt` |

当前工作目录可以通过系统属性 `user.dir` 获取。

```java
System.out.println(System.getProperty("user.dir"));
```

例如：

```java
File file = new File("temp.txt");
```

如果程序当前工作目录是：

```text
D:\workspace\demo
```

那么 `temp.txt` 实际表示：

```text
D:\workspace\demo\temp.txt
```

在 IDEA 中运行 Java 程序时，当前工作目录通常是**工程根目录**。如果创建了新文件但项目视图中没有立即显示，刷新项目目录即可看到。

> 易错点：相对路径不是相对于当前 Java 文件所在目录，而是相对于程序运行时的当前工作目录。

#### 路径分隔符的写法

在 Windows 系统中，路径常使用反斜杠 `\`：

```text
D:\data\test.txt
```

但在 Java 字符串中，反斜杠具有转义含义，因此直接写：

```java
File file = new File("D:\data\test.txt"); // 错误写法
```

可能导致转义问题。正确写法有两种：

```java
File file1 = new File("D:\\data\\test.txt");
File file2 = new File("D:/data/test.txt");
```

第一种使用双反斜杠表示普通反斜杠，第二种使用正斜杠。Java 在大多数常见平台上可以正确识别正斜杠路径。

> 结论：Java 路径字符串中推荐使用 `/`，或使用 `\\` 表示 Windows 反斜杠，避免转义错误。

### File 类的获取功能

`File` 提供了一组方法，用于获取文件或目录的名称、路径、大小、修改时间等信息。

| 方法                       | 说明                             |
| -------------------------- | -------------------------------- |
| `String getName()`         | 获取文件或目录名称               |
| `String getPath()`         | 获取创建 `File` 时使用的路径形式 |
| `String getAbsolutePath()` | 获取绝对路径                     |
| `long lastModified()`      | 获取最后一次修改时间，返回毫秒值 |
| `long length()`            | 获取文件大小，单位是字节         |

示例：

```java
import java.io.File;
import java.text.SimpleDateFormat;
import java.util.Date;

public class FileInfoDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println("名称：" + file.getName());
        System.out.println("路径：" + file.getPath());
        System.out.println("绝对路径：" + file.getAbsolutePath());

        long time = file.lastModified();
        String updateTime = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss").format(new Date(time));
        System.out.println("最后修改时间：" + updateTime);

        System.out.println("文件大小：" + file.length() + " 字节");
    }
}
```

需要注意：

1. `length()` 返回的是文件大小，单位是字节；
2. `lastModified()` 返回的是从 `1970-01-01 00:00:00` 到最后修改时间的毫秒数；
3. 如果文件不存在，部分方法可能返回默认值，例如 `length()` 可能返回 `0`，因此通常应先调用 `exists()` 判断。

### File 类的判断功能

`File` 可以判断路径是否存在、是否为文件、是否为目录、是否隐藏、是否可读写等。

| 方法                    | 说明                   |
| ----------------------- | ---------------------- |
| `boolean exists()`      | 判断文件或目录是否存在 |
| `boolean isDirectory()` | 判断是否为目录         |
| `boolean isFile()`      | 判断是否为普通文件     |
| `boolean isHidden()`    | 判断是否为隐藏文件     |
| `boolean canRead()`     | 判断是否可读           |
| `boolean canWrite()`    | 判断是否可写           |

示例：

```java
import java.io.File;

public class FileJudgeDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println(file.exists());
        System.out.println(file.isFile());
        System.out.println(file.isDirectory());
        System.out.println(file.isHidden());
        System.out.println(file.canRead());
        System.out.println(file.canWrite());
    }
}
```

> 注意：`File` 既可能表示文件，也可能表示目录。判断前不要只根据路径字符串猜测，应使用 `isFile()` 或 `isDirectory()` 明确判断。

### 文件和目录的创建

`File` 可以创建文件或目录。常用方法如下：

| 方法                      | 说明         |
| ------------------------- | ------------ |
| `boolean createNewFile()` | 创建文件     |
| `boolean mkdir()`         | 创建单级目录 |
| `boolean mkdirs()`        | 创建多级目录 |

#### 创建文件

```java
import java.io.File;
import java.io.IOException;

public class CreateFileDemo {
    public static void main(String[] args) throws IOException {
        File file = new File("logs/app.log");

        if (!file.exists()) {
            boolean success = file.createNewFile();
            System.out.println("创建文件：" + success);
        }
    }
}
```

`createNewFile()` 只能创建文件，不能创建目录。如果父目录不存在，创建文件会失败并可能抛出 `IOException`。

#### 创建单级目录

```java
File dir = new File("logs");

if (!dir.exists()) {
    dir.mkdir();
}
```

`mkdir()` 只能创建一级目录。如果父目录不存在，创建失败。

#### 创建多级目录

```java
File dir = new File("logs/2026/backup");

if (!dir.exists()) {
    dir.mkdirs();
}
```

`mkdirs()` 可以创建多级目录，父目录不存在时会一并创建。

> 结论：创建文件用 `createNewFile()`；创建单级目录用 `mkdir()`；创建多级目录优先使用 `mkdirs()`。

### 文件和目录的删除、重命名与移动

`File` 中常用的其他操作方法如下。

| 方法                          | 说明                   |
| ----------------------------- | ---------------------- |
| `boolean delete()`            | 删除文件或空目录       |
| `boolean renameTo(File dest)` | 重命名或移动文件、目录 |

#### 删除文件或目录

```java
File file = new File("logs/app.log");

if (file.exists()) {
    boolean success = file.delete();
    System.out.println("删除结果：" + success);
}
```

`delete()` 删除文件时不会进入回收站，而是直接删除。删除目录时，该目录必须是空目录，否则删除失败。

> 易错点：`delete()` 不能删除非空目录。如果要删除包含内容的目录，需要先递归删除目录中的所有子文件和子目录。

#### 重命名或移动

```java
File oldFile = new File("logs/app.log");
File newFile = new File("logs/system.log");

boolean success = oldFile.renameTo(newFile);
System.out.println("重命名结果：" + success);
```

如果源路径和目标路径位于不同目录，`renameTo()` 也可能表现为移动文件并重命名。不过该方法是否成功会受到操作系统、文件是否被占用、目标路径是否存在等因素影响，因此应根据返回值判断是否成功。

### list 与 listFiles

如果 `File` 表示一个目录，可以通过 `list()` 或 `listFiles()` 获取该目录下的子文件和子目录。

| 方法                 | 返回值      | 说明                                 |
| -------------------- | ----------- | ------------------------------------ |
| `String[] list()`    | 字符串数组  | 返回子文件或子目录的名称             |
| `File[] listFiles()` | `File` 数组 | 返回子文件或子目录对应的 `File` 对象 |

#### 使用 list 获取名称

```java
File dir = new File("logs");

String[] names = dir.list();

if (names != null) {
    for (String name : names) {
        System.out.println(name);
    }
}
```

#### 使用 listFiles 获取 File 对象

```java
File dir = new File("logs");

File[] files = dir.listFiles();

if (files != null) {
    for (File file : files) {
        System.out.println(file.getAbsolutePath());
    }
}
```

`listFiles()` 返回的是 `File` 对象，因此后续可以继续调用 `isFile()`、`isDirectory()`、`length()` 等方法，更适合进行复杂文件操作。

> 注意：如果当前 `File` 不是目录，或者目录不存在，或者没有访问权限，`list()` 和 `listFiles()` 可能返回 `null`。遍历前应先做非空判断。

### File 类的过滤器

在遍历目录时，如果只想获取符合条件的文件或目录，可以使用 `listFiles()` 的过滤器重载方法。常见过滤器有两种：

| 过滤器           | 方法                            | 适合场景                 |
| ---------------- | ------------------------------- | ------------------------ |
| `FilenameFilter` | `accept(File dir, String name)` | 主要根据文件名过滤       |
| `FileFilter`     | `accept(File pathname)`         | 根据完整 `File` 对象过滤 |

#### FilenameFilter：按文件名过滤

`FilenameFilter` 的 `accept()` 方法接收两个参数：

| 参数          | 含义                       |
| ------------- | -------------------------- |
| `File dir`    | 当前正在遍历的目录         |
| `String name` | 当前遍历到的文件或目录名称 |

例如，筛选指定目录下所有 `.java` 文件：

```java
import java.io.File;
import java.io.FilenameFilter;

public class FilenameFilterDemo {
    public static void main(String[] args) {
        File dir = new File("src");

        File[] files = dir.listFiles(new FilenameFilter() {
            @Override
            public boolean accept(File dir, String name) {
                // 返回 true 表示保留该文件或目录
                return name.endsWith(".java");
            }
        });

        if (files != null) {
            for (File file : files) {
                System.out.println(file.getName());
            }
        }
    }
}
```

`FilenameFilter` 适合只根据名称判断，例如筛选 `.java`、`.txt`、`.zip` 结尾的文件。

#### FileFilter：按 File 对象过滤

`FileFilter` 的 `accept()` 方法接收一个 `File` 参数，表示当前遍历到的文件或目录对象。

例如，筛选指定目录下的所有普通文件：

```java
import java.io.File;
import java.io.FileFilter;

public class FileFilterDemo {
    public static void main(String[] args) {
        File dir = new File("src");

        File[] files = dir.listFiles(new FileFilter() {
            @Override
            public boolean accept(File pathname) {
                // 只保留普通文件，不保留目录
                return pathname.isFile();
            }
        });

        if (files != null) {
            for (File file : files) {
                System.out.println(file.getAbsolutePath());
            }
        }
    }
}
```

如果要筛选所有目录，可以写成：

```java
return pathname.isDirectory();
```

如果要筛选所有 `.zip` 文件，也可以通过 `File` 对象获取名称后判断：

```java
return pathname.getName().endsWith(".zip");
```

> 结论：只关心名称时可以使用 `FilenameFilter`；需要判断文件类型、路径、大小等属性时，更适合使用 `FileFilter`。

### 递归遍历目录

如果只调用一次 `listFiles()`，只能获取当前目录的直接子文件和子目录。若要遍历某个目录下的所有层级，需要使用递归。

递归遍历的基本思路是：

1. 判断当前 `File` 是否为文件；
2. 如果是文件，直接处理；
3. 如果是目录，获取它的所有子文件和子目录；
4. 对每一个子项继续执行相同逻辑。

示例：

```java
import java.io.File;

public class RecursiveFileDemo {
    public static void main(String[] args) {
        File dir = new File("src");
        printAll(dir, 0);
    }

    public static void printAll(File file, int level) {
        if (file == null || !file.exists()) {
            return;
        }

        for (int i = 0; i < level; i++) {
            System.out.print("-");
        }

        System.out.println(file.getName());

        if (file.isDirectory()) {
            File[] files = file.listFiles();

            if (files == null) {
                return;
            }

            for (File child : files) {
                printAll(child, level + 1);
            }
        }
    }
}
```

这段代码中，`level` 表示当前递归层级，用于打印层次结构。每进入下一层目录，`level` 加 `1`。

> 注意：递归遍历目录时，应处理目录不存在、权限不足、`listFiles()` 返回 `null` 等情况，避免出现空指针异常。

## IO 流概述

IO 是 `Input/Output` 的缩写，表示**输入与输出**。在 Java 程序中，IO 流用于完成程序与外部数据之间的传输，例如从文件读取数据、向文件写入数据、从网络接收数据、向网络发送数据等。

理解 IO 流时，必须先明确一个核心参照物：**输入和输出都是站在程序内存的角度来看的**。数据从外部进入程序，称为输入；数据从程序写到外部，称为输出。

### 输入和输出的理解

**输入（Input）** 指的是程序从外部系统读取数据到内存中，核心含义是“读”。

常见输入场景包括：

1. 从硬盘文件读取内容到程序中，例如播放器读取视频文件、文本编辑器打开 `.txt` 文件；
2. 从网络读取数据到程序中，例如浏览器获取网页内容；
3. 从数据库读取数据到程序中，例如查询用户信息；
4. 从硬件设备读取数据到程序中，例如读取键盘输入、传感器数据等。

**输出（Output）** 指的是程序把内存中的数据写出到外部系统，核心含义是“写”。

常见输出场景包括：

1. 把数据写入硬盘文件，例如保存文档、生成日志文件；
2. 把数据写入数据库，例如注册用户时新增一条用户记录；
3. 把数据发送到网络中，例如客户端向服务器提交请求；
4. 把数据输出到控制台或设备中，例如 `System.out.println()` 打印内容。

> 结论：输入是“外部 → 程序内存”，输出是“程序内存 → 外部”。判断输入还是输出时，不看文件、网络或数据库本身，而是看数据相对于程序内存的流向。

### 数据源与流

在 IO 操作中，通常会涉及两个概念：**数据源**和**流**。

**数据源**是数据的来源或目的地，例如文件、网络连接、内存数组、控制台、数据库等。它本身只是数据所在的位置，不负责主动传输数据。

**流**是程序与数据源之间的数据传输通道。程序通过输入流从数据源读取数据，通过输出流把数据写入目的地。

可以这样理解：

```text
输入：数据源  ——输入流——>  程序内存

输出：程序内存  ——输出流——>  目的地
```

常见数据源如下：

| 数据源 | 作为输入时                     | 作为输出时               |
| ------ | ------------------------------ | ------------------------ |
| 文件   | 从文件读取内容                 | 向文件写入内容           |
| 网络   | 接收网络数据                   | 发送网络数据             |
| 内存   | 从数组、字符串等内存数据中读取 | 向数组、字符串缓冲区写入 |
| 控制台 | 读取键盘输入                   | 输出内容到屏幕           |

> 结论：数据源是数据所在的端点，流是连接程序和数据源的通道。没有流，程序就无法以统一方式读写外部数据。

### IO 流的单向性

流具有**方向性**。一个流通常只负责一个方向的数据传输。

| 流的方向 | 含义                   | 常见父类                 |
| -------- | ---------------------- | ------------------------ |
| 输入流   | 从外部读取数据到程序中 | `InputStream`、`Reader`  |
| 输出流   | 从程序写出数据到外部   | `OutputStream`、`Writer` |

例如，读取文件内容时，使用输入流；保存文件内容时，使用输出流。输入流不能用来写数据，输出流也不能用来读数据。

> 易错点：输入流和输出流不是站在文件角度命名的，而是站在程序角度命名的。文件中的数据进入程序，叫输入；程序中的数据写入文件，叫输出。

### 按数据单位分类：字节流与字符流

按照处理数据的基本单位，IO 流可以分为**字节流**和**字符流**。

| 分类   | 处理单位 | 常见父类                      | 适用数据     |
| ------ | -------- | ----------------------------- | ------------ |
| 字节流 | 字节     | `InputStream`、`OutputStream` | 任意类型文件 |
| 字符流 | 字符     | `Reader`、`Writer`            | 文本文件     |

#### 字节流

字节流以**字节**为单位读写数据。由于计算机底层所有文件本质上都由字节组成，所以字节流可以处理任意类型的数据。

常见适用场景包括：

1. 图片文件；
2. 音频文件；
3. 视频文件；
4. 压缩包；
5. 普通文本文件。

字节流的常见命名特点是以 `Stream` 结尾，例如 `FileInputStream`、`FileOutputStream`。

> 结论：字节流是最基础、最通用的流，适合处理所有类型的文件。

#### 字符流

字符流以**字符**为单位读写数据，主要用于处理文本内容。字符流会涉及字符编码和解码问题，例如 `UTF-8`、`GBK` 等。

常见适用场景包括：

1. `.txt` 文本文件；
2. `.java` 源代码文件；
3. `.properties` 配置文件；
4. 其他纯文本数据。

字符流的常见命名特点是以 `Reader` 或 `Writer` 结尾，例如 `FileReader`、`FileWriter`。

> 注意：字符流只适合处理文本数据，不适合处理图片、音频、视频等二进制文件。若用字符流处理二进制文件，可能破坏文件内容。

#### 字节流和字符流的选择

选择字节流还是字符流，关键看数据类型。

| 需求                         | 推荐流 |
| ---------------------------- | ------ |
| 复制图片、音频、视频、压缩包 | 字节流 |
| 复制任意文件                 | 字节流 |
| 读取或写入纯文本内容         | 字符流 |
| 需要按字符处理文本           | 字符流 |
| 不确定文件类型               | 字节流 |

如果只是复制文件，通常优先使用字节流，因为字节流不会关心文件内容含义，只按原始字节搬运数据。

如果需要读取文本中的字符内容，例如逐行读取、处理中文、解析配置文件，则更适合使用字符流。

> 结论：字节流偏底层，适合所有文件；字符流偏文本处理，适合读取和写入字符内容。

### 按功能角色分类：节点流与处理流

按照流是否直接连接数据源，可以把 IO 流分为**节点流**和**处理流**。

| 分类   | 含义                       | 作用                 |
| ------ | -------------------------- | -------------------- |
| 节点流 | 直接连接数据源或目的地的流 | 负责最基本的数据读写 |
| 处理流 | 包装其他流的流             | 增强功能或提高效率   |

#### 节点流

节点流直接与数据源连接。例如：

```text
程序 —— FileInputStream —— 文件
程序 —— FileOutputStream —— 文件
```

这类流直接操作文件、数组、字符串、管道等具体数据源，因此也可以称为基础流。

常见节点流包括：

| 节点流             | 作用           |
| ------------------ | -------------- |
| `FileInputStream`  | 从文件读取字节 |
| `FileOutputStream` | 向文件写入字节 |
| `FileReader`       | 从文件读取字符 |
| `FileWriter`       | 向文件写入字符 |

#### 处理流

处理流不直接连接数据源，而是包装在其他流外面，对原有流的功能进行增强。

例如，缓冲流可以提高读写效率：

```text
程序 —— BufferedInputStream —— FileInputStream —— 文件
```

这里 `FileInputStream` 负责直接连接文件，`BufferedInputStream` 负责在外层提供缓冲能力。

常见处理流包括：

| 处理流                 | 作用                                 |
| ---------------------- | ------------------------------------ |
| `BufferedInputStream`  | 给字节输入流增加缓冲                 |
| `BufferedOutputStream` | 给字节输出流增加缓冲                 |
| `BufferedReader`       | 给字符输入流增加缓冲，并支持按行读取 |
| `BufferedWriter`       | 给字符输出流增加缓冲                 |
| `ObjectInputStream`    | 读取对象                             |
| `ObjectOutputStream`   | 写出对象                             |

> 结论：节点流负责“连接数据源”，处理流负责“增强功能”。处理流可以包装节点流，也可以继续包装其他处理流。

### IO 流的四个抽象基类

Java IO 流体系中，有四个非常重要的抽象基类。

| 抽象基类       | 类型   | 方向 | 说明             |
| -------------- | ------ | ---- | ---------------- |
| `InputStream`  | 字节流 | 输入 | 字节输入流的父类 |
| `OutputStream` | 字节流 | 输出 | 字节输出流的父类 |
| `Reader`       | 字符流 | 输入 | 字符输入流的父类 |
| `Writer`       | 字符流 | 输出 | 字符输出流的父类 |

可以按两个维度记忆：

```text
按方向：
InputStream / Reader      输入
OutputStream / Writer     输出

按单位：
InputStream / OutputStream    字节
Reader / Writer               字符
```

> 结论：看到类名以 `InputStream` 或 `Reader` 结尾，通常表示输入流；看到类名以 `OutputStream` 或 `Writer` 结尾，通常表示输出流。

### IO 流体系概览

常见 IO 流可以按如下结构理解：

```text
IO 流
├── 字节流
│   ├── 字节输入流：InputStream
│   │   ├── FileInputStream
│   │   ├── BufferedInputStream
│   │   └── ObjectInputStream
│   └── 字节输出流：OutputStream
│       ├── FileOutputStream
│       ├── BufferedOutputStream
│       └── ObjectOutputStream
└── 字符流
    ├── 字符输入流：Reader
    │   ├── FileReader
    │   └── BufferedReader
    └── 字符输出流：Writer
        ├── FileWriter
        └── BufferedWriter
```

当前阶段不需要一次性掌握所有 IO 类。学习时应先抓住四个基础方向：字节输入、字节输出、字符输入、字符输出，再逐步学习文件流、缓冲流、转换流、对象流等具体实现类。

## IO 流学习主线

IO 流类很多，但学习顺序可以按照以下主线展开：

1. 先理解输入和输出的方向；
2. 再区分字节流和字符流；
3. 然后学习最基础的文件节点流；
4. 再学习缓冲流等处理流；
5. 最后学习对象流、转换流等特殊功能流。

对应关系如下：

| 学习阶段     | 重点                                                         |
| ------------ | ------------------------------------------------------------ |
| 基础概念     | 输入、输出、数据源、流                                       |
| 基础分类     | 字节流、字符流                                               |
| 基础文件操作 | `FileInputStream`、`FileOutputStream`、`FileReader`、`FileWriter` |
| 性能增强     | 缓冲流                                                       |
| 特殊处理     | 转换流、对象流等                                             |

> 结论：IO 流看似类很多，本质上都是围绕“数据从哪里来、到哪里去、按什么单位传输、是否需要功能增强”这几个问题展开。
