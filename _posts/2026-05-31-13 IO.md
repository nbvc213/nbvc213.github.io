## File 类

`File` 是 `java.io` 包下用于表示**文件路径或目录路径**的类。实例化一个 `File` 对象，并不等于真的创建了文件或目录，它只是把某个路径封装成 Java 对象，方便后续对该路径对应的文件或目录进行判断、创建、删除、重命名、遍历等操作。

> 结论：`File` 操作的是文件或目录本身，以及文件或目录的属性；如果要读写文件内容，需要使用 IO 流技术。

### File 类的基本作用

`File` 可以表示两类路径：

1. **文件路径**：例如 `note.txt`、`D:/data/user.txt`。
2. **目录路径**：例如 `src`、`D:/workspace/project`。

例如：

```java
File file = new File("data.txt");
File dir = new File("logs");
```

这两行代码只是创建了两个 `File` 对象，并不会自动在磁盘上创建 `data.txt` 文件或 `logs` 文件夹。是否真实存在，需要通过 `exists()` 判断；如果不存在，需要调用 `createNewFile()`、`mkdir()` 或 `mkdirs()` 创建。

### File 的构造方法

`File` 常用构造方法如下：

| 构造方法                            | 说明                                   |
| ----------------------------------- | -------------------------------------- |
| `File(String pathname)`             | 根据路径字符串创建 `File` 对象         |
| `File(String parent, String child)` | 根据父路径和子路径创建 `File` 对象     |
| `File(File parent, String child)`   | 根据父路径对象和子路径创建 `File` 对象 |

#### 使用路径字符串创建 File

```java
import java.io.File;

public class FileConstructorDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println(file.getPath());
        System.out.println(file.getAbsolutePath());
    }
}
```

`"logs/app.log"` 是一个相对路径，表示从当前程序工作目录开始查找 `logs/app.log`。

#### 使用父路径和子路径创建 File

```java
File file = new File("logs", "app.log");

System.out.println(file.getPath());
```

这种写法可以把父目录和子路径分开写，适合在代码中拼接路径。

> 注意：`File` 的构造方法只是封装路径，不会检查路径是否真实存在，也不会自动创建文件或目录。

### 相对路径与绝对路径

路径可以分为**相对路径**和**绝对路径**。

| 路径类型 | 说明                                   | 示例               |
| -------- | -------------------------------------- | ------------------ |
| 相对路径 | 相对于当前工作目录的路径               | `data/user.txt`    |
| 绝对路径 | 从磁盘根目录或系统根目录开始的完整路径 | `D:/data/user.txt` |

当前工作目录可以通过系统属性 `user.dir` 获取。

```java
System.out.println(System.getProperty("user.dir"));
```

例如：

```java
File file = new File("temp.txt");
```

如果程序当前工作目录是：

```text
D:\workspace\demo
```

那么 `temp.txt` 实际表示：

```text
D:\workspace\demo\temp.txt
```

在 IDEA 中运行 Java 程序时，当前工作目录通常是**工程根目录**。如果创建了新文件但项目视图中没有立即显示，刷新项目目录即可看到。

> 易错点：相对路径不是相对于当前 Java 文件所在目录，而是相对于程序运行时的当前工作目录。

#### 路径分隔符的写法

在 Windows 系统中，路径常使用反斜杠 `\`：

```text
D:\data\test.txt
```

但在 Java 字符串中，反斜杠具有转义含义，因此直接写：

```java
File file = new File("D:\data\test.txt"); // 错误写法
```

可能导致转义问题。正确写法有两种：

```java
File file1 = new File("D:\\data\\test.txt");
File file2 = new File("D:/data/test.txt");
```

第一种使用双反斜杠表示普通反斜杠，第二种使用正斜杠。Java 在大多数常见平台上可以正确识别正斜杠路径。

> 结论：Java 路径字符串中推荐使用 `/`，或使用 `\\` 表示 Windows 反斜杠，避免转义错误。

### File 类的获取功能

`File` 提供了一组方法，用于获取文件或目录的名称、路径、大小、修改时间等信息。

| 方法                       | 说明                             |
| -------------------------- | -------------------------------- |
| `String getName()`         | 获取文件或目录名称               |
| `String getPath()`         | 获取创建 `File` 时使用的路径形式 |
| `String getAbsolutePath()` | 获取绝对路径                     |
| `long lastModified()`      | 获取最后一次修改时间，返回毫秒值 |
| `long length()`            | 获取文件大小，单位是字节         |

示例：

```java
import java.io.File;
import java.text.SimpleDateFormat;
import java.util.Date;

public class FileInfoDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println("名称：" + file.getName());
        System.out.println("路径：" + file.getPath());
        System.out.println("绝对路径：" + file.getAbsolutePath());

        long time = file.lastModified();
        String updateTime = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss").format(new Date(time));
        System.out.println("最后修改时间：" + updateTime);

        System.out.println("文件大小：" + file.length() + " 字节");
    }
}
```

需要注意：

1. `length()` 返回的是文件大小，单位是字节；
2. `lastModified()` 返回的是从 `1970-01-01 00:00:00` 到最后修改时间的毫秒数；
3. 如果文件不存在，部分方法可能返回默认值，例如 `length()` 可能返回 `0`，因此通常应先调用 `exists()` 判断。

### File 类的判断功能

`File` 可以判断路径是否存在、是否为文件、是否为目录、是否隐藏、是否可读写等。

| 方法                    | 说明                   |
| ----------------------- | ---------------------- |
| `boolean exists()`      | 判断文件或目录是否存在 |
| `boolean isDirectory()` | 判断是否为目录         |
| `boolean isFile()`      | 判断是否为普通文件     |
| `boolean isHidden()`    | 判断是否为隐藏文件     |
| `boolean canRead()`     | 判断是否可读           |
| `boolean canWrite()`    | 判断是否可写           |

示例：

```java
import java.io.File;

public class FileJudgeDemo {
    public static void main(String[] args) {
        File file = new File("logs/app.log");

        System.out.println(file.exists());
        System.out.println(file.isFile());
        System.out.println(file.isDirectory());
        System.out.println(file.isHidden());
        System.out.println(file.canRead());
        System.out.println(file.canWrite());
    }
}
```

> 注意：`File` 既可能表示文件，也可能表示目录。判断前不要只根据路径字符串猜测，应使用 `isFile()` 或 `isDirectory()` 明确判断。

### 文件和目录的创建

`File` 可以创建文件或目录。常用方法如下：

| 方法                      | 说明         |
| ------------------------- | ------------ |
| `boolean createNewFile()` | 创建文件     |
| `boolean mkdir()`         | 创建单级目录 |
| `boolean mkdirs()`        | 创建多级目录 |

#### 创建文件

```java
import java.io.File;
import java.io.IOException;

public class CreateFileDemo {
    public static void main(String[] args) throws IOException {
        File file = new File("logs/app.log");

        if (!file.exists()) {
            boolean success = file.createNewFile();
            System.out.println("创建文件：" + success);
        }
    }
}
```

`createNewFile()` 只能创建文件，不能创建目录。如果父目录不存在，创建文件会失败并可能抛出 `IOException`。

#### 创建单级目录

```java
File dir = new File("logs");

if (!dir.exists()) {
    dir.mkdir();
}
```

`mkdir()` 只能创建一级目录。如果父目录不存在，创建失败。

#### 创建多级目录

```java
File dir = new File("logs/2026/backup");

if (!dir.exists()) {
    dir.mkdirs();
}
```

`mkdirs()` 可以创建多级目录，父目录不存在时会一并创建。

> 结论：创建文件用 `createNewFile()`；创建单级目录用 `mkdir()`；创建多级目录优先使用 `mkdirs()`。

### 文件和目录的删除、重命名与移动

`File` 中常用的其他操作方法如下。

| 方法                          | 说明                   |
| ----------------------------- | ---------------------- |
| `boolean delete()`            | 删除文件或空目录       |
| `boolean renameTo(File dest)` | 重命名或移动文件、目录 |

#### 删除文件或目录

```java
File file = new File("logs/app.log");

if (file.exists()) {
    boolean success = file.delete();
    System.out.println("删除结果：" + success);
}
```

`delete()` 删除文件时不会进入回收站，而是直接删除。删除目录时，该目录必须是空目录，否则删除失败。

> 易错点：`delete()` 不能删除非空目录。如果要删除包含内容的目录，需要先递归删除目录中的所有子文件和子目录。

#### 重命名或移动

```java
File oldFile = new File("logs/app.log");
File newFile = new File("logs/system.log");

boolean success = oldFile.renameTo(newFile);
System.out.println("重命名结果：" + success);
```

如果源路径和目标路径位于不同目录，`renameTo()` 也可能表现为移动文件并重命名。不过该方法是否成功会受到操作系统、文件是否被占用、目标路径是否存在等因素影响，因此应根据返回值判断是否成功。

### list 与 listFiles

如果 `File` 表示一个目录，可以通过 `list()` 或 `listFiles()` 获取该目录下的子文件和子目录。

| 方法                 | 返回值      | 说明                                 |
| -------------------- | ----------- | ------------------------------------ |
| `String[] list()`    | 字符串数组  | 返回子文件或子目录的名称             |
| `File[] listFiles()` | `File` 数组 | 返回子文件或子目录对应的 `File` 对象 |

#### 使用 list 获取名称

```java
File dir = new File("logs");

String[] names = dir.list();

if (names != null) {
    for (String name : names) {
        System.out.println(name);
    }
}
```

#### 使用 listFiles 获取 File 对象

```java
File dir = new File("logs");

File[] files = dir.listFiles();

if (files != null) {
    for (File file : files) {
        System.out.println(file.getAbsolutePath());
    }
}
```

`listFiles()` 返回的是 `File` 对象，因此后续可以继续调用 `isFile()`、`isDirectory()`、`length()` 等方法，更适合进行复杂文件操作。

> 注意：如果当前 `File` 不是目录，或者目录不存在，或者没有访问权限，`list()` 和 `listFiles()` 可能返回 `null`。遍历前应先做非空判断。

### File 类的过滤器

在遍历目录时，如果只想获取符合条件的文件或目录，可以使用 `listFiles()` 的过滤器重载方法。常见过滤器有两种：

| 过滤器           | 方法                            | 适合场景                 |
| ---------------- | ------------------------------- | ------------------------ |
| `FilenameFilter` | `accept(File dir, String name)` | 主要根据文件名过滤       |
| `FileFilter`     | `accept(File pathname)`         | 根据完整 `File` 对象过滤 |

#### FilenameFilter：按文件名过滤

`FilenameFilter` 的 `accept()` 方法接收两个参数：

| 参数          | 含义                       |
| ------------- | -------------------------- |
| `File dir`    | 当前正在遍历的目录         |
| `String name` | 当前遍历到的文件或目录名称 |

例如，筛选指定目录下所有 `.java` 文件：

```java
import java.io.File;
import java.io.FilenameFilter;

public class FilenameFilterDemo {
    public static void main(String[] args) {
        File dir = new File("src");

        File[] files = dir.listFiles(new FilenameFilter() {
            @Override
            public boolean accept(File dir, String name) {
                // 返回 true 表示保留该文件或目录
                return name.endsWith(".java");
            }
        });

        if (files != null) {
            for (File file : files) {
                System.out.println(file.getName());
            }
        }
    }
}
```

`FilenameFilter` 适合只根据名称判断，例如筛选 `.java`、`.txt`、`.zip` 结尾的文件。

#### FileFilter：按 File 对象过滤

`FileFilter` 的 `accept()` 方法接收一个 `File` 参数，表示当前遍历到的文件或目录对象。

例如，筛选指定目录下的所有普通文件：

```java
import java.io.File;
import java.io.FileFilter;

public class FileFilterDemo {
    public static void main(String[] args) {
        File dir = new File("src");

        File[] files = dir.listFiles(new FileFilter() {
            @Override
            public boolean accept(File pathname) {
                // 只保留普通文件，不保留目录
                return pathname.isFile();
            }
        });

        if (files != null) {
            for (File file : files) {
                System.out.println(file.getAbsolutePath());
            }
        }
    }
}
```

如果要筛选所有目录，可以写成：

```java
return pathname.isDirectory();
```

如果要筛选所有 `.zip` 文件，也可以通过 `File` 对象获取名称后判断：

```java
return pathname.getName().endsWith(".zip");
```

> 结论：只关心名称时可以使用 `FilenameFilter`；需要判断文件类型、路径、大小等属性时，更适合使用 `FileFilter`。

### 递归遍历目录

如果只调用一次 `listFiles()`，只能获取当前目录的直接子文件和子目录。若要遍历某个目录下的所有层级，需要使用递归。

递归遍历的基本思路是：

1. 判断当前 `File` 是否为文件；
2. 如果是文件，直接处理；
3. 如果是目录，获取它的所有子文件和子目录；
4. 对每一个子项继续执行相同逻辑。

示例：

```java
import java.io.File;

public class RecursiveFileDemo {
    public static void main(String[] args) {
        File dir = new File("src");
        printAll(dir, 0);
    }

    public static void printAll(File file, int level) {
        if (file == null || !file.exists()) {
            return;
        }

        for (int i = 0; i < level; i++) {
            System.out.print("-");
        }

        System.out.println(file.getName());

        if (file.isDirectory()) {
            File[] files = file.listFiles();

            if (files == null) {
                return;
            }

            for (File child : files) {
                printAll(child, level + 1);
            }
        }
    }
}
```

这段代码中，`level` 表示当前递归层级，用于打印层次结构。每进入下一层目录，`level` 加 `1`。

> 注意：递归遍历目录时，应处理目录不存在、权限不足、`listFiles()` 返回 `null` 等情况，避免出现空指针异常。

## IO 流概述

IO 是 `Input/Output` 的缩写，表示**输入与输出**。在 Java 程序中，IO 流用于完成程序与外部数据之间的传输，例如从文件读取数据、向文件写入数据、从网络接收数据、向网络发送数据等。

理解 IO 流时，必须先明确一个核心参照物：**输入和输出都是站在程序内存的角度来看的**。数据从外部进入程序，称为输入；数据从程序写到外部，称为输出。

### 输入和输出的理解

**输入（Input）** 指的是程序从外部系统读取数据到内存中，核心含义是“读”。

常见输入场景包括：

1. 从硬盘文件读取内容到程序中，例如播放器读取视频文件、文本编辑器打开 `.txt` 文件；
2. 从网络读取数据到程序中，例如浏览器获取网页内容；
3. 从数据库读取数据到程序中，例如查询用户信息；
4. 从硬件设备读取数据到程序中，例如读取键盘输入、传感器数据等。

**输出（Output）** 指的是程序把内存中的数据写出到外部系统，核心含义是“写”。

常见输出场景包括：

1. 把数据写入硬盘文件，例如保存文档、生成日志文件；
2. 把数据写入数据库，例如注册用户时新增一条用户记录；
3. 把数据发送到网络中，例如客户端向服务器提交请求；
4. 把数据输出到控制台或设备中，例如 `System.out.println()` 打印内容。

> 结论：输入是“外部 → 程序内存”，输出是“程序内存 → 外部”。判断输入还是输出时，不看文件、网络或数据库本身，而是看数据相对于程序内存的流向。

### 数据源与流

在 IO 操作中，通常会涉及两个概念：**数据源**和**流**。

**数据源**是数据的来源或目的地，例如文件、网络连接、内存数组、控制台、数据库等。它本身只是数据所在的位置，不负责主动传输数据。

**流**是程序与数据源之间的数据传输通道。程序通过输入流从数据源读取数据，通过输出流把数据写入目的地。

可以这样理解：

```text
输入：数据源  ——输入流——>  程序内存

输出：程序内存  ——输出流——>  目的地
```

常见数据源如下：

| 数据源 | 作为输入时                     | 作为输出时               |
| ------ | ------------------------------ | ------------------------ |
| 文件   | 从文件读取内容                 | 向文件写入内容           |
| 网络   | 接收网络数据                   | 发送网络数据             |
| 内存   | 从数组、字符串等内存数据中读取 | 向数组、字符串缓冲区写入 |
| 控制台 | 读取键盘输入                   | 输出内容到屏幕           |

> 结论：数据源是数据所在的端点，流是连接程序和数据源的通道。没有流，程序就无法以统一方式读写外部数据。

### IO 流的单向性

流具有**方向性**。一个流通常只负责一个方向的数据传输。

| 流的方向 | 含义                   | 常见父类                 |
| -------- | ---------------------- | ------------------------ |
| 输入流   | 从外部读取数据到程序中 | `InputStream`、`Reader`  |
| 输出流   | 从程序写出数据到外部   | `OutputStream`、`Writer` |

例如，读取文件内容时，使用输入流；保存文件内容时，使用输出流。输入流不能用来写数据，输出流也不能用来读数据。

> 易错点：输入流和输出流不是站在文件角度命名的，而是站在程序角度命名的。文件中的数据进入程序，叫输入；程序中的数据写入文件，叫输出。

### 按数据单位分类：字节流与字符流

按照处理数据的基本单位，IO 流可以分为**字节流**和**字符流**。

| 分类   | 处理单位 | 常见父类                      | 适用数据     |
| ------ | -------- | ----------------------------- | ------------ |
| 字节流 | 字节     | `InputStream`、`OutputStream` | 任意类型文件 |
| 字符流 | 字符     | `Reader`、`Writer`            | 文本文件     |

#### 字节流

字节流以**字节**为单位读写数据。由于计算机底层所有文件本质上都由字节组成，所以字节流可以处理任意类型的数据。

常见适用场景包括：

1. 图片文件；
2. 音频文件；
3. 视频文件；
4. 压缩包；
5. 普通文本文件。

字节流的常见命名特点是以 `Stream` 结尾，例如 `FileInputStream`、`FileOutputStream`。

> 结论：字节流是最基础、最通用的流，适合处理所有类型的文件。

#### 字符流

字符流以**字符**为单位读写数据，主要用于处理文本内容。字符流会涉及字符编码和解码问题，例如 `UTF-8`、`GBK` 等。

常见适用场景包括：

1. `.txt` 文本文件；
2. `.java` 源代码文件；
3. `.properties` 配置文件；
4. 其他纯文本数据。

字符流的常见命名特点是以 `Reader` 或 `Writer` 结尾，例如 `FileReader`、`FileWriter`。

> 注意：字符流只适合处理文本数据，不适合处理图片、音频、视频等二进制文件。若用字符流处理二进制文件，可能破坏文件内容。

#### 字节流和字符流的选择

选择字节流还是字符流，关键看数据类型。

| 需求                         | 推荐流 |
| ---------------------------- | ------ |
| 复制图片、音频、视频、压缩包 | 字节流 |
| 复制任意文件                 | 字节流 |
| 读取或写入纯文本内容         | 字符流 |
| 需要按字符处理文本           | 字符流 |
| 不确定文件类型               | 字节流 |

如果只是复制文件，通常优先使用字节流，因为字节流不会关心文件内容含义，只按原始字节搬运数据。

如果需要读取文本中的字符内容，例如逐行读取、处理中文、解析配置文件，则更适合使用字符流。

> 结论：字节流偏底层，适合所有文件；字符流偏文本处理，适合读取和写入字符内容。

### 按功能角色分类：节点流与处理流

按照流是否直接连接数据源，可以把 IO 流分为**节点流**和**处理流**。

| 分类   | 含义                       | 作用                 |
| ------ | -------------------------- | -------------------- |
| 节点流 | 直接连接数据源或目的地的流 | 负责最基本的数据读写 |
| 处理流 | 包装其他流的流             | 增强功能或提高效率   |

#### 节点流

节点流直接与数据源连接。例如：

```text
程序 —— FileInputStream —— 文件
程序 —— FileOutputStream —— 文件
```

这类流直接操作文件、数组、字符串、管道等具体数据源，因此也可以称为基础流。

常见节点流包括：

| 节点流             | 作用           |
| ------------------ | -------------- |
| `FileInputStream`  | 从文件读取字节 |
| `FileOutputStream` | 向文件写入字节 |
| `FileReader`       | 从文件读取字符 |
| `FileWriter`       | 向文件写入字符 |

#### 处理流

处理流不直接连接数据源，而是包装在其他流外面，对原有流的功能进行增强。

例如，缓冲流可以提高读写效率：

```text
程序 —— BufferedInputStream —— FileInputStream —— 文件
```

这里 `FileInputStream` 负责直接连接文件，`BufferedInputStream` 负责在外层提供缓冲能力。

常见处理流包括：

| 处理流                 | 作用                                 |
| ---------------------- | ------------------------------------ |
| `BufferedInputStream`  | 给字节输入流增加缓冲                 |
| `BufferedOutputStream` | 给字节输出流增加缓冲                 |
| `BufferedReader`       | 给字符输入流增加缓冲，并支持按行读取 |
| `BufferedWriter`       | 给字符输出流增加缓冲                 |
| `ObjectInputStream`    | 读取对象                             |
| `ObjectOutputStream`   | 写出对象                             |

> 结论：节点流负责“连接数据源”，处理流负责“增强功能”。处理流可以包装节点流，也可以继续包装其他处理流。

### IO 流的四个抽象基类

Java IO 流体系中，有四个非常重要的抽象基类。

| 抽象基类       | 类型   | 方向 | 说明             |
| -------------- | ------ | ---- | ---------------- |
| `InputStream`  | 字节流 | 输入 | 字节输入流的父类 |
| `OutputStream` | 字节流 | 输出 | 字节输出流的父类 |
| `Reader`       | 字符流 | 输入 | 字符输入流的父类 |
| `Writer`       | 字符流 | 输出 | 字符输出流的父类 |

可以按两个维度记忆：

```text
按方向：
InputStream / Reader      输入
OutputStream / Writer     输出

按单位：
InputStream / OutputStream    字节
Reader / Writer               字符
```

> 结论：看到类名以 `InputStream` 或 `Reader` 结尾，通常表示输入流；看到类名以 `OutputStream` 或 `Writer` 结尾，通常表示输出流。

### IO 流体系概览

常见 IO 流可以按如下结构理解：

```text
IO 流
├── 字节流
│   ├── 字节输入流：InputStream
│   │   ├── FileInputStream
│   │   ├── BufferedInputStream
│   │   └── ObjectInputStream
│   └── 字节输出流：OutputStream
│       ├── FileOutputStream
│       ├── BufferedOutputStream
│       └── ObjectOutputStream
└── 字符流
    ├── 字符输入流：Reader
    │   ├── FileReader
    │   └── BufferedReader
    └── 字符输出流：Writer
        ├── FileWriter
        └── BufferedWriter
```

当前阶段不需要一次性掌握所有 IO 类。学习时应先抓住四个基础方向：字节输入、字节输出、字符输入、字符输出，再逐步学习文件流、缓冲流、转换流、对象流等具体实现类。

### IO 流学习主线

IO 流类很多，但学习顺序可以按照以下主线展开：

1. 先理解输入和输出的方向；
2. 再区分字节流和字符流；
3. 然后学习最基础的文件节点流；
4. 再学习缓冲流等处理流；
5. 最后学习对象流、转换流等特殊功能流。

对应关系如下：

| 学习阶段     | 重点                                                         |
| ------------ | ------------------------------------------------------------ |
| 基础概念     | 输入、输出、数据源、流                                       |
| 基础分类     | 字节流、字符流                                               |
| 基础文件操作 | `FileInputStream`、`FileOutputStream`、`FileReader`、`FileWriter` |
| 性能增强     | 缓冲流                                                       |
| 特殊处理     | 转换流、对象流等                                             |

> 结论：IO 流看似类很多，本质上都是围绕“数据从哪里来、到哪里去、按什么单位传输、是否需要功能增强”这几个问题展开。

## 字节流

字节流是以**字节**为单位进行数据读写的 IO 流。由于计算机中的所有文件本质上都由字节组成，因此字节流可以处理任意类型的文件，包括文本、图片、音频、视频、压缩包等。

Java 字节流体系中有两个核心抽象父类：

| 抽象类         | 方向 | 作用                       |
| -------------- | ---- | -------------------------- |
| `InputStream`  | 输入 | 从数据源读取字节到程序中   |
| `OutputStream` | 输出 | 将程序中的字节写出到目的地 |

> 结论：字节流是最通用的 IO 流。只要是文件复制、图片读写、视频读写等不需要按字符理解内容的场景，都可以优先考虑字节流。

### OutputStream 类

`OutputStream` 是所有**字节输出流**的抽象父类，用于把程序中的数据以字节形式写出到外部目的地。它本身是抽象类，不能直接创建对象，实际使用时通常使用它的子类，例如 `FileOutputStream`。

`OutputStream` 常用方法如下：

| 方法                                     | 说明                                       |
| ---------------------------------------- | ------------------------------------------ |
| `void write(int b)`                      | 写出一个字节                               |
| `void write(byte[] b)`                   | 写出整个字节数组                           |
| `void write(byte[] b, int off, int len)` | 写出字节数组中从 `off` 开始的 `len` 个字节 |
| `void flush()`                           | 刷新输出流，将缓冲区中的数据强制写出       |
| `void close()`                           | 关闭流，释放系统资源                       |

`write(int b)` 虽然参数类型是 `int`，但实际写出的只是一个字节，也就是该整数的低 8 位。

> 注意：所有输出流都需要在使用完毕后关闭。带缓冲区的输出流在关闭前通常还需要刷新，避免缓冲区中的数据没有及时写出。

### FileOutputStream 类

`FileOutputStream` 是 `OutputStream` 的实现类，表示**文件字节输出流**，用于将字节数据写入文件。它是节点流，直接连接到文件这个数据目的地。

`FileOutputStream` 适合写出任意类型的文件数据，例如文本、图片、视频等。写文本时，需要先把字符串转换成字节数组。

#### FileOutputStream 的构造方法

`FileOutputStream` 常用构造方法如下：

| 构造方法                                        | 说明                                       |
| ----------------------------------------------- | ------------------------------------------ |
| `FileOutputStream(String name)`                 | 根据文件路径创建输出流，默认覆盖原文件     |
| `FileOutputStream(File file)`                   | 根据 `File` 对象创建输出流，默认覆盖原文件 |
| `FileOutputStream(String name, boolean append)` | 根据文件路径创建输出流，可指定是否追加     |
| `FileOutputStream(File file, boolean append)`   | 根据 `File` 对象创建输出流，可指定是否追加 |

其中，`append` 参数用于控制写入方式：

| `append` 值 | 含义                             |
| ----------- | -------------------------------- |
| `false`     | 覆盖写入，创建流时清空原文件内容 |
| `true`      | 追加写入，在原文件末尾继续写入   |

> 易错点：`new FileOutputStream("test.txt")` 默认会覆盖原文件内容。如果文件已经存在，创建输出流时原内容会被清空。

#### FileOutputStream 写出数据

写出数据时，通常先创建 `FileOutputStream`，再调用 `write()` 方法写出字节，最后关闭流。

```java
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.OutputStream;

public class FileOutputStreamDemo {
    public static void main(String[] args) {
        OutputStream out = null;

        try {
            // 默认覆盖写入：如果文件存在，会清空原内容；如果文件不存在，会创建文件
            out = new FileOutputStream("test.txt");

            byte[] data = "hello java".getBytes();

            // 将整个字节数组写入文件
            out.write(data);
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (out != null) {
                try {
                    // 关闭流，释放资源
                    out.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

执行后，`test.txt` 中会写入：

```text
hello java
```

这段代码中，`"hello java".getBytes()` 会把字符串按照平台默认编码转换成字节数组。如果希望编码更明确，可以指定字符集：

```java
byte[] data = "hello java".getBytes("UTF-8");
```

#### 写出部分字节数组

`write(byte[] b, int off, int len)` 可以写出字节数组中的一部分内容。

```java
import java.io.FileOutputStream;
import java.io.IOException;

public class FileOutputStreamPartDemo {
    public static void main(String[] args) {
        FileOutputStream out = null;

        try {
            out = new FileOutputStream("test.txt");

            byte[] bytes = {97, 98, 99, 100}; // 对应 a、b、c、d

            out.write(bytes);        // 写出 abcd
            out.write(bytes, 0, 2);  // 写出 ab
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (out != null) {
                try {
                    out.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

文件最终内容为：

```text
abcdab
```

其中，`write(bytes, 0, 2)` 表示从数组索引 `0` 开始，写出 `2` 个字节。

#### 文件追加写入

如果希望保留原文件内容，并在末尾继续写入数据，需要使用带 `append` 参数的构造方法。

```java
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.OutputStream;

public class FileAppendDemo {
    public static void main(String[] args) {
        OutputStream out = null;

        try {
            // true 表示追加写入，不清空原文件内容
            out = new FileOutputStream("test.txt", true);

            out.write("hello\n".getBytes());
            out.write("java\n".getBytes());
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (out != null) {
                try {
                    out.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

如果文件原来已有内容，新内容会追加到文件末尾。

> 结论：覆盖写入使用 `new FileOutputStream(path)`；追加写入使用 `new FileOutputStream(path, true)`。

### InputStream 类

`InputStream` 是所有**字节输入流**的抽象父类，用于从外部数据源读取字节到程序中。它本身是抽象类，实际使用时通常使用它的子类，例如 `FileInputStream`。

`InputStream` 常用方法如下：

| 方法                                   | 说明                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `int read()`                           | 一次读取一个字节；读到文件末尾返回 `-1`                      |
| `int read(byte[] b)`                   | 一次读取多个字节到数组中；返回本次读取到的字节个数；读到末尾返回 `-1` |
| `int read(byte[] b, int off, int len)` | 读取部分数据到数组指定位置                                   |
| `long skip(long n)`                    | 跳过 `n` 个字节                                              |
| `int available()`                      | 返回当前流中估计可读取的剩余字节数                           |
| `void close()`                         | 关闭流，释放系统资源                                         |

> 结论：`read()` 的返回值不是固定含义。`read()` 返回的是读取到的字节值；`read(byte[])` 返回的是本次读取到的字节个数。二者都在读到末尾时返回 `-1`。

### FileInputStream 类

`FileInputStream` 是 `InputStream` 的实现类，表示**文件字节输入流**，用于从文件中读取字节数据。它是节点流，直接连接到文件这个数据源。

`FileInputStream` 适合读取任意类型文件，包括文本、图片、音频、视频等。

### FileInputStream 的构造方法

`FileInputStream` 常用构造方法如下：

| 构造方法                       | 说明                       |
| ------------------------------ | -------------------------- |
| `FileInputStream(String name)` | 根据文件路径创建输入流     |
| `FileInputStream(File file)`   | 根据 `File` 对象创建输入流 |

示例：

```java
FileInputStream in1 = new FileInputStream("test.txt");
FileInputStream in2 = new FileInputStream(new File("test.txt"));
```

> 注意：创建 `FileInputStream` 时，文件必须已经存在。若文件不存在，会抛出 `FileNotFoundException`。

#### read()：一次读取一个字节

`read()` 方法一次读取一个字节。读取成功时，返回读取到的字节对应的整数值；如果读取到文件末尾，则返回 `-1`。

```java
import java.io.FileInputStream;
import java.io.IOException;

public class FileInputStreamReadDemo {
    public static void main(String[] args) {
        FileInputStream in = null;

        try {
            in = new FileInputStream("test.txt");

            int data;

            while ((data = in.read()) != -1) {
                System.out.println(data);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (in != null) {
                try {
                    in.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

如果文件中存储的是英文字符 `abc`，对应输出可能是：

```text
97
98
99
```

因为英文字符 `a`、`b`、`c` 在常见编码下对应的字节值分别是 `97`、`98`、`99`。

> 注意：`read()` 一次只读一个字节，频繁访问磁盘，效率较低。实际开发中更常使用 `read(byte[])` 配合字节数组批量读取。

#### read(byte[])：一次读取多个字节

`read(byte[] b)` 会尽可能读取多个字节到字节数组中，返回本次实际读取到的字节个数。如果已经到达文件末尾，返回 `-1`。

```java
import java.io.FileInputStream;
import java.io.IOException;

public class FileInputStreamBufferDemo {
    public static void main(String[] args) {
        FileInputStream in = null;

        try {
            in = new FileInputStream("test.txt");

            byte[] buffer = new byte[1024];
            int len;

            while ((len = in.read(buffer)) != -1) {
                String content = new String(buffer, 0, len);
                System.out.print(content);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (in != null) {
                try {
                    in.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

这段代码中：

1. `buffer` 是临时字节数组，用于存放本次读取到的数据；
2. `len` 表示本次实际读取到的字节个数；
3. `new String(buffer, 0, len)` 只把本次有效读取的字节转换为字符串。

> 易错点：使用 `read(byte[])` 后，必须按照 `len` 处理有效数据，不能直接使用整个数组。最后一次读取时，数组中可能残留上一次读取的数据。

#### available() 和 skip()

`available()` 可以获取当前输入流中估计还可以读取的字节数量，`skip(long n)` 可以跳过指定数量的字节。

```java
import java.io.FileInputStream;

public class FileInputStreamOtherDemo {
    public static void main(String[] args) throws Exception {
        FileInputStream in = new FileInputStream("test.txt");

        System.out.println(in.available());

        in.read();
        in.read();

        System.out.println(in.available());

        in.skip(2);

        System.out.println(in.read());

        in.close();
    }
}
```

假设文件中有 6 个字节：

1. 还未读取时，`available()` 返回 `6`；
2. 读取 2 个字节后，`available()` 返回 `4`；
3. `skip(2)` 跳过 2 个字节；
4. 再次调用 `read()` 会从跳过后的位置继续读取。

> 注意：`available()` 不适合被理解为“文件总大小”的通用方法。对于较大的文件，不建议使用 `available()` 创建同等大小的数组一次性读取全部内容，容易造成内存压力甚至内存溢出。

#### 一次性读取全部数据的问题

可以通过 `available()` 获取剩余可读字节数，并创建同等大小的数组一次性读取文件：

```java
import java.io.FileInputStream;
import java.io.IOException;

public class FileReadAllDemo {
    public static void main(String[] args) {
        FileInputStream in = null;

        try {
            in = new FileInputStream("test.txt");

            byte[] data = new byte[in.available()];
            in.read(data);

            System.out.println(new String(data));
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (in != null) {
                try {
                    in.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

这种写法只适合很小的文件。文件较大时，一次性创建大数组会占用大量内存。

> 结论：读取文件时，更推荐使用固定大小的缓冲数组循环读取，例如 `byte[] buffer = new byte[1024]`。这种方式内存占用稳定，适合处理较大文件。

### 字节流读取文本的乱码问题

字节流本身按字节读取，不理解“字符”的边界。对于英文字符通常问题不明显，因为英文字符在常见编码中通常占 1 个字节；但中文字符在不同编码中可能占多个字节。

常见编码中字符占用情况如下：

| 编码      | 英文字符      | 中文字符      |
| --------- | ------------- | ------------- |
| `UTF-8`   | 通常 1 个字节 | 通常 3 个字节 |
| `GBK`     | 通常 1 个字节 | 通常 2 个字节 |
| `Unicode` | 通常 2 个字节 | 通常 2 个字节 |

如果使用较小的字节数组读取中文文本，例如每次读取 2 个字节，而文件使用 `UTF-8` 编码，一个中文字符可能被拆成两次读取。随后把每次读取到的字节硬转换为字符串，就可能出现乱码。

```java
import java.io.FileInputStream;

public class FileInputStreamChineseDemo {
    public static void main(String[] args) throws Exception {
        FileInputStream in = new FileInputStream("a.txt");

        byte[] bytes = new byte[2];
        int len;

        while ((len = in.read(bytes)) != -1) {
            // 如果中文字符的字节被拆开，这里可能出现乱码
            System.out.print(new String(bytes, 0, len));
        }

        in.close();
    }
}
```

出现乱码的核心原因不是简单的“编码不一致”，而是**多字节字符被错误拆分后又被强行转换成字符串**。

> 结论：字节流可以读取文本，但不适合直接按小块字节处理中文文本。需要按字符处理文本时，应优先使用字符流。

### 字节流文件拷贝

字节流最典型的应用是文件拷贝。由于字节流不关心文件内容含义，只负责搬运字节，所以可以复制任意类型的文件。

文件拷贝的基本思路如下：

1. 创建字节输入流，连接源文件；
2. 创建字节输出流，连接目标文件；
3. 定义字节数组作为缓冲区；
4. 循环读取源文件中的字节；
5. 每读取一批字节，就写入目标文件；
6. 关闭输入流和输出流。

```java
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class FileCopyDemo {
    public static void main(String[] args) {
        FileInputStream in = null;
        FileOutputStream out = null;

        try {
            in = new FileInputStream("source.mp4");
            out = new FileOutputStream("target.mp4");

            byte[] buffer = new byte[1024];
            int len;

            while ((len = in.read(buffer)) != -1) {
                // 只写出本次读取到的有效字节
                out.write(buffer, 0, len);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (in != null) {
                try {
                    in.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }

            if (out != null) {
                try {
                    out.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

其中，`out.write(buffer, 0, len)` 非常关键。最后一次读取时，缓冲数组可能没有被填满，只能写出本次读取到的 `len` 个有效字节。如果直接写 `out.write(buffer)`，可能把数组中残留的无效数据也写入目标文件，导致文件内容错误。

### close 与 flush

IO 流使用完毕后必须关闭。关闭流的作用是释放系统资源，例如文件句柄、操作系统底层资源等。

`close()` 来自 `Closeable` 接口，所有流都需要在使用完毕后关闭。

`flush()` 来自 `Flushable` 接口，主要用于输出流，作用是把缓冲区中尚未写出的数据强制写到目的地。

| 方法      | 作用                           |
| --------- | ------------------------------ |
| `close()` | 关闭流，释放资源               |
| `flush()` | 刷新输出流，强制写出缓冲区数据 |

需要注意，`FileOutputStream` 本身是不带 Java 层缓冲区的节点流，通常不需要手动调用 `flush()`；但如果使用 `BufferedOutputStream`、`BufferedWriter` 等带缓冲的输出流，建议在关闭前确保数据被刷新。

> 结论：流用完必须关闭；带缓冲的输出流应关注刷新问题，避免数据仍停留在缓冲区中。

### try-with-resources 写法

从 JDK 7 开始，可以使用 `try-with-resources` 自动关闭资源。凡是实现了 `AutoCloseable` 或 `Closeable` 的资源，都可以放在 `try()` 中自动管理。

文件复制可以简化为：

```java
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class FileCopyTryWithResourcesDemo {
    public static void main(String[] args) {
        try (
                FileInputStream in = new FileInputStream("source.mp4");
                FileOutputStream out = new FileOutputStream("target.mp4")
        ) {
            byte[] buffer = new byte[1024];
            int len;

            while ((len = in.read(buffer)) != -1) {
                out.write(buffer, 0, len);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

这种写法不需要手动在 `finally` 中关闭流，代码更简洁，也更不容易遗漏资源释放。

> 补充：初学 IO 时应理解 `finally` 中关闭资源的写法；实际开发中，更推荐使用 `try-with-resources`。

## 字符流

字符流是以**字符**为单位进行读写的 IO 流，专门用于处理文本数据。与字节流相比，字符流会在读写过程中进行字符编码和解码，因此更适合操作 `.txt`、`.java`、`.properties` 等文本文件。

字节流可以处理任意类型文件，而字符流只适合处理文本文件。图片、音频、视频、压缩包等二进制文件不能使用字符流处理，否则可能破坏文件内容。

> 结论：处理任意文件优先考虑字节流；处理文本内容时，字符流更方便，也更符合字符数据的读写习惯。

### 字符流与字节流的区别

| 对比项       | 字节流                        | 字符流                           |
| ------------ | ----------------------------- | -------------------------------- |
| 处理单位     | 字节                          | 字符                             |
| 抽象父类     | `InputStream`、`OutputStream` | `Reader`、`Writer`               |
| 适用范围     | 所有类型文件                  | 文本文件                         |
| 是否涉及编码 | 本身不负责字符编码处理        | 会涉及编码和解码                 |
| 常见场景     | 文件复制、图片、视频、音频    | 读取文本、写入文本、处理中文内容 |

字符流本质上仍然要依赖底层字节数据，因为文件在硬盘上最终都是以字节形式保存的。字符流的作用是：在字节和字符之间完成转换，使程序可以直接按字符读写文本。

例如，读取文本时：

```text
硬盘中的字节数据  --解码-->  Java 程序中的字符
```

写入文本时：

```text
Java 程序中的字符  --编码-->  硬盘中的字节数据
```

> 注意：字符流可以减少手动处理字节与字符转换的麻烦，但前提是读取时使用的字符集必须与文件实际编码一致，否则仍然可能出现乱码。

### Writer 类

`Writer` 是所有**字符输出流**的抽象父类，用于将程序中的字符数据写出到外部目的地。它本身不能直接创建对象，实际开发中通常使用它的子类，例如 `FileWriter`、`BufferedWriter`。

`Writer` 常用方法如下：

| 方法                                        | 说明                                       |
| ------------------------------------------- | ------------------------------------------ |
| `void write(int c)`                         | 写出一个字符                               |
| `void write(char[] cbuf)`                   | 写出一个字符数组                           |
| `void write(char[] cbuf, int off, int len)` | 写出字符数组中从 `off` 开始的 `len` 个字符 |
| `void write(String str)`                    | 写出一个字符串                             |
| `void write(String str, int off, int len)`  | 写出字符串中从 `off` 开始的 `len` 个字符   |
| `void flush()`                              | 刷新输出流，把缓冲区中的数据写出           |
| `void close()`                              | 关闭流并释放资源                           |

`Writer` 处理的是字符，因此写出文本时可以直接写字符串，不需要像字节流那样先手动调用 `getBytes()` 转换为字节数组。

### FileWriter 类

`FileWriter` 是 `Writer` 的常用实现类，表示**文件字符输出流**，用于把字符数据写入文本文件。它适合写入普通文本内容，不适合写图片、音频、视频等二进制文件。

`FileWriter` 的继承结构可以理解为：

```text
Writer
  └── OutputStreamWriter
        └── FileWriter
```

其中，`OutputStreamWriter` 才是真正负责把字符按照指定字符集编码为字节的转换流，`FileWriter` 是针对文件写入场景提供的便捷类。

#### FileWriter 的构造方法

`FileWriter` 常用构造方法如下：

| 构造方法                                      | 说明                                           |
| --------------------------------------------- | ---------------------------------------------- |
| `FileWriter(String fileName)`                 | 根据文件路径创建字符输出流，默认覆盖原文件     |
| `FileWriter(File file)`                       | 根据 `File` 对象创建字符输出流，默认覆盖原文件 |
| `FileWriter(String fileName, boolean append)` | 根据文件路径创建字符输出流，可指定是否追加     |
| `FileWriter(File file, boolean append)`       | 根据 `File` 对象创建字符输出流，可指定是否追加 |

较新的 JDK 版本还提供了可以指定 `Charset` 的构造方法，用于明确控制写出文本时使用的编码。

| 构造方法                                                     | 说明                 |
| ------------------------------------------------------------ | -------------------- |
| `FileWriter(String fileName, Charset charset)`               | 按指定字符集写出     |
| `FileWriter(String fileName, Charset charset, boolean append)` | 按指定字符集追加写出 |
| `FileWriter(File file, Charset charset)`                     | 按指定字符集写出     |
| `FileWriter(File file, Charset charset, boolean append)`     | 按指定字符集追加写出 |

> 结论：如果不指定字符集，`FileWriter` 会使用 JVM 默认字符集。为了避免不同环境下出现编码差异，实际开发中更推荐明确指定字符集。

#### FileWriter 写入文本

使用 `FileWriter` 写入文本的基本步骤如下：

1. 创建 `FileWriter` 对象，指定目标文件；
2. 调用 `write()` 方法写入字符或字符串；
3. 调用 `flush()` 或 `close()`，确保数据真正写入文件；
4. 关闭流，释放资源。

```java
import java.io.FileWriter;
import java.io.IOException;
import java.io.Writer;

public class FileWriterDemo {
    public static void main(String[] args) {
        Writer writer = null;

        try {
            // 默认覆盖写入：文件存在时会清空原内容，文件不存在时会创建文件
            writer = new FileWriter("note.txt");

            // 写出字符串
            writer.write("今天学习字符流。");

            // 写出换行符
            writer.write("\n");

            // 写出部分字符串：从索引 0 开始，写出 4 个字符
            writer.write("Java IO 很重要", 0, 4);

            // 刷新缓冲区，确保数据写出
            writer.flush();
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (writer != null) {
                try {
                    // close() 会先刷新，再关闭资源
                    writer.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

文件内容示例：

```text
今天学习字符流。
Java
```

> 注意：`flush()` 表示刷新流，强制把缓冲区中的数据写出；`close()` 表示关闭流，关闭前也会刷新。流关闭后不能继续写入。

#### FileWriter 追加写入

默认情况下，`new FileWriter("note.txt")` 会覆盖原文件内容。如果希望在文件末尾继续追加内容，需要使用带 `append` 参数的构造方法。

```java
import java.io.FileWriter;
import java.io.IOException;
import java.io.Writer;

public class FileWriterAppendDemo {
    public static void main(String[] args) {
        Writer writer = null;

        try {
            // true 表示追加写入，不清空原文件内容
            writer = new FileWriter("note.txt", true);

            writer.write("\n继续追加一行文本。");
            writer.flush();
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (writer != null) {
                try {
                    writer.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

如果文件原来已有内容，新内容会被写到文件末尾。

> 结论：覆盖写入使用 `new FileWriter(path)`；追加写入使用 `new FileWriter(path, true)`。

#### 指定字符集写入文本

如果需要明确指定文件编码，可以使用带 `Charset` 参数的构造方法。

```java
import java.io.FileWriter;
import java.nio.charset.Charset;

public class FileWriterCharsetDemo {
    public static void main(String[] args) {
        try (FileWriter writer = new FileWriter("note.txt", Charset.forName("UTF-8"))) {
            writer.write("张三");
            writer.write("学习 Java 字符流。");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

如果指定为 `GBK`，写出的文件就会按照 `GBK` 编码保存：

```java
try (FileWriter writer = new FileWriter("note.txt", Charset.forName("GBK"))) {
    writer.write("中文内容");
}
```

> 易错点：文件写出时使用什么编码，后续读取时也应使用相同或兼容的编码。写入使用 `GBK`，读取却使用 `UTF-8`，就可能出现乱码。

### Reader 类

`Reader` 是所有**字符输入流**的抽象父类，用于从外部数据源读取字符到程序中。它本身不能直接创建对象，实际开发中通常使用它的子类，例如 `FileReader`、`BufferedReader`。

`Reader` 常用方法如下：

| 方法                                      | 说明                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| `int read()`                              | 一次读取一个字符，返回字符对应的整数值；读到末尾返回 `-1`    |
| `int read(char[] cbuf)`                   | 一次读取多个字符到字符数组，返回本次读取到的字符个数；读到末尾返回 `-1` |
| `int read(char[] cbuf, int off, int len)` | 读取字符到数组指定位置                                       |
| `long skip(long n)`                       | 跳过 `n` 个字符                                              |
| `boolean ready()`                         | 判断流是否已经准备好被读取                                   |
| `void close()`                            | 关闭流并释放资源                                             |

> 结论：`read()` 返回的是字符对应的整数值；`read(char[])` 返回的是本次读取到的字符数量。二者读到文件末尾时都返回 `-1`。

### FileReader 类

`FileReader` 是 `Reader` 的常用实现类，表示**文件字符输入流**，用于从文本文件中读取字符数据。它适合读取普通文本文件，不适合读取图片、视频、音频等二进制文件。

`FileReader` 的继承结构可以理解为：

```text
Reader
  └── InputStreamReader
        └── FileReader
```

其中，`InputStreamReader` 才是真正负责把字节按照指定字符集解码为字符的转换流，`FileReader` 是针对文件读取场景提供的便捷类。

#### FileReader 的构造方法

`FileReader` 常用构造方法如下：

| 构造方法                      | 说明                           |
| ----------------------------- | ------------------------------ |
| `FileReader(String fileName)` | 根据文件路径创建字符输入流     |
| `FileReader(File file)`       | 根据 `File` 对象创建字符输入流 |

较新的 JDK 版本也提供了可以指定 `Charset` 的构造方法：

| 构造方法                                       | 说明                 |
| ---------------------------------------------- | -------------------- |
| `FileReader(String fileName, Charset charset)` | 按指定字符集读取文件 |
| `FileReader(File file, Charset charset)`       | 按指定字符集读取文件 |

> 注意：创建 `FileReader` 时，文件必须真实存在。若文件不存在，会抛出 `FileNotFoundException`。

#### FileReader 读取一个字符

`read()` 方法一次读取一个字符，读取成功时返回该字符对应的整数值，读到文件末尾返回 `-1`。

```java
import java.io.FileReader;
import java.io.IOException;
import java.io.Reader;

public class FileReaderReadDemo {
    public static void main(String[] args) {
        Reader reader = null;

        try {
            reader = new FileReader("note.txt");

            int ch;

            while ((ch = reader.read()) != -1) {
                // read() 返回的是 int，需要强制转换为 char 才能按字符输出
                System.out.print((char) ch);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (reader != null) {
                try {
                    reader.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

这种方式每次只读取一个字符，逻辑简单，但效率较低。读取较大文本时，更推荐使用字符数组。

#### FileReader 读取字符数组

`read(char[] cbuf)` 可以一次读取多个字符到字符数组中，返回本次实际读取到的字符个数。

```java
import java.io.FileReader;
import java.io.IOException;
import java.io.Reader;

public class FileReaderArrayDemo {
    public static void main(String[] args) {
        Reader reader = null;

        try {
            reader = new FileReader("note.txt");

            char[] buffer = new char[1024];
            int len;

            while ((len = reader.read(buffer)) != -1) {
                // 只处理本次读取到的有效字符
                String text = new String(buffer, 0, len);
                System.out.print(text);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (reader != null) {
                try {
                    reader.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

其中，`len` 表示本次实际读取到的字符数量。最后一次读取时，字符数组可能没有被填满，因此必须使用 `new String(buffer, 0, len)` 只转换有效字符。

> 易错点：读取到字符数组后，不能直接把整个数组都转换成字符串。否则最后一次读取时可能带上数组中残留的旧字符。

### 使用 try-with-resources 自动关闭流

字符流实现了 `Closeable` 接口，使用完毕后必须关闭。JDK 7 开始，可以使用 `try-with-resources` 自动关闭流。

```java
import java.io.FileReader;
import java.nio.charset.Charset;

public class FileReaderTryDemo {
    public static void main(String[] args) {
        try (FileReader reader = new FileReader("note.txt", Charset.forName("UTF-8"))) {
            char[] chars = new char[4];
            int len;

            while ((len = reader.read(chars)) != -1) {
                System.out.print(new String(chars, 0, len));
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

`try()` 小括号中创建的资源会在代码执行结束后自动关闭，即使发生异常，也会自动释放资源。

> 结论：初学时应理解 `finally` 中关闭流的写法；实际开发中，推荐使用 `try-with-resources` 简化资源管理。

### 字符编码与乱码问题

文本文件在硬盘中保存的是字节，程序读取时需要按照某种字符集把字节解码为字符。如果文件保存时使用的编码和读取时使用的编码不一致，就可能出现乱码。

例如：

1. 文本文件使用 `GBK` 编码保存；
2. 程序使用 `UTF-8` 读取；
3. JVM 按 `UTF-8` 的规则解释 `GBK` 字节；
4. 解码规则不匹配，就会出现乱码。

默认构造方法：

```java
new FileReader("note.txt")
```

会使用 JVM 默认字符集读取文件。若文件实际编码与 JVM 默认字符集不同，就可能乱码。

如果文件是 `GBK` 编码，应明确指定：

```java
try (FileReader reader = new FileReader("note.txt", Charset.forName("GBK"))) {
    char[] chars = new char[1024];
    int len;

    while ((len = reader.read(chars)) != -1) {
        System.out.print(new String(chars, 0, len));
    }
}
```

> 结论：乱码的根本原因是编码和解码规则不一致。写出文件时使用什么字符集，读取时就应使用相同字符集。

### 字符流文件拷贝

字符流可以用于复制文本文件。复制思路如下：

1. 创建字符输入流，连接源文本文件；
2. 创建字符输出流，连接目标文本文件；
3. 使用字符数组循环读取；
4. 每次读取后，写出本次有效字符；
5. 关闭流。

```java
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class TextCopyDemo {
    public static void main(String[] args) {
        FileReader reader = null;
        FileWriter writer = null;

        try {
            reader = new FileReader("source.txt");
            writer = new FileWriter("target.txt");

            char[] buffer = new char[1024];
            int len;

            while ((len = reader.read(buffer)) != -1) {
                // 只写出本次读取到的有效字符
                writer.write(buffer, 0, len);
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (writer != null) {
                try {
                    // 关闭前会刷新字符输出流
                    writer.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }

            if (reader != null) {
                try {
                    reader.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

如果复制的是文本文件，这种方式可以正常工作。如果复制的是图片、音频、视频等二进制文件，则不能使用字符流，应使用字节流。

> 易错点：字符流文件拷贝只适合文本文件。任意类型文件复制应使用字节流。

### 字符流与编码的实际使用建议

字符流处理文本时，应尽量遵循以下规则：

1. 读取文件前确认文件实际编码；
2. 写出文件时尽量明确指定编码；
3. 读写同一个文件时，编码保持一致；
4. 不用字符流处理二进制文件；
5. 对于跨平台文件，优先使用统一编码，例如 `UTF-8`；
6. 如果使用默认构造方法，要知道它依赖 JVM 默认字符集。

例如，明确使用 `UTF-8` 写入和读取：

```java
import java.io.FileReader;
import java.io.FileWriter;
import java.nio.charset.StandardCharsets;

public class CharsetTextDemo {
    public static void main(String[] args) {
        try (FileWriter writer = new FileWriter("message.txt", StandardCharsets.UTF_8)) {
            writer.write("统一使用 UTF-8 编码。");
        } catch (Exception e) {
            e.printStackTrace();
        }

        try (FileReader reader = new FileReader("message.txt", StandardCharsets.UTF_8)) {
            char[] buffer = new char[1024];
            int len;

            while ((len = reader.read(buffer)) != -1) {
                System.out.print(new String(buffer, 0, len));
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这种写法能减少“在某台电脑正常，在另一台电脑乱码”的问题。

## 缓冲流

缓冲流是 IO 体系中的一种**处理流**，用于包装已有的节点流或其他处理流，通过内部缓冲区减少程序与底层设备之间的直接交互次数，从而提高读写效率。

常见缓冲流分为两类：

| 分类       | 输入流                | 输出流                 |
| ---------- | --------------------- | ---------------------- |
| 字节缓冲流 | `BufferedInputStream` | `BufferedOutputStream` |
| 字符缓冲流 | `BufferedReader`      | `BufferedWriter`       |

> 结论：缓冲流本身不直接连接文件，它必须包装在已有流的外层，用来提升效率或提供更方便的方法。

### 节点流与处理流

IO 流按照功能角色可以分为**节点流**和**处理流**。

| 分类   | 说明                       | 示例                                                         |
| ------ | -------------------------- | ------------------------------------------------------------ |
| 节点流 | 可以直接连接数据源或目的地 | `FileInputStream`、`FileOutputStream`、`FileReader`、`FileWriter` |
| 处理流 | 包装已有流，增强读写能力   | `BufferedInputStream`、`BufferedOutputStream`、`BufferedReader`、`BufferedWriter` |

节点流直接连接文件、数组、网络等具体数据源；处理流不直接连接数据源，而是包装已有流，在原有流的基础上增加功能。

例如：

```java
BufferedInputStream in = new BufferedInputStream(new FileInputStream("a.txt"));
```

这行代码中：

1. `FileInputStream` 是节点流，负责直接连接文件；
2. `BufferedInputStream` 是处理流，负责在外层增加缓冲能力。

> 注意：判断一个流是否是节点流，可以观察它是否能直接通过文件路径或 `File` 对象连接数据源。缓冲流的构造方法接收的是另一个流对象，因此属于处理流。

### 缓冲流的工作原理

普通节点流每次读写都可能直接与磁盘等底层设备交互，而磁盘 IO 的速度远低于内存操作。缓冲流会在程序和底层流之间增加一块内存缓冲区，先把数据集中读入或写入缓冲区，再批量与底层设备交互。

读取数据时：

```text
文件  →  底层输入流  →  缓冲区  →  程序
```

写出数据时：

```text
程序  →  缓冲区  →  底层输出流  →  文件
```

这样可以减少直接访问磁盘的次数，提高整体读写效率。

> 结论：缓冲流提升效率的核心原因是减少底层 IO 交互次数，而不是改变文件本身的读写规则。

### 关闭包装流的规则

当使用包装流时，通常只需要关闭**最外层的流**。关闭外层缓冲流时，底层会继续关闭被包装的流。

例如：

```java
BufferedOutputStream out =
        new BufferedOutputStream(new FileOutputStream("data.txt"));

out.write("hello".getBytes());

out.close();
```

这段代码只关闭 `out` 即可。`BufferedOutputStream` 关闭时，会自动刷新缓冲区，并关闭内部包装的 `FileOutputStream`。

> 结论：有包装流时，一般关闭最外层流即可。关闭顺序应从外到内，避免内部流提前关闭导致外层流无法继续工作。

### flush 与 close

输出缓冲流写数据时，数据可能先停留在缓冲区中，并不一定立即写入文件。此时需要理解 `flush()` 和 `close()` 的区别。

| 方法      | 作用                             | 调用后是否还能继续使用流 |
| --------- | -------------------------------- | ------------------------ |
| `flush()` | 将缓冲区中的数据强制写出         | 可以继续使用             |
| `close()` | 先刷新缓冲区，再关闭流并释放资源 | 不能继续使用             |

例如：

```java
writer.write("hello");
writer.flush();   // 数据写出，流仍然可以继续使用
writer.write("java");
writer.close();   // 数据写出并关闭流，之后不能再写
```

> 易错点：带缓冲的输出流如果只写数据但不刷新、不关闭，最后一部分数据可能仍停留在缓冲区中，导致文件内容不完整。

### 字节缓冲流

字节缓冲流用于包装字节流，以字节为单位进行高效读写。它可以处理任意类型文件，包括文本、图片、音频、视频等。

常见字节缓冲流如下：

| 类                     | 作用                             |
| ---------------------- | -------------------------------- |
| `BufferedInputStream`  | 字节缓冲输入流，提高字节读取效率 |
| `BufferedOutputStream` | 字节缓冲输出流，提高字节写出效率 |

字节缓冲流继承自字节流体系，因此它们操作的基本单位仍然是字节。

#### BufferedOutputStream

`BufferedOutputStream` 是字节缓冲输出流，用于包装已有的字节输出流。写数据时，数据会先写入内部缓冲区，缓冲区满了、调用 `flush()` 或调用 `close()` 时，数据才会被写到底层目的地。

```java
import java.io.BufferedOutputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class BufferedOutputStreamDemo {
    public static void main(String[] args) {
        try (BufferedOutputStream out =
                     new BufferedOutputStream(new FileOutputStream("data.txt"))) {

            byte[] bytes = "张三李四王五".getBytes();

            // 数据先写入缓冲区，不一定立即写入文件
            out.write(bytes);

            // close() 会自动刷新缓冲区
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

执行过程如下：

1. `FileOutputStream` 直接连接目标文件；
2. `BufferedOutputStream` 包装 `FileOutputStream`；
3. `write()` 先把数据写入缓冲区；
4. 缓冲区满、调用 `flush()` 或关闭流时，数据写入文件；
5. 关闭外层缓冲流时，底层文件输出流也会被关闭。

> 注意：缓冲流提升的是写出效率，不会改变字符编码问题。写入字符串时，仍然需要通过 `getBytes()` 把字符串编码成字节。

##### BufferedOutputStream 的 close() 源码阅读

`BufferedOutputStream` 是带缓冲区的字节输出流。写出数据时，数据通常会先进入内部缓冲区，并不一定立刻写入文件。只有在缓冲区满、手动调用 `flush()`，或者关闭流时，缓冲区中的数据才会被真正写出。

因此，理解 `close()` 方法非常重要：**关闭缓冲流时，不只是释放资源，还会先刷新缓冲区，并继续关闭被包装的底层输出流**。

`BufferedOutputStream` 关闭时的核心逻辑可以概括为：

1. 判断流是否已经关闭，如果已经关闭，直接返回；
2. 通过同步控制避免多线程环境下重复关闭；
3. 调用 `flush()`，先把缓冲区中尚未写出的数据刷新到底层输出流；
4. 调用 `out.close()`，关闭被包装的底层输出流；
5. 如果刷新或关闭过程中发生异常，按照异常处理规则继续抛出。

```java
private static final int DEFAULT_INITIAL_BUFFER_SIZE = 512;
private static final int DEFAULT_MAX_BUFFER_SIZE = 8192;

@Override
public void close() throws IOException {
    // 如果流已经关闭，直接返回，避免重复关闭
    if (closed) {
        return;
    }

    synchronized (closeLock) {
        // 多线程环境下再次检查，防止其他线程已经关闭该流
        if (closed) {
            return;
        }

        // 标记当前流已经关闭
        closed = true;
    }

    Throwable flushException = null;

    try {
        // 关闭前先刷新缓冲区，保证缓冲区中的数据真正写出
        flush();
    } catch (Throwable e) {
        // 记录刷新过程中出现的异常
        flushException = e;
        throw e;
    } finally {
        if (flushException == null) {
            // 如果刷新没有异常，则关闭被包装的底层输出流
            out.close();
        } else {
            try {
                // 即使刷新发生异常，也仍然尝试关闭底层输出流
                out.close();
            } catch (Throwable closeException) {
                if (flushException != closeException) {
                    // 如果刷新异常和关闭异常不是同一个异常，
                    // 则把刷新异常作为附加异常保存，避免异常信息丢失
                    closeException.addSuppressed(flushException);
                }

                // 抛出关闭阶段的异常
                throw closeException;
            }
        }
    }
}
```

这段源码体现了缓冲输出流关闭时的几个关键规则。

第一，`close()` 方法会先判断 `closed` 状态。如果流已经关闭，再次调用 `close()` 不会重复执行关闭逻辑。这说明关闭流具有一定的幂等性，多次关闭通常不会反复释放同一资源。

第二，`close()` 在真正关闭底层流之前，会先调用 `flush()`。这是缓冲流区别于普通节点流的重要地方。因为缓冲流写数据时，数据可能还停留在内存缓冲区中，如果关闭前不刷新，最后一部分数据可能无法写入文件。

第三，`out.close()` 会关闭被包装的底层流。这里的 `out` 通常就是构造 `BufferedOutputStream` 时传入的底层输出流，例如 `FileOutputStream`。因此，使用包装流时通常只需要关闭最外层的缓冲流，不需要再手动关闭内部的节点流。

第四，即使 `flush()` 发生异常，源码仍然会在 `finally` 中尝试关闭底层流。这说明关闭资源本身也是必须尽量完成的操作，不能因为刷新失败就直接跳过底层资源释放。

#### BufferedInputStream

`BufferedInputStream` 是字节缓冲输入流，用于包装已有的字节输入流。读取数据时，它会先从底层输入流批量读取一批字节放入缓冲区，程序后续读取时优先从内存缓冲区中获取数据。

```java
import java.io.BufferedInputStream;
import java.io.FileInputStream;
import java.io.IOException;

public class BufferedInputStreamDemo {
    public static void main(String[] args) {
        try (BufferedInputStream in =
                     new BufferedInputStream(new FileInputStream("data.txt"))) {

            byte[] buffer = new byte[1024];
            int len;

            while ((len = in.read(buffer)) != -1) {
                System.out.print(new String(buffer, 0, len));
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

执行过程如下：

1. `FileInputStream` 直接连接源文件；
2. `BufferedInputStream` 包装 `FileInputStream`；
3. 底层会先批量读取数据到缓冲区；
4. 程序调用 `read(buffer)` 时，优先从缓冲区中读取；
5. 缓冲区数据读完后，再从底层流继续填充缓冲区。

> 易错点：`BufferedInputStream` 仍然是字节流。用它读取中文文本后再直接 `new String(...)`，如果编码不一致或多字节字符被拆分，仍然可能乱码。

#### 字节缓冲流复制文件

字节缓冲流适合复制任意类型文件。复制时应使用字节数组循环读取，并且写出本次实际读取到的有效字节数。

```java
import java.io.BufferedInputStream;
import java.io.BufferedOutputStream;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class BufferedByteCopyDemo {
    public static void main(String[] args) {
        try (
                BufferedInputStream in =
                        new BufferedInputStream(new FileInputStream("source.mp4"));
                BufferedOutputStream out =
                        new BufferedOutputStream(new FileOutputStream("target.mp4"))
        ) {
            byte[] buffer = new byte[1024];
            int len;

            while ((len = in.read(buffer)) != -1) {
                // 只写出本次读取到的有效字节
                out.write(buffer, 0, len);
            }

            // try-with-resources 结束时会自动 close，close 前会自动 flush
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

其中，`out.write(buffer, 0, len)` 是关键。最后一次读取时，缓冲数组可能没有被填满，如果直接写出整个数组，可能导致目标文件多出无效数据。

> 结论：复制任意类型文件时，优先使用字节流；如果需要提升效率，可以在字节流外层包装字节缓冲流。

### 字符缓冲流

字符缓冲流用于包装字符流，以字符为单位进行高效读写，主要用于处理文本文件。

常见字符缓冲流如下：

| 类               | 作用                             | 新增常用方法 |
| ---------------- | -------------------------------- | ------------ |
| `BufferedReader` | 字符缓冲输入流，提高字符读取效率 | `readLine()` |
| `BufferedWriter` | 字符缓冲输出流，提高字符写出效率 | `newLine()`  |

> 注意：`BufferedReader` 是输入流，用于读；`BufferedWriter` 是输出流，用于写。

#### BufferedWriter

`BufferedWriter` 是字符缓冲输出流，用于包装已有的字符输出流。它继承了 `Writer` 的写出方法，并新增了 `newLine()` 方法。

`newLine()` 会根据当前操作系统写入合适的换行符，因此比手写 `"\n"` 更具有跨平台意义。

```java
import java.io.BufferedWriter;
import java.io.FileWriter;
import java.io.IOException;

public class BufferedWriterDemo {
    public static void main(String[] args) {
        try (BufferedWriter writer =
                     new BufferedWriter(new FileWriter("message.txt"))) {

            writer.write("第一行文本");
            writer.newLine();

            writer.write("第二行文本");
            writer.newLine();

            writer.write("第三行文本");

            // close() 会自动 flush
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

执行过程如下：

1. `FileWriter` 直接连接文本文件；
2. `BufferedWriter` 包装 `FileWriter`；
3. `write()` 写入字符数据到缓冲区；
4. `newLine()` 写入当前系统对应的换行符；
5. `close()` 关闭前会刷新缓冲区。

> 结论：写文本文件时，`BufferedWriter` 比 `FileWriter` 更常用，因为它既有缓冲能力，又提供了跨平台换行方法。

#### BufferedReader

`BufferedReader` 是字符缓冲输入流，用于包装已有的字符输入流。它继承了 `Reader` 的读取方法，并新增了 `readLine()` 方法。

`readLine()` 一次读取一行文本。读取成功时返回该行内容；读到文件末尾时返回 `null`。

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class BufferedReaderDemo {
    public static void main(String[] args) {
        try (BufferedReader reader =
                     new BufferedReader(new FileReader("message.txt"))) {

            String line;

            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

需要注意，`readLine()` 返回的字符串**不包含行尾换行符**。如果读取后再写入另一个文件，并希望保持原来的换行结构，需要手动调用 `newLine()`。

> 易错点：`readLine()` 只返回一行内容本身，不会把换行符一起返回。

#### 字符缓冲流复制文本文件

字符缓冲流适合复制文本文件。常见写法是使用 `readLine()` 按行读取，再用 `write()` 和 `newLine()` 写出。

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class BufferedCharCopyDemo {
    public static void main(String[] args) {
        try (
                BufferedReader reader =
                        new BufferedReader(new FileReader("source.txt"));
                BufferedWriter writer =
                        new BufferedWriter(new FileWriter("target.txt"))
        ) {
            String line;

            while ((line = reader.readLine()) != null) {
                writer.write(line);

                // readLine() 不读取换行符，因此写出时需要补充换行
                writer.newLine();
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

这种方式适合普通文本文件。如果复制图片、视频、压缩包等二进制文件，不能使用字符缓冲流，应使用字节流或字节缓冲流。

> 结论：字符缓冲流适合文本处理，尤其适合按行读取和写入；任意文件复制仍应使用字节流。

#### 字符缓冲流与编码问题

`BufferedReader` 和 `BufferedWriter` 本身只负责缓冲，它们不直接决定文本编码。真正决定编码和解码的是被包装的字符转换流或便捷字符流。

例如：

```java
BufferedReader reader = new BufferedReader(new FileReader("a.txt"));
```

这里实际使用的字符集取决于 `FileReader`。如果 `FileReader` 使用 JVM 默认字符集，而文件本身不是该字符集，就可能乱码。

如果需要明确字符集，可以使用转换流：

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.FileInputStream;
import java.nio.charset.StandardCharsets;

BufferedReader reader = new BufferedReader(
        new InputStreamReader(new FileInputStream("a.txt"), StandardCharsets.UTF_8)
);
```

> 注意：缓冲流只增强效率和方法，不负责自动解决编码不一致问题。文本乱码仍然要从字符集是否一致入手。

### 缓冲流与装饰器模式

缓冲流是典型的包装流，其设计思想属于装饰器模式。装饰器模式的核心是：不改变原对象本身，而是在外层包装一个新对象，为原对象增加功能。

例如：

```java
FileReader fileReader = new FileReader("a.txt");
BufferedReader bufferedReader = new BufferedReader(fileReader);
```

`FileReader` 原本只能按字符或字符数组读取；包装成 `BufferedReader` 后，就拥有了缓冲能力，并且可以使用 `readLine()` 按行读取。

这种结构也可以继续组合：

```text
程序
  ↓
BufferedReader
  ↓
InputStreamReader
  ↓
FileInputStream
  ↓
文件
```

其中：

1. `FileInputStream` 负责按字节连接文件；
2. `InputStreamReader` 负责把字节解码成字符；
3. `BufferedReader` 负责增加缓冲能力和按行读取能力。

> 结论：Java IO 流可以层层包装，每一层负责一个功能。理解这种组合关系，比死记具体类更重要。

## 转换流

转换流用于在**字节流**和**字符流**之间建立桥梁，核心作用是按照指定字符集完成**编码**和**解码**。当文本文件的编码格式与程序默认编码不一致时，直接使用 `FileReader` 或 `FileWriter` 可能出现乱码；此时就需要使用转换流明确指定字符集。

Java 中常用的转换流有两个：

| 类                   | 方向 | 作用                         | 本质 |
| -------------------- | ---- | ---------------------------- | ---- |
| `InputStreamReader`  | 输入 | 将字节输入流转换为字符输入流 | 解码 |
| `OutputStreamWriter` | 输出 | 将字符输出流转换为字节输出流 | 编码 |

> 结论：转换流解决的是“字节与字符之间如何按照指定编码规则转换”的问题。读取文本时是解码，写出文本时是编码。

### 编码问题的产生

文本文件保存在硬盘中时，本质上保存的是一组字节。程序读取文本时，需要按照某种字符集把这些字节解释成字符。

如果文件保存时使用的是 `GBK`，而程序读取时使用的是 `UTF-8`，那么同一组字节会被按照错误的规则解释，最终就会出现乱码。

例如，直接使用 `FileReader` 读取一个 `GBK` 编码的文本文件：

```java
import java.io.FileReader;
import java.io.IOException;
import java.io.Reader;

public class EncodingProblemDemo {
    public static void main(String[] args) {
        try (Reader reader = new FileReader("D:/temp.txt")) {
            int ch;

            while ((ch = reader.read()) != -1) {
                System.out.print((char) ch);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

如果 `D:/temp.txt` 实际是 `GBK` 编码，而 `FileReader` 使用的默认字符集不是 `GBK`，读取结果就可能乱码。

> 易错点：乱码的根本原因不是“中文不能读取”，而是**文件编码规则**和**程序解码规则**不一致。

### JVM 默认字符集

如果创建转换流时没有指定字符集，程序会使用 JVM 的默认字符集。可以通过以下方式查看当前 JVM 默认编码：

```java
import java.nio.charset.Charset;

public class DefaultCharsetDemo {
    public static void main(String[] args) {
        System.out.println(System.getProperty("file.encoding"));
        System.out.println(Charset.defaultCharset());
    }
}
```

在不同操作系统、不同 JDK 版本、不同运行配置下，默认字符集可能不同。因此，处理具有明确编码格式的文本文件时，不应过度依赖默认字符集。

> 结论：只要文本文件编码不是完全确定与 JVM 默认字符集一致，就应显式指定字符集。

### InputStreamReader：字节输入流转字符输入流

`InputStreamReader` 是 `Reader` 的子类，作用是把字节输入流转换为字符输入流。读取文件时，硬盘中的内容本质上是字节，`InputStreamReader` 会按照指定字符集把这些字节解码成字符。

继承关系可以理解为：

```text
Reader
  └── InputStreamReader
```

常用构造方法如下：

| 构造方法                                                | 说明                    |
| ------------------------------------------------------- | ----------------------- |
| `InputStreamReader(InputStream in)`                     | 使用默认字符集解码      |
| `InputStreamReader(InputStream in, String charsetName)` | 使用指定字符集名称解码  |
| `InputStreamReader(InputStream in, Charset cs)`         | 使用指定 `Charset` 解码 |

例如，读取 `GBK` 编码的文本文件：

```java
import java.io.FileInputStream;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.Reader;
import java.nio.charset.Charset;

public class InputStreamReaderDemo {
    public static void main(String[] args) {
        try (
                Reader reader = new InputStreamReader(
                        new FileInputStream("D:/temp.txt"),
                        Charset.forName("GBK")
                )
        ) {
            char[] buffer = new char[512];
            int len;

            while ((len = reader.read(buffer)) != -1) {
                System.out.print(new String(buffer, 0, len));
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

这段代码中，`FileInputStream` 负责从文件中读取字节，`InputStreamReader` 负责按照 `GBK` 把字节解码为字符。

执行过程如下：

1. `FileInputStream` 连接硬盘文件，读取原始字节；
2. `InputStreamReader` 按指定字符集进行解码；
3. 程序最终拿到的是字符数据；
4. 关闭最外层的 `InputStreamReader` 时，被包装的 `FileInputStream` 也会被关闭。

> 结论：读取指定编码的文本文件时，应使用 `InputStreamReader` 并明确指定文件实际编码。

### OutputStreamWriter：字符输出流转字节输出流

`OutputStreamWriter` 是 `Writer` 的子类，作用是把字符输出流转换为字节输出流。写出文本时，程序中的内容是字符，`OutputStreamWriter` 会按照指定字符集把字符编码成字节，再写入文件。

继承关系可以理解为：

```text
Writer
  └── OutputStreamWriter
```

常用构造方法如下：

| 构造方法                                                   | 说明                    |
| ---------------------------------------------------------- | ----------------------- |
| `OutputStreamWriter(OutputStream out)`                     | 使用默认字符集编码      |
| `OutputStreamWriter(OutputStream out, String charsetName)` | 使用指定字符集名称编码  |
| `OutputStreamWriter(OutputStream out, Charset cs)`         | 使用指定 `Charset` 编码 |

例如，把文本按照 `GBK` 编码写入文件：

```java
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.OutputStreamWriter;
import java.io.Writer;
import java.nio.charset.Charset;

public class OutputStreamWriterDemo {
    public static void main(String[] args) {
        try (
                Writer writer = new OutputStreamWriter(
                        new FileOutputStream("D:/result.txt"),
                        Charset.forName("GBK")
                )
        ) {
            writer.write("张三李四王五");
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

这段代码中，`FileOutputStream` 负责把字节写入文件，`OutputStreamWriter` 负责按照 `GBK` 把字符编码成字节。

执行过程如下：

1. 程序中准备写出的内容是字符；
2. `OutputStreamWriter` 按指定字符集进行编码；
3. 编码后的字节通过 `FileOutputStream` 写入硬盘文件；
4. 关闭最外层的 `OutputStreamWriter` 时，会先刷新数据，再关闭被包装的 `FileOutputStream`。

> 结论：希望生成指定编码的文本文件时，应使用 `OutputStreamWriter` 并明确指定编码。

### 编码与解码

转换流的核心可以用两个词概括：**编码**和**解码**。

| 操作 | 数据方向            | 含义             | 对应转换流           |
| ---- | ------------------- | ---------------- | -------------------- |
| 解码 | 文件字节 → 程序字符 | 把字节解释成字符 | `InputStreamReader`  |
| 编码 | 程序字符 → 文件字节 | 把字符转换成字节 | `OutputStreamWriter` |

读取文件时：

```text
硬盘中的字节  --按照字符集解码-->  Java 中的字符
```

写出文件时：

```text
Java 中的字符  --按照字符集编码-->  硬盘中的字节
```

例如，同样是字符串 `"张三"`，用 `UTF-8` 和 `GBK` 写出时，底层保存的字节序列不同。如果读取时字符集选择错误，就无法还原出正确字符。

> 结论：读文本要关注“用什么字符集解码”，写文本要关注“用什么字符集编码”。

### FileReader 与 InputStreamReader 的关系

`FileReader` 并不是直接继承 `Reader`，而是 `InputStreamReader` 的子类。它可以看作读取文件时的便捷字符输入流。

继承关系如下：

```text
Reader
  └── InputStreamReader
        └── FileReader
```

从构造逻辑上看，`FileReader` 底层仍然需要创建文件字节输入流，再交给父类完成解码：

```java
public FileReader(String fileName) throws FileNotFoundException {
    super(new FileInputStream(fileName));
}
```

因此：

```java
Reader reader = new FileReader("D:/temp.txt");
```

可以理解为一种简化写法，接近于：

```java
Reader reader = new InputStreamReader(new FileInputStream("D:/temp.txt"));
```

二者默认都使用 JVM 默认字符集。区别在于：`InputStreamReader` 可以显式指定字符集，而传统 `FileReader` 写法更简洁但控制能力较弱。

> 结论：如果文本文件使用默认字符集，`FileReader` 写法更简洁；如果需要指定编码，应使用 `InputStreamReader`。

### FileWriter 与 OutputStreamWriter 的关系

`FileWriter` 并不是直接继承 `Writer`，而是 `OutputStreamWriter` 的子类。它可以看作写文件时的便捷字符输出流。

继承关系如下：

```text
Writer
  └── OutputStreamWriter
        └── FileWriter
```

使用 `FileWriter` 写文本，本质上仍然要把字符编码成字节，再通过底层文件输出流写入文件。较新的 JDK 中，`FileWriter` 也可以在构造方法中指定 `Charset`，例如：

```java
import java.io.FileWriter;
import java.nio.charset.Charset;

public class FileWriterCharsetDemo {
    public static void main(String[] args) throws Exception {
        try (FileWriter writer = new FileWriter("D:/result.txt", Charset.forName("GBK"))) {
            writer.write("张三李四王五");
        }
    }
}
```

这种写法比直接使用 `OutputStreamWriter` 更简洁，但本质仍然是字符到字节的编码过程。

> 结论：`FileWriter` 是 `OutputStreamWriter` 的便捷子类。需要指定文件编码时，可以使用支持 `Charset` 的 `FileWriter` 构造方法，也可以使用 `OutputStreamWriter`。

### 转换流与缓冲流的组合

转换流经常和缓冲流配合使用。推荐组合方式是：**先用转换流解决编码问题，再用缓冲流提高效率和增强方法**。

读取 `GBK` 文本文件并按行输出：

```java
import java.io.BufferedReader;
import java.io.FileInputStream;
import java.io.InputStreamReader;
import java.nio.charset.Charset;

public class ReadGbkByLineDemo {
    public static void main(String[] args) {
        try (
                BufferedReader reader = new BufferedReader(
                        new InputStreamReader(
                                new FileInputStream("D:/temp.txt"),
                                Charset.forName("GBK")
                        )
                )
        ) {
            String line;

            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

按照 `UTF-8` 写出文本，并使用缓冲流提升效率：

```java
import java.io.BufferedWriter;
import java.io.FileOutputStream;
import java.io.OutputStreamWriter;
import java.nio.charset.StandardCharsets;

public class WriteUtf8ByLineDemo {
    public static void main(String[] args) {
        try (
                BufferedWriter writer = new BufferedWriter(
                        new OutputStreamWriter(
                                new FileOutputStream("D:/result.txt"),
                                StandardCharsets.UTF_8
                        )
                )
        ) {
            writer.write("第一行");
            writer.newLine();
            writer.write("第二行");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

组合关系可以表示为：

```text
读取文本：
程序
  ↑
BufferedReader
  ↑
InputStreamReader
  ↑
FileInputStream
  ↑
文件

写出文本：
程序
  ↓
BufferedWriter
  ↓
OutputStreamWriter
  ↓
FileOutputStream
  ↓
文件
```

### FileReader、FileWriter 与转换流的选择

| 场景                   | 推荐写法                                                 |
| ---------------------- | -------------------------------------------------------- |
| 读取默认编码文本       | `FileReader`                                             |
| 写出默认编码文本       | `FileWriter`                                             |
| 读取指定编码文本       | `InputStreamReader + FileInputStream`                    |
| 写出指定编码文本       | `OutputStreamWriter + FileOutputStream`                  |
| 读取指定编码并按行处理 | `BufferedReader + InputStreamReader + FileInputStream`   |
| 写出指定编码并按行写入 | `BufferedWriter + OutputStreamWriter + FileOutputStream` |

当前 JDK 的 `FileReader`、`FileWriter` 已支持 `Charset` 构造方法，也可以用更简洁的写法指定编码。但从理解 IO 流体系的角度看，`InputStreamReader` 和 `OutputStreamWriter` 更能体现转换流的本质。

以下内容结合 `PrintStreamTest01.java`、`PrintStreamTest02.java`、`PrintWriterTest01.java`、`SystemInTest.java`、`SystemOutTest.java` 和 `SystemErrTest.java` 中关于打印流、格式化输出、标准输入输出流和标准错误输出流的示例整理。

## 打印流

打印流是 Java IO 体系中用于**便捷输出数据**的一类流。它的主要作用不是“只能向控制台打印”，而是可以把各种类型的数据以文本形式输出到控制台、文件、网络等目的地。

Java 中常见打印流有两个：

| 类            | 所属体系   | 主要特点                                            |
| ------------- | ---------- | --------------------------------------------------- |
| `PrintStream` | 字节流体系 | `System.out` 和 `System.err` 的类型，常用于标准输出 |
| `PrintWriter` | 字符流体系 | 更适合普通文本输出，可包装 `Writer`                 |

打印流的核心价值在于：**输出各种类型数据更方便，格式化输出更直观，并且打印方法本身通常不抛出 `IOException`**。

> 结论：打印流更准确地说是一种“格式化输出流”。它简化了输出操作，尤其适合控制台输出、日志输出、调试信息输出和文本格式化输出。

### 打印流的主要优势

打印流相比普通输出流有几个明显优势。

| 优势             | 说明                                                     |
| ---------------- | -------------------------------------------------------- |
| 自动转换数据类型 | `int`、`double`、`boolean`、`char`、对象等都可以直接输出 |
| 支持格式化输出   | 可以使用 `printf()` 按指定格式组织输出内容               |
| 输出方法使用简单 | `print()`、`println()` 更接近日常打印习惯                |
| 异常处理简化     | 打印方法通常不抛出 `IOException`                         |
| 支持自动刷新     | 构造时开启 `autoFlush` 后，特定打印操作会自动刷新        |

例如，普通字符流写出数字前通常需要手动转换：

```java
writer.write(String.valueOf(100));
writer.write(String.valueOf(3.14));
writer.write(String.valueOf(true));
```

打印流可以直接输出：

```java
printWriter.print(100);
printWriter.print(3.14);
printWriter.print(true);
```

打印流会在内部把这些数据转换成字符串后输出。

### PrintStream

`PrintStream` 是字节打印流，属于 `OutputStream` 体系。`System.out` 和 `System.err` 都是 `PrintStream` 类型对象。

`PrintStream` 可以输出到控制台，也可以输出到文件。例如：

```java
PrintStream ps = System.out;
```

表示获取标准输出流，默认输出到控制台。

也可以创建输出到文件的打印流：

```java
PrintStream ps = new PrintStream(new FileOutputStream("log.txt", true), true);
```

这表示创建一个输出到 `log.txt` 的打印流，并采用追加写入方式。其中第二个参数 `true` 表示开启自动刷新。

> 注意：`PrintStream` 是处理流，可以包装 `OutputStream`。如果包装的是 `FileOutputStream`，最终内容就会写入文件；如果使用的是 `System.out`，默认输出到控制台。

#### PrintStream 的常用方法

`PrintStream` 常用方法如下：

| 方法                                    | 说明                 |
| --------------------------------------- | -------------------- |
| `print(...)`                            | 输出数据，不自动换行 |
| `println(...)`                          | 输出数据，并换行     |
| `printf(String format, Object... args)` | 按指定格式输出       |
| `format(String format, Object... args)` | 与 `printf()` 类似   |
| `flush()`                               | 刷新流               |
| `close()`                               | 关闭流               |
| `checkError()`                          | 检查是否发生输出错误 |

需要注意，`checkError()` 返回 `true` 表示输出过程中发生过错误，返回 `false` 表示没有检测到错误。

> 易错点：`checkError()` 不是“判断是否写入成功”。它返回 `true` 表示出错，返回 `false` 才表示没有检测到错误。

#### PrintStream 基本使用

```java
import java.io.FileOutputStream;
import java.io.PrintStream;
import java.util.Date;

public class PrintStreamDemo {
    public static void main(String[] args) throws Exception {
        PrintStream ps = new PrintStream(new FileOutputStream("log.txt", true), true);

        ps.print(100);
        ps.print("\t");
        ps.print("张三");
        ps.print("\t");
        ps.print(true);
        ps.print("\t");
        ps.print(3.14);
        ps.print("\t");
        ps.println(new Date());

        if (ps.checkError()) {
            System.out.println("输出过程中发生错误");
        }

        ps.close();
    }
}
```

这段代码会把多种类型的数据输出到 `log.txt` 文件中。`print()` 不换行，`println()` 会在输出后追加换行。

> 结论：打印流可以直接输出多种类型数据，不需要手动把每个值转换成字符串。

#### PrintStream 的自动刷新

创建 `PrintStream` 时，可以通过构造方法开启自动刷新：

```java
PrintStream ps = new PrintStream(new FileOutputStream("log.txt", true), true);
```

其中第二个参数 `true` 表示开启自动刷新。开启后，执行某些打印操作时会自动调用 `flush()`。

常见触发自动刷新的情况包括：

1. 调用 `println()`；
2. 调用 `printf()` 或 `format()`；
3. 对 `PrintStream` 来说，写入换行符或写入字节数组时也可能触发刷新。

如果没有开启自动刷新，则需要根据需要手动调用：

```java
ps.flush();
```

> 注意：自动刷新不是“每写一个字符都刷新”。刷新过于频繁会影响性能，通常在需要立即看到输出结果时才依赖自动刷新。

### 格式化输出 printf

`printf()` 是打印流的重要方法，用于按照指定格式输出内容。它的基本格式如下：

```java
printf("格式字符串", 参数列表);
```

常见格式说明符如下：

| 格式说明符 | 含义                 | 示例       |
| ---------- | -------------------- | ---------- |
| `%d`       | 整数                 | `100`      |
| `%f`       | 浮点数               | `3.140000` |
| `%.2f`     | 保留两位小数         | `3.14`     |
| `%s`       | 字符串               | `hello`    |
| `%c`       | 字符                 | `A`        |
| `%b`       | 布尔值               | `true`     |
| `%n`       | 平台无关换行符       | 换行       |
| `%%`       | 输出百分号           | `%`        |
| `%02d`     | 不足两位时前面补 `0` | `05`       |
| `%-8s`     | 左对齐，总宽度为 8   | 文本左对齐 |
| `%8s`      | 右对齐，总宽度为 8   | 文本右对齐 |

例如：

```java
public class PrintFormatDemo {
    public static void main(String[] args) {
        int year = 2026;
        int month = 6;
        int day = 2;
        String name = "张三";
        double score = 95.678;
        int progress = 85;

        System.out.printf("%d年%02d月%02d日，%s的成绩是%.2f，完成度%d%%%n",
                year, month, day, name, score, progress);
    }
}
```

输出结果：

```text
2026年06月02日，张三的成绩是95.68，完成度85%
```

其中：

1. `%02d` 表示整数不足两位时补 `0`；
2. `%.2f` 表示小数保留两位；
3. `%%` 表示输出一个普通百分号；
4. `%n` 表示使用当前系统对应的换行符。

> 结论：需要输出结构化文本时，`printf()` 比字符串拼接更清晰，也更容易控制格式。

### PrintWriter

`PrintWriter` 是字符打印流，属于 `Writer` 体系，更适合输出普通文本。它既可以包装 `Writer`，也可以包装 `OutputStream`，因此在文本输出场景中使用非常灵活。

例如，包装 `FileWriter` 输出文本：

```java
PrintWriter pw = new PrintWriter(new FileWriter("log.txt", true), true);
```

这里第二个参数 `true` 表示开启自动刷新。`PrintWriter` 开启自动刷新后，调用 `println()`、`printf()` 或 `format()` 时会自动刷新。

#### PrintWriter 基本使用

```java
import java.io.FileWriter;
import java.io.PrintWriter;

public class PrintWriterDemo {
    public static void main(String[] args) throws Exception {
        PrintWriter pw = new PrintWriter(new FileWriter("log.txt", true), true);

        pw.print("编号：");
        pw.print(1001);
        pw.print("\t");
        pw.println("姓名：李四");

        pw.printf("成绩：%.1f%n", 89.5);

        if (pw.checkError()) {
            System.out.println("输出过程中发生错误");
        }

        pw.close();
    }
}
```

`PrintWriter` 的使用方式与 `PrintStream` 非常接近，也支持 `print()`、`println()`、`printf()` 等方法。

> 结论：如果主要处理文本输出，尤其是需要包装字符流时，`PrintWriter` 更符合字符流体系的使用习惯。

### PrintStream 与 PrintWriter 的区别

| 对比项                          | `PrintStream`              | `PrintWriter`          |
| ------------------------------- | -------------------------- | ---------------------- |
| 所属体系                        | 字节流体系                 | 字符流体系             |
| 父类                            | `FilterOutputStream`       | `Writer`               |
| 典型对象                        | `System.out`、`System.err` | 文本输出、网络文本响应 |
| 是否支持 `print/println/printf` | 支持                       | 支持                   |
| 是否适合文本输出                | 可以                       | 更适合                 |
| 是否适合原始字节输出            | 更适合                     | 不适合                 |
| 是否可包装 `Writer`             | 不适合                     | 可以                   |
| 错误检查                        | `checkError()`             | `checkError()`         |

需要特别注意：`PrintWriter` 的 `print()`、`println()` 等方法通常也不会直接抛出 `IOException`，与 `PrintStream` 类似，它也可以通过 `checkError()` 检查输出错误。

> 结论：底层标准输出和字节输出常用 `PrintStream`；普通文本输出更推荐 `PrintWriter`。简单记忆为：**字节用 Stream，文本用 Writer**。

### 标准输入、标准输出和标准错误输出

`System` 类中提供了三个与标准 IO 相关的静态成员：

| 成员         | 类型          | 含义           | 默认目标 |
| ------------ | ------------- | -------------- | -------- |
| `System.in`  | `InputStream` | 标准输入流     | 键盘     |
| `System.out` | `PrintStream` | 标准输出流     | 控制台   |
| `System.err` | `PrintStream` | 标准错误输出流 | 控制台   |

这三个流由 JVM 在程序启动时准备好，通常不需要手动创建，也不建议随意关闭。

> 注意：`System.out` 和 `System.err` 都是 `PrintStream`。区别在于语义不同：`out` 用于普通输出，`err` 用于错误信息输出。

#### System.out 标准输出流

`System.out` 表示标准输出流，默认把内容输出到控制台。

```java
public class SystemOutDemo {
    public static void main(String[] args) {
        System.out.println("普通信息");
        System.out.printf("当前进度：%d%%%n", 80);
    }
}
```

`System.out` 本质上是一个 `PrintStream` 对象，因此可以使用 `print()`、`println()`、`printf()` 等打印流方法。

默认的 `System.out` 通常不需要手动 `flush()` 或 `close()`。

##### 修改标准输出流方向

`System.setOut(PrintStream out)` 可以修改标准输出流的输出目标。例如，把原本输出到控制台的内容改为输出到文件：

```java
import java.io.FileOutputStream;
import java.io.PrintStream;
import java.text.SimpleDateFormat;
import java.util.Date;

public class RedirectSystemOutDemo {
    public static void main(String[] args) throws Exception {
        PrintStream ps = new PrintStream(new FileOutputStream("app.log", true), true);

        System.setOut(ps);

        String time = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss SSS").format(new Date());

        System.out.println(time + " 程序启动");
        System.out.println("这行内容会写入文件，而不是控制台");
    }
}
```

调用 `System.setOut(ps)` 后，后续的 `System.out.println()` 就会输出到 `app.log` 文件中。

> 注意：修改标准输出流后，输出目标已经不再是默认控制台。此时创建的 `PrintStream` 如果连接到文件，应按照普通 IO 流的规则关注刷新和关闭问题。

#### System.err 标准错误输出流

`System.err` 表示标准错误输出流，通常也输出到控制台，但语义上用于输出错误信息、异常信息等。

```java
public class SystemErrDemo {
    public static void main(String[] args) {
        System.err.println("这是一条错误信息");
        System.err.println(new RuntimeException("模拟异常"));
    }
}
```

在许多开发环境中，`System.err` 输出的内容可能以红色显示，便于和普通输出区分。未捕获异常被 JVM 打印时，通常也会输出到标准错误流。

> 结论：普通运行信息使用 `System.out`，错误信息和异常信息使用 `System.err`。二者默认都输出到控制台，但表达的语义不同。

#### System.in 标准输入流

`System.in` 表示标准输入流，默认从键盘读取数据。它的类型是 `InputStream`，属于字节输入流。

直接使用 `System.in` 可以读取键盘输入的字节，但操作较繁琐：

```java
import java.io.InputStream;

public class SystemInByteDemo {
    public static void main(String[] args) throws Exception {
        InputStream in = System.in;

        byte[] buffer = new byte[1024];
        int len = in.read(buffer);

        System.out.println(new String(buffer, 0, len));
    }
}
```

键盘输入本质上是文本数据，而 `System.in` 是字节流。如果希望按行读取文本，需要配合转换流和缓冲流。

##### System.in 转为 BufferedReader

`System.in` 是字节输入流，而 `BufferedReader` 是字符缓冲输入流，并且提供了 `readLine()` 方法。要使用 `readLine()` 读取键盘输入的一整行，需要经过以下包装：

```text
System.in
  ↓
InputStreamReader
  ↓
BufferedReader
```

示例：

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;

public class KeyboardInputDemo {
    public static void main(String[] args) throws Exception {
        BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));

        while (true) {
            System.out.print("请输入：");

            String line = reader.readLine();

            if ("exit".equals(line)) {
                break;
            }

            System.out.println("输入内容：" + line);
        }

        reader.close();
    }
}
```

执行过程如下：

1. `System.in` 从键盘读取字节；
2. `InputStreamReader` 把字节转换成字符；
3. `BufferedReader` 增加缓冲能力，并提供 `readLine()`；
4. 输入 `exit` 时结束循环。

> 注意：在实际开发中，读取键盘输入通常使用 `Scanner` 更简单；这里使用 `BufferedReader` 主要是为了理解标准输入流、转换流和缓冲流的组合关系。

##### 修改标准输入流方向

`System.setIn(InputStream in)` 可以修改标准输入流的数据来源。例如，把默认键盘输入改成从文件读取：

```java
import java.io.FileInputStream;
import java.io.InputStream;

public class RedirectSystemInDemo {
    public static void main(String[] args) throws Exception {
        System.setIn(new FileInputStream("input.txt"));

        InputStream in = System.in;

        byte[] buffer = new byte[1024];
        int len;

        while ((len = in.read(buffer)) != -1) {
            System.out.print(new String(buffer, 0, len));
        }
    }
}
```

调用 `System.setIn()` 后，`System.in` 的数据来源就不再是键盘，而是指定的输入流。

#### 标准流使用注意事项

标准流使用时需要注意以下规则：

1. 默认的 `System.in`、`System.out`、`System.err` 通常不需要手动关闭；
2. 如果通过 `System.setOut()` 或 `System.setIn()` 替换为文件流，应按照普通 IO 流管理资源；
3. 不建议随意关闭 `System.out`，否则后续控制台输出可能失效；
4. `System.err` 适合输出错误信息，不应用来输出普通业务结果；
5. 复杂键盘输入建议使用 `Scanner`，按行文本输入可使用 `BufferedReader`。

> 易错点：`System.out.close()` 会关闭标准输出流，后续再调用 `System.out.println()` 可能无法正常输出。默认标准流一般由 JVM 管理，不需要主动关闭。

以下内容结合 `DataOutputStreamTest.java` 中使用 `DataOutputStream` 按固定顺序写出基本数据类型，以及 `DataInputStreamTest.java` 中使用 `DataInputStream` 按相同顺序读取数据的示例整理。

## 数据流

数据流用于读写 Java 的**基本数据类型**和字符串数据。普通字节流只能按字节读写，字符流只能按字符读写，而数据流可以直接以 `byte`、`short`、`int`、`long`、`float`、`double`、`boolean`、`char`、`String` 等形式写出和读取数据。

Java 中的数据流只有**字节流**形式，常用类有两个：

| 类                 | 方向 | 作用                   |
| ------------------ | ---- | ---------------------- |
| `DataOutputStream` | 输出 | 按指定数据类型写出数据 |
| `DataInputStream`  | 输入 | 按指定数据类型读取数据 |

> 结论：数据流适合保存和读取基本数据类型与字符串类型的数据，但读取顺序必须和写入顺序完全一致。

### 数据流的特点

数据流本质上属于**处理流**，不能直接连接文件，必须包装在已有的字节流外层。

例如：

```java
DataOutputStream dos = new DataOutputStream(new FileOutputStream("user.data"));
```

其中，`FileOutputStream` 是节点流，负责连接文件；`DataOutputStream` 是处理流，负责把基本数据类型按照固定的二进制格式写出。

数据流写出的内容不是普通文本，而是二进制数据。因此，用文本编辑器直接打开数据流生成的文件，通常会看到乱码或无法正常阅读。

> 注意：数据流写出的文件不是给人直接阅读的，而是给 `DataInputStream` 按规则读取的。

### DataOutputStream 类

`DataOutputStream` 是数据字节输出流，用于把基本数据类型和字符串数据写入输出流中。

常用方法如下：

| 方法                      | 说明                        |
| ------------------------- | --------------------------- |
| `writeByte(int v)`        | 写出一个 `byte` 类型数据    |
| `writeShort(int v)`       | 写出一个 `short` 类型数据   |
| `writeInt(int v)`         | 写出一个 `int` 类型数据     |
| `writeLong(long v)`       | 写出一个 `long` 类型数据    |
| `writeFloat(float v)`     | 写出一个 `float` 类型数据   |
| `writeDouble(double v)`   | 写出一个 `double` 类型数据  |
| `writeBoolean(boolean v)` | 写出一个 `boolean` 类型数据 |
| `writeChar(int v)`        | 写出一个 `char` 类型数据    |
| `writeUTF(String str)`    | 以 UTF 编码形式写出字符串   |

示例：

```java
import java.io.DataOutputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class DataOutputStreamDemo {
    public static void main(String[] args) {
        try (DataOutputStream dos = new DataOutputStream(new FileOutputStream("user.data"))) {
            byte b = 10;
            short s = 20;
            int age = 18;
            long id = 10001L;
            float height = 175.5F;
            double score = 98.5;
            boolean active = true;
            char level = 'A';
            String name = "张三";

            // 按固定顺序写出数据
            dos.writeByte(b);
            dos.writeShort(s);
            dos.writeInt(age);
            dos.writeLong(id);
            dos.writeFloat(height);
            dos.writeDouble(score);
            dos.writeBoolean(active);
            dos.writeChar(level);
            dos.writeUTF(name);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

这段代码会把多个不同类型的数据写入 `user.data` 文件。文件中的内容是二进制格式，不适合用文本编辑器直接查看。

> 易错点：`DataOutputStream` 写出的数据不是普通字符串。即使写入的是 `int 10`，文件中保存的也不是字符 `"10"`，而是 `int` 类型对应的二进制表示。

### DataInputStream 类

`DataInputStream` 是数据字节输入流，用于从输入流中读取由 `DataOutputStream` 写出的基本数据类型和字符串数据。

常用方法如下：

| 方法            | 说明                             |
| --------------- | -------------------------------- |
| `readByte()`    | 读取一个 `byte` 类型数据         |
| `readShort()`   | 读取一个 `short` 类型数据        |
| `readInt()`     | 读取一个 `int` 类型数据          |
| `readLong()`    | 读取一个 `long` 类型数据         |
| `readFloat()`   | 读取一个 `float` 类型数据        |
| `readDouble()`  | 读取一个 `double` 类型数据       |
| `readBoolean()` | 读取一个 `boolean` 类型数据      |
| `readChar()`    | 读取一个 `char` 类型数据         |
| `readUTF()`     | 读取由 `writeUTF()` 写出的字符串 |

示例：

```java
import java.io.DataInputStream;
import java.io.FileInputStream;
import java.io.IOException;

public class DataInputStreamDemo {
    public static void main(String[] args) {
        try (DataInputStream dis = new DataInputStream(new FileInputStream("user.data"))) {
            // 读取顺序必须和写入顺序完全一致
            byte b = dis.readByte();
            short s = dis.readShort();
            int age = dis.readInt();
            long id = dis.readLong();
            float height = dis.readFloat();
            double score = dis.readDouble();
            boolean active = dis.readBoolean();
            char level = dis.readChar();
            String name = dis.readUTF();

            System.out.println(b);
            System.out.println(s);
            System.out.println(age);
            System.out.println(id);
            System.out.println(height);
            System.out.println(score);
            System.out.println(active);
            System.out.println(level);
            System.out.println(name);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

读取时必须清楚文件中数据的写入顺序，并使用对应的读取方法依次读取。

> 结论：`DataOutputStream` 负责按类型写，`DataInputStream` 负责按类型读。二者通常成对使用。

### 为什么读取顺序必须一致

数据流写出的文件不是自描述格式。也就是说，文件中并不会完整记录“这里是一个 `int`，后面是一个 `double`，再后面是一个 `boolean`”这样的说明信息。程序必须根据写入时约定好的顺序来读取。

例如写入顺序是：

```java
dos.writeInt(18);
dos.writeDouble(98.5);
dos.writeBoolean(true);
```

读取时必须对应写成：

```java
int age = dis.readInt();
double score = dis.readDouble();
boolean active = dis.readBoolean();
```

如果读取顺序写错：

```java
double score = dis.readDouble(); // 错误：文件开头实际是 int
int age = dis.readInt();
boolean active = dis.readBoolean();
```

程序会按照错误的数据长度和格式解释字节，轻则读出错误数据，重则抛出异常。

不同类型占用的字节数不同，例如：

| 类型      | 占用字节数 |
| --------- | ---------- |
| `byte`    | 1 字节     |
| `short`   | 2 字节     |
| `int`     | 4 字节     |
| `long`    | 8 字节     |
| `float`   | 4 字节     |
| `double`  | 8 字节     |
| `boolean` | 1 字节     |
| `char`    | 2 字节     |

如果写入的是 `int`，却用 `readLong()` 读取，读取位置就会错乱，后续数据也会跟着解析错误。

> 易错点：数据流不是“按值自动识别类型”的流。读取时用什么方法，程序就会按什么类型解释接下来的字节。

#### writeUTF 与 readUTF

`DataOutputStream` 写字符串通常使用 `writeUTF()`，对应读取时必须使用 `readUTF()`。

```java
dos.writeUTF("hello");
```

对应读取：

```java
String text = dis.readUTF();
```

`writeUTF()` 写出字符串时，会按照特定格式保存字符串长度和字符串内容。`readUTF()` 会按相同格式读取并还原字符串。

> 注意：`writeUTF()` 和 `readUTF()` 必须成对使用。不能用普通字节流或字符流随意读取 `writeUTF()` 写出的内容，否则容易读出乱码或异常。

### 数据流与普通文本输出的区别

数据流和普通文本输出流的区别如下：

| 对比项                   | 数据流                                 | 普通文本输出               |
| ------------------------ | -------------------------------------- | -------------------------- |
| 代表类                   | `DataOutputStream` / `DataInputStream` | `Writer`、`PrintWriter` 等 |
| 文件内容                 | 二进制数据                             | 文本数据                   |
| 是否适合人直接阅读       | 不适合                                 | 适合                       |
| 是否保留数据类型读取方式 | 通过对应方法读取                       | 通常需要字符串解析         |
| 典型用途                 | 保存基本类型数据                       | 保存日志、配置、普通文本   |

例如，写入整数 `123`：

```java
dos.writeInt(123);
```

保存的是 `int` 的二进制格式。

而使用打印流：

```java
pw.println(123);
```

保存的是字符 `'1'`、`'2'`、`'3'` 以及换行符。

> 结论：如果目标文件需要给人阅读，使用文本输出；如果目标文件只需要程序按类型读取，可以使用数据流。

### 数据流的包装结构

数据流通常可以直接包装文件字节流：

```java
DataOutputStream dos = new DataOutputStream(new FileOutputStream("user.data"));
DataInputStream dis = new DataInputStream(new FileInputStream("user.data"));
```

也可以在中间加入缓冲流，提高读写效率：

```java
DataOutputStream dos = new DataOutputStream(
        new BufferedOutputStream(new FileOutputStream("user.data"))
);

DataInputStream dis = new DataInputStream(
        new BufferedInputStream(new FileInputStream("user.data"))
);
```

包装关系如下：

```text
写出数据：
程序
  ↓
DataOutputStream
  ↓
BufferedOutputStream
  ↓
FileOutputStream
  ↓
文件

读取数据：
程序
  ↑
DataInputStream
  ↑
BufferedInputStream
  ↑
FileInputStream
  ↑
文件
```

关闭时只需要关闭最外层的数据流，底层被包装的流会随之关闭。

> 结论：数据流负责“按类型读写”，缓冲流负责“提高效率”，文件字节流负责“连接文件”。

## 对象流

对象流是用于读写 Java 对象的处理流。前面学习的数据流 `DataInputStream` 和 `DataOutputStream` 可以按类型读写基本数据类型和字符串，但不能直接读写普通对象；如果需要把一个对象保存到文件中，或者从文件中恢复对象，就需要使用对象流。

Java 中常用的对象流有两个：

| 类                   | 方向 | 作用                           |
| -------------------- | ---- | ------------------------------ |
| `ObjectOutputStream` | 输出 | 将对象写出到文件、网络等目的地 |
| `ObjectInputStream`  | 输入 | 从文件、网络等数据源中读取对象 |

对象流本质上仍然属于**字节流体系中的处理流**，不能直接连接文件，通常需要包装在 `FileOutputStream` 或 `FileInputStream` 外层使用。示例中 `ObjectOutputStream` 包装 `FileOutputStream` 写出对象，`ObjectInputStream` 包装 `FileInputStream` 读取对象。

> 结论：对象流解决的是“对象如何存入文件、又如何从文件恢复回来”的问题。

### 对象流的基本作用

对象流既可以读写基本数据类型，也可以读写对象。

| 方法类型     | 输出流方法                        | 输入流方法                      |
| ------------ | --------------------------------- | ------------------------------- |
| 基本数据类型 | `writeInt()`、`writeBoolean()` 等 | `readInt()`、`readBoolean()` 等 |
| 字符串       | `writeUTF()`                      | `readUTF()`                     |
| 对象         | `writeObject(Object obj)`         | `readObject()`                  |

其中最核心的是：

```java
writeObject(Object obj)
readObject()
```

`writeObject()` 用于把对象写出，`readObject()` 用于把对象读取回来。由于 `readObject()` 的返回值类型是 `Object`，读取后通常需要向下转型为原来的类型。

> 注意：对象流写出的文件是二进制文件，不是普通文本文件，通常不能用文本编辑器正常阅读。

### 序列化与反序列化

对象流背后的核心概念是**序列化**和**反序列化**。

| 概念     | 含义                       |
| -------- | -------------------------- |
| 序列化   | 把 Java 对象转换成字节序列 |
| 反序列化 | 把字节序列恢复成 Java 对象 |

对象在内存中以复杂结构存在，里面可能包含属性、引用关系等内容。文件和网络只能传输字节数据，因此对象必须先转换成字节序列，才能保存或传输。

序列化常见用途有两个：

1. **对象持久化**：把对象保存到文件中，程序下次运行时再恢复；
2. **网络传输对象**：把对象转成字节后通过网络发送，接收端再恢复成对象。

> 结论：序列化是“对象 → 字节”，反序列化是“字节 → 对象”。

### ObjectOutputStream：对象输出流

`ObjectOutputStream` 用于把对象写出到目标位置。它是处理流，需要包装一个字节输出流。

示例：

```java
import java.io.FileOutputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;

public class ObjectWriteDemo {
    public static void main(String[] args) {
        Student student = new Student("张三", 20);

        try (ObjectOutputStream out =
                     new ObjectOutputStream(new FileOutputStream("student.obj"))) {

            // 将对象序列化到文件中
            out.writeObject(student);

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

执行过程如下：

1. `FileOutputStream` 连接目标文件；
2. `ObjectOutputStream` 包装字节输出流；
3. `writeObject(student)` 将 `Student` 对象转换为字节序列；
4. 字节序列被写入 `student.obj` 文件；
5. 关闭最外层对象流时，底层文件输出流也会被关闭。

> 注意：对象要能被 `writeObject()` 写出，其所属类必须实现 `Serializable` 接口，否则会抛出 `NotSerializableException`。

### ObjectInputStream：对象输入流

`ObjectInputStream` 用于从数据源中读取对象。它是处理流，需要包装一个字节输入流。

示例：

```java
import java.io.FileInputStream;
import java.io.ObjectInputStream;

public class ObjectReadDemo {
    public static void main(String[] args) {
        try (ObjectInputStream in =
                     new ObjectInputStream(new FileInputStream("student.obj"))) {

            // readObject() 返回 Object，需要向下转型
            Student student = (Student) in.readObject();

            System.out.println(student);

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

执行过程如下：

1. `FileInputStream` 连接保存对象的文件；
2. `ObjectInputStream` 包装字节输入流；
3. `readObject()` 从文件中读取字节序列；
4. 对象流根据字节序列恢复出 Java 对象；
5. 由于返回值是 `Object`，需要强制转换为具体类型。

`readObject()` 可能抛出 `ClassNotFoundException`，原因是反序列化时需要根据类信息恢复对象，如果本地找不到对应的类，就无法完成对象恢复。

> 结论：`ObjectOutputStream` 负责写对象，`ObjectInputStream` 负责读对象，二者通常成对使用。

### 对象流读写基本数据类型

对象流除了可以读写对象，也可以读写基本数据类型和字符串。

```java
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.util.Date;

public class ObjectStreamBasicDemo {
    public static void main(String[] args) {
        write();
        read();
    }

    public static void write() {
        try (ObjectOutputStream out =
                     new ObjectOutputStream(new FileOutputStream("data.obj"))) {

            out.writeInt(100);
            out.writeBoolean(true);
            out.writeUTF("hello");
            out.writeObject(new Date());

        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public static void read() {
        try (ObjectInputStream in =
                     new ObjectInputStream(new FileInputStream("data.obj"))) {

            int num = in.readInt();
            boolean flag = in.readBoolean();
            String text = in.readUTF();
            Date date = (Date) in.readObject();

            System.out.println(num);
            System.out.println(flag);
            System.out.println(text);
            System.out.println(date);

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

读取时必须保持和写入时相同的顺序。先写 `int`，读取时就必须先读 `int`；先写对象，读取时就必须先读对象。

> 易错点：对象流读写数据也要遵守顺序一致原则。读取顺序错误，可能导致数据解析错误或抛出异常。

### Serializable 接口

如果一个对象要被序列化，它所属的类必须实现 `java.io.Serializable` 接口。示例中 `Student`、`User`、`Person` 类都通过实现 `Serializable` 使对象具备被序列化的资格。

`Serializable` 是一个**标记接口**，接口中没有任何抽象方法：

```java
public interface Serializable {
}
```

实现该接口不需要重写任何方法，它的作用是告诉 JVM：这个类的对象允许被序列化。

例如：

```java
import java.io.Serializable;

public class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;

    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

如果一个类没有实现 `Serializable`，却尝试通过 `ObjectOutputStream` 写出它的对象，就会抛出：

```text
java.io.NotSerializableException
```

> 结论：自定义对象要参与序列化，类必须实现 `Serializable` 接口。

#### 引用类型属性的序列化要求

如果一个可序列化对象中包含引用类型属性，那么该属性指向的对象通常也需要能够被序列化。

例如：

```java
class Student implements Serializable {
    private String name;
    private Address address;
}
```

如果 `address` 属性不为 `null`，并且 `Address` 类没有实现 `Serializable`，那么序列化 `Student` 对象时可能抛出 `NotSerializableException`。

解决方式有两种：

1. 让 `Address` 类也实现 `Serializable`；
2. 如果该属性不需要被保存，可以使用 `transient` 修饰。

> 注意：序列化保存的是对象状态。如果对象状态中引用了其他对象，这些被引用对象也可能一起参与序列化。

#### serialVersionUID

`serialVersionUID` 是序列化版本号，用于判断序列化文件中的类版本和当前本地类版本是否兼容。

如果一个类实现了 `Serializable`，但没有显式声明 `serialVersionUID`，序列化机制会根据类的信息计算一个默认版本号。类结构发生变化后，这个默认版本号可能改变。此时再反序列化旧文件，就可能抛出：

```text
java.io.InvalidClassException
```

示例中的 `Person` 类手动声明了 `serialVersionUID = 1L`，目的就是固定序列化版本，避免类结构调整后默认版本号变化导致反序列化失败。

推荐写法：

```java
import java.io.Serializable;

public class Person implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
}
```

如果使用较新的 JDK，还可以加上 `@Serial` 注解，让编译器检查该字段是否符合序列化机制要求：

```java
@java.io.Serial
private static final long serialVersionUID = 1L;
```

> 结论：实现 `Serializable` 后，建议显式声明 `serialVersionUID`。如果没有特殊版本管理需求，通常写成 `1L` 即可。

##### 为什么需要 serialVersionUID

反序列化不是简单地把文件内容读出来，而是要把字节序列恢复成本地 JVM 中某个类的对象。因此，JVM 需要判断：

1. 文件中保存的对象属于哪个类；
2. 当前本地是否存在这个类；
3. 当前本地类和当初序列化时的类是否版本兼容。

`serialVersionUID` 就是用来判断版本兼容性的标识。若文件中的 `serialVersionUID` 和本地类中的 `serialVersionUID` 不一致，JVM 会认为二者不是同一个可兼容版本，从而拒绝反序列化。

这种机制本质上是一种保护：避免用旧版本对象数据强行恢复成不兼容的新版本对象。

> 易错点：`serialVersionUID` 不是普通业务字段，而是序列化机制用来识别类版本的特殊字段。

##### serialVersionUID 固定后的类结构兼容问题

手动声明 `serialVersionUID` 后，如果类在序列化之后发生了一些**可兼容修改**，反序列化旧对象时通常仍然可以成功。例如，先序列化一个只包含 `name` 和 `age` 属性的对象，之后在类中新增 `email` 属性，并且保持 `serialVersionUID` 不变，那么旧对象反序列化时不会因为版本号不一致而失败。

但是，旧的序列化文件中并没有保存新增属性的数据，因此新增属性会被赋为对应类型的**默认值**：

| 新增属性类型 | 反序列化后的默认值 |
| ------------ | ------------------ |
| 引用类型     | `null`             |
| `int`        | `0`                |
| `double`     | `0.0`              |
| `boolean`    | `false`            |
| `char`       | `'\u0000'`         |

例如：

```java
public class Person implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;

    // 后期新增的属性
    private String email;
}
```

如果旧文件是在 `email` 属性出现之前序列化生成的，那么反序列化旧对象时，`name` 和 `age` 可以从文件中恢复，而 `email` 因为旧文件中没有对应数据，所以结果为 `null`。

> 结论：固定 `serialVersionUID` 可以让某些类结构变化后的旧对象仍然能够反序列化；如果后来新增了实例属性，旧对象反序列化时新增属性会使用默认值，而不是自动获得某个业务值。

#### transient 关键字

`transient` 表示**瞬态**。被 `transient` 修饰的成员变量不会参与默认序列化。

示例中 `Student` 类的 `name` 属性使用 `transient` 修饰，因此该对象被序列化时，`name` 不会被写入文件；反序列化恢复对象后，`name` 会变成引用类型的**默认值** `null`，而普通的 `age` 属性仍然可以被保存和恢复。

```java
import java.io.Serializable;

public class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private transient String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

反序列化后：

| 属性   | 是否参与序列化 | 反序列化结果    |
| ------ | -------------- | --------------- |
| `name` | 否             | `null`          |
| `age`  | 是             | 原来的 `int` 值 |

`transient` 常用于不希望保存的敏感数据或临时数据，例如密码、验证码、临时缓存等。

> 结论：不希望对象中的某个实例变量被序列化时，可以使用 `transient` 修饰。

#### static 变量不会被序列化

`static` 修饰的变量属于类，而不是某一个对象。序列化保存的是**对象状态**，而不是类状态，因此静态变量不会作为对象的一部分被序列化。

例如：

```java
public class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private static int count;
}
```

这里的 `name` 属于对象，可以参与序列化；`count` 属于类，不属于某个具体对象，因此不会作为对象状态被保存。

> 注意：`static` 不参与序列化，是因为它不属于对象；`transient` 不参与序列化，是因为它被明确标记为不需要保存。

### 序列化多个对象

如果需要保存多个对象，不建议反复单独写出多个对象后再逐个读取，尤其是在对象数量不确定时，读取会变得不方便。更常见的做法是：先把多个对象放入集合，再序列化整个集合。

示例中先把多个 `User` 对象加入 `ArrayList`，再通过 `writeObject(list)` 序列化集合；反序列化时一次性读取出 `List<User>`，再遍历集合。

示例：

```java
import java.io.FileOutputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;
import java.util.ArrayList;
import java.util.List;

public class WriteUsersDemo {
    public static void main(String[] args) {
        List<User> users = new ArrayList<>();

        users.add(new User("张三", 20));
        users.add(new User("李四", 21));
        users.add(new User("王五", 22));

        try (ObjectOutputStream out =
                     new ObjectOutputStream(new FileOutputStream("users.obj"))) {

            out.writeObject(users);

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

class User implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

读取多个对象：

```java
import java.io.FileInputStream;
import java.io.ObjectInputStream;
import java.util.List;

public class ReadUsersDemo {
    public static void main(String[] args) {
        try (ObjectInputStream in =
                     new ObjectInputStream(new FileInputStream("users.obj"))) {

            List<User> users = (List<User>) in.readObject();

            for (User user : users) {
                System.out.println(user);
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

> 结论：多个对象需要序列化时，优先把对象放入集合，再序列化集合对象，这样读取和管理更方便。

### 对象流与数据流的区别

| 对比项                      | 数据流                                | 对象流                                    |
| --------------------------- | ------------------------------------- | ----------------------------------------- |
| 代表类                      | `DataInputStream`、`DataOutputStream` | `ObjectInputStream`、`ObjectOutputStream` |
| 能否读写基本数据类型        | 可以                                  | 可以                                      |
| 能否读写字符串              | 可以                                  | 可以                                      |
| 能否读写普通对象            | 不可以                                | 可以                                      |
| 是否需要实现 `Serializable` | 不需要                                | 写对象时需要                              |
| 典型用途                    | 保存基础类型数据                      | 保存对象或对象集合                        |

数据流适合保存简单的基础类型数据；对象流适合保存对象状态。如果业务数据天然是一个对象，例如学生、用户、订单等，使用对象流比手动拆成多个基础类型更方便。

> 结论：数据流关注“按基本类型存取”，对象流关注“按对象整体存取”。

## 字节数组流（内存流）

字节数组流是一类以内存中的 `byte[]` 数组作为数据源或数据目的地的字节流。它不直接操作磁盘文件，也不依赖文件路径，而是在内存中完成字节数据的读写。

Java 中常用的字节数组流有两个：

| 类                      | 方向 | 作用                       |
| ----------------------- | ---- | -------------------------- |
| `ByteArrayOutputStream` | 输出 | 将数据写入内存中的字节数组 |
| `ByteArrayInputStream`  | 输入 | 从内存中的字节数组读取数据 |

> 结论：字节数组流本质上是以内存数组为节点的节点流，适合完成“数据 ↔ `byte[]`”之间的转换。

### 字节数组流的定位

IO 流按照功能角色可以分为节点流和处理流。`FileInputStream`、`FileOutputStream` 是以文件为节点的节点流；`ByteArrayInputStream`、`ByteArrayOutputStream` 是以**内存字节数组**为节点的节点流。

对比关系如下：

| 节点流                  | 数据源或目的地           |
| ----------------------- | ------------------------ |
| `FileInputStream`       | 磁盘文件                 |
| `FileOutputStream`      | 磁盘文件                 |
| `ByteArrayInputStream`  | 内存中的 `byte[]`        |
| `ByteArrayOutputStream` | 内存中的 `byte[]` 缓冲区 |

由于字节数组流也是字节流，所以它也可以与缓冲流、数据流、对象流等处理流配合使用。例如，可以用 `ObjectOutputStream` 包装 `ByteArrayOutputStream`，把对象序列化成 `byte[]`；也可以用 `ObjectInputStream` 包装 `ByteArrayInputStream`，从 `byte[]` 中反序列化出对象。

> 结论：文件流解决“程序和文件之间的数据传输”，字节数组流解决“程序和内存字节数组之间的数据传输”。

### ByteArrayOutputStream 类

`ByteArrayOutputStream` 是字节数组输出流。它会在内部维护一个可自动扩容的 `byte[]` 缓冲区，写入该流的数据都会保存在这块内存缓冲区中。

常用构造方法如下：

| 构造方法                          | 说明                             |
| --------------------------------- | -------------------------------- |
| `ByteArrayOutputStream()`         | 创建默认初始容量的字节数组输出流 |
| `ByteArrayOutputStream(int size)` | 创建指定初始容量的字节数组输出流 |

常用方法如下：

| 方法                                     | 说明                         |
| ---------------------------------------- | ---------------------------- |
| `void write(int b)`                      | 写入一个字节                 |
| `void write(byte[] b, int off, int len)` | 写入字节数组中的一部分       |
| `byte[] toByteArray()`                   | 获取当前写入的数据副本       |
| `String toString()`                      | 将缓冲区内容转换为字符串     |
| `int size()`                             | 返回当前已写入的字节数       |
| `void reset()`                           | 清空缓冲区内容，重新开始写   |
| `void close()`                           | 关闭流，但对该类没有实际影响 |

`ByteArrayOutputStream` 的内部缓冲区会随着写入数据增多自动扩容，因此使用者通常不需要手动准备 `byte[]` 数组。

> 注意：`toByteArray()` 返回的是内部数据的一份副本，而不是直接暴露内部缓冲数组。这样可以避免外部代码直接修改流内部的数据结构。

#### ByteArrayOutputStream 的基本使用

`ByteArrayOutputStream` 可以把一段字节数据写入内存，并最终转换成 `byte[]`。

```java
import java.io.ByteArrayOutputStream;
import java.nio.charset.StandardCharsets;
import java.util.Arrays;

public class ByteArrayOutputStreamDemo {
    public static void main(String[] args) {
        ByteArrayOutputStream out = new ByteArrayOutputStream();

        out.write(97);
        out.write(98);
        out.write(99);

        byte[] data = "你好".getBytes(StandardCharsets.UTF_8);
        out.write(data, 0, data.length);

        byte[] result = out.toByteArray();

        System.out.println(Arrays.toString(result));
        System.out.println(new String(result, StandardCharsets.UTF_8));
    }
}
```

这段代码中，`97`、`98`、`99` 分别对应字符 `a`、`b`、`c`。后续写入的 `"你好"` 会按照 `UTF-8` 编码转换成字节，再进入内存缓冲区。

> 结论：`ByteArrayOutputStream` 常用于把程序运行中的数据临时收集到内存中，最后统一得到一个 `byte[]`。

### ByteArrayInputStream 类

`ByteArrayInputStream` 是字节数组输入流。它会把一个已有的 `byte[]` 数组包装成输入流，使程序可以像读取普通输入流一样，从该数组中按顺序读取字节。

常用构造方法如下：

| 构造方法                                                   | 说明                         |
| ---------------------------------------------------------- | ---------------------------- |
| `ByteArrayInputStream(byte[] buf)`                         | 使用整个字节数组创建输入流   |
| `ByteArrayInputStream(byte[] buf, int offset, int length)` | 使用数组中指定范围创建输入流 |

常用方法如下：

| 方法                                   | 说明                            |
| -------------------------------------- | ------------------------------- |
| `int read()`                           | 一次读取一个字节，读完返回 `-1` |
| `int read(byte[] b, int off, int len)` | 读取多个字节到指定数组          |
| `long skip(long n)`                    | 跳过指定数量的字节              |
| `int available()`                      | 返回剩余可读字节数              |
| `void mark(int readAheadLimit)`        | 标记当前位置                    |
| `void reset()`                         | 回到上一次标记的位置            |
| `boolean markSupported()`              | 判断是否支持标记功能            |
| `void close()`                         | 关闭流，但对该类没有实际影响    |

`ByteArrayInputStream` 的数据源已经在内存中，因此读取过程不会访问磁盘。

#### ByteArrayInputStream 的基本使用

```java
import java.io.ByteArrayInputStream;
import java.nio.charset.StandardCharsets;

public class ByteArrayInputStreamDemo {
    public static void main(String[] args) {
        byte[] data = "hello".getBytes(StandardCharsets.UTF_8);

        ByteArrayInputStream in = new ByteArrayInputStream(data);

        int value;
        while ((value = in.read()) != -1) {
            System.out.print((char) value);
        }
    }
}
```

执行结果为：

```text
hello
```

这段代码中，`ByteArrayInputStream` 并没有读取文件，而是从内存中的 `byte[] data` 中逐个读取字节。

> 结论：`ByteArrayInputStream` 的作用是把内存中的 `byte[]` 包装成输入流，从而让已有的流式读取代码可以直接复用。

### close() 方法无实际关闭效果

`ByteArrayOutputStream` 和 `ByteArrayInputStream` 操作的是内存数组，不占用文件句柄、网络连接等外部系统资源。因此，它们的 `close()` 方法没有实际关闭效果。

例如，`ByteArrayOutputStream` 的 `close()` 方法是空实现：

```java
@Override
public void close() throws IOException {
}
```

这意味着即使调用了 `close()`，之后仍然可以继续调用 `write()`、`toByteArray()` 等方法。

```java
import java.io.ByteArrayOutputStream;

public class ByteArrayCloseDemo {
    public static void main(String[] args) throws Exception {
        ByteArrayOutputStream out = new ByteArrayOutputStream();

        out.write(97);
        out.close();

        // close() 对 ByteArrayOutputStream 没有实际影响，仍然可以继续写
        out.write(98);

        System.out.println(new String(out.toByteArray()));
    }
}
```

输出结果为：

```text
ab
```

> 注意：虽然字节数组流的 `close()` 没有实际影响，但如果外层包装了对象流、数据流、缓冲流等处理流，仍然应当按规范关闭或刷新最外层处理流。

### 与处理流配合使用

字节数组流本身只能按字节读写。如果需要按基本数据类型、字符串或对象读写，可以在字节数组流外层包装数据流或对象流。

例如，使用对象流把不同类型的数据写入内存字节数组：

```java
import java.io.ByteArrayOutputStream;
import java.io.ObjectOutputStream;
import java.util.Arrays;
import java.util.Date;

public class ObjectToByteArrayDemo {
    public static void main(String[] args) {
        try {
            ByteArrayOutputStream byteOut = new ByteArrayOutputStream();
            ObjectOutputStream objectOut = new ObjectOutputStream(byteOut);

            objectOut.writeInt(100);
            objectOut.writeDouble(99.5);
            objectOut.writeBoolean(true);
            objectOut.writeUTF("hello");
            objectOut.writeObject(new Date());

            // 获取 byte[] 之前必须刷新外层对象流，确保数据已经写入底层字节数组流
            objectOut.flush();

            byte[] data = byteOut.toByteArray();

            System.out.println(Arrays.toString(data));

            objectOut.close();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这段代码的包装关系如下：

```text
程序
  ↓
ObjectOutputStream
  ↓
ByteArrayOutputStream
  ↓
内存 byte[] 缓冲区
```

执行过程如下：

1. `ByteArrayOutputStream` 在内存中准备可扩容的字节数组缓冲区；
2. `ObjectOutputStream` 负责把基本类型、字符串和对象转换为对象流格式的字节数据；
3. 数据最终写入 `ByteArrayOutputStream` 的内部缓冲区；
4. 调用 `flush()` 后，再通过 `toByteArray()` 获取完整字节数组。

> 易错点：如果外层使用了 `ObjectOutputStream`、`BufferedOutputStream` 等处理流，在调用 `toByteArray()` 前应先调用外层流的 `flush()`。否则，部分数据可能还停留在外层缓冲区中，没有真正写入 `ByteArrayOutputStream`。

### 从 byte[] 中恢复数据

既然可以把数据写入 `byte[]`，也可以使用 `ByteArrayInputStream` 从 `byte[]` 中读取并恢复数据。

```java
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.util.Date;

public class ByteArrayReadBackDemo {
    public static void main(String[] args) {
        try {
            byte[] data = writeToByteArray();

            ByteArrayInputStream byteIn = new ByteArrayInputStream(data);
            ObjectInputStream objectIn = new ObjectInputStream(byteIn);

            int number = objectIn.readInt();
            double score = objectIn.readDouble();
            boolean flag = objectIn.readBoolean();
            String text = objectIn.readUTF();
            Date date = (Date) objectIn.readObject();

            System.out.println(number);
            System.out.println(score);
            System.out.println(flag);
            System.out.println(text);
            System.out.println(date);

            objectIn.close();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    private static byte[] writeToByteArray() throws Exception {
        ByteArrayOutputStream byteOut = new ByteArrayOutputStream();
        ObjectOutputStream objectOut = new ObjectOutputStream(byteOut);

        objectOut.writeInt(100);
        objectOut.writeDouble(99.5);
        objectOut.writeBoolean(true);
        objectOut.writeUTF("hello");
        objectOut.writeObject(new Date());

        objectOut.flush();

        return byteOut.toByteArray();
    }
}
```

读取时必须和写入时保持相同顺序。先写入 `int`，就必须先读取 `int`；先写入对象，就必须在对应位置使用 `readObject()` 读取。

> 结论：字节数组流和对象流组合使用时，本质上是在内存中完成一次“序列化成字节数组”和“从字节数组反序列化”的过程。

### 使用字节数组流实现深克隆

字节数组流经常可以配合对象流实现**深克隆**。基本思路是：先把对象序列化到内存中的 `byte[]`，再从这个 `byte[]` 中反序列化出一个新对象。

由于反序列化得到的是重新创建的对象，因此它与原对象不是同一个对象。如果对象内部的引用类型属性也参与了序列化，那么这些引用属性也会被复制出新的对象，从而实现深克隆效果。

```java
import java.io.*;

public class DeepCopyDemo {
    public static void main(String[] args) throws Exception {
        Address address = new Address("天津", "南开");
        Person oldPerson = new Person("张三", 20, address);

        Person newPerson = deepCopy(oldPerson);

        newPerson.getAddress().setCity("南京");

        System.out.println(newPerson);
        System.out.println(oldPerson);
    }

    public static <T> T deepCopy(T obj) throws Exception {
        ByteArrayOutputStream byteOut = new ByteArrayOutputStream();
        ObjectOutputStream objectOut = new ObjectOutputStream(byteOut);

        objectOut.writeObject(obj);
        objectOut.flush();

        byte[] data = byteOut.toByteArray();

        ByteArrayInputStream byteIn = new ByteArrayInputStream(data);
        ObjectInputStream objectIn = new ObjectInputStream(byteIn);

        return (T) objectIn.readObject();
    }
}

class Person implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
    private Address address;

    public Person(String name, int age, Address address) {
        this.name = name;
        this.age = age;
        this.address = address;
    }

    public Address getAddress() {
        return address;
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + ", address=" + address + "}";
    }
}

class Address implements Serializable {
    private static final long serialVersionUID = 1L;

    private String city;
    private String street;

    public Address(String city, String street) {
        this.city = city;
        this.street = street;
    }

    public void setCity(String city) {
        this.city = city;
    }

    @Override
    public String toString() {
        return "Address{city='" + city + "', street='" + street + "'}";
    }
}
```

如果 `newPerson.getAddress().setCity("南京")` 只影响克隆对象中的地址，而不影响 `oldPerson` 中的地址，就说明 `Address` 对象也被复制了一份。

> 注意：使用对象流实现深克隆时，对象所属类以及对象内部的引用类型属性所属类都必须实现 `Serializable`。否则序列化过程中会抛出 `NotSerializableException`。

### 字符数组流补充

与字节数组流对应，Java 中也提供了面向字符数据的内存流：

| 类             | 说明                       |
| -------------- | -------------------------- |
| `StringReader` | 从字符串中读取字符         |
| `StringWriter` | 将字符写入内部字符串缓冲区 |

不过，在实际开发中，`StringReader` 和 `StringWriter` 的使用频率相对较低。对于字符串拼接和字符内容构建，更多时候会直接使用 `StringBuilder` 或 `StringBuffer`。

> 补充：如果处理目标是字节数据，使用 `ByteArrayInputStream` 和 `ByteArrayOutputStream`；如果处理目标是字符文本，也可以考虑 `StringReader` 和 `StringWriter`。

## 操作配置文件

配置文件用于把程序中可能变化的数据从 Java 代码中抽离出来，使程序在不修改源码、不重新编译的情况下调整运行参数。Java 中常见的配置文件是 `.properties` 文件，它本质上是普通文本文件，通常采用 `key=value` 的形式保存简单配置项。

例如，数据库连接信息可以写成：

```properties
# 数据库连接配置
driver=com.mysql.cj.jdbc.Driver
url=jdbc:mysql://192.168.137.111:3306/test
username=admin
password=admin123
```

其中，`#` 开头的内容是注释，不会被当作配置项读取；`driver`、`url`、`username`、`password` 是键，等号右侧是对应的值。

> 结论：配置文件的核心价值是提高程序灵活性，把容易变化的数据交给配置文件管理，而不是直接写死在 Java 代码中。

### properties 配置文件的基本规则

`.properties` 文件通常遵循以下规则：

1. 每一行通常表示一个配置项；
2. 配置项一般写成 `key=value` 形式；
3. `key` 用于标识配置名称，`value` 用于保存配置值；
4. `#` 开头的行表示注释；
5. 空行通常会被忽略；
6. 如果出现相同的 `key`，后读取到的有效配置会覆盖前面的配置；
7. 配置项的键和值本质上都是字符串。

例如：

```properties
# 用户登录配置
username=root
password=123456

# 如果后面再次出现相同 key，后面的值会覆盖前面的值
password=admin123
```

读取后，`password` 对应的值是 `admin123`。

> 注意：`.properties` 后缀不是语法强制要求，但属于约定俗成的规范。实际开发中应使用 `.properties` 后缀，便于识别和维护。

### 配置文件的使用意义

如果不使用配置文件，程序中的动态信息可能会直接写在 Java 代码中：

```java
String username = "admin";
String password = "admin123";
```

这种写法的问题是：一旦用户名、密码、数据库地址等信息变化，就必须修改源码并重新编译程序。

使用配置文件后，Java 代码只负责读取配置：

```properties
username=admin
password=admin123
```

当配置发生变化时，只需要修改 `.properties` 文件即可，程序代码无需改动。

常见适合放入配置文件的数据包括：

| 配置内容     | 示例                                   |
| ------------ | -------------------------------------- |
| 数据库驱动   | `driver=com.mysql.cj.jdbc.Driver`      |
| 数据库地址   | `url=jdbc:mysql://localhost:3306/test` |
| 用户名和密码 | `username=root`、`password=123456`     |
| 类的全限定名 | `className=com.example.UserService`    |
| 文件路径     | `uploadPath=D:/upload`                 |

> 结论：配置文件适合保存简单、经常变化、需要在程序外部调整的字符串配置项。

### Properties 类

Java 提供了 `java.util.Properties` 类专门操作属性配置文件。`Properties` 是 `Hashtable` 的子类，本质上也是一种键值对集合，但在实际使用中，键和值通常都使用字符串。

常用方法如下：

| 方法                                                  | 说明                                 |
| ----------------------------------------------------- | ------------------------------------ |
| `Object setProperty(String key, String value)`        | 添加或修改属性                       |
| `String getProperty(String key)`                      | 根据键获取属性值                     |
| `String getProperty(String key, String defaultValue)` | 根据键获取属性值，找不到时返回默认值 |
| `Set<String> stringPropertyNames()`                   | 获取所有字符串类型的键               |
| `void load(Reader reader)`                            | 通过字符输入流加载配置文件           |
| `void load(InputStream inStream)`                     | 通过字节输入流加载配置文件           |
| `void store(Writer writer, String comments)`          | 通过字符输出流保存配置               |
| `void store(OutputStream out, String comments)`       | 通过字节输出流保存配置               |

> 结论：`Properties` 既是集合，又可以配合 IO 流读取和保存 `.properties` 配置文件。

#### 使用 Properties 读取配置文件

读取配置文件的一般步骤如下：

1. 创建 `Properties` 对象；
2. 创建输入流，连接 `.properties` 配置文件；
3. 调用 `load()` 方法把配置文件内容加载到 `Properties` 集合中；
4. 调用 `getProperty()` 根据键获取值；
5. 关闭输入流。

例如，配置文件 `jdbc.properties` 内容如下：

```properties
driver=com.mysql.cj.jdbc.Driver
url=jdbc:mysql://192.168.137.111:3306/test
username=admin
password=admin123
```

读取代码如下：

```java
import java.io.FileReader;
import java.util.Properties;

public class PropertiesReadDemo {
    public static void main(String[] args) {
        Properties properties = new Properties();

        try (FileReader reader = new FileReader("jdbc.properties")) {
            // 将配置文件中的 key=value 加载到 Properties 集合中
            properties.load(reader);

            String driver = properties.getProperty("driver");
            String url = properties.getProperty("url");
            String username = properties.getProperty("username");
            String password = properties.getProperty("password");

            System.out.println(driver);
            System.out.println(url);
            System.out.println(username);
            System.out.println(password);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

`load(reader)` 执行后，配置文件中的每个有效配置项都会被加载到 `Properties` 集合中。之后就可以像操作键值对集合一样，根据 `key` 获取对应的 `value`。

> 易错点：`getProperty("username")` 中的键名必须和配置文件中的键完全对应。键名写错时，返回值通常是 `null`。

#### 遍历 Properties 中的所有配置

有时程序并不知道配置文件中有哪些键，此时可以使用 `stringPropertyNames()` 获取所有键，再逐个读取对应的值。

```java
import java.io.FileReader;
import java.util.Properties;
import java.util.Set;

public class PropertiesLoopDemo {
    public static void main(String[] args) {
        Properties properties = new Properties();

        try (FileReader reader = new FileReader("jdbc.properties")) {
            properties.load(reader);

            Set<String> names = properties.stringPropertyNames();

            for (String name : names) {
                String value = properties.getProperty(name);
                System.out.println(name + " = " + value);
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这种方式适合查看配置文件中的全部内容，或者在配置项数量不固定时动态读取。

#### 使用 Properties 写入配置文件

`Properties` 不仅可以读取配置文件，也可以把集合中的键值对保存到配置文件中。

写入配置文件的一般步骤如下：

1. 创建 `Properties` 对象；
2. 调用 `setProperty()` 添加键值对；
3. 创建输出流，连接目标配置文件；
4. 调用 `store()` 方法保存配置；
5. 关闭输出流。

```java
import java.io.FileWriter;
import java.util.Properties;

public class PropertiesStoreDemo {
    public static void main(String[] args) {
        Properties properties = new Properties();

        properties.setProperty("driver", "com.mysql.cj.jdbc.Driver");
        properties.setProperty("url", "jdbc:mysql://localhost:3306/test");
        properties.setProperty("username", "root");
        properties.setProperty("password", "123456");

        try (FileWriter writer = new FileWriter("jdbc.properties")) {
            // 第二个参数会作为注释写入配置文件
            properties.store(writer, "database config");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

生成的配置文件中会包含键值对，同时还可能包含由 `store()` 自动写入的注释和时间信息。

> 注意：`store()` 适合把程序中的配置持久化到文件。如果只是读取已有配置文件，使用 `load()` 即可。

#### load(Reader) 与 load(InputStream) 的区别

`Properties` 提供了两种加载配置文件的方式：

| 方法                         | 输入类型   | 特点                              |
| ---------------------------- | ---------- | --------------------------------- |
| `load(Reader reader)`        | 字符输入流 | 字符编码由 `Reader` 决定          |
| `load(InputStream inStream)` | 字节输入流 | 按 `.properties` 传统字节规则读取 |

在处理中文配置时，更推荐明确使用字符流并指定合适编码。例如：

```java
import java.io.FileInputStream;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;
import java.util.Properties;

public class PropertiesUtf8Demo {
    public static void main(String[] args) {
        Properties properties = new Properties();

        try (
                InputStreamReader reader = new InputStreamReader(
                        new FileInputStream("app.properties"),
                        StandardCharsets.UTF_8
                )
        ) {
            properties.load(reader);

            System.out.println(properties.getProperty("appName"));
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这样可以明确告诉程序：按照 `UTF-8` 读取配置文件。

> 结论：配置文件涉及中文时，应统一文件编码，并在读取时明确字符集，避免不同环境下出现乱码问题。

### 配置文件编码注意事项

配置文件本质上是文本文件，因此也存在字符编码问题。实际开发中，建议统一使用 `UTF-8` 保存 `.properties` 文件。

在 IDEA 中，可以检查配置文件编码设置：

```text
Settings / Preferences
  → Editor
  → File Encodings
  → Properties Files
```

建议将 Properties 文件的默认编码设置为 `UTF-8`，并保持项目中配置文件编码一致。

> 注意：编码不一致时，配置文件中的中文值可能读取成乱码。配置文件读取错误并不一定是 `Properties` 的问题，也可能是文件编码与读取编码不一致。

### ResourceBundle 资源绑定器

`ResourceBundle` 是 `java.util` 包下提供的资源绑定器，常用于读取类路径下的 `.properties` 配置文件。与 `Properties` 相比，`ResourceBundle` 使用更简单，不需要手动创建输入流，也不需要手动关闭流。

基本用法如下：

```java
import java.util.ResourceBundle;

public class ResourceBundleDemo {
    public static void main(String[] args) {
        ResourceBundle bundle = ResourceBundle.getBundle("db");

        String driver = bundle.getString("driver");
        String url = bundle.getString("url");
        String username = bundle.getString("username");
        String password = bundle.getString("password");

        System.out.println(driver);
        System.out.println(url);
        System.out.println(username);
        System.out.println(password);
    }
}
```

如果配置文件放在包路径下，例如：

```text
src/com/example/config/db.properties
```

绑定时应使用包名点语法，并省略 `.properties` 后缀：

```java
ResourceBundle bundle = ResourceBundle.getBundle("com.example.config.db");
```

> 易错点：`ResourceBundle.getBundle()` 绑定的是基础名，不写 `.properties` 后缀。写成 `db.properties` 反而是错误用法。

#### ResourceBundle 的特点

`ResourceBundle` 读取配置文件时有几个特点：

1. 配置文件通常放在类路径下；
2. 只能方便地读取 `.properties` 这类资源文件；
3. 绑定时省略 `.properties` 后缀；
4. 不需要手动创建输入流；
5. 不需要手动关闭流；
6. 只能读取配置，不适合写入配置文件。

例如：

```java
ResourceBundle bundle = ResourceBundle.getBundle("com.jkweilai.javase.chapter10.db");
```

这表示从类路径中查找：

```text
com/jkweilai/javase/chapter10/db.properties
```

并加载其中的配置项。

> 结论：如果配置文件在类路径中，并且只需要读取配置，`ResourceBundle` 更简单；如果配置文件路径不固定，或需要写入配置，使用 `Properties` 更灵活。

#### Properties 与 ResourceBundle 的区别

| 对比项             | `Properties`     | `ResourceBundle`   |
| ------------------ | ---------------- | ------------------ |
| 所属包             | `java.util`      | `java.util`        |
| 是否需要手动创建流 | 需要             | 不需要             |
| 是否需要关闭流     | 需要             | 不需要             |
| 配置文件位置       | 可指定任意路径   | 通常要求在类路径下 |
| 是否支持写入       | 支持 `store()`   | 不适合写入         |
| 读取方式           | `getProperty()`  | `getString()`      |
| 适用场景           | 灵活读写配置文件 | 简单读取类路径资源 |

> 结论：`Properties` 更灵活，适合读写配置文件；`ResourceBundle` 更便捷，适合读取类路径下的资源配置。

### 配置文件操作的典型流程

实际开发中，配置文件常用于保存数据库连接信息。例如：

```properties
driver=com.mysql.cj.jdbc.Driver
url=jdbc:mysql://192.168.137.111:3306/test
username=admin
password=admin123
```

程序启动时读取配置：

```java
import java.io.FileReader;
import java.util.Properties;

public class JdbcConfigDemo {
    public static void main(String[] args) {
        Properties properties = new Properties();

        try (FileReader reader = new FileReader("jdbc.properties")) {
            properties.load(reader);

            String driver = properties.getProperty("driver");
            String url = properties.getProperty("url");
            String username = properties.getProperty("username");
            String password = properties.getProperty("password");

            System.out.println("driver = " + driver);
            System.out.println("url = " + url);
            System.out.println("username = " + username);
            System.out.println("password = " + password);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

这样，数据库连接参数发生变化时，只需要修改 `jdbc.properties` 文件，不需要修改 Java 代码。

## 装饰器模式

装饰器模式（Decorator Pattern）是一种结构型设计模式，用于在**不修改原有类代码、不通过大量继承创建子类**的前提下，动态地给对象增加新的功能。它的核心思想是：让装饰器和被装饰对象实现同一个接口，并在装饰器内部持有被装饰对象，从而在调用原有功能的基础上附加新功能。

> 结论：装饰器模式解决的是“对象功能需要灵活增强和自由组合”的问题。

### 问题背景：继承带来的类爆炸

假设有一组基础动物，例如猫、狗、鸟；又有一组可附加能力，例如飞行、游泳、爬树。若使用继承来实现能力组合，就需要为每一种动物和每一种能力组合创建不同的子类。

例如：

```java
class Cat {}
class FlyingCat extends Cat {}
class SwimmingCat extends Cat {}
class FlyingSwimmingCat extends Cat {}

class Dog {}
class FlyingDog extends Dog {}
class SwimmingDog extends Dog {}
class FlyingSwimmingDog extends Dog {}
```

当动物种类和能力数量增加时，类的数量会迅速膨胀。3 种动物、3 种能力，理论上就可能产生大量组合类。如果后续再新增“隐身能力”“喷火能力”等功能，类的数量会继续增长，维护成本也会显著增加。

这种方式的主要问题有两个：

1. **类爆炸**：每一种组合都可能需要一个新类；
2. **耦合度高**：能力被写死在子类中，运行时很难灵活增删。

> 易错点：继承可以实现功能扩展，但继承更适合表达稳定的“是什么”关系，不适合表达运行时可变化、可组合的能力。

### 装饰器模式的解决思路

装饰器模式不再为每种能力组合创建子类，而是把能力设计成一个个可以包裹对象的装饰器。

基本思路如下：

```text
基础对象：猫
装饰器：飞行能力
装饰器：游泳能力
装饰器：爬树能力
```

当需要一只会飞的猫时：

```java
Animal animal = new FlyingAbilityDecorator(new Cat());
```

当需要一只会游泳、会爬树、会飞的猫时：

```java
Animal animal = new FlyingAbilityDecorator(
        new ClimbingAbilityDecorator(
                new SwimmingAbilityDecorator(new Cat())
        )
);
```

这类写法本质上是一层包一层。每一层装饰器都实现同一个接口，因此装饰后的对象仍然可以当作原接口类型使用。

> 结论：装饰器模式通过“对象包装对象”的方式，把功能扩展从继承关系转为组合关系。

### 装饰器模式的四个角色

装饰器模式通常包含四类角色：

| 角色                | 含义                       | 示例                                                         |
| ------------------- | -------------------------- | ------------------------------------------------------------ |
| `Component`         | 抽象组件，定义统一接口     | `Animal`                                                     |
| `ConcreteComponent` | 具体组件，被装饰的基础对象 | `Cat`、`Dog`、`Bird`                                         |
| `Decorator`         | 抽象装饰器，持有组件对象   | `AbilityDecorator`                                           |
| `ConcreteDecorator` | 具体装饰器，增加具体功能   | `FlyingAbilityDecorator`、`SwimmingAbilityDecorator`、`ClimbingAbilityDecorator` |

这四个角色的关系可以概括为：

```text
Animal 接口
  ↑
  ├── Cat / Dog / Bird
  ↑
  └── AbilityDecorator
          ↑
          ├── FlyingAbilityDecorator
          ├── SwimmingAbilityDecorator
          └── ClimbingAbilityDecorator
```

其中，具体动物和装饰器都实现 `Animal` 接口，因此无论是原始动物，还是被装饰后的动物，都可以统一用 `Animal` 类型接收。

### 定义统一接口

装饰器模式的第一步，是定义一个统一接口。基础对象和装饰器都必须实现这个接口，这样装饰后的对象才能保持和原对象相同的使用方式。

```java
package decorator;

/**
 * 动物接口：基础动物和能力装饰器都要实现该接口。
 */
public interface Animal {

    /**
     * 返回当前动物及其能力描述。
     */
    String describe();

    /**
     * 返回当前动物的速度。
     */
    int getSpeed();
}
```

`Animal` 接口中定义了两个行为：`describe()` 用于描述动物，`getSpeed()` 用于获取速度。后续无论是猫、狗、鸟，还是飞行能力、游泳能力、爬树能力，都围绕这两个行为进行扩展。

> 结论：统一接口保证了装饰前后对象类型一致，这是装饰器模式能够透明替换的基础。

### 定义基础对象

基础对象是最原始、未被装饰的对象。它只提供自身的基础功能。

```java
package decorator;

public class Cat implements Animal {
    @Override
    public String describe() {
        return "猫";
    }

    @Override
    public int getSpeed() {
        return 10;
    }
}
package decorator;

public class Dog implements Animal {
    @Override
    public String describe() {
        return "狗";
    }

    @Override
    public int getSpeed() {
        return 20;
    }
}
package decorator;

public class Bird implements Animal {
    @Override
    public String describe() {
        return "鸟";
    }

    @Override
    public int getSpeed() {
        return 30;
    }
}
```

这些类都直接实现 `Animal` 接口，表示它们是可以被装饰的基础对象。它们本身不关心飞行、游泳、爬树等扩展能力。

> 结论：具体组件只负责基础功能，扩展能力交给装饰器处理。

### 定义抽象装饰器

抽象装饰器也要实现 `Animal` 接口，并且在内部持有一个 `Animal` 类型的成员变量。这个成员变量就是被装饰的对象。

```java
package decorator;

/**
 * 抽象装饰器：所有能力装饰器的父类。
 *
 * 装饰器本身也是 Animal，因此装饰后的对象仍然可以作为 Animal 使用。
 */
public abstract class AbilityDecorator implements Animal {

    // 被装饰的动物对象
    private Animal decoratedAnimal;

    public AbilityDecorator(Animal decoratedAnimal) {
        this.decoratedAnimal = decoratedAnimal;
    }

    @Override
    public String describe() {
        // 默认行为：委托给被装饰对象
        return decoratedAnimal.describe();
    }

    @Override
    public int getSpeed() {
        // 默认行为：委托给被装饰对象
        return decoratedAnimal.getSpeed();
    }
}
```

抽象装饰器中的两个方法默认只是调用被装饰对象的原有功能，并不直接增加新能力。具体增强逻辑由子类完成。

这里最关键的是：

```java
private Animal decoratedAnimal;
```

这说明装饰器和被装饰对象之间不是继承关系，而是**关联关系**，即“装饰器中有一个被装饰对象”。

> 结论：装饰器模式强调组合优于继承。装饰器通过 `has-a` 关系持有被装饰对象，而不是通过 `is-a` 关系创建大量子类。

### 定义具体装饰器

具体装饰器负责在原有功能基础上增加新的能力。由于抽象装饰器已经把基础行为委托给被装饰对象，具体装饰器只需要重写需要增强的方法即可。

#### 飞行能力装饰器

```java
package decorator;

/**
 * 具体装饰器：给动物增加飞行能力。
 */
public class FlyingAbilityDecorator extends AbilityDecorator {

    public FlyingAbilityDecorator(Animal decoratedAnimal) {
        super(decoratedAnimal);
    }

    @Override
    public String describe() {
        return super.describe() + " + 飞行能力";
    }

    @Override
    public int getSpeed() {
        return super.getSpeed() + 10;
    }
}
```

`super.describe()` 会先获取被装饰对象原本的描述，然后在后面追加“飞行能力”。`super.getSpeed()` 会先获取原速度，再增加飞行带来的速度加成。

#### 游泳能力装饰器

```java
package decorator;

/**
 * 具体装饰器：给动物增加游泳能力。
 */
public class SwimmingAbilityDecorator extends AbilityDecorator {

    public SwimmingAbilityDecorator(Animal decoratedAnimal) {
        super(decoratedAnimal);
    }

    @Override
    public String describe() {
        return super.describe() + " + 游泳能力";
    }

    @Override
    public int getSpeed() {
        return super.getSpeed() + 5;
    }
}
```

#### 爬树能力装饰器

```java
package decorator;

/**
 * 具体装饰器：给动物增加爬树能力。
 */
public class ClimbingAbilityDecorator extends AbilityDecorator {

    public ClimbingAbilityDecorator(Animal decoratedAnimal) {
        super(decoratedAnimal);
    }

    @Override
    public String describe() {
        return super.describe() + " + 爬树能力";
    }

    @Override
    public int getSpeed() {
        return super.getSpeed() + 3;
    }
}
```

每个具体装饰器只负责一个功能。新增能力时，只需要新增一个装饰器类，不需要修改已有动物类，也不需要修改已有装饰器类。

> 结论：一个装饰器只负责一个增强点，多个增强点通过多层包装自由组合。

### 装饰器的组合使用

客户端可以根据需要自由组合装饰器。

```java
package decorator;

public class Test {
    public static void main(String[] args) {
        Animal cat = new FlyingAbilityDecorator(
                new ClimbingAbilityDecorator(
                        new SwimmingAbilityDecorator(new Cat())
                )
        );

        System.out.println(cat.describe() + " | 速度：" + cat.getSpeed());

        Animal basicCat = new Cat();
        System.out.println(basicCat.describe() + " | 速度：" + basicCat.getSpeed());
    }
}
```

执行过程可以理解为：

1. `new Cat()` 创建一只基础猫；
2. `new SwimmingAbilityDecorator(new Cat())` 给猫增加游泳能力；
3. `new ClimbingAbilityDecorator(...)` 在已有基础上继续增加爬树能力；
4. `new FlyingAbilityDecorator(...)` 在已有基础上继续增加飞行能力；
5. 最终得到的对象仍然是 `Animal` 类型。

输出效果类似：

```text
猫 + 游泳能力 + 爬树能力 + 飞行能力 | 速度：28
猫 | 速度：10
```

> 注意：装饰器的包装顺序会影响 `describe()` 的拼接顺序，也可能影响业务计算结果。因此在设计装饰器时，要判断多个装饰器之间是否允许任意换序。

### 装饰器模式的执行过程

以如下代码为例：

```java
Animal cat = new FlyingAbilityDecorator(
        new ClimbingAbilityDecorator(
                new SwimmingAbilityDecorator(new Cat())
        )
);
```

当调用：

```java
cat.describe();
```

实际调用链如下：

1. 最外层 `FlyingAbilityDecorator.describe()` 被调用；
2. 它先调用 `super.describe()`；
3. `super.describe()` 继续委托给内部的 `ClimbingAbilityDecorator`；
4. `ClimbingAbilityDecorator` 再委托给内部的 `SwimmingAbilityDecorator`；
5. `SwimmingAbilityDecorator` 再委托给内部的 `Cat`；
6. `Cat.describe()` 返回 `"猫"`；
7. 每一层装饰器依次追加自己的能力描述；
8. 最终返回完整结果。

调用链可以表示为：

```text
FlyingAbilityDecorator
  ↓
ClimbingAbilityDecorator
  ↓
SwimmingAbilityDecorator
  ↓
Cat
```

返回结果则是从内向外逐层增强：

```text
猫
→ 猫 + 游泳能力
→ 猫 + 游泳能力 + 爬树能力
→ 猫 + 游泳能力 + 爬树能力 + 飞行能力
```

> 结论：装饰器模式的执行过程是“调用从外到内，增强从内到外”。

### 装饰器模式的核心特点

装饰器模式具有三个关键特点。

| 特点   | 说明                                               |
| ------ | -------------------------------------------------- |
| 透明性 | 装饰前后都实现同一个接口，使用者可以统一用接口接收 |
| 嵌套性 | 装饰器可以包装基础对象，也可以包装另一个装饰器     |
| 灵活性 | 可以在运行时决定是否添加某个功能，以及添加哪些功能 |

透明性体现在：

```java
Animal animal = new Cat();
Animal flyingCat = new FlyingAbilityDecorator(animal);
```

无论是普通猫还是会飞的猫，都可以使用 `Animal` 类型接收。

嵌套性体现在：

```java
Animal superCat = new FlyingAbilityDecorator(
        new SwimmingAbilityDecorator(
                new ClimbingAbilityDecorator(new Cat())
        )
);
```

装饰器可以一层套一层，实现多个功能的叠加。

灵活性体现在：

```java
Animal cat = new Cat();

cat = new FlyingAbilityDecorator(cat);
cat = new SwimmingAbilityDecorator(cat);
```

对象可以在运行过程中逐步获得新能力。

### 为什么不直接实现多个接口

功能扩展也可以通过接口实现，例如定义 `Flyable`、`Swimmable`、`Climbable`：

```java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

interface Climbable {
    void climb();
}
```

然后让某个类直接实现多个接口：

```java
class SuperCat implements Flyable, Swimmable, Climbable {
    @Override
    public void fly() {
        System.out.println("猫在飞");
    }

    @Override
    public void swim() {
        System.out.println("猫在游泳");
    }

    @Override
    public void climb() {
        System.out.println("猫在爬树");
    }
}
```

这种方式不是错误的，但它更适合表达对象稳定的能力或类型特征。如果对象的能力需要在运行时动态增加、减少或组合，直接实现接口就不够灵活。

例如，一只普通猫在程序开始时不会飞：

```java
Animal cat = new Cat();
```

如果它在运行中获得“飞行能力”，使用装饰器可以直接包装：

```java
cat = new FlyingAbilityDecorator(cat);
```

而直接实现接口的方式无法让一个已经创建好的 `Cat` 对象在运行时突然变成 `Flyable`。除非重新创建一个新类型对象，或者提前设计大量组合类。

> 结论：接口实现适合描述稳定能力，装饰器适合描述可动态附加的能力。

### 装饰器模式与 IO 流

Java IO 中大量使用了装饰器思想。节点流提供最基础的读写能力，处理流在外层包装节点流，逐步增强功能。

例如：

```java
BufferedReader reader = new BufferedReader(
        new InputStreamReader(
                new FileInputStream("data.txt")
        )
);
```

这段代码中：

1. `FileInputStream` 负责最基础的字节读取；
2. `InputStreamReader` 在外层增加字节到字符的转换能力；
3. `BufferedReader` 再增加缓冲能力和按行读取能力。

包装关系如下：

```text
BufferedReader
  ↓
InputStreamReader
  ↓
FileInputStream
```

这和动物能力装饰非常相似：

```text
FlyingAbilityDecorator
  ↓
SwimmingAbilityDecorator
  ↓
Cat
```

二者都体现了同一种思想：**不改变原对象，通过外层包装逐步增强功能**。

> 结论：理解装饰器模式后，再看 Java IO 中的缓冲流、转换流、对象流，会更容易理解“为什么流可以一层套一层”。

### 装饰器模式的适用场景

适合使用装饰器模式的场景包括：

1. 需要在不修改原类代码的情况下增强对象功能；
2. 功能可以自由组合；
3. 使用继承会导致大量子类；
4. 功能需要在运行时动态添加；
5. 多个增强功能可以一层一层叠加；
6. 希望基础功能和增强功能解耦。

常见应用包括：

| 场景         | 示例                             |
| ------------ | -------------------------------- |
| Java IO 流   | 缓冲流、转换流、对象流包装节点流 |
| 游戏角色能力 | 装备、技能、状态叠加             |
| 文本处理     | 加密、压缩、缓存、格式化         |
| Web 请求处理 | 请求包装、响应包装               |
| 日志增强     | 时间戳、级别、颜色、输出位置增强 |

> 结论：只要遇到“原对象不变，但功能需要灵活叠加”的需求，就可以考虑装饰器模式。
