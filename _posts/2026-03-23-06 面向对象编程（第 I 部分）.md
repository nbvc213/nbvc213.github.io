## 面向对象概述

**面向对象**是一种组织和理解软件系统的思想。学习它之前，先要明确：软件开发中常见的两种基本思路是**面向过程**和**面向对象**。前者强调“按步骤完成事情”，后者强调“由哪些对象协作完成事情”。

### 软件开发方法

通常的软件开发方法主要包括两种：**面向过程**（Procedure Oriented，PO）与**面向对象**（Object Oriented，OO）。

它们都能解决问题，但**关注点不同**：

- **面向过程**：关注“做事的步骤”；
- **面向对象**：关注“谁来做这件事”。

这种区别看起来只是思考方式不同，但在实际开发中，会直接影响程序的结构、扩展性和维护难度。

#### 面向过程

**面向过程**是一种以“过程”或“步骤”为中心的开发思想。它会先分析解决问题需要经过哪些步骤，再把这些步骤依次写出来，最后按顺序执行。

`Procedure Oriented` 可以直译为“面向过程”。这类思想在早期程序设计中非常常见，**C 语言**就是典型代表。

面向过程解决问题时，通常遵循这样的思路：

1. 先确定要完成什么功能；
2. 再把这个功能拆分成若干个具体步骤；
3. 然后用函数或语句把每一步实现出来；
4. 最后按照顺序调用这些步骤，完成整个任务。

例如，假设要开发一个“计算学生总成绩并判断是否及格”的程序，若采用面向过程的思路，往往会这样考虑：

1. 输入语文、数学、英语成绩；
2. 计算总分；
3. 计算平均分；
4. 判断是否及格；
5. 输出结果。

此时，程序关注的重点是：**先做什么，后做什么，每一步如何衔接**。

这种方式的优点是**直观、简单、容易上手**，尤其适合处理**步骤固定、流程清晰、规模较小**的问题。但它也有明显局限：当系统越来越复杂时，程序会越来越依赖一连串流程和函数；一旦需求变化，往往需要修改很多地方，代码之间也容易互相牵连。

#### 面向对象

**面向对象**是一种以“对象”为中心的开发思想。它不再优先思考“先写哪一步”，而是先分析：**这个系统中有哪些对象，每个对象负责什么行为，对象之间如何协作**。

`Object Oriented` 即“面向对象”。在这一思想下，程序更像是在描述一个由多个角色共同工作的系统。**Java、C#、Python** 等语言都广泛采用面向对象思想。

在面向对象领域，常见的三个缩写如下：

| 缩写    | 全称                        | 含义                                                       |
| ------- | --------------------------- | ---------------------------------------------------------- |
| **OOA** | Object Oriented Analysis    | **面向对象分析**，分析系统中有哪些对象、对象之间有什么关系 |
| **OOD** | Object Oriented Design      | **面向对象设计**，设计对象的职责、结构和协作方式           |
| **OOP** | Object Oriented Programming | **面向对象编程**，把前面的分析和设计真正落地为代码         |

面向对象解决问题时，通常遵循这样的思路：

1. 先确定系统中有哪些对象；
2. 再明确每个对象负责什么事情；
3. 然后让对象之间彼此协作；
4. 最终完成整个系统功能。

例如，假设要开发一个“图书借阅系统”，若采用面向对象的思路，就不会只盯着“借书步骤”，而会先看到系统中的几个核心对象：`读者`、`图书`、`管理员`、`借阅记录`。
 其中：

- `读者`对象可以发起借书、还书请求；
- `图书`对象需要记录是否在馆、是否已借出；
- `管理员`对象可以办理借阅和归还；
- `借阅记录`对象负责保存借书时间、归还时间等信息。

这样一来，程序的重点就不再只是“先执行 A，再执行 B”，而是变成：**哪个对象负责什么行为，哪些对象需要互相配合**。

之所以说面向对象更适合复杂系统，是因为现实世界本身就是由许多“对象”和“角色”构成的。人类在理解现实问题时，往往天然会从“参与者”出发，而不是只从“固定步骤”出发。因此，当系统变复杂时，面向对象通常更符合人的思维习惯。

#### 面向对象为什么更适合复杂开发

面向对象的一个重要优势是：**耦合度相对较低，扩展能力通常更强**。

所谓**耦合度低**，可以简单理解为：模块之间不要绑得太死。一个对象只负责自己的事情，别的对象只通过明确的方式来使用它。这样即使某一部分发生变化，也不至于把整个系统都牵扯进去。

例如，在一个“在线购物系统”中，可以把 `商品`、`购物车`、`订单`、`支付方式` 设计成不同对象。
 假设后期系统要新增“微信支付”功能，如果原来的支付逻辑是按对象独立设计的，那么通常只需要新增一个新的支付对象，或者扩展支付模块，而不必把订单、购物车、商品等大量代码全部重写。

这就是面向对象中常说的**扩展性较好**：系统中的某个部分需要变更时，往往可以只调整相关对象，而不必推翻整体结构。

> **补充：** 面向对象并不表示程序里完全没有“过程”。程序运行时仍然有执行流程，只是这种流程不再是整个系统唯一的组织核心，而是建立在“对象分工与协作”之上的。

#### 面向过程与面向对象的区别

| 对比项           | 面向过程                           | 面向对象                         |
| ---------------- | ---------------------------------- | -------------------------------- |
| **关注点**       | 做事的步骤                         | 参与完成任务的对象               |
| **核心思路**     | 先分析流程，再逐步实现             | 先分析对象，再组织协作           |
| **适合场景**     | 简单、固定、线性的流程             | 复杂、可扩展、角色较多的系统     |
| **程序组织方式** | 以函数、步骤为中心                 | 以对象、职责为中心               |
| **扩展性**       | 一般较弱，改动时容易牵一发而动全身 | 一般较强，便于局部修改和功能扩展 |
| **代表语言**     | C 语言                             | Java、C#、Python 等              |

### 面向对象三大特征

面向对象之所以能够更好地描述复杂系统，核心就在于它提供了三种重要机制：**封装**、**继承**、**多态**。这三者不是彼此孤立的概念，而是面向对象程序设计中组织代码、复用功能、增强扩展性的基础。

面向对象的三大特征包括：**封装**（Encapsulation）、**继承**（Inheritance）和**多态**（Polymorphism）。

现阶段先对这三个特征建立整体认识即可：

- **封装**：把对象的属性和方法组织在一起，并尽量隐藏内部细节，只对外暴露必要的使用方式。
- **继承**：让一个类在已有类的基础上继续扩展，复用原有内容。
- **多态**：同一种行为在不同对象上可以表现出不同效果。

## 类与对象

学习面向对象时，**类**和**对象**是最核心的两个概念。可以先抓住一句话：

> **结论：类是模板，对象是根据模板创建出来的具体个体。**

例如，现实中有很多“学生”，虽然每个学生具体情况不同，但他们通常都有一些共性，如姓名、年龄、性别，也都可能具有学习、吃饭、休息等行为。把这类共同特征提取出来，就可以形成一个“学生类”；而某一个具体的学生，则是这个类创建出的对象。

### 类

**类**是对一类事物共同特征的抽象描述，本质上是一个**模板**。

所谓“共同特征”，通常包括两部分：

- **状态**，即这个事物“有什么”；
- **行为**，即这个事物“能做什么”。

在 Java 中：

- **状态**通常用**属性**表示，属性本质上就是定义在类中的变量；
- **行为**通常用**方法**表示，方法用于描述对象能够执行的动作。

因此，可以把类理解为：

**类 = 属性 + 方法**

例如，定义一个“学生类”时，可以抽取出这类对象的共性：

- 姓名、年龄、性别，这些属于**属性**；
- 学习，这属于**方法**。

也就是说，类并不是现实中某一个具体存在的人，而是人脑对“这一类对象共同点”的归纳和抽象。

> **注意：** 类是**抽象概念**，它描述的是“这一类对象长什么样、能做什么”，而不是某一个真实存在的个体。

例如，对于“学生”来说：

- `name`、`age`、`gender` 表示学生的状态；
- `study()` 表示学生的行为。

### 对象

**对象**是根据类创建出来的、实际存在的具体个体。

在 Java 中，对象也常称为**实例**（instance）。“实例”这个词可以理解为：**类这个模板被真正创建出来后的具体结果**。

例如，`Student` 是一个类，它只是一个模板；而“张三这个学生”“李四这个学生”则是具体对象。它们都来自同一个类，所以都具有同样的属性结构和方法结构，但每个对象内部保存的数据可以不同。

比如：

- 某个学生对象的姓名可能是 `"张三"`；
- 另一个学生对象的姓名可能是 `"李四"`。

它们都有 `name` 这个属性，但属性值不同。像这种“每个对象各自拥有一份”的属性，就称为**实例变量**。

### 类与对象的关系

类和对象的关系，可以用“图纸与实物”来理解：

- **类**像一张设计图纸，只规定“应该有哪些部分”；
- **对象**像按照图纸造出来的具体实物，是真正可以使用的个体。

例如，`Student` 类规定了学生应该有 `name`、`age`、`gender` 这些属性，也规定了学生可以执行 `study()` 这个方法；而通过这个类创建出来的每一个学生对象，都会具有这些成员，只是各自的数据不同。

## 实例变量与实例方法

当属性和方法是“属于某个对象本身”的时候，它们分别称为**实例变量**和**实例方法**。

### 实例变量

定义在类中、并且每个对象各自拥有一份的数据，称为**实例变量**。

例如，学生类中有 `name` 属性。
 当创建两个学生对象时：

- 第一个对象的 `name` 可以是 `"张三"`；
- 第二个对象的 `name` 可以是 `"李四"`。

虽然它们都来自同一个类，也都具有 `name` 这个属性，但每个对象保存的是**自己的那一份值**。这就是实例变量的特点。

### 实例方法

定义在类中、供对象调用的方法，称为**实例方法**。

例如，学生都有“学习”这个行为，因此可以在 `Student` 类中定义 `study()` 方法。只要创建了某个学生对象，就可以让这个对象去调用 `study()`。

> **注意：访问实例变量、调用实例方法，都必须先有对象。**因为“实例”本来就表示“属于某个对象的内容”，没有对象，就谈不上访问该对象的数据或行为。

下面是一个典型的“学生类”定义：

```java
package com.jkweilai.p01;

/**
 * 学生类
 */
public class Student {
    // 属性（实例变量）
    String name;
    int age;
    boolean gender;

    // 方法（实例方法）
    public void study() {
        System.out.println("学生在学习...");
    }
}
```

这段代码中包含了一个最基本的类结构：

1. `Student` 是一个**类名**，表示学生这一类对象；
2. `name`、`age`、`gender` 是学生对象的**属性**，用于描述状态；
3. `study()` 是学生对象的**方法**，用于描述行为。

### 为什么必须先创建对象，才能访问实例成员

这是初学面向对象时非常容易忽略的一点。

实例变量和实例方法都属于“某一个具体对象”。而类只是模板，本身不是某个具体学生，因此不能直接把“某个学生的姓名”或“某个学生正在学习”强行附到模板上。

例如，“姓名”一定是某个具体学生的姓名，而不是“学生类”这个抽象概念本身的姓名。同理，“学习”这个动作，也必须是某个具体学生在学习，而不是“模板在学习”。

所以，程序设计上必须先通过类创建对象，再通过对象去访问属于它的实例成员。

可以这样理解：

- **类**只负责规定“有什么”；
- **对象**才真正持有这些数据，并执行这些行为。

## 对象的创建和使用

前面已经认识了**类**和**对象**的基本含义，接下来要进一步掌握：在 Java 中，类是如何定义的，对象是如何创建的，以及创建出来之后如何访问对象的属性和方法。

### 类的定义

类是对象的模板，因此在创建对象之前，必须先定义类。定义类的基本语法格式如下：

```java
[修饰符列表] class 类名 {
    // 属性（描述状态）

    // 方法（描述行为）
}
```

这里需要先掌握以下几点：

1. `class` 是定义类的关键字；
2. `类名` 是这个类的名字，用来标识这一类对象；
3. 类的大括号内部可以写**属性**和**方法**；
4. **属性**用于描述对象的状态，**方法**用于描述对象的行为；
5. 前面的“修饰符列表”是可选的，现阶段最常见的是 `public`。

下面是一个学生类的定义示例：

```java
public class Student {
    // 属性（实例变量）
    String name;
    int age;
    boolean gender;

    // 方法（实例方法）
    public void study() {
        System.out.println("正在学习");
    }
}
```

### 对象的创建

类定义好之后，就可以根据类来创建对象。创建对象的基本语法如下：

```java
类名 对象名 = new 类名();
```

例如：

```java
Student s = new Student();
```

这行代码表示：根据 `Student` 类创建一个学生对象，并用变量 `s` 来接收它。

这句代码虽然很短，但实际包含三个层面的含义：

1. `Student` 表示变量 `s` 的数据类型是 `Student`；
2. `new Student()` 表示创建一个新的 `Student` 对象；
3. `=` 表示把创建出来的对象交给变量 `s` 保存。

这里要特别注意一个容易混淆的地方：**`s` 不是对象本身，而是一个引用变量。**

因为使用 `class` 定义出来的类型都属于**引用数据类型**，所以 `Student` 是引用数据类型，`s` 是一个 `Student` 类型的变量。这个变量中保存的是对象的引用信息，可以粗略理解为：**`s` 指向了这个学生对象**。

### 对象的使用

对象创建完成之后，就可以使用它。对象的使用主要包括三类操作：

1. **读取属性值**
2. **修改属性值**
3. **调用对象的方法**

它们都通过“点”的方式完成，也就是 **`.` 运算符**。

#### 读取属性值

读取属性值的语法格式如下：

```java
对象名.属性名
```

例如：

```java
s.name
s.age
s.gender
```

这表示读取对象 `s` 中对应属性当前保存的值。

#### 修改属性值

修改属性值的语法格式如下：

```java
对象名.属性名 = 值;
```

例如：

```java
s.name = "Jack";
s.age = 20;
s.gender = true;
```

这表示把新的值赋给对象 `s` 的对应属性。

#### 调用方法

调用对象方法的语法格式如下：

```java
对象名.方法名();
```

例如：

```java
s.study();
```

这表示让对象 `s` 执行 `study()` 方法。

> **注意**：当对象刚被创建出来，而实例变量还没有手动赋值时，Java 会为它们自动提供默认值。**只有成员变量（实例变量）才有默认值，局部变量没有默认值。**例如，方法内部自己定义的变量，必须先赋值后使用，否则会报错。

#### 一个类可以创建多个对象

同一个类可以实例化出多个对象。每个对象都拥有相同的属性和方法结构，但各自保存的数据彼此独立。

例如：

```java
Student s1 = new Student();
Student s2 = new Student();
```

这表示根据同一个 `Student` 类创建了两个学生对象。

虽然 `s1` 和 `s2` 都有 `name`、`age`、`gender` 这些属性，也都可以调用 `study()` 方法，但它们互不影响。比如：

```java
s1.name = "张三";
s2.name = "李四";
```

此时：

- `s1.name` 是 `"张三"`；
- `s2.name` 是 `"李四"`。

这说明：**实例变量是“每个对象各自拥有一份”的数据。**

可以把它理解为：类只规定“学生都有姓名”，但并没有规定“所有学生姓名都一样”。真正创建出不同对象后，每个对象的属性值可以各不相同。

#### 为什么不能直接写变量名访问实例变量

在测试类的 `main` 方法中，如果直接写：

```java
System.out.println(name);
```

这是不可以的。因为 `name` 是 `Student` 对象中的实例变量，而不是 `main` 方法中的局部变量。`main` 方法本身并没有定义名为 `name` 的变量，所以编译器找不到它。

正确写法必须通过对象访问：

```java
System.out.println(s1.name);
```

因为这里的 `name` 明确属于对象 `s1`。

这再次说明：**实例变量不属于当前方法本身，而属于某个对象。**

#### 为什么不能用类名访问实例变量和实例方法

下面这样的写法也是错误的：

```java
System.out.println(Student.name);
Student.study();
```

原因是：

- `name` 是**实例变量**，属于某个具体对象；
- `study()` 是**实例方法**，也属于某个具体对象。

而 `Student` 只是类名，表示模板，不表示某个具体学生对象。因此不能直接用类名去访问实例成员。

正确方式应该是：

```java
Student s = new Student();
System.out.println(s.name);
s.study();
```

> **注意：** **实例变量**和**实例方法**必须通过对象访问，不能直接通过类名访问。后面学到 `static` 之后，才会接触“可以通过类名访问的成员”。

## 对象的内存分析

### JVM 中的几个内存区域

继续学习之前，先要知道本节会反复出现的三个区域：**虚拟机栈**、**堆**、**方法区**。

| 内存区域                  | 主要存放内容                           | 与本节的关系                                             |
| ------------------------- | -------------------------------------- | -------------------------------------------------------- |
| **虚拟机栈（VM Stack）**  | 方法运行时的栈帧、局部变量表、操作数栈 | 方法中的局部变量、局部引用、形参、`this` 都与这里有关    |
| **堆（Heap）**            | 对象、数组，以及大量运行时对象数据     | `new` 创建出来的对象通常在这里，实例变量也存放在对象内部 |
| **方法区（Method Area）** | 类的元信息、方法字节码、运行时常量等   | 类加载后相关信息会进入这里，本节会顺带提到它的实现方式   |

前面已经学过：方法一旦调用，就会在虚拟机栈中创建自己的**栈帧**。栈帧里最关键的两个部分，仍然是**局部变量表**和**操作数栈**。而本节新增的重点是：**对象本身通常不在栈里，而在堆里。**

#### 方法区、永久代、元空间的关系

**方法区**是 JVM 规范中的一个逻辑区域，用来存放类相关的信息，例如：

- 类的元信息；
- 方法的字节码；
- 一部分运行时常量等。

但“方法区”只是规范里的概念，具体在 HotSpot 虚拟机中怎么实现，历史上有过变化：

- **Java 8 之前**，HotSpot 常用 **永久代（PermGen）** 来实现方法区；
- **Java 8 及以后**，HotSpot 去掉了永久代，改用 **元空间（Metaspace）** 来实现方法区。

元空间使用的是**本地内存（native memory）**，不再像永久代那样使用固定的堆内存区域，因此缓解了永久代容易因容量固定而出现的内存压力问题。

> **补充：** “缓解内存压力”不等于“绝不会 OOM”。元空间如果使用过多，或者限制过小，仍然可能发生内存溢出。

> **注意：** 方法区是规范概念，永久代和元空间是 HotSpot 的具体实现方式，不能简单把三者完全画等号。

### 对象是如何创建出来的

当程序执行到 `new` 时，JVM 会在内存中为新对象分配空间。入门阶段可以直接记成一句话：**`new` 会在堆内存中开辟一块空间，这块空间就是新创建出来的对象。**

例如：

```java
Book b = new Book();
```

执行这行代码时，可以这样理解：

1. `new Book()` 在堆中创建一个 `Book` 对象；
2. 对象中的实例变量会先被初始化为默认值；
3. 变量 `b` 保存这个对象的引用值；
4. 后续通过 `b` 去访问这个对象的实例变量和实例方法。

在常见的 HotSpot 虚拟机中，新对象通常会先分配到堆中的**年轻代**。不过现阶段不必纠结分代细节，只要先抓住最重要的一点：**对象在堆中创建，实例变量存放在对象内部。**

#### 什么是引用

平时我们常把 `p`、`s1`、`user` 这种变量直接叫“对象名”，这种叫法便于入门，但并不严谨。更准确地说，它们是**引用变量**。

**引用**本质上也是变量，只不过这个变量中保存的不是普通数值，而是**对象的引用值**。入门阶段可以把它粗略理解成“对象地址”。

例如：

```java
User u = new User();
```

这里的 `u` 不是对象本身，而是一个变量；真正的对象是 `new User()` 创建出来的那一块堆内存。`u` 之所以能访问对象，是因为它保存了指向该对象的引用值。

因此，下面两种访问方式本质上都是“通过引用找到对象，再访问对象成员”：

- `引用.变量名`
- `引用.方法名(实际参数列表)`

例如：

```java
u.name = "Tom";
u.login();
```

本质上都是在说：先通过 `u` 找到对应的 `User` 对象，再去修改 `name` 或调用 `login()`。

> **结论：** 引用不是对象本身，而是“通往对象”的入口。

#### 实例变量和局部变量分别存在哪里

这一点是本节的基础，必须分清。

- **实例变量**：存储在**堆内存的对象内部**；
- **局部变量**：存储在**当前方法栈帧的局部变量表中**。

例如：

```java
Phone p = new Phone();
```

这里：

- `p` 是定义在方法中的局部变量，所以它在当前方法栈帧的局部变量表中；
- `new Phone()` 创建出来的对象在堆中；
- `Phone` 对象内部的 `brand`、`price` 等实例变量，也跟着对象一起放在堆中。

### 字符串常量池

**字符串常量池**可以理解为 JVM 对字符串字面量进行统一管理和复用的一块机制。它的核心作用是：**把相同的字符串字面量集中保存、重复利用，避免反复创建内容相同的字符串对象。** 例如：

```java
String s1 = "jack";
String s2 = "jack";
```

这里代码中虽然写了两次 `"jack"`，但通常不会因此创建两个内容完全相同的独立字符串对象，而是会直接复用池中已有的那个 `"jack"`。这样做的好处很明显：一是减少重复创建对象的开销，二是节省内存，三是让相同字面量可以被统一管理。因此，字符串常量池的设计目的，本质上就是**复用相同字面量字符串，减少不必要的对象分配**。

像 `"jack"`、`"success"` 这种直接写在双引号中的内容，叫作**字符串字面量**。编译器能够识别出程序中出现了哪些字符串字面量，运行时 JVM 会利用字符串常量池对这些字面量进行管理和复用。例如：

```java
String name = "jack";
String str = "jack";
```

在这种写法下，可以把它理解为：`name` 和 `str` 都引用了字符串常量池中的同一个 `"jack"` 字符串对象。这也就解释了为什么对象中的某个 `String` 类型属性可以引用 `"jack"`，而另一个字符串变量也同样可以引用这个 `"jack"` —— 因为它们引用的是同一个被池化管理的字符串对象。

从当前主流 **Java 8+** 的入门理解来看，**字符串常量池中的字符串对象可以认为是存放在堆内存中的**。因此，在分析对象与引用、字符串字面量复用、以及内存图时，把字符串常量池理解为与堆内存中的字符串对象管理相关，是符合当前常见学习语境的。

### 引用可以重新赋值，也可以为 `null`

引用变量和普通变量一样，可以重新赋值。只不过它保存的是引用值，而不是普通数值。

例如：

```java
Order o = new Order();
o = null;
```

第二行的意思不是“语法错了”，而是：**变量 `o` 现在不再引用任何对象。**

这时要分清一件事：

- `o = null;` 本身没有错；
- 真正的问题出现在：**你还想继续通过 `o` 去访问对象。**

例如：

```java
Order o = new Order();
o = null;
System.out.println(o.id);
```

这里就会出错，因为 `o` 已经不再指向任何对象了。

#### 空指针异常是如何发生的

**空指针异常**（`NullPointerException`）的本质非常简单：**当访问一个空引用的实例相关数据时，就会出现空指针异常。**

例如：

```java
Customer c = null;
System.out.println(c.name);
```

这里 `c` 当前值是 `null`，却还试图访问 `c.name`，于是就会抛出空指针异常。

不仅访问实例变量会这样，调用实例方法也一样：

```java
Customer c = null;
c.shopping();
```

本质上也是“拿空引用去找对象”，而它根本找不到对象。

> **易错点：** 真正出错的不是“变量是 `null`”，而是“用 `null` 去访问实例成员”。

### 方法调用时参数是如何传递的

这一部分是经典重点。Java 方法调用时，不管参数类型是什么，本质上都遵循同一条规则：

> **把变量中保存的值复制一份，传给被调用方法。**

这个“值”有两种可能：

- 可能是基本数据类型的数值；
- 也可能是引用类型的引用值。

因此，Java 只有一种参数传递方式：**值传递**。

#### 基本数据类型参数的传递

先看基本数据类型。

```java
public static void add(int n) {
    n++;
}
```

如果这样调用：

```java
int x = 10;
add(x);
System.out.println(x);
```

调用时，传给 `add` 的不是 `x` 这个变量本身，而是 `x` 当前保存的值 `10` 的一份副本。于是：

- `main` 方法里的 `x` 还是自己的变量；
- `add` 方法里的 `n` 是另一份独立变量。

`add` 中即使把 `n` 改成 `11`，也只是改了 `add` 自己栈帧中的那份值，不会影响 `main` 中原来的 `x`。

> **结论：** 基本类型参数传递时，改的是副本，不会影响原变量。

#### 引用类型参数的传递

再看引用类型。这里最容易误解。

假设有下面的类：

```java
class Person {
    int age;
}
```

再看方法：

```java
public static void increase(Person p) {
    p.age++;
}
```

调用代码如下：

```java
Person person = new Person();
person.age = 10;

increase(person);

System.out.println(person.age);
```

最终输出是 `11`。但这并不表示 Java 把 `person` 这个变量本身传过去了。真正发生的是：

1. `person` 变量中保存了一个引用值；
2. 调用 `increase(person)` 时，把这个引用值复制一份给形参 `p`；
3. `person` 和 `p` 是两个不同变量，但它们都指向同一个 `Person` 对象；
4. 所以通过 `p.age++` 修改对象时，外部看到的同一个对象自然也变了。

> **注意：** 这里依然是值传递，只不过传过去的值恰好是“引用值”。

### `this` 关键字初识

前面已经学过：实例方法必须通过对象调用。既然实例方法一定是“某个对象在调用”，那么 JVM 在执行这个实例方法时，自然也要知道“当前到底是哪一个对象”。

这个“当前对象”，就用 **`this`** 来表示。

例如：

```java
public class Member {
    String name;

    public void buy() {
        System.out.println(this.name + "正在购物...");
    }
}
```

如果：

```java
Member m1 = new Member();
m1.name = "Tom";
m1.buy();
```

那么 `buy()` 方法中的 `this` 就代表 `m1`。如果是另一个对象调用同一个方法，那么 `this` 就代表另一个对象。

#### `this.` 大部分情况下可以省略

在实例方法中访问实例变量时，很多时候 `this.` 是可以省略的。

例如：

```java
System.out.println(this.name);
System.out.println(name);
```

在多数简单场景下，这两句效果相同，因为实例方法默认就是在访问当前对象的成员。

不过从理解角度看，刚开始学习时适当写出 `this.` 反而更清晰，因为它能提醒你：**这里访问的不是局部变量，而是当前对象的实例变量。**

#### `this` 存储在什么位置

结合前面学过的“局部变量表”，这一点现在就能看懂了。

实例方法在执行时，会形成自己的栈帧；在这个栈帧的**局部变量表**中，**0 号槽位**通常会保存当前对象的引用，这个引用就是 `this`。

也就是说：

- 在**实例方法**中，局部变量表的前面位置通常先放 `this`；
- 在**静态方法**中，没有当前对象，因此也就没有 `this`。

例如 `main` 方法是静态方法，所以它的局部变量表中不会有 `this`，通常最先出现的是参数 `args`。而实例方法中，`this` 会先进入局部变量表，再往后才是其他局部变量和参数。

> **注意：** 这也是为什么 `this` 只能出现在实例方法中，不能在静态方法中直接使用。

### 对象之间也可以互相关联

前面看到的属性，如 `name`、`age`，要么是基本类型，要么是字符串引用。现在要再向前一步：**一个对象的属性，还可以是另一个对象的引用。**

例如：

```java
class Address {
    String city;
    String street;
}

class User {
    String name;
    int age;
    Address address;
}
```

这里 `address` 不是普通值，而是一个 `Address` 类型的引用。于是可以这样写：

```java
Address addr = new Address();
addr.city = "天津";
addr.street = "南开";

User user = new User();
user.name = "张三";
user.age = 20;
user.address = addr;
```

此时：

- `user` 引用一个 `User` 对象；
- `user.address` 又引用另一个 `Address` 对象；
- 所以可以继续访问 `user.address.city`、`user.address.street`。

这说明对象之间的关系，很多时候并不是“一个对象里真的塞进另一个完整对象副本”，而是：**一个对象中保存了另一个对象的引用。**

#### 链式访问

像下面这种写法：

```java
System.out.println(user.address.city);
```

之所以能成立，是因为访问过程是一层一层下去的：

1. 先通过 `user` 找到 `User` 对象；
2. 再读取它里面的 `address` 引用；
3. 再通过这个引用找到 `Address` 对象；
4. 最后读取 `city`。

因此，链式访问成立的前提是：**前面每一段都必须不是 `null`。**

例如：

- `user` 不能是 `null`；
- `user.address` 也不能是 `null`。

只要中间某一段是空引用，后续继续往下访问时就会抛出空指针异常。

> **易错点：** 链式访问中，不只是最左边那个变量可能空指针，中间任何一段为 `null` 都一样会出错。

## 封装

**封装**是面向对象三大特征之一。它的核心思想不是“把代码包起来”这么简单，而是：**把对象的属性和对属性的操作统一放到类内部，并对外隐藏实现细节，只暴露必要、可控的访问方式。** 这样做的目的，是让外部“能用”，但不能“乱用”。

### 对封装的理解

现实生活中，很多设备本身就是封装思想的体现。例如，一台空调把压缩机、电路板、传感器、风扇等复杂部件都封装在内部，用户通常不需要也不应该直接接触这些内部结构，而是通过遥控器上的“开关、调温、模式切换”等有限入口来使用它。这样既提高了使用便利性，也降低了误操作和损坏内部结构的风险。

程序中的封装也是同样的道理。一个对象内部会有自己的**状态**和**行为**：

- **状态**就是属性；
- **行为**就是方法。

封装要求把这些内容统一组织到类中，并且尽量**隐藏对象内部的实现细节**，只对外提供必要的访问接口。外部程序不应该随意改动对象内部的数据，而应该通过类事先设计好的方式去读、去改、去调用。

### 封装的好处

封装最直接的价值，在于它能把“复杂和不安全的部分”收进类内部，只把“简单和安全的入口”暴露给外部使用。

它的主要好处可以概括为以下几点：

- **保证数据安全**。外部不能随意对对象内部数据乱改，类可以决定哪些数据能改、怎么改、什么情况下不能改。
- **隐藏实现细节**。使用者只需要知道“怎么用”，不需要知道内部具体是怎么实现的。
- **降低耦合度**。外部程序依赖的是公开接口，而不是内部细节，因此类内部实现调整后，外部代码通常不需要跟着大改。
- **提高可维护性和可复用性**。一个类只要把自己的数据和行为管理好，就更容易重复使用，也更容易集中修改和维护。

例如，“年龄”这个属性看起来只是一个整数，但并不是任何整数都合法。如果不加限制，外部完全可以把年龄设为 `-10` 或 `500`；如果使用封装，就可以把年龄的修改入口收拢到一个方法中，在方法里统一做合法性判断。

#### 不使用封装会有什么问题

如果一个类中的属性直接对外暴露，那么外部程序就可以随意读写这些数据。这样虽然看起来访问方便，但对象会失去对自身数据的控制能力。

例如下面这个类：

```java
public class Person {
    int age;
}
```

再看使用代码：

```java
public class PersonTest {
    public static void main(String[] args) {
        Person p = new Person();

        p.age = 20;
        System.out.println("年龄 = " + p.age);

        p.age = -1;
        System.out.println("年龄 = " + p.age);
    }
}
```

这段代码语法上没有问题，但设计上存在明显隐患：`age` 被直接暴露给外部，任何代码都可以随意赋值。程序虽然能运行，但对象内部的数据已经可能处于不合理状态。`-1` 显然不是合法年龄，可是类本身却没有能力阻止这种错误发生。

这说明一个关键问题：**如果属性直接暴露，对象就无法保证自己的数据始终合法。**

### 如何实现封装

在 Java 中，最常见、最基础的封装实现方式是：

1. **属性私有化**；
2. **对外提供公开的访问方法**；
3. **在访问方法中加入必要的控制逻辑**。

也就是说，先不让外部直接碰属性，再通过方法为外部提供“受控入口”。

#### 第一步：属性私有化

属性私有化，就是使用 `private` 修饰属性。例如：

```java
public class User {
    private int age;
}
```

`private` 表示“私有的”。被 `private` 修饰后，该属性只能在**当前类内部**直接访问，类外部代码不能再像以前那样写 `对象名.属性名` 去直接操作它。

这一步的意义在于：**先把入口收回来**。只有先收回来，后面才谈得上“按规则开放”。

#### 第二步：对外提供访问入口

属性私有化之后，外部如果完全不能读、不能改，显然也不方便使用。因此，通常还需要对外提供两个访问入口：

- 一个负责**读取**属性值；
- 一个负责**修改**属性值。

这两个方法在 Java 中有约定俗成的命名规范：

| 方法类型   | 命名规范      | 作用       |
| ---------- | ------------- | ---------- |
| **getter** | `getXxx()`    | 读取属性值 |
| **setter** | `setXxx(...)` | 修改属性值 |

例如：

```java
public class User {
    private int age;

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

这里：

- `getAge()` 用来读年龄；
- `setAge(int age)` 用来改年龄。

需要注意的是，**getter 和 setter 都是实例方法**，因此调用时仍然需要先创建对象。

#### 第三步：在 setter 中加入安全控制

如果 setter 只是机械地赋值，那么虽然表面上用了封装，但其实并没有真正发挥封装的价值。封装真正重要的地方，在于：**可以把安全控制逻辑写进 setter 中。**

例如：

```java
public class User {
    private int age;

    public void setAge(int age) {
        if (age < 0 || age > 150) {
            System.out.println("对不起，您提供的年龄不合法！");
            return;
        }
        this.age = age;
    }

    public int getAge() {
        return age;
    }
}
```

这样一来，外部再想修改年龄，就必须经过 `setAge()`。而 `setAge()` 会先检查数据是否合法，不合法就拒绝修改。这样对象的数据就不再是“谁都能乱改”的状态了。

可以配合一个简单测试理解：

```java
public class UserTest {
    public static void main(String[] args) {
        User u = new User();

        u.setAge(18);
        System.out.println("年龄 = " + u.getAge());

        u.setAge(-100);
        System.out.println("年龄 = " + u.getAge());
    }
}
```

第一次设置 `18` 合法，因此可以成功赋值；第二次设置 `-100` 不合法，因此会被拦截，年龄不会被改坏。

#### 为什么 `this.age = age;` 中的 `this` 不能省略

这一点是封装代码里很容易出现的细节问题。

看下面这段 setter：

```java
public void setAge(int age) {
    this.age = age;
}
```

这里左边的 `this.age` 表示**当前对象的实例变量**，右边的 `age` 表示**方法参数**。这两个名字虽然一样，但不是同一个变量。

如果把 `this` 去掉，写成：

```java
public void setAge(int age) {
    age = age;
}
```

那么左右两边都会优先理解为“方法参数 age”，结果就变成了“把参数自己赋值给自己”，对象中的实例变量根本没有被修改。

因此，在“**实例变量名**和**方法参数名**同名”的情况下，`this.` 不能省略，它的作用就是明确指出：这里访问的是**当前对象的那个属性**。

### getter / setter 的命名规范

getter 和 setter 不是随便命名的，通常要遵循规范，这样代码更统一，也更便于工具自动识别和生成。

对于普通属性，常见规范如下：

| 属性名 | getter      | setter                 |
| ------ | ----------- | ---------------------- |
| `age`  | `getAge()`  | `setAge(int age)`      |
| `name` | `getName()` | `setName(String name)` |

对于 `boolean` 类型属性，getter 方法通常使用 **`isXxx()`** 形式，而不是 `getXxx()`。例如：

```java
public class Customer {
    private boolean gender;

    public boolean isGender() {
        return gender;
    }

    public void setGender(boolean gender) {
        this.gender = gender;
    }
}
```

这里 `gender` 是布尔类型，因此读取方法写成 `isGender()` 是符合常见生成规则的。你上传的 `Customer` 示例中，IDEA 自动生成的也是这种写法。

> **补充：** 在实际开发中，布尔类型的命名有时会设计得更自然，例如 `isVip()`、`isSuccess()`。这样 getter 写出来会更符合语义。

### 自动生成 setter 和 getter

在实际开发中，如果一个类有很多属性，手写 getter 和 setter 会比较重复。IDEA 提供了自动生成功能，可以快速完成这部分代码。

常见操作方式是：在类体中使用 **`Alt + Insert`**，然后选择生成 `Getter and Setter`。

自动生成的好处主要有两个：

- 省去大量重复输入；
- 生成的方法格式更统一，不容易写错。

例如，一个包含多个属性的类，IDEA 可以一次性生成对应的 getter / setter。你上传的 `Customer` 类就是这种典型形式：多个属性私有化后，再统一通过方法对外开放读取和修改入口。

## 构造方法

**构造方法**又称**构造器**（Constructor），是对象创建过程中非常重要的一部分。构造方法的核心作用，可以概括为一句话：

> **结论：** 构造方法的主要作用是**完成对象初始化**；对象的内存分配由 `new` 触发，构造方法负责在对象创建过程中进一步为对象设置初始状态。

很多初学者会把“创建对象”和“执行构造方法”完全混为一件事，这样理解虽然便于入门，但不够准确。更严谨的说法是：当执行 `new` 时，会先为对象分配内存空间并完成默认初始化，然后再执行构造方法体，对对象做进一步初始化。因此，对象创建和对象初始化是紧密连在一起的两个阶段，它们在一次 `new` 操作中连续完成，先后顺序不能颠倒。

例如：

```java
User u = new User();
```

这行代码发生的事情，并不是“只调用了一个方法”这么简单，而是大致经历了以下过程：

1. 执行 `new`，在内存中为对象分配空间；
2. 对对象中的所有实例变量先赋默认值；
3. 执行与对象初始化相关的代码；
4. 执行构造方法体；
5. 对象初始化完成，最后把对象引用交给变量 `u`。

### 构造方法的语法特点

构造方法在语法上有几个非常鲜明的特点，必须记清。

#### 定义格式

构造方法的基本语法格式如下：

```java
[修饰符列表] 构造方法名(形参列表) {
    构造方法体;
}
```

例如：

```java
public class User {
    public User() {
        System.out.println("User类的无参数构造方法执行了！");
    }
}
```

构造方法和普通方法最大的区别主要有两个：

1. **构造方法名必须与类名完全一致**；
2. **构造方法没有返回值类型，连 `void` 也不能写**。

例如下面这种写法就不是构造方法，而是一个普通方法：

```java
public void User() {
}
```

虽然它的名字也叫 `User`，但因为写了 `void`，所以它已经不是构造方法了。

> **易错点：** 只要写了返回值类型，不管这个类型是不是 `void`，它就不再是构造方法。

#### 调用方式

构造方法不能像普通实例方法那样通过“对象名`.`方法名()`”来调用。它的调用方式是：

```java
new 构造方法名(实参列表);
```

例如：

```java
new User();
new User("jack");
```

这里的“构造方法名”本质上就是类名，因为构造方法名必须和类名一致。

### 无参数构造方法与缺省构造器

如果一个类中**没有显式定义任何构造方法**，那么系统会默认提供一个**无参数构造方法**，这通常也叫**缺省构造器**。

例如：

```java
public class Student {
    String name;
}
```

这个类虽然没有手动写任何构造方法，但下面的代码依然可以成立：

```java
Student s = new Student();
```

原因就在于：系统自动补了一个无参构造方法。

#### 一旦手写构造方法，默认无参构造器就没有了

这是一条非常重要的规则。只要类中**显式定义了任意一个构造方法**，系统就**不再自动提供**那个默认的无参构造方法。

例如：

```java
public class Student {
    String name;

    public Student(String name) {
        this.name = name;
    }
}
```

此时如果再写：

```java
Student s = new Student();
```

就会报错，因为这个类已经手动写了一个有参构造方法，系统不会再偷偷补一个无参构造方法给你。

### 构造方法支持重载

和普通方法一样，构造方法也支持**重载**。也就是说，一个类中可以定义多个构造方法，只要它们的**参数列表不同**即可。

例如：

```java
public class User {
    String name;
    int age;

    public User() {
    }

    public User(String name) {
        this.name = name;
    }

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

这三个构造方法都叫 `User`，但参数列表不同，因此构成重载。

这样设计的好处是：可以根据不同的初始化需求，用不同的方式创建对象。例如：

```java
User u1 = new User();
User u2 = new User("jack");
User u3 = new User("jack", 20);
```

这三种写法分别对应三种不同的初始状态。

### 构造代码块

构造代码块的语法很简单，直接写一对大括号即可：

```java
{
    // 构造代码块
}
```

它不是方法，没有方法名，也没有参数列表。它的作用是：**每次创建对象时，在构造方法体执行之前，先执行一次其中的代码。**

例如：

```java
public class User {
    {
        System.out.println("构造代码块执行！！！");
    }

    public User() {
        System.out.println("构造方法执行了！");
    }
}
```

执行：

```java
new User();
```

时，输出顺序一定是：

```java
构造代码块执行！！！
构造方法执行了！
```

构造代码块的价值在于：如果多个构造方法中有一段**公共初始化代码**，可以把这段代码提取到构造代码块中，这样能够减少重复。

例如，一个类有多个构造方法，而每个构造方法在执行前都要打印某条相同的初始化提示，这种逻辑就可以提取到构造代码块里。

#### 执行流程

一次对象创建，大致可以按下面的顺序理解：

1. `new` 时在堆内存中为对象分配空间；
2. 对所有实例变量赋**默认值**；
3. 按照代码书写顺序，执行**实例变量显式赋值**和**构造代码块**；
4. 执行对应的**构造方法体**；
5. 构造方法结束，对象初始化完成。

这里最容易漏掉的是第 3 步。很多人以为默认值之后就直接执行构造方法体了，其实中间还可能有：

- 实例变量的显式赋值，如 `int x = 10;`
- 构造代码块，如 `{ ... }`

并且它们不是分两批各自统一执行，而是：**按照它们在类中出现的先后顺序执行。**

下面这段代码是理解执行顺序的关键：

```java
public class CodeExeOrder {
    CodeExeOrder(){
        System.out.println("构造方法执行");
    }

    int x = getX();

    {
        System.out.println("构造代码块执行");
    }

    int y = getY();

    public int getX(){
        System.out.println("getX执行了");
        return 100;
    }

    public int getY(){
        System.out.println("getY执行了");
        return 200;
    }

    public static void main(String[] args) {
        new CodeExeOrder();
    }
}
```

这段代码的输出结果是：

```
getX执行了
构造代码块执行
getY执行了
构造方法执行
```

## this 关键字

`this` 是 Java 中非常重要的一个关键字。前面在学习对象、实例方法、构造方法时，其实已经多次接触过它。现在需要把这些零散认识收拢起来，系统掌握两件事：**`this` 到底代表什么**，以及 **`this()` 到底是做什么的**。

`this` 的核心含义可以先概括为一句话：`this` 出现在实例相关环境中，代表**当前对象**。

所谓“当前对象”，指的是：**当前正在调用这个实例方法，或者当前正在执行这个构造方法的那个对象**。

例如：

```java
Customer c1 = new Customer("杰克");
c1.shopping();
```

当执行 `c1.shopping()` 时，`shopping()` 方法里的 `this` 就代表 `c1`。如果换成另一个对象来调用同一个实例方法，那么方法里的 `this` 也会随之变成那个新对象。

这说明：`this` 不是固定指向某个类，也不是固定指向某个变量名，而是**谁在当前调用实例成员，`this` 就代表谁**。

### `this` 的基本用法

#### 通过 `this.` 访问实例变量

`this.` 最常见的作用，就是访问当前对象的实例变量。

例如：

```java
public class Customer {
    String name;

    public void shopping() {
        System.out.println(this.name + "正在购物！");
    }
}
```

这里的 `this.name` 表示“当前对象的 `name` 属性”。

#### 通过 `this.` 调用实例方法

`this.` 不仅能访问实例变量，也能调用实例方法。

例如：

```java
public class Customer {
    String name;

    public void shopping() {
        System.out.println(name + "正在购物！");
        this.pay();
    }

    public void pay() {
        System.out.println(this.name + "正在结账付款！！！");
    }
}
```

当执行：

```java
Customer c = new Customer("杰克");
c.shopping();
```

时，`shopping()` 中的 `this.pay()` 表示：让**当前对象**去调用 `pay()` 方法。既然当前对象是 `c`，那么本质上就等价于 `c.pay()`。

#### `this.` 大多数情况下可以省略

在实例方法或构造方法中，如果没有歧义，`this.` 一般都可以省略。

例如下面两种写法，在多数情况下效果相同：

```java
System.out.println(this.name);
System.out.println(name);
```

```java
this.pay();
pay();
```

这是因为在实例成员环境中，编译器默认就知道你访问的是“当前对象”的成员。

> **补充：** 从“运行效果”看，大多数情况下写不写 `this.` 没区别；但从“理解当前对象”这个角度看，刚开始学习时适当把 `this.` 写出来，反而更容易看清楚代码在做什么。

当**局部变量**和**实例变量**同名时，`this.` 不能省略。

例如：

```java
public class Customer {
    String name;

    public Customer(String name) {
        this.name = name;
    }
}
```

这里左边的 `this.name` 表示当前对象的实例变量 `name`，右边的 `name` 表示构造方法的参数 `name`。

如果把 `this.` 去掉，写成：

```java
name = name;
```

那么左右两边都会优先理解为“当前方法中的局部变量 `name`”，结果就变成了参数自己赋值给自己，对象的实例变量根本没有被修改。

所以，在“实例变量名”和“局部变量名”冲突时，`this.` 的作用就是**明确指出：我要访问的是当前对象的属性，而不是当前方法里的局部变量**。

#### `this` 为什么不能出现在静态方法中

这一点必须真正理解，不能只背结论。

**静态方法属于类，调用时不依赖对象。**例如：

```java
Customer.m();
```

既然静态方法可以在没有对象的前提下执行，那么方法内部自然就不存在“当前对象”这一说。**没有当前对象，也就谈不上 `this`。**

例如下面这种写法是错误的：

```java
public static void m() {
    System.out.println(this.name); // 错误
}
```

同理，在**静态方法中也不能直接访问实例变量、实例方法**：

```java
public static void m() {
    System.out.println(name); // 错误
    pay();                    // 错误
}
```

原因是一样的：实例变量和实例方法都依赖对象，而静态方法执行时未必有对象存在。

如果静态方法中确实需要操作某个对象的实例成员，就必须**先自己创建对象，或者拿到一个对象引用**，然后通过“对象名`.`成员名”的方式访问。

### `this` 在内存中的位置

这一点和前面学过的“局部变量表”直接相关。

实例方法或构造方法在执行时，都会形成自己的栈帧。这个栈帧中的**局部变量表**，除了保存方法参数和局部变量，还会保存当前对象的引用。这个引用就是 `this`。

入门阶段可以直接记住：`this` 通常存储在当前实例方法或构造方法栈帧的**局部变量表第 0 个槽位**。

这也解释了为什么实例方法中可以直接访问实例变量、实例方法：因为 JVM 在方法执行时，已经把“当前对象的引用”准备好了。

### `this()` 的用法

前面讲的 `this.`，表示“当前对象”。而 `this()` 是另一种完全不同的语法，它只出现在**构造方法**中。

#### `this()` 是什么

`this(实参列表)` 的作用是：**通过当前构造方法，去调用本类中的其他构造方法。**

例如：

```java
public class MyDate {
    private int year;
    private int month;
    private int day;

    public MyDate() {
        this(1970, 1, 1);
    }

    public MyDate(int year, int month, int day) {
        this.year = year;
        this.month = month;
        this.day = day;
    }
}
```

这里无参构造方法中的：

```java
this(1970, 1, 1);
```

表示：当前无参构造方法不自己单独写初始化逻辑，而是直接去调用本类中另一个三参数构造方法，把 `1970, 1, 1` 作为实参传过去。

#### `this()` 的作用：代码复用

`this()` 最主要的价值是**代码复用**。

如果不用 `this()`，无参构造方法通常会这样写：

```java
public MyDate() {
    this.year = 1970;
    this.month = 1;
    this.day = 1;
}
```

而三参数构造方法又会写一遍类似逻辑：

```java
public MyDate(int year, int month, int day) {
    this.year = year;
    this.month = month;
    this.day = day;
}
```

这样就出现了重复赋值代码。虽然这段代码不长，但如果类中的属性更多、初始化逻辑更复杂，重复就会越来越明显。

使用 `this()` 后，可以把真正的初始化逻辑集中到一个构造方法中，其他构造方法只负责“提供不同的入口”，从而**减少重复代码，提高可维护性**。

#### `this()` 的语法限制

`this()` 虽然很有用，但使用时有严格限制。

##### 1. 只能出现在构造方法中

`this()` 的作用是调用本类其他构造方法，因此它只能写在构造方法里，不能写在普通方法中。

##### 2. 必须写在构造方法第一行

这是最重要的一条规则。

例如：

```java
public MyDate() {
    System.out.println("创建日期对象");
    this(1970, 1, 1); // 错误
}
```

这段代码会报错，因为 `this()` 前面已经有别的语句了。

正确写法必须是：

```java
public MyDate() {
    this(1970, 1, 1);
}
```

一旦决定当前构造方法要去调用本类其他构造方法，那么这个调用必须最先发生，不能和当前构造方法里的其他初始化语句交叉执行，这是语法硬性规定。

## static 关键字

`static` 翻译为**静态的**。被 `static` 修饰的成员，不再属于某一个具体对象，而是属于**类本身**。这意味着：

- 不创建对象，也可能已经可以使用它；
- 所有对象看到的是同一份静态成员；
- 它的访问重点不再是“哪个对象在用”，而是“这个类本身提供了什么”。

### `static` 可以修饰什么

在当前阶段，重点掌握三种最常见的用法：

| 修饰对象            | 名称           | 含义                     |
| ------------------- | -------------- | ------------------------ |
| `static` 修饰变量   | **静态变量**   | 属于类，所有对象共享     |
| `static` 修饰方法   | **静态方法**   | 属于类，通常通过类名调用 |
| `static` 修饰代码块 | **静态代码块** | 在类加载时执行           |

> **注意：** 局部变量不能使用 `static` 修饰。`static` 讨论的是“类级别成员”，而局部变量属于方法执行时的临时数据，不属于类成员。

### 静态变量

#### 什么是静态变量

被 `static` 修饰的变量叫作**静态变量**，也叫**类变量**。它不属于某个具体对象，而是属于整个类。

例如：

```java
public class Employee {
    String name;
    static String companyName = "OpenAI";
}
```

这里：

- `name` 是实例变量，每个 `Employee` 对象各自拥有一份；
- `companyName` 是静态变量，整个 `Employee` 类只有一份，所有对象共享这同一个值。

也就是说：

```java
Employee e1 = new Employee();
Employee e2 = new Employee();
```

无论创建多少个对象，`companyName` 都不会因为对象变多而复制出很多份；它本质上是“类级别的共同数据”。

#### 什么时候定义为静态变量

判断一个属性是否适合定义为静态变量，关键不在于“能不能写”，而在于**它到底属于对象，还是属于整个类**。

如果某个属性满足下面这个特征：**所有对象该属性的值都相同，并且逻辑上它描述的是“这一类事物的共同信息”**，那么通常就适合定义为静态变量。

再换一个新例子：

```java
public class Student {
    String name;
    String studentId;
    static String schoolName = "第一实验中学";
}
```

这里：

- `name` 和 `studentId` 因人而异，必须是实例变量；
- `schoolName` 对所有学生都相同，更适合作为静态变量。

#### 为什么静态变量更节省空间

如果一个共同属性被设计成实例变量，那么每创建一个对象，这个属性就要跟着对象复制一份。对象越多，重复数据越多。

而定义成静态变量后，这个类级别的数据通常只保留一份，所有对象共享，因此可以减少不必要的重复存储。

例如，如果有 10000 个学生对象，而 `schoolName` 都是 `"第一实验中学"`：

- 设计成实例变量：每个对象内部都会带一份学校名；
- 设计成静态变量：全类共享一份学校名。

虽然现在的机器内存通常足够大，但从设计思想上看，后者明显更合理。

#### 静态变量何时建立

静态变量不依赖对象创建。它属于类，因此在**类加载后**就可以被使用。也正因为如此，静态变量通常会早于对象存在。

例如：

```java
public class Config {
    static String version = "1.0";
}
```

即使你没有写：

```java
new Config();
```

也仍然可以直接使用：

```java
System.out.println(Config.version);
```

这正是静态变量和实例变量最本质的差别之一：**实例变量必须依赖对象，静态变量依赖类。**

#### 静态变量的访问方式

静态变量既可以使用“类名.”访问，也可以使用“引用.”访问，但规范上**统一推荐使用“类名.”访问**。

例如：

```java
public class Student {
    static String schoolName = "第一实验中学";
}
```

推荐写法是：

```java
System.out.println(Student.schoolName);
```

不推荐写成：

```java
Student s = new Student();
System.out.println(s.schoolName);
```

虽然这种写法语法上没问题，但它容易让别人误以为 `schoolName` 是某个对象自己的属性。实际上，`schoolName` 与 `s` 这个对象并没有本质关系，它属于 `Student` 这个类。

#### 为什么空引用访问静态变量不会空指针

这是一个很容易考、也很容易误解的点。

例如：

```java
public class School {
    static String city = "北京";
    String name;
}
School s = null;
System.out.println(s.city);
```

这段代码**不会**抛出空指针异常。原因不是因为“空引用突然也能访问成员了”，而是因为编译器发现 `city` 是静态变量，于是这句代码本质上会按“类级别访问”来处理，效果等价于：

```java
System.out.println(School.city);
```

因此，真正被访问的不是空引用 `s`，而是类 `School`。

但如果写成：

```java
System.out.println(s.name);
```

就会抛出空指针异常，因为 `name` 是实例变量，必须通过对象访问，此时 `s` 为空，当然无法继续访问。

> **结论：** 空引用访问**静态成员**不会空指针，因为访问的本质是类；空引用访问**实例成员**才会空指针。

### 静态方法

被 `static` 修饰的方法叫作**静态方法**。它和静态变量一样，也属于类，而不属于某个具体对象。

例如：

```java
public class MathTool {
    public static int add(int a, int b) {
        return a + b;
    }
}
```

调用时直接使用：

```java
System.out.println(MathTool.add(10, 20));
```

这里不需要先创建 `MathTool` 对象，因为 `add` 是类级别的方法。

#### 静态方法与实例方法的根本区别

静态方法和实例方法最根本的区别，不在于“写法不同”，而在于**是否依赖对象**。

| 对比项                 | 静态方法             | 实例方法          |
| ---------------------- | -------------------- | ----------------- |
| 所属                   | 类                   | 对象              |
| 调用方式               | 推荐 `类名.方法名()` | `对象名.方法名()` |
| 是否依赖对象           | 不依赖               | 依赖              |
| 是否能直接访问实例成员 | 不能                 | 能                |

#### 静态方法中为什么不能用 `this`

这是 `static` 最核心的规则之一。

前面学过，`this` 代表**当前对象**。而静态方法属于类，不依赖对象调用，因此在静态方法执行时，根本不存在“当前对象”这一说。

所以，在静态方法中不能写：

```java
this.doSomething();
```

也不能直接访问实例变量：

```java
System.out.println(name);
```

原因都是一样的：**静态方法没有当前对象，所以无法直接操作实例相关内容。**

虽然静态方法中不能**直接**访问实例成员，但可以**间接**访问：先创建对象，再通过对象访问。

例如：

```java
public class Demo {
    int num = 100;

    public void show() {
        System.out.println("show method");
    }

    public static void test() {
        Demo d = new Demo();
        System.out.println(d.num);
        d.show();
    }
}
```

这里 `test()` 是静态方法，它自己没有 `this`，也不能直接写 `num` 或 `show()`。但它可以先自己创建一个 `Demo` 对象，再通过这个对象来访问实例成员。

> **注意：** 静态方法不能直接访问实例成员，不等于“永远不能访问实例成员”。它只是必须先借助对象。

#### 什么情况下方法定义为静态方法

判断一个方法应不应该定义为静态方法，关键在于：**这个方法的执行是否依赖对象状态。**

##### 应定义为实例方法的情况

如果方法体中需要直接访问实例变量，或者直接调用实例方法，那么这个方法通常必须定义为**实例方法**。

例如：

```java
public class Account {
    double balance;

    public void printBalance() {
        System.out.println(balance);
    }
}
```

这里 `printBalance()` 明显依赖对象自己的 `balance`，所以必须是实例方法。

##### 适合定义为静态方法的情况

如果一个方法不依赖任何对象状态，只是完成某种通用计算、通用处理，那么通常适合定义为静态方法。最典型的就是**工具类方法**。

例如：

```java
public class StringTool {
    public static void printUpper(String str) {
        System.out.println(str.toUpperCase());
    }
}
```

这个方法只处理传入参数，不依赖某个 `StringTool` 对象本身，因此定义为静态方法更自然。

### 静态代码块

静态代码块的语法格式很简单：

```java
static {
    // 静态代码块
}
```

静态代码块会在**类加载时执行**，并且**只执行一次**。

例如：

```java
public class AppConfig {
    static {
        System.out.println("类加载了，开始执行初始化代码");
    }

    public static void main(String[] args) {
        System.out.println("main begin");
    }
}
```

运行后，静态代码块会先于 `main` 执行。

#### 静态代码块有什么用

静态代码块本质上代表的是一个**类加载时刻**。如果你有一段代码希望在这个时刻自动执行，就可以放进静态代码块中。

常见理解方式有：

- 初始化某些类级别数据；
- 做一次性准备动作；
- 打印类加载日志；
- 做简单配置读取等。

入门阶段可以先理解为：**如果有代码必须在类第一次被使用时执行一次，就可以考虑放到静态代码块中。**

#### 一个类中可以有多个静态代码块

一个类中可以写多个静态代码块，它们会按照**自上而下**的顺序依次执行。

例如：

```java
public class InitDemo {
    static {
        System.out.println("A");
    }

    static {
        System.out.println("B");
    }

    static {
        System.out.println("C");
    }
}
```

当这个类加载时，输出顺序一定是：

```java
A
B
C
```

这说明静态代码块之间的执行顺序，不是随机的，也不是按调用顺序，而是按**代码出现顺序**来定。

### 代码执行顺序

`static` 这一节最容易乱的地方，就是各种代码块、构造方法、`main` 方法混在一起时，到底先执行谁。

这一块必须建立清晰顺序。

#### 总体顺序

当一个类第一次被主动使用时，大致顺序可以概括为：

1. **类加载**
2. 执行**静态变量显式赋值**和**静态代码块**（按代码顺序）
3. 执行 `main` 方法
4. 创建对象时，再执行**实例变量显式赋值**和**构造代码块**（按代码顺序）
5. 最后执行**构造方法体**

也就是说：

- **静态相关的内容先于对象存在**
- **对象相关的内容只有在 `new` 时才执行**

#### 用一个新例子看执行顺序

```java
public class InitOrder {
    static {
        System.out.println("静态代码块1执行");
    }

    static int count = initCount();

    static {
        System.out.println("静态代码块2执行");
    }

    int x = initX();

    {
        System.out.println("构造代码块执行");
    }

    public InitOrder() {
        System.out.println("构造方法执行");
    }

    public static int initCount() {
        System.out.println("静态变量显式赋值执行");
        return 1;
    }

    public int initX() {
        System.out.println("实例变量显式赋值执行");
        return 100;
    }

    public static void main(String[] args) {
        System.out.println("main begin");
        new InitOrder();
        new InitOrder();
        System.out.println("main over");
    }
}
```

输出顺序为：

```java
静态代码块1执行
静态变量显式赋值执行
静态代码块2执行
main begin
实例变量显式赋值执行
构造代码块执行
构造方法执行
实例变量显式赋值执行
构造代码块执行
构造方法执行
main over
```

#### 为什么是这个顺序

可以按下面的逻辑理解：

1. 程序先使用 `InitOrder` 类，类开始加载；
2. 类加载时，先按顺序执行静态相关内容：
   - 第一个静态代码块
   - 静态变量显式赋值
   - 第二个静态代码块
3. 静态相关内容执行完后，进入 `main`；
4. `main` 中第一次 `new InitOrder()` 时，开始创建对象，依次执行：
   - 实例变量显式赋值
   - 构造代码块
   - 构造方法
5. 第二次 `new InitOrder()` 时，再重复一次对象初始化流程；
6. 最后继续执行 `main` 后面的语句。

## JVM 体系结构

### JVM 是一套规范

**JVM**（Java Virtual Machine，Java 虚拟机）首先对应的是一套规范，即 **Java Virtual Machine Specification**。规范规定了 Java 字节码如何执行、运行时数据区应有哪些部分、类加载与方法调用应遵循什么规则，但**规范本身不是具体程序**，真正运行 Java 程序的，是各家对这套规范的具体实现。

常见的 JVM 实现可以简单了解如下：

| 实现          | 简要说明                                                     |
| ------------- | ------------------------------------------------------------ |
| **HotSpot**   | 目前最常见的 JVM 实现，Oracle JDK 和 OpenJDK 默认都以它为代表 |
| **JRockit**   | Oracle 曾使用的一种面向生产环境优化的 JVM 实现               |
| **Azul Zing** | 更强调高性能、低暂停和实时处理能力的 JVM 实现                |
| **OpenJ9**    | IBM 主导的 JVM 实现，强调轻量、低延迟和可观测性              |

> **注意：** 平时我们学习 JVM 体系结构，默认主要以 **JVM 规范** 为主线，再辅以 **HotSpot** 作为最典型、最常见的代表实现来理解。二者相关，但不能直接画等号。

### JVM 规范重点关注什么

从当前学习阶段来看，JVM 中最值得重点掌握的是**运行时数据区**。因为前面学到的对象、栈帧、`static`、构造方法、方法调用、字符串常量池等内容，几乎都要落到运行时数据区上去理解。

JVM 规范中的运行时数据区，通常可以归纳为下面 6 个部分：

1. **程序计数器**（The pc Register）
2. **Java 虚拟机栈**（Java Virtual Machine Stacks）
3. **堆**（Heap）
4. **方法区**（Method Area）
5. **运行时常量池**（Run-Time Constant Pool）
6. **本地方法栈**（Native Method Stacks）

这 6 部分是**规范视角**下的划分方式。后面如果看到某些图里出现“年轻代、老年代、元空间、字符串常量池、代码缓存”等内容，那已经是在讲某个具体 JVM 实现的布局了，而不再只是规范中的抽象结构。

为了后续学习更清楚，可以先把这 6 个区域按“是否线程私有”和“主要作用”统一整理出来：

| 区域              | 是否线程私有         | 主要作用                                         |
| ----------------- | -------------------- | ------------------------------------------------ |
| **程序计数器**    | 是                   | 记录当前线程正在执行的字节码指令位置             |
| **Java 虚拟机栈** | 是                   | 存放栈帧，支持 Java 方法调用                     |
| **堆**            | 否                   | 存放对象实例和数组，是 GC 的主要工作区域         |
| **方法区**        | 否                   | 存放类级别信息，如类元数据、常量、静态相关信息等 |
| **运行时常量池**  | 否（逻辑上隶属于类） | 存放类在运行期使用的常量数据、字面量和符号引用   |
| **本地方法栈**    | 是                   | 为本地方法（Native Method）服务                  |

这里有一个很重要的认识：**不是所有运行时数据区都跟着 JVM 整体“统一创建、统一销毁”**。更准确地说：

- **堆、方法区**等共享区域，通常随着 JVM 启动而建立，并在 JVM 结束时销毁；
- **程序计数器、虚拟机栈、本地方法栈**属于线程私有区域，通常会随着线程的创建而创建，随着线程结束而销毁。

#### 程序计数器

**程序计数器**是一块很小的内存空间，它的作用可以简单理解为：**记录当前线程下一条将要执行的字节码指令位置**。因为 Java 程序的执行本质上是一条条字节码指令按顺序推进的，所以线程需要这样一个“位置记录器”来知道自己执行到哪里了。

之所以程序计数器要做成**线程私有**，是因为 Java 程序通常支持多线程。不同线程执行的代码位置可能完全不同，因此每个线程都必须拥有自己独立的程序计数器，互不干扰。

#### Java 虚拟机栈

**Java 虚拟机栈**是前面已经接触最多的区域之一。它是**线程私有**的，用于支持 Java 方法调用。每调用一个方法，就会为该方法创建一个对应的**栈帧**；方法执行结束，对应栈帧出栈。

一个栈帧中，重点关注以下内容：

- **局部变量表**：存放方法参数、局部变量，以及实例方法中的 `this`
- **操作数栈**：存放运算过程中的中间结果
- **动态链接**
- **方法返回地址**

前面学过的很多知识，实际上都和虚拟机栈直接相关。例如：

- 方法调用时为什么会压栈、弹栈；
- 局部变量为什么只在方法内部有效；
- `this` 为什么通常在局部变量表的 0 号槽位；
- 参数传递为什么本质上是“值复制”。

#### 堆

**堆**是 JVM 所管理的最大的一块内存区域，也是学习对象时最核心的区域之一。它是**线程共享**的，主要用于存放：

- **对象实例**
- **数组**

前面学过，执行 `new` 时，对象通常就是在堆中创建的。也正因为对象大多在堆中，所以垃圾回收器（GC）主要清理的也是堆里的无用对象。

#### 方法区

**方法区**也是 JVM 规范中的一个逻辑区域，主要用于存放**类级别的信息**，例如：

- 类的元信息；
- 方法相关信息；
- 常量；
- 静态相关信息；
- 运行时常量池等。

这里要特别注意：**方法区是规范概念**。它回答的是“JVM 应该有这样一个用于存储类级别信息的区域”，但至于具体怎么实现，不同 JVM 可以不同。

例如，在 HotSpot 中：

- **Java 8 之前**，通常使用**永久代**来实现方法区；
- **Java 8 及以后**，通常使用**元空间（Metaspace）**来实现方法区。

因此，看到“方法区”“永久代”“元空间”这几个词时，一定要分清层次：

| 名称       | 层次                                        |
| ---------- | ------------------------------------------- |
| **方法区** | JVM 规范中的逻辑区域                        |
| **永久代** | HotSpot 早期对方法区的一种实现方式          |
| **元空间** | HotSpot 在 Java 8+ 中对方法区的主要实现方式 |

> **注意：** 方法区 ≠ 永久代 ≠ 元空间，它们是“规范概念”和“具体实现”之间的关系，不能机械混为一谈。

#### 运行时常量池

**运行时常量池**是**方法区的一部分**。它可以理解为：**类或接口的常量池表在运行期间的表现形式**。其中会存放编译期生成、运行期需要使用的一些常量信息，常见包括：

- **字面量**（Literal），例如整数常量、字符串字面量等；
- **符号引用**（Symbolic Reference），例如类名、字段名、方法名及其描述信息等。

这里有两个容易混淆的点需要特别说明：

##### 1. 运行时常量池和字符串常量池不是一回事

前面学过的**字符串常量池**，更准确地说是 **String Table**，它是 HotSpot 中专门管理字符串字面量和 `intern()` 结果的一种结构；而**运行时常量池**是 JVM 规范层面的概念，属于方法区的逻辑范畴。二者都和“常量”有关，但不是同一个东西。

> **结论：** 运行时常量池是类级别常量信息的运行期表示；字符串常量池是 HotSpot 中专门管理字符串的一种结构。二者相关，但不能混为一谈。

##### 2. “字面量”和“符号引用”要分清

这里建议直接用规范术语，不用“字面量符号”这种容易混乱的说法。

| 类型         | 含义                           | 例子                                        |
| ------------ | ------------------------------ | ------------------------------------------- |
| **字面量**   | 代码中直接写出来的常量值       | `10`、`3.14`、`"hello"`                     |
| **符号引用** | 对类、字段、方法等的符号化描述 | `java/lang/String`、`println`、某字段描述符 |

例如，在下面这段代码里：

```java
String s = "hello";
```

- `"hello"` 属于**字面量**；
- `String` 这个类型、构造或方法的相关符号信息，则会以**符号引用**的形式出现在常量池相关结构中。

#### 本地方法栈

**本地方法栈**和 Java 虚拟机栈很相似，但它服务的不是普通 Java 方法，而是**本地方法**（Native Method）。如果某个方法不是用 Java 实现，而是通过其他语言或底层接口完成，那么执行过程中通常会使用到本地方法栈。

### JVM 规范的代表实现：HotSpot

在实际开发和学习中，最常见、最值得重点理解的 JVM 实现，就是 **HotSpot**。Oracle JDK 和 OpenJDK 默认都主要以 HotSpot 为代表，因此平时我们分析“对象在哪、字符串常量池在哪、类加载后元数据在哪”时，很多默认都是按 HotSpot 的思路来讲。

从当前学习阶段出发，可以把 **HotSpot（Java 8+）** 的常见内存布局先理解为下面这样：

```
JVM内存（以 HotSpot，Java 8+ 为例）
├── 堆（Heap） - 线程共享，主要存储对象实例和数组
│   ├── 年轻代（Young Generation）
│   │   ├── Eden
│   │   ├── Survivor 0
│   │   └── Survivor 1
│   ├── 老年代（Old Generation）
│   └── 字符串常量池（String Table）
│
├── 元空间（Metaspace） - 线程共享，方法区的主要实现，使用本地内存
│   ├── 类元信息
│   ├── 运行时常量池等类级别元数据
│   └── 其他与类相关的数据
│
├── Java 虚拟机栈（JVM Stacks） - 线程私有
│   └── 栈帧
│       ├── 局部变量表
│       ├── 操作数栈
│       ├── 动态链接
│       └── 方法返回地址
│
├── 本地方法栈（Native Method Stacks） - 线程私有
│
└── 程序计数器（PC Register） - 线程私有
```

这张图里有几处需要特别注意。

1. **字符串常量池在 HotSpot（Java 8+）中通常放在堆里理解。**前面已经讲过，从当前主流 **Java 8+** 的入门理解来看，**String Table** 通常放在堆中理解是合适的。这也是为什么前面分析字符串常量池时，会把它归入堆这一侧来讲。
1. **元空间使用的是本地内存。**元空间取代了永久代，它不再直接使用传统意义上的 Java 堆空间，而是使用**本地内存**。这也是 Java 8+ 和早期资料中一个很重要的区别。
1. **“JIT 编译后的代码”不要简单等同于“方法字节码”。**这里容易被很多示意图带偏。**方法字节码**本身属于类文件内容的一部分；而 **JIT 编译后的本地代码** 是运行期为了提速而生成的机器码，它和普通“方法字节码”不是一回事。入门阶段不必深究 Code Cache 等细节，但要知道：**字节码**和 **JIT 后的机器码**是两个层次的内容。

## 单例模式

### 设计模式概述

**设计模式**（Design Pattern）是软件开发中对常见问题解决方案的总结与抽象。它不是某一门语言独有的语法规则，也不是固定不变的模板，而是在长期开发实践中逐渐沉淀下来的、可以反复复用的设计经验。

从面向对象的角度看，设计模式主要关注三个问题：**对象如何创建、对象之间如何组织、对象之间如何协作**。学习设计模式，本质上是在学习如何写出**更易复用、更易扩展、更易维护**的代码。

#### 设计模式有哪些

设计模式并不只指 GoF 的 23 种模式。从更大的范围看，常见设计模式相关内容可以分为以下几类：

1. **GoF 设计模式**：由《Design Patterns: Elements of Reusable Object-Oriented Software》系统总结提出，作者是 Erich Gamma、Richard Helm、Ralph Johnson 和 John Vlissides，通常称为“四人组”（Gang of Four，GoF）。
2. **架构设计模式**：用于系统整体结构设计，例如多层架构、MVC、微服务、REST 等。
3. **企业级设计模式**：用于企业应用开发，例如 SOA、企业集成模式、业务流程建模等。
4. **领域驱动设计模式**：用于领域建模，例如实体、值对象、聚合、领域服务、领域事件等。
5. **并发设计模式**：用于处理多线程与并发问题，例如线程池、Actor、管道等。
6. **数据访问模式**：用于组织数据访问层，例如 DAO、Repository、Active Record 等。

#### GoF 设计模式的分类

GoF 设计模式通常分为三大类：

| **分类**       | **核心作用**                     | **关注点**                 |
| -------------- | -------------------------------- | -------------------------- |
| **创建型模式** | 解决对象创建问题                 | 对象怎么创建更合理         |
| **结构型模式** | 解决对象与对象之间的组合问题     | 类和对象如何组织           |
| **行为型模式** | 解决对象之间的职责分配与协作问题 | 对象之间如何通信、如何配合 |

其中，**单例模式**属于**创建型模式**。

### `==` 运算符

在学习单例模式时，经常会写出下面这样的判断：

```java
System.out.println(obj1 == obj2);
```

因此，先理解 `==` 很重要。

`==` 运算符永远比较的是**变量中保存的值**。只不过，不同类型变量中保存的值含义不同：

- 如果两边是**基本数据类型**，比较的是具体数值。
- 如果两边是**引用数据类型**，比较的是对象引用中保存的值。这个值可以理解为对象在内存中的标识位置，因此本质上比较的是：**两个引用是否指向同一个对象**。

#### 基本数据类型中的 `==`

例如：

```java
int a = 20;
int b = 20;
System.out.println(a == b); // true
```

这里 `a` 和 `b` 中保存的都是整数 `20`，所以结果为 `true`。

#### 引用数据类型中的 `==`

例如：

```java
StringBuilder sb1 = new StringBuilder("abc");
StringBuilder sb2 = new StringBuilder("abc");
System.out.println(sb1 == sb2); // false
```

虽然两个对象中的内容看起来一样，但 `sb1` 和 `sb2` 指向的是**两个不同对象**，因此结果是 `false`。

再看下面这个例子：

```java
StringBuilder sb1 = new StringBuilder("abc");
StringBuilder sb2 = sb1;
System.out.println(sb1 == sb2); // true
```

这里 `sb2` 直接接收了 `sb1` 保存的引用值，所以它们指向同一个对象，结果为 `true`。

#### 为什么单例模式中常用 `==`

单例模式的目的就是：**同一个类，无论获取多少次，拿到的都应该是同一个对象。**

因此，测试单例是否成功时，常常会这样写：

```java
Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();
System.out.println(s1 == s2); // 理论上应为 true
```

如果输出结果是 `true`，说明两次拿到的是**同一个对象**，这正是单例模式要达到的效果。

> **注意：** 在单例模式中，`==` 不是用来比较“内容是否相同”，而是用来验证“是不是同一个对象”。

### 单例模式的核心思想

**单例模式**（Singleton Pattern）是一种创建型设计模式，它要解决的核心问题是：**如何保证某个类在整个程序运行期间只创建一个对象，并且提供一个统一的访问入口。**

例如，一个系统中有些对象天然就适合只存在一份：

- 配置管理器
- 日志管理器
- 窗口管理器
- 任务调度中心

如果这些对象被随意创建多个实例，可能会导致**数据不一致、资源浪费、管理混乱**等问题。

要让一个类只能产生一个对象，通常要做到三件事：

1. **构造方法私有化**，不让外部直接 `new` 对象。
2. **在类的内部自己保存唯一实例**。
3. **对外提供公共的静态方法**，让外部通过这个方法获取唯一对象。

可以概括为一句话：**不让别人创建，只让自己创建；不让别人随便拿，只提供统一入口去拿。** 

### 单例模式的实现方式

单例模式的实现并不复杂，核心始终只有三点：**构造方法私有化**、**在类的内部保存唯一对象**、**对外提供统一的访问入口**。所谓“实现方式”的不同，本质上主要区别在于：**这个唯一对象是在类加载时创建，还是在第一次使用时创建。**

#### 饿汉式单例

**饿汉式**是指：**类一加载，唯一对象就立即创建好。** 这种写法的思路很直接：既然这个类最终只需要一个对象，那就在类初始化时一次性创建完成，后续外部无论调用多少次获取方法，返回的都是这个已经创建好的对象。

```java
public class Singleton2 {

    private static Singleton2 s = new Singleton2();

    private Singleton2() {
    }

    public static Singleton2 getInstance() {
        return s;
    }
}
```

这段代码中，`private static Singleton2 s = new Singleton2();` 是整个饿汉式实现的关键。`s` 是一个**静态变量**，属于类，不属于某个对象；并且它在**类加载**时就会完成初始化，因此 `Singleton2` 的唯一实例也会在这个阶段被创建出来。构造方法被 `private` 修饰后，外部代码就不能再通过 `new Singleton2()` 的方式创建对象，只能通过 `getInstance()` 取得这个已经准备好的实例。

之所以把这种方式叫“饿汉式”，就是因为对象创建得很早，**不管后面用不用，先创建出来再说**。例如，一个“系统配置信息类”几乎在程序启动后就一定会被使用，此时直接在类加载阶段创建对象，就是一种简单而自然的做法。

#### 懒汉式单例

**懒汉式**是指：**先不创建对象，等到第一次真正使用时再创建。** 这种写法更强调“按需创建”，也就是只有在外部第一次调用获取方法时，程序才会检查对象是否已经存在；如果还没有，才去创建这个唯一实例。

```java
public class Singleton {

    private static Singleton s;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (s == null) {
            s = new Singleton();
        }
        return s;
    }
}
```

这段代码中，`private static Singleton s;` 只是先声明了一个静态变量，但并没有立刻给它创建对象。第一次调用 `getInstance()` 时，程序会先判断 `s` 是否为 `null`。如果是 `null`，说明此前还没有创建过对象，此时才执行 `new Singleton()`；如果不为 `null`，说明唯一对象已经创建过了，直接返回即可。

懒汉式的关键不在于“写了一个 `if`”，而在于这个 `if` 背后的含义：**只在第一次需要时创建对象，后续始终复用第一次创建出来的那个对象。** 例如，一个“日志导出器”对象创建过程较重，而且程序运行过程中不一定会立刻使用它，那么采用懒汉式就更符合“需要时再创建”的思路。

#### 饿汉式与懒汉式的区别

| **实现方式** | **对象创建时机** | **特点**               | **适用理解**                   |
| ------------ | ---------------- | ---------------------- | ------------------------------ |
| **饿汉式**   | 类加载时创建     | 写法简单，先创建后使用 | 适合理解“类中提前准备唯一实例” |
| **懒汉式**   | 第一次调用时创建 | 按需创建，先使用再创建 | 适合理解“延迟加载”的思想       |
