## Java 新语法

Java 在 JDK 8 之后持续引入了许多语法增强，例如 JShell、`try-with-resources` 改进、局部变量类型推断、`instanceof` 模式匹配、`switch` 表达式、文本块、`record` 和密封类等。这些特性并没有改变 Java 的核心类型体系，而是让常见代码写法更加简洁、安全和可读。

### JShell

JShell 是 JDK 9 引入的交互式编程工具，全称可以理解为 Java Shell。它提供了 REPL（Read-Eval-Print Loop，读取、执行、打印循环）环境，可以直接输入 Java 语句并立即看到执行结果。

传统 Java 程序通常需要先定义类和 `main()` 方法：

```java
public class Test {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

使用 JShell 时，可以直接在命令行中输入语句：

```java
jshell> System.out.println("Hello World")
Hello World
```

JShell 适合快速测试代码片段、验证 API 用法、学习新语法和排查简单问题。例如：

```java
jshell> "hello world".substring(0, 5)
$1 ==> "hello"
```

常用命令包括：

| 命令       | 作用                     |
| ---------- | ------------------------ |
| `/list`    | 查看已经输入过的代码片段 |
| `/vars`    | 查看已经定义的变量       |
| `/methods` | 查看已经定义的方法       |
| `/save`    | 保存当前代码片段         |
| `/exit`    | 退出 JShell              |

> **补充**
>
> JShell 主要用于学习、验证和临时测试，不适合替代正式项目中的类、方法和单元测试。

### try-with-resources

程序中打开的系统资源，例如文件流、网络连接、数据库连接等，使用完毕后必须关闭。如果资源没有及时关闭，可能造成资源泄露，严重时会影响系统稳定性。

在 JDK 7 之前，资源关闭通常需要写在 `finally` 中：

```java
public void copyFile(File srcFile, File destFile) {
    FileInputStream fis = null;
    FileOutputStream fos = null;

    try {
        fis = new FileInputStream(srcFile);
        fos = new FileOutputStream(destFile);

        byte[] buffer = new byte[1024];
        int len;

        while ((len = fis.read(buffer)) != -1) {
            fos.write(buffer, 0, len);
        }
    } catch (IOException e) {
        e.printStackTrace();
    } finally {
        if (fis != null) {
            try {
                fis.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }

        if (fos != null) {
            try {
                fos.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }
    }
}
```

这种写法的问题是关闭逻辑冗长，资源越多，`finally` 中的嵌套越复杂。

JDK 7 引入了 `try-with-resources`，可以自动关闭资源：

```java
public void copyFile(File srcFile, File destFile) {
    try (FileInputStream fis = new FileInputStream(srcFile);
         FileOutputStream fos = new FileOutputStream(destFile)) {

        byte[] buffer = new byte[1024];
        int len;

        while ((len = fis.read(buffer)) != -1) {
            fos.write(buffer, 0, len);
        }
    } catch (IOException e) {
        e.printStackTrace();
    }
}
```

能放入 `try (...)` 中自动关闭的资源，必须实现 `java.lang.AutoCloseable` 接口。`AutoCloseable` 中定义了 `close()` 方法，`try-with-resources` 会在代码块结束时自动调用资源对象的 `close()` 方法。

JDK 9 对该语法进行了增强。如果资源变量已经在 `try` 之前创建，并且是 final 或等效 final，也可以直接在 `try(...)` 中引用：

```java
public void copyFile(File srcFile, File destFile) throws FileNotFoundException {
    FileInputStream fis = new FileInputStream(srcFile);
    FileOutputStream fos = new FileOutputStream(destFile);

    try (fis; fos) {
        byte[] buffer = new byte[1024];
        int len;

        while ((len = fis.read(buffer)) != -1) {
            fos.write(buffer, 0, len);
        }
    } catch (IOException e) {
        e.printStackTrace();
    }
}
```

这里的 `fis` 和 `fos` 在 `try` 中会被自动关闭。由于它们被作为资源引用，后续不能再修改其指向。

> **结论**
>
> `try-with-resources` 用于自动关闭资源，前提是资源类型实现了 `AutoCloseable`。它能显著减少手动关闭资源的模板代码，并降低资源泄露风险。

### 局部变量类型推断

JDK 10 引入了局部变量类型推断，可以使用 `var` 声明局部变量。编译器会根据变量初始化表达式推断出具体类型。

例如：

```java
var number = 123;
var message = "hello world";
var array = new int[] {11, 22, 33};
var list = new ArrayList<String>();
var calendar = Calendar.getInstance();
```

这些变量在编译期已经确定了具体类型：

| 写法                                     | 推断结果            |
| ---------------------------------------- | ------------------- |
| `var number = 123;`                      | `int`               |
| `var message = "hello world";`           | `String`            |
| `var array = new int[] {11, 22, 33};`    | `int[]`             |
| `var list = new ArrayList<String>();`    | `ArrayList<String>` |
| `var calendar = Calendar.getInstance();` | `Calendar`          |

`var` 并不表示 Java 变成了弱类型语言。它只是把显式类型交给编译器推断，变量一旦确定类型，后续仍然必须遵守静态类型检查。

```java
var number = 100;

// number = "abc"; // 编译错误，number 已经被推断为 int
```

`var` 只能用于局部变量，不能用于所有场景。以下写法不允许：

```java
// var name;                 // 错误：必须初始化
// var value = null;         // 错误：无法从 null 推断类型
// var function = x -> x;    // 错误：Lambda 表达式缺少目标类型
// var method = System.out::println; // 错误：方法引用缺少目标类型
// var array = {"aa", "bb"}; // 错误：数组静态初始化不能这样推断
```

`var` 也不能用于成员变量、方法参数、构造方法参数和方法返回值类型。

```java
public class User {
    // private var name; // 编译错误

    // public void setName(var name) {} // 编译错误
}
```

> **易错点**
>
> `var` 不是动态类型，也不是任意类型。它只是局部变量的编译期类型推断，变量类型在编译阶段已经确定。

### instanceof 模式匹配

传统 `instanceof` 写法中，判断对象类型后通常还需要手动向下转型：

```java
Animal animal = new Dog();

if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
    dog.show();
}
```

这种写法存在重复：先判断 `animal` 是否是 `Dog`，然后又把 `animal` 强制转换为 `Dog`。

`instanceof` 模式匹配在 JDK 14 作为预览特性引入，在 JDK 16 转正。它允许在 `instanceof` 判断中直接声明转换后的局部变量：

```java
Animal animal = new Dog();

if (animal instanceof Dog dog) {
    dog.show();
}
```

这段代码表示：如果 `animal` 是 `Dog` 类型，就把它转换为 `Dog` 并赋值给变量 `dog`。在 `if` 代码块中，可以直接使用 `dog` 调用 `Dog` 类型的方法。

在重写 `equals()` 方法时，这个特性也很常用：

```java
public class Tiger {
    private String name;
    private int age;

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null) return false;

        if (obj instanceof Tiger tiger) {
            return age == tiger.age && Objects.equals(name, tiger.name);
        }

        return false;
    }
}
```

相比传统写法，模式匹配减少了强制类型转换代码，也降低了变量类型写错的风险。

> **结论**
>
> `instanceof` 模式匹配把“类型判断”和“类型转换”合并在一起，使向下转型代码更简洁、更安全。

### switch 表达式

传统 `switch` 语句有一些常见问题：如果忘记写 `break`，后续 `case` 可能继续执行；多个 `case` 需要重复书写；整个 `switch` 不能直接作为表达式返回结果。

传统写法：

```java
public static String getSeason(int month) {
    String season;

    switch (month) {
        case 12:
        case 1:
        case 2:
            season = "白雪皑皑";
            break;
        case 3:
        case 4:
        case 5:
            season = "春意盎然";
            break;
        case 6:
        case 7:
        case 8:
            season = "夏日炎炎";
            break;
        case 9:
        case 10:
        case 11:
            season = "秋高气爽";
            break;
        default:
            throw new RuntimeException("没有该月份");
    }

    return season;
}
```

`switch` 表达式在 JDK 12、JDK 13 中作为预览特性演进，并在 JDK 14 转正。新写法可以直接返回结果：

```java
public static String getSeason(int month) {
    return switch (month) {
        case 12, 1, 2 -> "白雪皑皑";
        case 3, 4, 5 -> "春意盎然";
        case 6, 7, 8 -> "夏日炎炎";
        case 9, 10, 11 -> "秋高气爽";
        default -> throw new RuntimeException("没有该月份");
    };
}
```

新语法的特点包括：

1. 使用 `->` 简化分支。
2. 一个 `case` 可以匹配多个值。
3. 不需要手动书写 `break`。
4. 整个 `switch` 可以作为表达式返回结果。

如果某个分支需要写多条语句，可以使用 `yield` 返回该分支结果：

```java
public static String getSeason(int month) {
    return switch (month) {
        case 12, 1, 2:
            yield "白雪皑皑";
        case 3, 4, 5:
            yield "春意盎然";
        case 6, 7, 8:
            yield "夏日炎炎";
        case 9, 10, 11:
            yield "秋高气爽";
        default:
            throw new RuntimeException("没有该月份");
    };
}
```

`yield` 的作用是从 `switch` 表达式的某个分支中返回结果。

> **结论**
>
> `switch` 表达式解决了传统 `switch` 容易遗漏 `break`、分支书写重复、不能直接返回值等问题，使分支逻辑更紧凑、更安全。

### 文本块

在传统 Java 字符串中，如果要表示 HTML、XML、SQL、JSON 等多行文本，通常需要大量 `\n`、`\t` 和字符串拼接，代码可读性较差。

传统写法：

```java
String html = "<html>\n"
        + "\t<head>\n"
        + "\t\t<title>test page</title>\n"
        + "\t</head>\n"
        + "\t<body>\n"
        + "\t\t<h1>My First HTML Code!</h1>\n"
        + "\t</body>\n"
        + "</html>";
```

文本块使用三个双引号 `"""` 表示多行字符串。它在 JDK 13、JDK 14 中作为预览特性出现，并在 JDK 15 转正。

```java
String html = """
        <html>
            <head>
                <title>test page</title>
            </head>
            <body>
                <h1>My First HTML Code!</h1>
            </body>
        </html>
        """;
```

文本块可以保留多行结构，减少转义和拼接，使多行字符串更接近原始文本格式。

文本块还支持一些增强写法。例如，在行尾使用 `\` 可以取消该行末尾的换行：

```java
String json = """
        {
            "username": "jack",\
            "age": 18
        }
        """;
```

使用 `\s` 可以显式保留一个空格：

```java
String text = """
        name\s:\sjack
        """;
```

> **注意**
>
> 文本块适合表达多行文本，例如 HTML、SQL、JSON、XML 等。普通短字符串仍然使用普通双引号即可，不需要强行改成文本块。

### Record

`record` 是用于声明纯数据载体类的语法。它在 JDK 14、JDK 15 中作为预览特性出现，并在 JDK 16 转正。

传统数据类通常需要手动编写字段、构造方法、访问方法、`equals()`、`hashCode()` 和 `toString()`：

```java
public final class Tiger {
    private final String name;
    private final int age;

    public Tiger(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String name() {
        return name;
    }

    public int age() {
        return age;
    }
}
```

使用 `record` 可以简化为：

```java
public record Tiger(String name, int age) {
}
```

编译器会自动生成：

1. 私有 final 字段。
2. 全参数构造方法。
3. 访问方法，例如 `name()`、`age()`。
4. `equals()`。
5. `hashCode()`。
6. `toString()`。

使用方式：

```java
Tiger tiger = new Tiger("东北虎", 5);

System.out.println(tiger.name());
System.out.println(tiger.age());
System.out.println(tiger);
```

需要注意，record 的访问方法不是传统 JavaBean 风格的 `getName()`，而是与组件名同名的 `name()`。

`record` 默认是 final 的，不能被继承；其组件字段也是 final 的，创建对象后不能修改，因此它适合表示不可变的数据载体。

```java
public record User(String username, String email, int age) {
}
```

适合使用 record 的场景包括 DTO、VO、配置对象、接口返回结果等纯数据对象。不适合需要复杂继承关系、可变字段或大量业务行为的对象。

record 中也可以添加静态属性、静态方法和成员方法，还可以定义紧凑构造方法：

```java
public record Tiger(String name, int age) {
    static double score;

    public Tiger {
        if (age < 0) {
            throw new IllegalArgumentException("年龄不能为负数");
        }
        System.out.println("创建 Tiger 对象");
    }

    public void show() {
        System.out.println(name + "：" + age);
    }

    public static void method() {
        System.out.println("static method");
    }
}
```

这里的：

```java
public Tiger {
}
```

不是普通无参构造方法，而是 **紧凑构造方法**。它会在调用 record 的全参数构造方法时执行，常用于参数校验或规范化处理。

> **易错点**
>
> record 不能声明真正的无参构造方法来绕过组件初始化。`public Tiger { ... }` 是紧凑构造方法，不是无参构造方法。

### 密封类

密封类用于控制继承范围。使用 `sealed` 修饰的类可以明确指定哪些类允许继承它，从而避免任意类随意扩展父类。

密封类在 JDK 15、JDK 16 中作为预览特性出现，并在 JDK 17 转正。

基本写法：

```java
sealed class Animal permits Dog, Bird, Tiger {
}
```

`permits` 后面列出允许继承 `Animal` 的子类。没有出现在 `permits` 列表中的类，不能继承该密封类。

密封类的直接子类必须使用以下三个修饰符之一：

| 修饰符       | 含义                                     |
| ------------ | ---------------------------------------- |
| `final`      | 该子类不能继续被继承                     |
| `sealed`     | 该子类仍然是密封类，需要继续限制继承范围 |
| `non-sealed` | 该子类重新开放继承，后续可以被普通类继承 |

例如：

```java
sealed class Animal permits Dog, Bird, Tiger {
}

final class Tiger extends Animal {
}

non-sealed class Bird extends Animal {
}

sealed class Dog extends Animal permits SmallDog {
}

non-sealed class SmallDog extends Dog {
}
```

这段代码中：

1. `Tiger` 使用 `final`，不能再被继承。
2. `Bird` 使用 `non-sealed`，重新开放继承。
3. `Dog` 继续使用 `sealed`，所以它也必须指定允许继承自己的子类。
4. `SmallDog` 继承 `Dog`，并使用 `non-sealed` 重新开放继承。

> **结论**
>
> 密封类的核心作用是控制继承边界，让父类在编译期明确知道自己的直接子类范围。

### 密封接口

接口也可以使用 `sealed` 修饰，称为密封接口。密封接口需要通过 `permits` 指定允许实现它的类或允许继承它的子接口。

例如：

```java
public sealed interface InterA permits Student, InterB {
}
```

密封接口的实现类必须使用 `final`、`sealed` 或 `non-sealed` 修饰：

```java
non-sealed class Student implements InterA {
}
```

密封接口的子接口必须使用 `sealed` 或 `non-sealed` 修饰：

```java
non-sealed interface InterB extends InterA {
}
```

密封接口也可以和 record 搭配使用。由于 record 默认是 final 的，因此 record 可以作为密封接口允许的实现类型。

```java
sealed interface Flyable permits SuperMan {
}

record SuperMan(String name, int age) implements Flyable {
}
```

这段代码表示：`Flyable` 是密封接口，当前只允许 `SuperMan` 实现它，而 `SuperMan` 是一个 record，天然满足不能继续被继承的要求。

> **注意**
>
> 密封接口的实现类和子接口都必须对后续继承关系作出明确声明。实现类可用 `final`、`sealed`、`non-sealed`；子接口不能用 `final`，只能用 `sealed` 或 `non-sealed`。

## Java 新 API

JDK 9 之后，Java 在 API 层面也做了许多增强，例如 `String` 底层存储结构变化、`String` 新增常用方法、接口支持私有方法、不可变集合工厂方法、`Optional` API 等。这些变化主要用于提升内存利用率、增强代码表达能力、减少模板代码，并提升程序的健壮性。

### String 存储结构改变

在 JDK 8 及以前，`String` 底层使用 `char[]` 存储字符。由于 Java 中的 `char` 占 2 个字节，即使字符串中只包含英文字符、数字等 Latin-1 字符，每个字符也会占用 2 个字节。

从 JDK 9 开始，`String` 底层改为使用 `byte[]` 存储字符，并额外使用编码标记区分当前字符串采用 Latin-1 还是 UTF-16 编码。这一优化通常称为 **Compact Strings**。

可以简化理解为：

| JDK 版本     | `String` 底层主要存储结构 | 特点                                   |
| ------------ | ------------------------- | -------------------------------------- |
| JDK 8 及以前 | `char[]`                  | 每个字符固定占 2 字节                  |
| JDK 9 及以后 | `byte[]` + 编码标记       | 能根据字符内容选择更节省空间的存储方式 |

例如，字符串 `"abc"` 中的字符都可以用 1 个字节表示。若底层使用 `char[]`，每个字符都占 2 个字节；改为 `byte[]` 后，每个字符可以只占 1 个字节，从而节省内存空间。

> **注意**
>
> `String` 底层改为 `byte[]` 并不改变 `String` 对外表现。开发者正常使用字符串时不需要手动处理底层编码，但理解该变化有助于认识 JDK 对内存优化的思路。

### String 新增方法

JDK 11 和 JDK 12 为 `String` 增加了一些实用方法，用于判断空白、去除空白、重复字符串、按行拆分和缩进处理。

#### isBlank

`isBlank()` 用于判断字符串是否为空白字符串。它会把空格、制表符、换行符等空白字符都视为“空白”。

```java
boolean blank = "\t \n".isBlank();

System.out.println(blank); // true
```

`isBlank()` 与 `isEmpty()` 不同。`isEmpty()` 只判断长度是否为 0，而 `isBlank()` 判断内容是否全为空白字符。

```java
System.out.println("".isEmpty());      // true
System.out.println("   ".isEmpty());   // false

System.out.println("".isBlank());      // true
System.out.println("   ".isBlank());   // true
```

#### strip、stripLeading、stripTrailing

`strip()`、`stripLeading()` 和 `stripTrailing()` 用于去除字符串前后的空白字符。

| 方法              | 作用         |
| ----------------- | ------------ |
| `strip()`         | 去除前后空白 |
| `stripLeading()`  | 去除开头空白 |
| `stripTrailing()` | 去除末尾空白 |

例如：

```java
String source = "\u3000\u3000www.baidu.com\u3000\u3000";

System.out.println(source.strip());
System.out.println(source.stripLeading());
System.out.println(source.stripTrailing());
```

`\u3000` 是中文全角空格。相比早期常用的 `trim()`，`strip()` 按 Unicode 空白字符处理，在国际化文本中更合适。

> **结论**
>
> `trim()` 主要处理较早定义范围内的空白字符；`strip()` 基于 Unicode 空白判断，对中文全角空格等场景支持更好。

#### repeat

`repeat(int count)` 用于把字符串重复指定次数。

```java
String result = "xixi".repeat(3);

System.out.println(result); // xixixixixixi
```

适合生成重复分隔符、占位符或格式化输出内容。

#### lines

`lines()` 用于按照行分隔字符串，并返回一个 `Stream<String>`。

```java
Stream<String> lines = "a\nb\nc\n".lines();

System.out.println(lines.count()); // 3
```

`lines()` 常用于处理多行文本：

```java
String html = "<html>\n"
        + "\t<body>\n"
        + "\t\t<h1>Hello</h1>\n"
        + "\t</body>\n"
        + "</html>";

long lineCount = html.lines().count();

System.out.println(lineCount);
```

由于 `lines()` 返回的是 Stream，因此可以继续使用 Stream API 进行筛选、映射、统计等操作。

#### indent

JDK 12 增加了 `indent(int n)`，用于调整字符串每一行的缩进。

```java
String result = "Java Golang".indent(4);

System.out.println(result);
```

`indent(4)` 表示在每一行前增加 4 个空格；如果参数为负数，则表示尝试减少缩进。

### 接口支持私有方法

JDK 8 开始，接口中可以定义默认方法和静态方法。JDK 9 进一步允许接口中定义私有方法，包括私有实例方法和私有静态方法。

接口私有方法主要用于在接口内部复用代码，避免多个默认方法或静态方法中出现重复逻辑。

例如：

```java
public interface Flyable {

    default void fly() {
        checkState();
        System.out.println("fly...");
    }

    default void stop() {
        checkState();
        System.out.println("stop...");
    }

    private void checkState() {
        System.out.println("check state...");
    }

    static void info() {
        printInfo();
        System.out.println("Flyable interface");
    }

    private static void printInfo() {
        System.out.println("private static method");
    }
}
```

其中：

1. `private void checkState()` 是私有实例方法，只能被接口内部的默认方法调用。
2. `private static void printInfo()` 是私有静态方法，只能被接口内部的静态方法调用。
3. 接口私有方法不能被实现类直接调用。

> **结论**
>
> 接口私有方法用于抽取接口内部的公共逻辑，提升默认方法和静态方法的复用性；它不属于接口对外暴露的 API。

### 标识符命名变化

在 JDK 8 及以前，单独的下划线 `_` 可以作为变量名使用：

```java
String _ = "hello";
System.out.println(_);
```

从 JDK 9 开始，单独使用 `_` 作为标识符不再允许，会导致编译错误。

```java
// String _ = "hello"; // 编译错误
```

需要注意，`_` 不能单独作为标识符，但可以作为标识符的一部分：

```java
String user_name = "jack";
String _name = "lucy";
```

> **结论**
>
> JDK 9 之后，单独的 `_` 不能再作为变量名、方法名或其他标识符使用。

传统方式运行 Java 源文件需要两步：

```java

```

从 JDK 11 开始，Java 支持直接运行单个源代码文件：

```java

```

例如：

```java

```

可以直接执行：

这种方式会在内存中完成编译并立即运行，适合学习、演示和运行简单单文件程序。

> **注意**

### 创建不可变集合

JDK 9 为 `List`、`Set` 和 `Map` 提供了 `of()` 静态工厂方法，用于快速创建不可变集合。

```java
List<Integer> list = List.of(1, 2, 3, 4, 5);

Set<Integer> set = Set.of(1, 2, 3, 4, 5);

Map<Integer, String> map = Map.of(
        1, "张三",
        2, "李四",
        3, "王五"
);
```

通过 `of()` 创建的集合是不可变集合，不能添加、删除或修改元素。

```java
List<Integer> list = List.of(1, 2, 3);

// list.add(4);      // 抛出 UnsupportedOperationException
// list.remove(0);   // 抛出 UnsupportedOperationException
// list.set(0, 100); // 抛出 UnsupportedOperationException
```

`Set.of()` 中不能出现重复元素，否则会抛出 `IllegalArgumentException`。

```java
// Set.of(1, 2, 2); // 抛出 IllegalArgumentException
```

### Arrays.asList 和 List.of 的区别

`Arrays.asList()` 和 `List.of()` 都可以快速创建列表，但二者并不完全相同。

```java
List<Integer> list1 = Arrays.asList(1, 2, 3, 4, 5);

list1.set(2, 33); // 可以修改已有位置元素

// list1.add(6);     // 抛出 UnsupportedOperationException
// list1.remove(0);  // 抛出 UnsupportedOperationException
```

`Arrays.asList()` 返回的是一个固定长度列表，不能添加或删除元素，但可以修改已有位置上的元素。

```java
List<Integer> list2 = List.of(1, 2, 3, 4, 5);

// list2.add(6);     // 抛出 UnsupportedOperationException
// list2.remove(0);  // 抛出 UnsupportedOperationException
// list2.set(2, 33); // 抛出 UnsupportedOperationException
```

`List.of()` 返回的是不可变列表，不能添加、删除或修改元素。

| 对比项          | `Arrays.asList()` | `List.of()` |
| --------------- | ----------------- | ----------- |
| 是否可添加元素  | 不可以            | 不可以      |
| 是否可删除元素  | 不可以            | 不可以      |
| 是否可修改元素  | 可以              | 不可以      |
| 是否允许 `null` | 允许              | 不允许      |
| 集合特点        | 固定长度列表      | 不可变列表  |

> **易错点**
>
> `Arrays.asList()` 不是完全不可变集合，它只是长度固定；`List.of()` 创建的集合才是不可变集合。

## Optional API

`Optional` 是 JDK 8 引入的空值处理工具类。它是一个最多保存一个值的容器，用于显式表达“某个结果可能存在，也可能不存在”。

`Optional` 的目标不是消灭 `null`，而是让可能为空的结果更加明确，迫使调用者在使用结果之前考虑空值情况，从而减少空指针异常。

### Optional 的基本作用

传统代码中，如果对象链较长，容易出现空指针异常：

```java
Address address = user.getAddress();
System.out.println(address.getCity());
```

如果 `user` 或 `address` 为 `null`，代码就会抛出 `NullPointerException`。

传统判空写法通常比较冗长：

```java
if (user != null) {
    Address address = user.getAddress();
    if (address != null) {
        System.out.println(address.getCity());
    } else {
        System.out.println("未知");
    }
} else {
    System.out.println("未知");
}
```

使用 `Optional` 可以写成链式结构：

```java
String city = Optional.ofNullable(user)
        .map(User::getAddress)
        .map(Address::getCity)
        .orElse("未知");

System.out.println(city);
```

这段代码表示：

1. 如果 `user` 不为空，继续获取地址。
2. 如果地址不为空，继续获取城市。
3. 如果中间任何一步为空，最终返回 `"未知"`。

### 创建 Optional 对象

常见创建方式有三种：

| 方法                         | 说明                                                  |
| ---------------------------- | ----------------------------------------------------- |
| `Optional.empty()`           | 创建一个空的 Optional                                 |
| `Optional.of(value)`         | 创建一个包含非空值的 Optional，值为 `null` 时抛出异常 |
| `Optional.ofNullable(value)` | 值可以为空，若为空则创建空 Optional                   |

例如：

```java
Optional<String> empty = Optional.empty();

Optional<String> name = Optional.of("张三");

Optional<String> maybeName = Optional.ofNullable(null);
```

`of()` 不能接收 `null`：

```java
String value = null;

// Optional.of(value); // 抛出 NullPointerException
```

如果值可能为空，应使用 `ofNullable()`：

```java
Optional<String> optional = Optional.ofNullable(value);
```

> **易错点**
>
> 只要值可能为 `null`，就应使用 `Optional.ofNullable()`，不要使用 `Optional.of()`。

### 判断值是否存在

`isPresent()` 可以判断 `Optional` 中是否有值：

```java
Optional<User> userOpt = findUserById(1);

System.out.println(userOpt.isPresent());
```

如果希望有值时执行某个操作，可以使用 `ifPresent()`：

```java
userOpt.ifPresent(System.out::println);
```

也可以使用 `ifPresentOrElse()`，分别处理有值和无值两种情况：

```java
userOpt.ifPresentOrElse(
        user -> System.out.println("用户：" + user.getName()),
        () -> System.out.println("用户不存在")
);
```

`ifPresentOrElse()` 能让“有值时做什么”和“无值时做什么”放在同一段表达式中，逻辑更集中。

### 获取 Optional 中的值

`Optional` 提供了多种获取值的方式。实际开发中应优先使用安全方法，而不是直接调用 `get()`。

| 方法                                                   | 作用                                         |
| ------------------------------------------------------ | -------------------------------------------- |
| `get()`                                                | 有值时返回值，无值时抛出异常                 |
| `orElse(T other)`                                      | 有值返回值，无值返回默认值                   |
| `orElseGet(Supplier<? extends T> supplier)`            | 有值返回值，无值时调用 `Supplier` 生成默认值 |
| `orElseThrow()`                                        | 有值返回值，无值时抛出默认异常               |
| `orElseThrow(Supplier<? extends X> exceptionSupplier)` | 有值返回值，无值时抛出指定异常               |

`get()` 示例：

```java
Optional<String> optional = Optional.ofNullable("hello");

String value = optional.get();

System.out.println(value);
```

如果 `Optional` 为空，`get()` 会抛出异常。因此更推荐使用 `orElse()`：

```java
Optional<String> optional = Optional.ofNullable(null);

String value = optional.orElse("default name");

System.out.println(value);
```

`orElseGet()` 适合默认值需要计算或创建的场景：

```java
String value = optional.orElseGet(() -> getDefaultName());
```

当值不存在时抛出自定义异常：

```java
String value = optional.orElseThrow(() -> new RuntimeException("用户不存在"));
```

> **结论**
>
> `get()` 只有在确定 Optional 中一定有值时才使用。多数场景应优先使用 `orElse()`、`orElseGet()`、`orElseThrow()` 或 `ifPresent()`。

#### orElse 和 orElseGet 的区别

`orElse()` 和 `orElseGet()` 都能提供默认值，但默认值的计算时机不同。

```java
String name = optional.orElse(getDefaultName());
```

`orElse()` 中的参数会先被计算出来，即使 `optional` 中已经有值，`getDefaultName()` 也可能会被执行。

```java
String name = optional.orElseGet(() -> getDefaultName());
```

`orElseGet()` 接收的是 `Supplier`。只有当 `optional` 为空时，才会调用 `getDefaultName()`。

> **结论**
>
> 默认值已经存在、计算成本很低时可以使用 `orElse()`；默认值需要调用方法生成，或计算成本较高时，优先使用 `orElseGet()`。

### Optional 的 map 和 filter

`Optional` 支持类似 Stream 的函数式操作，但它不是 Stream。`Optional` 最多包含一个值，而 Stream 可以包含多个元素。

`map()` 用于在有值时进行转换：

```java
Optional<User> userOpt = findUserById(1);

Optional<String> nameOpt = userOpt.map(User::getName);
```

如果 `userOpt` 中有 `User` 对象，就提取用户名；如果为空，结果仍然是空 `Optional`。

`filter()` 用于在有值时判断是否保留该值：

```java
Optional<User> adultUser = userOpt.filter(user -> user.getAge() >= 18);
```

如果用户年龄大于等于 18，就保留该用户；否则返回空 `Optional`。

可以组合成链式操作：

```java
String result = userOpt
        .filter(user -> user.getAge() >= 18)
        .map(User::getName)
        .map(String::toUpperCase)
        .orElse("未找到符合条件的用户");
```

这段代码表示：

1. 用户存在且年龄大于等于 18 时继续处理。
2. 提取用户名。
3. 转换为大写。
4. 如果任一步为空或不满足条件，返回默认值。

### Optional 使用案例

需求：原计划让某位演员参加表演，如果该演员无法参加，则使用默认人选。

```java
String name = null;

String finalName = Optional.ofNullable(name)
        .orElse("佟丽娅");

System.out.println(finalName);
```

如果 `name` 不为 `null`，结果就是原来的名字；如果 `name` 为 `null`，结果就是默认值 `"佟丽娅"`。

处理对象链时，`Optional` 更能体现优势：

```java
Address address = new Address("北京");
User user = new User("张三", address);

String city = Optional.ofNullable(user)
        .map(User::getAddress)
        .map(Address::getCity)
        .orElse("未知");

System.out.println(city);
```

这段代码避免了多层 `if` 判空，使“可能为空”的处理逻辑更加集中。

### Optional 的使用边界

`Optional` 适合用于方法返回值，表示“结果可能不存在”。例如：

```java
public static Optional<User> findUserById(int id) {
    return Optional.ofNullable(new User("zhangsan"));
}
```

不建议把 `Optional` 用作普通成员变量类型，也不建议把它作为方法参数大量使用。它的主要设计目的，是让调用者看到返回值类型时就意识到：这个结果可能为空，需要处理。

> **注意**
>
> `Optional` 不是用来替代所有 `null` 的工具。它更适合用于返回值建模，表达“可能有结果，也可能没有结果”。

## Java 8 新日期 API

Java 8 引入了全新的日期时间 API，主要位于 `java.time` 包下。新日期 API 解决了旧版 `Date`、`Calendar`、`SimpleDateFormat` 在设计混乱、线程安全、时区处理和可读性方面的问题，是现代 Java 项目中处理日期时间的首选方案。

### 为什么需要新的日期 API

旧版日期 API 主要包括 `java.util.Date`、`java.util.Calendar` 和 `java.text.SimpleDateFormat`。这些类存在一些明显问题。

`Date` 的设计较早，很多方法已经过时，而且对象本身可变，在多线程环境下使用时不够安全。

`Calendar` 的使用方式也不够直观。例如月份从 `0` 开始：

```java
Calendar calendar = Calendar.getInstance();

// 这里的 11 实际表示 12 月
calendar.set(2023, 11, 25);
```

这种设计容易造成理解错误。

此外，旧 API 中日期、时间、时区概念混杂，处理国际化时间时比较繁琐。`SimpleDateFormat` 也不是线程安全的，如果作为共享对象使用，可能在多线程环境下产生错误结果。

新日期 API 的设计目标是让日期时间处理更加清晰、安全、易用。

### 新日期 API 的优势

Java 8 新日期 API 主要有以下优势：

| 优势           | 说明                                                       |
| -------------- | ---------------------------------------------------------- |
| 不可变对象     | 日期时间对象创建后不能修改，线程安全                       |
| 类型划分清晰   | 日期、时间、日期时间、时区时间分别由不同类表示             |
| 方法语义明确   | `plusDays()`、`minusMonths()`、`isBefore()` 等方法含义直观 |
| 时区支持完善   | 使用 `ZoneId`、`ZonedDateTime` 等类型处理时区              |
| 支持链式调用   | 日期时间计算可以连续调用，代码简洁                         |
| 格式化线程安全 | `DateTimeFormatter` 是线程安全的                           |

例如：

```java
LocalDate today = LocalDate.now();

LocalDate nextWeek = today.plusWeeks(1);
```

`plusWeeks(1)` 不会修改 `today`，而是返回一个新的 `LocalDate` 对象。

> **结论**
>
> 新日期 API 的核心特点是不可变、线程安全、类型清晰、时区处理能力更强。

### 主要类及其用途

`java.time` 包中常用类如下：

| 类                  | 作用                                         | 示例                                    |
| ------------------- | -------------------------------------------- | --------------------------------------- |
| `LocalDate`         | 只表示日期，不包含时间和时区                 | `2023-12-25`                            |
| `LocalTime`         | 只表示时间，不包含日期和时区                 | `14:30:00`                              |
| `LocalDateTime`     | 表示日期和时间，不包含时区                   | `2023-12-25T14:30:00`                   |
| `ZonedDateTime`     | 表示带时区的日期时间                         | `2023-12-25T14:30+08:00[Asia/Shanghai]` |
| `Instant`           | 表示时间线上的一个瞬时点，常用于时间戳       | `2023-12-25T06:30:00Z`                  |
| `Duration`          | 表示时间间隔，适合秒、分钟、小时等精确时间差 | `PT5H`                                  |
| `Period`            | 表示日期间隔，适合年、月、日差值             | `P1Y2M3D`                               |
| `DateTimeFormatter` | 日期时间格式化和解析工具                     | `yyyy-MM-dd HH:mm:ss`                   |

选择日期时间类时，应根据业务需求选择最合适的类型。如果只需要日期，使用 `LocalDate`；如果只需要时间，使用 `LocalTime`；如果涉及具体时区，使用 `ZonedDateTime` 或 `Instant`。

### 创建日期时间对象

新日期 API 通常通过 `now()`、`of()` 和 `parse()` 创建对象。

#### now

`now()` 用于获取当前日期、当前时间或当前日期时间：

```java
LocalDate today = LocalDate.now();
LocalTime nowTime = LocalTime.now();
LocalDateTime now = LocalDateTime.now();

System.out.println(today);
System.out.println(nowTime);
System.out.println(now);
```

`LocalDate.now()` 获取当前系统默认时区下的日期。

#### of

`of()` 用于创建指定日期时间：

```java
LocalDate date1 = LocalDate.of(2008, 1, 1);
LocalDate date2 = LocalDate.of(2008, Month.JANUARY, 1);

LocalTime time = LocalTime.of(14, 30, 30);

LocalDateTime dateTime = LocalDateTime.of(
        2025,
        Month.JANUARY,
        1,
        14,
        20,
        30
);
```

与旧版 `Calendar` 不同，`LocalDate.of(2008, 1, 1)` 中的 `1` 就表示一月，不再从 `0` 开始。

#### parse

`parse()` 用于把字符串解析为日期时间对象。

```java
LocalDate date = LocalDate.parse("2008-08-09");

LocalDateTime dateTime = LocalDateTime.parse("2025-10-20T14:15:30");
```

`LocalDateTime` 默认支持的格式中，日期和时间之间使用 `T` 连接。

如果字符串格式是：

```java
2025-10-20 14:15:30
```

则不能直接使用默认 `parse()` 解析，需要指定格式化器：

```java
DateTimeFormatter formatter =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

LocalDateTime dateTime = LocalDateTime.parse(
        "2025-10-20 14:15:30",
        formatter
);
```

> **易错点**
>
> `LocalDateTime.parse("2025-10-20 14:15:30")` 默认无法解析，因为默认格式要求日期和时间之间使用 `T`，即 `2025-10-20T14:15:30`。

### 日期计算

新日期 API 提供了大量 `plus` 和 `minus` 方法，用于进行日期时间加减。

```java
LocalDate today = LocalDate.now();

LocalDate nextWeek = today.plusWeeks(1);

LocalDate lastMonth = today.minusMonths(1);
```

时间也可以加减：

```java
LocalDateTime now = LocalDateTime.now();

LocalDateTime threeHoursLater = now.plusHours(3);
```

需要注意，所有日期时间对象都是不可变对象。加减操作不会修改原对象，而是返回一个新对象。

```java
LocalDate today = LocalDate.now();

today.plusDays(1); // 原对象不会改变

LocalDate tomorrow = today.plusDays(1); // 应接收返回的新对象
```

> **结论**
>
> 新日期 API 的修改类方法都不会改变原对象，而是返回新的日期时间对象。

### 日期调整

除了简单加减，`LocalDate` 还可以配合 `TemporalAdjusters` 进行更复杂的日期调整。

调整到下一个星期一：

```java
LocalDate today = LocalDate.now();

LocalDate nextMonday = today.with(
        TemporalAdjusters.next(DayOfWeek.MONDAY)
);
```

调整到当月最后一天：

```java
LocalDate lastDayOfMonth = today.with(
        TemporalAdjusters.lastDayOfMonth()
);
```

调整到当月第一个星期一：

```java
LocalDate firstMonday = today.with(
        TemporalAdjusters.firstInMonth(DayOfWeek.MONDAY)
);
```

如果内置调整器无法满足需求，也可以自定义调整规则。例如，获取下一个工作日：

```java
LocalDate today = LocalDate.parse("2025-10-24");

LocalDate nextWorkDay = today.with(temporal -> {
    DayOfWeek day = DayOfWeek.from(temporal);

    int daysToAdd = 1;

    if (day == DayOfWeek.FRIDAY) {
        daysToAdd = 3;
    } else if (day == DayOfWeek.SATURDAY) {
        daysToAdd = 2;
    }

    return temporal.plus(daysToAdd, ChronoUnit.DAYS);
});
```

这段代码的逻辑是：

1. 如果当前是周五，下一个工作日是下周一，需要加 3 天。
2. 如果当前是周六，下一个工作日是下周一，需要加 2 天。
3. 如果当前是周日到周四，加 1 天即可。

> **结论**
>
> `TemporalAdjusters` 用于处理“下一个星期一”“当月最后一天”等规则性日期调整；自定义调整器可以处理更复杂的业务日期规则。

### 日期比较和判断

新日期 API 提供了语义明确的比较方法。

判断日期是否在另一个日期之前：

```java
LocalDate today = LocalDate.now();
LocalDate birthday = LocalDate.of(1999, 1, 1);

boolean before = birthday.isBefore(today);
```

判断时间是否在另一个时间之后：

```java
LocalTime meetingTime = LocalTime.parse("15:20:20");

boolean after = meetingTime.isAfter(LocalTime.now());
```

判断两个日期是否相等：

```java
boolean equal = today.isEqual(LocalDate.now());
```

也可以判断某一年是否为闰年：

```java
boolean leapYear = today.isLeapYear();
```

判断是否为周末：

```java
boolean weekend =
        today.getDayOfWeek() == DayOfWeek.SATURDAY
                || today.getDayOfWeek() == DayOfWeek.SUNDAY;
```

> **注意**
>
> 比较日期时间对象时，不要使用 `==` 判断内容是否相等。`==` 比较的是引用地址，应使用 `equals()`、`isEqual()`、`isBefore()`、`isAfter()` 等方法。

### 日期时间信息获取

`LocalDate` 可以获取日期的各个组成部分：

```java
LocalDate today = LocalDate.now();

int year = today.getYear();
Month month = today.getMonth();
int day = today.getDayOfMonth();
DayOfWeek dayOfWeek = today.getDayOfWeek();

System.out.println(year);
System.out.println(month);
System.out.println(day);
System.out.println(dayOfWeek);
```

`LocalTime` 可以获取时间组成部分：

```java
LocalTime nowTime = LocalTime.now();

int hour = nowTime.getHour();
int minute = nowTime.getMinute();
int second = nowTime.getSecond();
int nano = nowTime.getNano();

System.out.println(hour);
System.out.println(minute);
System.out.println(second);
System.out.println(nano);
```

这些方法名称清晰，能够直接表达获取的信息类型。

### 日期格式化与解析

`DateTimeFormatter` 用于日期时间和字符串之间的相互转换。

#### 日期时间转字符串

```java
LocalDateTime now = LocalDateTime.now();

DateTimeFormatter formatter =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

String text = now.format(formatter);

System.out.println(text);
```

也可以使用中文格式：

```java
DateTimeFormatter chineseFormatter =
        DateTimeFormatter.ofPattern("yyyy年MM月dd日 HH时mm分");

String text = now.format(chineseFormatter);
```

#### 字符串转日期时间

```java
DateTimeFormatter formatter =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

LocalDateTime dateTime = LocalDateTime.parse(
        "2008-10-11 20:20:20",
        formatter
);
```

`DateTimeFormatter` 是不可变且线程安全的，因此可以作为静态常量共享使用：

```java
private static final DateTimeFormatter FORMATTER =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
```

> **结论**
>
> 新日期 API 中应使用 `DateTimeFormatter` 替代旧版 `SimpleDateFormat`，尤其在多线程环境中更安全。

### 时区处理

如果系统涉及国际化时间，就必须明确处理时区。`LocalDate`、`LocalTime` 和 `LocalDateTime` 都不包含时区信息。处理时区时，应使用 `ZoneId`、`ZonedDateTime` 或 `Instant`。

获取所有可用时区 ID：

```java
Set<String> zoneIds = ZoneId.getAvailableZoneIds();

zoneIds.forEach(System.out::println);
```

获取指定时区当前时间：

```java
ZonedDateTime beijingTime =
        ZonedDateTime.now(ZoneId.of("Asia/Shanghai"));
```

将北京时区时间转换为纽约时区的同一时刻：

```java
ZonedDateTime newYorkTime = beijingTime.withZoneSameInstant(
        ZoneId.of("America/New_York")
);
```

获取系统默认时区当前时间：

```java
ZonedDateTime defaultZoneTime = ZonedDateTime.now();
```

`withZoneSameInstant()` 表示保持时间线上的同一个瞬时点不变，只改变展示时区。例如，北京时间的某一刻转换为纽约时间后，日期和钟表时间可能不同，但它们表示的是同一真实时刻。

> **注意**
>
> 国际化系统中，数据库通常建议存储 UTC 时间或时间戳，展示时再按照用户所在时区转换。不要在跨时区系统中只保存无时区含义的本地时间。

### Instant

`Instant` 表示时间线上的一个瞬时点，通常用于时间戳、日志时间、数据库时间等场景。它默认基于 UTC。

```java
Instant now = Instant.now();

System.out.println(now);
```

`Instant` 可以与带时区的时间互相转换：

```java
ZonedDateTime zonedDateTime = now.atZone(ZoneId.of("Asia/Shanghai"));

Instant instant = zonedDateTime.toInstant();
```

如果业务关心的是“某个真实发生的时刻”，例如订单创建时间、日志记录时间、消息发送时间，`Instant` 通常比 `LocalDateTime` 更适合存储。

### 时间间隔计算

新日期 API 提供了两个常用间隔类型：`Period` 和 `Duration`。

#### Period

`Period` 用于计算日期之间的间隔，关注年、月、日。

```java
LocalDate startDate = LocalDate.of(1999, 3, 7);
LocalDate endDate = LocalDate.of(2000, 12, 8);

Period period = Period.between(startDate, endDate);

System.out.println(period.getYears());
System.out.println(period.getMonths());
System.out.println(period.getDays());
```

需要注意，`period.getMonths()` 和 `period.getDays()` 不是总月数和总天数，而是“年月日拆分之后的月部分和日部分”。

例如一个间隔可能表示为：

```java
P1Y9M1D
```

这表示相差 1 年 9 个月 1 天，`getMonths()` 返回的是 `9`，不是总月数。

如果需要计算两个日期之间的总天数，可以使用：

```java
long days = ChronoUnit.DAYS.between(startDate, endDate);
```

#### Duration

`Duration` 用于计算时间之间的间隔，关注秒、纳秒，也常用于小时、分钟、秒的差值计算。

```java
LocalDateTime start = LocalDateTime.of(2023, 12, 1, 9, 0);
LocalDateTime end = LocalDateTime.of(2023, 12, 25, 18, 0);

Duration duration = Duration.between(start, end);

long hours = duration.toHours();
long days = duration.toDays();

System.out.println(hours);
System.out.println(days);
```

`Duration` 更适合处理精确时间段，例如任务耗时、接口响应时间、缓存过期时间等。

| 类型       | 适合场景                       |
| ---------- | ------------------------------ |
| `Period`   | 日期差，按年、月、日理解       |
| `Duration` | 时间差，按时、分、秒、纳秒理解 |

> **结论**
>
> 处理日期段使用 `Period`，处理精确时间间隔使用 `Duration`。如果需要总天数、总小时数，应使用 `ChronoUnit` 或 `Duration` 的转换方法。

### 与旧 Date 互操作

在实际项目中，可能仍然需要和旧 API、数据库驱动或第三方库交互，因此需要掌握 `Date` 和新日期 API 的互转。

#### Date 转 LocalDateTime

```java
Date oldDate = new Date();

LocalDateTime newDateTime = oldDate.toInstant()
        .atZone(ZoneId.systemDefault())
        .toLocalDateTime();

System.out.println(newDateTime);
```

转换过程为：

1. `Date` 转为 `Instant`。
2. `Instant` 结合系统默认时区变为 `ZonedDateTime`。
3. 从 `ZonedDateTime` 中取出 `LocalDateTime`。

#### LocalDateTime 转 Date

```java
LocalDateTime localDateTime = LocalDateTime.now();

Date date = Date.from(
        localDateTime
                .atZone(ZoneId.systemDefault())
                .toInstant()
);

System.out.println(date);
```

`LocalDateTime` 本身没有时区信息，因此转换为 `Date` 时必须指定 `ZoneId`。不同 `ZoneId` 会影响最终对应的真实时间点。

> **易错点**
>
> `LocalDateTime` 不包含时区。将它转换为 `Date` 或 `Instant` 时，必须结合明确的时区，否则容易产生时间偏移问题。

### 常见使用建议

#### 新项目优先使用 java.time

新项目中应优先使用 `java.time` 包下的新日期 API，不建议继续使用 `Date` 和 `Calendar` 处理业务日期时间。

#### 根据需求选择合适类型

如果只需要日期，使用 `LocalDate`：

```java
LocalDate birthday = LocalDate.of(1999, 1, 1);
```

如果只需要时间，使用 `LocalTime`：

```java
LocalTime meetingTime = LocalTime.of(15, 30);
```

如果需要日期和时间，但不关心时区，使用 `LocalDateTime`：

```java
LocalDateTime meeting = LocalDateTime.of(2025, 10, 20, 14, 30);
```

如果需要明确时区，使用 `ZonedDateTime`：

```java
ZonedDateTime time = ZonedDateTime.now(ZoneId.of("Asia/Shanghai"));
```

如果需要表示时间线上的一个真实瞬时点，使用 `Instant`：

```java
Instant createdAt = Instant.now();
```

#### 明确处理时区

涉及跨国家、跨地区用户的系统，应明确存储和展示规则。常见做法是存储 UTC 时间，展示时根据用户所在时区转换。

```java
Instant now = Instant.now();

ZonedDateTime userTime = now.atZone(ZoneId.of("Asia/Shanghai"));
```

#### 不要忽略不可变性

日期时间对象修改后必须接收返回值：

```java
LocalDate date = LocalDate.now();

date = date.plusDays(1);
```

错误理解是认为 `plusDays()` 会直接修改原对象。事实上，它只返回一个新对象。

#### DateTimeFormatter 可以共享

`DateTimeFormatter` 是线程安全的，可以定义为静态常量：

```java
private static final DateTimeFormatter FORMATTER =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
```

这比旧版 `SimpleDateFormat` 更适合多线程环境。
