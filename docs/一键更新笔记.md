# 双击更新笔记

此BAT使用自身目录定位仓库，可重命名本地文件夹，不要删除.git。应在已部署仓库的content内修改笔记、public内维护图片、config内维护分类。

双击根目录publish-notes.bat，执行本地完整构建、内容检查、发布目录检查，随后检查远端、提交并推送。默认分支有新推送后，GitHub自动构建并部署；本地推送成功不代表远端部署已经完成，请查看Actions。

脚本提交content、public、config、本脚本及BAT、site.yml、README、发布说明和本说明，包括这些目录下的删除。也会提交web、src、scripts目录和依赖配置，确保界面更新与笔记一同发布。存在预先暂存的修改、非默认分支、远端有新提交、检查失败或推送失败时停止；不自动合并、不强制推送、不丢弃修改。推送失败后修复网络，再双击可重试已有提交。

首次脚本自身和工作流尚未推送时，双击即可一并提交，开始启用自动发布。当前默认分支为master。仓库代理仍使用原有Git配置，不在脚本中写死代理端口。

仅检查、不提交：在仓库根目录运行 node scripts/publish-notes.mjs --check-only。

本地文件夹可改名，例如我的笔记或notes-blog；先关闭使用该目录的终端、编辑器和开发服务，资源管理器重命名后，从新路径重新打开。不影响GitHub仓库名和网站网址。

如果先在 GitHub 网页上传了笔记，本地不会自动变化。关闭正在运行的开发服务，在仓库终端执行 `git pull --ff-only`，再继续本地编辑；有冲突时先处理提示，不要强制推送。


网络连接：本机当前仓库已设置 `http.proxy=http://127.0.0.1:7897`、`http.version=HTTP/1.1`，只影响本仓库，不随 Git 提交上传。发布时保持代理运行；若代理端口变化，需要更新此仓库的代理配置。远端检查遇到连接重置等临时网络错误最多尝试 3 次；其他错误立即停止，仍不会强制推送或自动合并。
