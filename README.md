# 我的笔记：使用与编写手册

这个项目把 Markdown 笔记生成静态网站，用于 GitHub Pages。Java 21 负责生成网页，Vue 3 和 TypeScript 提供搜索、目录、阅读设置和浏览器本地记录。访问者无需安装 Java，也不需要账号。

**新笔记以本手册为准，不必沿用原 Jekyll 网站的文件名、日期前缀或模板语法。**

## 启动与检查

### 首次使用

需要 **JDK 21、Node.js 22（至少 22.12）**，`JAVA_HOME` 指向 JDK 21。首次安装和构建需要联网。

在 PowerShell 中执行：

```powershell
cd D:\Code\Projects\notes-garden
npm.cmd ci
npm.cmd run build
npm.cmd run preview
```

打开 <http://127.0.0.1:4173/>。预览只监听本机；终端需保持运行，按 `Ctrl+C` 停止。

### 安装依赖遇到 EPERM / 文件被占用

`npm.cmd ci` 只在首次准备或依赖需要重新安装时执行，不是每次新增笔记都要执行。它会清理并重建 `node_modules`；安装时不能同时运行使用这些依赖的开发或构建进程。

若报 Rollup 文件无法删除，先在运行 `npm.cmd run dev`、Vite 或构建的项目终端按 `Ctrl+C`，等待停止，再执行 `npm.cmd ci`。不要直接结束电脑上所有 Node 进程，也不必先尝试管理员权限。安装必须成功后再运行构建。安装失败后的缺少 `vue-tsc` 通常是依赖目录只完成了部分清理，不是笔记语法错误。

### 修改笔记后

`preview` **只展示生成结果，不会自动构建**。修改原稿后运行：

```powershell
npm.cmd run build
```

构建成功后刷新浏览器。已经有预览服务运行时，不必重复启动；否则再执行 `npm.cmd run preview`。端口占用通常意味着已有预览终端在运行。

也可以使用开发模式：

```powershell
npm.cmd run dev
```

它会构建、启动预览，并监视笔记、配置、Java 源码、网页模板、界面文件和 `public/` 图片资源。界面变化会先构建前端，再更新网页引用；连续保存会合并排队处理，构建失败后修正并保存即可重试。**看到构建成功后手动刷新浏览器**。修改依赖或构建脚本后应停止并重新启动开发模式。

### 检查命令

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run test:content
```

分别执行前端类型检查、完整构建及 Java 测试、生成页面检查。最后一项需要先构建成功，检查内部链接、资源、锚点、搜索和语法样例，不保证外部网址可访问。

内容检查会根据生成目录动态核对各分类篇数与文章总数，新增笔记不需要修改数量常量。脚本还保留指定语法样例和历史链接检查；若删除或改名这些测试样例，应同步维护对应断言。

构建自动准备项目内的 Maven 3.9.9，并检查下载文件 SHA-512；也提供 `mvnw` / `mvnw.cmd`。

## 新建笔记和命名规则

### 推荐使用命令

```powershell
npm.cmd run new-note -- --folder java --title "数组的使用"
```

程序会创建类似 `content/java/java-a1b2c3d4.md` 的文件，随机部分由程序生成；同时填写当前日期、分类内最大顺序值加一及 `draft: true`。完成编辑后改为 `draft: false`，重新构建，才会在网站显示。

分类必须已配置，并且存在对应的 `content/<分类ID>/` 目录。

### 文件名、ID、标题和顺序不同

| 项目 | 示例 | 实际作用 |
| --- | --- | --- |
| 文件名 | `java-arrays.md` | 本地文件名，不直接决定网页标题、网址和顺序；重命名时保留 `.md` 后缀和原 `id` |
| `id` | `java-arrays` | 网页地址 `/read/java-arrays/` 及本机记录对应关系 |
| `title` | `"数组的使用"` | 页面主标题、列表、侧栏及搜索中的文章名称 |
| `order` | `27` | 同一分类内的章节顺序及上一篇、下一篇 |

本站推荐约定：

1. 使用 UTF-8 编码，推荐无 BOM；扩展名使用小写 `.md`。
2. 文件名与 `id` 一致，例如 `java-arrays.md` 对应 `id: java-arrays`。这是维护约定，不是强制文件名校验。
3. `id` 必须以小写英文字母开头，其余只允许小写字母、数字和连字符 `-`，并且全站唯一。分类 ID 同样如此。
4. `id` 不用中文、空格、大写字母、下划线或斜杠。例如 `java-arrays` 合法，`Java_数组`、`02-java` 不合法。
5. 发布后尽量不改 `id`，否则网址会变化，旧收藏和阅读记录也不能自动迁移。只改文件名或 `title` 可以不改变网址。
6. 中文标题放在 `title`，不要求文件名携带中文、日期或顺序号。
7. 现有 `java-01.md` 等文件可以保留，不需要全部改成新建命令的随机 ID 样式。

若想在文章名称中显示序号，可填写 `title: "27 - 数组的使用"`。程序不会根据 `order` 自动重写文章名称，修改顺序时自行决定是否同步修改标题序号。

**文章标题中的序号，与正文小节的自动编号相互独立。** 阅读设置里的自动编号仅处理正文标题。

## 笔记头部信息

每篇笔记必须从 YAML 头部开始，两行独立的 `---` 包围。第一行之前不要加空行或说明文字。

```yaml
---
id: java-arrays
title: "数组的使用"
folder: java
order: 27
date: 2026-10-29
updated: 2026-10-29
tags: [Java, 数组, 基础语法]
description: "介绍数组的声明、初始化与遍历。"
pinned: false
draft: false
---
```

| 字段 | 规则及显示影响 |
| --- | --- |
| `id` | 必填，符合上一节规则；决定稳定文章地址。 |
| `title` | 必填，非空字符串。推荐双引号包围，避免冒号等字符被 YAML 误解。 |
| `folder` | 必填，写已配置的分类 ID，不是中文分类名称；每篇只属于一个分类。 |
| `order` | 建议填写整数，不加引号；缺省为 `1000`。推荐分类内不重复。 |
| `date` | 必填，真实有效的 `YYYY-MM-DD` 日期。 |
| `updated` | 建议填写，格式同上；省略沿用 `date`。影响“更新于”、最近更新和更新时间排序。改正文后需手动更新，不读取文件修改时间或 Git 历史。 |
| `tags` | YAML 列表，例如 `[Java, 数组]`；无标签用 `[]`。不能是逗号拼接的普通字符串，标签前不加 `#`。 |
| `description` | 可选，纯文本摘要，不写 Markdown 排版。省略时提取第一个不在引用块内的正文段落，过长截断。用于页面说明等；当前紧凑列表不逐行显示摘要。 |
| `draft` | 布尔值 `true` / `false`，不要加引号。为 `true` 时不生成文章页，不进入目录、搜索或相邻文章导航。省略按非草稿处理。 |
| `pinned` | 保留的布尔字段。新版首页没有“置顶笔记”区，设为 `true` 不会自动排到列表第一；顺序仍由 `order` 控制。 |
| `legacyUrls` | 可选，旧 `.html` 路径列表，生成旧地址迁移页；普通新笔记不必填写。 |

YAML 缩进用空格，带特殊字符的标题和标签应加引号。布尔值不能写成字符串 `"true"` / `"false"`。

草稿只是不出现在生成的网站中，**公开 GitHub 仓库中的草稿源文件仍然公开**。

旧链接写法：

```yaml
legacyUrls:
  - /java/笔记/2026-03-14-旧文章.html
```

旧路径以 `/` 开头，保留原大小写和标点，不要重复配置。当前生成器从各笔记的 `legacyUrls` 读取迁移路径；仅修改迁移记录 JSON，不等于为新笔记配置了重定向。迁移页保留查询参数和章节标识，但不能自动修复已改名的旧章节。

## 分类、排序与标签

### 单层分类

网页是单层分类，分类下面直接列笔记，不提供分类套分类。虽然生成器递归扫描 `content/`，但磁盘嵌套目录不会自动生成多层导航；实际归类看 `folder`。推荐始终使用 `content/<分类ID>/<笔记ID>.md`。

新增分类时，在 `config/site.yml` 的 `folders` 中增加定义，并创建对应目录：

```yaml
  - id: algorithms
    name: 算法笔记
    description: 数据结构与算法的学习记录。
    color: blue
```

对应目录 `content/algorithms/`，笔记头部填写 `folder: algorithms`。主页和侧栏分类顺序按配置先后排列，中文名称取自 `name`。

旧配置的 `eyebrow` 是原界面遗留字段，当前不显示这类装饰性英文，可以不填写。`color` 是保留样式字段；目前分类图标和卡片主要跟随全站主题，不应依靠它指定每个分类的固定配色。

### 顺序

- 侧栏笔记列表、上一篇和下一篇：同分类按 `order` 从小到大，同值再按 `id` 排列。
- 分类页：默认按章节排序，可切换最近更新或标题排序。
- 全部笔记：默认最近更新；选择按章节排序时，先按分类 ID，再按 `order`。
- 首页最近更新：按 `updated` 从新到旧，最多 6 篇，不受手动调整 `order` 的影响。

顺序值不要求连续，可以用 `10、20、30`，方便以后插入 `15`。新建工具使用现有最大值加一。

### 标签

```yaml
tags: [Java, 集合, 面向对象]
```

同一篇可以有多个标签，用于列表筛选。统一大小写和用词，`Java` 与 `java` 被当作不同标签。标签不生成新的分类层级。

## 标题、目录与自动编号

文章主标题由 `title` 生成。**正文从 `##` 开始，不再重复写 `# 文章标题`**，建议连续使用二级到六级，不跳级。

```markdown
## 计算机概述

本节内容。

### 硬件

硬件内容。

#### 中央处理器

更细一级的内容。

### 软件

软件内容。

## Java 语言概述
```

打开“阅读设置 → 排版 → 标题自动编号”后，显示为：

```text
1    计算机概述
1.1    硬件
1.1.1    中央处理器
1.2    软件
2    Java 语言概述
```

正文和目录都采用“编号    标题”，去掉短横线，并以约 0.65 个字号的固定间距分隔；无需在 Markdown 中手工输入空格。关闭后仅显示原始标题。**不要手工给正文标题添加数字，否则可能重复编号。**

标题进入本文目录和章节搜索。 折叠区域内部的标题同样按章节索引；从搜索结果、目录或章节链接进入时，会自动展开所有外层折叠。手动收起的内部标题不参与当前阅读章节的自动判定。段前间距用阅读设置调整，不用连续空行或大量 `<br>` 强行撑开。内容块中的小标题用粗体，避免额外标题混进目录和搜索分节。

### 章节锚点

锚点根据标题文字生成：统一字符形式、英文转小写、去掉大部分标点、空格和下划线转连字符。重复标题依次加 `-1`、`-2`；只含标点时使用 `section` 等回退名称。

例如 `### Java 版本` 通常对应 `#java-版本`，`### 硬件` 对应 `#硬件`。最可靠的方法是悬停生成页面的标题，点击出现的 `#` 复制本节链接。**不要用自动编号猜地址。**

自动编号、主题、字号不改变锚点；改标题文字、调整重复标题顺序可能改变锚点。标题 ID 由生成器重新设置，不采用 `{#自定义ID}` 作为本站语法。

## 正文排版

### 段落和换行

空一行开始新段落。普通单次回车通常仍是同一段；同段强制换行可以在行尾加两个空格，或适当使用 `<br>`。

### 强调和行内代码

```markdown
**重要内容**
*强调内容*
~~废弃内容~~
调用 `System.out.println()` 输出结果。
```

标记成对书写，内部不留首尾空格，不要写 `** 重要内容 **`。需要展示字面 Markdown 标记时，放进行内代码或代码块。

网站兼容修复了部分旧笔记中中文标点紧接加粗结束符的情况，但不会修复任意损坏的 Markdown，新笔记仍应正确书写。

### 列表、引用和分隔线

```markdown
- 第一项
- 第二项
  - 嵌套项

1. 第一步
2. 第二步
   1. 子步骤

> 引用第一段。
>
> 引用第二段。

---
```

嵌套内容用空格缩进。普通引用会使用网站引用外观，但不等于明确标注了“练习”等含义；固定含义使用下一节的标准块。正文分隔线放在 YAML 头部结束之后。

本站没有专门实现任务清单复选框，不把 `- [ ]`、`- [x]` 当作已支持的交互控件。

### 表格

```markdown
| 名称 | 类型 | 说明 |
| --- | --- | --- |
| 数组 | `int[]` | 多个整数 |
| 字符串 | `String` | 文本 |
```

表头下必须有分隔行；单元格支持加粗、代码和链接，字面竖线写 `\|`。宽表格可横向滚动，不必手动缩小字号。鼠标移入表格时，右上角显示放大图标，点击可打开独立阅读窗口；移出后 1 秒隐藏，再次移入取消隐藏。键盘聚焦时显示，触屏设备保留可点击图标。窗口支持横向、纵向滚动，纵向滚动时表头固定；按 Esc、点击“关闭”或窗口外部可返回正文。不依赖内联样式或复杂合并单元格设计 Markdown 表格。

### 脚注

```markdown
这段内容有说明[^说明一]。

[^说明一]: 这里填写脚注内容。
```

名称需一致，脚注不是章节标题。

## 本站规定的六种内容块

统一使用“引用块 + 类型标记”。标记保留英文大写，网页显示中文名称；这些英文是语法，不是装饰性界面文字。

| 含义 | 固定标记 | 行为 |
| --- | --- | --- |
| 注意 | `[!NOTE]` | 显示提示 |
| 补充 | `[!SUPPLEMENT]` | 补充折叠块，受全部补充开关控制 |
| 警告 | `[!WARNING]` | 显示警示内容，保留警示配色 |
| 结论 | `[!CONCLUSION]` | 显示归纳结论 |
| 练习 | `[!EXERCISE]` | 显示题目，按答案标记生成折叠答案 |
| 示例 | `[!EXAMPLE]` | 示例折叠块，受全部示例开关控制 |

```markdown
> [!NOTE] 可选的自定义标题
>
> 这里填写注意内容。

> [!SUPPLEMENT] 背景知识
>
> 这里填写补充内容。

> [!WARNING] 操作前检查
>
> 这里填写警告内容。

> [!CONCLUSION]
>
> 这里填写结论。

> [!EXAMPLE] 一个计算示例
>
> 这里填写示例内容。
```

必须遵守：

- 类型标记放在引用第一行，推荐严格使用 `> [!NOTE]` 形式，不增加额外缩进。
- 自定义标题写在标记后，空格隔开；没有可以省略。
- 标记与正文之间放空引用行 `>`。
- 块内每行保留 `>`，包括空行、代码围栏、列表、表格。
- 不同块之间放真正的空行，结束上一个引用块。
- 块内小标题用 `**加粗**`，不用 `##`、`###`，以免混入目录或影响章节搜索划分。
- 不建议嵌套多个标准内容块，复杂结构拆开写。

旧笔记的部分中文“补充”“示例”开头，以及 `TIP`、`CAUTION`、`IMPORTANT` 有兼容处理；新笔记不依赖推断，统一用六种规定标记。

## 练习题与答案

> 以下哪个命令用于编译 Java 源文件？

>
> 【答案】

## 代码、公式与图表

### 代码

工具栏使用无衬线字体，四个操作以图标显示，悬停可查看中文说明。复制成功后图标变为对勾，2 秒后恢复；失败时提示原因。

用三个反引号围栏，开头写语言标识：

````markdown
```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("你好，世界！");
    }
}
```
````

常用标识：`java`、`sql`、`javascript`、`typescript`、`json`、`html`、`css`、`xml`、`bash`、`powershell`、`markdown`。着色取决于内置程序支持，未知语言按普通代码显示。围栏内的 HTML、Markdown 和脚本只展示源码，不执行。

普通代码块带行号、换行、展开/收起和复制按钮，不要手工给代码加行号。全局设置控制默认状态，单块可临时切换。调整字体、配色或正文间距不会重置单块状态；切换对应的全局行号、换行、内容展开开关时，才会重新统一。

关闭“展开全部长代码”后，超过设定可见行数的代码会收起部分，短代码不受此默认规则影响。代码字号比正文小读者设定的 1～4 像素；代码中文、英文可分别设置字体。

演示“代码围栏写法”时，像上方示例一样用四个反引号作为外层，避免内部三个反引号结束外层示例。引用或列表里的代码必须保留对应前缀和缩进。

### 代码配色、行距和滚动

Vue 代码围栏写 `vue`（也接受 `vue3`、`vuejs`），可同时高亮模板、TypeScript/JavaScript 脚本及 CSS/SCSS 样式。其他常见语言请填写正确语言标识，包括 Java、JS/TS、HTML、CSS、SQL、JSON、YAML、Python、Shell、PowerShell、Dockerfile、C/C++、C#、Go、Rust 等；未知语言保持原文。

阅读设置的“代码与目录”中可选择跟随页面、清晰浅色、编辑器深色、柔和夜色四种代码配色，并分别设置普通文字、背景、关键字、字符串、注释、数字、函数、类型、变量、标签、属性和运算符颜色。只有语法识别出的类别会使用对应颜色，不等于 VS Code 的语义分析。自定义颜色即时生效，切换预设仍保留覆盖值；“重置自定义代码颜色”回到所选预设。个人记录备份包含这些偏好。

代码默认比正文小 2 像素，代码行距默认 1.55，可在 1.2～2.0 调整。收起状态默认保留约 25 个代码行的高度，可在“阅读设置 → 代码与目录 → 收起时可见行数”中按 1 行步进调整为 10～60 行，偏好自动保存在本机，并可在代码区域内部上下滚动，不再用渐隐遮住内容；换行后按可见行计算，实际容纳的源代码行数会变化。展开后恢复完整高度，复制始终复制完整代码。

### 批注定位与正文修改

新版批注保存章节标识、段落指纹和段内位置，不保存笔记原文或摘录。目标段落保持不变且在同一章节中可唯一识别时，前面插入或移动其他段落不再导致错位。同一段内可以跨加粗、斜体及行内代码选择；不支持跨多个段落、公式或代码块。

段落改写、章节标题改名、出现多个相同段落或旧版批注没有指纹时，不自动高亮，仍在书架保留备注并提示核对。需要重新标注时请先核对原备注，不要把提示当作备注被删除。新定位信息随个人备份导出、导入。搜索高亮、主题和工具栏变化不作为笔记正文定位依据。

### 本文目录自动跟随

正文滚动到新的章节时，本文目录会高亮该章节，并仅滚动目录自身，将超出目录可视区域的高亮项带回视野；向上、向下阅读均适用，不会因此改变正文位置。目标章节的父级折叠时会自动展开。当前高亮项已经在目录视野内时，不额外移动目录；手机重新打开目录时也会跟随当前位置。

### 拖动调整两侧目录宽度

桌面阅读页可拖动左侧笔记列表的右边缘、右侧本文目录的左边缘，分别调整宽度。每侧范围为 180～360 像素；窗口空间不足时进一步限制有效宽度，为正文保留至少约 480 像素的布局区域。宽度在松开鼠标后自动保存，刷新或切换笔记后保留；个人备份也包含此偏好。

双击对应拖动条恢复该侧默认宽度（左 220、右 224 像素）。聚焦拖动条后可用左右方向键微调，Home/End 调到可用最小/最大宽度。“恢复默认”也会重置两侧宽度。手机和窄屏抽屉目录不启用拖动，避免占用正文空间。

补充、示例内容块的图标、类型和自定义标题显示在同一标题行；右侧无背景的箭头图标及“展开／收起”文字控制本块内容，收起后标题仍保留。阅读设置中的全局展开开关仍然有效。

### 嵌套内容块与答案边界

嵌套引用每深入一层增加一个 `>`，例如 `> > [!EXERCISE] 内层练习`。每一层只识别自己的类型和答案；外层补充可以包含内层练习。答案标记必须是本层独立的一段 `【答案】`，前后留引用空行；`【答案】这里只是说明` 不会成为分界。不要把答案标记放在列表项或更深层引用中来控制外层练习。

内容块使用固定语义配色：注意红色、警告橙色、结论绿色、练习紫色、补充蓝色、示例青色；不随网站主题色改变。深色模式自动使用更亮的对应色。

### 内容重建失败时

Java 内容生成先写入项目内临时目录，成功后逐文件替换预览结果；笔记格式错误不会先清空上一版网页。成功重建后才移除已删除笔记对应的旧网页。两个 Java 内容生成进程通过系统文件锁排队，进程退出会释放锁。

这不是整个网站的一次性版本切换，更新过程中不同页面可能短暂属于不同构建；磁盘或权限错误仍可能影响替换。通过 npm 脚本启动的前端、完整构建及开发模式重建，现在还会经过统一构建锁；重复启动的构建会等待上一项结束。预览服务和内容监视模式的区别见启动章节。

### 构建排队

`npm.cmd run build`、`npm.cmd run build:ui` 和 `npm.cmd run dev` 的每次重建共用一个系统锁。看到“构建已排队”后等待即可，不必反复重启。构建任务正常结束或失败后会释放锁；不要手动删除 `.tools/build-pipeline.lock` 文件。

`build:ui` 会先构建界面资源，再生成引用新资源的网页，因此同样需要 Java 21。仍可用 `npm.cmd run preview` 单独查看已有结果。不要绕开脚本直接并行执行 Vite、Maven；手动强制结束构建的子进程、系统崩溃及磁盘故障不在本轮恢复保证范围内。开发模式启动后占用端口期间，不要重复启动第二个预览服务。

发布前运行 `npm.cmd run check:release` 核查生成目录，报告位于 `.tools/release-report.json`。具体准备、切换和回退步骤见 [发布与回退](docs/发布与回退.md)。该检查不执行部署。

- 除系统默认外，字体全部由网站内置；商业字体选项已改为风格接近的开源替代字体，不再逐项标注“内置”。
- 阅读设置从右侧滑入、滑出；两侧目录有滑动效果。系统启用减少动态效果时取消动画。
- 右下阅读工具放在正文区域，不遮挡本文目录的阅读进度。
- 从搜索结果进入笔记后，底部保留“返回搜索结果”和“返回原页面”；前者重新打开原搜索，保留关键词、筛选及结果列表滚动位置，后者回到发起搜索的位置。记录仅在当前浏览器标签页内有效。
- 保存的字体、字号、行距、主题与代码配色在样式加载前同步应用，减少刷新时闪回默认设置；首次加载内置字体仍可能经历浏览器正常的字体加载过程。
- GitHub 网页上传与本地文件夹不会自动同步。开始本地编辑前执行 `git pull --ff-only`；不要用旧文件覆盖网页更新的笔记。


### 侧栏与字体（2026-11-02）

两侧目录宽度在首次绘制前读取本机设置，不等待网页应用启动。标题统一高度，左侧分类之间有分隔线；本文目录的“展开全部 / 收起”位于目录列表下方，和“查看全部笔记”一样支持悬停与键盘焦点阴影。侧栏不再提供重复的回到顶部链接，正文悬浮栏保留统一尺寸的向上箭头图标。

文章大标题与正文使用相同的中英文字体组合。原有字体选择兼容迁移：微软雅黑/苹方改为思源黑体，宋体改为思源宋体，Arial 改为 Arimo，Times 改为 Tinos，Georgia 改为 Gelasio。开源字体名称保持真实，不冒充原商业字体。Courier Prime 是接近 Courier 打字机风格的代码字体，无法仅凭截图确定原字体名称。

字体文件经构建存入 assets，阅读时不访问字体 CDN；许可证保存在 public/licenses。首次访问仍需要下载字体，因此可能短暂使用备用字体。

`publish-notes.bat` 是手动运行的一键发布入口：检查网站、提交允许范围内的文件、正常推送到 origin，随后 GitHub Actions 构建部署。它不是定时同步程序，不会自动拉取并合并 GitHub 网页上的修改；推送前遇到远程新提交会停止。发布范围包括笔记、图片、配置、web/src/scripts 与依赖配置，方便同时发布网站功能更新。

清理项目时保留笔记与媒体、许可证、源码、依赖锁文件、测试、Maven wrapper 和使用文档。旧日志、重复下载压缩包、可再生成的测试临时文件可以删除；node_modules、target、dist、.tools 只用于本机依赖、构建和预览，均已被 Git 忽略，不会作为源代码上传。


### 已确认的字体方案

保留系统默认，另外内置且仅提供以下 8 款字体：正文中文和代码中文为思源黑体、思源宋体；正文英文为 Arimo、Tinos、Gelasio、Lora；代码英文为 Courier Prime、JetBrains Mono。Arimo、Tinos、Gelasio 分别作为原 Arial、Times New Roman、Georgia 的开源候选；它们使用真实名称，不会显示为原商业字体名称。旧字体偏好与个人备份导入会迁移到对应选项。所有字体文件随静态站点发布，许可证位于 public/licenses。

桌面端搜索匹配导航位于正文区域底部中央，与底部阅读工具对齐；调整两侧栏宽度、收起目录或进入专注模式时会重新居中。本文目录列表与标题之间保留额外 12 像素间距。
